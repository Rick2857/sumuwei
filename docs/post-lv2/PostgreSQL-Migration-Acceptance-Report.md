## 6. ★ 本轮抓到的关键缺陷（已修，但**未端到端验证**）

```text
`src/main.ts:990` 的 settings 表原来**只有 OPENAI_*** 键 —— 而它自己的注释就写着
"runtime.getSetting() 走的是这个内部设置表，而不是 process.env"。
⇒ 后果（实测）：插件读不到 POSTGRES_URL ⇒ **回退成 PGlite 适配器** ⇒ 去开 `PGLITE_DATA_DIR`
   （= **真实库**）⇒ 被身份核对拒（`期望 sumuwei，实际 template1`）。
⇒ 也就是说：**`.env` 那次切换对真入口本来不生效**，而且失败前**已经碰过真实库**。
⇒ 已修：追加播种 POSTGRES_URL / CHARACTER_DB_BACKEND / PGLITE_DATA_DIR / PGLITE_SNAPSHOT_DIR /
   LG_PG_EXPECT_DATABASE / LG_PG_EXPECT_DATABASE_PREFIX（**只在环境里真有这些键时才播种**）。
⚠️ 这是 `PG-ISO-01` 的**同一机制第二次出现**（第一次 G06 门；这次 P02 门，踩了两次）。
⚠️ 那两次失败的运行**碰过真实库** ⇒ 已做**内容**评估：
   **54/54 张表与参照快照逐表相同**（集群级文件原地重写、大小未变；`(路径,大小)` 摘要 `137b7233…` 未变）。
   ⇒ **用户数据未变**；但"干净关闭"一项仍不主张（该目录本来就是陈旧 `postmaster.pid` 状态）。
```
