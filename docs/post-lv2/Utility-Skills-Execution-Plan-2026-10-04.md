# 苏沐薇实用能力加装执行计划

日期：2026-10-04。状态：**计划已准备；实现、安装及运行验收尚未开始**。

执行顺序：**精确计算 → 文档阅读 → 网页深读 → OCR**。每项完成一个可用闭环后继续下一项，最后统一收口。四项共用现有行动链、一个当轮内容通道、一套验收脚本和一份交付报告。

本计划依据用户本轮指定的顺序与“减少、简化验收并提高效率”编写。组件来源及源码核对承接[准备方案](../research/Su-Muwei-Utility-Skills-Preparation-2026-10-04.md)和[来源清单](../../artifacts/research/utility-skills-preparation-20261004/sources.json)，不重复做已经完成的选型研究。执行顺序和验收组织以本计划为准；准备清单的完成状态不转写成能力已安装。

## 1. 交付目标与首版范围

完成后，苏沐薇能在用户明确请求时执行以下四项，并基于程序实际取得的结果回答。安装成功、组件返回成功、正文实际进入模型、用户看到正确回复分别记录。

| 顺序 | 首版能力 | 固定组件 | 用户可用的闭环 |
|---|---|---|---|
| 1 | 精确计算 | `mathjs@15.2.0` | 明确算式 → 受限计算 → 程序数值/错误 → 可见答案 |
| 2 | 文档阅读 | `markitdown[pdf,docx,pptx,xlsx]==0.1.8` | 指定沙箱文件 → 提取文字/结构 → 当轮阅读 → 有来源与范围的回答 |
| 3 | 网页深读 | `@mozilla/readability@0.6.0` + `jsdom@30.1.2` | 指定 HTTPS URL → 有界获取 → 正文提取 → 有来源与范围的回答 |
| 4 | OCR | `tesseract.js@7.0.0` + `tesseract.js-core@7.0.0` | 指定 PNG/JPEG → 本地中文/英文识别 → 展示识别文字与局限 |

首版采用以下范围以缩短接入和验收：

- 计算支持十进制四则、括号、负数、受限整数幂与 `abs/sqrt/round`。用 BigNumber，初始精度 64 位有效数字；除法、开方明确为有限精度结果。单位换算、统计及任意程序执行留给后续切片。
- 文档支持文字型 PDF、DOCX、PPTX、XLSX；保留转换器实际提供的标题、表格、幻灯片/工作表标记。首版阅读入口是既有沙箱目录中的明确文件名，不增加附件上传界面。
- 网页支持静态文章正文。登录态、验证码、动态渲染、浏览器自动操作不纳入首版；“深读”指提取并阅读比搜索摘要更长的正文，不承诺超出上下文预算的全文阅读。
- OCR 支持 `chi_sim` 和 `eng`，语言资产固定为 `@tesseract.js-data/chi_sim@1.0.0`、`@tesseract.js-data/eng@1.0.0`。扫描 PDF 转图、摄像头、屏幕和剪贴板不纳入首版。
- 首版一轮执行一项明确能力；多项组合任务返回范围说明，不增加自动多步代理。语音与字幕复用现有检查后回复通道，扬声器及持续对话验收仍归原语音工程。

许可证适用性按用户此前对 Anthropic Skills、NapCat 的确认记录为 `USER_CONFIRMED_APPLICABLE`。本批组件按代码边界和环境兼容性选用，QQ/NapCat 不进入本批范围。

## 2. 保留框架与环境的接入方式

所有执行沿用同一条链：

```text
明确用户请求 → 意图/确定目标 → ActionRequest → Registry / Policy / Gateway
             → 专用适配器 → ActionResult + 当轮内容
             → 预算及实际入模片段 → 已有回复检查 → 文本/字幕/TTS
```

能力影响矩阵：

| 能力 / 操作 | 权限、风险、副作用 | 复用 / 新增 | 认知边界 | 真实结果 / 账本证据 |
|---|---|---|---|---|
| `math.calculate / evaluate` | `math:calculate`；R0；none | 复用行动链；新增受限计算器 | 程序数值不自动成为记忆 | 参考值与实际结果一致 / action、结果指纹一致 |
| `document.read / read` | `document:read`；R0；read | 复用沙箱目标；新增格式转换 | 文件陈述不提升为用户事实 | 文件文字确实取得 / 文件指纹、实际范围一致 |
| `web.read / read` | `web:read`；R1；read | 复用行动链；新增有界获取/正文提取 | 网页正文是外部资料 | 最终网页确实取得 / 引用、指纹、入模范围一致 |
| `image.ocr / recognize` | `image:ocr`；R0；read | 复用沙箱目标；新增本地 OCR | 识别结果可能有误，不自动采信 | 原图对照识别读数 / 原图与资产指纹一致 |

共同实现只做必要追加：

1. 在 `AdapterOutcome / ActionResult` 增加可选的当轮内容；先实现计算结果，再随后三项追加具体类型。旧请求不产生新字段，默认三能力集合及旧 packet 基线保持。
2. 内容与持久化引用分离。正文只在当轮内存和可裁上下文 section 中流转；账本、trace、开发者面只保留允许的引用、指纹、计数和状态。正文不得通过 action 参数预览泄漏。
3. 新 section 预算代码缺省 0，隔离验收配置使用 2000 token，并服从现有总预算。长内容先按确定次序取片段，记录截断和实际入模集合；引用附录由程序生成，不由模型补来源或页码。
4. 当轮数据不冒充用户事件，不新增写入 Memory / Belief / Storyline 的入口。最终正常回复仍经既有对话记录与消费者；不据此宣称所有长期认知绝无变化。
5. 四项各有默认关闭开关。能力声明可以追加登记；权限授予和适配器构造绑定同一开关。关闭时不加载重组件、不启动执行器、不访问目标。依赖缺失时如实报告不可用。
6. 延用已有 `runtimeCapabilities` 注入点显示可用性。迟到结果绑定原 turn/action，取消后不能进入下一轮；正文里的指令无权发起新动作。

不新建通用技能加载器、MCP 任意工具入口、第二个 Agent/记忆后端或数据库迁移。现有搜索证据契约保留；新增正文不塞进只有短摘要用途的 `ExternalEvidence`。

环境安排：

- 以准备期 Node 22.23.2、pnpm 12.4.1 为基线，执行前重新核对；不为本批升级 Node、pnpm、TypeScript 或已有语音依赖。
- 每项按顺序在 `artifacts/post-lv2/local/utility-skills-preparation/` 验证其固定依赖和一个实际样本，通过后再接入。该样本继续用于正式验收，避免另起一轮组件验证工程。
- 正式 Node 依赖通过根项目的精确版本声明和 lockfile 管理，按四项顺序追加；核对差异，不接受无关现有依赖升级。不得通过复制临时 `node_modules` 交付。
- MarkItDown 使用已找到的 CPython 3.12.13 创建专属 venv，保存完整依赖锁及 wheel/文件摘要；不修改 TTS venv、Torch/CUDA。其 Magika/NumPy/ONNX Runtime 依赖在该环境中核对，不能按“纯文本无模型依赖”处理。
- OCR core、语言文件和 cache 使用明确本地路径，资产下载在准备阶段完成并核对哈希；日常识别及缺资产失败不得触发 CDN 下载。
- 文件转换、计算和 OCR 用可终止执行器；OCR 初始仅一个 worker。独立进程/venv仅提供生命周期及依赖分离，不宣称它们等同 OS 安全沙箱。
- 原始文档、图片、全文及模型输入输出放在已忽略的 `local/`；公开报告只记必要来源与读数。CPU/模型测试延用用户此前指定的测试时机。

### 3.1 四项各自必须实现的边界

**精确计算**：允许数值常量、括号、列举操作符/函数，禁止赋值、访问器、数组、导入、随机、嵌套解析执行及未知函数；函数名与 AST 类型共同检查。输入不得先转 JS 浮点数。初始限制为 512 字符、128 节点、深度 16、整数幂指数绝对值不超过 1000、格式化结果不超过 4096 字符、2 秒超时；结果过大或非有限值明确拒绝/失败，不截成一个貌似完整的答案。

**文档阅读**：目标解析复用沙箱边界，检查真实路径、junction/symlink、UNC、歧义及扩展名/实际格式；只把已授权字节交给 `convert_stream()`。禁用插件，不配置 LLM/Azure 客户端，不调用可读任意 URI 的通用入口。PDF 页码无法可靠取得时只报提取片段，PPTX/XLSX 仅引用实有结构。原文件前后指纹一致。

**网页深读**：HTTPS、443 端口、无 URL 用户凭据，最多三次重定向；逐跳校验 IPv4/IPv6 的回环、私有、链路本地及其它非公网地址。连接使用已校验 DNS 地址，并保留原主机的 TLS 证书/SNI 校验；不得“校验一次、实际连接重新随意解析”。优先用原生 HTTPS 获取及受控地址解析，避免再引入浏览器或通用爬虫。取得 HTML 后用 `new JSDOM()`，不启用脚本/子资源，不用 `JSDOM.fromURL()`；只提供正文文字。

**OCR**：仅向工作器传已授权图片字节，不传能自行访问路径/URL的原始字符串。显式配置 worker/core/lang/cache 本地路径；缺资产即失败。格式、字节数、尺寸和像素数在识别前校验；超时/取消释放执行器及其工作器，记录释放和后续恢复。

公共初始上限：文档 10 MiB；网页解压后 2 MiB，DOM 元素 50,000；图片 16 MiB/20 MP；网页总超时 15 秒，文档/OCR 30 秒。压缩容器的成员数及展开体积在转换前检查，另设展开 50 MiB/1000 个成员上限，不能只检查压缩文件大小。子进程退出后清理临时文件，避免把限时执行当作已证明硬内存隔离。

这些值是首版运行约束，不是已测性能 SLA。冷/热耗时及进程内存随原有验收采样，OCR 冷启动另测一次；不额外开展负载、500 轮对话或多轮参数扫档。

## 4. 验收压缩为三个环节

### A. 开发中短测：一个脚本，按能力选择

新增一个 `scripts/utility-skills-verify.ts`，提供 `--only math|document|web|ocr`，完整运行覆盖公共检查。对应 `pnpm utility:verify` **是计划新增命令，目前不存在**。

首批固定为 **32 组用例：公共 8 组 + 每项 6 组**。一组里的参数化输入逐条统计，不把一组通过误报成只执行了一个输入。共用同一批 fixture、断言与报告格式，不另建四套 component/e2e/measurement/gates 脚本。

| 组别 | 固定覆盖内容 | 判定依据 |
|---|---|---|
| 公共 8 组 | ①默认关闭/权限拒绝；②明确触发与旧搜索/文件/闲聊兼容；③目标歧义及真实路径越界；④正文 sentinel 的持久化隐私和事实资格；⑤预算/实际入模/引用；⑥取消、迟到与恢复；⑦内容指令不执行；⑧量具正控/负控/恢复及非空计数 | 真 gateway packet、实际 adapter/IO 计数、账本/trace/事件差异；旧路径输出对照 |
| 计算 6 组 | 十进制；括号/负数；大整数；幂/开方/舍入；数学错误和非法 AST；复杂度/超时 | 参考值由独立期望值给出；例如 `0.1+0.2=0.3`、`9007199254740993+1=9007199254740994`；近似结果按预先写明的误差比较 |
| 文档 6 组 | PDF；DOCX；PPTX；XLSX；空/扫描件；损坏、伪装格式、加密/超限 | 四个清晰 fixture 的指定文字、数字及实有结构；原文件未改；无法取得内容时没有成功阅读事实 |
| 网页 6 组 | 中文静态正文/去导航；允许重定向；禁止地址/协议/端口；DNS/重定向连接约束；状态码、超时/超限；脚本、子资源、动态空壳/正文空 | 离线网络夹具检查解析和连接边界；真实 DOM 正文提取；受禁目标连接数 0，无额外资源请求 |
| OCR 6 组 | 清晰中文；清晰英文；清晰混合及数字；退化图；缺资产/非法或超限图；工作器超时/恢复 | 三张清晰 fixture 的独立转录与逐样本 CER；识别实际输出；网络 0；工作器计数归零 |

隐私/认知用例同时设置正控：执行账本确实新增动作，正文确实进入当轮模型输入，但不增加由外部正文伪装成用户事实的写入。正常回复引发的既有事件另外记录，不能混入“零新增事件”判据。

OCR 首版清晰三样本分别要求 `CER ≤ 5%`、指定关键数字全部正确；退化样本展示读数和范围，不混入平均数掩盖问题。用预先独立写好的转录，不能拿 OCR 输出回填参考答案。此小样本只支持首版清晰打印文字可用性的结论；若不达标，该项如实 `PARTIAL/FAIL`，不以反复换样本或调阈值凑通过。准备方案的 12 样本建议在本计划中缩减为上述三正控和三个边界组，不宣称广泛 OCR 准确率。

每项实现后执行自己的六组及实际受影响的公共组；公共接线未改时不重复所有公共组。修改 TypeScript 后运行 `pnpm typecheck` 和相关继承门；阶段短测可使用缓存/安全并发，但不作为最终发布证据。

### B. 最终一次：组合离线验收及必要回归

WP5 冻结待验代码、依赖、fixture 和配置后，32 组完整运行一次。运行真实组件和实际 `TurnGateway`，离线 provider 只替换模型服务；不能只测一个直接调用函数就宣称聊天已接入。

随后合并执行以下清单，同一源码/配置版本内消除重复命令：

| 命令/检查 | 执行次数及原因 |
|---|---|
| `pnpm m4.5:ci` | **最终串行跑一次**，含 typecheck、内核、prompt、行动等既有累积门；由 [AGENTS.md](../../AGENTS.md) §1 明确要求 |
| `pnpm m5.1:measurement:verify` | 一次，满足新增判据的既有量具纪律；新能力自己的检测器三段式仍放在公共第⑧组 |
| `pnpm m5.1:gates`、`pnpm m5.1:regression:verify` | 一次读取证据并生成汇总；后者使用同次 CI 的有效 UTF-8 日志，不重跑 CI |
| 实际受改动影响的其它门 | 仅补不在上述链中的门；例如真改到搜索层才加 `td10:reliability/td12:privacy`，改到桥/交付链才加对应 post-Lv2 门 |

开发时优先复用 `pnpm fast` / `gates:run --lane affected --cache`。由于根 package/lock 变更会扩大影响面，短测可用现有 `--only` 明确筛选已核对的相关门，最终仍跑一次完整 CI。新验收脚本尚不在旧映射里，必须显式执行；不能拿 `fast` 全绿代替新增能力验收。

正式证据遵循现有串行、无缓存、干净树纪律。当前工作区有既有改动及历史证据重生成，WP0 登记后保留；必要时用本任务隔离 checkout 固定待验代码，而不是清理他人工作。历史证据只按本次新生成路径白名单处理，不能整目录恢复。

既有回归汇总器固定读取 `artifacts/m5.1/wp9-m4.5-ci.log`，执行时保存同次完整日志及真实 `EXIT_CODE`，并记录它与本任务 run 的关联；不能让它误读旧日志。已有证据能否承接按源/配置适用性核对，汇总器给出的历史 PASS 不能独自证明本批代码已通过。基线已有红项与新增回归分列，若必跑 CI 未达到退出码 0，完整回归仍为 FAIL，不标全绿。

不对四项分别运行 `m4.5:ci`，也不在已经跑过它后再调用 `m4.5:ci:full` 重跑离线链。本批真模型验证使用 C 的短链；若实际影响面还要求既有 live smoke，直接运行对应 smoke 并登记新增原因。旧里程碑的红项保持原状态，不借本批重新裁定。

### C. 真模型短链：八个固定场景，一次集中执行

四项各 **1 个成功场景 + 1 个失败/降档场景**，共八轮。使用既有 `with-test-model` 包装器和本任务隔离库，不加载或写生产库。成功场景实际调用组件；网页成功场景实际读取事先固定的公开 HTTPS 文章，并保存此次提取片段的指纹。模型调用正常情况下为八次；包装器若有传输重试，次数和首轮失败单独报告。

| 能力 | 成功场景 | 失败/降档场景 |
|---|---|---|
| 计算 | 明确十进制算式，回答与程序结果一致 | 非法函数/表达式，不声称已计算 |
| 文档 | 固定文档中找到指定事实/数字并说明来源 | 扫描或空文件，不猜测内容 |
| 网页 | 真实文章的指定段落信息，并给实际来源/范围 | 禁止访问的 URL 被程序拒绝，不声称已阅读 |
| OCR | 固定清晰图，复述指定关键文字/数字 | 缺语言资产，零出站且如实失败 |

检查用户可见回复、真实模型输入和账本引用的一致性；仅调用成功或模型说“读过了”不算通过。判断题答案来自固定材料/程序事实，不引入另一个大模型评分器。引用和状态由程序生成，正文涉及解释的部分结合原文核对；需要真人确认的疑点集中到一份材料中，不安排多轮盲审。

文本结果沿既有检查后交付链验证；如本次确实改到语音/字幕交付入口，再补一次对应短链。四项验收不替代原实时工程的持续对话/真人播放验收。

新增脚本还提供 `--live`，计划命令为 `pnpm with-test-model pnpm utility:verify --live`。该命令及八轮场景均尚未实现或执行。

## 5. 证据、失败处理和启用

公开证据目录拟为 `artifacts/post-lv2/utility-skills/<runId>/`，原始内容放相应 `local/`。一份 `run.json` 记录源码及相关输入指纹、依赖/资产版本、配置摘要、fixture 指纹、逐项 exit/status、实际测量数量、耗时、重试和缓存来源；一份报告读取同一 run 的结果。

报告逐项列出：**安装、LG 接线、离线验收、真模型短链、生产启用**。缺失证据为 `NOT RUN`，失败为 `FAIL`，不能把准备期来源核对、缓存 PASS 或配置开启当作运行验证。

失败处理只回到失败能力/公共接线及其实际影响门，保留第一次失败档。公共接线或源代码随后改变时，重跑受影响场景；最终完整回归必须对应交付版本。若 OCR 不达标或依赖不可用，可交付前三项并把 OCR 明确列为未完成；不能宣布四项全部完成。

生产启用按已有授权范围执行，不把“给计划书”解释为已经授权修改生产 `.env`。后续获得实施授权时连续推进工作包，已授权的安装、修复和检查不逐项重复询问。四项如需统一启用，可在同一次启用中完成并分别记录状态；若已有明确启用授权，则不再索取相同确认。

启用前默认关闭、隔离验证；回滚关闭对应能力开关和内容预算，确认适配器/进程/出站为 0。保留依赖锁、已生成动作账本和报告，无数据库恢复或迁移。
