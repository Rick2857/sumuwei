## 发现与修复

1. **旧冒烟继承新权限。** M4.5 冒烟的原判据针对旧沙箱，但运行器继承了后来激活的角色决策与本机文件能力。现在只在该测试的子进程固定 `m4.5-frozen-sandbox` 配置，原断言不变；结果明确记录配置。生产 `.env` 和权限未改。新读数 **52/52 PASS**，不覆盖原 43/7 FAIL，也不作为角色模式的证明。
2. **角色把连接未知误读成不能用。** 最初真实入口选择 `answer`，零动作。带相同最近对话的控制调用中，目录为 `unknown` 时模型称不能用浏览器，改成 `connected` 后提出工具。保留实际目录的未知状态，在决策指令明确：已开启且已授权的浏览器请求可先尝试快照，按实际失败说明原因，不猜测已连接。
3. **浏览器参数说明缺值域。** 控制调用给出了不存在的 `action=fill` 和尚未读到的引用占位文字。补充从既有 `BROWSER_ACTIONS` 派生的说明，决策器与后续规划器共用：`type/select/click` 的字段、真实快照引用、未读快照时先读取。没有新增操作、权限或通用 MCP 入口。
4. **重新规划在七份内容处异常。** 真实角色任务已经执行七个成功动作，测试服务器也收到确认，但下一次规划调用 `selectTurnContentContext` 时，八份容量的缓存撞上六份的契约上限。trace 记 `KernelError`，已执行结果丢失，最终回复错误否认执行能力。修正缓存上限与契约同源，保留最近结果；新增七份不同文件读取后重新规划的回归，要求七个成功动作全部回到轮次，后续规划看到最后一份内容。

另外查明一个测试目标问题：观察端与主入口各有 MCP 会话，观察端打开的页不自动成为主入口绑定的页。续验明确提供本地测试 URL，并用页面按钮发到测试服务器的确认值独立核对实际效果。观察端会话的快照没有包含主入口页面，单独记录，未把它当成成功读回。
