## 1. 这次具体交付什么

| 能力 | 首版行为 |
|---|---|
| 可靠被打断 | 用户有效抢话或明确停止后，音频与口型及时停止；取消能在 LG 正在处理时受理；下一轮正常恢复 |
| 边听边准备 | 音频按块输入，产生真正的 partial；LG 提前做只读召回或候选准备，final 才提交正式用户轮次 |
| 边听边查 | 仅在用户明确允许提前查、对象稳定且符合现有联网策略时启动；改口后取消或废弃结果 |
| 小集合快反 | 明确停止、呼唤苏沐薇等少量信号快速触发停止或可见回应；引用、否定和回声不能直接触发动作 |
| 有限插话 | 限于呼唤回应、明确更正冲突、已授权的边查边提醒；LG 生成并检查短句后让出话权，用户抢话优先 |
| 中途纠正 | 合法新证据或用户更正到达时，废弃未播余句，由 LG 重新判断、检查并给出纠正段 |
| 旧任务不串话 | 换话题后，旧检索结果、旧回复、旧音频不能进入新话题或继续播放 |
| 按播放事实续聊 | 后续语音上下文只把客户端确认播完的完整句子当作已说内容；中断句和断线不猜测已播文字 |

维持 Open-LLM-VTuber 外壳、当前 CosyVoice3 声线和 LG 唯一权威。Pipecat / LiveKit 的取消、版本和交付机制作为源码参考；现有 sherpa 流式接口优先复用。Smart Turn、专用 KWS 都是有明确缺口才试的小组件，安装它们不作为开工前置。

首版范围到这里为止：开放域自由抢话/争辩、持续重推整段答案、端到端语音模型替换、整套平台迁移、字词级播放对齐、多用户和连续数小时稳定性另行评估。CPU/GPU 原生推理不能安全停止时，分别记录「输出已停止」与「计算仍排空」。

## 2. 四个工作包，先交付能用的部分

| 顺序 | 工作与改动落点 | 出口检查 | 估算 |
|---|---|---|---|
| **P1：取消与播放事实** | 先用 2–4h 核对慢请求期间的取消路径与播放回报。修改 bridge transport：控制消息与耗时 `send()` 解耦，正式轮次仍串行；串接请求/回复/音频版本；复用交付账，接前端播放回报和 LG 语音上下文 | 慢请求不阻塞取消；旧包丢弃；断线未知；已提交事件保留；未播句不进入已说内容；停播后能继续聊 | **20–34h**，含上述探针与专项检查 |
| **P2：流式输入与提前准备** | 前端发送有序音频块；后端产 partial/final；LG 新增不写正式用户消息的只读准备入口；复用 Tavily 取消信号与既有搜索放行；接少量停止/呼唤信号 | 用户尚未说完时确有准备；改口撤回；final 只提交一次；临时输入不写记忆；引用/否定负控有效 | **18–30h** |
| **P3：有限插话与纠正** | 在 LG 内增加有来源的角色输出入口，复用同一上下文装配、回复守卫与角色输出落账；用户抢话、角色短句、检索完成之间按版本与话权协调 | 用户未结束前短插话实际发生；新证据在播放中到达并触发纠正；用户优先；旧任务结果不能串入新话题 | **16–26h** |
| **P4：一次联合验收** | 一批 20 次真实链路测试；一次短真人体验；最后统一跑受影响门和完整离线回归，出一份结果表 | 功能、失效处理、性能、真人体验分列；失败与未测不隐去 | **4–8h**，不含用户等待及上游故障等待 |

合计 **58–98 个有效工程小时，计划取 60–100h**，约 8–13 个 8 小时工作日。相比上一版 70–120h，主要节省重复回归、独立量具和验收材料；功能实现仍占大部分时间。此数是规划目标，P1 探针后按实际缺口更新，不作截止承诺；另选/下载/验证新 ASR、平台迁移或修复其他会话的既有失败不在此估算内。

P1 可独立交付：先得到可靠停播、取消、恢复和播放上下文，不等待流式 ASR 选型。P2 提前准备稳定后再接 P3，避免在输入版本尚不可靠时建设主动插话。

### 两个实现选择提前说清楚

1. **流式 ASR 不能从当前 SenseVoice 开关打开。** 网页目前交整段录音。先用现有 Zipformer 验证临时 partial 接口，SenseVoice 仍负责正式 final；这是增加计算支路的探针，鉴于用户要求两遍识别作备用，**不默认启用为正式配置**。若要采用单一流式模型，必须证明准确率和成本再切换。若这两条路径均不适合，报告 P2 的具体阻塞与额外成本，保留已完成的 P1，不把反复重跑离线识别称为流式交付。
2. **先做完整句子的播放对账。** 不为首版新增字词对齐模型；确认播完才进入已说内容。LG 的 `recentLines` 和参与语音轮次的历史读面均需应用交付视图，不能只删除网页聊天气泡。完整生成记录保留，语音交付记录独立对账；正式写入继续使用既有受控串行路径。

## 3. 验收只保留三个步骤

### 第一步：开发中只检查改到的地方

每个工作包完成时执行 `pnpm typecheck`，并只跑受影响的既有专项门。小修复只复跑失败或受新改动影响的检查；不每次重跑整批模型测试和全仓库回归。

| 改动 | 复用的检查 |
|---|---|
| bridge 控制/轮次/版本 | `postlv2:bridge:verify`、`postlv2:transport:verify`；客户端消息变动才加 `postlv2:speech:verify` |
| 播放回报/上下文 | `postlv2:delivery:verify`，并补真实接入与上下文读回；纯函数 PASS 不替代线上接线 |
| ASR 输入 | `postlv2:asr:verify` 作为现有流式组件检查，另在联合测试验证网页实际 partial/final |
| 模型/皮套配置 | 只有配置或对应路径被改动时才复跑 `postlv2:avatar:verify`、表达相关门 |
| LG 正式轮次/上下文 | 按实际改动补相关 context、守卫与轮次门；最后完整离线回归兜底 |

新增加的协调检查集中到**一个**脚本，不为每项能力创建独立 gate、量具、交接单。拟复用旧计划尚未实现的名字 `pnpm postlv2:realtime:verify`；拟提供离线与实测两个档，**命令与参数目前均未实现，不能现在运行或当作已有证据**。既有 `pnpm fast` 可帮助开发，但当前 affected 映射不能保证覆盖全部语音改动，不能替代上表的显式检查，也不能把缓存当发布证据。

离线档只验证难以从体验看出的关键性质：控制消息不会被慢回复挡住、正式写入串行、final 幂等、版本失效、未检查文本被拒、临时输入不落正式事件、交付视图保守。用实际适配入口和可控异步任务触发竞争，不以几句固定时序 mock 证明真实速度。正控、错误输入与恢复放在同一组用例中，验证脚本不另建一套里程碑体系。

### 第二步：一批 20 次真实链路测试

真实链路指实际网页、LG、ASR/TTS 与播放路径；查询用例走实际已授权的 provider。浏览器自动执行适合自动化的操作并采集事件，真人用例也进入同一个 run。预录音若使用，单独标为回放材料；不能替代真人麦克风验收。没有真实触发的功能保留 `NOT RUN`。

| 场景 | 次数 | 必须观察的结果；负控直接附在同组 |
|---|---:|---|
| 讲话中准备/提前查证 | 2 | 用户继续讲话时实际启动准备；改口后旧候选撤回；无授权不提前出站 |
| 角色短插话 | 2 | 用户尚未结束时 LG 检查后的短句播出并让出话权；引用角色名不能直接抢话 |
| 明确强信号 | 2 | 停止/呼唤有快速可见反馈；引用或否定停止词不错误执行 |
| 用户抢话 | 2 | 旧音频及口型停，下一轮可用；不是只更新字幕或给取消登记表打标 |
| 新证据触发中途纠正 | 2 | 证据在语音播放中到达，旧余句失效，LG 检查后的纠正段实际播出 |
| 换话题后旧结果到达 | 2 | 旧 request 结果被隔离；不影响新回答、不重复已执行动作 |
| 普通短对话 | 4 | 中文输入→正式 LG→检查后字幕/TTS→播放回报一致；核对打断后上下文 |
| 冷启动 | 1 | 首次使用等待可见、状态真实；单列启动/预热时间，不混入普通热轮次 |
| 故障或断线 | 1 | 可见失败/未知交付；恢复后不自动重播旧段 |
| 重复及乱序包 | 1 | final 不重复提交，旧事件不覆盖新版本 |
| 回声或非抢话声音 | 1 | 不误触发停止/插话；耳机与扬声器环境分列，未测环境不宣称已通过 |
| **合计** | **20** | 六类核心交互各 2 次，加 8 次基础/异常覆盖 |

计数按预先登记的输入流程，不能把一个动作的多个音频块算多次。负控可与主流程连续进行，仍保留各自结果。两次同类用例在输入或到达顺序上有区别，避免照抄一遍。至少一份真实麦克风与真实耳机/扬声器演示从这批里产生，用户集中做一次 **5–10 分钟**的体验即可；不另加多轮盲审或逐句打分。

**一次采集同时回答功能、交付和等待问题：**

- 浏览器同钟记录最终输入提交、首次可感知反馈、首段实质语音实际播放、有效停止确认、停播及对应控制响应。服务端时间只作事件对账。快信号另外记录从语音信号结束到反馈的整段等待，避免只展示内部处理时间。
- 保留所有 20 次的成功、失败、超时和未完成；报告各类别、样本数、max 与全部超标项。有实质答复的普通短轮记录 p50/p95/max；未得到实质答复者单列失败/未完成，不从全样本分母消失。
- 沿用现有阈值作诊断：首反馈每次 ≤10s、本地有效停止后停播 ≤250ms、服务取消/旧包失效 p95≤500ms、快速信号反馈 p95≤500ms、普通短轮实质语音 p95≤5s。低于原采样量的统计只代表本批读数，不能证明稳定 p95 或完整性能验收通过。
- 立即可见的停止/倾听反馈可以走有限快路径；有声回应仍由 LG 检查。固定占位音或一个表情不计为实质答复，不能拿它掩盖模型等待。

### 第三步：交付前统一回归与一份结果表

代码冻结后统一执行一次 `pnpm typecheck`、尚未在相同适用代码版本上通过的受影响专项门，以及**不使用缓存的 `pnpm m4.5:ci`**。纯文档变动不重复模型验收；新增代码改动则只重跑受影响部分，最终全仓离线读数必须适用于交付版本。

20 次实测与真人演示只合并跑一批。失败后复测失败项及其共享路径，保留原始 FAIL；更换 ASR/TTS、缓冲或调度逻辑后，受影响性能样本须重新采集，不能把多个不兼容版本拼成同一批通过读数。

复用已有记录/工具，单个 run 下保存配置及版本清单、带关联 ID 的事件、一个汇总结果。公开汇总不存整段录音/转录，私有材料进 `artifacts/post-lv2/local/`。结果只分列：**实现 / 离线机械检查 / 真实功能 / 20 次性能观察 / 真人体验 / 完整 Lv4.5 / 生产激活**。不为四个工作包各生成七份报告。

| 判定 | 本版含义 |
|---|---|
| 轻量工程 `PASS` | 上述有限功能与负控实际通过、上下文/落账边界通过、适用离线回归退出码 0，真人体验无阻断问题；性能另列，不能并成一个“全面通过” |
| 性能 `FAIL` / `NOT RUN` | 本批阈值未达 / 未测；说明具体瓶颈，不能以功能通过覆盖。普通短轮 p95 即使达标也仅记“本批观察达标” |
| 工程 `PARTIAL` / `FAIL` | 某项能力未接线、只能在 mock 成立、负控失败或回归未通过；已能用的部分与剩余缺口分开交付 |
| 完整 Lv4.5 `NOT RUN` | 未完成冻结契约所要求的样本量与完整真实回归，不以轻量 PASS 关闭它 |
| 生产激活 `NOT ACTIVATED` | 本期在隔离环境交付试用；正式库启用与必要迁移另行处理 |

如最终离线回归仍有其他工作流的既有失败，如实记录门名与原因，不越界修复，也不宣布全仓通过。后续要正式 Lv4.5 放行时，复用本版已完成的适用证据，再在候选版本上补齐原契约的真实采样与完整真实回归，不重做整套选型、接线与报告。

## 4. 保持效率的执行规则

1. **在现有链上接线。** 只改输入、控制、临时准备、交付和受限角色输出所需代码；不重构人格/记忆域，不引入第二套 runtime。外壳与语音服务不打开 PGlite。
2. **一次只准备一份有效候选。** revision 改变就失效；final 到来后重查文本、上下文、证据与授权版本。首版不同时推测整段 LLM 回复和提前 TTS，避免无效算力和额外等待。
3. **遇到组件缺口先限时验证。** Smart Turn 或 KWS 只有现有机制不足时才试；单个可选组件探针以 2–4h 为预算，失败则保留 VAD/规则回退并报告，不拖住其他工作。该预算是重新评估节点，不是自动宣称功能完成。
4. **先完成可见停播，再评估资源节省。** 不强杀 GPU 线程/数据库进程；已提交用户事实和外部副作用不撤销，不重执行。用户抢话总能压过角色短插话。
5. **需要正式持久化或改变冻结边界时先形成具体设计。** 优先复用现有合法事件/元数据；需要新 schema 时只在隔离环境实现与检查，正式库启用按既有受控路径处理，不借简化验收扩大授权。
6. **模型测试集中安排。** 本计划编制期间不启动 CPU/GPU 或麦克风测试；实际进入这些步骤前按用户关于游戏占用的安排先联系用户，等待可测试时段，不后台抢占算力。

执行起点：P1 的慢请求取消与播放回报小探针 → 完成 P1 并交付可试用基础 → P2 确认流式输入路线 → P3 有限插话/纠正 → P4 一次联合验收。各阶段只追加实际进度与必要阻塞，不重复整篇计划。
