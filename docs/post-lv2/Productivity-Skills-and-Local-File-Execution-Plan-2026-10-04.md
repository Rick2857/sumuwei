## 0. 用户决定与当前文件权限结论

本计划记录用户在本轮的最终决定，取代中途“必须逐个明确指定文件操作”的解释：

- 浏览器复用**已有登录账号和网站会话**。
- 本机文件范围为**全部 Windows 当前账户实际可访问的本地文件**，操作包括读取、创建、修改、覆盖。
- 苏沐薇在完成用户下达的任务时，可以**自行选择必要的文件及上述操作**；执行这些已授权步骤不逐个请求确认。
- 任务授权仍沿现有行动链执行。用户本轮要求交付计划书，因此本轮不直接修改生产配置；后续实施沿用上述权限决定，不重复询问相同权限。

### 0.1 现在是否能访问本机文件

**已有本地文件读写功能和沙箱权限；尚未实现全盘文件访问。** 当前代码/配置核查如下：

| 已核实的事实 | 实际含义 |
|---|---|
| `sandbox.file.read/write` 已登记；`sandbox:read/write` 在默认授权清单中；行动总开关代码缺省 on | 当前有低风险、用户驱动的本地读写机制，不是完全没有文件能力 |
| `ACTION_SANDBOX_ROOT` 在当前 `.env` 未设置；代码缺省为 `data/action-sandbox` | 从本工作区启动时默认范围是 `C:\Users\user\Desktop\project LG\data\action-sandbox`；本轮核查该目录尚不存在 |
| 原目标解析拒绝绝对路径、盘符、路径上跳；适配器还检查真实路径包含性 | 不能直接读取桌面、下载目录或任意 C:/D: 路径；不能靠链接跳出原沙箱 |

| 当前 `.env` 四项实用能力开关均为 true，当轮内容额度 3000 | 配置已启用相应适配器；OCR 的未达准确率读数仍单列，不能由开关推成验收全过 |
| 旧 `.txt/.md/.csv/.json` 路由优先，读取结果只返回字节数、指纹、引用，不带正文 | “文件确实读了”还不能保证她能依据普通文本正文回答；本批须补这处接线 |

### 0.2 “完全访问”在工程中的含义

范围覆盖本机各个可访问本地卷中的普通文件，支持中文、空格、绝对路径与目录枚举；不限定为项目目录。任务需要时可以创建目录和文件、修改内容及覆盖原文件。格式理解仍取决于已接入的解析器，文件锁、加密、Windows ACL 和系统保护仍可能导致读取/写入失败。

首版不新增删除、移动、原始磁盘/设备操作；网络共享不属于本轮“本机本地文件”范围。发生访问失败时报告具体失败，不能凭本轮授权宣称拥有管理员或 SYSTEM 权限。

普通文本、文档及登录页正文会按预算进入现有模型调用；使用云端模型时，实际入模片段会发送给该模型服务。执行器据任务定位必要文件和片段，正文及连接 token 不写入账本、trace 或开发者面。

## 2. 先补两个公共缺口

### 2.1 全盘文件授权：新增路径域，保留旧沙箱能力

新增具名 `local.file.list/read/write`，分别授予 `local-file:list/read/write`，只在全盘访问模式启用时构造和授权。旧 `sandbox.file.*` 及其根内判据保留，避免改根目录或删除旧守卫造成全部旧用例含义改变。

具体接线：

1. 新解析器支持本地绝对路径，规范化到确定本地卷和真实文件；重解析点按最终位置判断，拒绝网络/设备路径。目录枚举按任务涉及的目录执行并分页，不在每次聊天扫描全盘。
2. 全盘目标携带真实的本地路径域证据，Policy/trace 不能把它错误描述为“沙箱范围内”。文件多候选时先枚举/定位，取得足够目标证据后再读写，不猜一个执行。
3. 文档/OCR 从同一授权文件读取入口取得字节；增加普通文本/Markdown等到当轮内容通道的明确入口。旧路由及关闭模式保持兼容，不能把只返回字节数的旧读取当成正文已入模。
4. 写入载荷在临时内存/私有暂存中传递，账本参数保存载荷引用、目标和指纹。覆盖前保存原始字节的恢复副本，生成/编辑到临时文件，校验后提交；正文不通过参数预览泄漏。
5. 覆盖时比对读取时的原文件指纹。文件被其它程序改动则重新读取并核对，不能用旧内容覆盖新编辑；恢复副本位置和前后指纹可查。
6. 临时文件、恢复副本由本任务管理。不能随交付清理其它任务文件，也不能把全盘授权用来任意改动生产数据库、语音环境或未涉及的项目状态。

授权范围已由用户决定，不设置逐目录/逐文件二次审批。Windows 实际拒绝访问、文件被占用或内容格式不支持时如实失败。首版恢复保证针对普通文件内容，不宣称所有 NTFS ACL、加密属性、备用数据流都已有完整保真证据。

### 2.2 任务内自主决策：有限分步执行

用户最终授权要求支持“为达到任务目标自行决定”。只保留旧的一轮单动作入口不足以完成“找资料 → 读取 → 生成/修改办公文件”，本批因此增加一个有限任务执行环。

```text
用户任务 → 任务授权（原 user event / taskId / 能力 / 文件范围 / 预算）
         → 模型提出有限动作计划 → 程序校验
         → 逐步 ActionRequest → 既有 Registry / Policy / Gateway / Adapter
         → 实际结果 → 必要时修正后续步骤 → 检查后的任务回复
```

模型可以选择任务需要的文件、目标路径和具体操作；程序依据已授予的任务授权执行，不要求用户把每一步改写为新指令。每次动作仍有确定目标、actionId、traceId、原始任务归因和结果，不能通过伪造 user 消息绕过入口。

执行范围限定为任务内的具体能力：文件操作、天气、办公生成、资讯、浏览器的受控操作，以及任务需要的既有计算/文档/网页/OCR。网页或文件正文无权创建用户任务或扩大授权。普通聊天仍走旧路径，不自动生成全盘任务。

第一版计划一次下发有限步骤，只有缺信息/失败时再规划；避免每读一段文字就新增模型调用。候选预算为每任务 30 次行动、6 次规划调用、10 分钟总时限；超限、取消、断线与重启后如实返回已完成和未完成部分，不假报继续运行。

此任务授权先在内存中绑定当前会话和原任务，不增加数据库迁移或新的长期记忆/目标来源。现有 `ActionTurnPort/TurnGateway` 增加有限结果集合和实际入模片段选择；当前 `TurnContent` 的种类与每轮条数上限要做具名追加及相关回归，不能靠后台循环伪造新轮次规避旧搜索额度。

本地创建/修改/覆盖不逐步确认。浏览器提交、发布、发送、付款等外部操作依据对应用户任务的授权范围判断；本地文件授权本身不替这些操作授予权限。任务已明确授权的外部操作不重复询问，未涵盖的外部变更先准备到可核对状态再处理授权。

## 3. 四项能力的首版执行范围

### 3.1 天气查询

支持指定城市的当前天气、今天/明天及近 7 天预报，优先字段为温度、体感、降水、风和天气代码。请求只发送必要城市/坐标与时间范围；不读取浏览器 GPS 或用聊天片段推断精确住址。

用户明确城市或使用已设定城市时先走地理编码，保留国家/行政区/坐标/时区；同名候选无法确定时先澄清，不取第一条。随后调用固定天气域名，记录预报有效时间、获取时间、单位和时区。当前天气来自所用天气模型的数据口径，不能冒充现场气象站实测。

地理编码与天气获取属于一个具名天气动作的两个固定服务步骤；首版不自动换多个 provider。超时、空值、旧数据、限流分别报告；缓存若启用只做短时内存缓存并显示数据时间。

接口依据：[Forecast API](https://open-meteo.com/en/docs)、[Geocoding API](https://open-meteo.com/en/docs/geocoding-api)。

### 3.2 办公文件生成

支持 **DOCX、XLSX、PPTX**，由模型提供受限结构化内容、可信模板和程序生成文件，不接受模型生成 Python/Shell 代码直接运行。

- DOCX：标题、章节、段落、列表、表格、页眉页脚及任务指定图片；先做报告/说明文档固定模板。
- XLSX：指定工作表、列名、数据、基础格式和必要合计。普通文字以文字写入；公式采用明确类型及有限函数，不把外部正文中的 `=` 自动当公式；不添加宏或外部工作簿链接。
- PPTX：封面、章节、要点、表格和基础图表，先做固定简洁版式；长内容分页/分片，不无限缩小字体塞入一个文本框。

沿已授权任务自行选择必要输入和输出位置，复用全盘文件读取与提交路径；有明确输出路径按该路径执行，未指定时使用固定输出目录和确定命名策略并报告实际路径。覆盖现有文件时复用恢复副本与并发修改检查。

生成后重新打开文件校验指定文本、数字、工作表/幻灯片数和结构，再用现有文档阅读链抽查。三种格式各留一个固定样本，合并进行一次排版查看；没有已验证的渲染器时记录排版查看待办，不能把 XML 可读当成“视觉排版已通过”。不为首版静默安装 Microsoft Office、WPS 或 LibreOffice。

首版交付的是可编辑 Office 文件；PDF 导出、宏、复杂模板修改另做后续切片。初始规模为文档 50,000 字符、表格 10,000 单元格、PPT 20 页、单文件 10 MiB，超出时拆分或报告限制。

### 3.3 资讯阅读

默认按需查询，不增加定时监控或自动推送。支持明确来源/主题的 RSS/Atom 条目、标题/来源/发布日期/摘要，单次最多 3 个订阅源、10 条候选、5 条交付资讯。

用 LG 的受限 HTTPS 获取器取得 XML，再调用 `rss-parser.parseString()`；不让 `parseURL()` 自行处理网络、重定向及 60 秒默认超时。XML 字节、条目数、解析时间受限，拒绝 DTD/实体声明，标题、摘要和链接作为外部资料处理。

按实际发布时间和用户时间范围过滤，发布时间未知时标为未知；同链接/同条目去重，不把转载当独立验证。不采用“以抓取时间冒充发布时间”的补齐方式。

“最新消息概览”允许从 RSS 摘要回答并标明范围；任务要求深读某条时，任务执行环把该条链接交给现有 `web.read`，依据实际取得正文回答。链接来自订阅条目的事实要进入目标证据，不能伪称用户逐字指定了该 URL。动态/付费墙正文不可得时如实标注仅看到摘要；无订阅源时复用现有搜索能力查询。

初始正文仍服从已有 3000 token 总额度；不为每篇资讯额外建立一个模型 agent、向量库或爬虫调度器。

### 3.4 浏览器：复用已登录会话

采用固定版本 Playwright MCP sidecar 加官方扩展；Chrome/Edge 的实际浏览器及 profile 在实施首连时核定。官方扩展通过既有 profile 复用 cookie、登录状态；不是创建一个空白浏览器后宣称登录已继承。[官方扩展说明](https://raw.githubusercontent.com/microsoft/playwright/main/packages/extension/README.md)

首连完成一次 profile/标签选择与扩展连接设置；用户允许后，用该 profile 的本地连接 token 减少重复连接弹窗。token 不写入报告/trace，原始 cookie 不复制到公开文件。此人工首连是扩展的安装连接流程，不是每次任务的审批。

有限操作为打开/导航、页面快照/阅读、确定元素点击、输入/选择和等待结果，以及本任务标签组管理。点击/填写基于当前快照元素引用或唯一匹配；过期引用刷新后重判，多匹配不猜。用户正在使用的标签默认保留，任务在同 profile 专属标签组进行。

LG 专用适配器只连接这个固定 sidecar、只允许已映射的操作和参数；不向模型暴露任意 MCP 工具入口。禁用任意 JavaScript/服务器代码执行、网络头正文抓取、无约束文件访问和全浏览器关闭等非必要工具。需要网站脚本执行时由浏览器正常运行网站脚本，模型没有任意代码执行权限。

浏览器的 URL/域名和实际跳转由 LG 任务范围校验，程序检查读取快照和可见结果，不只相信工具“点击成功”。上游 origin 选项及 MCP 本身不能被描述为安全沙箱，重定向和子资源还要按实际任务检查。[上游边界说明](https://github.com/microsoft/playwright-mcp#security)

**已有具体桌面影响发现**：核对的 `background.ts` 含 `chrome.tabs.update(...active:true)` 和 `chrome.windows.update(...focused:true)`。先测首连与正常动作分别是否触发聚焦；不能承诺官方扩展天然不抢焦点。优先后台任务标签；若正常动作强制聚焦，则对必要激活调用作最小受控修补并保留上游回退版本，重新测桌面不受干扰。未通过时明确记 PARTIAL，不静默切换到丢失登录态的独立 profile。[固定源码](https://github.com/microsoft/playwright/blob/7ad3fba1aad9471c7e46d67a11b0e710a5d77ea8/packages/extension/src/background.ts)

首版不新增通用桌面鼠标键盘控制、任意浏览器插件访问或无范围的多网站代理。上传/下载能力需要具名文件与网站任务接线后追加，不能利用浏览器扩大未登记动作。

## 4. 能力影响矩阵

以下为计划新增，尚未登记。具体浏览器操作不能仅因为上游标了 `readOnly` 就跳过 LG 风险判断。

| 能力 / 操作 | 权限及风险 | 复用 / 新增 | 认知与持久化 | 真实结果 / 行动证据 |
|---|---|---|---|---|
| `local.file.list/read` | `local-file:list/read`；R0；read | 新本地路径域，复用目标/Policy/Gateway；补文本入模 | 正文只进任务/当轮内容 | 真实目录/字节/片段 / 路径域、指纹、入模范围 |
| `local.file.write` | `local-file:write`；R1；write | 复用幂等/目标判据，新增载荷引用、备份/提交 | 目标/前后摘要；不持久化正文参数 | 文件真实变化与恢复副本 / 确定目标、提交结果 |
| `weather.query` | `weather:query`；R1；read | 固定 API + 有界请求，复用内容通道 | 不自动写记忆/位置 | 城市、时间、单位、服务结果 / 来源与实际数据摘要 |
| `office.generate` | `office:generate` + `local-file:write`；R1；write | 已有 Python 环境，新增固定模板/结构化生成 | 产物引用与生成摘要 | 三格式文件可重新打开 / 文件指纹、读回与交付状态 |
| `news.read` | `news:read`；R1；read | RSS 解析 + 既有搜索/深读 | 外部来源不提升为用户事实 | 条目/正文范围真实 / 链接、发布时间、获取时间 |
| `browser.read` | `browser:read`；R1；read | 固定 MCP/扩展的快照与资料读取 | 登录页正文与 token 保持私有 | 指定 profile/标签实际资料 / 实际页面及读取范围 |
| `browser.operate` | `browser:operate`；R2；write | 导航、点击、填写、任务标签操作；目标级授权 | 只记必要状态及操作结果 | 页面变化/表单值读回 / 对应 task/action 和结果 |

任务授权按能力和操作授予对应额度，浏览器 R2 仅在已授权浏览器任务中使用；不为运行浏览器把所有聊天的风险上限统一升为 R2/R3。现有身份、记忆采信、Policy、幂等、账本及回复真相边界保留。

## 5. 工作包与执行顺序

| 工作包 | 交付内容 | 完成判据 |
|---|---|---|
| WP0 基线及固定输入 | 代码/config/环境基线；复用第一批组件；锁 RSS、sidecar、扩展；合成文件和测试网页 | 非空基线与真实版本；不覆盖已有脏文件；没有新依赖时不重复安装 |
| WP1 全盘文件及任务执行环 | 新文件路径域、普通文本正文、覆盖恢复；原任务授权、有限计划、ActionRequest 分步执行 | 模型可以为一个任务自行选文件并读/写；旧沙箱关闭档兼容；越权/取消不执行；真实文件和账本能对照 |
| WP2 天气 | 城市解析、固定天气 API、时间/单位/来源、失败口吻 | 指定城市结果准确读回；歧义不猜；失败不报天气成功 |

| WP6 一次收口 | 组合用例、必要继承回归、真模型短链；一份使用/回滚报告 | 五类状态分列；文件授权、任务自主性及四项能力真实可用；未达/未跑保留 |

WP1 是本批主要框架变更，不再宣称只需要装四个包。后三项业务组件复用同一任务授权、内容预算、文件提交和结果汇总。首版不增加通用插件框架、数据库迁移、人格改动或新后台调度。

## 6. 验收：一个入口，三段完成

### A. 开发短测及最终组合离线验收

计划新增 `scripts/productivity-skills-verify.ts` / `pnpm productivity:verify`，按 `--only files|weather|office|news|browser` 选择。**该脚本/命令尚不存在。** 复用第一批的报告格式及 fixture，避免再为每能力创建 component/e2e/measurement/gates 四套脚本。

固定 **28 组：公共 8 组 + 文件/任务 4 组 + 天气 4 组 + 办公 4 组 + 资讯 4 组 + 浏览器 4 组**；参数化输入逐条计数。

| 组别 | 需要验证的行为 |
|---|---|
| 公共 8 组 | 默认关闭/授权；旧聊天与第一批兼容；目标/路径域事实；正文/token隐私与来源资格；预算/实际入模；取消/迟到；任务归因/操作范围与风险；量具正控/负控/恢复和非空计数 |
| 文件/任务 4 组 | 沙箱外中文/空格/多卷路径读取和正文入模；自主选输入及创建/修改/覆盖；恢复副本与并发修改冲突；OS访问失败/任务取消/无授权任务不写 |
| 天气 4 组 | 已知城市及字段单位；同名候选/未知城市；时区/有效时间/旧数据；限流、坏响应和超时 |
| 办公 4 组 | DOCX读回；XLSX读回与数值/公式类型；PPTX读回与固定版式范围；超限/生成失败/覆盖冲突时原文件保留 |
| 资讯 4 组 | RSS/Atom正常条目；时间过滤/去重/未知日期；按需深读及摘要/全文区分；坏XML/实体声明/网络边界与失败 |
| 浏览器 4 组 | 已绑定会话/任务标签范围；确定元素点击/填写及页面读回；默认禁用工具/超范围导航/断连；登录态继承与焦点/窗口影响 |

每包只做本组短测和实际受影响公共组；组件探针使用的样本直接留作组合验收。最终冻结交付代码/config/fixture 后完整运行一次。新量具三段式放公共组，继承要求的 `m5.1:measurement:verify` 只集中补一次。

文件写入测试使用沙箱外的**合成临时文件**证明全盘路径域生效，不修改真实私人文件来做覆盖试验。浏览器离线/组件测试使用受控页面；现有 profile 的登录态、桌面影响在 C 集中验证。

### B. 必要继承回归：最后完整跑一次

TypeScript 修改后跑 `pnpm typecheck` 与实际影响门，开发中复用 `pnpm fast`/内容缓存及已声明安全并发。新增脚本必须显式执行，不假设旧影响映射能覆盖它。

最终保留 [AGENTS.md](../../AGENTS.md) 要求的串行、无缓存完整 `pnpm m4.5:ci` **一次**；不在五个阶段各跑一遍。公共改动涉及契约/Policy/TurnGateway，相关内核、prompt及行动门在该累积链中去重；如改到开发者面/遥测、桥或交付入口，补对应未包含的门。

集中执行 `pnpm m5.1:measurement:verify`，读取同次 CI 的有效日志完成 `m5.1:gates/regression:verify` 收尾。后者固定读取 `artifacts/m5.1/wp9-m4.5-ci.log`，需保存真实 `EXIT_CODE` 和本次关联，不能误承接旧日志。四项不各跑 `ci:full`；实际需要既有 live smoke 时直接补对应 smoke。

正式发布证据来自固定交付版本、串行无缓存和干净树。当前既有改动先登记，必要时用本任务隔离 checkout；不清理其它任务文件。历史红项与新增回归分列，必跑 CI 退出码非 0 时仍记 FAIL。

### C. 一次真模型短链和一次首连/排版核对

固定 **8 个任务场景**，正常文件/办公闭环同时验证自主文件决策：

| 场景 | 实际要看到的结果 |
|---|---|
| 1 天气成功 | 指定城市、固定日期范围、真实天气 API；可见回复与结果的单位/时间一致 |
| 2 天气降档 | 同名目标或失败响应；不猜城市、不编天气数值 |
| 3 文件 + 办公成功 | 一个用户目标；自主读取沙箱外合成输入、选择步骤、生成三格式并覆盖一个合成文件；读回、恢复副本与账本一致 |
| 4 文件 + 办公失败 | 目标不可写或并发冲突；原文件保留，不声称产物已保存 |
| 5 资讯成功 | 固定真实源，概览 + 任务要求的一条深读；发布日期/来源/实际阅读范围正确 |
| 6 资讯失败 | 坏源/无正文；不给假全文结论 |
| 7 浏览器成功 | 已授权 profile 中真实已登录任务页，确定元素读取/填写并读回；账号与会话状态确实继承 |
| 8 浏览器失败 | 扩展断连、过期元素或未绑定标签；如实失败，不继续其它标签/页面 |

使用现有 `with-test-model` 包装器和隔离库；本批测试不打开生产记忆库。八个场景包含规划、动作和最终回复，**不是八次 API 调用的保证**；优先一次规划批量执行，逐次记录真实模型调用/token/重试，预算到限时记未完成而不扩跑凑 PASS。

首连/profile选择、已登录页核对及三格式排版抽查集中一次进行，不安排多轮盲审或另一个大模型评分器。没有拿到真实登录态/排版/焦点读数的项记录 NOT RUN/PARTIAL，不能用受控测试页或上游说明代替。

## 7. 交付与回滚
