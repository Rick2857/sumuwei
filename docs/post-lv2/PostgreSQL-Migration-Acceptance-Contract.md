# PostgreSQL 迁移：验收契约（第一阶段）

日期：2026-10-12（Asia/Shanghai）。状态：**DESIGN FROZEN**（WP0 交付；实现未开始）。
上游：[执行计划](PostgreSQL-Migration-Execution-Plan-2026-10-12.md) ·
[ADR-132](../adr/ADR-132-postgresql-migration-backend-and-activation.md) ·
[WP0 基线](PostgreSQL-Migration-WP0-Baseline.md) · [门矩阵](PostgreSQL-Migration-Gates-Matrix.md)。

本契约把计划 §5 的"门"、§6 的"迁移比较规程"与 §9 的"完成判定"翻译成**可判定**的断言。
它同时是一份**负清单**：什么**不算**证据（§5）。二者同等重要 —— 本仓库反复记录的失败形状，
正是"看起来绿了，其实量的是别的东西"。

## 1. 判定分的槽（不许合成一个总分）

按计划 §9 逐字，结论必须**分列**。本契约固定下列槽位与它们的命名（收口文档必须逐槽填，缺项写 `NOT RUN`）：

| 槽 | 名字 | 由什么填 |
|---|---|---|
| `S1` | 设计 | ADR-132 的状态与裁定数 |
| `S2` | 实现 | WP1–WP6 的实际改动路径清单 |
| `S3` | PGlite 旧门 | 既有门在**未设 PG 后端**时的读数（回归适用性） |
| `S4` | 真实 PG 门 | `PG-G01…G09` 各自的 runId 与 measured_count |
| `S5` | 量具 | `PG-G09` 三段式（正控 / 负控 / 恢复） |
| `S6` | 数据副本 | WP5 的完整性比较读数 |
| `S7` | 真模型链 | 受控真模型 smoke（隔离 PG + 指定测试模型） |
| `S8` | 资源读数 | 时延 / 连接数 / CPU / 内存 / 磁盘 / 备份耗时 |
| `S9` | 恢复演练 | 备份 → 新目标恢复 → 比较 |
| `S10` | 生产切换 | `PG-P01` |
| `S11` | 在线运维 | 核心运行时的独立查询与备份 |
| `S12` | 首次使用 | 真实轮次（**未观察到就写 NOT OBSERVED**） |
| `S13` | 长期运行 | 独立观察，不由配置或隔离 smoke 推定 |
| `S14` | 多写进程 | **第二阶段**，不因第一阶段完成而 PASS |

**硬规则**：任一关键门 `FAIL` / `NOT RUN` ⇒ **不得**汇成 PASS。`S12/S13/S14` **不得**由
配置存在、隔离 smoke 通过或计划书写得好来推定。

## 2. 每个门的通用形状（`measured_count > 0` 是入场券）

对 `PG-G01…G09` 与 `PG-P01/P02` 的**每一条**，收口时必须能回答：

```text
① id                    门标识（PG-G0x）
② runId                 本次运行的唯一标识（UTC 时间 + 短摘要）
③ backend               实际后端（pglite | postgres）—— **不是配置声明的，是连接后读回来的**
④ target identity       脱敏身份：database / user / host / port / server_version / 扩展版本
⑤ commands + exit codes 实际命令与退出码（逐条）
⑥ measured_count        实际执行的断言条数（**>0**）
⑦ passed / failed       逐条计数
⑧ not_run               未运行项，**具名**列出来
⑨ evidence path         artifacts/post-lv2/postgresql-migration/<runId>/ 下的文件
⑩ source fingerprints   HEAD + 相关源码指纹（工作树 dirty 时必须按内容记）
```

**缺 ①②⑥⑨ 任一项 ⇒ 该门判 `INVALID`（不是 `FAIL`，也不是 `PASS`）**，且 `INVALID` 不得当绿用。

## 3. 逐门断言

### PG-G01 配置与隔离

**必须通过**：

```text
G01.1  backend=postgres 且 POSTGRES_URL 为空/空白          ⇒ db_postgres_url_missing，**退出码非 0**
G01.2  POSTGRES_URL 有值 但 backend 未设/pglite            ⇒ postgres_url_without_backend，拒绝
G01.3  backend 非法值（'postgresl' / '' / 'pg'）           ⇒ db_backend_invalid，拒绝（不做拼写纠正）
G01.4  祖先目录 .env 里塞 POSTGRES_URL                     ⇒ **实测**它是否被读到；读到了且未授权 ⇒ 拒绝
G01.5  指向一个**存在的但错误**的数据库（如 postgres 系统库）⇒ db_identity_mismatch，在**写入前**拒绝
G01.6  生产 URL 被继承到"已隔离"的实验脚本                 ⇒ isolateDatabase() 拒绝（db_postgres_isolation_not_provided）
G01.7  同进程第二个目标（不同 connection string）          ⇒ 拒绝，或走**已验证**的隔离实现
G01.8  拒绝发生在**任何** CREATE / INSERT / ALTER 之前     ⇒ 以服务端日志或"目标库表数未变"证明
G01.9  日志与证据里**不出现**密码或完整凭证 URL             ⇒ 对证据文件做静态扫描
```

**负控（必须真的做）**：把 `D02` 的四条判定各自**摘掉一条**，门必须变红；恢复后变绿。
**`measured_count > 0`**，且 `G01.1…G01.9` 每条至少 1 次实测。

### PG-G02 schema 与权限

```text
G02.1  全新隔离 PG 从零可运行（迁移账号 bootstrap → 运行账号启动）
G02.2  待迁移而**未放行**时 ⇒ 拒绝启动（沿用既有 kernel 迁移闸语义）
G02.3  并发两个迁移执行者 ⇒ 只有一个执行（advisory lock 互斥），另一个如实等待/具名拒绝
G02.4  普通启动**不**自动应用 kernel 迁移（沿用 `--migrate/--migrate --apply` 的显式口径）
G02.5  lg_runtime 执行 DDL ⇒ 拒
G02.6  lg_readonly 执行 INSERT/UPDATE/DELETE/CREATE ⇒ 全拒（**靠 GRANT 造成的拒绝**）
G02.7  lg_readonly 执行插件迁移 ⇒ 拒
G02.8  lg_test 连生产库 ⇒ 拒
G02.9  事务失败回滚：故意让迁移第 N 条失败 ⇒ 不留半个 schema（与既有 `applyKernelMigrations` 的原子性一致）
```

**负控**：把 `lg_readonly` 临时提权为 owner ⇒ `G02.6` 必须**变红**（证明这条门量的是权限，不是"碰巧没做"）。

### PG-G03 生命周期与写入资格

```text
G03.1  正常退出：只关本进程连接池；**服务继续可用**（另一个只读 OS 进程随后查询成功）
G03.2  初始化失败退出：不留悬挂连接、不留下"以为在跑"的状态
G03.3  锁连接丢失（模拟：终止该连接 / 断网）⇒ 停止接收新轮次 + 取消未提交工作
G03.4  在飞任务晚返回 ⇒ 有可审计结果（不静默丢弃、不静默提交）
G03.5  第二核心 ⇒ 拒绝（资格锁）；**只读**与**备份**连接**仍可进入**
G03.6  服务器重启 ⇒ 核心重连；重连后资格重新建立或如实拒绝
G03.7  关闭判据 = 关闭 Promise 成功 + 本进程会话释放（**不是** isClosed 标记）
G03.8  `D12` 的两个缺陷：旧实现（清 Map 不关池 / PGlite 管理器为空就早退）在门里**必须判红**
```

**必须由两个真实 OS 进程完成**（计划 §5 逐字）。单进程"模拟第二个核心"**不算**。

### PG-G04 SQL / 仓储兼容

```text
G04.1  JSON/null：jsonb 列的 null 与"空对象"可区分；读回形状与 PGlite 一致（按契约列规范化）
G04.2  bigint 边界：0 / 1 / 2^53-1 / 2^63-1 / 负数 的写入与读回形状（**注意 pg 的 int8 默认返回字符串**）
G04.3  RETURNING：`... returning *` 的行数与内容正确（含 UPDATE 影响 0 行的情形）
G04.4  唯一索引 / **部分**唯一索引：含 null 行与"被部分索引排除的行"的边界
G04.5  幂等：同 idempotency key 重复提交只落一行
G04.6  乐观冲突：revision 不匹配 ⇒ 0 行返回 ⇒ 上层如实报冲突（不覆盖）
G04.7  事务原子性：多语句中途失败 ⇒ 全部回滚
G04.8  Memory / Conversation / Event / Job 四类仓储**真实执行**（不是纯 SQL 探针）
G04.9  向量：`vector(384)` 的写入与 `<=> / <#>` 查询走**显式** `::vector` cast（`D09`）
```

### PG-G05 迁移完整性

```text
G05.1  完整表清单一致（来源 51 张 public 基表 → 目标同集合；缺一张即 FAIL）
G05.2  主键集合一致
G05.3  规定字段摘要一致（规范化 JSON / 时间 / 数字编码）
G05.4  来源 / 归因 / 更正撤回链完整（不忽略 retracted / corrected 历史）
G05.5  记忆生命周期字段完整（不物理丢弃）
G05.6  消费者水位与序号完整（**不**推进水位来跳过问题）
G05.7  插件历史（agents / memories / rooms / participants / entities / worlds / embeddings）完整
G05.8  无主键表用**稳定行多重集**比较（不只比总数）
G05.9  迁移登记表 `character_schema_migrations` 的行集合与来源一致（18 行）
```

### PG-G06 投影与语义召回

```text
G06.1  领域投影重建 A == B（先记录恢复后投影，再在**另一个**一次性目标重建并比较）
G06.2  向量代 / 维度 / 数量一致（含 vector 扩展版本差异的显式记录：来源 0.8.0 → 目标 0.8.7）
G06.3  相同向量 ⇒ 固定查询 ID / 距离核对
G06.4  等距结果按**集合**比较（不比顺序）
G06.5  不重新编码凑一致（编码器指纹不变）
```

### PG-G07 在线备份恢复

```text
G07.1  核心活动时备份成功（不停止核心）
G07.2  恢复到**新的**空目标成功
G07.3  篡改备份 ⇒ 拒收（具名原因）
G07.4  截断备份 ⇒ 拒收（具名原因）
G07.5  数据库外资产按 manifest 验证
G07.6  比较基于**同一逻辑快照或受控写入屏障**（不拿"备份开始前"或"仍在变化的实时源"随便比）
G07.7  源身份与目标身份在恢复后**分开**记录（不把备份源身份当目标部署身份）
```

### PG-G08 功能整链与回归

```text
G08.1  记忆增 / 改 / 撤回 端到端
G08.2  认知恢复（水位 / 投影 / 消费者）
G08.3  后台消费者续跑
G08.4  通知与提醒（含 `deferred_until` / `repeat_mode` / `repeat_attempt`）
G08.5  QQ / Live2D 两条入口的路由
G08.6  重启后续跑
G08.7  外部发送在测试中**受控**，**不向真实联系人发测试消息**
G08.8  `pnpm typecheck` EXIT 0 · `pnpm m4.5:ci` EXIT 0
```

### PG-G09 量具有效性（三段式）

```text
G09.1  正控：比较器对"应当一致"的两份数据判一致
G09.2  负控（每条**只改一处**，且各自具名）：删一条事件 / 改一个归因 / 回退一个水位 / 改一个向量维度
       ⇒ **每一条都必须让比较器失败**，且失败原因**互不相同**
G09.3  恢复：把改动还原 ⇒ 又一致
G09.4  只读聚合器校验：源指纹 / 后端 / 配置 / run 归属 —— 不适用就拒收（不是"跳过"）
G09.5  **mtime 不决定选档**（沿用 `TD-23` 的既有裁定与 `scripts/m10.1-gate-select.ts` 的身份优先口径）
```

### PG-G10 切换就绪（只读审查）

```text
G10.1  PG-G01…G09 全 PASS（逐条给 runId，不接受"上一次跑过"）
G10.2  旧后端回归适用性：未设 PG 后端时既有门仍绿（S3）
G10.3  恢复演练成功（S9）
G10.4  Runbook、目标身份、停机估计、回滚条件完整（WP6）
G10.5  两条回滚路线（`R0` / `R1`）各自的**可用性**明确（计划 §8）：R1 到底是"PG 内修复"还是"已验证反向迁移"
```

### PG-P01 生产执行（WP7 专属）

```text
P01.1  最终源快照合格（旧核心排空关闭之后、cleanClose=true、manifest 在）
P01.2  导出 / 恢复到目标成功，每步退出码在案
P01.3  数据读回在**业务启动之前**完成
P01.4  实际连接身份与配置一致（读回，不是声明）
P01.5  单核心资格成功；**不得**承接早期副本读数替代最终检查
P01.6  无双写（任何时刻只有一个权威）
```

### PG-P02 生产使用（WP8 专属）

```text
P02.1  真实往返（真实轮次）
P02.2  实际 trace / 事件
P02.3  在线只读查询与备份**同时**成功
P02.4  正常重启：核心重启**不迫使数据库停机**
P02.5  未观测的功能**明确 NOT OBSERVED**（不许用"配置在"代替"用过"）
```

## 4. 数据迁移与比较规程（计划 §6 的可判定化）

| 步 | 规程 | 判定 |
|---|---|---|
| 1 选择来源 | 用有 manifest、内容摘要与合格关闭归属的 verified snapshot；先校验再复制为**一次性源** | 无合格快照 ⇒ **记录阻塞**，不得边运行边复制 `data/pglite` |
| 2 源清单 | 在副本里读引擎/schema/扩展/表/约束/索引/序列/角色/关键计数 | 物理快照**只证明来源**，不当 PGDATA |
| 3 导出 | 官方 pgDump 工具（已在合成库验证兼容）；记工具版本/参数/退出码/dump 摘要 | 覆盖完整应用对象；系统/扩展对象排除**逐条说明原因** |
| 4 空目标恢复 | 先验目标身份与"允许初始化"用途；预装扩展；恢复完整 SQL 并检查**所有**错误 | **不得**先用 runtime 建同名表再忽略导入冲突 |
| 5 权限与身份绑定 | 源 owner/ACL/search_path/扩展版本 → 目标账号**显式映射**；恢复后**重设**目标部署身份 | 全局角色与库外资产**独立**恢复步骤 |
| 6 完整性检查 | 按主键排序 + 规范化 JSON/时间/数字 计算摘要 | 只有契约列明的派生更新时间或新目标元数据允许差异，**逐项解释** |
| 7 可恢复性检查 | 先记恢复后投影 → 在另一个一次性目标重建并比较 | **不得**用重建覆盖首次发现的不一致；pending/running/未知投递态按原规则处理 |
| 8 只读与业务验收分开 | 最终生产导入读回在业务启动前完成；隔离演练才跑合成消息 | 真实生产首轮只执行**已授权的真实使用** |

**schema 落后于代码时**（计划 §6 末段）：
先以**源 schema** 完成一致性比较 → 再**独立**预览/执行新增迁移与比较允许变化。
**不把**导入、schema 升级、重算、数据修复揉成一个无法对账的步骤。
`origin` / `cutover` / 水位 / generation / namespace **保持原值**。

## 5. 什么**不算**证据（负清单）

这一节与前三节同等重要。下列每一条在本仓库都有对应的历史事故或已登记教训：

```text
N01  PGlite 门变绿 ⇒ **不算** PG 证据（计划 §5 逐字："不得把 PGlite PASS 当作 PG PASS"）
N02  "表数一样" ⇒ 不算完整性（要比主键集合与规范化字段摘要，无主键表要按稳定行多重集）
N03  "总数一样" ⇒ 不算完整（删一行加一行总数不变）
N04  "配置里写了 postgres" ⇒ 不算后端是 PG（必须连接后读回 current_database/current_user）
N05  "代码里 AGENTS.md 写着 v16" ⇒ 不算来源版本（必须从合格快照副本读回；本轮已读为 v18）
N06  "mtime 最新" ⇒ 不算证据归属（TD-23 的既有裁定，沿用身份优先）
N07  "进程看不到了" ⇒ 不算合格关闭（必须有 cleanClose 与 post-final 快照）
N08  "恢复成功" ⇒ 不等于"零数据损失"（PG 内从备份恢复会丢掉备份后的写入；计划 §8 逐字）
N09  "备份文件名叫 backup" ⇒ 不假定安全（可能含私人历史 ⇒ 归 `local/` 或已忽略目录）
N10  "advisory lock 拿到了" ⇒ 不算完整失效保护（D05 逐字）
N11  "把目录快照那套套到 PG 连接上" ⇒ 不算适用（INV-DB-01…07 是 PGlite 归属）
N12  "'没结果'/'超时'" ⇒ 不等于"没有数据"（要区分"查到但为空"与"没查成"）
N13  "在运行中复制 PGDATA" ⇒ 不算可恢复备份（INV-DB-02 的同一条纪律）
N14  "单进程模拟第二个核心" ⇒ 不算 PG-G03（计划 §5 要求两个**真实 OS 进程**）
N15  "把 `POSTGRES_URL` 设给了测试" ⇒ 不算隔离（还要证明它**不等于**生产目标，且在生产侧被拒）
```

## 6. 退出条件（计划 §9 的四张判定表，逐字保留并加可判定化）

| 判定 | 必要条件 |
|---|---|
| **隔离实现完成** | WP0–WP5 完成 · `PG-G01…G09` PASS · `typecheck` + `m4.5:ci` EXIT 0 · 局限与失败档齐备 |
| **切换候选就绪** | WP6 完成且 `PG-G10` PASS · 实际命令、源/目标和回滚边界**具体可审查**（无待猜的命令） |
| **生产迁移完成** | WP7 完成、`PG-P01` PASS · 实际权威已切到 PG · **无双写** |
| **第一阶段验收完成** | WP8 必选场景通过 · 首用**按实际功能列明** · 长期运行**仍独立观察** · 多写核心**仍属第二阶段** |

**四张表之间的硬边界**（不许越级）：

```text
· "隔离实现完成" ≠ "切换候选就绪"：后者还要 Runbook 与具体可审查的生产命令
· "切换候选就绪" ≠ "生产迁移完成"：切换是**独立授权动作**
· "生产迁移完成" ≠ "第一阶段验收完成"：验收要在**生产**上观察真实使用
· 任何一张表通过 ⇒ **不自动**打标签、合并或推送（计划 §9 逐字）
```
