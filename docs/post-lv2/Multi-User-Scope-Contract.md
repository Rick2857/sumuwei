## 0. 地位

```text
本契约回答：  谁（principal）· 为了什么（purpose）· 在哪个空间（room）· 能读/写什么、不能做什么
本契约不回答：怎么建表、怎么落 RLS、怎么改入口、怎么做后台页面   —— 那些是 U1/S1/G1/A1/A2
冲突时：      以 ADR-133 的 D01–D22 为准；本文件是它的可查表
```

⚠️ 一处**不许混**：`owner` / `subject` / `source` 是**语义归属**，不是**可见性授权**。
本契约的全部判定都建立在**来源域 + 披露类别**上，不建立在"这条记忆讲的是谁"上。

## 1. 主体、用途、空间（ScopeContext）

```text
ScopeContext := {
  principal : Principal
  purpose   : Purpose
  room      : Room
}

Principal :=
  | { kind: 'owner';  userId: UserId; verifiedBy: 'config_binding' | 'admin_session' }
  | { kind: 'user';   userId: UserId; verifiedBy: 'onebot_inbound' | 'admin_session' }
  | { kind: 'system'; subsystem: 'affect' | 'relationship' | 'belief' | 'reflection'
                                | 'goal' | 'rollup' | 'proactive' | 'scheduler' }

Purpose := 'external_query' | 'internal_cognition' | 'admin_operation'

Room :=
  | { kind: 'private'; userId: UserId }
  | { kind: 'group';   groupId: string }
```

**硬约束**

| 编号 | 约束 |
|---|---|
| `SC-01` | `ScopeContext` **只能**由后端可信身份生成；入口层**不得**接受调用方自报的 principal/room |
| `SC-02` | 在**同一事务/固定连接**内设置并使用；请求完成/取消/异常后**必须清除**，不得残留到下一个请求 |
| `SC-03` | 缺 principal、缺 purpose 或 purpose 与 principal 不匹配 ⇒ **拒绝**（fail-closed），不回退默认用户 |
| `SC-04` | 后台处理携带**发起时**的 principal/purpose/room，**不得**用"执行时的当前用户"覆盖 |
| `SC-05` | `system` principal 的 purpose **只能是** `internal_cognition`；持 `external_query` 即拒绝 |

**身份解析规则**（D04）

```text
QQ 入站 user_id (= external_id)  ──user_identity_mappings(transport='qq')──▶  UserId
同一 QQ 的私聊与各群发言 ⇒ 同一 UserId；群号只决定 room，绝不写进 user_id
self_id / 重连 / 群名片 / 昵称 / 会话 ID / 自报身份 / 客户端字段 / 模型声称 ⇒ 均不作身份依据
```

## 2. 权限矩阵

行 = principal（× room 语境），列 = operation。`✓` = 允许，`✗` = 拒绝（fail-closed），`△` = 条件允许。

| operation | owner（自己私聊/后台） | 普通用户（自己的私聊） | 普通用户（群 G 成员） | system（内部认知） |
|---|---|---|---|---|
| 读**自己**的私聊记忆/记录 | ✓ | ✓ | ✓（仅其**本人**私聊来源） | △（仅按消费者用途） |
| 读**他人**私聊记忆/记录（原文） | ✓（独立审计入口） | ✗ | ✗ | ✗（**不得**把原文回吐给任何用户） |
| 读**当前群** G 的群内资料 | ✓ | ✓ | ✓（仅 G，不跨群） | △ |
| 读**其他群** H 的群内资料 | ✓ | ✗ | ✗ | △ |
| 人物印象查询（对自己/他人/原主人） | ✓ | △（**门槛满足后**，见 §5） | △（同门槛，检查**提问者**） | ✗（不是查询面） |
| 情绪状态（她此刻的心情）可感知 | ✓ | ✓ | ✓ | ✓（内部） |
| 情绪**成因**（他人私聊正文） | ✓（独立审计入口） | ✗ | ✗ | ✓（内部，不回吐） |
| 写入自己的记忆（真实自述、证据充分更正） | ✓ | ✓ | ✓ | ✗（写入走既有归属链） |
| 写入/修改**他人**记忆 | ✓（受控、留痕） | ✗ | ✗ | ✗ |
| 修改**关系**值 | ✗（`MAINTENANCE_INJECTION` 失败关闭） | ✗ | ✗ | ✗（只由真实互动事件驱动） |
| 修改**永久人格 / Seed / 权限 / 预算** | ✗（须独立流程 + 版本/指纹） | ✗ | ✗ | ✗ |
| 新开档 / 换档 / 重置关系 | △（原主人**具名、可信、留审计**的管理通路） | ✗ | ✗ | ✗ |
| 工具/动作（桌面、全盘、数据库、凭证、高风险出站） | ✓（按既有授权轴） | ✗ | ✗ | ✗ |
| 受控查询类工具（搜索等） | ✓ | ✓（**部署总账**内，见 §7） | ✓（同总账，**每群/每用户限频**） | ✗ |
| 受控演戏（表达层） | ✓ | △（关系性演戏：提问者已建档，有效双 >0.25；范围见 S0） | △（同） | ✗ |
| 管理后台只读（总览、trace、状态） | ✓ | ✗ | ✗ | ✗ |
| 管理后台可操作（启停、备份、重试） | ✓（按已授能力 + 审计） | ✗ | ✗ | ✗ |

**判定顺序（每一步失败即拒，不继续）**

```text
① principal 可信？        （SC-01/SC-03）      否则 deny(identity_unverified)
② purpose 与 principal 匹配？（SC-05）         否则 deny(purpose_not_granted)
③ room 是否在授权集？      （群白名单 / 私聊归属）否则 deny(room_not_authorized)
④ operation 是否在该格 ✓/△？                   否则 deny(operation_not_permitted)
⑤ △ 的条件满足？（印象门槛 / 额度）            否则 deny(condition_not_met)
⑥ 所有候选/输出仅来自 authorized room 集       否则 deny(scope_leak)
```

⚠️ **群管理员身份不参与任何一步**：它是平台角色，不是 LG principal。

## 3. 可见性归属模型（D07）

```text
VisibilityLabel := {
  originRoom : Room                 // 写入时的来源域（private:userId | group:groupId）
  disclosure : DisclosureClass      // 披露类别
  audience   : AudienceRule         // 谁可以读（按 room 集/关系条件）
}

DisclosureClass :=
  | 'private_to_origin'   // 默认：只有来源域的本人（+ 原主人在独立通路）可读
  | 'explicit_shared'     // 显式分享：保留授权范围与可追溯记录
  | 'public_to_room'      // 该群内公开
  | 'character_internal'  // 只进内部认知，永不原文外泄
```

**铁律**

```text
VL-01  写入时打标；标签缺失 ⇒ 按 'private_to_origin' 处理（最保守），不提升为公共
VL-02  "内容讲 B" ≠ "B 可读"（subject 不是 audience）
VL-03  'explicit_shared' 必须记录：谁在何时向哪个 room 分享
VL-04  更正/撤回/去重/重建必须携带同一标签；不回写已发布事件
VL-05  无法确定归属的**旧**记录 ⇒ 不向任何新用户开放为原文（D21）
VL-06  附件/图片/日志/trace/导出/恢复与正文同标签同判定
VL-07  身份归属**改绑失败关闭**：`conversation_identities` / `user_identity_mappings` 的归属变更
       不得走静默 `on conflict do update`（现状 `identity-store.ts:194-199` 允许静默改绑，
       唯一防护在 `actor-resolver.ts:140-147` 而它在生产链路上不执行 —— 见 ADR-133 `G9`）
```

## 5. 条件印象通路（D10）

**门槛检查提问者与苏沐薇的关系**（不检查被问对象）。门槛建立在**已有维度**上，
不新造"好感度"：

```text
门槛机制（R-X0-1 已由用户于 2026-10-13 裁定；R-X0-3 仍待裁定）：
  关系投影 relationship:user:<askerUserId> 必须 originated
  取读时有效值（含衰减）后的 closeness / trust
  T_IMPRESSION_TRUST = 0.4；T_IMPRESSION_CLOSENESS = 0.4
  必须 trust > 0.4 AND closeness > 0.4（严格大于；任一恰好 0.4 均不通过）
  是否额外叠加时间/互动次数条件：**已裁定：首版不叠加**（R-X0-3，2026-10-13）
```

**候选阈值只能取自既有分带**（`relationship.ts:320-333` 已冻结的渲染边界，不新造刻度）：

| 边界 | closeness 既有语义 | trust 既有语义 |
|---|---|---|
| `≥ 0.8` | 觉得对方非常亲近，是自己人 | 非常信任对方，几乎不设防 |
| `≥ 0.6` | 和对方很亲近 | 比较信任对方 |
| `≥ 0.4` | 与对方有一定距离感 | 信任程度一般，会保留一部分判断 |
| `≥ 0.2` | 和对方比较疏远 | 不太信任对方，会提防 |
| `< 0.2` | 感觉与对方已经很生疏 | 几乎不信任对方 |

⇒ `R-X0-1` 复用上表里的 **0.4** 边界，按用户原话采用**严格大于**；
既有渲染分带的 `≥` 判定保持不变，印象授权判定单独使用 `>`。

**新用户初始关系（同次用户裁定）**：获准的新用户首次幂等建档时，
`trust = 0.2`、`closeness = 0.2`。不继承原主人的 `0.85/0.60` 设定基线；
原主人既有关系及其他已建档关系不重置，跨群/私聊、重连与重启不重播初始值。
建档事件的来源资格与冻结层影响在 U1 设计中明确，不用管理员注入绕过既有关系链。

**印象输出允许字段（R-X0-2，2026-10-13 已按建议裁定）**

| 允许 | 说明 | 例 |
|---|---|---|
| 她的概括判断（自然语言） | "我觉得他……" | "我觉得他比较认真" |
| 关系维度的**定性**表述 | **不**回吐数值/排名 | "还在认识中" · "接触不多，暂时说不好" |
| **具有明确披露资格**的属性 | 收紧点：**不**由模型自行认定某件事不算隐私 | 公共/当前 room 且提问者有权的材料 |

| **禁止** | 说明 |
|---|---|
| 关系数值 · 排名 | 任何形式的数值/位次回吐 |
| 私聊逐字记录 / 可反查原文的引用 | 无论门槛多高 |
| 秘密细节 · 具体私聊事件 | 包括从全局情绪成因反推 |
| 原文链接、消息 ID、可定位到具体消息的坐标 | 形式上含 ID/时间戳/索引 |
| 无依据的编造 | 无依据 ⇒ 明说"说不好"，**不**编 |

**边界（原主人逐字要点）**：内部经历**可以**影响她的印象，但概括仍须遵守保密范围 ——
"他比较认真"可以；借印象透露某人的**疾病、家庭矛盾**等**不可以**。

⚠️ 印象**不产生**记录查询权限；不得用"印象"请求逐字引用、秘密细节或原文链接绕过记录权限。

**`R-X0-3`（2026-10-13 已按建议裁定）**：首版**不叠加**固定互动轮数门槛。
理由：0.2/0.2 → 双维度严格 > 0.4 本身已形成积累要求；再加"聊满多少轮"易被刷，且引入计数与去重规则。
先保证关系变化来自**真实、合格的互动证据**；若实测门槛过快被触达 ⇒ **处理具体原因**，不加计数闸。

## 6. 群披露（D11 / D17）

```text
GD-01  群 G 的原文不默认向群 H 或不具访问权的私聊开放（room 隔离）
GD-02  显式分享保留授权范围与可追溯记录；不把原始私有来源改成公共
GD-03  原主人在群 G 中 @机器人 ≠ 向全群展示其可查的私人记录
GD-04  首版特权原文查询限定：原主人私聊 / 后台
GD-05  群里问印象同样检查提问者关系与输出范围
GD-06  匿名/系统事件不得冒充个人长期记忆来源；群内提及 B ≠ B 亲口确认
GD-07  跨群、转私聊、主动提醒不自动获得许可
GD-08  退群/禁用群/成员权限变化 ⇒ 在飞与待发送任务重新校验目标与授权
GD-09  **群回复必须按"全群受众"检查披露权限** —— 不得因提问者能读自己的私聊记录，
       就把这些记录公开到群里（R-X0-4 的**新增硬要求**）
```

**群首版触发方式与记忆范围（R-X0-4，2026-10-13 两批均已确定）**：群白名单内保留明确
`@机器人`、回复机器人消息触发，并增加**提到她名字时，按语境判断是否回复**。
名字命中只是候选，不是必回指令：区分直接呼唤/向她提问与第三人称谈论、引用转述；
无法确定是否向她说话时不自动回复。回复目标、权限与预算仍由程序约束，
