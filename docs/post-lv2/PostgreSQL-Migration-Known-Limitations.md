# PostgreSQL 迁移 · 已知局限（Known-Limitations，WP6）

> 这份文件写的是**这套迁移方案不保证什么**。销账条件写在每条后面。

---

## A. 备份与恢复（计划 §L186 逐字要求如实记录）

```text
L-PG-01  备份是**按需 `pg_dump`**，**不是定时**⇒ **RPO = 上一次备份之后的写入**。
         当前**没有** PITR / WAL 归档 / 异地备份 —— 三者**未验**（计划把它们划到第二阶段）。
         销账：定时备份 + 恢复演练 + RPO 读数。

L-PG-02  **恢复成功 ≠ 零数据损失**。R1 是快照恢复，恢复点之后在 PG 里的写入会丢。
         销账：不销 —— 这是快照恢复的定义；只能靠缩短备份周期把窗口变小。

L-PG-03  反向迁移（PG → PGlite）**不是**默认附带能力，**未实现也未验证**。
         销账：若真需要，另立一包做"已验证反向迁移"。
```

## B. 本次迁移没有覆盖到的面

```text
L-PG-04  迁移完整性只做到**规范化内容摘要**级别：14 张**空表**两侧 0 行 ⇒ 只证结构性一致；
         **无 numeric 列、无 bytea 列** ⇒ 这两类类型的跨驱动等价**没在真数据上验证过**。
         （比较器**有** `canonicalDecimal` 与编码判据，但那是**预防性**的。）

L-PG-05  向量面只有 **5 行 / 3 条记忆 / 3 代**（`embeddings` 表 0 行、6 个 vector 列全 NULL）
         ⇒ **不主张**"向量路径在真实规模上验证过"。

L-PG-06  等距（tie-break）场景用的是**合成夹具**（3 条 2 维向量）；真实那 5 行里没有并列。
         ⇒ 主张的是"判据在等距时按集合比"，**不是**"真实数据上出现过等距"。

L-PG-07  `PG-G07` 的"活动"是**并发写入进程**，**不是真实核心**；逐表只做到**行数**一致
         （内容级由 `PG-G05` 承担）。

L-PG-08  资源读数（S8）是**单机、容器化、这一档规模**上的读数 ⇒ **不主张**任何性能结论；
         计划逐字"未设性能收益目标"，门里也有结构性断言禁止判优字段。
```

## C. 消费者与后台

```text
L-PG-09  后台消费者只验证到**两轮 tick**（`mode` 闸 / 隔离 provider / 幂等 / 水位只进不退）
         ⇒ **不主张**"长跑"（真实 tick 循环 + 在飞任务 + 崩溃恢复窗口）。

L-PG-10  双入口路由验证到**纯函数层 + 库层**（两个入口的消息落在两条会话里）
         ⇒ 未在**真实 ChatSession 装配**上跑双入口共存（那属 WP3 余项 / WP6 演练）。
```

## E. 量具自身的局限（本线踩过的）

```text
L-PG-13  点采样（`pg_stat_activity` 看后端/连接）会**时红时绿**；子进程 stdout 会**成块缓冲**。
         ⇒ 并发类判据一律改挂**直接证据**（探针表行数在长）。`F-WP5-16`。

L-PG-14  `G06.1m` 的判据**换过方向**（从"归因差异存在"改成"守修复的回归"）——
         这是**换方向**不是放宽，但读历史证据时要看清它是哪一版。

L-PG-15  本工作区**多会话并行**改动（lock 文件、依赖版本、约 15 条不属于本线的脚本）
         ⇒ `m4.5:ci` 的绿是**混合树**上的绿；单看它不能证明"只有本线的改动"。
```

## F. 实施后回归适用性（**已给读数与处方**，2026-10-13 更新）

```text
L-PG-16  **旧后端（PGlite 归属）回归适用性**：判据是"那些门在切换之后还能不能跑、读数是什么"。
         ⚠️ 实测结论：**切换之后它们跑不了 —— 而且是按设计失败关闭**：
           ① `.env` 说 postgres 时 `pnpm m4:restore:verify` ⇒
              「拒绝：后端是 postgres，但本次实验没有给出**测试目标**」
           ② 只传 `CHARACTER_DB_BACKEND=pglite` 不够 ⇒
              「检测到 PostgreSQL 连接串，但 CHARACTER_DB_BACKEND 没有显式选 postgres。
                这是刻意的失败关闭：仅'环境里有 URL'不足以换后端」
              （因为 `.env` 的 `POSTGRES_URL` 还在；PowerShell 里 `$env:X=''` 是**删除**变量，
                dotenv 又会读回来）
         ⇒ **处方**：要跑旧后端归属的门（含完整 `m4.5:ci`），**先临时回滚 `.env`（R1）**，跑完再切回来。
           步骤写在 `PostgreSQL-Migration-Maintenance-Manual.md` §6。
         ⚠️ 因此 **`pnpm m4.5:ci` 的 EXIT 0 是"切换之前"的读数**（见 Acceptance-Report §1 的标注）；
            "切换之后重跑一次 `m4.5:ci`"**仍未做**（需要临时回滚配置，是一次有状态的操作）。
         销账：按处方临时回滚 → 重跑 → 切回 → 把两次读数都记进 Acceptance-Report。

L-PG-17  ⚠️ **共存激活令牌的锚点语义过时了**（已分析，未改用户文档）：
         令牌是 `PROJECT_LG_COEXIST_ACTIVATE='coexist@<resolve(dataDir)>'`
         （`scripts/coexist/readiness.ts:165` 算期望值，`supervise.ts:81` 比对），
         其中 `dataDir` 来自 `PGLITE_DATA_DIR`。
         ⇒ **机制上仍然通过**（`PGLITE_DATA_DIR` 一直保留 ⇒ 算出来还是同一个路径），
           但**含义过时**：它锚的是**回滚库**（`data\pglite`），**不再**是核心真正在用的那个库
           （现在是 PG 的 `sumuwei`）。⇒ 这个令牌不再能证明"你要激活的就是她实际会用的库"。
         销账（建议）：把锚点扩成含后端与目标（例如 `coexist@postgres/sumuwei`），
         或至少显式记明"它只是回滚库的路径"。**在改之前不要动用户文档那一行**。

L-PG-18  ⚠️ **切换之后 `.env` 的后端选择是"全局开关"**：它同时决定
         "核心连哪个库"与"旧后端归属的门能不能跑"。
         ⇒ 任何"要在切换后跑离线回归"的操作都变成**有状态**的（改配置 → 跑 → 改回 → 复验核心能起）。
         销账：给这些门加一个显式的"目标覆盖"入口（像 PG 门用 `LG_PG_SOURCE_SNAPSHOT` 那样），
         让它们不必依赖 `.env` 的全局状态。
```
