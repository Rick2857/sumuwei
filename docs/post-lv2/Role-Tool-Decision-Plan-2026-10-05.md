# 苏沐薇自行选择工具：可行方案与执行范围

日期：2026-10-05。状态：**设计建议已准备；代码未实施，生产未切换**。

用户目标：“我希望她的所有工具都由她自己来决定是否调用”。本方案将“所有工具”解释为 LG 已登记的行动能力；用户自然表达需求，角色模型判断是否需要工具、选择工具及参数、查看结果并决定继续或回答。模型决定意图，现有程序执行已授权且合法的动作。

## 1. 当前工程事实

- `src/main.ts:1535` 已把默认行动、搜索、四项实用能力、本机文件、天气、办公、资讯、浏览器能力装入同一登记表。
- `src/main.ts:542` 的任务候选表包含 13 个业务工具；旧沙箱读/写与 `system.echo` 另外登记。实施 WP0 必须核对完整登记表，不把这 13 个当成“所有”。
- `task-intent.ts` 先按关键词决定是否进入任务环。任务规划器的输入仅包含原任务、已执行引用摘要和失败摘要，没有角色的完整当轮上下文，也没有上一步取得的实际正文。
- 普通回复请求只发送文本消息，未发送工具定义；`readChatStream()` 把 `finish_reason=tool_calls/function_call` 当作错误。因此当前主回复链没有完整工具决策闭环。
- 原话“我想问个问题，就是我的电脑桌面上有几个快捷方式。”不命中任务入口或显式路径入口；现成目录适配器能正常读取两个桌面。取证见私有诊断 `artifacts/post-lv2/local/shortcut-investigation-20261005/`。

## 2. 推荐方案

```text
当前真实用户事件 + 角色的当轮 ContextPacket + 当前可用工具目录
  → 角色模型选择：直接回答 / 需要澄清 / 提议工具步骤
  → 严格解析提案 + 绑定原用户事件与当前任务授权
  → 既有 ActionRequest → 目标解析 → Policy/Gateway → Adapter
  → 实际 ActionResult + 有预算的当轮内容回到角色上下文
  → 决定下一步或结束 → 既有回复守卫 → 字幕/TTS/对话交付
```

决策使用当前角色模型与同一角色快照、人格和上下文，不新增具有独立人格/记忆的代理。通过 ContextCompiler 的既有 `instruction` 扩展点提供工具目录和受限提案协议；每次决策的实际 section、内容范围和模型调用都可追溯。

首版复用当前兼容接口支持的严格 JSON 提案方式：私有决策阶段输出闭集分支与现有有限计划，最终回复沿用已接好的语音流。它不依赖服务端原生 function calling，避免把未验证的提供商协议能力当成已支持。是否改用原生工具协议留给另一个有证据的实现选择，不同时维护两套执行权威。

同一模式下只有一个工具选择入口；不让关键词检测、搜索需求判定和角色提案重复执行同一动作。旧规则模式保留作回滚，新模式采用独立、具名的配置和验收。

## 3. 能力影响矩阵

| 工具范围 | 谁选择用途/参数 | 执行与授权 | 本轮新增执行能力 |
|---|---|---|---|
| 本机目录、读文件、写文件 | 角色模型，必要路径由程序提供确定证据 | 复用本机域权限、实际账户权限、恢复副本、并发检查 | NONE |
| 计算、文档、OCR | 角色模型 | 复用受限表达式、格式/路径校验、现有执行器 | NONE |
| 搜索、网页、资讯、天气 | 角色模型 | 复用开关、出站校验、来源事实与既有调用上限 | NONE |
| Office 生成、浏览器阅读/操作 | 角色模型 | 复用任务级授权、风险额度、真实结果读回 | NONE |
| 旧沙箱读/写与 echo | 纳入完整工具清单，保持各自路径语义和测试用途 | 复用旧域、权限和登记表 | NONE |

“已登记”与“已开启/已授权/已连接”分别呈现。工具选择不能启用被关闭的能力，也不能把浏览器安装/连接状态猜成可用。参数名单仍是闭集，不暴露任意 Shell、JavaScript 或 MCP 调用入口。

沿用用户已授权的本机读/创建/修改/覆盖与任务内自行选必要文件，完成这些步骤不增加逐个确认。这里不增加新的权限或动作种类。

记忆采信、Belief、Affect、Relationship、Storyline 等内部认知机制继续走已有权威链。此方案不把它们改成模型可任意写入的外部工具。

## 4. 两个必须一起补的缺口

1. **自然语言入口**：每轮通过角色决策表达是否需要工具，允许完整问题句触发；“不要读取/只是讨论/引用别人的指令”等情况也要被正确理解。关键词不再决定是否有资格提出工具请求。
2. **真实内容回传与目标证据**：决策环能读取预算内的实际目录条目/文件片段/网页内容，而非仅 `path=...=success`。程序提供 Windows 已知目录证据（个人桌面、公共桌面等），处理重定向后的实际路径；模型不能猜 `user/Administrator`。

工具内容始终作为资料，不能变成用户命令、系统指令或自动写入长期记忆。被裁剪或未读到的内容必须显示范围；工具提案/参数协议绝不能进入 TTS。

## 5. 与现有冻结定义的关系

此方案保留 [ADR-030](../adr/ADR-030-action-request-is-the-only-execution-entry.md) 和 `INV-M45-01…06`：模型提案不等于权限，执行仍只有一个 Gateway，最终回答绑定真实结果。

统一选择入口需要新的设计裁定和明确的兼容记录，尤其是：

- 任务形关键词入口 → 每轮角色提案入口；受信触发仍为原用户事件，不伪造新用户消息。
- 搜索需要统一选择而不是双重需求模型。首版保留 `explicit/auto_public` 授权含义、每轮 provider 至多一次，以及 [ADR-049](../adr/ADR-049-adaptive-search-verification.md) 的当前文本 `querySpan` 校验。选择搜索不代表已经解除了查询补全/改写限制。
- 若要进一步允许从历史补全搜索 query、增加一次以上搜索或主动后台使用工具，须在设计中单独提出，不能从“自行选择工具”隐含推出。
- 不改写旧 ADR 和历史通过/失败证据；新模式的适用规则与旧模式分列。

本文是一份可审查建议，不是以上冻结定义已经修改或实施的记录。

## 6. 工作包与验收

| 步骤 | 交付 | 验证 |
|---|---|---|
| WP0 设计与基线 | 完整工具/操作/参数目录、当前权限、来源指纹、新旧入口关系 | 登记表非空；每项工具均有覆盖；无遗漏或通用绕过接口 |
| WP1 角色决策入口 | 受限提案端口、角色 ContextPacket、直接回答/澄清/工具分支 | 无关键词问题可触发；普通闲聊可直接回答；非法提案拒绝且零动作 |
| WP2 结果闭环与目标 | 实际内容回传、已知目录证据、预算/停止/取消 | 正确数个人+公共桌面；依据实际内容选下一步；无进展或超预算如实结束 |
| WP3 全工具组合验收 | 参数化的完整工具覆盖、禁止场景、失败/关闭/未连接 | 每个工具至少一次选中和一次拒绝/不选；先证实调用，再证实实际入模和回复 |
| WP4 交付与激活 | 新模式文档/回滚、必要完整回归、隔离真实链 | 工程、语义、人审、真实链与生产激活分别记录；不拿部件绿代替完整体验 |

至少覆盖：原快捷方式问题及改写、精确计算、文档/OCR、天气同名城市、搜索后深读、生成 Office 后读回、确定浏览器元素操作、拒绝读取/写入、输入含引用指令、工具资料里的注入指令、关闭能力、连接失败、空结果、权限错误、截断、重复调用、取消、格式错误。

新量具采用正控/注入非法提案负控/恢复，且覆盖分母非零。模型选择质量须在固定样本上逐案报告；具体阈值实施前冻结，不宣称开放对话零误判。

回归采用 `pnpm typecheck`、相关 action/context/bridge/stream 门与交付纪律 `pnpm m4.5:ci`；真实模型只在隔离副本与合成任务/文件中验收，不写正式记忆。浏览器未完成真实连接的情况按实际状态保留，不冒充全工具真链已过。

## 7. 代价与当前状态
