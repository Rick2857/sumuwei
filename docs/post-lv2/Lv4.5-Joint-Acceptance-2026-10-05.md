## 5.2 那一条"未验"为什么**现在**验不了（而且与用户要修的那件事同源）

计划 §3 的验收行写的是「**新证据**在语音播放中到达」。本批真链路验的是
**用户更正**那条触发（"不对"），**证据**那条触发只有门覆盖。原因是**时延结构**：

```text
提前检索在 **用户说话期间** 发起（2–8 秒返回）
而她在用户说完之后才开始：生成 7–24 秒 → 才轮到播放
⇒ 检索几乎总是在**生成期间**就回来了 —— 那时她**还没出声** ⇒ 判据（她正在说）不成立
⇒ 要让"证据落在播放期间"，需要**生成更快**（播放窗口提前开始）或检索更慢
```

⚠️ **所以它与用户要单独修的那件事同源**：**把生成改快 ⇒ 这条 arm 才会变得可达**。
在那之前，把它登记为 `未验`（门绿**不等于**链路验过）是本批能给的诚实结论。


⚠️ 这条不是形式主义：**机器验证**证明的是"这条链按判据工作"，
**真人验证**证明的是"人在真实使用里能不能忍受 / 会不会用"。二者**不可互相替代** ——
本批的呼唤与插话在**真人会话**里尚未被观察过。

## 6. 本批**不主张**什么（避免外推）

```text
· 不主张"她不会误触发"：呼唤的近音类与"不对/不是这样"的词形表都是**刻意短**的，
  已知代价已逐条登记（如"这个方案不对"这类**她不是被纠正对象**的句子也会命中）
· 不主张时延达标：§3 两条阈值如实未达标，且**不许**用负载/冷启动/样本量解释掉
· 不主张"干净窗口之外的读数有效"：时序探针现在**拒绝**在重负载窗口里跑
  （这条闸本身曾挂在文件末尾 ⇒ 形同虚设，已修 + 三段式验证）
· 不主张"提前查一定成功"：ADR-098 只解除**归因**那一处阻塞；
  出站能否拿到结果、以及"她正在说"的时机，各由各自的读数回答
```

## 7. 附：本批修掉的**沉默类缺陷**（都会让读数看起来正常）

```text
① 桥的 stdout 是 NDJSON 协议通道 ⇒ 桥里 logger.info 写的诊断**生产上读不到**
   （我据此误判过"那个分支没跑"；现在结局随协议回，或走 stderr）
② markSuperseded 把 synthesized 映射到 unknown，而迁移表不允许 ⇒ 抛错被 bare catch
   吞掉 ⇒ 报"没有余句可废"（真链路读数 0 段，而当时确实有）
③ 纠正的顺序"先废余句、再给纠正段" ⇒ 纠正段重读 hasUnplayed() 必然 false
   ⇒ 在**真正该纠正的时候**把它丢掉（与 ② **互相掩盖**）
④ 门自己的桩不模拟"废余句会把 hasUnplayed 变 false"这个副作用
   ⇒ 上面 ③ 在桩里永远不会发生（**桩不模拟副作用 = 把被测的顺序问题从测试里删掉**）
⑤ 负载闸挂在文件末尾 ⇒ 轮次早就跑完了（"拒绝跑"的用例反而跑了整批）
```

**这五条的共同形态**：读数看起来正常，而**事实没有发生**。本批的应对是同一条纪律 ——
把"发生了没有"变成**可反证**的数（`superseded` / `lookup_*` / `correction_count` /
`loadCheck` / 计数自检），而不是靠"门是绿的"。
