# 材料驱动提醒

提醒适用于课程、会议、截止事项等通用事件。发送文字或图片，再提出提醒要求，例如：

> 这是本周的安排。请在每个事件开始前 5 分钟通过 QQ 提醒我。

也可以直接说“2027 年 3 月 12 日上午 9 点提醒我提交材料”。单独发图不会自动授权建单；没有日期、仅有节次却没有作息表、图片看不清或材料截断时，需要先补齐信息。

## 配置与使用

使用自己配置的共存核心和提醒出口，按相应入口文档准备 QQ、皮套或控制台。提醒入口沿用现有开关：

```dotenv
CHARACTER_ENTRY_SCOPED_CONVERSATIONS=true
CHARACTER_QQ_PROACTIVE_MODE=on
CHARACTER_IMAGE_INPUT_ENABLED=true
```

前两项与可用的提醒调度／投递连接共同决定能否建单，第三项用于图片材料。文档或 OCR 读取还需要该能力自己的授权、外部依赖和 `CHARACTER_TURN_CONTENT_TOKENS` 额度；额度为 0 的工具正文不会另行传给提醒解析器。不要为了提醒绕过既有能力权限。

明确指定年月日、本周／下周的星期、既有相对时间均由程序解析；本周按周一开始。图片既可与请求同发，也可来自同一会话近期上下文。超出近期图片范围的材料需要重发或通过已有读取能力重新取得。

可继续要求“查看提醒”“把第一条提醒改到明天下午三点”“取消第二条提醒”。改期保持原投递渠道，确认重复请求不改写已有内容。用户、会话、计划版本和未开始投递条件共同限制修改。

## 处理链与边界

1. 复用既有图像上下文、文档／OCR 能力和有界 TaskLoop 取得材料。
2. 模型只提出来源、原文时间片段、事件名和提前分钟数。
3. 程序核对来源，用 chrono-node 中文解析与既有时区函数计算事件时刻，再扣除提前量。
4. 整批先校验；通过后逐项保存，复用 notification_intents / occurrences、版本检查、Croner 与原渠道投递。
5. 回复按实际新增、已有、改期、取消、跳过和失败逐项报告；保存不等于发出，API 接受不等于用户看见。

一批最多 100 项，提前量为 0–1440 的整数分钟。周期要求只在已给明确截止范围时展开；没有无限周期规则或额外后台通用代理。过期项跳过，不立即补发。写入故障按实际部分成功报告，不宣称整批原子事务。

原文引用与事件名称用于核对和去重；图片时间转写仍可能误读，模型候选不是事实保证。整个解析调用受 45 秒时限约束，失败时如实报告。这个功能没有新增数据库迁移，也没有开放普通群成员的主人级任务／提醒权限。

## 检查

```powershell
pnpm typecheck
pnpm reminder:planning:verify
pnpm reminder:context:verify
pnpm reminder:channels:verify
```

离线检查使用合成资料、隔离数据库及模拟 QQ API 接受。图文真实理解可以用自己的测试端点验证：复制 `.env.test.example` 为本机 `.env.test`、填写自己的 Key，再运行 `pnpm with-test-model pnpm reminder:planning:live`。该检查只处理合成日程并核对计算结果，不写数据库、不发送 QQ 提醒。公开副本的实际新读数与未运行项目见 [PUBLIC-VERIFICATION.md](PUBLIC-VERIFICATION.md)。
