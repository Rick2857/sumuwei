# M4.5 Execution Truth —— 她不能宣称未发生的动作

- **阶段**：M4.5（WP-08）
- **相关 ADR**：ADR-033（执行真相）、ADR-034（两本账）
- **代码**：`src/kernel/action/claim-guard.ts`、`claim-scanner.ts`、`action-turn.ts`、`src/kernel/app/turn-gateway.ts`、`src/main.ts`
- **守着它的测试**：`m4.5:test` §5；`m4.5:verify` §3；`m4.5:nl-action:verify` NL-03/04/05；`m4.5:smoke:live` S3/S4/S5/S6/S9

---

## 1. 两层保证，方向相反

```text
① 前置：动作在**模型生成之前**执行完毕，结果作为一条 droppable:false 的
   context section 交给模型 —— 让"如实转述"成为唯一自然的选择

② 后置：**确定性**守卫。指令可以被无视，因此还需要语法级保证：
   没有 success 的 ActionResult 且回复含未被否定的动作成功口吻 → 替换
```

第 ① 层的措辞（`actionFactSummary`）：

| status | 给模型的事实 |
|---|---|
| success | "你刚刚已经执行了一次动作，并且成功了（detail）。这是已经发生的事实，可以直接说。" |
| partial | "只完成了一部分（detail）。不要说得像全部做完了。" |
| ambiguous | "目标不唯一，因此系统**没有执行**。不要猜目标，也不要说已经处理。" |
| not_found | "目标不存在，因此系统**没有执行**。不要说你做了。" |
| rejected | "被系统**拒绝**（code），**没有任何副作用发生**。不要说你做了。" |
| timeout / failed / cancelled | "无法确定是否完成 / 没有完成任何事。不要说它成功了。" |

第 ② 层的替换（`truthfulActionSentence`）按 status 分派六种不同的如实句，
**不允许**统一成一句"没成功"：`ambiguous` 与 `not_found` 对用户要
采取的行动完全不同。

## 2. 词表与记忆的**不共用**

```text
记忆词表（M4.1，冻结）：记住了 / 记下了 / 忘掉了 / 改好了 / 处理好了 …
动作词表（M4.5）      ：已完成 / 已经创建 / 已经发送 / 已经修改 / 已经删除 /
                        写好了 / 建好了 / 读到了 / 执行成功 / 处理好了 …
```

三条理由：

1. **命中率**：混用会让"我记住了"在动作失败时被误替换。
2. **回归安全**：M4.1 的 `RESPONSE_SUCCESS_MARKERS` / `replyClaimsSuccess`
   对外行为一个字节都不能变（`verify-m4-smoke-live.ts` 直接 import 它们）。
3. **可解释**：替换日志要能说清是动作口吻还是记忆口吻触发的。

共享的只有最底层扫描 `scanClaims(text, markers, { negationWindow: 4 })` ——
"标记往前 4 个字符内有否定词就不算违规"这条规则**只有一份实现**。
4 字符窗口覆盖"我**没有**记住" / "我**没能**记住"，又不至于把上一句的否定吸进来。

---

## 3. 串联顺序（`ChatSession.send`）

```text
模型生成 → 记忆守卫（M4.1）→ 动作守卫（M4.5）→ 写账本 → 写 memories → 展示
```

- 串联而不是替换：两条守卫各认自己那一类口吻，不会互相误伤
- 若两条都触发，动作的那句更贴近"我做了什么"，因此让它覆盖
- **替换发生在写账本与写 memories 之前** —— 否则账本里会留着那句
  没有被说出口的话（M4.1 的现场纪律）

---

## 4. 触发条件（严格）

```text
results 为空 / undefined        → 完全不经手（普通对话零影响）
存在 success 的 ActionResult    → 不替换（唯一允许成功口吻的情形）
其余                            → 只有当回复里出现**未被否定的**成功口吻时才替换
```

取向是**宁可漏报**（漏报退回 prompt 层），因为误伤会制造一次反向的假话
（"她明明写对了文件，回复却被替换成'没有执行成功'"）。

---

## 5. 这一层的代价（如实记录）

在触发替换的那一种情形下，回复由**代码**写，而不是由模型写。
M4.1 已经接受过这个代价，M4.5 沿用 —— 换来的是
"成功口吻不可能出现在未执行的动作之后"这条**语法级**保证。

---

## 6. 边界

```text
Action Result ≠ Memory
执行事实进 Execution Ledger；要变成记忆必须另走
    Action Result → Memory Candidate → Memory Policy → Memory Write
而 M4.5 **不做**这条转换（ADR-034）。
```

它的机器证据：`m4.5:verify` §6 —— 跑完全部动作后
`memory_records` 与 ElizaOS 的 `memories` **一条都没增加**。
