# M4.5 Measurement Invariants —— 量具自己也是被测对象

- **阶段**：M4.5（WP-11 / §33–§39）
- **相关 ADR**：ADR-035（Measurement Truth）；INV-M45-06
- **代码**：`scripts/verify-m4.5-measurement.ts`、`scripts/seed-m4.5-ledger-fixture.ts`、`src/kernel/action/audit-invariants.ts`
- **守着它的测试**：`pnpm m4.5:measurement:verify`（**G12 / Hard Gate**）

---

## 1. 为什么新增 L0

M4.1 的验收发现了两次**量具自身的错误**（不是被测系统）：

| 量具 | 错法 | 后果 |
|---|---|---|
| `activeValues()` v1 | 取"所有含 `=` 的行"，把启动日志的 `hash=…` 收进来 | 库没动，断言却红了（噪声在变） |
| `activeValues()` v2 | 函数名写 `active`，实际用 `--memory-list`（**全部状态**） | 已正确遗忘的记录仍被算成"当前有效" → 幻影假红 |

两版的共同形状：

```text
函数名 / 意图说的是 A
代码实际量的是 B
而结果看起来"合理"，所以没人查
```

因此新增 **L0 Measurement Validation** 层：它**不测系统，只测量具**。

---

## 2. L0 门做了什么

```text
① 播七种终态 fixture（success×2 / failed / partial / rejected /
   ambiguous / not_found / cancelled）—— 走**生产端口**，不手写 SQL
② 对每个状态跑**生产 CLI**（`--action-list --status X`）
③ 断言输出**恰好等于**该状态的集合（逐 id 比对）
④ 断言不过滤时的集合**严格大于**任一单态集合
⑤ 负向控制：未知 status / 不存在的 actionId → 非零退出，且输出里没有记录行
⑥ 冒烟自己的解析器用混合 fixture 单测（日志行 / `hash=` / `actionId=` 都不许被认成记录）
```

第 ④ 条防的是最隐蔽的错法：**过滤恒空 / 恒全**。
如果过滤器永远返回空集，"恰好等于 success 集合"在 success 为空时
也会绿 —— 那是一个不会失败的判据。

## 3. 状态过滤只有一处实现

`--status` 的过滤发生在 `action-ledger-store.ts` 的 **SQL where 子句**里
（`status is not null` + `and status = $n`），不是读回来再 `filter`。

CLI、`action:audit`、L0 门全部走同一个 `listRecords({ status })`。

静态锁（`m4.5:test` §9.15 / §9.16）：

```text
src/main.ts 必须包含 `ledger.listRecords`，
     且必须**不**包含 `from character_action_events`（不自己写 SQL）
action-ledger-store.ts 必须包含 `status is not null` 与 `and status =`
```

## 4. 正负双控（§39）

```text
Positive Control —— 该成功的真的成功
    合法写 → 【Level 1】文件真的出现 + 内容正确 + Result success + Ledger 终态

Negative Control —— 不该执行的真的没有执行
    越界 / 模糊 / 无权限 / 超风险 / 干跑
      → 沙箱目录**快照哈希不变**
      → 适配器**调用计数为 0**
```

只测"不该写的时候不写"会被"什么都不做"骗过；只测"该写的时候写了"
则拦不住越权。两者必须同时存在。

## 5. 证据优先级（§50）

```text
Level 1  真实外部结果        （文件真的在不在、内容对不对）
Level 2  Execution Ledger    （真实事件流）
Level 3  ActionResult
Level 4  Integration Test
Level 5  Unit Test
```

**最终验收必须至少有 Level 1 + Level 2**：

```text
Level 1  m4.5:verify §1.3（文件真的存在）/ m4.5:nl-action:verify NL-02.1 / L4 S2.1
Level 2  m4.5:verify §5（账本里的终态记录）/ m4.5:measurement:verify（逐 id 精确）
```

## 6. STOP-10：真实链路优先

Live Smoke 与离线结论冲突时，**优先相信真实链路**，并重新检查量具与系统。

禁止用"离线有很多测试通过"来否定 Live Smoke —— M4.1 的常态正是
"离线全绿而真实链路红"，而发现 D1 的途径不是任何测试，是
**在真库里真的说了一句话**。
