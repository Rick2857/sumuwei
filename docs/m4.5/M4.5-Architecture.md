# M4.5 Action Truth & Observability Foundation —— 架构冻结

- **阶段**：M4.5（前置 M4.1，后续 M5）
- **日期**：2026-09-17
- **状态**：已冻结（WP-01）
- **相关 ADR**：ADR-030 / 031 / 032 / 033 / 034 / 035

---

## 1. 这个阶段要解决的问题

M4.5 不新增"完整 Agent 能力"。它建立的是**未来每一种行动能力都必须服从的协议层**：

```text
模型"想做什么"
≠ 系统"允许做什么"
≠ 系统"真正执行什么"
≠ 系统"执行结果是什么"
≠ 模型"最后说自己做了什么"
```

这五条边界的每一处，M4.5 之前都不存在（仓库里没有任何"执行"概念）。

---

## 2. 目标架构

```text
User / Character
      ↓
    Intent                      （规则式意图判定；LLM 不决定执行）
      ↓
 ActionRequest                  （唯一执行入口的输入值）
      ↓
 TargetResolver                 （exact / strong / weak / none + 证据）
      ↓
 PolicyEngine                    （风险等级 / 权限 / 目标确定性闸）
      ↓
 CapabilityRegistry              （能力必须登记才存在）
      ↓
 ToolGateway                     （唯一执行入口）
      ↓
   Adapter                       （真实 IO：echo / sandbox-filesystem）
      ↓
 ActionResult                    （accepted / executed / status / effect / evidence）
      ↓
 ExecutionLedger                 （append-only 事件流 + 折叠）
      ↓
 ActionClaimGuard                （回复不得宣称未发生的动作）
      ↓
 Character Response
```

Trace 旁路：

```text
Intent → Request → Policy → Execution → Result
   └────────── 同一条 traceId ──────────┘
                      ↓
              Audit / Inspector（action:list / show / trace / audit）
```

## 5. 分层与文件地图

| 层 | 位置 | 职责 |
|---|---|---|
| 协议 | `src/kernel/action/action-request.ts`、`action-result.ts`、`errors.ts` | 纯类型 + 失败语义归一 |
| 目标 | `src/kernel/action/target-resolver.ts` | 五步梯子，纯函数 |
| 能力 | `src/kernel/action/capability-registry.ts` | 唯一登记处 + 声明校验 |
| 策略 | `src/kernel/action/policy.ts` | 纯函数判定，可穷举 |
| 编排 | `src/kernel/action/gateway.ts` | 唯一执行入口 |
| 适配器 | `src/infrastructure/action/adapters/*` | 真实 IO（`kernel` 不得 import） |
| 账本 | `src/kernel/action/execution-ledger.ts` + `src/infrastructure/action/action-ledger-store.ts` | 具名写入端口 + SQL 实现 |
| 折叠 | `src/kernel/action/execution-record.ts` | 事件流 → ExecutionRecord |
| 守卫 | `src/kernel/action/claim-guard.ts`、`claim-scanner.ts` | 动作真相的确定性后置守卫 |
| 审计 | `src/kernel/action/audit-invariants.ts` | CLI 与门共用一份 |
| 轮次 | `src/kernel/action/intent-detector.ts`、`action-turn.ts` | 自然语言 → 请求；轮次级端口 |

住 `kernel` 会打破 MI-13 / ADR-001。§43 用词是"例如"，因此按边界拆分。

## 6. 与既有内核的接口（不变的部分）

```text
Character Kernel   —— 不被触碰（src/character/** 哈希不变）
Memory Kernel      —— 不被重构（M4/M4.1 的 store / validator / reducer / 显式路径原样）
Context Compiler   —— 只新增一个 section provider（仅在真的发生动作时挂载）
Turn Gateway       —— 新增可选的 actionWriter；不注入时行为与 M3.5 完全一致
```

M4.1 遗留的两项**本阶段不接线**（保持原状）：

```text
ChainedContentExtractor（LLM 抽取兜底）  默认 false
Background Memory Extraction             NOT-WIRED
```

未来它们若上线，同样必须服从 Action / Execution Truth。

## 7. 边界声明

### 7.1 Memory ≠ Belief ≠ World State

```text
Memory     长期存储的事实/经历
Belief     角色当前认为是真的东西（M5）
WorldState 外部世界当前可观察状态（M5+）
```

**不得**因为"记忆里写着 X"就认为"外部世界现在仍然是 X"。
M4.5 只在类型层面预留 World 接口，不实现任何预测/模拟/规划。

### 7.2 Action Result ≠ Memory

执行事实进 Execution Ledger。要变成记忆必须另走
`Action Result → Memory Candidate → Memory Policy → Memory Write`，
而 M4.5 **不做**这条转换。

### 7.3 本阶段实际运行的能力

```text
system.echo             R0
sandbox.file.read       R0
sandbox.file.write      R1
```

全部限定在 `ACTION_SANDBOX_ROOT`（默认 `data/action-sandbox/`）内。

### 7.4 明确不做（计划书 §45 / §16）

完整 Web Search、任意 Shell、真实主机文件操作、后台自治 Agent、
Scheduler、浏览器/桌面控制、消息/邮件/支付、多 Agent、
真正 World Model、复杂 Planner、长期 Autonomous Task Loop。

## 8. 证据与验收

### 8.1 证据优先级（计划书 §50）

```text
Level 1  真实外部结果        （文件真的在不在、内容对不对）
Level 2  Execution Ledger    （真实事件流）
Level 3  ActionResult
Level 4  Integration Test
Level 5  Unit Test
```

**最终验收必须至少 Level 1 + Level 2。**

### 8.2 测试四层（+ L0）

```text
L0 Measurement Validation  只测量具
L1 Component               协议 / 登记 / 策略 / 目标 / 守卫 / 账本折叠 / 适配器
L2 Subsystem               Request → Policy → Gateway → Executor → Result → Ledger
L3 Integrated Behaviour    从真实语言进入（离线、确定性）
L4 User-observable         Production-copy Live Smoke（Hard Gate）
```

### 8.3 Hard Gate

```text
G12 Measurement Validation
G13 Natural Language E2E
G14 Sandbox Live Smoke
```

### 8.4 停止条件（§52）

任一命中立即停止 PASS：无 SUCCESS 却宣称成功 / ambiguous 仍产生副作用 /
绕过 Gateway / 执行无 Ledger / trace 断链 / 重复副作用 /
量具读错状态 / 越界真实主机 / 旧 Memory 回归 / Live Smoke 与离线冲突。

冲突时**以真实链路为准**。

## 9. 后续 milestone 的计划模板（计划书 §48）

从 M4.5 起，任何**新增副作用能力**的 milestone 计划书都必须包含：

```text
 1. Target Resolution
 2. Permission / Risk
 3. Execution Semantics
 4. Execution Truth
 5. Audit / Trace
 6. Failure Semantics
 7. Idempotency
 8. Measurement Validation
 9. Positive Control
10. Negative Control
11. Natural Language E2E
12. Live Smoke / Real Integration
```

缺任何一章，该计划书不得视为设计完整（计划书 §58）。

## 10. 长期原则（计划书 §58）

```text
模块正确 ≠ 组合正确
组合正确 ≠ 用户行为正确
返回成功 ≠ 副作用成功
唯一候选 ≠ 正确目标
测试通过 ≠ 测试量对了东西
```

因此每个后续计划都必须能回答：

```text
她打算做什么？她实际做了什么？她操作的是不是正确对象？
她是否有权这么做？外部状态到底发生了什么变化？
她最后说的话是否与事实一致？能否沿 trace 还原全过程？
验收工具本身有没有测错对象？真实链路是否跑过？
```
