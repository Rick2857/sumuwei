## 1. `src/kernel/contracts/developer-query.ts` —— **加法**（+1 个 DTO / +1 个纯函数 / +2 处派生登记）

```diff
+export interface DeveloperAttributionCountsDto {
+  readonly unknownSlotCount: number          // U-1 逐槽位（K-30 裁定）
+  readonly recordsWithUnknownCount: number   // U-2 记录级
+}
+export const ATTRIBUTION_COUNTED_SLOTS = ['initiator','actor','executor','authority','recordedBy','contentOriginator'] as const
+export function attributionCountsOf(records: readonly (DeveloperAttributionDto | undefined)[]): DeveloperAttributionCountsDto

+export interface DeveloperTraceListDto extends DeveloperPage<TraceSummaryDto> { counts: DeveloperAttributionCountsDto }
 TraceDetailDto                += counts: DeveloperAttributionCountsDto
 DeveloperExecutionDetailDto   += counts: DeveloperAttributionCountsDto
 DeveloperQueryService.listTraces: Promise<DeveloperPage<TraceSummaryDto>> → Promise<DeveloperTraceListDto>
```

**为什么是加法而不是改造**：计数的**语义**（单位 / 范围 / 边界）是 K-30 的裁定，落地时只在
**一处**实现（`attributionCountsOf`），查询面调用它、门独立复算它。契约里**没有**第二个计数实现。

**决定：执行列表面（`listExecutions`）刻意**不带** `counts`。**
WP6-4 让它**不携带归因**（逐行读事件流是 N+1），因此它的"当前结果集"里根本没有归因数据；
给它 `counts: {0,0}` 等于把"这个响应不携带归因"说成"没有未知"。理由写在
`DeveloperTraceListDto` 的注释里（与"无信封 ≠ Absent"同一条纪律）。

**接地（编译期）**：`counts` 在两处派生清单里登记
（`DeveloperTraceDetailDerivedKeys` / `EXECUTION_DETAIL_DERIVED_KEYS`）——
它是**由归因槽位算出来的聚合**，不是 `character_traces` / `character_action_events` 的列。
`DEVELOPER_TRACE_SUMMARY_IS_GROUNDED` / `DEVELOPER_TRACE_DETAIL_IS_GROUNDED` 仍为 `true`。

**从约定变成不变量**：`assertDeveloperExecutionDetail` 现在**拒绝**与
`attributionCountsOf(detail.attribution)` 不一致的 `counts`（理由码
`developer_attribution_counts_mismatch`）—— 生产者编一个数就失败关闭。

## 3. `scripts/verify-m5.1.1-wp7-preflight.ts` —— AT-W7-0 的**换形**（不是放宽）

计数的 `0` 不可见，违反 U-14 的"0 必须显式出现"。已把计数行移到早返回之前。
