### 1.1 判据（三值，不合并）

```text
ESTABLISHED           attribution_origin = RECORDED ∧ Axis B confirmed ∧ contentOriginator = Known(USER)  ⇒ 放行
CONTRADICTED_ORIGIN   ⊢ 上 ∧ contentOriginator = Known(非 USER)                                          ⇒ 拒（理由码 ②）
UNCONFIRMED_ORIGIN    没有受信读数（无信封 / MIGRATED_LEGACY / 形状坏）∨ Axis B 不 confirmed              ⇒ 拒（理由码 ①）
```

**"知道不是他" ≠ "不知道"** —— 两个理由码不合并（`DR-3`）。但两者对"能不能建立用户事实"的答案一致（都不能）。

### 1.2 为什么闸必须放在权威推导**之前**

`authorityFromSource('UNCONFIRMED_ORIGIN')` 是**抛错**（`memory.ts` 的 K-1=B1 分支），不是干净拒绝。
让未确立的来源走到那里，会把一条可读的拒绝理由变成 **500**。新闸让那条抛错在**正常路径上不可达**，
同时**保留**它作最后一道防线 —— 本门有一条断言专门守它没有松动（`DR-2`）。

## 3. 两条冻结断言的方向性禁止 → 已由 **R-59** 授权取代

**第一次判定为 FAIL 的原因就在这里。** 4a 按执行令**必须**让抽取器读到受信归因与 Axis B，
而 M5.1 的两道门**各自用一条断言明文禁止**这件事：

```text
① scripts/verify-m5.1.1-k17-consumer-impact.ts:659
   check('processorEventViewOf 也只搬非 Axis B 的字段',
         !NEEDLES.some((needle) => viewMapper.includes(needle)))
   NEEDLES = [source_kind, source_authority, epistemic_source,
              sourceKind, sourceAuthority, epistemicSource]

② scripts/verify-m5.1.1-wp61-conversation-ingress.ts:1717
   check('★ §10 extractor **没有**被接线到归因（源码里不出现 attribution / contentOriginator）',
         !/attribution|contentOriginator/.test(extractorSource))
```

**为什么这不是"兼容性追平"**：把"抽取器**不得**看见 Axis B / **不得**被接线到归因"
改写成"抽取器只看得见**派生**的受信读数"，是**架构层断言的方向反转**。
原断言保护的是 **Phase 4 之前**的架构状态，继续保留就是**禁止已批准的设计本身**。
