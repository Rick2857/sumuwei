> 本文要解决的是"**她已经相信的东西怎么办**"（认知资格）。
> 把后者塞进归因 ADR 会让两个问题互相绑死 —— 这正是 B7 要拆开的原因。

---

## 1. Problem

ADR-042 Revision 2 确立：`contentOriginator` 已确立（尤其是否为 `USER`）才是
Fact Firewall 抬升认知资格的依据；`actor_type='user'` **不足以**证明
"这段语义内容由人类提供"。

**由此产生的存量问题**：

```text
一批**已经落库**的 memory 记录，其 authority 是**抽取时**按旧规则计算并存下来的。
旧规则把 actor_type='user' 等同于"人类亲手输入" ⇒ 它们拿到了 USER_EXPLICIT。

按新规则，这批记录的真实来源是 Unknown(LEGACY_UNRECORDED)。
⇒ 它们**可能不再满足**新的 Attribution Truth。
```

**具体实例（D01 的原始触发点）**：

```text
mem:…:person_fact-8d64c71c49424b51
  education.institution = 示例工程科技大学
  authority = EXPLICIT_USER_STATEMENT / USER_EXPLICIT
  根证据   = conversation_event #27（role=user，**内容来源未确立**）
⇒ 它现在被当作"用户明确陈述的事实"，而"由谁提供"从未被记录。
```

**问题的两难**：

```text
若不动它 → 一个已知可能错误的认知资格被**永久固化**（append-only，无法回收）
若直接改它 → 对既有认知状态做**追溯性的静默重写**，违反"不得 silent rewrite"
```

---

## 2. Scope

```text
在范围内
  · 已落库 memory 记录的 authority 是否/如何重新资格化
  · 历史认知状态的保留方式（"她曾经相信什么" vs "现在剩什么"）
  · Recall / Trust 是否随之变化
  · 重新资格化动作的事件表示（必须产生新事件，而非改写历史）
  · 失败关闭的当前行为

不在范围内
  · 归因模型本身（ADR-042）
  · Memory Kernel / Memory Lifecycle 的语义变更（属新里程碑 + ADR + 全套 m4:*）
  · Cognitive Integrity 的完整实现（原则见 docs/architecture/cognitive-integrity.md）
  · 外部 audit service（U-19 已冻结边界：独立表 ≠ 独立故障域）
```

---

## 3. Why ADR-042 cannot decide it

```text
① 它改变的是**既有不变量（Assistant Fact Firewall）的输入行为** ——
   这是阶段 4 的动作，不属于"归因模型"的范畴。

② 它是**产品语义决定**，不是工程决定：
   "保留当时的判定" vs "按新判据重算" vs "标记为来源未确立"
   三种选择对用户可见行为的影响不同，不能由归因设计顺带决定。

③ 它会触碰**冻结区**：src/kernel/app/memory/**（AGENTS §3）——
   语义变更需新里程碑 + ADR + 全套 m4:*。ADR-042 只提供前置条件。

④ 若在 ADR-042 内顺手裁决，会出现"一个 ADR 同时改归因与认知资格"，
   一旦出问题无法判断是哪一侧造成的（与分阶段落地的理由同源）。
```

## 5. Relationship to Cognitive Integrity

本 ADR 是 Cognitive Integrity 原则（`docs/architecture/cognitive-integrity.md`）
在**存量数据**上的第一次真实适用：

```text
INV-CI-05  Cognitive History May Be Corrected, But Must Not Be Falsified
   ⇒ 允许纠正资格，禁止伪造历史。这正是本 ADR 要解决的两难。
INV-CI-01  No Cognitive State Without Provenance
   ⇒ 必须读作 "without **established** provenance"（见 Gap Audit §1）
INV-CI-04  Intervention Must Be Explicit, Warned, Authorized, Audited, Verifiable
   ⇒ requalification 若发生，必须走完整流程（Preview → Warn → Confirm → Audit → Verify）
```

因此 **U-19 的边界在此继续生效**：

```text
Logical Cognitive Rollback  → 不得删除 intervention history
Physical Disaster Restore   → 必须建立 restore epoch 并记录 boundary；
                              不得声称同一数据库可证明跨物理恢复的完整历史
```

## 6. Required blast-radius report（**任何裁决之前必须先有它**）

本 ADR 的正式设计**必须**以一份**只读**报告为前提，其内容至少包括：

```text
□ 受影响条目清单：哪些 memory 记录会失去 USER_EXPLICIT（精确计数，不是抽样）
□ 逐条的依据：每条当前 authority + 其根证据的 contentOriginator 状态
□ 分档：D 可确定降级 / P 部分确定 / U 不可确定
□ 影响面：这些记忆是否会被 Recall 选中、是否影响既有回复行为
□ 反向清单：哪些记录**不受影响**（actor_type='character'/'system'/'tool'）
□ 只读保证：报告本身不修改任何数据（沿用 M5.1 的"只读门"纪律）
```

**不得先切换再解释**（沿用 Migration-Strategy §4 的要求）。
