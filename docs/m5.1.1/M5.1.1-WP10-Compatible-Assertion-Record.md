## 1. `C-G1` —— 仪器缺陷修正：`git status --porcelain` 的路径解析（**判据变严**）

### 1.1 OLD / NEW / WHY

```text
OLD（第一版，commit 4ddd680）
   .map((line) => line.slice(3).trim().replace(/\\/g, '/'))
   缺陷：git() 这个 helper 是 execFileSync(...).trim()，它会 trim **整段输出**，
        于是 porcelain 的**第一行**丢掉 `XY` 前导空格（" M artifacts/x" → "M artifacts/x"），
        slice(3) 就把路径首字母切掉：artifacts/… → rtifacts/…。
   实测后果：第一次运行在 §5 的
        execFileSync('git', ['checkout', TAG, '--', ...dirtied])
        处抛错，**EXIT = 1**，并留下"半还原"的工作树
        （13 条里有 9 条被还原、4 条因 pathspec 不存在而未还原）。

NEW（commit 842691f）
   .map((line) => line.slice(2).trim().replace(/\\/g, '/'))
        —— slice(2) 对"有无前导空格"两种形态都正确（已用 stdin 两种输入各验一次）。
   **并且新增两条机器自检**（这才是"变严"的部分）：
     ① 每条解析出来的路径都必须以 `artifacts/` 开头（否则 MEASUREMENT INVALID）——
        这正是 AGENTS §6.8 要求的"计数型检测器必须自检"，本 WP 的第一版**没有**这条，
        所以解析坏了只能靠下游 git 报错才发现。
     ② 每条待还原路径都必须真的存在于 immutable 标签里（`git cat-file -e <tag>:<path>`）——
        第一版的失败模式恰恰是"paths 不存在 ⇒ git 报错 ⇒ 半还原"。

WHY（为什么 OLD 在当时是"合理"但仍必须修）
   它是一个**新门**的解析缺陷，第一次运行就暴露；门当时**从未**通过过任何一次
   （因此不存在"为了让一个原本红着的判据变绿而改它"的动机）。
   修复方向不是让人工判断更宽松，而是**增加两条机器判据**。

PRESERVED
   · `dirtied` 的语义（跑门期间被改写的冻结路径集合）未变
   · 还原的 canonical source 仍是 immutable 标签 `m5.1-complete`（不是 HEAD / 父提交 / 工作树备份）
```

## 4. `C-G4` —— "覆盖前先 fork"是**读数级** fork；原 utf-16le 日志已被第一次（中止的）运行覆盖（**如实登记**）

计划 §3 C1 的口径是：**记录读数 + sha256，不复制 734 KB**。这在本 WP 里被如实执行，但过程有一处
**必须写清**的事实：

```text
M5.1 期的原始日志（WP10-A 于 2026-09-19 记录的边界身份）
    artifacts/m5.1/wp9-m4.5-ci.log
    734070 字节 · utf-16le · sha256 502c1d7243a6c1411806235b84d7873dc715e5f95302fe1baac09f55dd56884c
    mtime 2026-09-17T14:55:33.362Z
    ⇒ 边界身份的 fork **保存在已提交的** artifacts/m5.1.1/wp10a-preflight.json
      的 forkRestoreWhitelist.gitignoredLogs[0] 里（`gitignoredLogsRule` 逐字写明：
      "`*.log` 被 ignore ⇒ 覆盖 = 磁盘级历史丢失，不进 git 也无法用 git 还原 ⇒ 覆盖前必须先 fork 读数"）。

本 WP 的第一次运行（因 C-G1 的解析缺陷而**中止**）在它自己的 §1 里 fork 了这份日志的读数：
    ciExit = 0 · 逐门小结 = 26 · 硬门 = 3 · 回归 verdict = PASS
    然后 **§3 覆盖了它**。
⇒ 从此磁盘上那份 utf-16le 日志**不再存在**（这正是 §4 第一段"不得不用 fork 读数"的原因）。
本门**最终**证据（wp10-regression.json）的 `priorLog` 块描述的是**被中止运行写下的那一份**：
    430608 字节 · utf-8 · sha256 2acf28a5…（它的**解析读数与原始日志完全一致**：exit 0 / 26 / 3）。
```

**为什么这仍然是合规的"先 fork"**：

1. canonical / 计划的原文要求是 **fork 读数**（"记录读数 + sha256，不复制 734KB"），
   不是"保存文件副本"；
2. 原始日志的**边界身份**（字节数 · sha256 · 编码 · mtime）与**解析读数**
   （`ciExit = 0` · 逐门小结 26 · 硬门 3 · `regressionVerdict = PASS`）都已落在**已提交的**
   `artifacts/m5.1.1/wp10a-preflight.json` 里；
3. M5.1 期的权威回归读数另有**冻结 blob**承载：`artifacts/m5.1/regression-evidence.json`
   （从 immutable 标签还原，本 WP §5 的零差异断言覆盖它）—— 它里面的 `m45Ci` 块就是同一份日志的
   解析结果，`exitCode = 0`；
4. 本 WP **不**声称"原始 734 KB 日志仍可取回" —— 它在磁盘上**已经不存在**，这一条逐字写进
   `WP10-Handoff.md` 的 Known Issues。
