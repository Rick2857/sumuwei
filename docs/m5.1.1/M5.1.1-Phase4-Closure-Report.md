## 2. D01 关闭的**实质**（这次到底关掉了什么）

`M5.1-D01` 立案时的问题是：**账本只记 role，不记 authorship** ——
于是"agent 用一次性入口替用户发的话"落进账本是不可区分的 `[user]` 发言，
`EXPLICIT_USER_STATEMENT` 的出处**技术上成立、对人却是误导的**。

关闭它意味着这条链**每一环都有机器读数**：

```text
写      对话 ingress 的三个具名生产者（human-console / agent-runner / character-turn）
        → 18 个槽位列 + Axis B 三列 + attribution_origin（RECORDED / MIGRATED_LEGACY）
读      processorEventViewOf() **唯一**适配边界 → trustedOrigin?: TrustedOriginReading
判      4a 形成期闸（新候选）：来源未确立 ⇒ 拒绝建立用户事实
        memoryQualificationOf()（读时派生）：ESTABLISHED / UNCONFIRMED_ORIGIN / CONTRADICTED_ORIGIN
效果    ⑤ 召回入选**不变** · ⑥ 排序 authority 降一档（**不改库值**） · ⑦ prompt 标签后缀
探针    contaminatedMemories()（不变）**并列** 第二个只读探针（资格不足 ≠ 污染）
可查    开发者平面 DTO（`unqualifiedUserFacts` + `qualificationCounts`）
```

三条真实语料读数（这一次实测，不是推断）：

```text
① 存量 2 条用户事实的资格 = **2/2 `UNCONFIRMED_ORIGIN`**（历史行没有受信信封 —— 诚实状态）
② 经**交互式人类控制台**写入的合成偏好 ⇒ 派生资格 **`ESTABLISHED`**（正控成立）
③ 经**程序化入口**（`SERVICE/agent-runner`）提交的用户形状事实
   ⇒ 库里 `authority` 仍是 `EXPLICIT_USER_STATEMENT`，而派生资格 = **`UNCONFIRMED_ORIGIN`**，
      **没有**混进 `established`（负控成立）
```
