# M5.1.1 — WP4.1 Compatible Assertion Record

> **为什么要这份文件**：加 `MIGRATION_0008` 让"代码里的最新 schema"从 7 变成 8，
> 而仓库里有一批门把 `7` 写死在断言里。改这些断言是**必须**的，但必须
> **逐条留痕**——否则下一个人无法区分"判据被合理更新"与"判据被悄悄放宽"。
>
> 逐条记录格式沿用 `M5.1.1-WP2.4-Compatible-Assertion-Record.md`：
> **[文件] · [旧断言] · [新断言] · [为什么这不是放宽]**。
> 本文件只覆盖 WP4.1（K-22 physical landing）改动的判据。

---

## 1. 总原则

```text
① 已发布迁移 0001–0007 的**内容指纹一字不改**（v7 仍是不可改的历史 DDL）；
   新增 0008 的指纹在"第一次成功的 production-copy apply"之后锁定。
② `conversation_events` 的 Axis B 语义与 5 条约束**逐条不变**；
   唯一被替换的是 `character_action_events` 上那条 `axis_b_complete`。
③ 没有任何断言被"改成更容易通过"：每一条要么是版本号跟随（7 → 8 或 latestSchemaVersion()），
   要么是把"只待应用 v7"精确化为"待应用 = [v7, v8]（升序、连续）"。
④ 证据文件名按仓库既有约定 **fork**：继承门不再覆盖已关闭 WP 的历史证据。
```

## 3. 本轮**重跑**了哪些门、**没重跑**哪些

```text
重跑（exit 0）:
  typecheck · kernel:test(26/0) · kernel:test:conversation(47/0) · m5.1.1:test(42/0)
  m5.1.1:k25:verify(22/0) · m5.1.1:wp3.2:verify(35/0) · m5.1.1:wp4:verify(48/0)
  m5.1.1:wp4.1:verify(43/0) · m5.1:measurement:verify(16/0) · m5.1.1:k20:verify(30/0)
  m5.1.1:migration:verify(97/0) · m5.1.1:prod-copy:verify(30/0) · m4.5:test(135/0)

只更新判据、**未**重跑（理由）:
  · scripts/verify-m5.1.1-wp3-backfill.ts —— WP3 的 production-copy 回填门：重跑会执行一次
    副本回填并重写 `wp3-backfill.json`（WP3 的历史证据），而本轮**没有**回填任何行动行，
    也不该改写 WP3 的结论。C-12 的三条判据与 C-5/C-9 是同一机制，由那两个门实际覆盖。
  · scripts/verify-m5.1.1-k16-overlap-audit.ts / k17 / k19 / wp2.2 / wp2.4 等审计门 ——
    它们不依赖"最新版本 = 7"（k16 明确**不**在副本上跑迁移），因此加 v8 不影响它们。
```
