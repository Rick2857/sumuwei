# M5.1.1 — WP5 Compatible Assertion Record

> **为什么要这份文件**：WP5 把行动账本的写/读路径从"自由 payload 归因"升级为
> **权威归因列**。这会改变若干**既有**断言所处的现实，也会改动两个
> **兼容面**（`ActionRequester` / 折叠视图的 `requestedBy`）。
> 每一条都必须留痕，否则下一个人无法区分"判据被合理更新"与"判据被悄悄放宽"。
>
> 格式：**[文件/面] · [旧] · [新] · [为什么不是放宽]**。
> 本文件只覆盖 WP5 改动的判据与兼容面。

---

## 1. 总原则

```text
① 没有任何"必须成立"的断言被删掉。被改的两条静态判据都换成了**更精确**的形状
   （从"文件里出现过这些列名"变成"写入路径只写 NULL / 读路径不引用它们"）。
② 权威语义只增不减：necessity matrix 是唯一判据；`assertActionAxisBNotApplicable`
   在写入前必过；DB 的 CHECK 仍在。
③ 兼容面只做**最小扩展/最小改名**，不建立第二份权威（`PrincipalKind → ActionRequester`
   之类的投影**没有**被引入）。
④ 证据按 WP5-15 的原话处理：**先 fork，再还原**冻结路径（见 §4）。
```

## 2. 逐条变更

| # | 面 | 旧 | 新 | 为什么不是放宽 |
|---|---|---|---|---|
| W-1 | `scripts/verify-m5.1.1-wp41-k22-action-axisb.ts`（WP4.1 门） | `★ action 写入路径**一个归因列都不写**（INSERT 列清单里没有任何归因列）` | `★ 行动写入路径只把 Axis B 写成**字面量 NULL**，并在写入前断言 N/A`：判据 = `axisBCells = { sourceKind: null, sourceAuthority: null, epistemicSource: null }` **且** `assertActionAxisBNotApplicable(axisBCells)` **且** INSERT 的三格绑定的是 `axisBCells.*` | WP4.1 时"一个归因列都不写"是**事实**；WP5 把它升级成"写六个槽位 + origin，而 Axis B 三格只能是 NULL"。新判据钉住的是**更强的**性质（写入期 Axis B 恒 N/A 的静态形式 + 写入前断言），不是把旧判据放宽 |
| W-2 | 同上 | `★ 也没有任何代码**读**行动表的 Axis B`：判据 = "任何含 `from character_action_events` 的文件都不得提到那三列" | `★ **读路径**（`toEvent` 及其之后）不引用行动表的 Axis B 列`：判据 = 在 `action-ledger-store.ts` 的 `toEvent` 之后切片里不得出现那三列 | 旧判据在 WP5 之后变成**假阳性**：写入路径必须**列出**那三列才能写 NULL（INSERT 列清单里出现的是列名，不是取值）。新判据仍然禁止"读侧引用它们"，而"读侧不把它们当认知来源"另有一条**运行时**判据（WP5 门 §6：全库 RECORDED 行动行里携带 Axis B 的 = 0 行） |
| W-3 | `ActionRequester`（`src/kernel/action/action-request.ts`，**兼容/输入证据**） | `kind: 'user' \| 'character' \| 'system'` | 追加 `'tool'`（`createActionRequest` 的校验同步） | 冻结的 `Migration-Strategy` §3.3 早就写着"其 kind 只有 user\|character\|system（**缺 tool**）⇒ 部分确定" —— 也就是"工具发起的动作"在兼容契约里**表达不出来**。这是 WP5-4 要求的**最小扩展**；**没有**引入 `PrincipalKind → ActionRequester` 投影（权威槽位由 `attribution.ts` 承担） |
| W-4 | `ExecutionRecord.request`（`src/kernel/action/execution-record.ts`） | `requestedBy: ActionRequester`（payload 缺省时被替换成 `{ kind: 'system' }`） | 新的视图类型 `FoldingActionRequest`：`requestedBy?` **可选**；payload 没记就是**没有** | 旧行为是**伪造**："没记"被写成"系统发起的"（WP5-3 明令："Missing requestedBy is NOT evidence of SYSTEM"、"Do not silently convert: missing → system"）。新形状**只能**表达"缺席"，不可能表达出一条编造的断言 |
| W-5 | `DeveloperExecutionRequestDto.requestedByKind` + `src/infrastructure/dev/query-service.ts` | `requestedByKind: string`（`folded.request.requestedBy.kind`） | `requestedByKind: string \| null`（`folded.request.requestedBy?.kind ?? null`） | W-4 的直接后果：开发者平面**不能**再替一条没有记录请求方的历史行显示 `system` —— 那是同一次伪造在外发 HTTP 面上的镜像。`null` 的含义在 DTO 注释里写明 |
| W-6 | `ActionGateway.execute(characterId, request)` | 两个参数 | 追加**可选**第三参数 `invocation?: ActionInvocationContext` | 纯追加：既有调用点（含 135 条 L1 测试的测试台）**一个都不需要改**，行为逐字段不变；只有**装配了** `attribution` 的 gateway 才要求它（否则失败关闭 —— WP5-3） |
| W-7 | `ActionTurnInput.speaker` | `{ kind: 'user' \| 'character' \| 'system'; id?: string }` | 追加 `'tool'` | 与 W-3 同源（呈现角色词表对齐）；纯扩展 |
