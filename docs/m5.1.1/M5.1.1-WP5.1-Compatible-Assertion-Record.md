# M5.1.1 — WP5.1 Compatible Assertion Record

> **为什么要这份文件**：K-27 修正的是 **initiator 的证据来源**（呈现角色 → 因果上下文）。
> 它删掉了一个公开的契约入口、给一个端口输入加了字段、并让 WP5 的专项门改用它。
> 每一条都必须留痕，否则下一个人无法区分"判据被合理更新"与"判据被悄悄放宽"。
>
> 格式：**[面] · [旧] · [新] · [为什么不是放宽]**。

---

## 1. 总原则

```text
① 没有任何"必须成立"的断言被删掉。被改的判据都换成了**更精确**的形状
   （"呈现角色不能构造 Known"从**约定**变成**结构上不可表达**）。
② 权威语义只增不减：action 的 actor / executor / authority / recordedBy / 必要性矩阵 /
   Axis B N/A / Execution Truth 阶梯 / MIGRATION_0007 / MIGRATION_0008 **一字未动**。
③ 兼容面只做**最小**扩展（`speaker` 保留、只新增 `triggeringEvent`）。
④ 证据沿用 WP4.1 / WP5 的约定：**先 fork，再还原**冻结路径（见 §4）。
```

## 2. 逐条变更

| # | 面 | 旧 | 新 | 为什么不是放宽 |
|---|---|---|---|---|
| X-1 | `src/kernel/contracts/attribution.ts` | `attestActionInitiatorFromIngress({ adapterId, principal, unresolvedReason? })` —— 任意调用方给一个位次就能构造 `Known(principal)` | **删除**。in­itiator 只剩两个入口：`attestActionInitiatorFromCausalOrigin({ adapterId, causalSource })`（因果判据）与 `attestActionInitiatorUnresolved({ adapterId, reason? })`（不接受任何位次参数） | 这是**收紧**：旧入口让"呈现角色 → Known(USER)"在类型层完全可表达（K-27 的成因）。新形状下**没有任何 API** 能把一个呈现角色变成具体位次（WP5.1 §2 的"结构上不可表达"） |
| X-2 | `src/kernel/action/action-turn.ts` | `speakerPrincipal(speaker)`（呈现角色 → `PrincipalRef`）+ 用 `input.speaker` 构造 initiator 证据 | 删除 `speakerPrincipal`；initiator 证据只从 `ActionTurnInput.triggeringEvent`（因果上下文）或"如实未定"产出 | 同上。`speaker` 仍然存在、仍然只填 payload 的 `requestedBy`（兼容/输入证据） |
| X-3 | `ActionTurnInput` | `{ characterId, traceId, text, eventId, speaker }` | 追加**可选** `triggeringEvent?: TriggeringConversationEvent` | 纯追加：不传 ⇒ initiator 记 `Unknown(RUNTIME_UNRESOLVED)`（**不是**退回呈现角色）。既有调用点语义不变，只是不再有一条"呈现角色优先"的隐式路径 |
| X-4 | `src/kernel/app/turn-gateway.ts` | 只传 `speaker: { kind: 'user', id: userId }` | 追加 `triggeringEvent: triggeringConversationEventOf(userEvent)`（`userEvent` 是 recorder 读回来的那条 conversation event，WP4 之后带权威归因） | 这是**修好**数据来源：动作的因果上下文现在来自**账本读回的那一行**，而不是动作入口自己声明的角色 |
| X-5 | `scripts/verify-m5.1.1-wp5-action-attribution.ts` | 用 `attestActionInitiatorFromIngress({ principal: USER })` 造九个阶段的 initiator | 用 `humanInitiatorEvidence()`：一份**真正的受信人类来源**的因果上下文（RECORDED + `actor` 与 `contentOriginator` 都是 `Known(USER/u-1)`） | 断言**没有变**（九阶段仍要求 `initiator = Known(USER/u-1)`）；变的只是它现在必须**由因果证据建立** —— 这正是 K-27 要求的行为，而且 WP5 门因此也覆盖了新的构造路径 |
| X-6 | 契约新增（本步） | — | `TriggeringConversationEvent` / `CAUSAL_CORRELATION_BOUNDARY` / `TrustedCausalSource` / `triggeringConversationEventOf()` / `correlationSourceFromConversationEvent()` / `ActionInitiatorCausalBasis` / `TrustedActionInitiatorEvidence` | 纯新增。注意 `causalBasis` 把"为什么是 Unknown"**写进证据**（not_recorded / slots_disagree / slot_not_known），使"未定"可审计而不是一句含糊 |
| X-7 | `ActionGatewayOptions.attribution` 的语义 | 配了它 ⇒ 每次调用必须带**任意**受信 initiator 证据 | 配了它 ⇒ 每次调用必须带**因果建立的**（或如实未定的）initiator 证据 | 同 X-1：`ActionInvocationContext.initiatorEvidence` 的类型没变（仍是 `TrustedActionPrincipalEvidence`），但能产出它的构造器只剩两个 |
