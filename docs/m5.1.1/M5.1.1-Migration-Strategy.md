## 1. 不可协商的约束（来自仓库既有规矩）


### 2.1 **Phase 4：ADR-043 已批准，但落地分三步且必须先做只读预检（B7）**

```text
阶段 4 会改变既有不变量（Assistant Fact Firewall）的输入行为 ⇒ 它同时是
```

## 3. 历史数据回填：**逐（事件族 × 槽位）**判定

### 3.1 四态字母（**替换 Draft v1 的 A/P/U**）

```text
D  deterministic —— 存在**权威依据**，可以回填成具体值
P  partial       —— **一部分**行有依据（例如只有 ACTION_REQUESTED 带 requestedBy）
U  unknown       —— 从未记录 ⇒ **必须** Unknown(LEGACY_UNRECORDED)
N  not applicable—— 该槽位对此事件族**不适用** ⇒ 必须 Absent
```

> **为什么弃用 Draft v1 的单个 `A`**（请求 §13）：
> 旧字母表里 `A` 同时被用来表示 *available*（可确定）与 *absent*（不适用），
> 例如"`initiator` 在对话事件上是 **A（absent）**"。
> 一个字母承担两种互斥含义，必然在实现时被读错 —— 而读错的后果正是
> 把"不适用"回填成具体值（伪造）。故拆成 **D** 与 **N**。

### 3.2 `conversation_events`（逐 event family）

| 槽位 | `user_message` | `assistant_message` | `tool_event` | `system_event` |
|---|:--:|:--:|:--:|:--:|
| `subject` | D(派生) | D(派生) | D(派生) | D(派生) |
| `initiator` | **N** | **N** | **U** | **P** |
| `actor` | **U** ← B1 | **D** | **D** | **P** |
| `executor` | **N** | **N** | **N** | **N** |
| `authority` | **N** | **N** | **N** | **N** |
| `recordedBy` | **D** | **D** | **D** | **D** |
| `contentOriginator` | **U** ← D01 | **U** ← Rev2 修正 | **D** | **U** ← K-21/R-19 |

**逐条依据**

```text
subject      D：character_id 已是列，且既有行都有 → 派生，不新增存储（U-13）
initiator    user/assistant = N：一条消息没有"独立于 actor 的发起者"
             tool = U：必要性矩阵要求它，但历史上从未记录
             system = P：actor_id 常命名组件，对系统自发事件即为发起者 —— 但有行缺 actor_id
actor        user = **U** ← B1 的核心：actor_type='user' 只能证明"以 user role 提交"，
                             **不能**证明是谁作出决定 ⇒ 不得回填成 Known(USER)
             assistant = D：actor_id **强制**且类型被 assertSourceConsistency 约束为 character
                            ⇒ 这是**结构事实**，不是推导
             tool = D：同因（actor_type='tool' + actorId 即该工具）
             system = P：actor_id 可空
executor     **全部 = N**（K-3 FINAL，2026-09-18 裁定；WP2.1 同步）
             不存在"谁执行了一次 action"这个结论：执行者身份归 **Action / Execution Ledger**。
                          旧文本曾把 tool 判成 D（"该工具既是 actor 也是 executor"）—— 那会让
             conversation 的 tool_event 变成**第二个 Execution Truth 来源**；
             `actor` 与 `contentOriginator` 的 **D 不受影响**（它们是结构事实）。
authority    全部 = N：说话、观测、系统通知都不需要"许可"这个结论
recordedBy   D：**结构性事实** —— 系统里只有 kernel 自己的写入器能写这些表
             ⇒ **K-23 / R-20（2026-09-18 冻结）**：canonical ledger recorder =
               `Known(PrincipalKind.SYSTEM, "kernel")`；回填行的 `recordedBy`
               **必须恰好**是它（**`Absent` 也算违规 = 迁移完整性失败**）。
               它只说明"**谁写下了这一行**"，**不**说明也不得推出
               actor / initiator / contentOriginator / executor。
               `recordedBy` **不得由调用方提供**；将来的写入器必须**显式登记**
               （`TRUSTED_LEDGER_WRITERS`），不得顺手发明 `SERVICE` principal。
contentOriginator
             user = **U** ← 校名一案：从未记录"这段语义内容是谁提供的"
             assistant = **U** ← Revision 2 修正（见 §3.4）
             tool = D：工具即内容来源（观测）
             system = **U**（K-21 / R-19，2026-09-18 用户裁定）：
                      `actor_id` **不得**当作"这段内容是谁提供的"的充分证据 ——
                      系统事件里的 actor_id 常是一个组件名，它能说明"谁自发了这条事件"，
                      不能说明"内容来源"。历史 system_event 的 contentOriginator 一律
                      `Unknown(LEGACY_UNRECORDED)`（本格从 `P` 收敛为 `U`，
                      与 Proposed-Schema §3 的 `?` 一致）
```

### 3.3 `character_action_events`（逐 event type，**禁止整表判 D**）

| event type | initiator | actor | executor | authority | contentOriginator |
|---|:--:|:--:|:--:|:--:|:--:|
| `ACTION_REQUESTED` | **P** | **P** | **N** | **N** | **N** |
| `ACTION_TARGET_RESOLVED` | P | U | N | N | N |
| `ACTION_AUTHORIZED` | P | **U** | N | **U** | N |
| `ACTION_REJECTED` | P | U | N | **N** | N |
| `ACTION_STARTED` | P | U | **U** | **U** | N |
| `ACTION_SUCCEEDED` / `FAILED` / `PARTIAL` / `CANCELLED` | P | U | **U** | **U** | N |

```text
subject    : 全部 D（character_id 已是列）
recordedBy : 全部 D（结构性）
initiator  P：`ACTION_REQUESTED` 的 `payload.requestedBy` 是**已记录事实**，
              但其 kind 只有 user|character|system（**缺 tool**）⇒ 部分确定；
              同一 actionId 的其它事件可**关联**该记录值（关联 ≠ 推导）
actor      U：决策点（gateway / policy）没有被作为归因记录
executor   U：执行器从未记录（唯一有希望的是将来由执行器自报）
authority  REQUESTED / REJECTED = **N**：
             请求尚未授权（B5.1）／被拒即**未**获授权 ⇒ 结论集里没有"许可"
           AUTHORIZED 与执行事件 = U：策略结论未作为归因持久化
             ⚠️ ACTION_AUTHORIZED **存在**（已核实），所以这里不是"事件缺失"，
                而是"该事件没把 authority 写进归因"
contentOriginator N：行动不是内容断言
```

### 3.4 Revision 2 对回填矩阵的两处实质修正

```text
① `conversation_events.actor` 从 Draft v1 的"整列 D"改为**按族**：
```

### 3.6 旧行的 **Axis B**：冻结的精确值（Rev 2.1 · F3）

回填时必须写入**具体受控值**，不得留 NULL、不得用描述性占位：

```text
source_kind      = legacy classifier 的输出（既有 4 值之一）   ← D 确定
source_authority = 'UNCONFIRMED_ORIGIN'
epistemic_source = 'UNCONFIRMED_ORIGIN'                       ← EpistemicSource 新增值
```

```text
· Axis B **没有 Absent 态** ⇒ 三列在 MIGRATED_LEGACY 行上都必须非 NULL
· 写入期等式 `epistemic_source === epistemicSourceForKind(source_kind)`
  对 MIGRATED_LEGACY 行**刻意不成立**（不得声称它是 SourceKind 的推导）
  **· K-24 / R-21（2026-09-18）：该等式只属于 RECORDED 的 `confirmed` 分支。**
   `attribution_origin = RECORDED` **只**意味着"归因是在事件发生当时记录的"，
   **不**意味着认知来源已确立；因此 RECORDED 还有一个 **unconfirmed** 分支：
   `source_authority = epistemic_source = 'UNCONFIRMED_ORIGIN'`（**成对**，无外部事实资格）。
   两个混合形态必须拒。门 = `pnpm m5.1.1:wp3.2:verify`
· 迁移门 M7（见 §7）专门检查这三列在回填后**无 NULL、无越界值**
```

## 4. 认知资格影响的爆炸半径（**Phase 4 之前必须先量出来，且其处置属 ADR-043**）

`Unknown(LEGACY_UNRECORDED)` 的 `contentOriginator` **不得**支持外部事实（ADR D3 / B4）。
因此 Phase 4 之后，一批历史 `user_statement` 会**失去** `USER_EXPLICIT` 资格。

```text
受影响：所有「以 user role 提交但无法确立内容来源」的历史行
          → 包括 D01 实例中的那条「记住，我现在上的大学是示例工程科技大学」
不受影响：actor_type='character' / 'system' / 'tool' 的行
          （它们本来就不能支持外部事实 —— 白名单形状不变）
```

**三点必须写清**

```text
① **这是纠正，不是回归。** 那些内容从来没有"人类亲口说过"的证据；
   它们此前获得资格，靠的是把 actor_type='user' 等同于"人打的字"。

② **必须先在只读视图里量出半径，再切换。**
   落地时提供"若切换到新判据，哪些记忆会降级"的只读报告，
   让用户在看到**具体条数**之后决定是否继续。**不得**先切换再解释。

③ **已落库 memory 的 authority 如何处置 = MOVED TO ADR-043（U-06 / U-15）。**
   本 ADR 不裁决"保留当时判定 / 按新判据重算 / 标记为来源未确立"。
   ⇒ 这也是 Phase 4 被 BLOCKED 的直接原因。
```

## 5. 回滚 / forward compatibility

### 5.1 两类回滚必须区分（U-19 裁定 · `DECIDED WITH BOUNDARY`）

```text
Logical Cognitive Rollback（逻辑认知回滚）
  · 撤销一次认知干预的**影响**
  · 必须产生新事件（INJECTION_APPLIED → INJECTION_REVERTED）
  · **不能删除** intervention history

Physical Disaster Restore（物理灾难恢复）
  · 从数据恢复还原整库
  · **必须**建立新的 ledger epoch / restore epoch
  · **必须**显式记录 restore boundary
  · **不得**声称"同一数据库可证明跨物理恢复的完整历史"
```

**一条必须写下的边界**：

```text
若未来要求"即使整库灾难恢复也不能抹掉认知干预审计"，
则 audit sink 必须位于**不同的 persistence / failure domain**。
**"独立表" ≠ "独立故障域"。**
本轮**不**设计外部 audit service，只冻结这条边界。
```

### 5.2 回滚能力与阶段的对应

| 阶段 | 回滚方式 | 代价 |
|---|---|---|
| 1（只加列 + 回填） | 逻辑上可不还原 —— 旧代码忽略新列即可继续跑；需还原时按 §5.1 记 restore epoch | 低（列可空，旧代码无感） |
| 2（并存记录） | 停写新列；actor_type 与 event family 的检查是契约层既有闸，无需开关 | 低 |
| 3（槽位成为 attribution 真相来源） | **无行为级回退需求** —— actor_type 的值从不因此改变（Rev 2.1 删除了方向反转） | **低** |
| 4（切换 Firewall 输入） | **行为级回退**：Firewall 输入切回 actor_type | 中；且回退会**恢复**被降级的资格 |
| 5（日落 actor_type） | 不可回退（列被删/停写） | 高 → 需独立批准 |

**推论（Rev 2.1 修正）**：**只有阶段 4** 需要一个显式开关（走 `flags` 纪律：
"开关必须被真的消费" + 回归锁，见 AGENTS §5）。

```text
阶段 3 不需要开关 —— 因为 Rev 2.1 删除了"方向反转"，
       阶段 3 只是让槽位成为 attribution 的真相来源，
```

## 6. replay / rebuild consistency

```text
① attribution 属于**事件本体** ⇒ replay 必须**原样重现**，不得重新推导
② 投影**不得**做归因判断（它只能消费）
③ MI-11 的 `A == B` 必须仍然成立：删掉投影 → 从事件重放 → 逐字段一致
④ **新增**：attribution 不同的两行，不得因为经过投影而变得相同
   （否则审计信息在投影层被抹平 —— D01 这类缺陷最容易复发的地方）
⑤ **新增**：Unknown(LEGACY_UNRECORDED) 重放后必须**仍然是** Unknown；
   不得因为重放而被"洗"成 Known（B4：未知不得变成确定）
⑥ **新增**：`attribution_origin='MIGRATED_LEGACY'` 重放后仍必须是 MIGRATED_LEGACY
```

第 ⑤ 条对应请求 §14 的 mutation #6（`LEGACY_UNRECORDED` 被洗成 KNOWN USER → detector 必响）；
第 ④ 条作为 replay 门的新增断言（见 Test-and-Gate-Plan §5）。
