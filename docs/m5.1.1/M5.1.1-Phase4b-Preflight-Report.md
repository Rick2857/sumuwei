> **性质**：**只读**。本步**没有**改 `src/**`、**没有**打开数据库、**没有**执行 4b、**没有**写认知。

> Phase 4                 = PARTIAL / NOT COMPLETE

> M5.1.1 PASS 是否被主张   = 否

>
> 证据：`artifacts/m5.1.1/wp4bpre-preflight.json`（本门 `22 通过 / 0 失败 · EXIT 0`）

## 4. ⚠️ `warn` —— 真库的归因列状态（**D-1 已裁定 ②，迁移已落地并实测**）

用户在同一条消息里裁定 `D-1 = ②`「**先将真实库迁移至 v9，再考虑激活 4b**」。
迁移**已执行并逐条验证** —— 见 **`M5.1.1-Phase4b-Real-DB-Migration-v9.md`**：

```text
真实库 schema  v6 → **v9**（2026-09-19 应用；应用前有**已逐字节验证**的备份）
既有业务行     身份摘要**逐字未变**（conversation_events 28 行 d5277b597906… · 0 行 · state_events 1 行 c6ae3092fb4e…）
伪造归因       **0 行**带 `attribution_origin` · **0 行** `content_originator_kind='USER'` · **0 行** `MIGRATED_LEGACY`
记忆面         memory_records 仍是 2 条 EXPLICIT_USER_STATEMENT · 两个探针仍 = 0
```

**迁移不改变下面这个 100%**（这一点很重要，别读错）：

```text
28 行 conversation_events 里 `attribution_origin` 非 NULL = **0**
⇒ 全部历史行**没有信封** ⇒ 4b 的资格派生对它们一律 fail-closed（DR-7）
⇒ 她今天**全部 2 条**长期记忆（2/2 = **100%**）仍会拿到：
     · prompt 标签从 `（EXPLICIT_USER_STATEMENT）` 变成 `（EXPLICIT_USER_STATEMENT / 来源未确立）`
     · 排序里 authority 分量**降一档计**（**不改库值**）
```

迁移改变的是**另一件事**：**新写入**的记忆从此有地方记录受信归因 ⇒ 新记忆**可以**被确立。
（4a 已经让新记忆必须先过来源资格闸；那个闸读的就是这些列。）

**这是 INV-CI-04 要求必须 warn 的内容**，而它现在是**实测**的（不再是"由 v6 推出的推论"）。

## 6. 新专项门必须带的判据（ADR-043 §4.2 N-1…N-6）

| id | 类型 | 判据 | 归属 |
|---|---|---|---|
| `N-1` | 负控 | 伪造"agent 以 user 角色替发"（无受信归因）⇒ 必须拒绝 | 4a 已实现（新门复用） |
| `N-2` | 正控 | 同一内容带**受信的人类**归因 ⇒ 必须正常形成 | 4a 已实现 |
| `N-3` | 正控 | 既有 legacy 记忆资格 = `UNCONFIRMED_ORIGIN` ∧ `memory_records.authority` **逐字节未变** | **4b 新增（最重要）** |
| `N-4` | 恢复 | 规则版本回退 ⇒ 资格恢复 `ESTABLISHED` ∧ 账本**未被改写** | **4b 新增** |
| `N-5` | 正控 | `contaminatedMemories()` 仍 = 0（不得把新状态算成污染） | 4b（既有门 + 新门都守） |
| `N-6` | 自检 | 受影响条目数 / 受影响脚本数 **> 0**，否则 `MEASUREMENT INVALID` | **4b 新增**（本预检已给出两个非零读数：2 条 / 9 道门） |

`N-3` 与 `N-6` 最重要：前者证明"纠正资格"没有变成"改写历史"；
后者防的是"半径只有 2 条 ⇒ 门看起来全绿但其实什么都没量到"。
