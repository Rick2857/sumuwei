## 1. 一句话

任务书 §6 要求给 `SourceAuthority` 加一个新值；**加了之后，一个冻结文件就编译不过**
——而它编译不过的原因不是"缺一行"，是"**这个新值对应哪一种 MemoryAuthority** 还没有裁定"，
那个决定恰恰被 `U-06` / `U-09` **移交给了 ADR-043**。

---

## 2. 确切证据（可复现）

命令：

```bash
pnpm typecheck
```

结果：`exit code 2`，其中一条（其余为我自己的测试夹具类型问题，已修）：

```text
src/kernel/contracts/memory.ts(1336,13): error TS2322:
  Type '"UNCONFIRMED_ORIGIN"' is not assignable to type 'never'.
```

冲突点（`src/kernel/contracts/memory.ts:1307`）：

```ts
export function authorityFromSource(
  source: SourceAuthority,
  options: { isExplicitCorrection?: boolean } = {}
): MemoryAuthority {
  ...
  switch (source) {
    case 'USER_EXPLICIT':
    case 'USER_REPLY_CONFIRMATION': return 'EXPLICIT_USER_STATEMENT'
    case 'DIRECT_INTERACTION':      return 'DIRECT_INTERACTION'
    case 'TOOL_OBSERVATION':        return 'TOOL_OBSERVATION'
    case 'CHARACTER_GENERATION':    return 'CHARACTER_GENERATION'
    case 'SYSTEM_INSTRUCTION':      throw ... // 刻意失败关闭
    default: {
      const exhaustive: never = source     // ← 1336 行：穷尽性锁
      throw new KernelError('validation_error', 'unknown_source_authority', ...)
    }
  }
}
```

也就是说：`SourceAuthority` 的每一个取值都**必须**在同一个地方回答"它能形成哪种记忆权威"。
这是仓库**故意**装的锁（文件自己的注释写着：不用回落、失败关闭），
所以加值的那一刻，"记忆权威"这个问题就被强制提出来了。

---

## 3. 为什么这不能"顺手改一行"

| 约束 | 出处 | 后果 |
|---|---|---|
| `src/kernel/contracts/memory.ts` 的**事件 payload / Memory Kernel 语义**是**冻结区** | `AGENTS.md` §3（"只允许**追加**能力；语义变更要新里程碑 + ADR + **全套 `m4:*`**"） | 改它要走冻结区程序，而 WP1 §9 明确**只**跑 `typecheck` / `m5.1.1:test` / `kernel:test`，并明说"大的 inherited regression 留在后面明确的兼容性/回归 WP" |
| `MemoryAuthority changes` 属于 **Forbidden Scope** | WP1 任务书 §11 | 命中即"write blocker → STOP" |
| "新 SourceAuthority 对**已落库** MemoryAuthority 的影响" | `M5.1.1-Unresolved-Decisions.md` **U-06 / U-09** → `MOVED_TO_ADR_043`；`ADR-042` §4 L585 | 这正是**未裁定**的事项：来源未确立的内容**能不能**形成记忆、以什么权威形成 |
| `ADR-042` §7 | ADR 自述"不改变 Memory Kernel 语义" | 所以 ADR-042 本身**没有**给这个映射答案 |
| 设计集把 `contracts/memory.ts` 列为"★ 冻结区 —— 落地必须走新里程碑 + ADR + 全套 `m4:*`" | `M5.1.1-Affected-Surface-Map.md` §7 | 一致：这不是 WP1 能顺手做掉的事 |

**我特别没有选**"让它静默进入库里"的那条路：把 `default` 的 `never` 锁放宽，
等于把"我们不知道它算什么"变成一条正常返回的映射 —— `memory.ts` 自己的注释把这种做法
称作**最危险的做法**。

---

## 4. 我**没有**做什么（边界声明）

- 没有修改 `src/kernel/contracts/memory.ts`（一个字都没动）
- 没有放宽 `const exhaustive: never = source` 这个穷尽性锁
- 没有把新值改名、挪到别的类型、或先塞进数组而不进联合类型（那只是把同一个决定藏起来）
- 没有为了 `typecheck` 变绿而删除任何既有断言
- 没有运行任何会重写 `artifacts/m5.1/**`、`artifacts/m4.5/**`、`artifacts/m5/**` 的门

工作区状态：`pnpm typecheck` / `pnpm m5.1.1:test` / `pnpm kernel:test` **三条全绿**
（Axis B 扩展被隔离在本次交付之外，因此树是绿的、可提交的）。

## 5. 需要你裁定的三个选项

| # | 方案 | 具体做法 | 代价 / 风险 |
|---|---|---|---|
| **B1** | **在冻结区加一条 fail-closed 分支**（推荐） | `memory.ts` 的 `authorityFromSource` 加 `case 'UNCONFIRMED_ORIGIN': throw new KernelError(..., 'unconfirmed_origin_cannot_become_memory_authority', ...)`；语义 = "来源未确立的内容**不得**形成任何记忆权威"。ADR-042 充当"新 ADR"，但按 `AGENTS.md` §3 还应补跑**全套 `m4:*`**（约 +10 分钟；属"冻结区程序"的一部分，可以安排成一个独立的小 WP 来做） | 这是**新增语义裁定**（虽然是最保守的那个）；它会让"来源未确立"变成一条**硬拒**，而不是"低权威入库" |
| **B2** | 放宽穷尽性锁 | 把 `default` 的 `never` 改成普通兜底 | **不推荐**：削弱一条既有静态保障（把"必须显式回答"变成"可以漏答"），且与 `memory.ts` 的注释纪律相反 |
| **B3** | **把 Axis B 扩展推迟到 ADR-043 之后** | WP1 只交付归因七槽位 + 必要性矩阵 + Attestation 边界（即当前状态）；`UNCONFIRMED_ORIGIN` 与依赖它的 WP3 历史回填一起等 ADR-043 | M5.1.1 的 Phase 1 无法闭合（WP3 的回填需要这个取值）；`M511-G6` 的 `M7`（Axis B 完整性）也无法成立 ⇒ 需要重排批次表 |

**我的建议：B1，另开一个"冻结区落地"小 WP。** 理由：`ADR-042` §4 已经冻结了
"legacy 行的 `source_authority = UNCONFIRMED_ORIGIN`、且它 fail-closed、不得伪装成 `USER_EXPLICIT`"，
B1 是与之**唯一相容**的记忆侧表达；B3 会让阶段 1 结构性停摆；B2 是拿掉锁。
若你选 B1，请确认**是否允许在本 WP 内**（而不是新开 WP）改 `memory.ts` 并跑全套 `m4:*`。
