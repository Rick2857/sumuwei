## 0. 这份记录要回答的问题

WP9-B1 把**能力与边界**做好了（写入路径只接受带 `TRUSTED_INGRESS_MARK` 的信封），
但 `src/state/init.ts` **没有接线** ⇒ 生产里没有任何一条 `state_events` 带信封，
`E4-A = still unreachable`（`WP9-GAP-1`）。B2 接上那条线。

与 B1 不同，**B2 没有把任何既有 verifier 的判据文本从一个常量改成另一个常量**
（没有 `=== 8` → `=== 9` 这类 current-repository expectation advancement）。
B2 的判据变更面是：

```text
  ① 一个**新的**判据（新门 `wp9b2:verify`：Hard Gate 静态判据 + E4-A/E4-B + 三个负控）
  ② 一个**判据分类**改动（归因门注册表：把新门登记为"命中针表但非 WP8 九门 constituent"）
  ③ 一处**生产事实**变化（首启 state_events 行从此带信封）⇒ 若干既有判据的**观测输入**变了
  ④ 若干**必须保持不变**的判据面（矩阵 / Axis B / 回填分类 / v9 指纹 / INITIAL_STATE / manual reset）
```

R-46 §4 要求 F4 **至少 20 个 criterion-change groups**，每组十个字段。本文件 §3 给出
**22 组**：凡**改动**的组按十个字段逐条写；凡**有意不改**的组在 OLD/NEW 上都写"不变"，
并写明"为什么不改"与"证明它没被改的读数"（R-46 G20 的同一纪律：**有意不改也要如实登记**）。

**一条总原则**（贯穿全部 22 组）：

> 本轮的改动是**给一条已经存在、已经验收过的生产生命周期补上"它是谁"的受信来源**，
> **不是**发明一个新的业务操作，**也不是**把任何历史读数重新解释成"当时其实已经是这样"。

## 2. 三个 instrumentation correction（**必须单列**）

R-46 §5 要求 F4 单列 instrumentation correction，并明确标
**reading correction / instrument correction, NOT production semantic change**。B2 本轮实测到三条：

### ① `artifacts/m5.1.1/wp8-gate-manifest.json` 提交在 HEAD 上的是**红树读数**，不是当前读数

- **读数**：`git show HEAD:artifacts/m5.1.1/wp8-gate-manifest.json` 的
  `summary = { passed: 48, failed: 2, wp8Verdict: 'PARTIAL / BLOCKED' }`，
  `M511-G6 = FAIL（红门=wp3）`，`M511-G9 = FAIL（兼容性约束未过）`，
  同一个 commit 里的 `wp8-gate-exits.txt` 写的是 `24 / 25 绿 · 红门 = wp3(EXIT=1)`。
- **当前读数**：本轮 `pnpm m5.1.1:wp8:verify` 实测 **EXIT = 0 · 53 通过 / 0 失败 · `WP8-B = PASS`**，
  26 道被 harness 运行的门**全部 EXIT = 0**，`unexpectedWrites = 0`。
- **归属**：这是 **B1 收尾时的证据纪律副作用**（R-46 §2 要求把重跑改写的历史 evidence
  逐路径还原），把 B1 那次**红树阶段**的 manifest 留在了 HEAD，而"提交后绿树跑"的 manifest
  被还原掉了。它**不是**生产语义变化，也**不是** B2 引入的。
- **处置**：B2 在**提交后**重跑 `wp8:verify`（`wp8c3` 会连带跑它），把 harness 的
  **当前**读数（manifest / exits / invariants / mutations / measurement-health /
  negative-controls / cross-gate-consistency）与 `gate-results.json` 一起提交，
  使 `pnpm m5.1.1:gates` 在 HEAD 上重新读作 `G1–G7 PASS · G8 NOT RUN · G9 PASS`。
  **不改任何判据** —— 只让"当前读数"回到仓库里。
- **分类**：`instrument correction`（证据当前性），**NOT** production semantic change。

### ② `TRUSTED_INGRESS_MARK` 是**类型层**标记，浅拷贝会保留它（B1 既有边界，如实登记）

- **实测**：`isTrustedAttribution({ ...真实受信信封, ...攻击者字段 })` === `true`
  （读数：`负控(c2) 边界读数：…是否保留类型层标记 = 1`）。
  根因：`TRUSTED_INGRESS_MARK` 是**公开字符串常量**
  （`attribution.ts:2381` 原文："类型层：外部 DTO 不可能'顺手'长成这个形状"），
  `isTrustedAttribution` 是对那个字符串的运行期**结构**检查。
- **这不是 B2 引入的**：B1 的负控 (c) 用的就是"**没有** `TRUSTED_INGRESS_MARK` 的手写同形对象"
  （`verify-m5.1.1-wp9b1-verify.ts:766` 注释逐字如此），因此 B1 从没主张过"浅拷贝被拒"。
- **B2 的处置**：
  1. **不悄悄改判据**：B2 的门把它作为**读数**登记（`measure`，不冒充 PASS 条件）；
  2. 真正的负控 (c2) 用**没有标记**的手写信封 ⇒ 实测
     `untrusted_state_event_attribution` + 零行残留；
  3. 另加一条**生产不可达性**判据：静态 R7/R3 证明调用方**没有任何路径**把自报信封交给
     `recordStateEvent`（`attribution` 的值只能来自 `stateTransitionAttributionOf`）。
- **销账条件**：给受信信封加运行期 `WeakSet` 登记（硬化 `isTrustedAttribution`）属**独立 WP** ——
  它会触及共享契约与全部族的写入边界，超出用户裁定的 "minimal producer" 范围。**登记为 OPEN。**
- **分类**：`reading correction`（把一条既有边界的真实形状写清楚），**NOT** production semantic change。

### ③ 用 `Get-Content` 读 `artifacts/**` 会得到乱码，不能用来做证据比对

- **实测**：`Get-Content artifacts/m5.1.1/wp8-gate-exits.txt` 输出
  `缁撴灉锛?4 / 25 缁?路 绾㈤棬 = wp3(EXIT=1)`；同一文件用 `git show HEAD:<path>` 输出正确 UTF-8。
- **根因**：AGENTS §7 已登记 —— 仓库的文本多为 UTF-8 无 BOM，`Get-Content` 按 ANSI 读。
  后果不是"读起来难看"，而是 **`Select-String` 会静默匹配零条**（量具看起来没问题、其实什么都没量到）。
- **处置**：本轮所有证据比对一律用 `git show` / `read` / Node `readFileSync(…,'utf8')`；
  **没有**任何结论建立在 `Get-Content` 的读数上。
- **分类**：`instrument correction`，**NOT** production semantic change。

## 11. 证据纪律（本轮实际做法）

1. **一个进程一个库**：`isolateDatabase('m5.1.1-wp9b2')` 在最前面；真实库只被 `statSync` 采样。
2. **冻结面还原只按白名单逐路径**：跑门后先 `git status --porcelain -- artifacts`，只对**确实出现**
   的 `M` 路径执行 `git checkout --`；**没有**对 `artifacts/` 做无差别还原。
   本轮的**有意产物**是 `artifacts/m5.1.1/wp9b2-*.json` 与刷新后的 `wp8-*` / `gate-results.json`（§2①）。
3. **绝不 `git add -A`**：每个提交显式列出路径。
4. **不并发跑门**：所有门串行执行，任何时刻只有一个 pnpm 进程。
5. **读日志前看编码**：仓库文本 UTF-8 无 BOM ⇒ 一律用 `git show` / `read` / `readFileSync('utf8')`
   （§2③ 的真实事故）。
6. **冻结目录**：`artifacts/m5.1/**` 与 `artifacts/m4.5/**` 在收尾时 `git status` 为空。
