## 1. Attribution Truth Hard Gate + Attestation Gate

### 1.1 判据（原始原则）

> **不能仅凭 Character 是事件主体，就推断 Character 是作者或发起者。**
> 同理：**不得仅凭 `actor_type='user'` 推断"人类亲手输入"**，
> 也不得据此推断 `contentOriginator=USER`。

### 1.2 **B6 的核心修正：禁止的是"无证据推导"，不是"值相等"**

```text
Prohibited      : derive B from A without evidence
NOT prohibited  : A and B legitimately have the same value

⇒ 因此**废除** Draft v1 的两条错误全局规则：
   ✗ executor == actor   → FAIL
   ✗ initiator == subject → FAIL

合法反例（**必须能通过**，这是防假阳性的关键）：
   角色自主发起：subject=CHARACTER, initiator=CHARACTER, actor=CHARACTER
   工具既决定又执行：actor=TOOL/x, executor=TOOL/x
```

### 1.3 四条可执行判据

```text
G-AT-1  `actor` 不得由 `subject` 无证据推出
        · 运行时：写入路径不得以 subject 作为 actor 的默认值
        · 静态  ：不得存在 `actorKindFromSubject(…)` 之类的单一输入推导函数

G-AT-2  `contentOriginator` 不得由 `actor_type` 推出
        · 静态锁：不得出现 "actor_type === 'user' ⇒ 可支持外部事实"
        · 运行时：Fact Firewall 的可达性必须**消费 contentOriginator**
                  （落地锚点：canEvidenceExternalFact / extractor.ts:149）

G-AT-3  任何"默认作者"都必须不存在
        · 现存反例：`execution-record.ts` 的 `?? { kind: 'system' }`
        · 判据：全仓 grep 不得出现"把缺失归因填成具体位次"的默认值

G-AT-4  **Attribution Attestation Boundary**（B3 新增）
        · untrusted caller **不能**直接指定 contentOriginator
        · untrusted caller **不能**直接指定 authority
        · untrusted caller **不能**冒充 executor
        · 证伪形态：构造一份自报 contentOriginator=USER 的输入 →
          必须被 trusted ingress 拒绝 / 覆盖 / 不可传入（三者之一），
          **绝不**无条件信任
```

**门形态**：`G-AT-1..4` 各配**正控 + 负控**。其中 G-AT-2 必须有
"构造一个 agent 替发的 user 事件 → 断言它**不能**获得外部事实资格"的负控
（**这正是 D01 实例的回归锁**）。

**所有负控一律围绕 `evidence → recorded attribution` 的一致性设计，
不得围绕 `field A != field B`（B6）。**

## 2. 六类验收场景（ADR 第 13 点）

每一类要求：**正控**（链路正确）+ **负控**（**证据冲突**必须被拒）。

| # | 场景 | 必须能回答 | 正控 | 负控（证据冲突式） |
|---|---|---|---|---|
| **S1** | **User initiated** | 谁发起？谁决定？谁执行？ | `initiator=Known(USER/id)` · `actor=Known(CHARACTER)` · `executor=Known(TOOL/SERVICE)` · `authority=Known(CAPABILITY/…)` 四者可分别读出 | trusted ingress 记录 `initiator=USER`，测试**篡改为 CHARACTER** → 必响 |
| **S2** | **Character initiated** | `initiator` 是否**不再冒充用户** | `initiator=Known(CHARACTER)`；且 fingerprint 与 S1 **不同** | 无证据地声称 `initiator=Known(USER)` → 必拒 |
| **S3** | **System initiated** | 是否正确标 `SYSTEM`，以及"不知道"如何表达 | `initiator=Known(SYSTEM/组件名)`；无法确认时 `initiator=Unknown(RUNTIME_UNRESOLVED)`（U-04） | 无证据地填成 `USER`/`CHARACTER` → 必拒 |
| **S4** | **Tool executed** | Agent 与 `executor` 是否可**分离** | `actor=Known(CHARACTER)` 且 `executor=Known(TOOL/foo)`（此刻两者不同） | tool 证据说 `executor=TOOL/foo`，**篡改为 CHARACTER** → 必响 |
| **S5** | **failed execution** | 谁发起仍可追溯，**但不得记成已执行** | `initiator`/`actor` 可读；`outcome ≠ verified`；`verification` 四态如实 | 伪造 `executed=true` → 必拒（沿用 M5.1 既有负控） |
| **S6** | **legacy unknown** | 是否**显式**不可确定，而非被推测 | `attribution_origin=MIGRATED_LEGACY`、`<slot>=Unknown(LEGACY_UNRECORDED)`，且**不能**支持外部事实 | 把 `LEGACY_UNRECORDED` **洗成** `Known(USER)` → 必响（**迁移负控**） |

### 2.1 跨场景断言 —— **按语义维度**可区分（Rev 2.1 · F2）

> **Rev 2.1 删除**了 Rev 2 的"S1–S6 attribution 指纹**两两不同**"。
> 那是 B6 所禁止的值级判据的**场景级变体** ——
> S1 与 S4（乃至 S5）**可以描述同一次事件**，因此 attribution 完全可能相同。

**反例（必须被允许，不得报错）**

```text
S1 User initiated:      initiator=USER · actor=CHARACTER · executor=TOOL/foo
S4 Tool executed:       initiator=USER · actor=CHARACTER · executor=TOOL/foo
S5 failed execution:    initiator=USER · actor=CHARACTER · executor=TOOL/foo
  ⇒ 三者 attribution **相同**，区别只在
     S5 的 execution outcome = FAILED（**执行态**不同，不是 attribution 不同）
```

**改为按判定维度证明可区分**

```text
S1 vs S2 vs S3  → **initiator** 这一维必须可区分
                    （USER / CHARACTER / SYSTEM 三种发起者）
S4              → **executor 证据**必须真实，且其表达**独立于 actor**
                    （不得靠"executor ≠ actor"来证明分离）
S5              → **execution-state** 指纹与成功场景不同；
                    **attribution 允许相同**
S6              → **attribution origin / unknown 态**与 recorded-known 不同
                    （MIGRATED_LEGACY 与 RECORDED 可区分）
```

**原则（与 B6 一致）**

```text
不同**语义**必须可区分；
不同**测试场景**不必人为制造不同的 attribution。
```

**保留的对照（B6 的反假阳性要求）**

```text
构造 S2' = 自主发起（subject=initiator=actor=CHARACTER）→ 必须 **PASS**，
不得因为"三个字段值相同"而报错。
```

### 2.2 证据等级要求

```text
S1–S6 至少 Level 2（账本/事件）
S4 / S5 需要 Level 1（真实执行结果 / 真实失败）
否则"executor 与 actor 分离"只是契约层的自说自话。
```

## 3. mutation 负控（**七个**，取代 Draft v1 的五个）

| # | 注入 | 检测器必须报出 | 三段式 |
|---|---|---|---|
| ① | agent 以 user role 提交，但 `contentOriginator` 非 USER | Fact Firewall 检测器 | 正控安静 / 注入必响 / 恢复安静 |
| ② | untrusted caller **自报** `contentOriginator=USER` | Attestation 检测器（G-AT-4） | 同上 |
| ③ | untrusted caller **自报** `authority=CAPABILITY` | Attestation 检测器（G-AT-4） | 同上 |
| ④ | known `initiator` 证据被**篡改** | 证据一致性检测器 | 同上 |
| ⑤ | known `executor` 证据被**篡改** | 证据一致性检测器 | 同上 |
| ⑥ | `LEGACY_UNRECORDED` 被洗成 `KNOWN USER` | 历史洗白检测器 | 同上 |
| ⑦ | `ABSENT` 被错误填成具体值（如只读诊断填 `authority`） | **必要性矩阵检测器** | 同上 |

### 3.1 第 ⑦ 条为什么必须存在

它是 ADR §5 专论（"一个事件是否真的需要同时填写所有 attribution 字段"）的**唯一强制手段**。

```text
只测"必需槽位缺失 → 拒绝"，系统可以靠"把所有槽位都填上"通过。
必须同时测"非必需槽位被填充 → 拒绝/报出"，
否则"为了字段完整而填满"这条**制造虚假语义**的路径是敞开的。
```

### 3.2 第 ④⑤ 条为什么取代了 Draft v1 的"值相等"注入

```text
Draft v1 注入"把 executor 填成与 actor 相同 → 必响"
  ⇒ 它在合法世界会**假阳性**（工具既决定又执行时二者本就相同）
Revision 2 注入"篡改**已记录**的 executor 证据 → 必响"
  ⇒ 它测的是"记录是否忠实于证据"，与值是否相等无关
```

### 3.3 量具自检（INV-M45-06）

```text
□ 必要性矩阵检测器：喂一份**故意填满所有槽位**的 fixture → 必须报出
□ 历史洗白检测器：喂一份 LEGACY_UNRECORDED 写成 KNOWN 的 fixture → 必须报出
□ Attestation 检测器：喂一份**合法**（由 trusted ingress 构造）的输入 → 必须**安静**
□ 七个检测器各自：恢复真实现之后必须重新**安静**（否则检测器是恒响的噪声）
```

## 4. replay / rebuild consistency 断言

| # | 断言 | 说明 |
|---|---|---|
| R1 | 删掉投影 → 从事件重放 → **逐字段一致**（MI-11 的 `A == B`） | 既有性质，必须仍然成立 |
| R2 | replay **原样重现** attribution，不重新推导 | 若重放会推导，则"历史未知"又可被洗白 |
| R3 | `attribution_origin='MIGRATED_LEGACY'` 重放后**仍是** MIGRATED_LEGACY | 防"重放洗白来源" |
| R4 | attribution 不同的两行，**不得**因经过投影而变得相同 | 防审计信息在投影层被抹平 |
| R5 | `Unknown(LEGACY_UNRECORDED)` 重放后**仍是** Unknown | 防 B4 违规：未知不得变成确定 |
| R6 | 三态在渲染层可区分：`Unknown` **不得**被折叠成 `Absent`，也不得渲染成具体值 | 防"人类界面里看不到未知"（U-14：默认可见 + unknown count） |

**R4 的正控/负控**

```text
正控：两条 attribution 真正相同的事件 → 投影后仍相同（不得为了区分而造假）
负控：两条 attribution 不同的事件 → 投影后必须仍不同（抹平即失败）
```

**与 M5.1 的边界 —— compatibility rule（**Rev 2.1 · F4 已冻结**）**

> Rev 2 在这里留了一个"实现期待决"。评审指出它**不能**与退出条件的
> "全量回归零退化"同时悬空。以下为冻结规则，**不再留给实现去猜**。

```text
artifacts/m5.1/*            → **永久冻结**（一字不动）
M5.1 原 Gate 的**语义**      → **永久冻结**（不得删除、放宽或改变任何既有判据）
M5.1 Gate 的**测试源码**     → 若因**纯 additive** 契约演化而**无法编译**，
                              允许做**最小 compatibility update**
```

**允许的最小更新必须同时满足四条（缺一不可）**

```text
① 单独记录 changed assertions —— 逐条列出改了什么
② 证明**没有删除、放宽或改变**旧判据（只允许适配形状 / 类型 / 字段增补）
③ 新运行结果**只写** artifacts/m5.1.1/
④ 原 artifacts/m5.1/ **一字不动**
```

```text
⇒ 于是"历史证据永久冻结"与"当前代码仍能重跑旧 Gate"**同时成立**，
   退出条件里的"m4.5:ci / m5:* / m5.1:* 全量回归零退化"也就不再悬空。
⇒ 与之配套的门：**M511-G9 旧 Gate 兼容性**
   （检查 ①–④ 四条约束本身，而不只是看回归是否绿）
```

**仍然成立的既有硬约束**

```text
⑤ M5.1.1 的总判定**不得反过来**改动 M5.1 的结论或标签
```

## 8. Break-glass 的门（规则已冻结，**未实现**）· U-18 的落点

```text
M511-G8  Break-Glass Cognitive Override（**尚未实现**）
```

U-18 已裁定落地形式，此处只登记它将来必须被哪些判据守住：

```text
规则（冻结）
  system-level **enable flag**（默认 off）
+ per-operation **explicit reason**
+ explicit confirmation
+ mandatory audit
  ⇒ **存在 flag ≠ 获得一次操作许可**；每次仍必须重新授权

将来必须有的判据
  □ flag 默认 off，且被**真的消费**（沿用 flags 纪律 + 回归锁）
  □ 单次操作缺 explicit reason → 拒绝
  □ 单次操作缺 confirmation → 拒绝
  □ 每次使用都产生审计事件；**审计不可关闭**
  □ 审计里能**一眼识别**本次是 break-glass（不得事后靠推断）
  □ 执行后强制 integrity check
  □ **不得**伪造来源（沿用 G-AT-4）
```

> 本轮**不实现**，也**不设**该 flag —— 它属 Sovereign Core 约束，
> 落地归 Cognitive Integrity 里程碑。此处登记是为了让将来实现时
> 不必重新推导"一个开关不能满足两件事"这个结论。
