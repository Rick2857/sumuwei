# M5.1.1 — WP6 Compatible Assertion Record

> **为什么要这份文件**：WP6 让**读侧**开始消费权威归因，这会新增 DTO 字段、
> 触碰一条**编译期接地断言**，并让若干既有门重新生成证据。
> 每一条都必须留痕，否则下一个人无法区分"判据被合理更新"与"判据被悄悄放宽"。
>
> 格式：**[面] · [旧] · [新] · [为什么不是放宽]**。

---

## 1. 总原则

```text
① 没有任何"必须成立"的断言被删掉。唯一被改的编译期判据是**加一个派生键**，
   而且那个键的接地被 WP6 门逐字段实测（不是"声明它是派生的"就算数）。
② 权威语义只增不减：读写两侧都不做归一化 —— Unknown 不折叠、MIGRATED_LEGACY 不升格、
   执行真相（accepted / attempted / executed / verification）与归因可见性无关。
③ 只读面只增不改：查询套件前后六张权威表逐字段/逐字节等价（mutation = 0）。
④ 证据按既有约定：**先 fork，再还原**冻结路径（见 §4）。
```

## 2. 逐条变更

| # | 面 | 旧 | 新 | 为什么不是放宽 |
|---|---|---|---|---|
| Y-1 | `DeveloperTraceSummaryDerivedKeys`（`kernel/contracts/developer-query.ts` 的**编译期接地断言**） | `'durationMs' \| 'stepCount' \| 'hasError'` | 追加 `'attribution'` | 新键确实**不在** `CharacterRunTrace` 里（trace 表上也没有、不允许有归因列 —— WP6-6）。因此它必须以"派生键"登记；而**派生 ≠ 凭空**：WP6 门逐字段把 DTO 与 `conversation_events` 的物理列比对，并断言 trace 表没有归因列。这是任务书 WP6-5 明说的"minimal F4-compatible test-source adjustment" |
| Y-2 | `TraceSummaryDto` | 无归因 | `+ attribution?: DeveloperAttributionDto`（`input_event_id` → 那条对话事件的存储归因） | 纯新增且**可选**：没有信封的历史行**缺席**（不是"三态全 Absent"）。既有消费者不受影响 |
| Y-3 | `DeveloperExecutionDetailDto` | 无归因 | `+ attribution?: DeveloperAttributionDto`（最后一条带信封的 action 事件的**阶段快照**） | 纯新增且可选；**不**跨阶段合并（WP5-5），`basisEventType` / `basisSequence` 说明来自哪一条 |
| Y-4 | `DeveloperExecutionSummaryDto`（列表面） | 无归因 | **保持无归因**（有意） | 列表面对每一行都要多读一次事件流（N+1），而 WP6-10 明令"本 WP 暴露真相、不造新的搜索产品"。归因在详情面给；这条选择写进 WP6 handoff 与证据 |
| Y-5 | `conversation-store.ts` | 只有事件对象语义的 `rowToEvent`（RECORDED 才有信封） | 追加**读侧**函数 `readConversationEventAttribution(db, id)`（RECORDED 与 MIGRATED_LEGACY **都**解码） | 纯新增。**没有**改 `rowToEvent`（WP4 的语义与它的门原样：MIGRATED_LEGACY 不制造信封）。两条路分工是刻意的：事件对象 vs 读侧表示 |
| Y-6 | `action-ledger-store.ts` | 只有 `toEvent`/`decodeActionAttribution`（RECORDED 才有信封） | 追加读侧 `readActionStoredAttributions(db, characterId, actionId)`（两个 origin 都解码，按 sequence 升序） | 纯新增，同上 |
| Y-7 | `attribution.ts`（契约） | 只有槽位解码 | 追加 `storedAttributionOfRow()`（行 → origin + 六槽位 + Axis B 原样读数）与 `StoredAttributionReadback` | 纯新增；它是"读侧唯一解码入口"，避免查询面自己写第二套三态解码 |
| Y-8 | `developer-query.ts`（契约） | 无归因 DTO | 追加 `DeveloperPrincipalAttributionDto` / `DeveloperAuthorityAttributionDto`（三态可判别联合）、`DeveloperAxisBDto`（APPLICABLE / NOT_APPLICABLE）、`DeveloperAttributionDto` + 两个纯映射函数 + `DEVELOPER_ATTRIBUTION_IS_GROUNDED` 编译期接地证明 | 纯新增。三态用**判别联合**表达（`state` 字段），因此"未知"在类型层不可能被写成 `null` / `''` / `'-'` |
| Y-9 | `query-service.ts` | `toTraceSummary(trace)` 同步、无归因 | `toTraceSummary(trace, attribution)` + `traceAttributionOf(inputEventId)`（受信读取路径）+ 行动详情面的归因 | 纯增量：查询服务仍然**只读**（门里前后快照 + 静态扫描双证） |
