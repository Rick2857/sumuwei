## 3. 已被堵死的路（不要重走）

| 路 | 为什么不通 |
|---|---|
| **把两条被取代的断言"直接删掉"** | R-59 第 ④ 条明令：必须被**正向边界 + 反后门断言替换**。删除会让"抽取器不得把归因渗进认知路径"这件事**再无机器判据**——而它恰恰是最该守的那条 |
| **把 `trustedOrigin` 做成必需字段**，让 `tsc` 当影响枚举器 | legacy 行**确实**没有读数。做成必需会在**类型层说谎**，而且它会强迫每个夹具声明一个它没有的前提。预检预测"typecheck 必红一轮"，**实测 `TC=0`** —— 这条偏差已登记 |
| **在夹具里手写 `TrustedOriginReading`** | `DR-6`：只有**受鉴证**的归因算数。4a 门的 S4 会红（`axisBConfirmed` 在 `scripts/**` 必须 0 处） |
| **在 `processorEventViewOf` 之外读原始归因** | 4a 门 S5 与 `wp61` 的取代断言都会红（负控②实测过） |
| **往 `ProcessorEventView` 里另开一个原始 Axis B 字段** | `k17` 取代② 与 4a 门 S6 都会红（负控①实测过） |
| **把新闸放到闸 3 之后** | `authorityFromSource('UNCONFIRMED_ORIGIN')` 是**抛错** ⇒ 未确立来源会得到 500 而不是一条可读理由 |
| **把 `UNCONFIRMED_ORIGIN` 折进 `MemoryAuthority` 的最低档** | `DR-2` 明令禁止；那正是 `memory.ts` 里两段注释拒绝的回落 |
| **把 `CONTRADICTED_ORIGIN` 与 `UNCONFIRMED_ORIGIN` 合并成一个理由码** | `DR-3`：三值不可互相折叠；三值对"该怎么说"不同 |
| **给 `system_event` 补一个 ingress** | 用户 4a 执行令**明文禁止**；本步没做（`conversation-attribution.ts` 零改动） |
| **用 `createM4Harness` 之外的路径绕过正例** | 28 个 M4 脚本经它写用户事件；绕过 = 得到 legacy 行 = 事实类候选被失败关闭地拒掉 |
| **把 `wp11` 与 `wp8` / `gates` 串在同一条命令里跑** | `wp11` 的 §0 要求"干净树 + 五个冻结目录零差异"⇒ 会因前两道门刚写过 artifacts 而**假红**（实测 EXIT 1）。它必须**单独**跑 |
| **在注释里写出 `authorityFromSource(` 这种调用形状** | `k17` **不剥注释**，它按字面计数"src/ 里只有一处真的在算记忆权威" ⇒ 注释会把它变成 2 / 3（本步踩过**两次**） |
