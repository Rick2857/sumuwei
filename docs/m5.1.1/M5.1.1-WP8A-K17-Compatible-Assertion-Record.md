## 8. 本 WP 自身的一处**证据用词更正**（2026-09-18，如实记录，不是修判据）

**问题**：本记录（原 §6）、`M5.1.1-Execution-Plan.md` 的 R-36、以及
`artifacts/m5.1.1/k17-gate-exits.txt` 三处都写过「K-17 的（副本）预检只 `cpSync` 到临时副本」。
**这是错的**：`cpSync` 属于 `scripts/verify-m5.1.1-production-copy-schema.ts`
（该文件第 44 行 import `cpSync`、第 149 行 `cpSync(PRODUCTION_DB_DIR, workDir, {recursive:true})`，
`PRODUCTION_DB_DIR` 来自 `src/dev/sandbox.ts`），**不属于** K-17 的门。

**根因**：把「同一次 WP 里被提到过的另一个脚本的机制」当成了「这个门自己的机制」——
正是 AGENTS §6.9 的那一类（*描述的不是你以为的那个东西*）。

**实测**（`scripts/verify-m5.1.1-k17-consumer-impact.ts`）：

```text
第 33 行  import 'dotenv/config'
第 35 行  import { mkdirSync, readdirSync, readFileSync, writeFileSync } from 'node:fs'
第 36 行  import { join, relative } from 'node:path'
          —— 全部 import 就这三个；无 node:child_process / initDatabase / pglite
第 697 行  mkdirSync(<ROOT>/artifacts/m5.1.1)
第 698 行  writeFileSync(... 'wp2.2-k17-consumer-impact.json' ...)  ← 唯一的写操作
第 380 行  分类表里为 scripts/verify-m5.1.1-production-copy-schema.ts 记了一条 D
```

⇒ 正确的说法是：**K-17 门自身从不打开任何库**（不是"它用 cpSync 副本预检"）；
仓库既有的副本预检在**另一个**脚本里，本 WP 既未运行也未修改它。
真库 `data/pglite` mtime 仍为 **2026-09-17 23:51:40**（未变）。

**更正了什么 / 没有更正什么**：改的只有**三处文字**。判据、分类表内容、verdict、门读数
（15 / 0 · `unclassified = 0` · `staleEntries = 0` · `dangerous = 0` · `measurementInvalid = 0`）
与全部 artifact **一个字节都没动**。这类更正必须写进记录而不是悄悄改掉：一句把机制说错的
证据，和一条会说错话的判据（§4）是同一类风险。
