## 0. 一句话

**把「归因」（谁发起的 / 谁决定的 / 谁执行的 / 凭什么 / 谁记录的 / 内容是谁给的）从"只记 role"升级为"事件本体里记录、读时不再猜"的账本语义**，
而**不**在这一里程碑里改变"她的内容能不能变成外部事实"的判据 —— 后者是 Phase 4，属 ADR-043。

## 1. 里程碑定位与 D01 的关系

| 事实 | 值 |
|---|---|
| 里程碑 | **M5.1.1 Correctness Milestone**（M5.1 之后的独立里程碑） |
| 归属缺陷 | `M5.1-D01` Ledger Actor / Author Attribution Gap · Severity Architectural Correctness · **P1 · OPEN** |
| ADR-042 批准是否关闭 D01 | **否**（ADR-042 明确：ADR 批准 ≠ D01 关闭） |
| D01 何时可以关闭 | 仅在 **ADR-043 批准并落地**、且阶段 1–3 的验收全部达成之后（`Migration-Strategy.md` §7；`Test-and-Gate-Plan.md` §7 L313） |
| 本轮可交付 | **阶段 1–3**（WP2–WP6）；阶段 4/5 只登记依赖与停止条件 |

**继承的账本语义缺口（不是 M5.1 引入的）**：`conversation_events.actor_type` 是**归属声明**而非**作者证明**；
`character_action_events` 只有 `character_id`，没有 initiator / authority / executor。
M5.1 的十二道门没有任何一道在断言这件事 —— 所以 D01 不改变 M5.1 的 PASS。

## 6. 执行纪律

```text
每个 WP：Inspect → Implement → Target Tests → Evidence → Commit → STOP
每次 execution 只做一个 WP；做完即停，不得自动进入下一个 WP。
不得合并：WP2+WP3 / WP4+WP5 / WP8+WP9+WP10。
批次表与启动前置：见 M5.1.1-Execution-Plan.md §3。
```

三条跨里程碑的硬性质（任何改动都不许破坏）：

```text
① 她生成的内容永远不能自动变成外部事实（Assistant Fact Firewall）
② 投影是派生的：删掉能从事件重放出来，结果逐字段一致
③ 有副作用就必须有目标确定性、有账本、有 traceId；没成功就没成功口吻
```
