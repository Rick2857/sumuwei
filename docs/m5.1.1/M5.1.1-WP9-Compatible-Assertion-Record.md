## 2. WP9-1：真实运行时边界（本门实际用的入口）

```text
isolated sandbox DB（真实 schema v8，0→8 全迁移）
  → createM4Harness（真实 AgentRuntime + kernel + DB）        ← 唯一一个 runtime（单库单进程）
  → ConversationRecorder + TurnGateway（生产 ingress 由 conversationAttributionForEntryMode 提供）
  → createActionGateway + createEchoAdapter（与 src/main.ts 同一批工厂/权限/适配器）
```

## 3. 逐场景读数（全部 40 条断言通过）

| E | 真实入口 | Level 1（运行时可见） | Level 2（权威账本/物理行） |
|---|---|---|---|
| E1 | `interactive_human_console` ingress | turn 返回的 eventId / traceId；Query DTO actor=KNOWN/USER | `actor_type=user` · `actor=contentOriginator=Known(USER/<id>)` · `user_statement/USER_EXPLICIT/user_report` · origin=RECORDED · recordedBy=SYSTEM/kernel |
| E2 | `scripted_agent_runner` ingress | 同上（traceId 关联） | `actor_type=user` 但 `actor=contentOriginator=Known(SERVICE/agent-runner)` · Axis B `UNCONFIRMED_ORIGIN`（**不得**形成"用户本人陈述"） |
| E3 | 同轮 `completeTurn` → assistant 事件 | assistant eventId | `assistant_message` · `actor=Known(CHARACTER/<canonical>)` · `character_output/CHARACTER_GENERATION/character_generation` |
| E5 | 真实 action gateway + 真实 echo 适配器 | `executed=true` / `status=success` | 5 事件阶梯 REQUESTED→TARGET_RESOLVED→AUTHORIZED→STARTED→SUCCEEDED；initiator=USER · actor=SERVICE/action-gateway · executor=SERVICE/adapter:system.echo · authority=CAPABILITY/system.echo · Axis B 三列 NULL · recordedBy=SYSTEM/kernel |
| E6 | 同一真实适配器 + 缺参数（零副作用） | `error.code=validation_failed` | 同阶梯但以 **ACTION_FAILED** 收尾（无 SUCCEEDED）；initiator/actor 保留 |
| E7 | 同一 runtime 内不接线归因的 legacy 行 | —— | legacy 行 `attribution_origin` 为 NULL、受信读回**不制造信封**；与 RECORDED 行在同一 DB 共存 |
| E4 | 无生产入口（见 §4） | —— | 诚实 Unknown 分支：`Unknown(RUNTIME_UNRESOLVED)` |
| E8 | 真实 control 命令经真实 HTTP 面 | 阶梯到 `verified` | 审计行**不存在**（见 §4） |

**L1↔L2 关联（WP9-2）**：4 条关联全部由真实键建立且两侧一致（`eventId` / `traceId` /
`conversationId+sequence` / `actionId`）——没有"看起来应该是同一次运行"这种说法。

**逐字段相等（WP9-10）**：`runtime 写入的物理行 == 受信回读`，指纹逐槽位算（6 个槽位 + origin + Axis B），
`initiator=ABSENT|-|-|-` 与 `Unknown(reason)` 都参与比较，**不折叠**。

**D01 硬门（WP9-4）**：跨 5 层（写意图 / 物理行 actor / 物理行 contentOriginator / 受信回读 / Query DTO）
的 **USER substitution count = 0**；并以 agent-as-user 的真实 RECORDED 行作因果证据发起行动 ⇒
行动 `initiator = Known(SERVICE/agent-runner)`（K-27 跨账本，**永不** USER）。

**人类正控成对（WP9-5）**：同一 runtime、同一 presented role = user，human → `Known(USER/<id>)`、
agent → `Known(SERVICE/agent-runner)` ⇒ 排除"为了避免 D01 把所有 user role 降级"。

**E3 负控**：同一 family、但 recorder 不接线 ⇒ 无信封 ⇒ 证明 `family=assistant_message` **本身**
不是 `Known(CHARACTER)` 的证据。

**E6/Execution Truth**：`executed` 只由 `ACTION_*` 事件阶梯决定 —— `Known(executor) ⇒ executed`、
`Known(authority) ⇒ accepted` 都不成立；失败链以 ACTION_FAILED 收尾且无成功口吻。

## 4. 两个 capability gap（WP9-13：缺生产入口 ⇒ NOT RUN / BLOCKED，**不补功能**）

```text
WP9-GAP-1  E4-A：S3 的 Known(SYSTEM/组件名) 分支
  测量：生产 ingress 只覆盖 user_message / assistant_message
        （`conversationAttributionForEntryMode(...).producers` 实测 = assistant_message, user_message）
        ⇒ 没有任何生产调用点能给出 SYSTEM 因果证据；行动侧的 initiator 由因果来源决定，
          而因果来源只能是真实 RECORDED 对话行（USER/SERVICE/CHARACTER）。
  本门做到：证明该分支**不可达**（而不是猜一个 SYSTEM）；并把 S3 的另一半——"无法确认时如实 Unknown"
             ——用真实端口跑出来（`Unknown(RUNTIME_UNRESOLVED)`，不从呈现角色猜）。
  禁止的修法（执行令）：加 system producer / 加测试专用生产入口。

WP9-GAP-2  E8-audit：developer control 的 durable audit row
  测量：`developer_control_events` 表存在（MIGRATION_0007，31 列，**没有** Axis B 列、22 条 CHECK），
        但全仓库**没有任何生产 writer**（只有 DDL 与一处注释）——控制面自身明文写着"今天没有持久化的
        控制账本"（U-03 的 LANDING = 只落物理表示；已知局限 L-02）。
  本门做到：真实 control 命令经真实 HTTP 面执行并到达 `verified`（这一半真实可跑）；
            审计行**保持 0 行**，本门**不替它写一行**（写一行就变成 fixture 自证，违反 WP9-1/WP9-13）。
  禁止的修法（执行令）：给 src 加 writer / 让门自己造审计行冒充 E2E。
```

**冻结语义未变**：`developer_control: row('REQUIRED','REQUIRED','ABSENT','REQUIRED','REQUIRED','ABSENT')`
（`attribution.ts:385`）——`executor` / `contentOriginator` 必须 Absent；`authority` 的 kind 词表是
`POLICY/CAPABILITY/SYSTEM_RULE/USER_CONSENT/BREAK_GLASS`；`PRINCIPAL_KINDS` 里没有 DEVELOPER（U-02）。

## 8. 剩下的决定（留给用户裁定，不在 WP9 里自行决定）

1. **E4**：S3 的"无法确认 ⇒ 如实 Unknown"分支是否满足 canonical `E4 system initiated`？
   若满足 ⇒ E4 = PASS（以诚实 Unknown 形态），WP9 只剩 E8 一处 gap；
   若不满足（要求 Known(SYSTEM) 的真实生产路径）⇒ E4 保持 NOT RUN / BLOCKED，需要**另一个 WP**
   去实现 system producer（那属于新功能，不在验收 WP 里做）。
2. **E8**：`developer_control_events` 的持久化 writer（U-03 / L-02）是一个**独立**的未决物理面。
   本门只证明"命令真实可跑 + 审计承载面已冻结 + writer 尚不存在"。是否接受这个状态、
   还是先把 writer 作为独立 WP/ADR 落地，需要裁定。
