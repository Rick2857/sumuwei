## 2. 量具设计（为什么这些读数只有本门能出）

- **入口机制**（M7 §8.3 时序逐字沿用 M8）：交互控制台 spawn + stdin 管道 ⇒
  ESTABLISHED(KNOWN USER) 受信归因 ⇒ 显式陈述有资格成为信念证据。
- **spawn-per-turn**：每轮一个全新进程 ⇒ 19/200 次真实重启，信念状态每轮都从盘上来
  （投影/水位/依赖失效）——「重启后还在」是活体事实，不是模拟。
- **单臂注入**：`CHARACTER_BELIEF_ENABLED=true` 只注入子进程环境（代码缺省仍 false；
  生产激活属 WP11 独立裁定 M9-D26）。
- **真实库纪律**：`cpSync` 生产副本 → 门内只写副本 → `digestTree` 真实库前后摘要
  **逐字相同**才认读数（6/6 次运行全部成立；本里程碑从未打开真实库写入）。
- **开跑闸**（量具有效性先于读数，INV-M45-06）：① `DSH_TEST_MODEL_WRAPPER` 标记缺失
  即拒（绝不回落 `.env` 原 key）；② 语料自检（真判据函数逐轮过闸）。
- **程序状态 oracle**：5+6 个冻结检查点逐点断言状态机轨迹（不是只看回复）——
  s1：槽位恰 1 条 detailed 记忆 + reported 信念已成 + active 恰 2（语料槽+真实学历）+
  **cutover < T01 序号（真实旧历史零重判）**；s2：brief 生效、detailed superseded 仍在、
  旧值信念不再 active；s3：retracted + 槽位 active 信念=0（依赖失效传播）+ 学历不受牵连；
  s4：Memory 数与 s3 持平（诱导/未知/情绪轮零写入）+ 无深夜/杯子污染；s5：夹具 3 根×2 会话

## 3. 结构性边界（如实记录，不造假覆盖）

## 5. 发现

### 5.1 F-1（真发现，呈现层）：遗忘后追问会从可见对话历史复述被遗忘取值（1/3 复现）

- **现象**（run 1 T11，逐字）：用户问「你刚才让我忘的具体是什么？」，她答
  「一开始你说“技术问题我喜欢详细解释”，后来更正两次，最后落在“平时按简短讲……”」
  ——**逐字复述了被遗忘的取值**（命中 2 处泄漏词形）。
- **状态层无恙**（这是关键归属）：s3 检查点证明记忆已 retracted、槽位信念已失效、
  学历信念不受牵连；s4 证明遗忘后 6 轮零写入、无复活。**泄漏通道不是信念状态**，
  而是上下文窗口里的**原始对话行**（T01/T05/T07 就在近期窗口里，模型如实引用）。
- **政策缺口**（非回归）：M4 的 `response-truth.ts` 只绑定**遗忘轮自身**的回复口吻
  （「撤了」必须为真）；对**后续轮**的复述没有任何条款。族 7 的「不借解释再泄漏」
  强于既有政策——live 门量出的正是这条缝。
- **非确定性**：run 2 的 T11 是**干净的拒绝**（「最早的，后来的更正，都算在里面……
  你说，撤了，以后不用」——只讲结构不复述取值），run 3 同样干净。⇒ 1/3 泄漏率，
  不是确定性缺陷。
- **修复选项**（**需用户裁定**，改的是回复行为=措辞层政策，ADR 领域，
  cf. DR-11/ADR-055 对措辞层启发式守卫的既有否决立场）：
  ① 上下文侧：近期行装配时对命中 retracted 记忆的行做遮蔽/标注（改 turn-gateway
  装配层，风险=误伤正常对话）；
  ② prompt 侧：遗忘确认后注入一段「已撤内容不再引用」的政策行（改 sections，
  风险=与 DR-11 立场冲突，需要新 ADR）；
  ③ 接受为已知局限登记（L-M9-xx），交 M9.5/M10 处理。
- **登记**：WP10 Gate-Decision 必须分列此项；§15.3 的严重项 0 阈值在修复/裁定前**不满足**。

run 1 的 T19：夹具推断信念（讲解偏好 concise）确实入模（LV-S5 机械面绿），但她把
