## 1. 审计方法

1. 通读 M9.5 计划全文（§0–§21 + 附录），提取其建设面：WP0–WP12、S01–S60 场景矩阵、
   技术债接收表（§4.3）、八段漏斗（§10.4）、拟议文件边界（§13）。
2. 对照 M9 **剩余**建设面（WP8–WP11；WP0–WP7 已收口，不在审计范围——已建成的不存在
   "取消建设"问题，只有被 M9.5 **消费**的关系）。
3. 对每个疑似重合点问两个问题：
   - **重合吗？**（同一性质、同一证据面，还是不同平面的平行性质）
   - **迭代吗？**（新一代是否覆盖旧一代的全部断言面并扩展之；旧一代是否因此失去
     独立建设的必要性）
4. 迭代成立 → 按用户裁定②取消落后一代（M9 侧）建设；重合但不迭代 → 按裁定①只取消
   真正重复的部分；都不成立 → 保留。

## 3. 逐项判定

### 3.1 迭代关系成立（2 项）→ 取消 M9 侧建设

#### ① B32 长轨迹 + 1×500 门 → 取消 `m9:long:verify` 建设

| | M9（旧一代） | M9.5（新一代） |
|---|---|---|
| 原文 | 计划 §14：B32「更正后第 60/200/500 轮追问 \| 当前读数/入模/回复分别核对，旧值回潮不能隐藏」；WP8 交付「1×500」 | §4.3：L-M61-04「长程取回衰减」+ L-M61-05「更正后旧值回潮」均标**核心专项**；WP0 任务 2「用隔离夹具复现……60 轮更正回潮、200/500 轮取回」；WP9「至少三条 500 轮轨迹」；S53「60/200/500 轮回访与中途重启 \| 当前有效证据仍可用，检查点零旧值污染」 |
| 断言面 | 信念面单层（believed 旧值回潮） | 八段漏斗（§10.4）八层：持久化→supersede→索引→候选→资格→预算→**第 7 层明确含 Belief section**→回复；外加中途重启 |
| 规模 | 1 条 × 500 轮 | 3 条 × 500 轮 + WP0 复现读数 |

判定：M9.5 的轨迹建设**覆盖** M9 B32 的全部断言面（漏斗第 7 层点名 Belief section 旧值回潮；
第 8 层覆盖"回复"核对）并在规模与检查点纪律上扩展。M9.5 WP0 自带"用隔离夹具复现 60/200/500
读数"的任务，**不依赖** M9 先跑出 B32 读数——它自己复现基线。⇒ **迭代关系成立**。

处置（裁定②）：**取消 M9 的长轨迹门建设**。`m9:long:verify` 不创建；B32 不在 M9 出证据。
M9 收口报告如实记录：「B32 = CANCELLED → 迭代移交 M9.5（其 WP0 复现 + WP9 三轨覆盖）」。

**诚实风险声明**：M9.5 计划状态是「本执行方案待审阅」——若 M9.5 最终不建设，
60/200/500 轮的信念持久性将**没有专门的长轨迹证据**（WP6 的恢复/分页/断点证据仍在，
但非 500 轮档）。此风险由用户裁定②显式接受，本审计如实登记，不替用户淡化。

#### ② B43 的 Recall 半边 → 取消该半边建设

| | M9（旧一代） | M9.5（新一代） |
|---|---|---|
| 原文 | 计划 §14：B43「Memory 位于 1/50/51/500/501/最老 \| **核心依赖 ID 回查完整；Recall 候选范围如实报告**」 | §4.3 技术债接收表：TD-08「候选规模/截断 \| **接收仍未解决的 Recall 半边** \| 第 1/50/51/500/501/最老记录及全覆盖计数有证据」；S31「第 1/50/51/500/501/最老事实 \| 索引覆盖与候选截断分别可见」；S32（500/2,000/10,000 覆盖对账） |

判定：B43 是**双半边场景**。信念半边（核心依赖 ID 回查完整）是 M9 独有契约，M9.5 不接管；
Recall 半边（候选范围如实报告）被 M9.5 §4.3 **显式接收**为 TD-08，并以 S31/S32 建设真实
覆盖证据——旧一代只做"如实报告局限"，新一代做"全覆盖计数证据"。⇒ Recall 半边**迭代关系成立**。

处置（裁定②）：M9 的 scale 门**只建信念半边**（1/50/51/500/501/最老位置的依赖 ID 回查完整），
**不建** Recall 候选范围的报告构造。M9 收口时 B43 记：「信念半边 = M9 证据；Recall 半边 =
CANCELLED → 移交 M9.5 TD-08/S31/S32」。
