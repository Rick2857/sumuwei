## 2. Blaniel（主参考）：借鉴与改造清单

固定源码：[`lib/emotional-system/modules/appraisal/engine.ts`](https://github.com/Lucas-Dono/blaniel/blob/8d390b13b5f21fc807ef4a64ed9fa61dbde28f4f/lib/emotional-system/modules/appraisal/engine.ts)（AppraisalEngine）。

**借鉴（思路层，逐条对应 M8.5 设计）**：

| Blaniel 做法 | M8.5 对应 |
|---|---|
| 角色视角评价与回复生成分离 | 语义评估器独立于回复链（慢路径 worker） |
| LLM 只返回结构化评价 | 判定闭集 + ≤3 候选 + span（ADR-068 D05/D12） |
| 明确评价对象 | `target: "CHARACTER"` + 对象/立场判别（D08） |
| 失败有具名出口 | FAILED/INELIGIBLE 分列 + 闭集失败码（D06） |

**必须改掉（本项目边界，逐条冻结）**：

| Blaniel 做法 | 为什么不能照搬 |
|---|---|
| 入口无显式近期对话历史 | M8.5 需要**有界上下文**解决代词/反讽/修复（D10） |
| fallback 含 `desirability: 0.1` | 模型失败不得默认产生正面影响——失败如实落终态（D04/D06） |
| 缺失值补中点、数值夹紧 | 结构不合法必须**拒绝**，不自动补成可提交提案（D13） |
| 自由数值评分 / 关系阶段 / 目标输入 | 首版只分类既有七族；模型不指定数值（D05/D07） |
| 模型输入/输出可进日志 | 出站隐私闭集 + 回执只存引用/闭集/偏移/指纹（D11） |

**"参考思路"与"复制实现"登记**：M8.5 **未复制任何 Blaniel 代码**——必要接口以项目现有类型、原生 `fetch` 与严格解析重新表达（判别器先例 `openai-search-need-judge.ts` 的传输纪律）。若后续任何 WP 实际复制代码，须另登记文件、SHA、许可证与修改清单，并保留归属说明。

## 3. 其余候选逐条

**FAtiMA Toolkit（Apache-2.0，GAIPS 研究组）**：认知评价理论（OCC 系）与组件化术语的参考来源；其 C# 组件栈与本仓库技术面不匹配，引入即第二状态权威（计划 §4.1 已否决）。**采用**：appraisal 术语与"评价 ≠ 情绪状态"的概念边界。**不采用**：任何运行时组件。

**EmoLLMs（MIT，中文情绪分类/强度模型 + 训练代码）**：文本情绪分类 ≠ 角色所受互动影响（计划 §4.1 的核心理由——"用户这句话是悲伤的"与"苏沐薇被这句话影响了什么"是两个问题）。**定位**：推荐路线（现有 LLM + 受限类别）未达 WP2 阈值时的备选研究入口，届时另行评估部署与适配成本。**不预先部署**。

**CPED（中文个性化情感对话数据集）**：多轮对话 + 情绪 + 对话行为标注，对 WP2 的**标签设计**（情绪/对话行为区分、多轮标注格式）有参考价值。**三条硬边界**（计划 §3.3）：① 仓库许可不自动覆盖数据再分发——任何实际取数前先核对数据自身使用条件；② 测试语料**永不进生产记忆**；③ 电视剧中的角色关系**不能**直接当成苏沐薇的关系。金标主体是自建语料（计划 §13.5）。

**Affect Kernel（Apache-2.0，确定性状态层）**：职责与 M8 已交付的状态轴/衰减/投影高度重叠——引入即第二状态权威，违反 D01。其"per-constant provenance"的常量溯源做法与本项目"数值改动留版本记录"（D16）精神一致，属已有纪律，无需引入。

**occ-emotion-engine（MIT，OCC/VA 演示）**：计划编制轮已读源码：其"语义理解"仍含词表驱动，恰是 M8.5 要解决的问题本身，不构成参考。
