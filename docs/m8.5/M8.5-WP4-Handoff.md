## 5. 设计要点（供 WP5/WP6 对齐）

- **传输在两层之间**：`buildSemanticOutbound`（出站文本+指纹）→ WP5 provider 一次 HTTP → `parseSemanticJudgment`（信封→判定）。provider 只产 `SemanticModelResponseEnvelope { content, finishReason, hasToolCalls }` + 传输失败码（4 码闭集）。
- **指纹链**：出站 fp = SHA-256(指令+输入块) 前 16 hex；指令变 ⇒ 出站 fp 变 ⇒ 新指纹 + 重验（闸保证不重评旧事件）。
- **IMPACT reasonCode 家族必须落在候选家族里**（判定自洽检查，schema 拒）。
- **映射防御性兜底**：`semantic_mapping_no_legal_family` 抛错路径不可达（解析层已保证候选合法）——失败关闭，不静默。
- 出站文本含完整指令（~1.7k units）+ 输入块；守卫 6,000 units 下常规消息 + 6 条上下文有余量（门 O7–O10 实测截断行为）。

## 6. 交接给 WP5 的事项

- provider 输入 = `SemanticOutbound.text`（单条 user 消息即可；或 system=指令 + user=输入块——由 WP5 定并冻结，出站 fp 覆盖两侧拼接）。
- `finishReason` 语义：'length' → truncated、'content_filter' → refusal（解析层已按此归因）；HTTP 429/5xx/网络/超时 → 传输 4 码（唯一可重试类别）。
- `json_object` response_format（探针实测 JSON 合法率 100%）；max_tokens 3,000；超时 20,000ms 覆盖 body 读。
- 环境面：`OPENAI_SMALL_MODEL` 槽位（与 judge 先例同面）；凭证/端点纪律照 `openai-search-need-judge.ts` 先例。
