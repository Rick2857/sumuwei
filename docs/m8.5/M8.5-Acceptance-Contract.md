## 4. 量具有效性契约（§6 纪律的机器面）

1. **三段式**（正控/负控/恢复）：每件量具都要证明"测量范围正确"与"测量结果
   正确"；盲测器内置 §17 失败注入自检（timeout/5xx/拒答三注入全响，零伪造
   NEUTRAL、零 IMPACT）。
2. **measured_count 自检**：计数型检测器检查 0 项时结论必须是 MEASUREMENT
   INVALID 不是 PASS（live 门 LV85-MEASURED、盲测器、shadow 器均内置）。
3. **判据子集显式落盘**（D-WP10-1）：立场/操纵/注入/清晰正例四个子集的成员
   由标签穷举进证据 JSON，可复核。
4. **报告值 = 最差 run**（D-WP10-3）：重复 run 是稳定性证据，不是挑最好的一次。
5. **SEMANTIC_MISS 归属权**（D-WP10-4）：机器无金标不能判"语义漏了"——
   keyword 命中 ∧ 语义 NEUTRAL 一律先记 LEGACY_FALSE_POSITIVE 候选，人审
   抽样改判。

## 5. 证据纪律（§21）

- 证据优先级：Level 1 真实外部结果 > Level 2 账本/事件 > Level 3 集成 >
  Level 4 单测；最终验收至少 Level 1 + Level 2。
- 失败档分列保留、不回写（m8 先例；本里程碑 e2e/long/live 的 FAIL 跑全部
  入库为诚实记录）。
- 聚合门失败关闭如实拒收（m6.1 先例）。
- 判据错了如实写进报告，不悄悄改判据。
- 真实库零打开：全部真模型门在隔离库或生产**副本**上；真实库只做
  digestTree 前后摘要对照（live 终读数：1208 文件逐字相同）。

## 6. 人审与激活的硬前置（§20/§22.1）

- 人审材料独立成包（无标签盲审：不标金标/类目/tags/模型名/路径来源）；
  判定权在人，未审不填，审不过不激活（M85-D22）。
- 激活三前置**不可互相替代**：§16–21 全门 PASS + §20 人审 PASS + 用户显式
  批准。实施授权（头部 2026-09-26 记录）不覆盖本条。
- 金标裁定清单：Corpus-Spec §6 Q1–Q9（pending-ruling）+ WP10 裁定二的两条目
  （b-rep-006 金标归属 + b-host-010 稳定性复核）——人审材料无标签，裁定权
  在人；人审结论与金标的分歧清单回写 Corpus-Spec §6，不回写已冻结条目原文。

## 7. 判定格式（Gate-Decision 的分列格式，沿 M8 先例）

六项分列，不许合成一个总分：design approval / implementation / hard gates /
semantic evaluation / live smoke / production activation。每项独立判定
（PASS / FAIL / PENDING / NOT RUN），证据路径一一对应。
