## 3. 本轮冻结的设计裁定（WP8 新增）

1. **D-WP8-1 reducer 版本是注册级决定，不是模式级。** 首跑门撞上 event-store 的
   `reducer_version_mismatch` 守卫（投影行只许一个 reducer 版本，混用增量折叠被
   绝对拒绝）。正确形状：`createAffectJobPorts`/`seedAffectOrigin` 接
   `affectReducerVersion`（缺省 1 = 生产现状，M8 逐字不变）；语义调度器的 apply
   恒 @2。**WP13 激活 = 受控 rebuild（@2 重放、重盖 @2 章）+ 注册切 @2**；
   A==B（M85-D19）保证激活后 rules 模式的折叠结果也不变（门内 P3pre3 实测：
   @2 重放 rules 时代事件，valence 逐字一致）。
2. **D-WP8-2 激活就绪闸（`affectSemanticActivationReady`）。** 没有它，WP13 之前
   把旗设成 `semantic` 会得到坏中间态：词形 IMPACT 已让位、语义 IMPACT 全被
   版本守卫拒 ⇒ valence 冻结无人写入。闸的语义：旗 ∧ 投影行 @2 才生效；未就绪 ⇒
   **不让位**（M8 全路径照常）+ 语义 worker 不跑 + 一次性告警。这是启动前提的
   失败关闭（确定性判据：注册状态），**不是** M85-D01 禁的运行时自动回落。
   main.ts 的 `semanticActive()` 消费它（S2f 静态锁——D3 消费锁纪律）。
3. **D-WP8-3 语义扫描窗从 0 起扫 ⇒ 模式切换后的首轮会把切换前的合格 source
   一并评估**（M8 消费不产生语义闸行）。生产上由 §8.3 的 120s 时龄上限兜底
   （激活时旧消息全部 EXPIRED）；门内如实覆盖（M1 判 NEUTRAL——词形时代已记，
   语义面不双重记）。
4. **D-WP8-4 可重试失败的任务行落 `failed` + 闭集传输码**（不是 pending）：
   行状态只是审计残留，重推导的真相源是水位间隙 `(workerWm, scannerWm]`
   （WP6 W7 已证；本轮 R2e 修正了门的错误预期）。
5. **D-WP8-5 收尾链**：`close()` 先 `semanticAbort.abort()`（在飞模型调用 ⇒
   传输失败 ⇒ 可重试）再有界（10s）等 drain 退出，然后交唯一关库链。一次性
   CLI 的消息若在收尾前没评估完 ⇒ 留可重试态，**下一进程**启动追赶补（或按
   时龄 EXPIRED）——已知局限，记 §7。

## 7. 已知局限（WP8 范围内如实登记）

- **一次性 CLI 的语义评估大概率不在本进程完成**：回复返回后 drain 是
  fire-and-forget，收尾是 abort-收拢（D-WP8-5）⇒ 消息留可重试态，下一进程
  补或按时龄 EXPIRED。交互式会话（`pnpm chat`）不受影响（进程常驻，tick 排干）。
- **WP13 之前生产语义面休眠**：旗设 `semantic` 而未激活 ⇒ 就绪闸让全链按
  rules 运行 + 告警（D-WP8-2）。这是刻意的不半激活。
- **模式往返需要 rebuild**（rules↔semantic 各一次）：版本守卫的必然推论。
  回滚到 rules 后 M8 路径在 @2 行上会撞守卫 ⇒ 回滚 ADR 必须含 @1 rebuild
  或保持 @2 注册（A==B 下后者行为等价、更省——建议 WP13 ADR 里裁死）。
- 扫面/就绪闸读投影行：`getAffectProjection` 每进程一次（`semanticActive` 缓存），
  无热切换。
