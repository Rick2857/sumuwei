## 4. worker 关键设计（冻结，WP7/WP8 不得漂移）

- **commitOutcome 端口**是终态唯一出口：`{impact?, receipt, fallbackReceipt}` →
  事件落地用 `receipt`（COMMITTED/NO_IMPACT 编码）、放行口拒绝改落 `fallbackReceipt`
  （TERMINAL_FAILED 编码）——**两种结局闸行都落**，source 永不悬空。
  WP7 接真 validator 后此语义不变（拒绝 ⇒ TERMINAL_FAILED 终态 + 拒码进计数）。
- **EXPIRED 语义**：扫描期与认领期各查一次时龄；过期 = 终态（不出站、不重试、
  无 IMPACT）——"很久前的闲聊不在重启后突然改变当前情绪"。
- **SOURCE_INVALIDATED**：认领时重读 source 重跑资格判定（提交前重新校验）；
  失败 ⇒ 终态不提交。CANCELLED_BY_MODE_CHANGE 的回执编码走同一条
  commitOutcome 原子路径（模式切换的主动取消写入归 WP8 装配）。
- **上下文装配**：候选 = 账本区间 `[max(1, seq-50), seq-1]`，收紧（同会话/≤30min/≤6 条）
  在 WP4 `assembleSemanticContextWindow` 唯一实现里。
- **资格判定**：`affectEvidenceVerdictOf`（唯一实现）逐事件单候选调用；
  `trustedOrigin` 走 `processorEventViewOf` 派生（ADR-043 DR-6，不读裸字段）。

## 6. 交接给 WP7 的事项

- **放行口判据**：`affect-validator.ts` 增 `affect-semantic-policy@1` 白名单——
  按 family 校验**精确增量**（`AFFECT_RULE_DELTAS[family]` 逐字段，不是只查 ±0.25 范围）；
  `ruleVersion` 必须等于 policy 版本；`timingKind=SOURCE_ANCHORED` + `sourceAt` 有限。
- **接线**：worker 的 `commitOutcome` 生产实现 = 提案 → 真 validator →
  `applyAcceptedEvents`（extras 闸行）；拒绝 ⇒ `fallbackReceipt` 终态 + 拒码闭集计数。
  门的直构实现（本批）证明的是编排不变量，不是放行口判据——WP7 门要补
  "validator 拒绝 ⇒ 闸行仍落、零事件、TERMINAL_FAILED"的负控。
- **proposalId 形状**：门里用了 `affect-semantic:<sourceEventId>`；WP7 定稿后写进契约注释。
- **影子模式采集面**（WP9/WP10）：worker 不含 shadow 分支（单写入者纪律）；
  采集 = 同一评估栈 + 隔离证据汇，不写生产闸/水位/任务行。
