## 1. 位置：M8 词形理解的一次语义升级，不是一个新投影

M8.5 不新增投影、不新增事件类型、不改 ContextCompiler 的出口格式。它把 M8 的
**输入理解**从"词形规则表匹配"升级为"模型语义判定"，其余全部继承：

- 事件类型仍是 `AFFECT_ORIGIN / AFFECT_TOUCH / AFFECT_IMPACT`（M8 冻结面）；
- 投影仍是单行 affect 状态（valence/arousal/revision/…），reducer 升版
  **@1 → @2**（SOURCE_ANCHORED 折叠——见 §4.2），@2 对旧事件折叠与 @1 逐字一致；
- 上下文注入块仍是 M8 的 affect section（用户可见面零变化）；
- 三条跨里程碑硬性质原样成立：Assistant Fact Firewall（她的生成内容永不自动
  变外部事实）、投影可重放（删掉能从事件逐字段重放出来）、有副作用就有账本
  （没成功就没成功口吻）。

**语义判定不是事实来源**：Affect interpretation ≠ 外部事实（ADR-068 §2.2）——
M9 的采信仍走自己的证据资格，M8.5 不自动批准任何后续里程碑。

## 2. 三模式（M85-D01/D04：具名切换，无混合、无自动回落）

```text
CHARACTER_AFFECT_SEMANTIC_MODE = rules | shadow | semantic   （代码缺省 rules）
```

| 模式 | 生产写入者 | 语义面行为 | 用途 |
|---|---|---|---|
| `rules` | 词形路径（唯一） | 语义 worker 不跑（具名 no-op） | M8 行为逐字不变（回归锁：既有 m8 门全绿） |
| `shadow` | 词形路径（唯一） | 语义评估**只进隔离证据**，生产情绪/回执/水位差分 = 0 | 上线前对照读数（§18 七类分类学） |
| `semantic` | 语义路径（唯一） | 词形命中只产 TOUCH 不产 IMPACT；语义 IMPACT 走慢路径 | 正式语义模式 |

- **无混合模式**：任一时刻生产写入者恰一个（单写入者不变量，wp8 门 + live 门
  双证）。
- **无自动回落**：语义失败 ⇒ 失败关闭（RETRYABLE ≤2 → TERMINAL_FAILED/EXPIRED
  终态闸），**绝不**静默回落词形（M85-D04——回落会破坏"没成功就没成功口吻"）。
- 切换 = 具名运维操作（改 `.env` + 重启），语义见 §24 矩阵 + 本文 §6。

## 4. 一轮的真实时序（semantic 模式）

### 4.1 快慢两径（§8.1）

```text
用户消息 N ──► TurnGateway（快径，本轮回复用编译时已提交的状态）
   │            词形命中 → TOUCH（不产 IMPACT——semantic 下词形让位）
   ▼
 completeTurn ──► 轮后 drain（fire-and-forget，void 调用——回复延迟不被模型
   │             调用放大；串行守卫：在飞 tick 存在 ⇒ 本次跳过，持久水位间隙
   │             才是工作真相）
   ▼
 语义慢路径 tick：
   ① 发现   扫描水位 (scanner, latest] 批次 ≤32：非 user_message 跳过 ·
            资格矩阵（ESTABLISHED 归因 + 已知 originator + active user +
            affect cutover 之后）不满足跳过 · sequence ≤ semanticCutover
            跳过（skippedPreCutover）· 已有终结闸跳过 · 词形 IMPACT 已落
            跳过（skippedKeywordFinalized——证据式兜底）· 时龄 >120s 落
            EXPIRED 终态（不出站）· 其余入队
   ② 补发现 从 (worker, scanner] 间隙重推导待办（崩溃恢复；内存队列不是
            真相）；连续已终结前缀推进 worker 水位，第一个未终结合格 source
            楔住它（§8.4 不变量）
   ③ 逐任务 升序串行：提交前重验资格（失效 ⇒ SOURCE_INVALIDATED）→ 认领时
            再查时龄 → 重试间隔未到本轮跳过 → 认领（短事务）→ 出站（预算
            估算超限 ⇒ TERMINAL_FAILED）→ 模型调用（无事务；shutdown 信号
            透传）→ 解析（11 码闭集，失败 ⇒ TERMINAL_FAILED 不重试）→
            终态（短事务）
   ④ 终态   IMPACT 判定 ⇒ commitOutcome（Validator 精确 delta 校验 →
            AFFECT_IMPACT 事件 + 终结闸 + 推进 worker/impact 水位）；
            NEUTRAL/UNCERTAIN/OUT_OF_SCOPE ⇒ no-impact 终结闸；
            传输失败 ⇒ 任务行 failed（可重试 ≤2，仅 4 个传输码；耗尽 ⇒
            TERMINAL_FAILED 终结闸）
   ⑤ trace  tick 出结果后经 appendPostTurnStep 追加 affect_semantic_* 步
            （no-op 结局不追加——rules/shadow 轮 trace 不变长）
```

**时序承诺（诚实口径）**：消息 N 的语义 IMPACT 最早影响**下一次**上下文编译；
"可能不止延后一轮"是设计口径，不承诺同轮/下一轮生效（L-M85-01）。

### 4.2 @2 折叠（SOURCE_ANCHORED）

@1 reducer 的 IMPACT 折叠按事件序（旧事件重放会改变结果——M8 已知语义）；
@2 改为**按 source 锚定**：每个 source 的语义 IMPACT 折叠一次、锚在其 source
事件之后，重放确定。@2 对**旧事件**（词形 IMPACT）的折叠与 @1 **逐字一致**
（§9.3 A==B 判据）——这是"回滚无需投影重建"的根据。激活 = 受控重建
（rebuildAffectProjectionV2：隔离演练先行 + 历史 A==B + 批准范围内执行）。

### 4.3 出站与上下文窗口（§6.2）

- 上下文窗口：source 前最多 6 条 / 30 分钟内的对话（`assembleSemanticContextWindow`
  纯函数装配；不读全史——L-M85-05）。
- 出站 = 冻结指令 v5（指纹进策略版本）+ 角色别名 + 当前消息 + 有界上下文；
  预算估算超限 ⇒ 确定性失败（不出站）。
- 响应 schema：单对象、decision（IMPACT/NEUTRAL/UNCERTAIN/OUT_OF_SCOPE）、
  candidates（family + span）、reasonCode 闭集词表——未知字段/越界 span/
  伪造 contextRef 等 11 码解析失败闭集全部失败关闭（§16.2 负控清单逐项有门）。

## 5. 水位、边界与闸（持久化的工作真相）

```text
affect-semantic-scanner@1   发现水位（扫描到哪）
affect-semantic-worker@1    完成水位（只许越过有持久终态的合格 source）
affect-semantic-impact@1    最后成功影响水位（审计面）
affect-semantic-cutover@1   模式切换边界（§22.2/§23/§24③——M85-D20）
processed_operations: affect-semantic-finalized:<sourceEventId>
                            终结闸（processor affect-semantic-worker@1；
                            operation = 终态回执：COMMITTED|<族>|fp=… /
                            NO_IMPACT|<判定>|fp=… / EXPIRED / CANCELLED_BY_
                            MODE_CHANGE / TERMINAL_FAILED / SOURCE_INVALIDATED）
character_jobs: affect-semantic-task:<sourceEventId>
                            任务行（幂等键；失败行允许重建=重试；≤2 次尝试）
```

**semanticCutoverSequence（R-6 实现补齐）**：计划 §22.2/§23/§24③ 冻结、
WP6–WP8 只实现了终结闸而漏实现的边界机制，WP11 补齐。载体 = 水位行
`affect-semantic-cutover@1`（零迁移、单调只进）；`sequence ≤ 边界` 的来源
永不语义重评（防双重计分的主机制）。写入点两处：激活程序
（`markAffectSemanticCutover` = 受控重建 + 边界）+ 每次非语义启动的取消扫面
（先收拢在途、最后推边界——次序铁律）。证据式兜底（第二层）：词形 IMPACT
已落的 source 永不语义重评（判别 `payload.ruleVersion === 'affect-rules@1'`）。
已知残余窗口：切走后、切回前出生的**无词形命中**中性来源可能在 120s 时龄内
被评估一次（单次计分，非双重——L-M85-09）。

## 6. 模式切换语义（§24 矩阵的实现面）

| 从 → 到 | 在途语义任务 | 生产写入者 |
|---|---|---|
| rules → shadow | 无（rules 不产语义任务） | 词形（唯一） |
| shadow → semantic | 隔离证据任务不受影响（永不进生产） | 语义 |
| semantic → shadow | 取消扫面 → CANCELLED_BY_MODE_CHANGE 终态闸 + 边界推进 | 词形恢复 |
| semantic → rules | 同上 | 词形恢复 |
| shadow → rules | 隔离证据任务不受影响 | 词形 |

- 取消扫面收拢的是**水位间隙** (worker, scanner] 里的未终结合格 source——
  不是任务行本身；闸行挡住重推导，任务行如实记"未完成 + 原因"。
- 语义模式内**重启不跑扫面** ⇒ 边界不动 ⇒ 在途工作不丢——这是"切换"与
  "重启"的判别面。
- 激活程序第三步（WP11 工程选择，随 R-6 记录）：scanner/worker 水位预置到
  边界——边界前来源定义上永不评估，扫描它们只是激活瞬态（长历史上批次
  32/跳要多轮；期间切换模式会埋葬未发现的语义工作——live run 2 的实错发现，
  行为计划一致但读数不确定）。

## 7. 失败与恢复的形状

| 失败 | 行为 |
|---|---|
| 传输失败（timeout / server_error / rate_limited / network） | 任务行 failed，可重试 ≤2（间隔 2s）；耗尽 ⇒ TERMINAL_FAILED 终结闸 |
| 解析失败（11 码闭集） | 确定性 ⇒ TERMINAL_FAILED，不重试 |
| 时龄超限（120,000ms） | 扫描期/认领期两道闸 ⇒ EXPIRED 终态（不出站） |
| 出站预算超限 | 确定性 ⇒ TERMINAL_FAILED（不出站） |
| 进程中止（shutdown abort） | 在飞模型调用 abort ⇒ 传输失败 ⇒ 任务留可重试态；重启后从持久间隙补发现 |
| 模式切换 | 取消扫面 ⇒ CANCELLED_BY_MODE_CHANGE 终态闸 |
| 提交前资格失效 | SOURCE_INVALIDATED 终态（不提交） |

全部终态都写终结闸（幂等键 `affect-semantic-finalized:<sourceEventId>`）——
**每个合格 source 恰一个终态回执**，这是永不重评/永不双计的机械根据。

## 8. 与 M7 / M8 的并存关系

- **M8 词形路径**：rules/shadow 模式下逐字不变（回归锁）；semantic 模式下
  词形命中只产 TOUCH（让位 IMPACT）。M8 的 `L-M8-01`（词形覆盖不是自然语言
  理解）由本里程碑在 semantic 模式下解除；rules 模式保留至切换（L-M85-06）。
- **M7 关系轴**：完全正交。语义评估器不耦合关系评估器；M7 潜伏缺陷
  （`L-M8-13`）不因 M8.5 顺手修（归 M7 维护线/M9）。
- **M8 人审 PENDING 不代填**：M8.5 人审是独立判定、材料独立成包（§20）。

## 9. 验证骨架（怎么知道它是对的）

- **离线**（`pnpm m8.5:verify` = 10 门链，全离线）：部件（契约/解析/评估器/
  worker/reducer/validator）· 语料回放（冻结语料 + 假 provider 达 WP2 阈值）·
  子系统正负控（wp3–wp8）· `kernel:test` 依赖方向锁。真模型门（blind/shadow/
  e2e/long/live）**不进**离线链（§16.1）。
- **真模型**（`pnpm with-test-model …`）：盲测 3 run × 106 heldout（十一项冻结
  阈值，报告值 = 最差 run）· shadow 对照（生产副本真历史七类分类学）·
  e2e 慢路径时序（47/47）· 长轨迹 1×500（混合账本重放 A==B）· live 生产副本
  §24 全矩阵（11/11）。
- **量具三段式**：正控/负控/恢复（§6.7 纪律）；计数型检测器自检
  `measured_count > 0`（MEASUREMENT INVALID 不是 PASS）。
- **证据纪律**：失败档分列保留不回写；`m8.5:gates` 只读落盘证据（缺文件 =
  NOT RUN）；判据错了如实写进报告。
