## 3. 判定闭集与失败码（M85-D06）

| 码 | 层 | 状态作用 |
|---|---|---|
| `IMPACT` / `NEUTRAL` / `UNCERTAIN` / `OUT_OF_SCOPE` | 模型判定 | 前者→程序映射唯一主导类别；后三者→NO_IMPACT 终态 |
| `FAILED` | 传输/超时/解析 | 不是 NEUTRAL；传输类可重试（§6），解析类烧尝试 |
| `INELIGIBLE` | 结构性（出站前） | 扫描原因计数 + 扫描水位推进；无任务、无闸行、不出站 |

## 4. 输出 schema（M85-D12/D13）

```json
{
  "decision": "IMPACT | NEUTRAL | UNCERTAIN | OUT_OF_SCOPE",
  "target": "CHARACTER",
  "candidates": [ { "family": "<七族之一>", "span": { "start": 0, "end": 0 } } ],
  "contextRefs": ["m-1"],
  "reasonCode": "<WP2 闭集词表>"
}
```

| 约束 | 冻结值 |
|---|---|
| 未知字段 / 未知枚举 / 数值 delta / `confidence` | 一律拒（schema 失败） |
| `candidates` | IMPACT ⇒ 1..3 项；其余决定 ⇒ 恰为空数组 |
| `contextRefs` | 0..6 项，只认本次请求分配的别名 `m-1`…`m-6`（`m-1`=最近一条先前消息）；伪造引用（如 `m-999`）拒 |
| `reasonCode` | 闭集词表由 WP2 随语料冻结；**只进 trace result 步**（闭集码），回执不携带 |
| 响应体硬上限 | content 字符串 ≤ **16,384 UTF-16 code units**；超限 = invalid_output（FAILED） |
| 解析纪律 | 单完整 JSON 对象；不二次调用"修 JSON"；不从任意正文挖对象（M85-D13） |
| 权威字段 | `sourceEventId` / `characterId` / `processorVersion` / `policyVersion` / `epoch` / `delta` / model profile 全由程序填，模型无权指定 |

## 5. span 协议（M85-D12）

- 原始当前消息字符串的 **UTF-16 code unit 半开区间 `[start, end)`**；不经 Unicode normalization 后定位。
- 合法性：`0 ≤ start < end ≤ message.length`，且 **start 处不得是低位代理项、end−1 处不得是高位代理项**（不跨 surrogate pair）。
- span 只落在**当前消息**；跨消息 span 一律拒。
- span 验证只证明"引用存在"，不证明"分类蕴含正确"（后者归语义验收，M85-D05）。
- **实测依据**：WP0 探针 20/20 界内（单轮简单场景）；更难场景的可靠性归 WP13 盲测。若盲测推翻可靠性 ⇒ 备选协议"原文短片段→程序唯一定位"另行裁定（歧义不得取第一个蒙混）。

## 6. 预算（M85-D10/D11；§6.2 的落实）

| 项 | 冻结值 | 依据 |
|---|---|---|
| 上下文窗口 | 当前消息 + ≤ **6** 条先前消息；同一 conversation；序号 ≤ source；回溯 ≤ **30 分钟**；截断只移除完整最旧消息；当前消息**永不**为凑预算截断 | 计划 §6.2 |
| 输入字符守卫（出站前） | 组装后总文本（指令+别名+当前+上文）≤ **6,000 UTF-16 units**；超限 ⇒ `input_budget_exceeded` 计数 + 不出站、NO_IMPACT 终态 | 估算口径（无本地 tokenizer） |
| 输入 token 预算 | **3,000**（估算口径）；真实 usage 每次调用回填记录；真实 prompt tokens > 3,000 ⇒ `input_budget_exceeded` + 不产生 IMPACT（判定作废，NO_IMPACT 终态） | 探针：指令+1 消息 ≈ 352 tokens，余量充足 |
| 输出 `max_tokens` | **5,000**（2026-09-26 WP10 修订：3,000 ⇒ 5,000，用户裁定，ADR-068 §7 R-5） | 探针：completion avg 553 / **reasoning 占 91%** / 2,000 上限被烧穿一次；3,000 在盲测期仍 3/318 烧穿（truncated 终态 ⇒ 失败终态率 0.0283 > 2% 触发本行"重新裁定"条款）。截断率进 §12.2 计数；盲测期截断率 > 2% ⇒ 重新裁定 |
| 上下文版本固定 | 每个 source 的上下文事件引用 + 内容摘要在**首次任务创建时固定**；重试不读新增消息 | §6.2 |
| 提交前来源复验 | source 被遮蔽/删除/资格变化 ⇒ `SOURCE_INVALIDATED`，不提交 | §6.2 |

## 7. 时间 / 重试 / 过期 / 批量 / 并发（M85-D15/D16/D17；§8.3 的冻结）

| 参数 | 冻结值 | 依据 |
|---|---|---|
| 单次模型超时 | **20,000 ms**（硬超时覆盖响应体读取——判别器先例同款赛跑） | 探针 max 11,569 ms ×1.7 头寸；判别器先例 25s；计划初值 10s 被实测否决 |
| 每 source 总尝试 | **≤ 2**（含首次） | 计划 §8.3 |
| 可重试类别 | **仅传输类**：网络错误 / HTTP 429 / 5xx / 超时；解析/截断/拒答**不重试**（烧尝试） | §8.3"仅网络/429/5xx 等传输失败可重试" |
| 重试最短间隔 | **2,000 ms**；`Retry-After` 仅在任务寿命内遵守，上限 **60,000 ms** | 防热循环；判别器先例 `RETRY_AFTER_CAP_MS` |
| 任务最大影响时龄 | **120,000 ms**（自 source `createdAt`；**排队计入**）；到龄 ⇒ `EXPIRED` 终态、无 IMPACT、放行队列 | §8.3 |
| 每次扫描批量 | ≤ **32** 个 source | §8.3 |
| 模型并发 | 每 Character **1**，按 `sourceSequence` 升序；模型调用期间**不持数据库事务**（短事务 claim → 调用 → 短事务提交） | §8.2 |
| 任务状态机 | `DISCOVERED → CLAIMED → EVALUATING → VALIDATED → COMMITTED`；`RETRYABLE_FAILED → CLAIMED`（≤1 次）；终态 = `COMMITTED / NO_IMPACT / TERMINAL_FAILED / EXPIRED / CANCELLED_BY_MODE_CHANGE / SOURCE_INVALIDATED` | §8.4 |
| 水位纪律 | 完成水位**永不越过**没有持久终态的合格 source；TOUCH 成功不冒充语义完成（M85-D18） | §8.4 |

## 8. 回执拆分（WP0 实测修正计划 §11.2 后的冻结）

WP0 发现 `character_jobs` **无 payload 列** ⇒ "job payload 承载回执"不可行。冻结拆分：

| 载体 | 承载 | 不承载 |
|---|---|---|
| `character_jobs` | 调度生命周期（status / retry_count / last_error / 区间幂等键 / triggerKind=conversation） | 任何回执内容 |
| `processed_operations`（终结闸行） | 稳定键 + 紧凑闭集回执（§8.1 编码）+ `domain_event_id`（COMMITTED 时）+ `processed_at` | 候选明细 / 偏移 / 自由文本 |
| trace 四步（§10） | 候选类别（闭集）、span 偏移（数字）、尝试计数、延迟、真实 usage、reasonCode（闭集）、model profile | 用户正文 / 模型原始输出 / 思维链 / HTTP 错误正文 |

**§8.1 终结闸 operation 编码（冻结语法）**：

```text
COMMITTED:               affect-semantic@1|COMMITTED|<FAMILY>|fp=<16hex>
NO_IMPACT:               affect-semantic@1|NO_IMPACT|<NEUTRAL|UNCERTAIN|OUT_OF_SCOPE>|fp=<16hex>
TERMINAL_FAILED:         affect-semantic@1|TERMINAL_FAILED
EXPIRED:                 affect-semantic@1|EXPIRED
CANCELLED_BY_MODE_CHANGE: affect-semantic@1|CANCELLED_BY_MODE_CHANGE
SOURCE_INVALIDATED:      affect-semantic@1|SOURCE_INVALIDATED
```

- `fp` = 组装出站输入的 SHA-256 前 16 hex（输入**版本**指纹：上下文引用 + 内容摘要；非正文本身）。
- **事务边界**：闸行 + 可选 IMPACT 事件 + 完成水位推进 + job 终态在**同一短事务**内（M85-D20）。
- 提交 IMPACT 前**必须查闸**；闸在 ⇒ 该来源永不重评（换模型/提示词/策略版本都不重评）。
- WP0 实测：`on conflict do nothing` 幂等、首写保留、与水位共存互不干扰（14/14 PASS）。

## 9. reducer@2 与时间语义（M85-D19；§9 的冻结）

| 项 | 冻结值 |
|---|---|
| 新 IMPACT payload 字段 | `sourceAt`（ms）+ `timingKind: 'SOURCE_ANCHORED'`（程序填） |
| SOURCE_ANCHORED 分支 | 衰减结算到 `sourceAt`；**不推进** `lastInteractionAt`（双锚都不动——晚到的语义 IMPACT 不冒充刚互动过） |
| 历史事件（无 `timingKind`） | @2 下行为与 @1 **逐字一致**（双锚推进到 `event.createdAt`）⇒ 混合重放历史前缀 **A==B** |
| TOUCH | 两个版本下都不变（只推进 `lastInteractionAt`） |
| 投影行 | `reducer_version` 守卫沿用：@1 行拒 @2 追加、反之亦然 |
| 受控重建 | 激活期（WP13、批准范围内）删行重放；重建后历史前缀逐字段一致是验收项 |

## 10. trace 步骤名与计数器（§12 的冻结）

**步骤名（4 个，WP8 登记进白名单；字段追加走 `m5.1:measurement:verify` / AT4.5 先例）**：

```text
affect_semantic_discovered   → affect_semantic_dispatched（出站：输入指纹 + 预算读数）
  → affect_semantic_result（闭集判定 + reasonCode）→ affect_semantic_terminal（终态 + 水位读数）
```

**计数器（§12.2 全清单，分别计数）**：出站总数、超时、429/5xx、拒答、缺 content、截断、JSON 失败、schema 失败、伪造引用、span 越界、重试、过期、取消、`input_budget_exceeded`、队列深度、水位滞后、时龄分布、token usage（真实回填）。新计数器须有正控（量到非零），防"0 检查 0 不一致"假 PASS（§6.8）。

**禁项（重申）**：模型自由解释、思维链、用户正文、原始响应、HTTP 错误正文不进 trace/日志/回执；内容指纹不放公共 telemetry。

## 11. 出站隐私（M85-D11）

模型只收：固定任务指令 + 角色别名 + 脱敏说话者角色（`user` / `assistant`）+ 当前消息 + 有界上文（§6.1 资格矩阵内的消息）。
**不收**：API key、真实 userId、traceId、数据库路径、M7 数值、召回内容、M8 当前 Affect 值（M85-D09：防自激）。

## 12. 修订纪律

本文任何值的变更 = ADR 修订记录 + 前后效果读数；**不准用延长超时/加大预算掩盖质量失败**（M85-D16）。语义阈值类（§13.3 指标）由 WP2 随语料另行冻结，不在本文。
