# ADR-114：能力说明依据当前程序事实；提醒跨轮接线修复

状态：ACCEPTED / EXECUTED（2026-10-07）

授权：用户接受提醒对话诊断，要求全面审计并直接删除会因新增功能而过时的“没有主动 XX 能力”等提示，其余按诊断建议修复。历史裁定和验收读数不回写。

## 决策

1. 删除目标解析器对整个产品能力的否定、工具决策器和目录中的固定“不存在”清单、浏览器说明中的永久否定。目标解析器只处理目标状态；执行能力由相应入口、本轮目录、权限和实际结果判断。没有列入本轮目录只代表本轮不可调用。
2. 提醒继续使用既有通知表、调度器、QQ 投递能力与 Policy/Gateway；不产生第二个外发执行者，不新增 schema。提醒解析替换原有私有正文调用，不额外增加一次模型调用。
3. 提供同一会话、交付视图及撤销遮蔽后的有界前文（最多 24 行，每行最多 500 码点）和该会话/本人可编辑的待发送提醒。模型只能产生闭集候选；时间只能引用实际用户事件，由既有时间判据计算。助手事件不能作为用户时间授权来源。
4. 完整请求创建排期；明确再次提醒建立新排期；补充内容更新对应通知并保持时间；确认不新建。唯一、可核对的确认直接读取既有通知。无可读时间、多个不能区分的对象或实际执行不可用时如实说明。
5. 内容更新使用版本比较并递增计划版本；实例占用校验预期计划版本。已占用/尝试投递的提醒不允许换正文。创建以实际记录读回为准，更新以写口版本比较及成功返回为准，不以模型候选代替事实。
6. 提醒处理结果进入不可裁的本轮事实块和回复守卫；已排期不等于已发送。完整回复核对确认内容，逐句语音检查保持普通语句，必要时只补一次事实确认。目标域保留澄清理由和失败事实；不再根据当轮未写入推断历史不存在或要求重述。
7. 已处理的提醒不再交目标快路径和约定慢路径重复建立目标/承诺。原有其他目标、约定及权限规则保留。
8. “叫我拔插头”等行动请求不再成为称呼偏好，规则版本为 `content-rules@8`，规则与 LLM 显式抽取均受此约束。已有生产误记不在本次源代码修复中改写。
9. `capability:audit` 扫描维护的源代码/提示词夹具及提醒主入口实际请求中的提示；接入 `m4.5:audit`。这是常见过时断言的回归检查，不替代新能力的注册、授权、执行验证或逐案语义评价。

## 验证与边界

完整读数、失败档与来源见 [修复审计报告](../post-lv2/Capability-Prompt-and-Reminder-Repair-2026-10-07.md)。实验只使用隔离库；未修改生产配置、迁移、历史目标/通知/记忆，未发送真实 QQ 消息。模型试验经 `with-test-model`，核心至模拟 OneBot 的投递与手机实收分列。
