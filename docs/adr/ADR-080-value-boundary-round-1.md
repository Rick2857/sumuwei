# ADR-080 · M9.7 **取值边界线** / 第 1 轮：一个虚词 / 疑问词**不是一个取值**

> **状态**：`ACCEPTED / IMPLEMENTED`（用户 2026-09-30 授权「**在取值边界线上做一轮（新 ADR）**」）
> **日期**：2026-09-30 · **里程碑**：**M9.7** · **线**：**取值边界**（接 [`ADR-056`](ADR-056-free-text-value-boundary-fix.md)）
> **性质**：**只动取值前后缀剥法**（① 尾部填充语 ② 整值级拒绝）。
> **不动**线索词表 / `priority` / `cueInValue` / 匹配语义 / 任何开关 / 任何冻结条文。
> **依据**：[`Memory-Coverage-Baseline-Report.md`](../memory-coverage/Memory-Coverage-Baseline-Report.md) §4.4 ·
> `L-M97-14`（加 cue 会让既有取值退化）· `L-M97-02`（问句假阳）· ADR-056 §4（"再动取值边界 = 新开 ADR"）

---

## 1. 为什么现在做这一轮

`ADR-056` 把"扩覆盖"与"修取值"划成两件事（§5 逐字禁止混着做）。而 M9.7 的**实测**表明：
**扩覆盖已经被取值边界卡住了** —— 给 `device.primary` 加一个平台名 cue，会让**既有正确条目**
的取值从「Windows 笔记本」退化成「笔记本」（机制：`best` 取**最长线索词** ⇒ 取值那一支
从"往后"翻到"往前"；`L-M97-14`，有完整档）。

⇒ 所以这一轮先修取值边界，**不是**为了顺手，而是因为它是扩覆盖的**前置**。

---

## 2. 机制（先把"取值是怎么来的"讲清楚，再谈修什么）

```text
一条自由文本规则命中之后，取值由**两支**之一给出（顺序由 `cueInValue` 决定）：

  ①  "往后"（`afterCueValue`）：线索词是**引导词**，不属于值
        「我学的是计算机」 ⇒ 值「计算机」
  ②  "往前"（`beforeCueValue`）：线索词**通常是值的一部分** ⇒ **有意**把它接回来
        「我在示例工程科技**大学**」 ⇒ 值「示例工程科技大学」

⚠️ 哪一支胜出，取决于**命中了哪个线索词**（`best` = 最长命中），而不是句式本身。
   ⇒ 这就是"加一个更长的、出现在值内部的 cue 会改变既有取值"的根因（`L-M97-14`）。
```

### 2.1 本轮**量出来**的取值边界缺陷（逐条给机制，不靠推断）

| # | 语料 | 实测取值 | 机制 | 本轮 |
|---|---|---|---|---|
| `A` | 记住，叫我 Alex 就行 | 「Alex 就行」 | **尾部填充语**没剥（`normalizeValuePhrase` 只剥标点与少数后缀） | ✅ **修好** |
| `B` | 记住，我不是计算机专业的 | 「**的**」 | "往后"那一支**接受了一个虚词** —— 那一支**没有**"像不像值"的判定（只有"往前"那一支有 `looksLikeName`） | ✅ **修好**（改成"终止"） |
| `C` | 记住，我的生日是什么时候 | 「什么时候」 | 同上：**疑问词**被当成取值 ⇒ 那条问句假阳**真的落库**（WP4 实测） | ✅ **修好**（`L-M97-02` 收窄） |
| `D` | 记住，我在做一个角色 Agent 的项目 | 「的项目」 | `beforeCueValue` 只取**最后一个空白段** ⇒ 中文+拉丁混排时把「的」当成了名字 | ⛔ **不做**（见 §5） |
| `E` | 记住，我用的编辑器是 neovim | 「用的编辑器是neovim」 | **取值本身也在线索表里**（`neovim` 是 cue）⇒ `best` 把它当线索词 ⇒ "往前"把整句粘回来（与 `L-M97-14` 同一机制） | ⛔ **不做**（见 §5） |

## 3. 决定

| # | 决定 | 依据 |
|---|---|---|
| `D-80a` | `normalizeValuePhrase` 多剥一类**尾部填充语**：`就行` / `就好了` / `就好` / `就可以了` / `可以了` | 修 `A`；⚠️ **不**收裸的「吧/呢/吗」—— 那几个是**整值级**拒绝，由 `D-80b` 承担 |
| `D-80b` | 新增**整值级**拒绝 `VALUE_STOP_SET`（**精确等于**才拒）：实测两条（「的」「什么时候」）+ 同类的推断扩展（结构/语气助词、疑问词，逐条列在源码里） | 修 `B` / `C` |
| `D-80c` | 拒绝是**终止**语义（**不**回退去试另一支） | 实测：对「我不是计算机专业的」，"往前"那一支会给出「**不是计算机专业**」—— 把**否定**也当成取值 ⇒ 回退只会换一个错值。⇒ 如实说没抓住（`content_unresolved`）比记一个错值好 |
| `D-80d` | `CONTENT_RULE_VERSION` **`@4` → `@5`** | `content-extractor.ts` 逐字："线索表、`priority`、`cueInValue`、**取值前后缀剥法**，任一改动都必须升版本" |
| `D-80e` | 新门 **`pnpm extractor:value-boundary:verify`**：8 条用例（3 修好 / 3 正控 / 2 特征化未修）+ 三段式 + 接线证明 + `measuredCount > 0` | `AGENTS.md` §6.7/§6.8；⚠️ ADR-056 的 `m6.1:extractor:repro` **不能**扩（它自己的纪律写着"**不要**在这里加'顺手想到的句子'"） |
| `D-80f` | 两个**具名测试缝**：导出 `extractFreeTextValueRaw`（负控①：关掉判据）与 `VALUE_STOP_SET`（负控②：精确 vs 包含） | 没有它们，两个负控只能退化成"故意写错的期望"——那只证明比对器在比，**不**证明判据 load-bearing |

### 3.1 三段式自证（**本轮实测**）

```text
正控              8 / 8（修好 3 · 正控 3 · 特征化未修 2）
负控① 关掉判据     2 条垃圾取值**重新出现**：「的」·「什么时候」 ⇒ 判据是 load-bearing 的
负控② 精确 vs 包含  2 条读数**不同**（「的项目」·「用的编辑器是neovim」）⇒ "精确等于"是经过选择的
接线证明           走 `createRuleOnlyContentExtractor()`：两条该拒的**真被拒**、两条该收的**真被收**
恢复 / 计数自检     PASS · measuredCount = 8 > 0
```

⚠️ 负控② 的一个**反直觉读数**（如实记下）：换成"包含"会**顺手**把 `D`/`E` 两条脏值也拒掉 ——
看起来"更好"。但那是因为它们的脏值里恰好含「的」；**同一个判法也会误杀任何含「的」的合法取值**
⇒ 所以选**精确等于**（宁可留着可审计的脏值，也不要一个会误杀的判据）。

## 5. 本次**不做**（边界，逐条给理由）

```text
⛔ `D`（空白分段缺陷）：`beforeCueValue` 只取**最后一个空白段**。要修得改**分段逻辑**
   （中文没有空格，"最后一个空白段"这个假设本身就是错的）⇒ 那需要一个**中文分词/切分**层面的
   决定，不是取值边界的一行改动。⚠️ 它已被**特征化**在门里（`vb-07`）⇒ 修好会报红、强制回来更新。
⛔ `E`（取值本身在线索表里）：要修得决定"线索词恰是值本身时怎么办"——
   是**去掉那些 cue**（覆盖损失）还是给规则表加一个 `valueIsCue` 之类的字段（**改线索表语义**）。
   两者都超出"只动取值剥法"的授权 ⇒ 登记为 `L-M97-14` / `L-M97-03`，**不在本轮**。
⛔ **问句守卫**（按语气拒整句）：`D-80b` 挡的是"**取值是疑问词**"这一种，
   **不是**问句本身（「记住，我生日是几号」这类仍要看取值形态）⇒ `L-M97-02` **收窄但未关闭**。
⛔ **qualifier / 否定**：`B` 的根因是**规则表表达不了限定**（规则产出 `{subject, predicate, value}`，
   没有 qualifiers 位）。⇒ 本轮只能"如实不记"，**不能**记成"不是计算机专业"那种否定取值。
⛔ 不改任何线索词 / priority / cueInValue / 匹配语义 / 开关 / 冻结条文。
```
