## 0. 为什么要有这一步（问题陈述，全部有读数）

```text
① 现象：R-26。她的提及密度 **22/48 轮**；`recent-conversation` 注入**最近 16 条事件**（8 个来回）
   ⇒ **任意窗口里都有 2–4 句她的提及**。用户明确结清一次**压不过**这个"证据量"（#155 仍复述、#159 又追问）。
② 程序侧事实（同一次只读诊断）：那件事**不在记忆里**（0 命中）、**不在目标/承诺里**（无 `goal:` 投影）
   ⇒ 它**只以散文形式活在窗口里**：在窗口里就反复提，出了窗口就彻底忘。
③ 结构性缺口：M10 的**目标状态块从未接线**（`goalTokens` 只出现在注释里）⇒ 即使把约定记成承诺，
   现状下她**也看不见**这条状态 ⇒ 桥必须先把这个缺口补上，否则等于白记。
```

**一句话**：约定没有**程序侧归宿**，也没有**终态**，于是"提醒"只能靠窗口里的散文反复出现。

### D01 · 里程碑归属：**M10 的增量（M10.1）**，只追加、不改既有语义

```text
· 复用 M10 的事件集与放行口：`GOAL_CREATED/REVISED/...`、`COMMITMENT_ACCEPTED/FULFILLED/BROKEN/CANCELLED`。
· **不**修改 M10 已冻结的语义、**不**改任何既有事件的 payload 形状、**不**动 M10 的判定与标签。
· 只**追加**：约定的识别 → 承诺的**提案** → 结清（含**到期**）→ 结清后的**事实陈述**。
· 若需要新事件（见 D07 的到期），按"只许追加"的迁移纪律新增，并给出 `MIGRATION_00NN`。
```

### D02 · 触发点：**慢路径**，与 M11 反思同型（有界窗口 + 一次模型调用 + 严格校验）

```text
· **不**每轮检测（成本与噪音都不可接受：每轮一次额外模型调用）。
· 只在**有触发**的窗口跑：窗口里出现"疑似约定"（她给了时间/地点/动作 或 用户给了接受语）才跑一次。
· 复用 M11 已交付的**慢路径骨架**（水位 / 任务 / 失败重试 / 晚写闸门 / 一次性 cutover）——
  这是一处**刻意的复用**：同一套可靠性机制，不另造。
· ⚠️ 与 M11 的**分离**：M10.1 的慢路径**不产生**反思事件、不写 `ADAPTIVE_SELF_*`；
  两个慢路径**各自独立开关**（见 D09）。
```

### D03 · 识别的对象：**双方合意**的约定（**提出者可以是任一方**；本条已于 2026-10-01 修订，见 §0.2）

```text
必须同时满足：
  ① **任一方**提出了可核对的具体内容（时间 / 地点 / 动作 至少其一，且指向未来或未完成的时点）；
  ② **另一方**明确接受 —— "提出者"与"接受者"必须是**不同说话者**（同一个人的两句不算合意）。
反例（**不**识别）：她单方面说"明天十点二十五楼下"而用户没回应；
      用户说"明天我可能有空"（不确定）；她说"我会一直等你"（无可核对判据）；
      **同一个人**既提出又接受（自说自话）。

【⚠️ 修订前原文（保留，不回写）】
  ① **她**提出了可核对的具体内容…；② **用户**明确接受。
  反例含："**用户**提出而**她**接受"（当时按 `proposal_not_character` 拒绝）。
  ⇒ 2026-10-01 用户裁定 (b) 后改为上面的版本；依据见 §0.2，前后读数见交接单。
```

### D04 · 同意语义：用户的**明确接受**即为同意，但必须**指得到那句话**

```text
· 程序必须能把"同意"落到**具体的对话事件**上（`sourceRefs` 逐条给出处）；
  指不到出处 ⇒ **不写**（失败关闭）。
· ⚠️ **不做启发式词表**判"接受"（`DR-11` 的既有立场）：由模型判定 + 严格校验 + **必须给出处**。
  与 M10 的"澄清，不猜日期"同一条纪律。
· 用户**明确否认**或**要求不要记** ⇒ 不写，且记一条**不写的原因**（可查，不进 prompt）。
```

### D05 · 写入门槛：沿用 M10 的放行口，不新增写路径

```text
提案 → `validateGoalProposal` → 事件 → 折叠 → 投影。M10.1 **不**引入第二条写路径。
```

### D06 · 时间：沿用 `dueAt` + `dueBasis`（**澄清，不猜日期**）

```text
· "明天十点二十五"这类**相对时间**必须记下**解析依据**与口径（`dueBasis`，含时区）；
· 无法解析到具体时点 ⇒ 记成**无截止**的承诺（并如实说"我只记着这件事，不猜具体时间"）；
· **不**用当前时钟去"猜"用户没说的日期（M10 WP11 的既有裁定）。
```

### D07 · 结清与**到期**（本 ADR 唯一需要新语义的地方）

```text
终态三条：
  ① 用户报告达成（或给出达成证据）⇒ `COMMITMENT_FULFILLED`（复用 M10）
  ② 用户取消 / 撤回 ⇒ `COMMITMENT_CANCELLED`（复用 M10）
  ③ **到期**：`dueAt` 过去而未见达成 ⇒ **新增 `COMMITMENT_EXPIRED`**（不新增则无终态）
     ⚠️ **为什么不复用 `COMMITMENT_BROKEN`**：`broken` 是"**失约**"的**指控**（语义上把她/他判为违约）；
        "时间过去了"只是**事实**。把二者合并会在 prompt 与开发者面里把"没到时间"说成"你失约了"
        —— 那是**凭空指控**，违反 `① 她生成的内容永不自动变成外部事实` 的同类精神。
     ⇒ 到期必须**另立事件**，且**默认不注入指控性表述**（见 D08 的措辞边界）。
· **谁判到期**：确定性任务（定时/开库时扫描 `dueAt` 已过的 pending 承诺），**不**调模型。
· **判据是"报告"不是"猜测"**：程序**不**从对话里猜"他到底去没去"；只认用户报告 / 真实动作结果。
```

### D08 · ⭐ 结清必须**进 prompt**（R-26 的修法核心）

```text
新增一条**程序事实块**（不可裁、非 droppable），按承诺的**当前状态**渲染：
  · 未结清 ⇒ 「有一条未结清的约定：<内容> · 判据：<可核对的一句话> · 截止：<dueAt/dueBasis>」
  · **已结清 / 已过期 / 已取消** ⇒ 「这条约定**已结清**（或**已过期**），**不要再提**」
    （到期那档措辞**不含**"失约/违约"这类指控 —— 与 D07 一致）

⚠️ **为什么必须是程序事实、而不是"提醒模型别说"**：
   R-26 的读数表明**历史提及的数量**（窗口里 2–4 句）会压过一句用户的话；
   能压过"历史锚"的只有**程序事实**（与 M11 的"给事实，不加措辞守卫"同一纪律）。
⚠️ **不做**的事：**不**对 `recent-conversation` 去重/衰减、**不**改写她的逐字历史
   （理由见 §2 被否决备选 (b)）。
```

### D09 · 额度与**必须一并销账的接线缺口**

```text
· 新 section（约定状态）走**独立额度** `commitmentTokens`：**代码缺省 0 = 不注入**（与 M10/M11 同规）。
· ⚠️ **同时必须接线 `goalTokens`**：M10 的目标状态块从未注入（`L-M11-10`，判定表却写着 ACTIVATED）
  ⇒ 本里程碑把"目标状态可见"作为**前置销账条件**；否则承诺记了也看不见，桥等于白做。
· 两个额度**互不顶替**：目标状态 ≠ 约定状态（前者是她的目标，后者是双方的约定）。
```

### D10 · **不许改写历史**（明确否决 R-26 的"窗口层去重"）

```text
`recent-conversation` 是**逐字历史**；对它去重/衰减 = 让她**记错自己说过什么** ⇒ 与真实性冲突。
⇒ 本 ADR **否决**该路径。修法只走 D08（程序事实）。
```

### D11 · 边界与隐私

```text
· 范围：`current_character_user`（单角色单用户，与既有各域一致）。
· 落库只落**引用**（对话事件 id / 出处），不落正文副本；正文只在既有账本里。
· 开发者面按既有 `*_FACTS` 纪律：只说"程序做了什么"，不说"他到底去没去"。
```

### D12 · 不主张（写死，激活时照抄）

```text
· **不**主张"她不会再重复同一件事"——只主张"约定有终态、结清后可被**程序明确陈述**"。
· **不**主张"她能判断他有没有真的到场"——判据只认用户报告 / 真实动作结果。
· **不**主张"到期=失约"——到期只是时间过去（措辞边界见 D07/D08）。
· **不**主张"约定一定被识别"——识别有门槛（D03/D04），漏识别是**已知边界**。
```

### D13 · Cognitive Integrity

```text
"约定识别 → 承诺写入"会**改变长期认知状态** ⇒ 属 `Privileged Cognitive Operation`，
必须过 `docs/architecture/cognitive-integrity.md` 的审查：本 ADR 是其裁定载体，
判据与"不主张"清单在 `M10.1-Execution-Plan.md` 与验收契约里。
```

## 2. 被否决的备选（连同否决理由）

| 备选 | 否决理由 |
|---|---|
| **(a) 每轮检测约定** | 每轮一次额外模型调用（成本），且噪音大（把闲聊判成约定）⇒ 走慢路径（D02） |
| **(b) `recent-conversation` 去重/衰减** | 改写**逐字历史** ⇒ 她会记错自己说过什么（D10） |
| **(c) 措辞守卫（扫描她的输出、发现"又提了"就重写）** | `DR-11`：措辞层**没有**启发式守卫（M5.1.1 关闭时就写死了这一条） |
| **(d) 把约定塞进记忆域** | 约定不是"用户事实"（`M10` 的记忆域语义是"用户/外部事实"）⇒ 会污染记忆域的采信语义；且记忆没有"终态/判据" |
| **(e) 复用 `COMMITMENT_BROKEN` 表示到期** | `broken` 是**失约指控**，到期只是时间过去 ⇒ 会凭空指控（D07） |
| **(f) 让她"自己记住"（靠窗口）** | 这就是 R-26 的现状：窗口内反复提、窗口外彻底忘 |
