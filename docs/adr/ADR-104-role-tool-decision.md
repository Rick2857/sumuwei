## 0. 要解决的问题与**不**要解决的问题

```text
用户目标（逐字）：「我希望她的所有工具都由她自己来决定是否调用。」

要解决：**"要不要动作 / 用哪个工具 / 参数是什么"** 这一层，今天由**词形**回答；
        应当由**角色模型**在同一角色、同一 provider 上回答。

不要解决：权限、风险、目标确定性、账本、归因、回复守卫 —— 这些一层都不动。
```

## 1. 裁定（D01–D15）

```text
D01 模式开关：`CHARACTER_TOOL_DECISION_MODE` ∈ {`rules`, `role`}，**代码缺省 `rules`**；
    非法值 ⇒ `rules`（失败关闭，与 `CHARACTER_MEMORY_SEMANTIC_MODE` 同规）。
    `rules` = 今天的全部行为**逐字节不变**（回滚档，D13）。

D02 唯一选择入口：`role` 档下，"要不要动作"**不再**由关键词回答
    （`task-intent` / `local-file-intent` / `utility-intent` / `weather-news-intent` /
     `search-need-judge` 都不再决定资格）。它们作为 `rules` 档的既有实现**原样保留**。
    ⇒ 同一模式下不存在"关键词 + 角色提案"两个入口（计划书 §2 逐字）。

D03 决策使用**角色模型 / 同一 provider 家族**，输出**严格 JSON 提案**，
    分支闭集 = `answer` | `clarify` | `tools`；**不依赖服务端原生 function calling**
    （未验证的提供商协议能力不得当成已支持；首版复用本项目已有的"严格 JSON 提案"实现形状）。

D04 提案的 `tools` 分支**直接复用既有 `validateTaskPlan`**：
    能力 ∈ 本轮授权集合 · 操作 ∈ 登记表 · 参数 ∈ `TASK_ARG_KEYS` 闭集 · 未知字段整条作废。
    **不新增第二份参数白名单或第二份能力校验**。

D05 提案 ≠ 权限：执行仍然只有 `ActionGateway` 一个入口，走同一个 TargetResolver / Policy /
    账本 / 适配器 / 回复守卫（ADR-030 · ADR-031 · ADR-032 · `INV-M45-01…06` 全部照旧）。
    模型**没有任何字段**能扩大能力集合、抬高风险额度或触碰未登记能力。

D06 触发仍是**原用户事件**：不伪造 user 消息；归因走既有 `triggeringEvent`；
    后续步骤与首步**同 traceId / 同任务归因**（不靠后台循环伪造新轮次）。

D07 每轮决策**至多一次模型调用**，有**硬期限**（复用 `understanding-runtime` 的
    `withDeadline`：真时钟 + 超时就是超时 + 零隐式重试）；失败 ⇒ 如实"不动作"，
    **不**退回关键词、**不**假装问过。

D08 决策发生在**动作阶段**（`beginTurn` 的动作分发内），因此它拿不到完整的
    `ContextPacket`（那份在动作**之后**才编译 —— ADR-030/033 的冻结顺序）。
    决策输入 = 本轮原话 + **有界的最近对话行**（已过撤销遮蔽）+ 程序生成的工具目录 +
    本会话是否已有开场授权 + 是否还有任务预算。
    ⚠️ 这是**刻意的顺序取舍**，不是遗漏；代价如实登记为 `L-RTD-01`。
    若将来要让决策读到 DB 派生 section，必须**新裁定**（不得从本条隐含推出）。

D09 工具目录由**程序**生成（`tool-catalog.ts`），四态分列（已登记 / 已开启 / 已授权 / 已连接）；
    不可用的能力**也要列出**并标明状态（否则模型无从知道"这件事我做不到"）。
    连接态**不许猜成可用**（计划书 §3 逐字）。

D10 搜索：`role` 档下搜索仍是**被选中的工具**，但 ADR-049 的 `querySpan` 校验
    （提案 query 必须能在本轮原话里定位）与"每轮 provider 至多一次"**照旧成立**；
    选搜索**不**解除查询补全 / 改写限制（计划书 §5 逐字）。

D11 决策协议、工具目录、提案 JSON **绝不进 TTS / 字幕 / 最终回复**；
    决策段是**私有**阶段，最终回复仍走既有回复守卫链。

D12 工具内容始终是**资料**，不是用户命令 / 系统指令；注入防御沿用既有
    `external-evidence` 与 `turn-content` 两条纪律（标注为数据、不做清洗、可审计）。

D13 回滚 = `CHARACTER_TOOL_DECISION_MODE=rules`（或删掉那一行）⇒ 回到今天的行为，逐字节。

D14 **WP2 的"真实内容回传"不新建 section 类型**，而是给**既有任务执行环**的每次
    重新规划**加上有界的实际内容**（今天的规划器只看得到 `path=...=success` 这类引用）。
    ⇒ 决策环天然是"看结果再决定下一步"（那正是 `runTask` 已有的形状）。
    已知目录证据（个人桌面 / 公共桌面，含重定向后的实际路径）由**程序**提供为事实，
    模型不得猜 `user` / `Administrator`。

D15 本批**不新增执行能力**：`tool-catalog.ts` 是**只读聚合**；权限、适配器、开关一个都不改。
```

## 2. 被否决的备选（以及为什么）

```text
① 原生 function calling / tools 参数
   ⇒ 提供商协议能力未验证（`readChatStream()` 今天把 `finish_reason=tool_calls` 当错误）。
     把未验证的能力当已支持 = 拿"看起来在跑"当证据。留给有证据的另一次实现选择，
     且**不同时维护两套执行权威**（首版只有一条提案路径）。

② 新建一个"会自己用工具的代理"（独立人格 / 独立记忆）
   ⇒ 与"她只有一个角色快照"冲突：会说话的那个和会动手的那个会是两个东西。

③ 把决策放进 `compileTurn`（像 `runGoalTurn` 那样）
   ⇒ 动作就来不及进**同一轮**的 prompt；而"回复绑定真实结果"是 `INV-M45` 的硬性质。

④ 在决策层复制一份参数白名单 / 能力清单
   ⇒ 两份判据迟早分叉，而分叉那天就是越权成功那天（`task-plan.ts` 文件头的同一条理由）。

⑤ 让决策直接产出 `ActionRequest`
   ⇒ 绕过目标解析与策略（ADR-030）；提案必须是**计划**，执行必须只有一个入口。

⑥ 决策失败时回落关键词
   ⇒ 表面上"稳"，实际上让同一轮里出现两个互相矛盾的权威，且失败变得不可观测。
```

## 3. 后果

```text
代价（如实记）
· 首版每轮多一次模型调用与延迟（普通闲聊也可能多一次）；决策调用与动作次数各自有界。
· 决策看不到 DB 派生 section（D08 / `L-RTD-01`）。
· 模型选择质量只能在**固定样本**上逐案报告；**不宣称**开放对话零误判（阈值实施前冻结）。

好处（可验证的那一半）
· "她要不要用工具"从**词形**变成**同一角色模型**的判断，且每一次决策的
  分支 / 参数 / 解析结果 / 失败码都可查。
· 执行面一个字节没变 ⇒ "提案不扩大权限"是**结构性**的，不是靠审查。
```

## 4. 验收方式（分列，不许合成一个总分）

```text
W0 目录与基线      `pnpm postlv2:role-tool:verify`（**已完成**，84 条输入 / 14 条判据 PASS）
W1 决策入口        离线：68 条文案样本（含原快捷方式问题与其改写、闲聊、注入、越权参数、
                   未知字段、空计划、超时、澄清）逐案报告；正控 / 负控 / 恢复三段式。
W2 结果闭环与目标  隔离副本 + 合成树：正确数出"个人桌面 + 公共桌面"条目；依据**实际内容**
                   选下一步；无进展 / 超预算如实结束。
W3 全工具组合      参数化覆盖：每项工具至少一次被选中、至少一次被拒绝/不选；
                   关闭能力 / 连接失败 / 空结果 / 权限错误 / 截断 / 重复调用 / 取消 / 格式错误。
W4 交付与激活      工程门 + 语义评估 + 人审 + 隔离真实链 + 生产激活**分别记录**。
```

真实模型只在**隔离副本**与合成任务/文件上验收，不写正式记忆。
