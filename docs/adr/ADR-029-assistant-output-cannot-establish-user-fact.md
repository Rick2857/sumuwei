# ADR-029：Assistant 的输出不能建立用户事实（记忆写入路径）

- **状态**：已接受（M4）
- **日期**：2026-09-16
- **相关**：计划书第 96 / 148 / 149 / 154 / 181 / 182 节；
  MI-02 / MI-09 / MI-14；**ADR-009**（前身）；ADR-020
- **代码**：`src/kernel/contracts/memory.ts`（`authorityFromSource`）、
  `src/kernel/app/memory/extractor.ts`（`resolveCandidates` / `processorEventViewOf`）、
  `src/kernel/app/memory/intent-detector.ts`

---

## 背景

ADR-009（M2.5）已经确立：**Assistant 的输出不是事实**。

M4 需要**重新决策同一件事**，因为前提变了：

| | M2.5 的 ADR-009 | M4 的 ADR-029 |
|---|---|---|
| 场景 | 她的话被当成"世界事实" | 她的话被当成"**用户**事实" |
| 路径 | 总结 / 召回 | **自动记忆写入** |
| 后果 | 她编出整个世界 | 她编出**用户的整个人生** |
| 是否有人看着 | 每一轮都在上下文里 | **没有** —— 后台自动写入 |

最后一行是关键：M2.5 里错误会立刻体现在下一轮的上下文里，
而 M4 里它会被**安静地存进长期记忆**，
在几十轮之后以"她为什么记得我妹妹学医"的形式出现 ——
而用户从来没说过这句话。

计划书第 148 节把它列在 Critical Test 的第一条：

> Assistant 的输出不能建立关于用户的事实。

---

## 决策

**在记忆写入路径上，Assistant 的输出不能建立任何关于用户的事实；
这条约束由四处独立的机制保证，而不是由一条 prompt 规则保证。**

### 1. 入口：显式意图只接受用户事件

```ts
detectExplicitIntentFromEvent(detector, event)
// event.actorType !== 'user' → 抛 explicit_intent_from_non_user
```

约束写在**签名里**（`actorType: 'user'` 是类型要求），
不是靠调用方自觉。

理由：污染链的起点正是"把 assistant 的输出当成用户的意思"。
止住这一点，后面所有环节都不需要再考虑"这个意图可能是她自己编的"。

### 2. 权威：从证据推导，且系统指令失败关闭

```text
证据事件的 actorType / actorId
  → sourceKindForActor()
  → defaultAuthorityForKind()
  → authorityFromSource()      ← SYSTEM_INSTRUCTION 在这里失败关闭
```

模型**没有任何字段**可以声明 authority（ADR-020 决策 1）。
因此"她声称这是用户说的"不是"需要被校验的输入"，
而是**写不出来的表达式**。

### 3. 契约：用户个人事实的权威受限

`assertMemoryAuthorityAllows()` 把 `person_fact` 可用的权威
限制在一个小集合里。角色的输出推导出的权威**不在**其中，
因此在契约层就写不进去。

这一层与第 2 层的分工：
第 2 层决定"这么多权威"，第 3 层决定"这类记忆需要多少"。

### 4. 持久化：写不进库

`m4:verify` §11 直接断言"关闸"：
无证据或非法权威的记忆**落不了库**。

### 5. 工具与外部观测同属这一类（MI-14）

`processorEventViewOf()` 对 `actorType === 'tool'` **失败关闭**：

> `ProcessorEventView.actorType` 只有三种（user / character / system），
> 而 `ConversationEvent` 有四种（多一个 tool）。
> 把 tool 冒充成 character 或 system 正是 `tool_event` 这个枚举
> 要阻止的伪装通道。

**失败关闭而不是降级**是刻意的：降级会把一个"我们还没设计"的
通道悄悄打开，而计划书第 154 节要求 Tool Observation
与用户陈述**隔离**。

### 6. 为什么是四层而不是一层

只在一层守的规则，会在那一层被重构时消失。
四层的具体分工：

| 层 | 拦住的输入 |
|---|---|
| 入口 | 她的话被解读成"用户要求记住" |
| 权威推导 | 她的输出被赋予用户级权威 |
| 契约 | 用户事实用了不够格的权威 |
| 持久化 | 前面漏掉的任何一条 |

它们**不是冗余**：每一层拦的是不同的输入形态，
而且任何一层单独失效时其余三层仍然给出正确的拒绝。

---

## 被否决的备选方案

### 方案 A：靠 prompt 规则（"角色自己说的话不是关于用户的事实"）

**采纳了，但明确它**不构成保证**。**

抽取 prompt 的第 6 条确实写着这句话。但 prompt 是概率的：
实测中它**确实漏过** —— 同一段共同经历被抽成
`person_fact: project.background.active`（见 ADR-021 / ADR-022）。

因此 prompt 规则是"第一道软约束"，而保证由上面四层提供。

### 方案 B：只在持久化层校验

**否决理由**：抽取流水线有六个阶段。若校验只在最末端，
前面五个阶段的输入都带着不确定性 —— 每个阶段都得处理
"这条候选可能来自她自己"这种情况。在**构造时**就排除，
让下游可以假定输入是干净的。

### 方案 C：让 tool 事件降级成 system

**否决理由**：见决策 5。降级会打开一条未设计的通道，
而那条通道的表现是"工具的输出看起来像系统事实"——
正好是 MI-14 要防的。

### 方案 D：依赖 ADR-009，M4 不再单独决策

**否决理由**：见背景表格。前提变了（自动写入、无人看着），
而复用一条"看起来一样"的决策会让 M4 的实现者
以为这件事已经被解决过 —— 而 ADR-009 针对的是
**世界事实**，不是**用户事实**，两条路径的入口也完全不同。

### 方案 E：把 authority 作为模型的输入字段并校验

**否决理由**：见 ADR-020 方案 A。

## 后果

### 正面

- 污染链在四个不同形态的入口上都被切断。
- 她自己说的话在**类型层面**无法被解读成用户意图。
- 四层中任意一层被重构掉时，其余三层仍然拒绝。

### 代价

- 抽取器必须把 `actorType` / `actorId` 带进证据视野；
  tool 事件因此必须失败关闭（一个当前不支持的来源
  会让整批抽取报错，而不是静默跳过）。

  这是一个**刻意的取舍**：静默跳过会让"工具输出被记成了用户事实"
  这类问题在没有任何提示的情况下发生。

- 共同经历（`episode`）的类型判定更依赖 prompt 质量 ——
  因为它不是"关于用户的单一事实"，四层闸门不直接覆盖
  "类型选错但来源合法"这种情况。
  `M4X-005` 是它的回归守卫（见 ADR-022 决策 6）。

## 怎么验证这条决策还成立

| 检查 | 由谁守 |
|---|---|
| 非用户事件 → 显式意图抛错 | `m4:test` 分组「显式意图检测（规则优先）」 |
| `SYSTEM_INSTRUCTION` → 权威失败关闭 | `m4:test` 分组「权威映射」 |
| 候选类型里没有 `authority` 字段 | 类型系统 + `m4:test` 分组「后台抽取 · Source Firewall」 |
| 用户个人事实的权威受限 | `m4:test` 分组「权威映射」+ `m4:verify` §11 |
| tool 事件失败关闭 | `m4:test` 分组「后台抽取 · Source Firewall」 |
| 工具来源与用户陈述隔离 | `eval:m4` M4-018 Tool Source Isolation |
| 她的猜测建不了用户偏好 | `eval:m4` M4-009 |
| 她的自述成不了历史正史 | `eval:m4` M4-010 |
| 注入的污染候选两条都被拒 | `M4X-022`（`minRejected: 2`，离线档，确定性） |
| 非法权威的记忆落不了库 | `m4:verify` §11 |
