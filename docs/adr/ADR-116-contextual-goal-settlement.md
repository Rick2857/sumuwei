# ADR-116：结合前文结清约定，支持明确的多目标范围

日期：2026-10-07。状态：ACCEPTED / IMPLEMENTED。

授权来源：用户明确要求“放宽结清限制，并且修复过度追问或者说需要我反复确认问题”。本裁定承接 ADR-076 §10 的 `user_report`，修订的是自然语言操作范围及理解输入，不扩大外部执行权限。历史 ADR、门和失败记录保持原样。

## 决定

1. 用户报告完成即可申请结清，无需再说“结掉”。“已经拔了”提供完成事实；后续“就是刚列出的三条”可以补齐范围。双方前文只是本轮指代的解释材料，完成事件仍引用本轮本人、受信的对话事件，不拿助手的话充当用户报告。
2. 目标解析收到同会话、撤销遮蔽后的双方前文，最多 24 行，每行最多 500 码点。它不读取其他入口的历史，不把历史文字当指令，也不绕过既有撤销遮蔽。
3. `goal-proposal@2` 的 `report_complete` 和只读 `query` 可以用 `targetGoalId` 或 `targetGoalIds`，两者互斥；后者最多 12 个不重复的程序候选 ID。历史 `@1` 的单目标形状继续接受；`@1` 不能带新批量字段。其他操作不接受批量字段。
4. 多目标结清使用同一个已有程序提案，复用每个目标及承诺的映射、放行口、独立 revision 和完成证据判定。任一项被拒或证据不可读，整批不写。一次提交各自的 `GOAL_COMPLETED` 和符合判据的 `COMMITMENT_FULFILLED`，不合并或删除历史记录。
5. 已结清项的重复完成确认不再次写事件。混合集合里的已结清项不阻挡其余待结清项；全部已经完成则转成状态确认。取消、被替代等其他终态不冒充完成，不恢复旧终态。
6. 澄清只针对仍待执行的操作缺口。已结清事项的口头数量差异不要求再次选择编号。普通情况报告没有对应目标时正常回应，不自动追问是不是要记成目标。确实只指定了若干项、仍无法确定范围时可以问一次必要的问题。
7. “收到了”可以作为对应一次提醒职责的报告；不证明拔插头等现实事项已做。“已拔插头”是该事项的完成报告。默认提醒偏好、无关任务和新的未来约定不连带结清。`api_accepted` 不自动满足 `user_report`，本次没有改通知投递状态机。
8. 本轮成功事实明确说明结清项数；只读确认按真实状态计数。回复守卫只在本轮确已结清或所确认范围已经结清时阻止再次索要范围/完成授权，真正的 `clarify` 不被覆盖。主入口保持回合对象身份，使编译阶段产生的目标/提醒结果能被定稿及语音回复守卫实际读取。

## 验证和适用边界

入口：`pnpm goal:settlement:verify`、`pnpm with-test-model pnpm goal:settlement:live`。新增门覆盖结构负控、真实隔离库写入、第二项证据失败后零写入及同进程恢复、重复确认、主入口多轮回复和账本读回。

真模型使用 `.env.test` 的测试端点。QQ 外壳是本机协议夹具，未向真实 QQ 发消息；不将测试材料写入生产记忆。自然语言判定仍有模型及超时边界，不主张任意表达永不误判。
