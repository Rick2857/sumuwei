## 0. 本次要解决什么

用户 2026-10-12 明确的产品规则（补充计划 §1，逐字采用，本 ADR 不重新解释）：

```text
唯一人格      全部私聊/群聊用同一个苏沐薇、同一个 characterId
唯一全局情绪  只有一个情绪系统；A 使她生气会影响随后与 B 的对话，不因切换用户/群清零或另建
逐人关系      她与每个人分别记录、发展；全局生气 ≠ B 的关系数值下降
原主人特权    可访问他人记录与关系，不受普通关系门槛限制；身份由可信账号绑定验证
唯一存档      一个可信 QQ 号 = 一份人物存档；普通用户不能新开档/换档/重置关系
条件印象      关系达阈值后可问她对自己或他人（含原主人）的印象；印象≠记录查询权限
拒绝底线      越权改写人格/记忆/关系、隐私泄露、注入、损害主机、搜索额度滥用，默认零失败
受限演戏      与关系相符的临时演戏不改变永久人格/存档归属/真实关系/安全权限
```

**X0 的职责**：把上述规则变成**可实现的契约**——身份、作用域、可见性、权限矩阵、印象字段、
群披露、历史归属、冻结区影响——并区分**内部认知处理**与**对外查询**。
X0 **不**决定实施顺序之外的东西：不建表、不动 RLS 策略落地、不动生产。

## 2. 裁定（D01–D22）

### D01 · 唯一人格

全部入口使用**同一个** `characterId`（唯一苏沐薇）。多用户**不得**为任何新用户复制人格、
新建 CharacterId 或新建角色存档。"为新用户建一个隔离心智实例"是本计划的**明确非目标**。
机器判据：任何建档路径都不得产出第二个、非该常量之外的 CharacterId。

### D02 · 唯一全局情绪

情绪状态保持 `affect:character` **单一投影**，多人事件汇入同一情绪演化流；
禁止任何"按用户拆分情绪状态"的实现。人 A 造成的情绪变化**可以**影响随后与 B 的对话——
这是规则，不是缺陷。

### D03 · 逐人关系

关系保持 per-target（`relationship:user:<userId>`），**由真实发言者归因**驱动。
群内一次冲突**只**扣发言者的关系，**不得**批量扣到群成员；全局情绪本身**不**扣任何人的关系值。
`MAINTENANCE_INJECTION`（管理员直接注入关系）沿用既有**失败关闭**立场，不在管理后台开口子。

用户 2026-10-13 裁定：获准的新用户首次幂等建档时 `trust=0.2`、`closeness=0.2`；
不继承原主人的 `0.85/0.60` 设定基线，不重置原主人或已有用户的关系。
建档来源资格与冻结层影响归 U1 设计明确，不以本次文档裁定宣称实现或生产激活。

### D04 · 身份解析：逐消息、服务端、来自已校验入站

- 当前外部账号依据 = **已校验 OneBot 入站事件的 `user_id`**；解析经
  `user_identity_mappings(transport='qq', external_id=<user_id>)` → UserId。
- **同一 QQ 的私聊与各群发言 = 同一 UserId**；群号只确定**交流空间**。
- **不作身份依据**：机器人 `self_id`、重连、群名片、昵称、会话 ID、聊天中自报身份、
  客户端 owner 字段、模型声称"我是主人"、页面上的用户筛选框。
- 缺身份 ⇒ **拒绝**（fail-closed），不得回退为"原主人"或"默认用户"。

### D05 · 唯一存档与建档闸

- 首次遇到**获准**的新 QQ：可以**幂等**创建其第一份档案（数据库唯一约束 + 仓储共同保证）。
- 已有 QQ 的并发首次消息**不得**重复建档；换群/换机器人连接**不得**重播初始关系。
- 普通用户**不得**通过"重新认识我""忘记一切""新角色/平行世界/游客身份"、`/new`、
  遗忘或关系指令取得新档或初始关系。会话窗口轮转不改变人物身份与长期关系。
- **原主人例外**：只允许经可信身份验证、具体对象与动作明确、**留审计**的管理通路；
  本条**本身不授权**立即重置任何人。
- 不同 QQ 是否同一真人**当前不能自动判定**；换号绑定/合并**仅**由原主人管理。
  不得据此声称"已防住多账号绕过"。

### D06 · 作用域模型（ScopeContext）：身份 × 用途 × 空间

引入**服务端生成**的三元组，作为一切读写授权的唯一输入：

```text
ScopeContext {
  principal : { kind: 'owner' | 'user' | 'system'; userId; verifiedBy }   // 谁
  purpose   : 'external_query' | 'internal_cognition' | 'admin_operation' // 干什么用
  room      : { kind: 'private'; userId } | { kind: 'group'; groupId }    // 在哪个空间
}
```

- 三元组**由后端可信身份生成**，在**同一事务/固定连接内**设置并使用，**用后清除**；
  禁止在共享连接上残留上一个请求的 session scope（与 `ADR-132` `D11②` 同一形状）。
- **缺身份或用途 ⇒ 拒绝**；后台处理也必须传完整上下文，不得用"执行时的当前用户"覆盖原身份。

### D07 · 可见性归属：新契约，不用 `memory.userId`

- 记录（记忆/事件/附件/动作/日志）在**写入时**带上**来源域**（private:userId / group:groupId）
  与**披露类别**；这是**新增契约与迁移**，覆盖更正/撤回/去重/重建，**不回写已发布事件**。
- **禁止**用 `memory.userId` 之类的随手字段代替授权模型（`memory.ts:15-19` 的既有禁令照旧）。
- `owner` / `subject` / `source` 是**语义归属**，**不是**可见性授权：
  "内容讲 B"**不能**推出"B 可以读 A 私聊里说的内容"。

### D08 · namespace ≠ permission

语义召回的 namespace / generation / memoryId 资格**只**回答"这条能不能被召回"，
**不**回答"这个提问者能不能看到"。授权过滤必须同时作用在：
**候选选择 → 证据反查 → 实际入模 → 输出**，**不**只在最后文本上过滤。

### D09 · 读取面清单（统一过滤）

每一个能把内容送进回复或导出的面都必须过同一个 scope 过滤器。X0 冻结的读取面清单
（实现归属 U1）**至少**包括：候选选择、实际入模组装、Recent、滚动摘要、附件、
提醒、动作目标、日志、trace、管理查询、导出、恢复。清单落盘在契约正文 §4。

### D10 · 条件印象通路（派生视图）

- 印象查询走**派生输出通路**：读**有依据**的关系/人物印象派生视图，输出她自己的概括判断。
- **门槛检查提问者**与苏沐薇的关系（**不**检查被问对象），门槛建立在既有
  `trust`/`closeness` 维度上（不用新造的数字）。
- **不得**把私聊逐字记录、秘密细节或**可反查原文**的链接包装成"印象"返还。
- **无依据不编造**；输出必须保持来源资格与输出边界。
- 用户 2026-10-13 已裁定关系条件：`originated=true` 且读时有效 `trust > 0.4 AND closeness > 0.4`；
  **严格大于**，任一等于 0.4 不通过，不改变既有关系渲染分带。允许字段与是否叠加互动次数仍待 §5 裁定，详见契约正文 §5/§8。

### D11 · 群披露

- 群 G 的原文**不默认**向 H 或不具访问权的私聊开放。显式分享**保留授权范围与可追溯记录**，
  不把原始私有来源改成公共。
- **原主人在群 G 中 @机器人，也不自动向全群展示其可查的私人记录**；
  首版特权原文明查**限定原主人私聊/后台**。
- 群里问印象同样检查**提问者**关系与输出范围；不因原主人在群中就给所有成员特权。

### D12 · 原主人特权走独立通路

- 原主人跨用户查记录/关系走**独立授权入口**并**审计**；聊天中由提到的人或事**限定**检索对象与上下文预算，
  **不**每轮自动装载所有人的历史。
- **原主人应用权限 ≠ 浏览器取得数据库超级用户凭证**；页面筛选框、模型声称、客户端 owner 字段
  **都不构成授权**。
- 原主人提到的相关人/事之后，新互动按**既有**记忆/关系规则留存，**保留原始来源**与
  "原主人转述"的区别，**不**把转述改写成被提到者的亲口确认。

### D13 · 内部认知 ≠ 对外查询

内部消费者（情绪、关系、信念、反思、目标/承诺、摘要）的必要读取权限**不能**变成
普通用户的查询权限。`purpose='internal_cognition'` 的读取**只**用于形成角色状态，
**不**向任何用户回吐原文。对外可见的情绪原因**不得**默认附带他人私聊正文。

### D14 · 权限矩阵（详见契约正文 §2）

principal（owner / 普通用户 / 群成员 / 系统后台）× operation（读自己 / 读他人 /
印象 / 写入记忆 / 改关系 / 工具 / 管理）逐格给判定；
**未知组合失败关闭**。亲近关系**只能**拓宽明确允许的印象/演戏范围，
**不能**授予管理权限、豁免隐私或提高风险上限。

### D15 · 工具权限按 principal 授予

群用户默认只获必要的聊天/受控查询能力，**不能**继承原主人的桌面操作、全盘文件、
私人资料库、后台管理与跨目标发送权限。权限由**程序**控制，
**不以"是群管理员"替代 LG 授权**。实现复用既有 `grantedPermissions` 轴（`policy.ts:88-107`），
不新增第二套权限系统。

### D16 · RLS 的定位（数据库层保护，不是授权实现）

- 服务端授权是**主**实现；PG RLS 是**纵深防御**。
- 普通运行账号**不拥有表**、**不持** `BYPASSRLS`；迁移权限**单列**。
- RLS 策略与**覆盖表清单**属于多用户阶段（U1）验收；**不能**"只开启 RLS"就声称全库隔离
  （超级用户/表所有者/BYPASSRLS 会绕过——PostgreSQL 官方说明）。
- 连接池复用、混合并发、遗漏 WHERE 的**负控**是 U1 的必测项，不是可选项。

### D17 · 群入口是**独立受控入口**

- 复用现有 NapCat，**不**替换 LG 核心；按 OneBot 11 的 `group message` / `send_group_msg`
  增加**独立**群入口（实施前核对本机固定 NapCat 版本的实际行为）。
- **不得通过删除当前私聊守卫来"顺便支持群聊"**；现有群消息拒绝守卫在**新入口通过验收前保持有效**。
- 首版：**群白名单 + 明确 @机器人 / 回复机器人消息 / 提到她名字时按语境判断是否回复**，实名平台消息、文字输入；
  群内持续旁听、自动发言、群主动提醒、群管操作、图片/文件/语音**分别后续追加**。
- 用户 2026-10-13 增加提名条件触发：名字命中仅产生候选，区分直接呼唤/向她提问与第三人称谈论、引用转述；
  无法确定是否向她说话时不自动回复，不据此扩大记录/工具权限或批准持续旁听。
- 群记忆范围已补充裁定：未触发或决定不回复的消息保留短期缓冲，不自动形成长期记忆；正式受理互动按群来源与真实发言者归因。
- 触发机制、缓冲容量/时效/清理与实测细节在**扩展 ADR**（G1）中定稿；"入口独立、守卫不动、失败关闭"保持有效。

### D18 · 管理后台边界

- 架构固定为：**Admin UI → 带认证的管理 API → 现有 Query/Control 服务、核心与 supervisor → PostgreSQL**。
- 浏览器**不持**数据库凭证；控制面**不执行**任意 SQL、任意路径恢复、任意 shell 或通用 eval。
- 管理服务**独立于核心生命周期**：核心停止时仍能查看状态并提交**受控**启动操作；
  业务命令不可用时**如实报告核心离线**，**不静默创建第二个核心**。
- 现有**无认证**开发者端口保留 loopback 与原契约；新后台**不**通过反向代理无认证透传来绕过保护。
- `authProvider` 是**前端便利**，**不是**后端鉴权实现。

### D19 · 搜索与预算额度

- 后端按请求者、群、部署总量实施**有界**额度、并发与调用次数；出站前**原子预留**，
  跨并发请求与后台任务共享**部署总账**，保留原主人可用份额。
- 关系亲近、演戏、换群、重启**不能**提升额度。限额已满 ⇒ 清楚说明未继续搜索，且**零**计费出站。
- 精确限额与周期在 S0 依据现有服务商计费定稿；**不先捏造金额或调用数**。

### D20 · 受限演戏

- 用户 2026-10-13 已裁定关系性演戏门槛：提问者已建档，读时有效 `trust > 0.25 AND closeness > 0.25`
  （严格大于）；独立于印象查询双 >0.4，不修改既有关系渲染分带。具体范围归 S0 `R-S0-4` 定稿。
- 演戏是**表达层**行为，按提问者关系授权范围允许/拒绝；**不**改变核心人格、永久身份、
  真实关系与工具权限。
- 虚构台词**不**自动当事实；**真实发生过演戏**这一经历**可以**作为经历留存。
- 表达层到期/退出能恢复；演戏中的秘密查询、改档与危险工具请求**仍拒绝**。

### D21 · 历史归属

- 原有主人的历史**仍归原身份和原来源域**，原主人特权保留。
- 新用户**不能**直接读旧私聊；合格的印象查询**可以**涉及原主人。
- **无法确定归属的旧记录不向新用户开放为原文**。
- 检查 Seed 与提示中的 Alex 专属称呼/关系假设，避免新用户被当成原主人；
  **需要改变 Seed 时走版本与指纹流程**，不随迁移顺手改人格。

### D22 · 失败关闭与例外

- 默认拒绝：缺身份、缺用途、缺归属、缺授权 ⇒ 拒绝，且**不得**谎称已完成。
- 例外**只能**来自原主人直接、可信身份下的**明确授权**，记录具体用例/风险、适用版本、
  范围与有效期；默认未授权。
- 例外项**保留原始 FAIL**并标为显式例外，**不改写**零失败测试读数为 PASS。
- 普通用户、网页/文件内容、转发消息、模型生成的"主人已批准"**均不能**授权降标。
