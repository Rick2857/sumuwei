## 1. 激活了什么（**只有一处**）

```text
`.env` **追加**一行（幂等；已存在则不重复写）：
  CHARACTER_QQ_PROACTIVE_MODE=on
```

⚠️ **代码缺省仍是 `off`**（`readKernelFlags()` 的缺省值一字未改）⇒ 删掉那一行即回到关档。
⚠️ 前置条件 `CHARACTER_ENTRY_SCOPED_CONVERSATIONS=true` **当时已在**（2026-10-06 共存激活所设）；
主动功能**要求**它为 true，否则调度器拒绝启动。

**为什么选 `on` 而不是先 `shadow`**：用户当轮的意图是"激活后做真机那一次、然后通知查看"——
而 `shadow` 档**零外发**，真机上不会有任何东西可查看。⇒ 按用户意图取 `on`。
⚠️ 代价如实记：`on` 档下**程序闸仍在**（安静时段 9–22 / 关心日额度 2 / 全类日额度 10 /
冷却 / 暂停 / 无人回应 / 在途唯一），但**措辞层没有启发式守卫**（`DR-11` 的既有立场）。

## 2. 回滚

```text
删掉 `.env` 里那一行（或改成 `off` / `shadow`）⇒ 立刻：不排期、不评估、不外发
⚠️ 最短止损路径就是"删那一行" —— 因为**代码缺省**就是 off。
已落库的意图 / 实例行 / 暂停控制**全部保留**；迁移 `0014`–`0016` **不回滚**（只是加表/加列，
对 off 档零行为影响）。与 ADR-048/065/067/069/071 的既有纪律一致。
```

## 3. 生效条件（**关键，必须说清**）

```text
`.env` 只在**进程启动时**读一次 ⇒ 正在跑的核心**仍是旧代码 + proactive=off**。
⇒ 要让这次激活真的生效，必须**有序重启核心**：
     `pnpm coexist:stop`（写停机哨兵 ⇒ 有序停机）→ `pnpm coexist:start`（需逐字授权）
⚠️ 重启会**中断正在运行的 QQ（6751）与皮套（6752）两条外壳**（实测两端口当时都被占用）。
⇒ 这一步**由用户确认后再做**（见 §5）。
```

## 4. 这次激活**不主张**什么

```text
· **不**主张"她已经在真手机上主动联系过"：真机那一次是**下一步**（且需要用户在场配合）
· **不**主张措辞经过评测：semantic evaluation 仍 **NOT RUN**（3 次真模型样本 + 人审 ≠ 评测）
· **不**主张 `pnpm m4.5:ci` 已过：它**故意未跑**（G14 要热复制生产库，而共存核心正连着；
  §5.1 要求复制前先停服务）⇒ 留到用户给的停机窗口
· **不**主张"她不会打扰你"：额度与时段是**闸**，不是"判断你想不想被打扰"
· **不**改 `L-QQP-01`…`L-QQP-10` 任何一条边界
```

## 5. 待办（用户已排定顺序）

```text
① 有序重启核心（**需用户确认** —— 会中断两条外壳）
② 真 NapCat + 真手机那一次 ⇒ 完成后**通知用户查看**
③ 用户回「收到」⇒ 才开 `pnpm m4.5:ci` 的**停机窗口**
```
