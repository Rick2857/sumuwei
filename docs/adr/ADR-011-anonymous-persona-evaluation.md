# ADR-011：人格评测必须包含匿名模式

- **状态**：已接受（M3）
- **日期**：2026-09-16
- **相关**：计划书第 65–68 / 111 / 114 节（RolePlayBench 启发）

---

## 背景

M3 要建立人格一致性的**度量**（Personality Consistency / Style Adherence 等）。
做这件事时有一个不容易发现、但会让度量结果完全失去意义的陷阱：

> 如果测试用的角色是模型训练数据里已经知道的角色，
> 模型可能依赖**训练数据里的人物印象**，而不是我们提供的 Seed 定义。

计划书第 65 节引用了 RolePlayBench 的发现：正因如此，
它使用**匿名化角色评估**，并发现"明确 Personality 信息能提升角色一致性"。

对苏沐薇来说，这个陷阱有一个具体的形态：她的名字是一个原创的中文名字，
但"苏沐薇"这三个字在中文语料里有很强的联想（"沐"、"薇"都是常见的
女性角色命名用字）。模型完全可以不看 Seed 就演一个"冷淡傲娇的青梅竹马"，
而那个表演恰好会在我们的 PC 指标上拿高分。

于是度量测的是"模型认识这个名字吗"，而不是"Seed 定义得清楚吗"。
**后者才是 M3 要保证的东西。**

---

## 决策

**M3 的评测套件必须包含匿名模式，并把它对比具名模式产生
`Anonymous Persona Gap` 指标。**

具体做法：

1. **同一份 Seed，只换显示名**：
   - 具名：`name = 苏沐薇`
   - 匿名：`name = Character A`

   Seed 的其余内容（人格倾向 / 价值 / 风格 / 边界 / 初始偏好）
   **逐字节相同**。`EvalCase.displayNameOverride` 就是这条的落地点。

2. **测三个维度并分别比较**：
   人格一致性（PC）、价值一致性、风格一致性。

3. **产出 `Anonymous Persona Gap`**，并把它作为**一等指标**记录进 baseline。

4. **Gap 大不是失败，而是一个诊断信号。**
   `计划书第 67 节`给出的判读方式：

   ```text
   苏沐薇模式  PC = 90
   匿名模式    PC = 55
   ```

   说明模型可能过度依赖名字/隐含联想，而不是 Seed。
   对原创角色理论上差距应该比较小。

5. **不改 Seed 去迁就匿名模式。**
   如果 Gap 很大，正确的处理是**强化 Seed 的可判定性**
   （更具体的行为例子、更清晰的反例），而不是把名字删掉。

---

## 被否决的备选方案

### 方案 A：不测匿名，只测具名

**否决理由**：那 PC 指标无法区分两件事：
"Seed 定义得好"与"模型恰好认识这类角色"。
而 M3 的全部工作都建立在后者的对立面上 ——
我们花力气做结构化 Seed，就是为了让角色**由 Seed 定义**。

### 方案 B：评测一律用匿名（干脆不用真名）

**否决理由**：日常使用的名字就是"苏沐薇"，
而评测要测的是**实际运行的那套配置**。
只用匿名测会漏掉"名字带入的联想与 Seed 冲突"这类真实问题
（例如名字让人联想到"温柔"，而 Seed 写的是"外冷内热"）。

两个模式**都要测**，差值才有意义。

### 方案 C：引入 RolePlayBench 的整套 runtime 来做这件事

**否决理由**：计划书第 68 节明确写了：
> 只参考 anonymous evaluation methodology，不引入其整套 benchmark runtime。

而且 ADR-006 的依赖 Gate 要求新增依赖必须回答
"删除它以后系统还能否运行"。一个只用来做"换个名字"的 benchmark runtime
解决不了任何**实测问题** —— 匿名化本身是几行代码的事。

我们真正需要借的是**方法论**（匿名化 + 对比），不是它的实现。

---

## 后果

### 正面

- PC 指标的含义变得明确：它测的是"Seed 是否足以定义她"。
- Gap 本身是一个有用的诊断数字：它告诉你 Seed 里有多少内容
  其实是被名字"补全"的。
- 匿名模式顺带验证一件事：**Seed 是自足的** ——
  不依赖任何外部知识就能演好这个角色。

### 代价

- 评测成本翻倍（每个用例跑两个模式）。
  缓解：匿名模式只在 Release Gate 与 nightly 跑，
  PR smoke 只跑具名 + 少数匿名用例（计划书第 145/146 节）。

- 匿名模式的 judge 需要额外的防护：
  它不能因为"Character A 这个名字听起来不像中文角色"而扣分。
  因此 rubric 明确写出"名字不属于评价范围"。

| 检查 | 由谁守 |
|---|---|
| 匿名模式保留完全相同的 Seed | 评测套件（`displayNameOverride` 只改 name） |
| 两个模式都产出具名/匿名结果 | `evals/m3/suites/anonymous-persona.ts` |

| Gap 记进 baseline | `evals/m3/baseline.json` |
| 参考项目不是运行时依赖 | `package.json`（不新增依赖）+ `docs/evaluation/identity-evaluation.md` |
