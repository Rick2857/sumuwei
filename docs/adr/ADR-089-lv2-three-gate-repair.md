# ADR-089：Lv2 G1/G3/G6 修复边界

状态：ACCEPTED / IMPLEMENTED；验收分列 G1 PASS、G3 PASS、G6 FAIL（14/16）。日期：2026-10-03。

授权来源：用户本轮「三项 FAIL你能不能修复？」。承接既有 Lv2 验收，能力影响 `NONE`；真实库迁移、生产配置和标签不在本次变更内。

## 决策

1. 约定以双方引用中的用户事件确定接受身份。快路径已接受、同窗重放、窗口尾端变化不得重复新增；新一次用户事件可以建立新约定，旧终态保持。慢路径携带提议原文及双方真实指纹，经过既有 Goal 放行口。
2. 取消目标时显式同时取消它的非终态承诺，走既有事件、乐观锁和原子提交。不得由目标终态推算承诺终态。
3. Lv2 夹具接入与生产同款的只读召回、根证据资格、排序和预算；不注入期待答案。C04-04 的准备改为同会话两次显式记忆写入，Windows → Linux 初始状态、实际测试输入和期望不变；语料升为 @4，保留 @3 的旧读数。
4. 追加登记实际使用的五个槽位：实验室位置、备用便携设备、茶、咖啡、颜色偏好。这些槽位原本允许写入，但缺登记的中文检索表面；不改身份、采信、reducer、排序阈值或预算。
5. 在 `content-rules@6` 追加有标记的设备改口：明确自我更正 + 「还是」+ 单个 Windows/Linux/macOS。裸「还是」、放弃语、疑问、假设和多个设备名保持拒绝；不扩为通用省略语解析。先验证正控与负控，再验证新值落库与旧值历史。这是 ADR-088 D-88e 所留另案。
6. 目标理解区分询问方法、完整流程、独立备选方案、接受、重新订立与仅重述。明确接受须有有界内容及可核对判据；单方计划、含糊接受、无界鼓励不得产生承诺。
   空记忆约束只禁止补造未知的既往个人事实，允许当前输入、合格对话、程序事实及明确作为建议的方法。创建新目标后，回复守卫只丢弃无据的成功小句，保留非成功小句中的新提议；其余情况仍用原替换策略。更正抽取保留同一事件的完整原话，防止意图检测剥离标记后条件规则不可达。
7. G6 修复缺入口、缺显式清单与修复证据适用性承接。必选门的当前 FAIL/INVALID/NOT RUN 继续阻断；M11.1 缺少评分、长程、来源矩阵和 A12 时不得用窄离线控制替代。
8. 接受字符提议时，`proposalSpan` 对上一条真实 ASSISTANT 原文校验，`span` 仍对当前 USER 原文校验；两份来源分别检查边界及指纹。给理解模型的候选包含程序已知的配对承诺状态，重复确认非新约定，不新增行。
9. 生产端约定与反思共用单个带关闭围栏的串行队列，各保留独立任务和水位。独占开库时只恢复约定处理器自己的遗留 running 任务；普通轮次不回收并行任务。业务已提交而水位未提交的重放必须去重，关闭后的在途请求及排队任务不得写入。
10. M4/M4.5 继承接口只接受本候选完整 `m4.5:ci:full` 的新档，核对全部来源及私有原始日志/Smoke 摘要。M6.1 使用 R-17 在案的两个显式清单。G4 按当前适用的 M11.1 G11 及八项联合覆盖读取，不再写死「未交付」。
11. C05-02 的派生 Episode 必须复用原始已遗忘 USER 事件；准备程序不得把相同文字重新录成新的用户重述。语料 @5 只修正来源准备，输入和期望保持。Goal 与 Reflection provider 使用已有搜索/情绪 provider 同款 `json_object` 格式，不修补非法 JSON，不放宽内容校验或延长期限；Reflection 候选升为 @5，与旧正式 @2 和开发 @4 读数分列。
12. M5.5.1 正式三轮与 `smallSample` 诊断分列，正式最新 FAIL 仍阻断；M11 最新档按 Git 候选与自报/提交时刻排序，WP0 读完整收尾载体的 BASELINE CAPTURED，开工前缺实现断言如实保留。两处均补缺项、失败与恢复控制。
13. 原撤销集在同一轮只读一次，同时供 Recent 遮蔽和召回资格检查。所有记忆类型的来源若与撤销集相交，按 FORGOTTEN 拒绝并保留候选去向；撤销集不可得时召回具名失败，不伪装为零记录。Episode 的认知资格标签规则保持，新的用户重新确认只使用新来源，不撤销旧来源的遗忘记录。
14. M5 runtime 的专业正控、M9.1 P05 的院校正控均因旧词面机制改为三字后零命中。在既有登记项追加已复现问句的具体片段「什么专业」「什么大学」，避免加入泛化的「是什么」片段；匹配算法、阈值与旧问句不变。保留前后门读数和无关问句负控。
15. JSON 模式的出站形状只追加 `response_format:{type:'json_object'}`；隐私门明确核对这一个格式参数及完整字段白名单，不再称字段完全未变。目标地址、方法、角色、出站正文范围和来源权限保持既有边界。
16. M5.1 的聚合实现及验收文件逐字冻结。Lv2 先核验本候选完整回归，再在私有证据副本中运行原生 M5.1 读取器；M5/M4.5 继承输入来自实际原生聚合，G14 须与本候选原始 Smoke 对齐。任一本体或继承硬门失败仍拒收，并以副本中的量具 FAIL / G14 FAIL / 恢复自证。CI 未调用的 Lv2 读取器在回归归档中明确分列执行范围，由独立控制验证，不能改写 Memory 或其他生产源码指纹。
17. 轨迹及重启的实际请求数使用原生 runTurn 计数，不用零占位或估算代替。子段按实际执行轮数声明计划值，跨进程计数缺失即拒收；同一个 conversation id 不登记为两个会话。首段只跑到重启点，25+25 共 50 轮；沙箱名称不含子段长度，同一 runId 必须打开同一目录。真实轨迹必须全部回复完成，CLI 和聚合门都拒收失败档，状态回访通过不能遮蔽回复失败。原始未计量档、75 轮拒盘档及开错实验目录的控制失败档保留，新量具重跑 50 轮；CI 未调用的 Lv2 量具独立验证，不重定义生产行为或扩轮数。

## 验证

每项先复现，再做正控、负控及恢复。冻结 Memory Kernel 仅追加检索数据与抽取规则，既有事件语义和 DDL 不变；完整 `m4:*` 离线门及 `m4.5:ci:full` 必须通过。Lv2 每轮 ≥90%、每类每轮 ≥5/6、严重错误为 0 与 50 轮长链保持原裁定。所有结论只由新证据决定，本 ADR 不宣布门通过。
