# ADR-096：对话链启用纯语义记忆命中

日期：2026-10-04。授权：用户「那我现在允许纯语义命中在整个对话链中都启用」。
状态：ACCEPTED / IMPLEMENTED；2026-10-05 已观察生产 CLI 与正式 bridge 的纯语义入上下文，追加记录见末节。

此前 `semantic-render@2` 已支持 Claim 与 Episode，但最终相关性门的下限为 1.0，
语义权重又为 0，导致拿到语义分数仍不能凭改述进入上下文。

## 决策

- 在各入口共用的 `rankCandidates` 启用 `semantic-relevance@1`：本地 E5 q8 分数至少 0.87；
  多候选时，必须比最强其它候选领先至少 0.01。只有一条语义候选时只检查分数。
- 仅有效模式 `on` 消费该路径；`off` 不调用语义，`shadow` 的语义分数不改变最终选择和总分。
- 最终排序的语义权重为 1。词面与显式目标仍优先建立相关性。
- 这是一项对 ADR-074 D26 的追加修订：允许纯语义数值成为相关性证据；多候选同时检查相对间隔。
  原冻结文档和旧校准读数不回写。该策略不冒称已经完成 M9.5 全量质量验收。
- 原有角色/用户隔离、生命周期资格、完整性、来源降档、去重和上下文预算继续生效。
  纯语义相似不改变事实权威，不等于证明问句中的所有细节。
- 修复索引枚举、构建和失效检查三处丢失 Episode `summary` 的传递；
  维护入口只复用当前渲染器版本的发布代，旧 @1 代由既有换代流程保留为 unavailable。

## 验证与范围

`scripts/postlv2-semantic-recall-verify.ts` 使用本地编码器、当前 Claim/Episode 渲染器，
先声明小样本标准（dev/val 各相关至少 4/6；无关误放行 0/6），再验证正式 Memory 提交、
维护建索引、真实检索、最终排名、上下文预算与真实 TurnGateway 的 prompt。
参数确定后的 val 使用不同事实和经历；材料由程序作者提供，不称真人盲测。
还验证模式对照、无分数/低分/歧义、隔离、撤回、来源降档、只读网关和正文不进 trace。

CLI 与 bridge/语音由同一个生产网关消费该默认策略。现有 `.env` 的语义模式已是 `on`，
新进程加载本次代码即可生效；已运行进程需重启。真实索引写入、迁移和正在运行的进程重启分别按其既有入口执行。
本次验证在隔离库建 @2 索引。2026-10-04 05:38Z 的已验证生产快照中仍是 @1 的 Claim 索引；
该快照与检查时的真实库摘要不同，因此不冒称是真实库的最新逐行状态。Claim 渲染文本前后相同。

回滚：将语义模式设为 `shadow`，即停止纯语义放行及语义总分；派生索引保留。
