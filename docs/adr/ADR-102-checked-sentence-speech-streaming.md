# ADR-102：正文按已检查句子流式交给语音

日期：2026-10-05。状态：ACCEPTED / IMPLEMENTED；验证读数见[本轮实现与验证记录](../post-lv2/Checked-Sentence-Streaming-2026-10-05.md)，完整当前配置回归仍有四项文件能力失败。

用户本轮裁定：「第一和第二个我都测过，并不是很想改，我建议直接3」。本次只实现正文流式到语音，不调整模型、推理设置、上下文装配或现有状态评估。

## 决策与适用范围

ADR-091 D11 的原始流程是整篇生成、整篇守卫、分句、合成。本 ADR 对显式请求 `SUBMIT_TURN.streamSpeech=true` 且启用表达封套的语音路径追加新流程：同一个 LG 轮次装配 → 同一个 TEXT_LARGE provider 的 SSE 正文 → 封套中的完整 JSON 对象 → 完整句子 → 原有守卫链 → `SPEECH_SEGMENT` → 原有 TTS 流及客户端播放。普通整篇文本调用仍采用原流程；ADR-091 的历史内容不改写。

每句使用本轮固定的程序事实，按原顺序运行记忆、承诺、动作、外部证据、当轮内容、搜索判定策略。已发出的已检查句子不可撤回；后续触发整段替换策略时，只替换该待发句，保留先前句子。这与整篇守卫的语义不同，不宣称两者逐字等价，也不新增跨句语义审核或事实正确性保证。跨句拆开的成功口吻可能与整篇规则匹配不同，属于本次按句策略的已知边界。

增量解析只接受保留封套的完整对象，忽略 SSE 的 reasoning_content、心跳与 usage；XML 中的 thought 不进入播报。对象内未结束的句子跨对象暂存。缺少标准封套的合法正文在最终返回时沿用表达兜底，因此这类回复没有提前播报收益。坏封套、异常结束、空正文、截断输出均不冒充完整回复。

## 身份、记录与失败

分句 replyId 来自本轮已分配的 assistantSequence，使用现有 conversation event ID 构造器。每段仍是 `<replyId>#<index>`；发送前为累计已检查段开交付账，允许整篇结束前回报合成与播放。最终 completeTurn 必须产生同一个助手事件 ID；重复结果不重播分句。

正常完成时，助手事件的播报正文由已检查句子逐字拼接，程序来源附录只在记录中追加一次，字幕与 TTS 均使用同一段正文。守卫报告和标记按句汇总。

网络、格式失败或用户取消发生在首句之后时，只将已发出的已检查前缀交给 completeTurn，随后标记轮次失败，终态 `streamStatus=interrupted/cancelled`、`outcome=failed`。未完成文本不会落成助手正文。取消通过 AbortSignal 中止 provider 流；首个正文 delta 后不重试，以免重复前缀。前缀之前的失败仍直接失败关闭。

外壳在本代流失败时取消该请求的 TTS、发送 `lg-speech-stream-failed`，客户端按 generation 停音并撤销余句。已播、未知及未播的交付状态仍由原有交付账定义。失败信号不得撤销更新的一代回复。

已检查句子是在整篇持久化之前发出的；进程硬崩溃或 completeTurn 落盘失败可能留下已经交付、但助手正文尚未持久化的窗口。此处没有逐句持久化或崩溃原子性承诺，交付账也仍是进程内状态。后续设计若要关闭该窗口，需单独处理存储契约。

## 验证口径

必须验证首句先于最终结果、真实 UTF-8 SSE、推理不播、后句守卫改写、截断前缀、provider 无重复重试、早期合成身份、取消与旧包、最终正文一致及 Python 消费器不重播。真实模型与 CosyVoice 的重叠样本与浏览器实际播放分列；单样本不代表 p95 或全部输入的时延收益。相关桥接、表达、交付、语音、外壳门与完整回归均须保留读数。
