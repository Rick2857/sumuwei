# ADR-113 —— 活动时段**只约束自主关心**，不约束本人明确要求的提醒

- **状态**：`ACCEPTED / EXECUTED`
- **日期**：2026-10-07
- **授权**：用户当轮指令（文中原话）：
  > 「不对呀我这里没看到启动窗口…」（前一轮）→「**没有来源的自主关心别在半夜自己冒出来，但是既然我提到了 or 有明确要求，就不用管作息表了**」
- **修订对象**：[ADR-110](ADR-110-qq-proactive-messaging.md) 的 `D14`（夜间规则）**在提醒那一侧的语义**
- ⚠️ 它**不改** ADR-110 的其它任何一条；`D14` 的**关心**那一侧一字未动（见 §3 的负控）

---

## 1. 旧语义与它的问题

```text
旧（`D14`）：普通提醒落在活动时段外 ⇒ **顺延**到下一个活动时段起点；
            只有"本人**说出了**一个时段外的钟点"才走 `explicit_night_exception`。
```

⚠️ **这条顺延在这里其实是空的**：能走到"排期成立"的提醒，**本来就要求**原话里有提醒动词
（`REMINDER_VERBS = ['提醒','叫我','记得告诉','别忘']`）⇒ **每一条提醒都是"本人明确要求"**。
⇒ 旧规则从来没有拦下过"他没明确要求的提醒" —— **它拦的全是他要的**。

## 2. 新语义（一句话）

```text
**本人明确要求的提醒，不受活动时段限制**（他说几点就几点）。
活动时段**只**约束**自主关心** —— 也就是"没有来源、不该半夜自己冒出来"的那一类。
```

## 3. 改了什么（**只有一处**）

```text
`src/kernel/contracts/notification-intake.ts` ③ ：
  删掉 `nextActiveWindowStart` 那条顺延分支与 `explicit_night_exception` 分支，
  改成：落在时段外时**只**把 `basis` 标成 `outside_window_allowed`（如实、可审计，不静默）
```

⚠️ **两处闸我只改了一处，而这是对的**：查实后 `proactive-scheduler.ts:241` 那个时段检查
**本来就在 `fireCare()` 里面** —— 它从设计上**只拦关心**，提醒的交付路径**原本就没有**时段闸
⇒ 不需要动它（动了反而是把"只拦关心"改成别的意思）。

⚠️ `notification-intake.ts` 的**关心预检**（`outside_active_window`）**一字未动**。

## 4. 判据（三段式，见 `postlv2:qq-proactive:verify` 的夜间那一段）

| 判据 | 读数 |
|---|---|
| ★ 正控（新规则）：普通提醒落在时段外（"八小时后" = 次日 04:00）⇒ **不顺延** | `04:00` + `>outside_window_allowed` |
| ★ 正控：夜间**明确钟点**（"今晚十一点半"）同样不被限制 | `23:30` · `explicitNight=true` |
| ★ 负控（**不许被我改坏**）：**关心**在时段外 ⇒ 仍被 `outside_active_window` 拦 | 闸还在 |
| 负控：**时段内**的提醒**不标** `outside_window_allowed` | 边界正确 |

⚠️ **旧读数按纪律保留、不回写**：原来那条"顺延到 09:00 且 `basis` 以 `>shifted_to_window` 结尾"
的断言已**换掉**，旧读数记在 `WP5-Record` 与本 ADR 里（历史事实，不追改）。

## 5. 本 ADR **不主张**什么

```text
· **不**主张"她不会在半夜吵你"：他现在**可以**让她在任意时刻发提醒 —— 那是他要的
· **不**主张"关心那一侧也不受限制"：恰恰相反，关心的时段闸**原样保留**（这是本裁定的另一半）
· **不**改 `L-QQP-01`（秒截断）…`L-QQP-10`（模型倾向）任何一条
· **不**改"收件人恒为本人"、"额度"、"暂停"、"冷却"、"无人回应"那几道闸 —— 它们与作息表无关
```
