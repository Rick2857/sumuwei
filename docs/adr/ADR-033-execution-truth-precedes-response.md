# ADR-033：执行真相先于回复

- **状态**：已接受（M4.5）
- **日期**：2026-09-17
- **相关**：M4.5 计划书 §10 / §29 / §30；INV-M45-01 / INV-M45-04；STOP-01
- **代码**：`src/kernel/action/claim-guard.ts`、`src/kernel/app/memory/response-truth.ts`、
  `src/main.ts`（`ChatSession.send`）

---

## 背景

M4.1 已经解决了一次 False Success：

```text
用户：记住，我平时主要用 VS Code
她  ：好，记住了。          ← 而库里一条都没有
```

修法（`response-truth.ts`）是**确定性后置守卫**：本轮"没写入"
而回复里出现未被否定的成功口吻时，替换成一句如实表述。

M4.5 面对的是同一类问题的放大版：**"我已经帮你处理了"** ——
而"处理"可以是写文件、发消息、执行命令。这些外部副作用比记忆更难撤销。

---

## 决策

**动作性语言必须由 `ActionResult` 驱动，而不是由 prompt 驱动。**

```text
ActionResult → Response Truth Policy → LLM 渲染
```

### 1. 执行结果先于模型生成

动作在 `beginTurn` 里执行完毕（在模型生成之前），结果作为一个
`droppable: false` 的 context section 交给模型。因此模型的默认倾向
不是"猜自己成功了"，而是"转述一条已经发生的事实"。

这是 M4 显式记忆路径的同一个形状（同步、前置、结果可观察）。

### 2. 确定性后置守卫兜住"模型不听"

指令可以被无视，因此还需要一层**语法级**保证：

```text
if (没有 success 的 ActionResult) and (回复含未被否定的动作成功口吻)
     → 替换成按真实 status 分支的如实句
```

如实句按 status 分派，**不允许**统一成一句"没成功"：

| status | 必须表达 |
|---|---|
| `success` | 允许出现成功口吻（这是唯一允许的情形） |
| `partial` | **必须**说只完成了一部分（含 x/y 计数） |
| `rejected` | 说没有执行，并给出原因类别（权限 / 目标不确定 / 校验失败） |
| `not_found` | 说没找到，什么都没改 |
| `ambiguous` | 说候选不止一个、不确定，**不得**猜目标 |
| `timeout` | 说没等到结果、**不能确定**是否完成（不得当成 success） |
| `failed` | 说执行失败、什么都没完成 |

### 3. 词表**分开**，不复用记忆的成功词

记忆的词是"记住了 / 忘掉了 / 改好了"，动作的词是
"已完成 / 已经创建 / 已经发送 / 处理好了"。

两者分开的三条理由：

1. **命中率**：混在一起会让"我记住了"在写入成功、动作失败时被误替换。
2. **回归安全**：M4.1 的 `RESPONSE_SUCCESS_MARKERS` 与
   `replyClaimsSuccess` 对外行为**一个字节都不变**
   （`verify-m4-smoke-live.ts` 直接 import 它们）。
3. **可解释**：守卫日志要能说清"是动作口吻还是记忆口吻触发的"。

共享的只有最底层的纯函数：`scanClaims(text, markers, { negationWindow })`
（即 M4.1 的"往前 4 个字符内有否定词就不算违规"）。

### 4. 替换发生在写账本与写 memories **之前**

否则账本里会留着那句**没有被说出口**的话，而用户看到的又是另一句 ——
"她说过什么"与"用户看到什么"分叉，trace 立刻失去意义。

这条与 M4.1 的现场注释是同一条纪律（那次也是刻意的顺序）。

### 5. 只有真的发生了动作请求才拦截

没有动作请求的轮次（绝大多数）**完全不经过**这条守卫，
因此普通对话的回复与 M3.5 基线逐字节一致。

---

## 被否决的备选方案

### 方案 A：只靠 prompt 让模型诚实

**否决理由**：M4 已经证过 —— 那是"模型愿意配合时才成立"的保证，
而 C 类判据是 Hard Gate。

### 方案 B：复用一个统一词表

**否决理由**：见决策 3。误伤的代价是"她明明写对了文件，回复却被
替换成'没有执行成功'"—— 那是一种新的、方向相反的谎。

### 方案 C：后置守卫只在 CLI 上生效

**否决理由**：M4.1 就是这样（`send()` 里调用），并且如实记了
"其它 transport 需要复用同一个纯函数"。M4.5 的做法是把策略
放在纯函数里（`applyActionClaimGuard`），由装配层决定在哪调 —— 
形状与 M4.1 一致，因此这不是新债，而是把已有的债标注清楚。

---

## 后果

### 正面

- "她说了她做了，而系统其实没做"这件事在**语法层面**不可能发生。
- 五种非成功状态各自有如实表达，用户能分辨"没找到"与"没权限"。
- M4.1 的守卫行为零变化（回归可证）。

### 代价

- 在触发替换的那一种情形下，回复由**代码**写而不是模型写。
  这是 M4.1 已经接受过的代价，M4.5 沿用。
- 词表面临"漏报 vs 误伤"的取舍。取向是**宁可漏报**（漏报退回
  prompt 层），因为误伤会制造一次反向的假话。
