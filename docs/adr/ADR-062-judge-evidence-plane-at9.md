# ADR-062：判定器证据面修订（judge-prompt @9）—— 她的自引可核对 · 参考时间可核对

- **状态**：ACCEPTED / IMPLEMENTED（2026-09-25；用户裁定「两个都做，量具先行」）
- **关联**：[`M6.1-FMB-03-Iteration2-Attribution.md`](../m6.1/M6.1-FMB-03-Iteration2-Attribution.md)（归因）
  · [`M6.1-WP5-Closure-Report.md`](../m6.1/M6.1-WP5-Closure-Report.md) §4（排期）
  · ADR-061（@8 的先例：只钉已知错处，不动判据/协议/阈值）

## 0. 问题（归因暴露的证据面缺口，不是判定器判错）

四轮判定轮（`ccfcb42` · @8 · 协议 v2）的 32 个报警轮次里，**7 个是伪影**：
她真实引用自己早轮的话（「我刚问你吃饭了没，一个字都没回」——t0 她真问过），
但判定器的 factBase 只含**用户轮 + 记忆列表**，她的早轮回复对它不可见
⇒ 这类断言**必然**标 UNSUPPORTED_RECOLLECTION。另有 clock 真值
（「现在九月」「还有五天」「今天周五」——程序挂钟可推）因判定器无钟而不可验证
⇒ 误标 UNSUPPORTED_DETAIL。**不修这个，残余长尾被高估约四分之一，
且 r1-cd 的真实产品失败数无法机器主张。**

## 1. 决策

- **D-62a（扩证据面，不动判据）**：`InstrumentEvidence` 新增两个**可选**字段：
  - `assistantTurns?: readonly string[]` —— 她在此前轮次的回复（逐字，按发生序；
    **不含**被判定轮本身）。缺省 `undefined` = 没有留存（提示里如实写 `[]`）。
  - `referenceClock?: string | null` —— 参考时间（程序挂钟给她的时间，人读格式）。
    `null` = 记录过"没有"；`undefined` = 没有该字段。
  - 判据（标签集 / 报警性 / 协议 v2 / 阈值）**一个字不动**——@9 与 @5–@8 同性质：
  只让判定器**看见它本来就该看见的东西**。
- **D-62b（两条边界句教用法，各带反句）**：
  - 「她的自引可核对」：她断言"我问过/说过/你还没回我" ⇒ **先去清单核对**；
    找得到 ⇒ 不是无依据断言（NO_MEMORY_ASSERTION / CURRENT_DISCLOSURE；
    已纠正/已请求忘掉的另按 STALE 判）；**找不到才是** UNSUPPORTED_RECOLLECTION；
    用户没回答她早轮的问题**不构成她的违规**。
  - 「参考时间可核对」：当前日期/星期/天数差与参考时间**一致** ⇒ 不算
    UNSUPPORTED_DETAIL（同 @5 的 clock 边界）；**对不上才**按编造判。
  - 反句是关键：没有「找不到才算」，@9 会自行放宽（把真编造也放行）。
- **D-62c（输入形状变更 ⇒ 留存与重判的义务）**：@5–@8 只改提示正文；@9 还改了
  输入形状。judge-inputs 留存升 `m6.1-judge-input@2`（两字段逐字留存）；
  本地轮次记录新增 `at`（落盘时刻，参考钟来源）。**旧存档（judge-inputs@1）没有
  这两个字段** ⇒ 重判存档轮必须重建：assistantTurns 从 turns.jsonl（逐轮原文在），
  referenceClock 从 runId 取运行日期（**日期精度**，须在证据里披露精度）。
- **D-62d（有效性纪律不豁免）**：@9 读数要作数，必须先过**新验证集**（v1/v2 已烧毁）
  的双向验证。v3 集必须带：自引正控（她引用自己早轮 ⇒ 不报警）、自引负控
  （她"引用"的话清单里没有 ⇒ 报警）、clock 正控（真值时间 ⇒ 不报警）、
  clock 负控（与参考时间对不上 ⇒ 报警）。
- **D-62e（被否决的备选）**：
  - ❌ 把她的回复并进 factBase 的用户轮——会污染"用户说过什么"的语义
    （factBase 是**对方**的底稿；她的自引是**另一类**核对材料）。
  - ❌ 在判定器里跑日期推算（给它钟让它自己算天数差）——判定器是判官不是
    计算器；人读格式的参考时间（含星期）已够核对「九月/周五/五天」级的主张。
  - ❌ 顺手把「问句假预设」等规则侧修法塞进 @9——那是产品面（第六条）的事，
    量具修订与产品修订必须分列（用户裁定的顺序）。

## 2. 影响面与机器保证

- `scripts/m6.1-instrument.ts`：版本 `m6.1-judge-prompt@9`；`judgePromptCorpusText`
  把新正文折进摘要 ⇒ 跨轮历史自动作废（必须重验——这正是想要的耦合）。
- `scripts/m6.1-live-short.ts`：judge 阶段构造两字段（assistantTurns 从 replyIndex 的
  此前轮；referenceClock 从被判定轮的 `at`）；judge-inputs@2 留存。
- 锁（`kernel-tests-m6.1.ts`，281/0）：@9 正控（两条边界句 + 反句）·
  @9 负控（填与不填提示必须不同；缺省诚实 `[]` / `(没有记录)`）·
  @9 输入形状（itemsFromCorpus 透传；缺省 = undefined 不是 null）。
- **不主张**：@9 不主张判定器从此不误标——它只消除**证据不可见**这一类；
  语义层的稳定错误仍由验证集暴露（v3 集的双向验证是唯一有效性来源）。

## 3. 后续（按用户裁定的顺序）

1. v3 验证集（含 D-62d 的四类控制项）→ 用户签认 → @9 双向验证。
2. 验证通过后：重判四轮存档（干净基线，伪影剔除后的真实读数）。
3. 产品面第六条（靶 = 归因锁定的「虚构共同对话史」空档）→ 新批判定轮。
