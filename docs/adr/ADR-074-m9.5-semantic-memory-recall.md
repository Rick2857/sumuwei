## 1. 背景：M9.5 在四层分离中的位置

```text
事实权威（不变）     ：事件 + 既有投影政策。向量表**可删可重建**，不定义"她知道什么"。
相关性权威（本 ADR 新增）：版本化、可测的检索与排序策略。
使用权威（不变）     ：原资格链 + 当前有效性复核。异步索引里存着一条旧记录 ≠ 授予使用资格。
认知写入（本阶段为 NONE）：M9.5 只读；不调用 `FORMED` / `RESTORED`；
                        不把旧 Memory bootstrap 成 M9 Belief（计划 §2.3、§10.3）。
```

### 1.1 WP0 的基线结论（本 ADR 的设计输入，不是背景装饰）

```text
① 改述召回**在小规模下已经可用**（ADR-059 已修词面覆盖）⇒ M9.5 的缺口不是"没有向量"。
② 规模缺口定位在**层④候选范围**：候选按 `recorded_at` 降序后 `slice(0, candidateLimit=50)`，
   而 lexical 命中**不参与排序**（`memory-retrieval-store.ts:164/180`）⇒
   一条完美命中只要比最新 50 条旧，就在资格层之前被丢掉。
③ 否定改述（「我能不能接受辣味？」→「我不吃辣。」）在**层⑤**被相关性闸拒。
```

### 1.2 WP1 的组件结论

```text
④ `vector@0.8.0` 真查可用；`$n::vector` 参数绑定可用；精确检索三算子可用；
   维度不符被拒；事务无半成状态；namespace 过滤 + 向量排序可用。
⑤ **零范数向量数据库会接受**、余弦静默变 `NaN`（数据库不报错）；`NaN` 分量被拒。
⑥ E5-small q8：离线加载 766 ms · 384 维 · 确定性逐位相同 · 单条 query 热编码 p50 3 ms / p95 5 ms
   · RSS 497.6 MB · 前缀确实改变向量。
⑦ `AbortSignal` **不取消**底层工作（结算后 500 ms 内仍烧 8,625 ms CPU）。
⑧ 余弦绝对值带宽窄：负控头名 0.8284 vs 目标 0.8452（差 0.017）⇒ 绝对阈值不可靠。
```

## 3. WP0 / WP1 驱动的追加裁定（M95-D25…D31）

> 这六条在计划 §21 里**没有**（计划编制时还没有这些读数）。它们的作用是把计划里
> 「加语义通道」这一步**改精确**，并堵上实测暴露的三个坑。

### M95-D25 · 候选选择策略（**本 ADR 最重要的一条**）

```text
冻结：
  ① `candidateLimit` 的语义由「**新近度排序后截断到 k**」改为
     「**相关性排序后截断到 k**」——即：截断**之前**必须先由相关性给出顺序。
  ② 候选池的截断上限缺省 **200**（= 现有 `maxCandidateLimit`），
     且**分页取完整候选集**（keyset 稳定排序），不再以 `limit*5` 的扫描窗当"全量"。
  ③ 兼容方式 = **策略版本化**，不是就地改语义：
        `lexical-recency@1`  = 现状（**off 模式必须逐字节等价于此**）
        `hybrid-relevance@1` = 本 ADR 的新策略（**shadow / on**）
     `RecallRequest` 增加 `retrievalPolicyVersion`；缺省 = `lexical-recency@1`。
  ④ **语义命中必须与词面命中同样参与排序**。只把 `capabilities.semantic` 标成 available
     而分数不参与候选选择 ⇒ **视为未实现**（对应附录 C 的 R3 与 S49）。

依据：WP0 §4（N=0 选中 / N=50 起目标不进候选池，且目标恰是 lexical 命中）。
反例判据：若只加语义通道而排序仍按新近度，**S4 缺口原样保留** ⇒ 该实现判为不满足 D25。
```

### M95-D26 · 相关性口径与阈值（**禁止绝对余弦阈值**）

```text
冻结：
  ① **向量原始余弦值不是置信概率**，且本机 q8 E5-small 的**绝对值带宽很窄**
     （实测：有目标问句 0.8452–0.8896，负控头名 0.8284 ⇒ 仅差 0.017）。
     ⇒ **禁止**使用跨模型/跨语料统一的绝对阈值（如"≥0.8 即相关"）。
  ② 相关性判定必须**同时**使用：`lexical` 分量（原样保留）、`semantic` 分量、
     以及**相对间隔信号**（头名与次名的间隔 / 间隔比）。三者权重与阈值
     由**开发集 + 验证集**校准后在验收契约 §2 冻结。
  ③ 阈值冻结后，**正式盲测期间不得再调**；调整 = 新版本 + 新证据（不覆盖 FAIL 档）。
  ④ `semantic` 的 `available` 只在**本次确实得到合法分数**时为 true；
     `not_indexed` / `timeout` / `model_missing` / `dimension_mismatch` 各有**具名不可用原因**。

依据：WP1 L-M95-02 + 计划 §9.2。
```

### M95-D27 · 取消与超时（**必须真的停止工作**）

```text
冻结：
  ① 模型编码**必须**在**可终止的执行单元**里跑（worker / 子进程 / 可 kill 的隔离执行），
     **不接受** `AbortSignal` 作为取消机制 —— 本机实测它被接受但**不取消**底层工作。
  ② "取消成功"的判据是**程序事实**，且必须两端都有读数：
     正控：取消后**底层 CPU 不再增长**（有界窗口内）；
     负控：不取消的对照确实**继续增长**（否则正控证明不了任何事）。
  ③ 编码有硬截止（计划 §14.5 起始 2,000 ms），超时 ⇒ 该轮语义**降级**并如实记录原因；
     权威资格失败与语义超时是**不同**的原因码。

依据：WP1 L-M95-01（结算后 500 ms 内仍消耗 8,625 ms CPU）+ 计划 §6.2。
```

### M95-D28 · 向量输出校验（**不能依赖数据库**）

```text
冻结：编码输出在**发布进派生表之前**必须项目侧自检，四条全过才可发布：
  ① 维度 == 模型 manifest 声明的维度；② 全部为**有限数**；
  ③ **范数非零**（实测：数据库**接受**零范数向量，余弦静默变 `NaN`）；
  ④ 归一化后范数 ≈ 1（容差写进契约）。
不合格的向量**不发布**，产出**具名失败分类**（`invalid_vector:<哪一条>`），
不走数据库原始报错路径。

依据：WP1 §2.2（两条不对称：零范数被接受、NaN 被拒）。
```

### M95-D29 · 运行时依赖的声明位置

```text
冻结：**实验期**允许按绝对路径解析已存在的 `node_modules/.pnpm` 副本（本机为
`@huggingface/transformers@4.2.0` + `onnxruntime-node@1.24.3`），但：
  ① 必须**失败关闭**（解析不到即拒绝运行，不自动安装、不静默回退）；
  ② 解析来源必须**写进证据**；
  ③ **WP3 必须**把依赖正式声明进**隔离试验目录**，再让实现引用它；
  ④ **不得**把推理运行时加进生产 `package.json`（计划 §12 WP1 明文）。

依据：WP1 L-M95-03。
```

### M95-D30 · 模型与资产的可复现性

```text
冻结：
  ① `revision` **不得**记可变引用（如 `main`）作为冻结指纹 ⇒ WP3 起改用**不可变 commit sha**。
  ② 模型资产清单必须含：文件名 / 字节数 / sha256 / 来源 URL；
     以**上游报告的 LFS sha256** 为完整性基准（镜像一致性靠哈希比对，不靠"镜像可信"）。
  ③ 已冻结的 q8 指纹（本机实测）：
     `onnx/model_quantized.onnx` = 118,308,185 B ·
     sha256 `f80102d3f2a1229f387d3c81909990d8945513e347b0eab049f7de3c6f98c193`
  ④ 模式/维度/归一化/前缀任一变化 ⇒ **新 generation**（D15），禁止混排。

依据：WP1 §3.2 + L-M95-04。
```

### M95-D31 · 派生 schema 由 M9.5 **自己版本化**（**不追加 kernel 迁移链**）

```text
冻结：
  ① 语义召回的派生对象（`memory_semantic_meta` / `_generations` / `_index` / `_failures`
     与 `memory_semantic_index_scope` 索引）**不进入 `MIGRATIONS`**；
     kernel 迁移链保持 0001–0009，`latestSchemaVersion()` **仍是 9**。
  ② 它们的建/升由 `ensureSemanticIndexSchema()`（`src/infrastructure/persistence/memory-semantic-index.ts`）
     按 `index_schema_version`（该列**已在本文 §4.1 冻死**）在**事务内**完成：
     `create … if not exists` ×5 + 版本登记；版本常量与升级步骤表**必须自洽**
     （`assertSemanticIndexUpgradesWellFormed()`：声明了 vN 却没有 N-1→N 的步骤就抛）。
  ③ 四条性质是**判据**（`pnpm m9.5:migration:verify` 逐条出证据）：
     幂等（已最新 ⇒ `noop` 且**零语句**）· 事务内（中途失败 ⇒ **无半成状态**）
     · **失败关闭**（记到的版本比代码新 ⇒ `refuse-newer`，一个对象都不动）
     · 半径最小（**只新增**；既有表的列集合逐字段不变；DDL 里不得出现对既有表的写操作）。
  ④ 安全边界**一条都没放松**：本模块只提供纯函数、**不打开任何数据库**；
     真实库仍必须走 INC-01 的租约 → pre-open verified snapshot → token（AGENTS §5.1）。

依据（三条，都是本轮实测/既有裁定）：
  · 派生索引**不是事实权威**（本文 §1）：删掉这几张表，"她记得什么"一个字段都不变，
    它们可以从事件重放重建。AGENTS §3 的迁移纪律是为**事实** schema 设的
    （防的是既有事实表被 `create table if not exists` 静默失效）。
  · **代价实测**：追加一条 kernel 迁移会让 M5.1.1 约 **25 处断言 / 20 个文件**的写死版本读数变红，
    其中 **10 道门**（生产库副本 / live / harness / 关闭门）在本环境**无法复跑**
    ⇒ 只能标"已改未复跑"，而仓库纪律明说 **未跑 ≠ PASS**；
    且不完整地改一半会把**原本绿**的门改红（已实测并回退）。把**可重建的派生结构**绑到
    **事实 schema 的版本轴**上，代价与风险不成比例。
  · 计划 §11.3 自己写的就是「**派生表**迁移」。

⚠️ **与计划字面的偏离（如实登记，不淡化）**：
  计划 §12 WP4「新增迁移编号取 `max(existing)+1`」与 §19.3「实际新编号由开工时完整迁移链决定」
  都预设了走 kernel 链。D31 **偏离**了那两处字面。
  · 偏离载体：本条 + `docs/m9.5/M9.5-WP4-Preflight.md` §6.5/§6.6（含两条路的代价对比）；
  · 触发经过：WP4 实测发现爆炸半径后**回退**了已做的 kernel 迁移尝试，把选择交用户裁定，
    用户 2026-09-28 选择 **B**（本方案）；
  · 计划历史**不回写**（采用追加登记，与本文其它"额外裁定"同形）。
```

## 4. 技术接口冻结

### 4.1 派生索引最小模型

```text
表名（拟）：`memory_semantic_index`（WP4 落；**不复用** `plugin-sql` 的 `embeddings` 表 —— 附录 C 的 R2）
列组：
  主体标识   namespace(character) · memory_id（**权威 ID，不是另造 id 空间**）
  源版本     source_revision · canonical_content_hash · renderer_version
  模型身份   model_fingerprint · tokenizer_fingerprint · pooling · normalize · dtype · dimension
  向量       embedding vector(384)（**非空**）
  索引身份   generation_id · index_schema_version · build_state
  控制信息   processed_watermark · failed_ids · pending_count · authority_epoch · retry_reason
唯一键： (namespace, memory_id, source_revision, model_fingerprint, generation_id)
正文：    **不存**；正文以原 Memory 为准（诊断需要的文本只在隔离本地材料里临时读）
```

### 4.2 冻结的检索链路（唯一读取链）

```text
合法 MEMORY_* 已提交事件 ──→ 有界索引维护器 ──→ 派生向量/版本/水位
用户本轮原话 → 原意图/目标解析 → 词面候选 + 语义候选（只读）
            → 按 Memory ID 合并（多通道命中 ≠ 多条 Memory）
            → 批量回查当前权威状态 + 根资格 + 完整性
            → 原 Eligibility
            → 相关性排序（**D25：相关性先排序再截断**）→ 冲突组 → 去重 → 预算选择
            → 使用判定点复核（见 4.3）
            → 原 ContextCompiler → 本轮回复与实际入模记录
```

### 4.3 使用判定点（与 M9.1 的 D15 **同一处**）

```text
**ContextCompiler 接受最终证据集合之前**。此前若本轮 epoch / 相关 ID 发生变化，
必须**有界重查一次**；仍不稳定 ⇒ 去掉相关候选并记录原因。
跨模型推理期间**不得**持有数据库长事务（短事务快照或乐观版本复核）。
```

### 4.4 资格边界（**不得把业务判定藏进数据库**）

```text
物理范围限制（namespace 预过滤）**不是**资格判断；owner / 撤回 / 根资格 / subject
**全部**由 domain 层 eligibility 复核。⇒ 必须能用故障适配器注入
「跨 owner / 已撤回 / 错 subject / 高相似度坏根」候选，并证明它们**真的到达资格层**且被拒。
```

### 4.5 通道与理由码的增量（不改变旧含义）

```text
`RecallChannel` **追加** `semantic`；`RECALL_CHANNEL_FACTS` 同步追加（producer / semantics）。
`RESERVED` 槽位的既有成员**不动**。
`off` 模式下 `semantic` 不得出现在任何请求/读数里（S46 的"语义调用数 = 0"）。
新增排除理由码必须**追加**，不得重定义既有码。
```

### 4.6 模式与配置

| 配置 | 缺省 | 含义 |
|---|---|---|
| `CHARACTER_MEMORY_SEMANTIC_MODE`（拟） | **`off`** | `off / shadow / on`；未知值**拒绝配置**或显式 `off`，**不能默认 `on`** |
| `CHARACTER_MEMORY_EMBEDDING_MANIFEST`（拟） | 无 | 指向已验证的本地模型清单；`on` 缺清单 ⇒ 语义**不可用**（不是猜一个默认） |
| index generation | 数据控制记录 | **不由**环境变量绕过发布门 |
| 阈值 / 候选数 / 超时 | **版本化策略文件** | 按冻结模型与语料确定；避免一串不可追溯的临时 env |

### 4.7 结果状态（六态，用户可见口径）

| 状态 | 程序含义 | 用户可见口径要求 |
|---|---|---|
| `available_hit` | 找到且有内容实际入模 | 可依据该记忆回答，保留来源/当前状态边界 |
| `available_no_match` | 本次覆盖与检索完成，未达相关性阈值 | 「这次没有找到相关记录」，**不证明**用户从未说过 |
| `partial_coverage` | 有索引缺口或新记忆待同步 | 不把未命中解释为不存在 |
| `degraded_lexical` | 语义路径不可用，旧路径仍有效 | **不宣称**本次完成了语义检索 |
| `source_unavailable` | 权威回查失败 | **不使用**旧向量中携带的文本作为替代事实 |
| `excluded_or_budgeted` | 找到但资格拒绝或未入模 | 诊断面分别记录；**不得**向普通回复泄漏被遗忘内容 |

## 5. 生命周期与失效传播（继承 M9.1 的 D17 集合语义）

```text
① 索引的失效**不是**自立的黑名单：向量/缓存/混合召回**继承 D17 集合**语义
   （`explicit_forget` ⇒ 记录 sourceRefs ∪ 同 canonical slot 的 superseded 链全部 sourceRefs；
    `explicit_correction`/`audit` ⇒ 仅自身）。**不得另立一套**。
② 权威回查 + 同轮 overlay **优先于**索引更新；索引维护失败**不得**反向撤销已合法提交的事实。
③ 同 id 新 revision（M9.1 的复活语义）⇒ 索引按**新 source revision** 更新；
   **正文 hash 相同也必须更新状态/来源**。
④ M9 的**禁根**不因索引重建、模型换代、根资格恢复而复活；
   M9.5 只读，**不调用** `FORMED` / `RESTORED`。
⑤ 主库从副本恢复 ⇒ 校验事件前沿/快照身份；不匹配的索引**转不可用待核对**，
   **较新的派生索引不得倒灌**（S43）。
```

## 6. 隐私边界（两条，照旧）

```text
① 不出站：正常运行**只加载本地模型**，关闭运行时远端自动下载；模型缺失时如实降级，
   **不临时改走云服务**。（唯一例外是 `--phase download` 这一次安装出站，已单独记录。）
② 不进 trace / 公共 artifact：正文、完整向量、模型输入、密钥一律不落。
   trace 只记 id / 版本 / 计数 / 通道 / 理由分布。错误堆栈不得包含整条 SQL 参数。
   ⇒ 向量仍按**敏感派生数据**保护，不以"不是明文"声称匿名。
（`L-M55-12` 的教训照旧：真实出站路径的超时/失败必须如实降级，不冒充"查到了"。）
```
