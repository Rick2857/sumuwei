## 1. 问题（一句话链，全部有实测）

```text
① 「同一件更正、三种说法、三种程序行为」（设计文档 §2.6）：
   「改一下」⇒ `correct` ⇒ 旧值被取代；「记住，…」⇒ `remember` ⇒ 同槽位**两条 active 并存**；
   「更正一下」⇒ 词表未命中 且 **生产没有 LLM 回退** ⇒ **整轮没有任何记忆操作**。
② 显式写入路径**不消费冲突判定**（`ExplicitMemoryServiceDeps` 没有 `conflict`）⇒
   连"矛盾"都不标：`--scenario nomarker` 实测同槽位**两条都 active**（§1.17）。
③ 遗忘在**程序层真的成功**，但旧值仍在 `Recent` 里 ⇒ 回复层照样可能把它说出来（§2.9）。
④ 编造那一族：提示里**已经**有禁令与资格标签，缺的是"**本轮没有可依据的记录**"这件事没被渲染（§2.8）。
```

### 2.1 修订记录（2026-09-24，用户复审后）

用户对 **`D-55d` / `D-55e` / `D-55f`** 的两份设计草案给了**九点**修订意见（§4.5 五点、§4.6 四点），

```text
§4.5（渲染设计）
 ① 不设单选枚举：原因**可并存**，另记"最终入模数量"（否则"可用"会掩盖被遗忘槽位的状态）
 ② 默认措辞收敛为「本轮长期记忆召回未向最终上下文提供记录。」；
    「没有可支持这段共同经历的合格记录」**只在程序确实覆盖了全部相关来源**时才可用
    ⇒ 先前那句基准话**不能无条件逐字冻结**
 ③ `ineligible` **按原因拆开**（遗忘 / 取代 / 来源未确立 / 依据链不完整）；
    "目前没有有效替代值"**必须**有"该槽位当前状态的完整查询"支持，且槽位要**具名**
 ④ 补 `search_failed` / `state_unknown`（失败**不得**伪装成零结果）；
    `no_relevant` 收紧为"未达到召回相关性阈值"（**不写**"没有与话题相关的条目"）
 ⑤ 状态行必须与**最终入模结果**一致（走 `applyContextReality()` 的编译后事实 `turn-gateway.ts:1138`）·
    **可裁且留痕** · **不得挤占记忆额度** · **不依赖非空 `memory-recall`**；
    验收覆盖"部分裁剪 / 整段裁剪 / 状态行未入模"；
    且"禁止写法"的机器检查**只扫程序生成的状态文本**，**不得**扩展成对模型回复的词形守卫
§4.6（等价判据）
 ① 共用入口是**必要不充分** ⇒ 必须列明允许差异（库路径 / 凭证 / 测试 provider / 日志级别），
    其余一切影响行为的装配（flags · 预算 · 端口 · 分类器 · 冲突分析 · 守卫链）必须一致；
    共用入口**不得**触发生产启动、**不得**打开真实库
 ② 第三读数改为**按能力的"本轮实际效果"**（召回→实际入模的记录/section；写入→结果 + 状态变化 + 取代链；
    动作→执行结果 + 账本；守卫→是否触发 + 具名原因 + 最终回复对应结果）
 ③ 关键路径**不止 Gateway**：验收必须经过生产实际调用的
    意图处理 → 显式写入 → 上下文编译 → 回复守卫 → 完成记录（外部依赖可隔离，**不得绕过**）
 ④ 负控补齐"**正控—破坏—恢复**"，至少覆盖 端口缺失 / 开关未被消费 / 结果未进入后续链路，
    且**必须因预期原因报红**；场景要**预先声明触发条件**，安静轮次**不算**"装配缺失"
```

## 3. 已知弱化（如实登记）

1. **"无标记的矛盾"不会自动取代**（D-55c 的残差）：用户没时间标记的更正仍会落到 `MARK_DISPUTED`。
   这是**保守设计**（`conflict.ts` 的标记表自己写明：宁可"进 DISPUTED"，也不要错误覆盖用户说过的话）。
2. **词表不可能枚举干净**（D-55a）：B′ 只覆盖新增的那些说法；其余说法仍走 A 的判据或落 DISPUTED。
3. **B″（在线意图分类器）本次不接**：它会默认增加一次在线调用，属独立里程碑。
4. **不顺手批量修复真实库里已有的冲突记录**：本里程碑只在合成隔离库上验证机制；
   真实库的任何数据处置都需要**当轮单独授权**。
5. **摘要那一档在本 harness 里给不出读数**（设计文档 §1.15）：源被 16 条 recent 窗口吞掉，
   或在够长时被归因规则全部拒绝（`non_user_source` / `unconfirmed_origin`）。

| 项目 | 每轮样本数 | 允许失败的整数条数 |
|---|---:|---:|

| 正常写入正控 | 建议 **10 条** | **0 条** |
| 更正意图误触发负控 | 建议 **12 条** | **0 次未经请求的记忆变更** |

```text
正式运行   **两轮**；**两轮分别判定**，不合并平均、**不择优取轮**。
额度关系   技术失败与弃判**都在那 30 条之内**，且**均计入未成功额度** ⇒
           三个数（成功 / 技术失败 / 弃判）**必须同时报**：
           27 成功 + 1 技术失败 + 1 弃判 + 1 条真失败，与 27 成功 + 3 技术失败，
           在"成功率"这一个数上**分不开**。
报法       逐条给分子 / 分母 / n；**弃判单列**；传输失败**不得**从分母剔除；
           修复前后用**同一正控集与配置**对照，且只能说"**样本内未退化**"。
统计       **不得**把 `3/n` 当产品风险上界（定向选择、重复两轮、非独立样本）；
           主报**覆盖范围与观察次数**；条件不成立写"总体风险上界不适用"。
```
