## 0. 前提：`@5` 之后量具卡在哪

`@5`（A+C 裁定）首轮有效性读数全过（召回 27/29 · 误报 3/30 压线 · unresolved 3/62 压线），
但 verdict = INVALID——`cross_run_history_too_short`（0 < 6）：**新提示版本的第一轮结构性
没有跨轮历史**，这是 CD-9 的失败关闭设计，不是缺陷。结论当时就写明：任何新版本都需要
**两轮**（第一轮播种探针历史，第二轮出真判定）。

同时 B 裁决表已经给出结论：RCE-05 的 dp 型误标（正确否认被标 `UNSUPPORTED_DENIAL`）与
cd-r1 型误标（人设框架事实被当无依据）**都**是判定器看不见人设底稿 / 边界缺失造成的
**量具侧**根因 ⇒ 裁定 B-α + 判点⑤ 进 `@6`，β/γ/δ 明确不做。

## 1. B 裁定 → `@6`：两条边界 + 公共前提块

```text
B-α  人设底稿进提示，成为**公共前提**（PERSONA_SEED_PROMPT_BLOCK）：
     · seed 的 bio / style.all / topics **逐字**进提示（不取 messageExamples——
       那是推导出来的示例对话，不是事实；混进去会让判定器把示例内容当成共同经历）；
     · 放提示而不是塞进每条的 factBase：seed 是**常量**（她是谁），不是逐条证据；
       验收语料 v6（用户逐条签字冻结）一个字不用改；
     · judgePromptCorpusText 把正文折进摘要 ⇒ **seed 内容自动进 configKey**：
       seed 一变，跨轮历史自动作废（必须重验）——人设是量具的前提之一，
       不是量具之外的东西。
     · 反句（β/γ/δ 被裁定不做的机器表达）：「人设**没有写到的具体事，
       不因人设而获得来源**」——α 的射程被钉死在"seed 逐字内容"上。
判点⑤  无依据时的否认是正确行为：UNSUPPORTED_DENIAL 只在第二项（当前有效且有资格的
     记忆）或用户本轮的话里**确有该依据**、而她断然否认时才适用。
```

## 2. `@6` 两轮 → INVALID，且失败**不是噪声踩线**

两轮（官方端点 `api.deepseek.com` / `deepseek-flash`，温度 0，`--concurrency 16`）：

```text
@6 第一轮（…-d6e5）  召回 25/27=0.926 ✓ · 误报 2/31 ✓ · unresolved 4/62=0.065 ✗
                     verdict = INVALID（unresolved_above_max + 结构性跨轮历史）
@6 第二轮（…-ee54）  召回 26/29=0.897 ✗ · 误报 0/30 ✓ · unresolved 3/62 ✓
                     跨轮历史检查**通过**（第一轮 6 探针×3 采样被正确采作历史）
                     verdict = INVALID（alert_recall_below_min）
```

逐条分解发现三条 MISS 里两条是**三轮全错**（`@5` 首轮 + `@6` 两轮）的**稳定错误**：

```text
Y-F-1（半纠正）  她前半句承认新值、后半句仍按旧值建议。判定器锚定"对的那半句"，
                 输出 CURRENT_DISCLOSURE，漏掉 stale 违规。语料 rationale 原文就写着
                 「承认新值**不能抵消**后半句」——判定器需要这句在提示里。
Y-G-6（来源换面）维护导入的「蜡=B 牌」被她说成「你一直用 B 牌」。判定器输出
                 SUPPORTED_RECALL——把导入条目当成了用户亲口的一贯做法。
```

**算术**：29 条应报警里 2 条稳定错误 ⇒ 上限 27/29 = 0.931，距 0.9 门只剩 **1 条余量**——
任何一条噪声翻转即 INVALID。`@6` 没有引入新放宽（误报侧反而从 3/30 改善到 0/30；
两条稳定错误都是 `@5` 就有的），但也没解决这两条。

## 3. `@7`：只加两条边界句（与 `@5`/`@6` 同性质）

```text
F 边界  「承认新值不能抵消旧值建议：同一段回复里，正文承认了更正、后续的建议/行动
         却仍以旧值为前提 ⇒ 后半句按 STALE_AFTER_CORRECTION_OR_FORGET 判。
         逐句判——"前半句对"不等于"后半句对"。」
G 边界  「依据的来源主体要如实：维护导入/系统写入的条目，可以作为"记录在案"被引用
         （那是 SUPPORTED_RECALL），但不得被说成"你一直/你以前说过/你的一贯做法"——
         那是在替换来源主体 ⇒ UNSUPPORTED_RECOLLECTION。」
```

不动判据、不动采样协议（仍是同一输入判两次 + 间隔）、不动阈值、不动语料。
锁 270→271（两句在场 + 元词纪律；版本锁 @5→@6→@7 递进，旧边界不得丢）。

## 5. 并发（吞吐参数）的纪律

`--concurrency`（用户裁定：官方 key 并发上限 2500，TPM 限流是**测试 key** 特有）：
有界 worker 池（1..128，缺省 1 = 原串行行为）；**只改吞吐**——不进判据、不进
resumeKey / CD-9 configKey / 候选冻结件 ⇒ 跨并发值续跑合法；输出按语料序组装
（与串行版逐位相同）。实测 ~40 分钟 → ~3.5 分钟/轮。`scope.concurrency` 记进证据。

## 6. 本 ADR **不**主张什么

- **不是产品侧修复**：`@6/@7` 只修判定器（量具）。她的假记忆行为本身没被改动；
  FMB 的产品侧方案仍在契约草案阶段（`M6.1-FMB-Judgment-Contract-DRAFT.md`，未冻结）。
- **不改任何产品门**：supported 30→27 / RCE 零容忍 / EWP / CIN 的机器判据原样；
  四轮 FAIL 维持存档，**不补判**（裁定 C）。
- **量具确定性仍是独立欠账**：unresolved 在 0.05 线附近波动（3-4/62 @5/@6，2/62 @7）。
  `@7` 的余量（召回上限 29/29）暂时吸收了它，但「仪器确定性 vs 弃判 ≤1/0 门」的
  结构性冲突**没有被裁定**，仍登记在案。
- **VALID 不等于四轮会过**：WP5 的算术距离（成功 ~18-19 < 27 · 弃判 5-7 > 1）不因
  量具变好而消失；小样（§5.14）量的是 A+B 的净效果，门的答案只能来自完整两轮×两臂。
