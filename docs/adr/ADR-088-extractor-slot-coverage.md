# ADR-088 —— 规则抽取器的**槽位覆盖**：`device.primary` 的更正措辞与 `education.lab` 的覆盖边界

- 出身：Lv2 综合验收 · 用户 2026-10-02 裁定 `LV2-D13` 立案、随后批准冻结

## 1. 背景（读数，不是推测）

```text
Lv2 第四代读数里，C04（更正）仍是最差的一类之一（7/12），失败集中在**两条**：
  · `C04-04`「我刚才说错了，还是 Windows。」   ⇒ 意图已通（`correct`），但**抽取器读不出新值**
  · `C05-04`「还是记一下吧：我的实验室在 A 楼 302。」⇒ 意图已通（`remember`），但**抽取器读不出槽位**
离线诊断（`pnpm lv2:diagnose:memory`，0 次调用，每条探针一个隔离库）把它们钉到同一格：
  · `F2`（= C04-04）意图 `correct` · 抽取 **—** · 服务结论 `content_unresolved`
  · `F4`（= C05-04）意图 `remember` · 抽取 **—** · 服务结论 `content_unresolved`
  · 对照：`F1`「那个改一下，我现在能吃香菜了。」意图 `correct` · 抽取 ✓ ⇒ **四段全通、槽位真的改了**
⇒ 缺的不是意图、不是放行口、不是复活语义，而是**规则抽取器的槽位词表覆盖**。
```

⚠️ **`C05-04` 当前不能作为"复活失败"的证据** —— 它卡在抽取，链根本没走到复活那一步
（这一点是本 ADR 的**前提**，也是 `LV2-D13` 的原话）。

## 2. 决策（候选，待裁定）

| # | 决策 | 理由 |
|---|---|---|
| **D-88a** | **覆盖对象明确限定为两条**：`device.primary` 的**更正措辞**（`还是 X` / `我换 X 了` / `改成 X`）与 `education.lab` 的**陈述措辞**（`我的实验室在 X` / `实验室是 X`） | "受控扩覆盖"必须是**可数的**；一口气扩成"通用地点/设备解析"就是另一件事 |
| **D-88b** | **只收有标记的说法**；无标记的隐含更正（`唉，其实我早就能吃香菜了。`）**明确不在覆盖内** | 与 `C02-02` 已裁定的"**澄清、不猜改**"一致；`DR-11` 的立场是措辞层不加启发式 |
| **D-88c** | **歧义负控必须保留**：目标含歧义（两个同名候选）· 缺地点/设备主体 · 与既有取值形状不符 ⇒ 必须 `content_unresolved` **或**要求澄清，**不得猜** | 覆盖扩张最容易的副作用就是"从猜不出变成瞎猜" |
| **D-88d** | **顺序硬约束**：① 先证明**抽取成功**（正控）→ ② 再验**更正**（新值落库、旧值不复活）→ ③ 最后才是**复活**（同内容重述） | 三件事的证据不能互相顶替；把 ③ 建在 ① 之上的读数才有意义 |
| **D-88e** | **不与修取值混做**（`ADR-056 §5` 逐字）：本 ADR **只**扩**词表覆盖**，**不**改任何取值语义、判据、阈值或严重错误闭集 | 混做会让"覆盖变宽"与"判据变松"无法区分 |
| **D-88f** | **三段式 + 五道门**：正控（该抽的抽出来）/ 负控（歧义与无标记句保持安静）/ 恢复；跑 `m4:test` · `m4:verify` · `m4:nl-mutation:verify` · `m4:mutation-safety:verify` · `memory-coverage:verify` | 与 `src/kernel/app/memory/**` 的既有纪律一致（`AGENTS.md` §5） |

## 3. 本 ADR **不**主张什么

```text
· 不主张"扩完之后 C04-04 / C05-04 会通过" —— 那要**跑**才知道（LV2-D09 ⑤ 的同一条纪律）
· 不主张"通用自然语言更正已支持"；只主张**两条具名措辞**进入覆盖
· 不主张复活语义已修（`D-88d` 的顺序约束：复活是第 ③ 步，且 `C05-04` 现在不构成证据）
· 不触碰 `CHARACTER_MEMORY_LLM_EXTRACTOR_ENABLED`（默认 off 的既有开关，属独立里程碑）
```

## 4. 备选与为何不选

| 备选 | 为何不选 |
|---|---|
| 打开模型抽取器（`CHARACTER_MEMORY_LLM_EXTRACTOR_ENABLED`） | 它把"覆盖"变成"模型行为"，需要新批次与预算，且**离线门不再能守**；属独立里程碑 |
| 放宽成通用正则（地点/设备一律解析） | 覆盖不可数、负控无法穷举 ⇒ 与 `DR-11`、`D-88b` 冲突 |
| 改语料让那两句带上已支持的措辞 | 用户已在 `D13` 明确选择"**扩覆盖**"而不是"改输入"；改输入等于把缺口藏起来 |

### 6.8 **二分结果：不是装配，是 F-4（同内容重述永不复活）**（2026-10-02 · 0 调用）

```text
[lv2:diagnose] case-shape 二分：
  意图 = remember
  **端口**      = handled：{"kind":"not_written","intent":"remember","reason":"write_not_effective", …}
  **直调服务**  = 拒绝：**already_applied**
  事后活跃 = []（没有）
```

⇒ **两条路都写不进**，而且**直调服务的具名理由是 `already_applied`**
—— 即：服务认为"这条记忆**已经生效**"，于是**什么都不写**。
那条记录的实际状态是 **`retracted`** ⇒ 这正是 **M9 的 `F-4`：同内容重述永不复活**
（确定性 id/指纹撞上 `retracted` 记录 ⇒ 折叠器 `applyCreated` 变成 no-op；
`pipeline.ts:117` 的复活意图在折叠层从未实现 —— **M4 冻结层**）。

**这解释了 §6.7 的"探针写、批次不写"**：两者的**种子路径不同** ⇒ 指纹/去重判断不同：

```text
探针 `F4` 的种子：`h.commitAndFold(h.makeCandidate(...))`（直构造） ⇒ 新 create 的指纹**不撞** ⇒ 写得进
语料 `C05-04`：`seedMemory(...)`（走记忆路径）          ⇒ 指纹**撞上**那条 retracted ⇒ `already_applied` ⇒ 写不进
```

⇒ **`C05-04` 的红是"继承来的 `F-4` 读数"，不是 Lv2 新发现的缺陷**；而 `D-88d` 的顺序（先证抽取）
在这里正好起作用：**抽取已证**（§6.5/§6.7），所以这一条红**现在才成为关于复活的真证据**。

要么该 flag 在这条路径上**没被咨询**，要么"复核用的指纹"与去重用的指纹**不是同一个**
（`memory-validator.ts:721-732` 的那段）。两者都是 M4/M9.1 的领域，**不改**，只定位 + 归口。

### 6.9 **查清了：是我夹具缺一个依赖（第 5 个"装配保真度"缺口），不是 `F-4` 本身**（2026-10-02）

```text

  ② `features.restatementRevivalEnabled === true`      —— Lv2 装配**已传** ✓（`LV2-D10` ③）
```
