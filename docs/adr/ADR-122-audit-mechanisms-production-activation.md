# ADR-122 — 审计修复与 OSS 借鉴机制生产激活

2026-10-09 · ACCEPTED / EXECUTED。

授权：用户在获知新增机制尚未生产激活及 AUD-ISO-01 尚开放后，明确要求“请继续进行，然后生产激活”。本裁定执行 ADR-121 的已有实现，并处置当前数据库的可用性；不把这句话解释为恢复历史快照、删除数据或接受事故全部残余。

1. 先按独占租约保存现有真实库现场，健康验证和逐表检查只打开一次性副本。当前库通过检查则保留原库，不恢复、不迁移、不清理 pid/WAL。缺少事故前摘要与事故原连接的关闭证据，仍作为 UNKNOWN 保留。
2. 新前端按已审核源码构建并部署；补丁与 index 摘要必须等于上一轮验证包，旧前端与受管源码先备份。AIRI / LiveKit / Pipecat / MaiBot 为独立适配的机制，不安装四套框架。
3. 复用一个生产核心与 QQ / avatar 两条外壳。首轮真实检查发现共存核心未开启表达侧车，补齐 `.env` 的 `CHARACTER_EXPRESSIVE_SPEECH=true`，与正式单独 avatar 入口的既有要求一致；首轮 FAIL 保留。
4. 自动记忆保持原开关、资格、水位、失败预算和授权上限。健康视图只读；本次无积压、无失败耗尽，因此不制造恢复授权。真实诊断对话的消费与任务账本作为首次使用证据，不用写入虚构个人事实来测试。
5. 正式装配每轮相关记忆上限 3 条，与 token 预算同时生效。生产观察与隔离量具分列；没有触达条数上限不得宣称生产限制分支已被实测触发。
6. 真实页面验证短回复、音频终态、打断清队列和核心 ACK。ACK 中的 `alreadyCommitted=true` 如实保留，不等同于模型中止或已提交事实回滚。语音性能验收和人格收益评测仍 DEFERRED。
7. 共存停机脚本根路径少算一层，修正为项目根，增加从任意 cwd 执行真实脚本的隔离检查。关闭沿用同一哨兵与既有 drain / close / post-close 状态机。
8. `.env` 的 `PGLITE_SNAPSHOT_DIR` 指向独立目录 `data/snapshots/audit-activation-20261009`，本轮不清理既有快照；事故原现场另存不参与自动保留清理的本地副本。完整回归只使用该目录中已验证的 post-close 快照作副本源；原始 tracked 证据先备份，新增输出归档后恢复原字节。

激活记录：[生产执行与分列读数](../audit/2026-10-09-audit-production-activation.md)。停止新运行时沿用 `pnpm coexist:stop`，等待核心退出码 0、owner `cleanClose=true` 与 post-close 快照；禁止强杀数据库持有者。

执行终读数：生产配置与部署摘要读回通过，正式页面已连接；共享核心 PID 25748，QQ 6751 / avatar 6752 由同一持有者监听，HTTP 12394 正常。`pnpm typecheck`、共存离线整链（含真实停机脚本路径检查）、`pnpm m4.5:ci` 均 EXIT 0。当前保持运行；此前受控关闭的 `cleanClose=true` 与 post-close 快照单独留证，不为仍在运行的连接填写关闭证明。
