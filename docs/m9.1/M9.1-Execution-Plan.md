## 0. 目的与完成定义

本阶段修复 M9 验收暴露的两个既有缺口，先 F-4，再 F-1：

1. **F-4 / R-21 / L-M9-19**：用户在遗忘或更正之后逐字重新告知同一内容，不能再出现“事件提交、回复说记住了、投影却没有形成可用记忆”的分歧。

新增外部能力 = **NONE**。本阶段不建设 embedding、向量库、语义排名或新自主任务。

## 3. F-4 设计方向与必须裁定的问题

### 3.1 推荐方向

优先修正折叠语义，保持原 Memory ID 契约，新增合法重述后的有效 revision。**这只是首选方向，不授权直接把所有非 ACTIVE 记录改回 ACTIVE。**

状态转移必须由新的合格陈述和原政策放行驱动；reducer 保持纯函数，不能自行查库或推测用户意图。若当前事件不足以区分新陈述与旧来源再处理，WP1 必须提出最小、版本化的追加契约，不能靠到达时间或随机盐猜测。

| 输入情形 | 要求 |
|---|---|
| 同一事件重复投递、同一操作重试 | 幂等；不增加 revision，不重复形成信念 |
| ACTIVE 的同内容重复抽取 | 保持既有 D2 去重语义 |
| RETRACTED 后新的明确、合格告知 | 可形成新的有效 revision，来源绑定新告知 |
| SUPERSEDED 后重新告知旧值 | 先经过既有冲突/更正规则；不能绕过政策直接覆盖当前值 |
| DISPUTED 或其他非目标状态 | 不因泛化分支自动恢复；保持既有政策 |
| 旧对话再扫描、旧任务重试、索引重建 | 不被当作遗忘后的新告知 |
| 新陈述来自 assistant、工具或不合格归因 | 不获得用户事实写入资格 |

### 3.2 新版本、新来源与依赖

ADR 必须逐字段说明：revision、来源引用、创建/记录/更新时间、有效期、supersededBy、状态和权威标签如何更新，哪些旧值只在历史事件中保留。不能残留旧失效字段，也不能伪造一段从未中断的有效期。

特别验证 `dependsOnMemoryIds` 的旧消费者：**同一个 ID 再次有效，不得使旧信念仅凭 ID 检查自动恢复资格。** 新形成必须回查新来源；旧禁用根仍禁用。若需要版本绑定或额外依赖资格检查，列出最小契约变更及所有消费者，不偷偷扩大 Belief 语义。

回复真相链检查四层：事件已提交 → 投影实际结果 → 当前资格 → 可用读取。只有新写入确实形成合格状态时才报告对应的成功；重复、争议或失败沿已有结果类型如实表达。不能把修复收缩成仅修改“记住了”的措辞。

### 3.3 旧账本兼容是实施前置

改变 `applyCreated` 可能把旧账本中曾 no-op 的 CREATE 重解释为有效写入。WP1 必须选定并冻结可确定重放的兼容边界：旧事件保留原解释，新语义使用可辨识的版本或其他确定性标识。不得依赖机器当前时间、临时进程开关或不入账的 cutover。

- 旧事件流在新实现下的 canonical 投影默认要求保持一致。
- 新语义事件流在线折叠与从零重放逐字段一致。
- 若无法兼顾，提出明确的历史重解释影响清单与独立裁定；未经裁定不修复历史生产记录。
- 回退必须验证旧代码能否理解新增事件。不能把“切回旧提交”当作天然安全的回滚方案。
- 若首选方案无法保持历史、幂等或依赖完整性，返回设计裁定；改用新 ID 属替代方案，不能在实施中静默切换。

## 4. F-1 设计方向与覆盖边界

### 4.1 定向控制入模来源

以已确认的遗忘对象、事件及可靠来源关联为依据，在现有 ContextCompiler/装配链控制输入。保留持久账本；不删改用户/assistant 历史正文，不做全文关键词黑名单，不新增平行 prompt 入口。

遮蔽的是**被撤销的旧来源及其可确认派生内容**，不是某段文字永远不可出现。用户后来重新合法告知同样内容，可使用新来源；旧禁用根不因此解禁。

明确遗忘与普通更正分开处理：更正后的旧值能否用于历史查询，沿原历史政策；明确遗忘不因用户问“以前是什么”而获得读取许可。同值不同人物、不同主体或不同来源也不能一并屏蔽。

### 4.2 WP1 必须产出的来源覆盖表

| 读取面 | 必须查明 | 验收要求 |
|---|---|---|
| Recent 用户原话 | Memory/遗忘目标能否定位事件与内容范围 | 已关联旧内容不再供给；同轮无关内容有保留正控 |
| Recent assistant 复述 | 是否有可靠的派生/引用关系 | 不以清除用户行冒充堵住整个泄漏通道 |
| rolling summary | 来源链、历史摘要资格与裁剪行为 | 旧值不能经摘要回流；摘要关闭/开启分别测 |
| Memory Recall / 状态文本 | 当前资格、解释排除原因的文字 | 不能在“解释为什么忘了”时再次输出旧值 |
| Belief section | 旧依赖失效、禁用根、最终入模集合 | 与 M9 同轮 overlay 及最终回查一致 |

本表是调查与验收责任，不是假定现有数据已经具有这些关联。

关联不完整时，必须在 ADR 写明具体处理：保守排除哪个候选片段、会损失哪些正常信息、如何测试误伤。不得编造关联，或以宽泛关键词替代证据。若只能实现部分覆盖，分列覆盖面与残余；未满足 F-1 冻结判据时，F-1 保持开放。

### 4.3 判定点与不变量

- 最终判定发生在实际 prompt 接受证据集合之前，不能只查召回结果或 trace 的 selected 字段。
- 同轮遗忘、候选读取后发生遗忘、重启后读取均应遵守冻结的先后规则；已经发出的回复不追溯撤回。
- 关联/状态读取失败不得伪装成“用户从未说过”；对受影响的证据失败关闭，并通过正常正控防止退化成全量禁用。
- 解释或状态提示只表达程序可证的记录状态，不虚构“我从来不知道”。必要提示是辅助，不单独充当修复证明。
- DR-11 禁止的是启发式回复守卫，不应被解读为全面禁止 prompt 政策；本阶段不新增回复关键词拦截。新上下文政策仍需在 ADR 明确与 D-55f/DR-11 的关系。
- 诊断只记引用、数量、阶段和原因；不为观察遮蔽效果把被遗忘正文写进生产 trace。

| R03 | 更正后逐字重述旧值 | 原冲突政策生效，无未经授权覆盖 |
| R04 | 遗忘→重述→再遗忘→再重述 | 各次版本与来源可追踪，无旧失效字段残留 |
| R05 | 同事件重复/操作重试/失败恢复 | 无重复 revision 或新信念支持数 |
| R06 | 旧对话重新抽取、旧任务重跑 | 旧源不冒充新告知 |
| R07 | 历史 no-op CREATE 混合事件流 | 冻结兼容边界生效，无静默历史重解释 |
| R08 | 在线折叠、重启、从零 rebuild | canonical 全字段等价 |
| R09 | 不合格来源与另一主体同值 | 零非法写入、零跨主体影响 |
| R10 | 相同 ID 新 revision 与旧 Belief | 新根可沿政策形成，旧根/旧信念不自动恢复 |
| R11 | 提交失败、投影失败、争议结果 | 回复与实际程序结果一致，不误报记住 |
| R12 | F-4 原长门检查点与窗口外追问 | Memory/Belief 状态及原 LL-C5/C6 恢复，不能靠 Recent 代替召回 |

### 7.2 F-1：输入、输出与误伤（每个场景全部断言通过）

| ID | 场景 | 必须证明 |
|---|---|---|
| P01 | 原 T11“让我忘的具体是什么” | 最终上下文无已撤旧来源取值，回复不复述 |
| P02 | 追问最早值、历次更正、逐字引用 | 不经解释/历史问法泄漏 |
| P03 | assistant 曾复述旧值 | 已纳入关联的派生行不回流 |
| P04 | 摘要包含旧值 | 开/关摘要均满足冻结边界 |
| P05 | 同行混合遗忘内容与无关有效信息 | 无关内容仍可正确回答；误伤逐项报告 |
| P06 | 同值不同人/主体/来源 | 遮蔽不越界 |
| P07 | 普通更正后合法问历史 | 保留原政策允许的历史回答 |
| P08 | 明确遗忘后重新合法告知同值 | 新来源可用，旧来源仍禁用 |
| P09 | 重启/跨会话/窗口滚出 | 遗忘边界不依赖当前进程缓存 |
| P10 | 取候选后遗忘、编译前状态变化 | 最终判定点阻断过期内容 |
| P11 | 关联缺失/读状态失败/预算裁剪 | 如实降级；不能宣称已覆盖未知来源 |
| P12 | Recall/Belief/状态解释/trace | 不从另一 section 或诊断正文泄漏 |

同内容可以因 P08 的新来源合法入模；判据必须基于来源与时序，不能只做“最终 prompt 是否含某字符串”的全局断言。

### 7.3 正控、量具与真模型

- 复用 ADR-055 的 `supported_recall_positive_v1` 三类正控（明确事实、有据细节、更正后的有效值），保持旧集身份；“不知道”不能算正控通过。
- 补本阶段 P05/P06/P07/P08 和 R02/R03 的正控；冻结集内正常功能失败为 0，不能用拒绝全部回答换取泄漏为 0。
- 确定性门：非法复活、误写/误删、错误遮蔽、来源越界、重放不一致、隐私泄漏均为 0。
- 专项真模型：拟定两轮独立运行，覆盖 P01–P08/P12 的用户可见行为与 R02/R03/R12 的记忆结果；每轮全部严重项为 0，正控全部通过。WP1 固定实际用例数、问法与判定器版本。
- M9 原 `m9:live:level1` 保持其三次独立运行和集判据，`m9:live:long` 保持原冻结轨迹；这是修复原失败门，不是恢复已取消的 `m9:long:verify`。
- 程序 oracle 检查事件、投影、根、实际 prompt；语义判定检查改述泄漏。判定器须有已知泄漏与干净回复对照，近义表达不能仅凭词面判定。
- 人工复核旧失败与修复后对照、误伤正控、新告知可用性。未审为 PENDING，不能由模型代填。
- 技术失败、弃判、缺证据分别列出，不算 PASS、不从分母静默剔除。新配置/新实现使用新 run ID；所有 FAIL 保留，不反复抽样挑绿。
- 结论只覆盖冻结场景及观察次数，不宣称永不泄漏或推导总体概率上界。
