## 1. 一句话

M9.1 修的是三处「确定性身份压过一次合法状态变化」的错配：

| 编号 | 层 | 原缺陷 | 修补 |
|---|---|---|---|
| **F-1** | 呈现/供给层 | 遗忘后追问，模型从**上下文窗口里的原始对话行**复述被撤取值 | 编译前**装配层遮蔽**（D15–D24） |
| **F-4** | 投影折叠层 | 忘掉/更正后逐字重述：`MEMORY_CREATED` 真的提交，但确定性 id 撞旧记录 ⇒ `applyCreated` **无条件 no-op** ⇒ 永不可召回 | **复活形 CREATE**（D01–D14） |
| **F-5** | 信念派生层 | 记忆复活后派生 reported 信念不重建：身份段取自 Memory id ⇒ 形成幂等键已消费 ⇒ `duplicate_operation` | 身份分量并入 Memory **revision**（WP8，ADR-072 §13.1） |

共同母题：**确定性标识（id / 幂等键）在「同内容重新合法告知」这一路径上没有区分「第一次」与「第 N 次」**。

## 3. F-4：复活形 CREATE（D01–D14）

### 3.1 为什么不换 id（D01）

发射侧换新 id（选项②）被否决，理由是可核对的契约依赖：M9.5 §8 `sourceRevision`、Belief
`dependsOnMemoryIds` 精确回查、M9.5 §11.1「保持原主键」**全部建立在「同内容 ⇒ 同 id」**上；
且旧流里**已存在的 no-op CREATE** 无法靠新 id 语义修复。⇒ 修折叠器，保持确定性 id 契约。

### 3.2 事件形状（D02/D04）

```text
MEMORY_CREATED（复活形）:
  { memoryId, record: <复活快照，全量>, mutation,
    restatement: { previousRevision: <旧 revision>, previousStatus: 'retracted'|'superseded' } }
```

`restatement` 是 `MemoryCreatedPayload` 上的**可选**字段——这是计划 §3.1 要求的「最小、版本化的
追加契约」：**不靠到达时间、不靠随机盐、不靠进程开关**区分新旧语义。
`createMemoryDomainEventRegistry` 的 `validatePayload` 原本只重建契约内字段（未知字段被剥离），
D02 同步放行该字段。

### 3.3 reducer 三分支（D05，含两处实现期修正）

```text
applyCreated(state, event):
  state === null                                   → 建档（原语义，含旧事件流）
  event.restatement ∧ previousStatus === state.status → state = event.record（复活）
  otherwise                                        → no-op（原语义逐字节）
```

两处**实现期修正**（首跑发现，行为不变、只换判别机制）：

1. 原稿守卫 `previousRevision === state.revision` 在**重放**里必然失配——store 每次折叠 +1，
   纯 reducer 只在创建/复活时设置 revision（`applyRetracted` 等不动）⇒ 在线 2 ≠ 重放 1
   ⇒ 复活只在在线发生 ⇒ **A==B 破**。改为 `previousStatus === state.status`（两侧一致的投影事实）。
   D14「第二个重述不重复复活」仍被保证：第一个复活后状态是 ACTIVE，第二个标记折在 active 上不匹配。
2. 复活快照的 `recordedAt` / `createdAt` **保留原值**（原稿写「复活事件时刻」）——在线（DB 行保留旧值）
   与重放（reducer 算出新值）必然分叉 ⇒ A==B 破。记录身份的最初创建时刻不因复活改变。

### 3.4 复活快照逐字段（D04）

| 字段 | 复活时 | 旧值去向 |
|---|---|---|
| `revision` | `previousRevision + 1` | 历史事件流 |
| `status` | `active` | 历史事件流 |
| `sourceRefs` / `evidenceRootIds` | **新告知的证据**（MI-03 非空） | 旧证据仍在旧 CREATE payload |
| `validFrom` | **复活事件时刻**（不伪造「从未中断的有效期」） | 历史事件 |
| `validUntil` / `supersededBy` | 清空 | 历史事件 |
| `contentFingerprint` / `canonicalKey` / `content` / `subjects` / `type` / `owner` / `id` | 与候选一致（这正是撞线的原因） | 不变 |
| `recordedAt` / `createdAt` | **保留原值**（见 §3.3 修正 2） | — |
| `updatedAt` | 复活事件时刻 | — |
| `authority` / `epistemicStatus` / `importance` / `confidence` | 新告知的抽取值 | 历史事件 |
| `reducerVersion` / `schemaVersion` | 常量（`memory-reducer@1`，D06 **不升版**） | — |

复活快照**由发射侧整体构造**（`record` 全量进事件），reducer 整体采用 ⇒ 不存在「半新半旧」合并态；
`rebuildMemory` 从事件重放逐字段一致（R08 断言面）。

### 3.5 发射闸门的四个条件（D03）

在去重层 1/2 **之后**、快照构造处判定，四条**全满足**才附标记：

```text
① features.restatementRevivalEnabled（D12 开关）
② getRecord(proposedId) 存在
③ 既有 status ∈ {retracted, superseded}        ← D10：DISPUTED 不复活
④ 新证据与既有记录 sourceRefs **不相交**        ← R06：旧对话重扫/旧任务重试不得冒充新告知
```

任一不满足 ⇒ 事件形状与今天**逐字节相同**。

### 3.6 回复真话与 dispute 翻译（D08/D09，**不受开关控制**）

- **D08 写效检查**：create 分支折叠结果必须 `status === 'active'` 才 `ok:true`；否则 `ok:false` +
  新失败原因 **`write_not_effective`**。这是 INV-CI-13「请求提交成功 ≠ 认知修改成功」的实现；
  开关只闸账本语义（D12），**不闸诚实**。R01 不受影响：ACTIVE 重复在 dedup 层已 `already_applied`。
- **D09 dispute 如实翻译**：`MARK_DISPUTED`（含 remember 触发的冲突分支）的 outcome 附
  `performed: 'dispute'` ⇒ `translate` 映射为 `kind='not_written'` + 新原因 `marked_disputed`
  （`executed=false`，无成功口吻）。否决「新 kind」方案：会稀释既有 `executed = kind !== 'not_written'` 契约（C9）。

### 3.7 状态转移表（§3.1 逐行）

| 输入情形 | 冻结行为 |
|---|---|
| 同一事件重复投递 / 同操作重试 | 幂等键拦截（既有）；无重复 revision / 无重复信念形成（D14） |
| ACTIVE 同内容重复 | 既有 D2 去重（`already_applied` / `duplicate_content`）逐字节不变（R01） |
| RETRACTED 后新的明确合格告知 | 标记 + 复活为新 revision，来源绑定新告知（R02） |
| SUPERSEDED 后重新告知旧值 | **先走冲突规则**（D-55c）；不绕过政策直接覆盖（D11，R03） |
| DISPUTED / 其他状态 | 不自动恢复（D10） |
| 旧对话重扫 / 旧任务重试 / 索引重建 | 证据不相交检查拦下（R06） |
| 新陈述来自 assistant/工具/不合格归因 | 既有资格闸（ADR-043）不变，到不了 create 放行（R09） |

### 3.8 兼容与回滚边界（D07）

事件库**原样存储** payload（`appendDomainEvent` 不再校验，`event-store.ts:170`），重放时旧
`applyCreated` 只是不读 `restatement` ⇒ 走原 no-op 分支（`validatePayload` 的字段剥离只发生在
**发射侧**，与重放无关）。

⇒ **回滚候选必须写明**：「回滚后 rebuild 会丢复活、需重建投影或接受丢失」。
**不得把切回旧提交当天然安全回滚**。

## 4. F-1：装配层遮蔽（D15–D24）

### 4.1 为什么在供给面修（D15）

否决选项②（prompt 政策行）：DR-11 的机械保证只到 prompt **供给面**——①可离线断言
「被撤取值不进最终 packet」，②依赖模型服从。否决关键词黑名单（计划 §4.1 明文禁止）：
误伤面不可控（P05/P06 全红）、同值新告知（P08）会被误杀。

### 4.2 撤销证据端口（D16，只读、无新表/列）

```text
输入：characterId / owner
输出：{ withdrawnEventIds: Set<ConversationEventId>,
        byReason: Map<EventId, 'explicit_forget'|'explicit_correction'|'audit'>,
        chainDepth, readAt: sequence }

数据源两条路径：
① 记录面：当前 retracted 记录的 sourceRefs（记录面保留）+ MEMORY_RETRACTED 事件的 reason
② 事件面：每条 MEMORY_RETRACTED 事件的「撤回时来源」
          = 该事件前最近一条 MEMORY_CREATED 的 payload.record.sourceRefs
```

**实现期修正**（验收契约 §6）：复活把记录现值 sourceRefs 换成新告知，但**用户对旧行的遗忘言语
行为不被撤销** ⇒ 旧行仍遮蔽（P08②）、新行不遮蔽（P08①）；多次遗忘各自成立，重复由纯核集合语义去重。

语义**单点**在 `withdrawnSetCore`（D17），端口只拼输入；量具 `computeWithdrawnSet` 委托同一端口
（单一事实源，INV-M9-11 同族纪律）。

### 4.3 遮蔽范围（D17）

| 原因 | 遮蔽集合 |
|---|---|
| `explicit_forget` | 该记录 sourceRefs **∪ 同 canonical slot 的 superseded 链上全部记录**的 sourceRefs（T11：遗忘后整段偏好史不再复述） |
| `explicit_correction` / `audit` | **仅该记录自身** sourceRefs（T17：普通更正的历史沿原政策可查，P07） |

同值不同人/主体**不遮蔽**：`canonicalKeyOf` 含 owner + subject + qualifier、**不含 value**（P06 结构基础）。
superseded 链遍历**有界**（沿 `supersededBy`/`supersedes` 双向，深度上限 + 已访问 id 集合防环），
超界如实降级（D19），不静默截断。

### 4.4 判定点与算法（D15/D18）

```text
turn-gateway（单一编译入口）:
  recentLines ← recentContextLinesFrom(...)              // 现状
  if 开关开:
    withdrawn ← 撤销证据端口（失败 → D19 降级：本轮不供给 Recent + trace 如实记原因）
    for line of recentLines:
      line.actorType === 'user'      ∧ line.id ∈ withdrawn              → 占位
      line.actorType === 'assistant' ∧ line.replyToEventId ∈ withdrawn  → 占位
  compileInput.recentEvents ← 处理后的行                 // 判定在编译接受证据之前
```

- `ConversationLine` 追加 `actorType?` + `replyToEventId?`（D18），`recentContextLinesFrom`
  （`adapters.ts:126`）映射之——**assistant 行按 `replyToEventId` 关联**（P03：不以清除用户行
  冒充堵住派生面）。
- **占位不删除**：保留 `id`/`sequence`/`speaker`/`actorType`，只替换正文 ⇒ Recent 窗口计数、
  序列连续性不受影响；**不伪装「用户从未说过」**（计划 §4.3）。占位文本**程序生成、不含被撤取值**。
- **同轮遗忘**（本轮先忘后编译）：端口在编译前读 ⇒ 天然覆盖（P10）。
- **重启/跨会话**：端口读持久账本，不依赖进程缓存（P09）。
- **已发出的回复不追溯撤回**（计划 §4.3）。

### 4.5 失败关闭与 trace 隐私（D19/D20）

- 端口读失败 ⇒ 本轮**整段 Recent 不供给** + trace 如实记降级原因。**不伪装零结果、不静默放行**；
  正控（P05 无关内容保留）防退化成「全量禁用」（D-55e：失败 ≠ 零结果，原因具名，不合并）。
- 诊断只记**引用/数量/阶段/原因**（trace step `withdrawn_masking`），**不把被撤正文写进生产 trace**
  （计划 §4.3；M5.1 隐私边界同族）。

### 4.6 与已闭合面的关系（D22/D23/D24）

- **语义零改动**：rollup 资格闸④ / Recall ACTIVE-only / Belief 失效 + 禁根 / 状态文本程序生成——
  P04/P12 只加**开/关双测**钉住；遗忘后下一轮由 rollup 每轮重算自愈（WP0 D-2 实测）。
- 遮蔽是**结构供给面控制**（离线可断言最终 packet），**不新增**任何回复文本拦截（计划 §4.3 明文）；
  既有 `applyResponseTruthPolicy` 成功口吻纠正（M4）继续按原语义运行。
- 状态/解释提示只表达**程序可证的记录状态**；禁止「我从来不知道」式虚构（D24）。

## 5. F-5：信念侧传播（WP8，ADR-072 §13.1）

### 5.1 缺陷机制

```ts
// 原身份推导（src/kernel/app/belief/reconciler.ts:191）
const beliefId = makeBeliefId(characterId, slotKey, beliefReportedFormationKeyOf([memoryId]))
```

复活**沿用同一个 Memory id**（F-4 的确定性语义）⇒ 再形成推导出**同一个 `beliefId`**；而 formed
提案的领域幂等键按 `beliefId` 推导（`src/kernel/app/belief/job.ts:231-234`）⇒ 该键在**首次形成时
已消费** ⇒ `duplicate_operation` 拒绝 ⇒ **派生信念永不重建**。

与 F-4 同族：确定性身份压过一次合法的状态变化（F-4 在记忆层、F-5 在信念层）。

### 5.2 最小补修

```text
beliefReportedDependencyTokenOf({ memoryId, revision }):
  revision > 1  ⇒ 身份分量 = `<memoryId>@r<revision>`   （新信念身份）
  revision = 1  ⇒ 裸 id                                  （M9 基线身份逐字节不变）
```

- **同源**：reconciler（产出身份）与 `belief-validator.ts`（复推身份）调用同一函数（INV-M9-11 不变）；
- **端口供数**：`revision` 由 `belief-scheduler.ts:245`（`revision: record.revision`）提供，
  `ReconcilerMemoryView` / `BeliefMemoryLookup` 各加 `revision?: number`；
- **旧信念不复活**（D13 原意不变）：旧 retracted 信念保持 retracted；
- **新信念带新根**：复活告知的证据根；
- **禁根不外扩**：`forbiddenRootsForSlot` 按根 id，复活前后逐条一致（R10③）。

### 5.3 为什么算“假设更正”而不是“设计转向”

D13 原本声明的行为就是「复活 ⇒ reconciler 走**新形成**候选路径：**新信念身份** + 新根」，
只是**假设**了「新形成天然得到新身份、因此 belief 面零代码变更」。实测证伪的是**这个假设**，
不是 D13 的目标行为。⇒ §13.1 记录为假设更正 + 实现补齐，**不回写** D13 原文。

## 7. 与相邻域的边界

- **Memory Kernel 冻结区**：M9.1 是经 ADR-072 批准、走完整 `m4:*` 门的**语义追加**——只**追加**
  可选标记字段与一个 reducer 分支；无标记路径逐字节不变（这是旧流兼容的根据）。
- **已发布迁移 DDL：零改动**（D16 复用既有表，无新表/列）⇒ `Database Migration = NONE`。
- **M9 信念域**：F-5 补修**只**动身份分词函数与其供数端口；不扩形成类型、不动白名单/阈值/守卫。
- **M9.5**：本层**不是**它的验收；交接契约见 `M9.1-to-M9.5-Handoff.md`（同内容重述、遗忘呈现、
  旧根禁用、正常历史查询、事件位置、最小夹具六项）。
- **不新增回复文本拦截**、**不新增外部能力**（`External Capability Added = NONE`）。

| M9 原门复跑 | 回归 | `m9:live:level1` ×3（flags ON 验收批 + flags OFF 负控批）· `m9:live:long` 原冻结轨迹 |

Live 门不在 `gates/manifest.ts` 的 lane 内（要 `with-test-model`，M8/M9 先例），
登记为 package.json 脚本；`m9.1:gates` 只读证据。

## 9. 已知架构级边界（详见 `M9.1-Known-Limitations.md`）

- **占位文本本身是新的 prompt 面**（ADR-072 §8.1）：形状不当可能诱导追问；本里程碑以 P05 正控 +
  真模型两轮观察约束，残余登记为限制。
- **`explicit_forget` 的整槽历史遮蔽是语义选择**（T11 vs T17 分轮处理）：用户遗忘后**明确要求**
  讲历史时，冻结语义仍遮蔽——细化留给后续里程碑（ADR-072 §8.3）。
- **旧代码读新标记事件 = no-op**（D07）：回滚窗口内的复活会从投影消失（账本事件仍在）。
- **superseded 链深链成本**：有界遍历 + 深度记 trace，超界如实降级。
- **词形/语义边界**：机械保证只到「被撤取值不进最终 packet」；**不主张**她不会用别的说法说错
  （DR-11 同源）。
