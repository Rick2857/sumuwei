## 1. 交接的性质与边界

M9.1 **不是** M9.5 的前置功能开发，而是 M9 两个 live 红项（F-1 / F-4）与执行期发现项（F-5）
的**最小修补层**。它对 M9.5 的意义是：**M9.5 要继承的 M4/M9 语义基线已经变了**——
具体是 `MEMORY_CREATED` payload 多了一个可选标记、`applyCreated` 多了一个分支、
信念身份多了一个 revision 分量。M9.5 的「保持原契约」条款必须指向**修复后**的语义。

⚠️ **M9.1 未向 M9.5 交付任何索引/向量/检索能力**（计划 §5 末段明文：共享
Context/Memory/Recall 正式集成应等待 M9.1 稳定交接；M9.5 的向量与长程专项**不接回**本里程碑）。

## 3. 六项消费规则（ADR-072 §6 逐条冻结）

| 项目 | M9.1 已冻结的规则（M9.5 消费） | M9.5 负责 |
|---|---|---|
| **同内容重述** | 权威状态 = 复活后记录；`revision` **单调 +1**；来源 = **新告知**；M9.5 索引按「同 id 新 revision」更新——**正文 hash 相同也必须更新状态/来源**（其 §8 `sourceRevision` 消费 `restatement.previousRevision → previousRevision+1` 规则） | 按新源版本更新索引；不得因正文 hash 相同而跳过状态/来源变化 |
| **遗忘呈现** | Recent 边界 = **D17 集合**（`explicit_forget` ⇒ 记录 sourceRefs ∪ 同 canonical slot 的 superseded 链全部 sourceRefs；`explicit_correction`/`audit` ⇒ 仅自身）；M9.5 向量/缓存/混合召回**继承同一集合语义**，**不得另立黑名单** | 向量、缓存、混合召回与组合上下文继承该规则 |
| **旧根禁用** | 复活**不触碰**旧禁根（Belief 禁根按根 id；旧 retracted 信念不复活）；同 id 新 revision **不恢复**旧信念资格 | 查询、重建、模型换代均不得绕过 |
| **正常历史查询** | `explicit_correction` / `audit` 的遮蔽**仅自身来源**（D17）⇒ 更正史沿**原历史政策**可检索（T17）；`explicit_forget` 的整槽历史遮蔽**是语义选择**（`L-M9.1-02`） | 沿同一历史政策检索 |
| **事件位置** | `restatement` 在 **`MEMORY_CREATED` payload（可选字段）**；M9.5 事件前沿消费「标记存在 ⇒ 该 CREATE 是**复活**」（`previousRevision` / `previousStatus` 给出前驱） | 事件前沿按标记识别复活 |
| **最小夹具** | WP2 产出五件（计划 §5 交接 2），见本文 §4 | 复用；不重造 |

## 6. 新 ID / 版本 / 事件位置映射（消费者规则）

| 项 | 值 | 消费者须知 |
|---|---|---|
| `MEMORY_CREATED.payload.restatement` | 可选，`{ previousRevision: number, previousStatus: 'retracted'\|'superseded' }` | 存在 ⇒ 该 CREATE 是**复活**；`record.revision = previousRevision + 1` |
| `MEMORY_REDUCER_VERSION` | **不变**（`memory-reducer@1`，D06） | 升版会让 store 对全部存量记录 fail-close；**判别器是标记本身，不是版本号** |
| 投影 | `character_projections`（复用 M5 domain-events 基座） | **无新表/新列** ⇒ `Database Migration = NONE` |
| 信念身份 | `beliefReportedDependencyTokenOf({memoryId, revision})`：`revision>1` ⇒ `<id>@r<revision>`，`revision=1` ⇒ 裸 id | M9 基线身份**逐字节不变**；M9.5 若重推身份必须调同一函数（INV-M9-11 同源纪律） |
| 来源（事件面 vs 记录面） | 记录面 = **现值**；事件面 = **撤回时来源** | 合法性/遮蔽判定必须指明读哪一面（`L-M9.1-09`） |
| 默认配置 | 两开关**代码缺省 false**；候选配置 = 两开关 true（+ 既有 `CHARACTER_BELIEF_ENABLED=true`） | 见 `M9.1-Activation-Candidate.md`；**回退限制**见 `L-M9.1-03` |

## 8. M9.5 需要自行追加的交接记录（不覆盖在途修改）

M9.5 计划 §11.1 现有条款「**M4 / M4.1 Memory | 保持的契约：原主键、来源、事件 payload、
reducer、放行口与遗忘确定性**」在 M9.1 之后**需要重新指向**：

- 「reducer」与「事件 payload」的**基线 = M9.1 修复后的语义**（多一个可选标记字段、多一个
  `applyCreated` 分支）——**不是** M9 收口时的原语义；
- 「off 模式等价」与 prompt 基线：M9.1 两开关**缺省 off** 时逐字节等于 M9 基线（`m3.5:test` 逐字节回归守着，D21）；
- §4（依赖与交接）/ §8（索引数据契约）/ §10（更正遗忘历史查询）/ §11（兼容矩阵）/ §15（场景矩阵）
  需以**追加**方式记录本次继承，**不回写**其历史行。

**协调方式**：由 M9.5 的执行会话追加（本文提供映射，不代其修改文件——`docs/m9.5/**` 本轮零改动）。

## 9. M9.1 对 M9.5 的**不主张**

- 不主张 M9.5 的向量/缓存/混合召回会继承正确——只冻结**集合语义**，通道未实现、未验收；
- 不主张 M9.5 可以复用 M9.1 的 live 读数（`m9.1:smoke:live` / `m9:live:level1` / `m9:live:long`）；
- 不主张 `restatement` 标记已被任何 M9.5 事件前沿消费（消费者尚未存在）；
- 不主张生产激活——M9.1 状态为 **NOT ACTIVATED / NOT MERGED / NOT TAGGED**（ADR-072 §12）。
