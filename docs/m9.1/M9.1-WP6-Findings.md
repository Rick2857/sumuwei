## 2. F-5（新发现）：记忆复活有效，派生 reported 信念不重建

**读数**（`artifacts/m9/m9-live-long-20260927-24f6cca44435-edcc/live-long.json`）：

```text
LL-C5: active 记忆=1(detailed) · active 信念=0 · retracted 链=1     ← 记忆复活 ✓ / 信念 ✗
LL-C6: active 记忆=1 · 信念=0 · 污染=0 · 水位=951/951 · failed=0     ← 同上
```

**原始库行**（同一 run 的临时生产副本，只读查询）：

```text
memory_records: id=…:preference-1fc4ad20eb342f20  status=active
                valid_from=1790545112197（= 复活事件时刻 2026-09-27T21:38:32Z）
domain_events : seq=552 MEMORY_CREATED RESTATEMENT={"previousStatus":"superseded","previousRevision":2}
```

⇒ **WP3 的复活在 live 端到端生效**（F-4 的记忆侧缺陷已修复）：复活形 CREATE 发射、折叠落库、
`valid_from` 取本次告知时刻。

**但派生信念没有重建**（同一 run 终态）：

```text
beliefs: blf:…:9cbdea5a:e88a8a2c  preferred.explanation.style = detailed  status=retracted   ← 仍是旧 retracted
beliefEvents: BELIEF_FORMED=3 / BELIEF_RETRACTED=2（终态无第四次形成）
jobs: belief-memory-reconciler completed=403 · 水位 953 > 账本 951   ← 调和流跑过、追平了账本
```

**设计期望 vs 实测**：[ADR-072](docs/adr/ADR-072-m9.1-restatement-revival-and-withdrawn-masking.md) `D13`
写的是「复活 ⇒ reconciler 走**新形成**候选路径：新信念身份 + 新根，过完整 validator；旧 retracted 信念
不复活」并据此声明 **Belief 面「零代码变更」**。实测：**没有任何新形成发生**（旧 retracted 信念
既没复活——这一半符合 D13——也没有新的 active 信念出现）。

**机制（已钉死，非推测）**：离线 rig 复现该形状（`R13-B1` ❌）并暴露了调和器读数：

```text
R13-B1: active detailed 信念=0 · 依赖含复活记忆=false · mem流 formed=1 · skipped=[] · lastKind=no_tail
```

即：**调和器确实提出了新形成（`formed=1`）**、**没有跳过（`skipped=[]`）**，但终态没有 active 信念
⇒ **提案在放行口被拒**。原因在身份推导：

```ts
// src/kernel/app/belief/reconciler.ts :191-195
const beliefId = makeBeliefId(
  deps.characterId, slotKey,
  beliefReportedFormationKeyOf([memoryId]),   // ← 身份段 = Memory id
)
```

复活**沿用同一个 Memory id**（WP3 的确定性语义：同槽同值 ⇒ 同 id，只升 revision）⇒ 再形成推导出
**同一个 beliefId**；而 formed 提案的领域幂等键按 beliefId 推导（`src/kernel/app/belief/job.ts` :231–234）
⇒ 该键在**首次形成时已消费** ⇒ 判 `duplicate_operation` 拒绝 ⇒ 派生信念永不重建。

**与 F-4 同族**：确定性身份压过一次合法的状态变化。F-4 在记忆层（`applyCreated` 撞 id 折叠 no-op，
WP3 已修），F-5 在信念层（幂等键撞 beliefId，**未修**）。

**注意范围边界**：用户可见面**已修复**——真模型冒烟 R02/R12、S5/P08 全部通过（她能答出复活后的取值）；
F-5 是**信念层内部一致性**的缺口（`belief` section 不会带上复活后的取值），长门 `LL-C5/C6` 正是按
「记忆 + reported 信念」两条一起判的，所以它仍红。

## 3. 为什么这构成 M9.1 的未竟项

- 冻结的 M9 长门检查点 `LL-C5` 要求「detailed 记忆 **+ reported 信念**」、`LL-C6` 要求
  `activeSlotBeliefs` 含 detailed ⇒ **该门仍红**，而计划 WP6 的要求是复跑原失败门并让它变绿。
- 但修它**要动信念层**（身份/幂等/形成路径），而 `D13` 已把它裁定为「零代码变更」⇒
  **属于设计变更**，需要 ADR 修订 + 用户裁定，不能由执行侧静默偏离。
