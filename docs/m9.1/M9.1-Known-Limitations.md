# M9.1 Known Limitations —— 已知局限

- 日期：2026-09-28（WP7 收口）· 分支 `feature/m7-relationship`
- 依据：`ADR-072` §8（设计冻结时的残余）+ 本轮实测发现追加项
- 纪律：每条**分列**，不合并成总分；新证据可取代单条，**不回写**历史（M9 的 `L-M9-13` / `L-M9-19` 保持原样）。
- 读法：本清单是 **M9.1 修补层**的边界；M9 域本身的边界见 `docs/m9/M9-Known-Limitations.md`（`L-M9-01…19` 全部仍有效）。

## 一、设计冻结时就已知的残余（ADR-072 §8，逐条）

- **L-M9.1-01（占位文本本身是新的 prompt 面）**：F-1 的遮蔽把用户行/assistant 行替换为
  **程序生成的占位**。占位形状不当可能**诱导追问**（「那条被隐藏的是什么？」）或显得异常。
  本里程碑以 P05 正控（无关内容仍可正确回答）+ 真模型两轮观察用户可见行为约束；
  **不主张**占位在所有措辞下都自然。
- **L-M9.1-02（`explicit_forget` 的整槽历史遮蔽是语义选择）**：D17 规定遗忘 ⇒ 该记录
  sourceRefs ∪ 同 canonical slot 的 superseded 链**全部**记录 sourceRefs 进入遮蔽集
  （T11 语义：遗忘后整段偏好史不再复述）。后果：用户遗忘后**明确要求**讲历史
  （「我以前让你忘的是什么」）时，冻结语义**仍然遮蔽**。T11（忘的是什么）与 T17（什么改过）
  当前按**分轮**处理；该交互形态的细化**留给后续里程碑**（ADR-072 §8.3 明文，不在本里程碑扩权）。
- **L-M9.1-03（旧代码读新标记事件 = no-op，回滚窗口内复活会消失）**：D07——事件库原样存储
  payload，旧 `applyCreated` 不读 `restatement` ⇒ 走原 no-op 分支。⇒ **回滚到旧提交后
  rebuild 会丢复活**（账本事件仍在，投影丢失），需重建投影或接受丢失。
  **「切回旧提交」不是天然安全回滚**；回滚候选必须逐条写明（见 `M9.1-Activation-Candidate.md`）。
- **L-M9.1-04（superseded 链深链成本）**：D16/D17 的链遍历沿 `supersededBy`/`supersedes`
  双向、有界（深度上限 + 已访问 id 集合防环）。深链在长历史上可能贵；**超界如实降级**
  （D19：本轮不供给 Recent + trace 记原因），**不静默截断**。

## 二、本轮实测发现追加项

- **L-M9.1-05（长门 `LL-MARKERS` 在阈值附近非确定性摆动）**：三次同轨迹同配置 run 的读数分别是
  **11/11 = 100%**（WP8 前）· **9/11 = 81.8%**（run A）· **10/11 = 90.9%**（run B，**通过**）。
  漏词都落在**同一个探针** `你有哪些看法改过，为什么？`（run A 漏 #60 与 #180 两处，run B 只漏 #60），
  期望词面 `改过|更正|变过|更新过|调整过|改过主意`。**与 F-4/F-5 修复面无关**
  （`LL-C5/C6` 两次 run 双绿、`LL-SEVERE = 0`）。词形断言是**下界不是上界**——
  语义判定权在人审（INV-M45-06 的持续含义）。⚠️ **粒度问题见 `L-M9.1-17`**。
  **原读数不移除、不覆盖**；**不反复抽样挑绿**（计划 §7.3）。
- **L-M9.1-06（泄漏判定器的指令引用边界需实测校准）**：`m9.1-judge` 在 `@4` 把 S1-P01 的
  回复判 `LEAK`，而该内容**只能来自用户自己的遗忘指令**（指令本身带着被忘对象的说法，
  按 D17 设计**保持可见**），且她同时明确声明**不再持有** ⇒ 属**量具边界未覆盖**，
  不是遮蔽失效。`@5` 把 D17 边界明确到「**逐字或轻度改述**都算指令引用」+ 第四控
  （指令改述 + 明确不再持有 ⇒ 必判 CLEAN）。**原 `@4` 读数不改写**。
  残余：LLM 判定器的边界永远是**枚举出来的**，开放世界措辞仍可能落在边界外。
- **L-M9.1-07（判定器对网络瞬时失败敏感）**：`@5` 首跑已知泄漏正控返回
  `UNSURE` 并伴随 `TypeError: fetch failed`（瞬时网络失败，非判据问题）。
  已加重试（3 次、递增退避）。**残余**：LLM 判定器依赖外部端点可达性；
  正控失败时**整个读数作废**（不是 PASS），这是失败关闭的正确行为。
- **L-M9.1-08（D05/D04 两处实现期修正——原冻结稿的判别机制在重放下不成立）**：
  1. D05 原守卫 `previousRevision === state.revision`：store 每次折叠 +1、纯 reducer 只在
     创建/复活时设置 ⇒ 重放必然失配 ⇒ 复活只在在线发生、**A==B 破**。改为
     `previousStatus === state.status`（可观察行为不变，只换判别机制）。
  2. D04 原稿 `recordedAt`/`createdAt` = 复活事件时刻：在线（DB 行保留旧值）与重放
     （reducer 算出新值）必然分叉 ⇒ **A==B 破**。改为**保留原值**。
  ⇒ 教训：**「纯 reducer 与 store 的字段写入语义不同」是冻结设计必须逐字段核对的面**，
  不能只核对状态机。两条修正已登记进 ADR-072 D05/D04（追加，不回写原行）。
- **L-M9.1-09（D16 的「撤回时来源」必须读事件面，不能只读记录面）**：复活会把记录现值的
  `sourceRefs` 换成**新告知**的证据，但用户对**旧行**的遗忘言语行为不被撤销。若只读记录面，
  P08②（旧行仍遮蔽）会失效。实现取「该 `MEMORY_RETRACTED` 事件前最近一条 `MEMORY_CREATED`
  的 `payload.record.sourceRefs`」（事件面）。⇒ 边界：**记录面是现值、事件面是历史**，
  合法性判定必须指明读哪一面。
- **L-M9.1-10（D13「Belief 面零代码变更」的假设被实测证伪 ⇒ 范围扩展至 WP8）**：
  F-5（复活未传播到派生 reported 信念）在 WP6 复跑暴露。**这不是设计转向**——
  D13 声明的「新信念身份」正是补修要实现的行为，被证伪的是「新形成天然得到新身份」这个**假设**。
  用户 2026-09-28 裁定 **A：纳入 M9.1 补修**（ADR-072 §13.1）。
  ⇒ 教训：**「结构已满足」类断言必须被实测钉住，不能靠推理宣布零改动**。
- **L-M9.1-11（F-1 的复现是非确定性的）**：flags **OFF** 基线批 3 次里只有 run3 命中严重项
  （`…9cc15f13f90c-685c`），run1/run2 全绿。⇒ 单次 live 运行**不能**用来排除 F-1；
  也不能把「一次绿」当成修复证据。缺陷的在场证明与修复的销账证明**都必须是新 run 集**
  （R-20 条件即为此而设）。
- **L-M9.1-12（结论只覆盖冻结场景与观察次数）**：M9.1 的修复主张限定为
  「**冻结场景通过、来源边界可查、重述语义可重放**」（计划 §10 明文）。
  **不主张**永不泄漏、**不主张**总体概率上界、**不主张**她不会用别的说法说错（DR-11 同源）。
- **L-M9.1-13（开关缺省 = off；修复在缺省配置下不生效）**：两个新开关代码缺省都是 `false`。
  验收与候选配置是**显式打开**（`CHARACTER_MEMORY_RESTATEMENT_ENABLED=true` +
  `CHARACTER_WITHDRAWN_CONTEXT_MASKING_ENABLED=true`）。⇒ **不得凭配置宣布运行验证通过**；
  也不得把缺省 off 下的读数当成修复生效的证据（`§1.1` 负控批正是 off 读数）。
- **L-M9.1-14（M9.5 兼容性不在本里程碑验证）**：交接契约（`M9.1-to-M9.5-Handoff.md`）冻结了
  六项消费规则，但 **M9.5 的向量/缓存/混合召回未实现、未验收**。本层提供的只是**可继承的
  版本与来源契约**；M9.5 若另立黑名单或绕过旧禁根，属其自身缺陷。
- **L-M9.1-15（生产激活已执行；合并/标签已执行；首聊仍未观察）**：三行状态分别登记——
  ① **生产激活 = ACTIVATED**（2026-09-28 用户显式授权，载体
  [ADR-073](../adr/ADR-073-m9.1-production-activation-merge-tag.md)：`.env` 两个开关置 `true`；
  **代码缺省仍 `false`**）；② **合并 = DONE**（ff 进 `main`，无合并提交）· **标签 = `m9.1-complete`（annotated）已打**；
  ③ **FIRST-USE NOT OBSERVED**——真实对话轮未发生，轮级观察面（`withdrawn_masking` trace /
  `belief_context` / 复活形 `restatement`）待首聊（不凭配置宣布运行验证通过）。
  真实库在本次激活中**未被打开**（M9.1 无激活期真库动作，理由见 ADR-073 §3）；
  ⇒ **生产写入/并发条件下的一致性条件仍未观察**（这一条不因激活而关闭）。
- **L-M9.1-16（人工复核：已由用户声明式裁定 PASS）**：5 道审题 + F-5 说明于 2026-09-28 获用户
  **声明式裁定——全部确认、无异议**（Q1 行为无问题 · Q2 无关记忆未误伤 · Q3 区分可接受 ·
  Q4 符合预期 · Q5 确认窗口外读回来自召回）。**原 `PENDING` 呈交状态不回写**；载体
  `M9.1-Gate-Decision.md` §6 + `M9.1-Human-Review-Materials.md` §4。
  **边界**：本裁定覆盖**这 5 道题**，**不**外推到 M9 其余人审题、不等于「她不会再说错」、
  不构成生产激活授权；**未表达判断的项目不得由模型代填**（该纪律不因本裁定失效）。
- **L-M9.1-17（`LL-MARKERS` 阈值的粒度：n = 11 ⇒ 一个探针 = 9.09%）**：判据是「11 个冻结探针轮里
  ≥90% 命中正控词」，而 **90% 恰好等于「至多错 1 个」**——**单个探针的措辞波动就能翻转整道门**。
  实测即如此（见 `L-M9.1-05`）。⇒ 这道门在 n = 11 时**不是一个稳定的二值判据**，而是**单点灵敏**
  的阈值。本里程碑**不修改**该阈值（改判据 = 版本化重评，且属 M9 冻结面）；如实登记为**量具边界**：
  读这道门的红/绿时必须同时看**漏了哪个探针**。
- **L-M9.1-18（长门 `LL-TURNS` 的控制台偶发失败，与认知面无关）**：复跑 B 的 `LL-TURNS = 199/200`，
  失败点是 **filler 轮 #186**（「先这样。」）：`status=1`、`replyChars=0`、**耗时 1587ms（快速失败，
  非超时）**——即控制台子进程**启动后即刻失败**。同 run 零泄漏、零严重命中、11 个探针轮全部正常执行，
  且 `LL-C5`（#140）与 `LL-C6`（#200）都在其后取值且双绿 ⇒ **不影响 R-21 的判据面**。
  与 `m9.1:smoke:live` 早期「轮 1 中途抛错」同族 ⇒ **测试基础设施的非确定性**。
  **处置**：读数为 **`FAIL(9/10)` 原样呈交**，不从分母静默剔除、不重跑挑绿（计划 §7.3 明文）。
  冒烟侧已由量具 `m9.1-smoke-live@2` 的**完整性自检**把这类失败**显性化**（残缺 ⇒ 该场景不算过）；
  长门侧原本就如实计入 `LL-TURNS`（**未被吞掉**，行为正确）。
- **L-M9.1-19（M9 原 live 运行器的证据不自描述开关配置）**：`m9-live-level1.json` / `live-long.json`
  **没有** config/flags 字段；`manifest.json` 的 `notes` 是**逐 run 完全相同的常量**
  （实测 `425c75a83465-39f5` 与 `9cc15f13f90c-4e62` 的 `notes` 逐字相同，尽管两者是 OFF/ON 两个批次）。
  ⇒ **M9.1 的 ON/OFF 归属读不出来自产物**，只能靠**调用命令行**（`pwsh-228` 显式设两个开关后连跑 3 次）
  与运行次序佐证。这是**证据可核性缺口**，不是行为缺陷。本轮**不改造 M9 运行器**（属 M9 领土，
  改动会让 M9 的门与读数重新归属）；M9.1 自有的 `m9.1:smoke:live` 已带 `instrument` 版本字段。
  ⚠️ 后续里程碑若要在 live 读数上做**配置分列**，必须让运行器把配置写进产物。
