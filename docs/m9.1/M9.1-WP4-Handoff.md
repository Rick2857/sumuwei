## 3. 实现期教训（WP5 必读，均已登记契约 §6）

1. **D16 双路径是 P08② 的语义要求**：复活把记录现值 sourceRefs 换成新告知（M4 语义）；只读现值 ⇒ 复活后旧行不再遮蔽。用户对旧行的遗忘言语行为不因重新告知被撤销——撤回时来源从旧 CREATE payload 读（ADR-072 §3.2「旧证据仍在旧事件 payload」）。
2. **事件定位必须按 id**：`indexOf` 用引用相等——两条读取路径各自解析，必然 -1（e2e 三轮实测）。
3. **断言面 = 最终 packet**：遮蔽发生在 compileTurn 内部的行副本上，不回写库；读回原始行永远是原文。同文本新旧行用**计数判据**（P08：占位后恰好剩 1 次）。
4. **候选改主体必须 `createMemoryCandidate` 重建**：spread 保留旧 `proposedId` ⇒ CREATE 折到别人记录上变 no-op。
5. **P05 场景构造**：无关信息用「与遗忘句零词面重叠」的异槽告知（就读院校）。两个坑：槽B 与槽A **同 canonical slot**（WP0 结论，撞槽 disputed）；香菜槽登记描述含「偏好」⇒ 遗忘句片段同时命中两条候选 ⇒ `target_ambiguous`（INV-M41-02 诚实歧义——系统行为正确）。
6. **F4-N1 负控改合成注入**：WP3 的 D08 让 off 档重述诚实报 `write_not_effective`——预修复「假成功」缺陷已无法经开关复现（设计内行为变化）；真实 rig 流改为新正控 F4-P3 钉 D08。
7. **P-rig 序号语义**：每次 beginTurn/appendLine 前必须 `syncSeq()`（查 `latestConversationSequence`）；rig 不走 completeTurn ⇒ 无 assistant 事件 ⇒ 分配用 +1（+2 会 gap）。`assertSequenceContiguous` 的幂等命中会**返回既有事件**（不是报错）。
8. **rollup 读数在 compile 步属性里**（DR-9 不加独立 step kind）：断言用 `rollup_rejected_invalidated` 属性；被撤行要落窗口**之前** reader 才扫得到（P04 先写 20 条填充行）。
