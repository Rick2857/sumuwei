# 显式记忆操作（Remember / Correct / Forget）

> **这份文件回答**：用户说"记住 / 改一下 / 忘掉"时，系统**具体**做了什么？
> 为什么这条路径必须**同步**、必须在生成回复**之前**完成？

- **相关 ADR**：ADR-024（显式记忆走独立同步路径）、ADR-023（supersede 而非覆盖）
- **不变量**：MI-06、MI-07、MI-08
- **守它的测试**：`m4:verify` §13、`m4:test`「显式意图检测（规则优先）」「生产装配接线（回归锁）」、`m4:restore` §7、真库实测

---

## 1. 一句话

> 显式路径是**用户授权的一次状态变更**，因此它必须**可靠**：
> 要么真的改了，要么如实说没改 —— **不能回答"记住了"而其实没记**。

计划书第 55 节的原文：

> 不能在 Memory Commit 失败时回答"记住了"。

M4 验收发现实际比那更糟：**在 Memory Commit 从未发生时，她回答了"记住了"**。
根因是两处接线缺口（服务没人调用 + 生产内核没注册 `MEMORY_*`），
修法与回归锁见 `memory-lifecycle.md` §5 与 `m4:test`「生产装配接线（回归锁）」。

---

## 2. 三个操作

```text
记住   "请记住，我最喜欢的颜色是蓝色"        → create
纠正   "我说错了，不是蓝色，是黑色"          → create 新条 + supersede 旧条
忘掉   "忘掉我喜欢咖啡这件事"                → retract
```

意图检测是**规则优先**（`intent-detector.ts`）：

```text
forget → correct → dispute → remember
```

顺序**就是**优先级，因为一句话可以同时命中多个关键词：
"不要再记这件事了"必须被读成 forget，而**不是** remember（`M4X-031` 守着）。

判定器只接受**用户**事件（`detectExplicitIntentFromEvent`）——
她自己的输出不能触发一次用户授权。

⚠️ 实测漏过一个关键词：`改一下` 不在纠正词表里，
于是计划书第 175 节的原话无法触发纠正。已补，且有断言。

## 3. 目标解析（第 57 节）：**找不到时不许猜**

`correct` / `forget` 都要先回答"用户指的是哪一条"。五步梯子：

```text
1. 显式 id          —— 找不到就停（返回 not_found，不继续往下猜）
2. canonical 槽位    —— 该槽位当前有效的记录
3. 收窄后的候选集 → 打分
4. 语义判别器（LLM） —— 只在收窄过的集合里选
5. 仍不唯一 → ambiguous
```

**这一层最容易做错的地方不是"找错了"，而是"找不到时随便挑一个"** ——
那会改错记忆，而用户不会知道。

两条断言守着：

- 显式 id 找不到时返回 `not_found`，**不继续猜**（`kernel-tests-memory.ts`）
- 一条都没打上分时返回**全部候选**（让上层报 `ambiguous`，而不是报 `not_found`）——
  报 not_found 会让用户以为记忆丢了

⚠️ 实测踩到过：解析器用 `/\d+/` 读选项，于是 `-1` 被读成"选了 #1"。
改成 `/-?\d+/`。

### 3.1 M4.1：第 3 步加了**相关性闸**（D1 的修复点）

第 3 步原本是：

```ts
if (active.length === 1) return resolved      // ← D1 就在这里
```

它把"**唯一**"当成了"**相关**"：用户说"忘掉我养过一只鹦鹉这件事"，
而库里唯一 active 是"示例工程科技大学" —— 候选数为 1 就被当成唯一命中，
于是**撤掉了那条正确的事实**。

现在：

```text
取该 subject 的 active 候选（只有一次查询）
  ↓
lexicalOverlapHits(用户那句话, 候选)      ← 相关性判定（绝对存在性）
  ↓
1 条命中 → resolved（strong）
多条命中 → 第 4 步打分 → 第 5 步闭集内模型判别 → 否则 ambiguous
0 条命中 → not_found
```

**候选数不再参与判定。**

⚠️ 一个必须记住的细节：**`scoreByHints` 不能当这个闸用**。
它在"一条都没打上分"时会**返回全部候选**（刻意的，为了让上层报 ambiguous），
于是单条无关候选在那里得到的是 `[那一条]`，"长度 1"又被读成唯一命中 ——
**那个改法修不动 D1**。

所有 destructive 操作还要过 **Mutation Gate**（`mayMutate`）：
只有 `resolved` 且置信度 ∈ {exact, strong} 才允许改动。
见 [`memory-invariants.md`](./memory-invariants.md) 的 INV-M41-01 / INV-M41-02。

## 4. 三种结果（缺一不可）

`ExplicitMemoryTurnResult`（`explicit-turn.ts`）是一个**判别联合**，
三种 `kind` 各自对应一句不同的话：

| `kind` | 含义 | 上下文里的表现 |
|---|---|---|
| `written` | 这次真的写进去了 | 告诉她"记下了" |
| `already_applied` | 幂等命中（之前就记着了） | 要说"**已经记着**"，而不是"记下了" |
| **`not_written`** | **没写成功** | **必须**让她知道没记上（计划书第 55 节） |

`not_written` 是这一整条设计的存在理由。
代码里对它的注释就是：

> `not_written` —— **没写入**，绝不能声称记住了（计划书第 55 节）

## 5. 为什么必须在**生成回复之前**完成

ADR-024 说显式路径是**同步**的（"用户在等答复"），
计划书第 55 节要求"提交失败时不能回答记住了"。两者合起来决定了：

```text
TurnGateway.beginTurn
   ├─ ① 显式记忆写入（validate → commit → fold）
   └─ ② 生成回复        ← ②必须能看见①的**结果**
```

因此有一个**轮次级端口**（`explicit-turn.ts`）把服务包起来，
并在 `compileTurn` 里把结果渲染成一条 context section。

**那条 section 是 `droppable: false` 的**（优先级 `currentInput - 1`）——
这是刻意的：被预算裁掉 = 模型失去那条事实 = 回到默认的"好，我记住了"。
**一个"只在上下文紧张时才违反"的规则不是规则。**

⚠️ 它只在**有显式指令**时出现 —— 普通对话一个字节都没变
（`pnpm m3.5:baseline:check` 逐字节守着 prompt 基线）。

### 5.1 M4.1：指令之外，还有一层**确定性的**守卫

上面那条 section 是**指令**，而指令取决于模型是否配合。实测（M4 验收）：
`content_unresolved` 时她回过「这次是 VS Code。平时主要用。」
—— 读起来像已经记下，而库里什么都没有。

因此 M4.1 加了第二层（INV-M41-03）：

```text
Memory Service → Execution Result → applyResponseTruthPolicy() → 回复
```

`response-truth.ts` 是**纯函数**：

- 只在 `result.kind === 'not_written'` 时生效
- 检测**未被否定的成功口吻**（"我没记住"不算违规 —— 判据是标记前 4 字内有
  `不/没/未/无/别`）
- 命中就整句替换为与 `reason` 对应的如实表述
- 暴露 `executed`（`undefined` / `true` / `false`）—— 执行结果可被测试直接检查

**接线位置**：`main.ts` 的 `ChatSession.send()`，
在拿到模型输出之后、**记账本与写 memories 之前**。
因此"她说过什么"（账本）、"用户看到什么"、"库里实际发生了什么"三者一致 ——
否则账本会留着那句没被说出口的话。

**代价（如实记录）**：这一种情形下她的回复由**代码**写，不由模型写。
**范围（如实记录）**：目前只在 CLI 真实链路调用；其它 transport 必须复用
**同一个纯函数** —— 策略在 kernel，不在装配层。

判据由 `m4:test`「执行真相（Response Truth / INV-M41-03）」7 条纯函数用例
离线钉死，并由 `m4:smoke:live` 在真实多轮上逐轮断言"库没变 ⟹ 回复不含成功口吻"。

## 6. 诊断入口（全部离线，不连库）

```bash
tsx scripts/diag-m4-explicit.ts "记住，我现在上的大学是示例工程科技大学"
```

它分别打印：意图判定、内容抽取、目标解析**各自**是否成功 ——
因为"她没记住"可能是其中任一步。

真库排查：

```bash
pnpm memory:replay            # 重跑折叠，验证 A == B（只读）
pnpm memory:list / stats / audit
```

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 意图检测是**规则** | 规则漏词就会漏触发（`改一下` 就是这么漏的）；补词要连同原话一起补进测试 |
| 语义判别器需要模型 | 只在第 4 步用，且只在**收窄过的**候选集里打分 |
| `not_written` 的可见性依赖 context | 那条 section 不可裁剪，但**模型仍可能不照做** —— 这是 prompt 层能做的上限 |
