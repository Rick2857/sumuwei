## 2. 程序链（六步，逐条有读数）

| 步 | 内容 | 门 |
|---|---|---|
| ① | **有界输入**：本轮原话 + 程序给定的候选（id/状态/优先级/有界描述/revision）+ 来源资格读数 | `F4` |
| ② | **provider 调用**：硬期限 **8000ms**、**零隐式重试** | `D2` |
| ③ | **严格结构校验**：12 条具名拒绝原因 | `C1`–`C13` |
| ④ | **来源资格**：非 ESTABLISHED ⇒ 不调用 provider，结论 `source_unusable` | `D3` |
| ⑤ | **span 是原话范围**：切片由程序从原话取，草案**不携带任何文本** | `B4` · `F2` |
| ⑥ | **映射**：草案 → 程序侧提案 → `validateGoalProposal` | `E1`–`E6` |

### 2.1 五态结论（**不合并**）

```text
understood       拿到合法草案（草案本身可能是 none / query / clarify —— 那也是结论）
invalid          模型给了东西但结构不合法        —— **不是** none
transport        超时 / provider 抛错            —— **不是** none，也**不是** invalid
source_unusable  来源不是本轮合格用户话语（且**不调用** provider）
not_invoked      本轮没有可理解的内容
```

门 `D1`–`D5` 把四态分别触发一次。"非法输出记 `none`"是本项目最坏的失败模式之一
（把故障读成"她没提目标"），所以这一条被单列成组。

## 3. 结构性边界（"模型不能编造程序事实"的落成）

| 边界 | 怎么做到 |
|---|---|
| 没有 `goalId` / `userId` / `sourceEventId` / `evidenceId` 的位置 | 草案字段闭集里**没有**这些名字（`F1`）。目标只能从**程序给的候选集**里选，选了集合外的 ⇒ `candidate_goal_not_provided`（`C7`） |
| 身份由程序算 | `create` 的草案里没有 id；映射写一个**占位**，放行口（WP3 阶段 C）用程序材料重算并重写（`E1` 实测 占位 ≠ 派生） |
| "用生成的字当原文证明"不可能 | 草案只有 `span` 坐标，**没有** `text` / `content` / `quote` 字段；切片一律由程序从原话取（`F2` · `B4`） |
| 采纳必须能定位提议（`D28`） | `character_proposed` 必须同时给 `proposedByAssistantEventId` 与 `proposalSpan`，否则 `adoption_reference_missing`（`C8`） |
| 乐观锁真的接上 | `expectedRevision` 取自**候选摘要里的程序读数**（候选由 `createGoalStateLookup` 读出）—— 门 `E4` 用"改候选 revision ⇒ payload 跟着变"证明它不是猜的 |
| 没有复核读数就不能恢复 | `resume` 的缺省复核读数是 `dropped: 1`（**刻意的失败关闭**）⇒ 放行口拒绝（`E5`）。装配层必须先把 WP2 的复核读数填进来 |

## 5. 结论

程序链在 **300 条**语料上全绿，**12 条**非法输出原因逐条可达且**记 invalid 不当 none**，

草案**不携带程序事实、也不携带文本**。
