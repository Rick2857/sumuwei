
WP10 的出口要的是"语义 / 真实链 / 人审各有结论"，而**语义结论只能来自真模型**。
本门做的是**在那之前把两件与模型无关的事做实** —— 这样真模型门那天要做的
就只剩"换一个 provider"。**任何引用本门读数来支持"语义评测通过"的说法都是错的。**

## 1. 甲 · 度量机是**已知答案**可验的（全部 140 条 test 语料）

`evals/m10/goal-metrics.ts` 是**唯一**一份算术实现（干跑与真跑共用，
因为 M10 已经在 `applyGoalRows` 上吃过一次"同一件事两份实现"的亏）。

| 检查 | 已知答案 | 实测 |
|---|---|---|
| `A1` | 语料装载：140 条 · **0 个闭集外标签** | 140 · 0 |
| `A2` | **预测 = 金标** ⇒ 准确率与 macro-F1 **恰好** 1 | `accuracy=1 · macroF1=1`（9 类） |
| `A3` | **全猜多数类** ⇒ 恰好等于多数类基线，且 **< 1** | 多数类 = `clarify`(45) · `0.3214285714…` |
| `A3b` | **全猜 `none`** ⇒ 恰好 = `none` 的 support 占比 | `0.2857142857…` |
| `A5` | 把每个 `none`/`clarify` 猜成 `create` ⇒ `falseCreate` 恰好 = 它们条数 | **85** |
| `A6` | 全猜 `report_complete` ⇒ `falseFulfill` 恰好 = 非它的条数 | **132** |
| `A7` | 六层 `total` 之和 = 总条数 | 140 = 140 · 6 层 |
| `A8` | `measured_count > 0` 自检 | 140 条 · 9 个类非零 |

### 1.1 `A2` 与 `A3` 是**成对**的

`A2`（1.0）单独看没有意义 —— 一个"永远返回满分"的算术也能通过它。
`A3` 把"全猜多数类"的读数钉在**恰好** `0.3214…` 上，两条一起才排除
"算术恒等于 1"这种最蠢的错法。

### 1.2 抓到的量具缺陷：`A3` 第一版的**前提写死了**

第一版断言的是"**全猜 `none`** ⇒ 准确率 === 多数类基线"。它跑出
`accuracy=0.2857` 而 `baseline=0.3214` ⇒ 红。

**算术没错，检查的前提错了**：`none` 不是 test 分片的多数类（`clarify` 45 条才是），
两个是**不同**的量。⇒ 教训：

```text
基线是"**多数类**"的性质，不是"**某个具体类**"的性质。
把某个类写死进检查，等于把**语料的分层设计**当成了算术的一部分 ——
换一版语料，这条检查就会以"算术错了"的样子红掉。
```

⇒ 现在**先算出**多数类再断言；并把"全猜 `none`"单列成 `A3b`（第二个已知答案点，
恰好 = `none` 的 support 占比）。

干跑只能驱动"有明确操作"的那些金标。这恰好说明真模型门**必须**存在：
能否判出 `none`/`clarify` 是**语义能力**，句法层的 provider 替代不了。
