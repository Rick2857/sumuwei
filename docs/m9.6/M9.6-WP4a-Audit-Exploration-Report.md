## 4. 本轮的**量具缺陷**（必须显式登记，否则会把量具问题记成模型问题）

`derivedRelation` 这一列是本轮自加的**次要**指标，它有**混杂**：

```text
aud-dev-0006  ev=pet.cat.name = 团子  回复=你养了一只叫团子的橘猫。
  链抽出 2 条：①你养了一只叫团子的猫（有据）②你的猫是橘猫（证据里**没有**颜色）
  ⇒ 链判 insufficient —— **判对了**：第二条确实无据。
  但本列把"对全部抽出断言的总判断"与"单条固定金标主张的关系"相比 ⇒ 记成"错"。
aud-dev-0007 同理（抽出"大概二十分钟"，证据只有 commute.mode）。
```

⇒ **这一列不是判据**：它把"链正确识别出的**额外**无据主张"记成了错误。
计划 §6.3 要求的第二层指标是**提取覆盖 / 漏主张 / 端到端关键错误**（上表前三行），
那三项没有这个问题。本列的读数**只作参考**，**不得**写进任何门。

## 6. 结论与它**不**主张什么

**结论（dev/val 探索性）**：
```text
· 修复后的审计链本身是一个**可用**的基线：提取覆盖 100%、假阳性 0、伪造检出正确。
· Jev 在"主张—证据关系"上与同题 LLM **基本打平**（dev 同为 0.9667；val 0.95 vs 1.00），
  唯一系统性缺口是"泛推断 vs 不是断言"这条边界。
· Jev 作为"判支持"的**增量方**（组合方案）在本轮**没测到收益**，且在一例上把正确答案改错。
· 延迟上 Jev 比同题 LLM 快约 **4.6 倍**。
```

**不主张**：
- **不**主张 Jev 通过了或没通过任何门 —— **G8 的正式条件是 test 最差 run 的三轮读数**，本轮没跑 test。
- **不**主张"值得进入正式独立验证"（计划 §6.3 的门槛要 test 最差 run 关系准确率 ≥90% 等），
  本轮只给 dev/val 探索读数。
- **不**主张组合方案要保留 —— 计划明令组合方案必须单独登记，其成绩**不得**归功于 Jev 单次调用。
- **不**主张 `derivedRelation` 那一列有效（见 §4；且 §3 已用**同码两轮**的读数实证它跨运行不稳定）。
- **不**主张人审充分：仍然是"用户抽查 + 其余信任"。
