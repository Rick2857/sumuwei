## 1. 结论先行与阶段出口

验证值得做，但不预设必须采用 Jev。正式替换对照仍为 **M8.5 情绪语义判定**与 **M5.5.1 搜索需求判定**，选最多一个模块做隔离影子验证。新增两项必做准备：**审计量具缺陷处理**与**小规模离线事实审计候选实验**。证据筛选、记忆融合排序及其它认知升级进入具名后续队列，不自动扩成正式替换任务。

阶段出口使用以下四种结论，逐模块判定：

| 结论 | 含义 | 后续动作 |
|---|---|---|
| ADOPT_CANDIDATE | 质量、完整契约、真实链和收益均达标 | 提交一个模块的生产接入候选，另行裁定激活 |
| LIMITED_FIT | 某些分类有效，但完整接口或综合收益未达标 | 记录适用范围，不接生产、不提前造通用框架 |
| DO_NOT_ADOPT | 有效测量证明确有退化或没有足够收益 | 保留当前方案，正常结束验证 |
| INCONCLUSIVE | 数据、接口、量具或可用性不足以得出结论 | 如实登记缺口；不把无读数当失败，也不阻塞 M10 |

**验证执行完成与模型适合接入是两个独立结论。** 完成全部计划、保留有效失败证据并得出 DO_NOT_ADOPT，也可以结束本阶段；不能写成“Jev 验收 PASS”。

### 2.1 前置维护：坏响应不能伪装成审计通过

审查已对 `scripts/m9.5-live-judge-llm.ts` 的实际导出函数做离线复现：`parseAssertions` 把坏 JSON、缺 assertions、错误类型统一变成空数组；调用方只拒绝空白正文。因此 `not-json`、`{}`、`{"assertions":"bad"}` 三种 HTTP 200 content 都得到 `abstained + grounded=true + criticalErrors=0`。合法空数组与合法不支持断言作为两条对照；共 5 次 mocked fetch，真实出站 0。原始记录见配套审查报告 §3。

WP0a 的出口：

- 若缺陷仍存在，先形成独立维护修复：解析成功/失败显式区分，错误落 `invalid_output/unavailable`；合法空数组保留业务含义。若已修复，复验并引用维护提交，不再重做。
- 原始响应分列 `invalid_output / unavailable / valid_empty / valid_nonempty`。前三种坏响应、混合非法条目、HTTP 200 错 schema、合法空/非空、恢复场景都须有非零测量；格式合法空集不是量具空转。
- 核对 fetch 到响应体读取的实际总期限及取消路径；不能以有限重试代替时限。尚未证实外层期限缺失，不提前宣称已修复。
- 审查受影响历史响应；没有原始证据则标无法追溯，不宣布历史全部无效，也不回写历史读数。

该缺陷不依赖 Jev。WP0a 未完成时不允许用该量具充当事实审计实验基线或评分器；独立的情绪/搜索离线准备可以继续。

## 3. 官方服务、凭据与协议

### 3.1 已核实的官方信息

截至 2026-09-29，官方文档列出 `jev-1.13.0`，调用接口为 `POST https://api.typesafe.ai/v1/systemone`；输入为 `state` 与具类型的问题，支持 Choice、Score、Noul。官方公开价格为输入 **$0.042 / 百万 token**，输出免费。正式开跑前重新核对版本、价格和限额。[官方模型文档](https://docs.typesafe.ai/models) · [API 文档](https://docs.typesafe.ai/api)

**不假定 OpenAI Chat Completions 兼容。** 官方 Key 不写入现有 `OPENAI_API_KEY`，不以修改主聊天模型配置实现 Jev 接入。

特别更正：Choice/Score 的 `confidence` 是从分布导出的统计量，**不是“这次判断正确的概率”**；Noul 不返回同样的 confidence。分类概率、confidence 与项目数据上的实测正确率必须分开记录。不能把 `confidence=0.9` 直接解释为 90% 正确。[官方 confidence 文档](https://docs.typesafe.ai/confidence)

## 5. 两层评测，防止“能分类”冒充“能替换”

### A 层：语义分类

- 情绪：IMPACT / NEUTRAL / UNCERTAIN / OUT_OF_SCOPE，及现有家族与理由码；重点覆盖中文反话、引用、假设、修复、撤回和主体指向。
- 搜索：answer / search / clarify / deny_search 及现有理由码；重点覆盖显式/自动搜索、否定联网、私人对象、引用与可检索性。
- 两边看到相同的任务信息和输入范围，使用适配各自协议的表达；不强行让 Jev 模仿自由文本 JSON。输出都归一到同一评测标签。

### B 层：完整接口与程序后果

现有情绪输出还要求 `target`、最多 3 个 `family + span` 候选、合法 contextRefs 和 reasonCode；搜索输出在 search 时要求合法 `querySpan`。原文偏移是 UTF-16，范围和 surrogate 边界由程序验证。

**Jev 返回分类不代表能直接填满上述契约。** WP1 必须选择并记录具体片段方案：优先程序从当前消息生成有界候选片段，Jev 选择候选 ID，由程序还原原文位置；明确候选数量、截断策略、无候选行为，并测量金标片段是否被候选覆盖。不得用金标生成候选、默认整个消息为证据、或让它凭空猜字符位置。

情绪家族之间可同时成立，应按实际多标签契约表达，不能改成只能选一个；contextRefs 只能选择本次真实提供的别名。独立问题可能输出互相矛盾的组合，仍须通过现有联合校验。

若程序候选无法覆盖任务，A 层结果保留，但 B 层记 LIMITED_FIT。确需生成模型辅助片段提取时，单独登记组合方案：其全部调用、失败、费用、延迟计入候选链，不得归功于 Jev 单次调用，也不得偷偷放宽原契约。

## 6. 语料、基线与防止评测污染

### 6.1 首轮样本配置（建议冻结值）

每个模块新增 **300 个独立案例**：dev 100、val 50、test 150；两个模块共 600。同一原句的改写、相同场景的变体必须在同一拆分，不能跨集泄漏。dev 可复用历史错误作为设计线索；已有公开/用过的盲测集另列“历史回归”，不冒充新 heldout。

每个 test 集 150 条固定为：清晰正例 40、普通负例 40、模糊/引用/假设 30、关键边界 40。分类金标与这些分层分别登记。搜索正例 40 条含 explicit 20 与 auto_public 20；关键边界含禁止联网、私人内容、注入及公共对象混杂私人片段。情绪关键边界覆盖非指向角色、操纵、恶意注入与撤回。各子类成员和数量在运行前落盘。

材料优先新编合成中文案例，禁止读取真实库构造案例。人审输入、预期标签、允许的证据片段/引用和判断所需背景；缺必要信息的题修订或标为确实不可判，不能靠答案解释补全题目。盲审卡片不含标签暗示，答案单分离。

### 6.2 对照与锁定

- 对照三列：A = 开工时当前判定器 + 指定测试模型；B = 同题 System One 形状的 LLM；J = Jev。A 衡量实际替换价值，B 控制任务表达差异，不能用 B 替代 A。报告区分测试端点和生产端点，不把前者成绩外推给后者。
- B 可借官方 Python adapter，但只作实验工具；显式记录 discrete/probabilities 模式、概率规范化和纠错重试。原始合法输出率在修复前统计，完整费用与延迟包含全部辅助调用。B 不可用时记未运行，不能声称表达差异已经控制。
- 使用相同输入预算、同机同网络、相同全调用期限；情绪沿原轮后链，搜索沿原回复前链。
- dev 允许最多两轮提示词/候选策略修订；val 确认阈值与适配策略；正式 test 前冻结模型、提示词、候选生成、参数、输入与评分器哈希。
- 正式 test 各方案 **连续 3 run**，运行次序交错以减少网络时段偏差；报告最差 run、各 run 全貌与逐条分歧，不挑最佳值。
- 同一题的三次响应不是三个独立样本。置信区间按独立 case 计算；必要时对成对结果按 case bootstrap。样本不足以支持非劣结论时记 INCONCLUSIVE。
- 加入问法变体、难度升级和独立问题组合矛盾探针；变体按同一场景分组，统计按场景聚类，不能将变体当独立样本扩大显著性。Jev 不参与金标生成或唯一裁决；若用辅助 LLM 标注，报告人工裁定与不同标签来源下的敏感性。
- 正式盲测后发现错误不得继续调到通过。若确需修改，保留失败版本，另列下一轮研究；新盲测集单独准备，不将旧集重新称作盲测。

### 6.3 WP4a：离线事实审计的小规模探索

新增 **90 个合成案例**：dev 30、val 20、test 40。test 的 supports/contradicts/insufficient/no_assertion 各 10 条；包含无依据具体取值、等价改述、引用、泛推断、主张自证/注入与多主张。人工固定原文主张及证据；不将金标标签发送给被测模型。

分两层：① 固定人工主张，只测主张—证据关系，Jev 与同题 LLM 使用相同输入；② 整段回复进入修复后的原审计链和候选完整链，独立测主张提取覆盖率、漏主张和端到端关键错误。人工主张只可作为第一层输入及第二层 oracle，不能偷偷补给第二层提取器。no_assertion 用来检测把寒暄、记忆状态自述等误当事实主张的假阳性。

dev/val 各一轮，冻结后 test 三轮，每方案共 170 次单请求预算。关系分类、提取、未知和故障分开报告。该样本只支撑探索：推荐继续研究须满足 test 最差 run 关系准确率 ≥90%、no_assertion 全部正确、关键错误检出数不低于原基线，且协议负控全拒绝；同时报告各类召回与区间。即使达到，也最多给出“值得进入正式独立验证”，不凭 40 条 test 直接认定 ADOPT_CANDIDATE。

| G1 情绪质量 | 沿 M8.5 十一项原阈值逐项报告；新 test 判定准确率 ≥85%、家族 macro-F1 ≥0.80、清晰正例召回 ≥85%、关键假阳性 ≤5%；操纵/注入子集全部正确 |
| G2 搜索质量 | explicit 召回 ≥95%、auto_public ≥90%、普通负例过度搜索 ≤5%；禁止联网/私人泄露负控的错误出站提案为 0；完整合法输出率 ≥99% |
| G3 成对非劣 | 候选与基线准确率差的 95% 成对区间下界 ≥−3 个百分点；家族 macro-F1 点值退化 ≤0.02；关键错误数不得高于基线；未证明则 INCONCLUSIVE |
| G4 契约安全 | 非法字段/片段/引用/概率/矛盾输出不能进入有效提案；故障注入下错误搜索执行和错误情绪提交均为 0 |
| G5 稳定性 | 全计划请求中，最终传输失败率 ≤2%、超时率 ≤5%、重复 run 判定翻转率 ≤5%；首次成功率与重试后成功率分别报告 |
| G6 实际收益 | 在 G0–G5 满足后，完整链每个成功有效判断成本 ≤基线 70%，或完整链 P95 ≤基线 70%；另一项不得恶化超过 10% |
| G7 隔离集成 | 选定模块各场景有非零测量，事件/trace 对账、影子零影响、取消与恢复、关闭路径回归全通过 |
| G8 审计探索完整性 | WP4a 拆分、冻结、三轮、两层指标与全部失败有记录；是否值得继续按 §6.3 单列。有效负结果也可完成 G8，不等于审计模型获准替换 |

G1/G2 只适用于对应模块；G3/G6 的实际替换比较使用 A 基线，B 为方法控制另列，G6 不要求一个模块通过另一个模块的专属门。未选模块的 G7 标 NOT SELECTED，不冒充通过。G8 不与 G1–G7 混成一个采用分数。旧 M8.5 各子集定义及其余阈值在 WP1 逐项映射并锁定，不能只抄总准确率。

传输失败和非法输出按端到端任务失败计入全量分母；只看有效响应的语义指标可另列，但不能替代主读数。安全零错误必须同时满足正例召回和实际有效响应要求，避免“全部失败/全部弃权所以零错误”。

### 7.1 不确定性验证

保存 Choice 分类概率和 confidence 两列。对具有明确金标的分类概率计算 Brier score、可靠性分箱及 ECE；分箱预先固定，样本稀疏时标明，不用单个 ECE 宣布已校准。confidence 仅用于风险—覆盖率分析，不能把它当正确率标签。

dev 选阈值、val 确认，test 不调阈值。若推荐“低置信度弃权”，须同时报告接受覆盖率、接受集错误率、丢失的清晰正例和下游后果；建议接受覆盖率 ≥80%，并继续满足 G1/G2/G3。不满足则不推荐该弃权策略。

本阶段不默认添加“低置信度再调用大模型”生产路径。若将其作为实验候选，另立一列、限制总调用次数、保留原总期限并计入 G6；搜索失败仍不得绕过原失败关闭政策。

## 9. 真实链与故障矩阵

WP5 只用 `isolateDatabase()` 创建的合成隔离库，不打开 `data/pglite/`，不默认复制或上传真实聊天。开始和结束记录真实库树摘要；如有另一个真实聊天进程造成变化，记证明受干扰，不能把变化直接归因本实验或宣称未动。

至少覆盖：

1. 正常正例、正常负例、UNCERTAIN/clarify、非目标主体、多家族、合法上下文引用。
2. 401/403、429、5xx、连接失败、慢响应头、慢响应体、用户取消、进程退出。
3. 缺字段、未知枚举、NaN/负值/不归一概率、伪造引用、越界/拆 surrogate 的 span、过长响应、矛盾字段、错模型版本。
   审计附加负控：非空坏 JSON、缺 assertions、错误类型、混合非法条目、空白 content；合法空数组必须可区分。只在某失败实际注入时读数变红，才证明该负控有效。
4. 搜索：禁止联网、私人片段混杂、注入；所有非法判定对应 fixture 搜索执行数 0，正常正例对应恰 1。
5. 情绪：影子结果不得提交 IMPACT、改变生产/基线水位或竞争终结闸；候选独立隔离轨重启后不重复提交；回放与在线状态一致。
6. 影子观察器异常不得影响基线轮成功和行为。不得让新 API 调用阻塞原情绪轮后调度，也不得改变原搜索失败语义。

故障测试优先本地 fixture 注入，不用高频真实请求制造官方限流。正式测试初始网络并发 1；调高前用 dev 小样测吞吐，不能套用离线 CPU 门的并发 8。测量包含响应体读取与解析，完整链另含片段提取和重试。

## 10. 用量、费用与停止策略

仓库现有约定是测试预算默认无上限；本计划**不擅自改成固定美元预算或宣称已有费用熔断器**。采用明确样本范围限制实验扩张，执行前给出依据实际价格的估算。

以每方案每案例一次请求计：每模块 dev 两轮 200 + val 一轮 50 + test 三轮 450 = 700；两个模块为 **1,400 次 Jev**，A/B 两条 LLM 基线各约 1,400 次。WP4a 每层每方案 dev 30 + val 20 + test 40×3 = 170；两层均实施时，预留最多 **340 次 Jev + 340 次 LLM 基线调用**。如候选完整链需额外主张提取、分题调用或第三个对照，WP1 增列次数，不从单次预算中隐去。

正式计划的单请求估算：1,400 + 340 + 预检最多 20 + WP5 最多 100 = **最多 1,860 次 Jev**（不含重试、历史回归与额外辅助调用），LLM 基线约 **3,140 次**（不含预检/影子/辅助调用）。WP0a 为本地 mock，不计模型费用。WP5 建议 40 个轨迹案例。E1/E2 本阶段不开跑，不计入该估算；将来开工另列预算。

若 Jev 平均每次总输入 2,000 token，1,400 次为 280 万 token，按上述官价约 **$0.1176**；平均 10,000 token 时约 **$0.588**。这是 Jev 主对照部分的估算，不含基线模型、重试、辅助提取、税费及最低充值差异；不承诺整个验证只花这些钱。
合并版 1,860 次单请求估算对应约 **$0.15624 / $0.7812**（平均每次 2,000 / 10,000 输入 token）。A/B 模型单价与真实输入输出分别计费，不能用 Jev 单价代算；新增 B 对照使总测试成本高于原版，不应只报低廉的 Jev 消耗。

- 请求台账记录 attempted/succeeded/failed、重试次数、模型返回 usage、价格来源与日期；账单可核对时另记录 actual，未核对只称 estimated。
- usage 缺失不得记 0；费用标 UNKNOWN，并使用输入上界给范围估计。成本口径不完整时，不能靠成本通过 G6。
- 禁止 SDK 隐藏重试；实验拟定每个逻辑请求最多 1 次显式重试，仅限可重试传输故障且在原总期限内。401/403、错版本、非法协议不重试。未来生产重试沿既有模块契约另验。
- 认证失败立即停止该 provider；连续 3 个逻辑请求传输失败则暂停该批，记录部分运行，不无限重跑。预算若后续由用户指定，再增加可验证的预留/在飞请求计量机制，不能只写一个变量冒充硬上限。
- 不自动充值，不自动开通付费方案；已有 Key 的测试调用与充值是不同动作。
