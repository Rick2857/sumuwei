## 1. 本契约冻结什么

冻结之后，正式 test 只允许按已冻结的模型、提示词、候选生成、参数、输入与评分器运行。
变更输入面 = 变更判据，必须重开一轮（计划 §6.2）。**dev 允许最多两轮提示词/候选策略修订；val 确认阈值；test 不得调阈值。**

## 2. 官方接口事实（核实日 2026-09-29）

| 项 | 核实读数 |
|---|---|
| 端点 | `POST https://api.typesafe.ai/v1/systemone`（+ `GET /v1/models`） |
| 认证 | `Authorization: Bearer <key>`（**无** `x-api-key` 形式） |
| 请求体 | `state`（字符串/数组/对象）+ `model`（**必填**）+ `questions`（map） |
| 问题 id | **就是 map 的 key**，不是对象内字段；key 不参与推理 |
| 问题类型 | 恰好三种：`noul` · `choice` · `score` |
| `noul` | `instructions` 必填 · `criteria` 可选（`{true,false}`）· **返回 `noul` ∈ [0,1]，不带 `confidence`** |
| `choice` | `criteria` **必填**（选项 → 描述 map，**≤255 选项**，值可为 null）· 返回 `choice`（最高概率项）+ `probabilities`（和为 1）+ `confidence` |
| `score` | `criteria` **必填**（**有序**描述数组，**2–10 档**）· 返回 `score`（跨档概率加权，可落在档之间）+ `legend` + `probabilities` + `confidence` |
| 数值区间 | **没有**数值区间字段；区间只能表达为有序档位数组（位置即索引） |
| 响应体 | `{ model, answers, usage }`；`usage.input_tokens` / `usage.output_tokens`；**无 request id 字段** |
| 版本 | `jev-1.13.0` 已在文档中；别名 `jev-latest` / `jev-preview`；**用 `model` 字段固定版本 id**；响应 `model` 报告实际作答版本 |
| 价格 | **$0.042 / 百万输入 token**；**输出免费**；文档**未**载明最低充值额 |
| 限额 | 250,000 token/s · 1,200 请求/分；超限 ⇒ 429。**文档注明限额会动态调整** |
| 上下文 | 64k token/请求（`state` 32k + 最长问题）；Choice ≤255 选项；Score 2–10 档 |
| 超时 | **文档没有超时指引**，只有 429/529 的退避重试建议 |
| 错误 | 401 · 429 · 529 已确认；422 出现在检索索引副本但直取未复现 ⇒ **未确认**；错误体字段名**未文档化** |
| OpenAI 兼容 | **不存在**（无 `/v1/chat/completions`、无 `messages`）。**不得假定兼容** |

### 2.1 对执行计划的三处更正

1. **`confidence` 的适用范围比计划书写的更窄**：计划说"Choice/Score 的 `confidence` 是分布导出的统计量"，
   实测文档确认这一点，**并且 Noul 根本不返回 `confidence`**。
   ⇒ 情绪的多标签若用 Noul 实现，就**没有** confidence 列可做风险—覆盖率分析（§9 相应分列）。
2. **请求体是四个必备要素而不是两个**：计划 §3.1 只写了"`state` 与具类型的问题"，
   实测 `model` 也是必填，且 `questions` 的每个值都要求 `instructions`。
   ⇒ 漏 `model` 会直接请求失败，而不是默默用 latest。
3. **没有数值区间**：Score 只能表达为有序档位，**不能**给一个闭区间让模型回数值。
   ⇒ §6 的 family 判定不得设计成"给 0–1 区间"。

## 4. 三列对照（A / B / J）

| 列 | 是什么 | 作用 |
|---|---|---|
| **A** | 开工时**现行**判定器 + `.env.test` 测试端点 | 衡量**真实替换价值**（唯一可用于 G3/G6 的基线） |
| **B** | 同题 **System One 形状**的 LLM（现有 Chat Completions 测试端点，按 System One 的问题形状提问） | 控制**任务表达差异**；**不可**替代 A |
| **J** | Jev 官方 API | 候选 |

- 三列使用**相同输入预算、同机同网络、相同全调用期限**。
- B **不**可用/未跑 ⇒ 记 `NOT RUN`，**不得**声称"表达差异已控制"。
- 报告必须区分**测试端点**与**生产端点**，不把前者成绩外推。
- 同一题的三次响应**不是**三个独立样本：置信区间按**独立 case** 算，必要时按 case bootstrap。
- Jev **不参与**金标生成，也不作唯一裁决。

## 5. A 层：语义分类的标签归一

两边看到**相同的任务信息与输入范围**，但用各自协议的**自然表达**（不逼 Jev 模仿自由文本 JSON）。
两边的输出都归一到**同一评测标签**。

| 模块 | 归一标签（闭集） |
|---|---|
| 情绪 | `IMPACT` / `NEUTRAL` / `UNCERTAIN` / `OUT_OF_SCOPE`，**外加**现行情绪家族（多标签）与现行 `reasonCode` |
| 搜索 | `answer` / `search` / `clarify` / `deny_search`，外加现行 `reasonCode` |

**多标签不许压成单选**：情绪家族之间可同时成立。Jev 侧按 §6 用**每家族一个 Noul** 表达。

静默评测无法离线判定的部分（真模型语义）在离线门里一律 `NOT RUN`，不冒充 PASS。

## 6. B 层：完整契约与片段方案（**先于 B 层结论冻结**）

现行情绪输出还要求 `target`、最多 3 个 `family + span` 候选、合法 `contextRefs` 与 `reasonCode`；
搜索在 `search` 时要求合法 `querySpan`。**Jev 返回分类 ≠ 能填满这些契约**（计划 §5）。

### 6.1 候选生成 → Jev 选 ID → 程序还原（唯一允许的方案）

```text
① 程序从**当前消息**生成**有界**候选片段，每个候选携带自己的 [start, end)（UTF-16 偏移）
② Jev 只回答**候选 ID**（Choice 的一个选项，或 Noul 逐候选）
③ 程序按 ID 还原原文位置 ⇒ 契约要求的 span 由**程序**给出，Jev 不猜字符位置
```

**冻结参数**：

| 参数 | 冻结值 | 理由 |
|---|---|---|
| 候选上限 | **48 个**（原冻结 12；见下「修订记录」） | 与 Choice ≤255 不冲突；离线扫描显示 48 时金标覆盖 30/30 |
| 候选文本总上限 | **512 UTF-16 单元** | 配合 §2 的 32k `state` 上界 |
| 生成方式 | 按句切分（`。！？；\n`）+ **以小句/句边界为锚**、长度**由长到短**的尾窗与首窗（v2），再兜底滑窗；去重、按出现顺序编号 `C0…` | 可复现、无随机 |
| 无候选时 | 记 `no_candidate`，**不**调 Jev，**不**默认整条消息为证据 | 计划 §5 明列禁止 "默认整个消息为证据" |
| 截断策略 | 超出上限的候选**不截断文本**，而是**不纳入候选表**；被丢弃数量必须记录 | 截断会制造原文里不存在的 span |
| 偏移纪律 | 全部按 UTF-16；程序校验范围与 **surrogate 边界**；非法 span ⇒ `invalid_output` | 现行契约要求 |

**修订记录（`MAX_CANDIDATES` 12 → 48）** —— dev 第 2 轮修订，依据是**零出站**的上限扫描：

| 候选上限 | 金标覆盖（30 条正例） | 平均候选文本（UTF-16 单元） |
|---|---|---|
| 12（原冻结） | 24/30（80%） | 120.8 |
| 16 | 28/30（93%） | 148.9 |
| 24 | 28/30 | 201.0 |
| 32 | 29/30 | 257.7 |
| **48** | **30/30（100%）** | **335.9** |
| 96 | 30/30 | 361.5 |

⚠️ 提高上限**不增加调用次数**（仍是每案 1 次 Jev 请求），只增加每次请求的输入 token。
⚠️ 原有读数（cap=12）**不回写**，作为历史保留；`test` 必须使用**修订后**的值。
⚠️ 这是搜索模块用掉的**第 2 轮**（也是计划允许的**最后一轮**）dev 修订 ⇒ 之后不得再调。

**禁止**（计划 §5 逐字）：用金标生成候选、默认整条消息为证据、让 Jev 凭空猜字符位置。

### 6.2 `target` / `family` / `reasonCode` / `contextRefs` 的 Jev 表达

| 契约字段 | Jev 表达 | 归一 |
|---|---|---|
| `target` | Choice：选项 = 候选片段 id + 一个显式 `无/不确定` 选项（`criteria` 值可 null） | 选项映射回候选 span |
| 家族（多标签） | **每个家族一个 Noul**（"本条消息是否属于家族 F"） | `noul ≥ 阈值_F` ⇒ 该家族成立 |
| `reasonCode` | Choice：选项 = 现行理由码闭集 | 直接映射 |
| `contextRefs` | Choice：选项 = **本次真实提供的别名** | 只能选已提供的别名（计划 §5） |
| 搜索 `querySpan` | Choice：选项 = §6.1 候选表 | 映射回 UTF-16 span；须非空白、在界内、不拆 surrogate |

- 阈值 `阈值_F`：**dev 选、val 确认、test 前冻结并记录取值**（§7.1）。test 期不得调。
- 联合校验：独立问题可能输出**互相矛盾**的组合，仍须通过**现行联合校验器**；不通过 ⇒ `invalid_output`。
- 若程序候选**无法覆盖**任务：A 层结果保留，**B 层记 `LIMITED_FIT`**（计划 §5）。
- 若确需模型辅助片段提取：必须**单独登记组合方案**，其全部调用/失败/费用/延迟计入候选链，
  **不得归功于 Jev 单次调用**，也**不得**偷偷放宽原契约。

### 7.1 阈值与冻结程序

```text
dev   → 最多 2 轮提示词/候选策略修订；选定 阈值_F
val   → 确认阈值与适配策略（不调 dev 以外的自由度）
test  → 冻结 模型 id · 提示词 hash · 候选生成参数 · 上下文预算 · 输入 hash · 评分器 hash

        ⚠️ **不挑最佳值**；test 期发现错误不得继续调到通过
```

### 7.2 WP4a 审计语料（计划 §6.3 落地）

| 项 | 冻结值 |
|---|---|
| 规模 | **90 条**合成案例：`dev 30` / `val 20` / `test 40` |
| test 分层 | `supports` 10 · `contradicts` 10 · `insufficient` 10 · `no_assertion` 10 |
| dev / val 分层 | dev 8/8/7/7 · val 5/5/5/5 |
| 关系闭集 | `supports` / `contradicts` / `insufficient` / `no_assertion` |
| 语料文件 | `evals/m9.6/audit-corpus.ts`（+ `audit-{dev,val,test}.ts`；导入时**失败关闭**校验） |

**两层的输入面（计划 §6.3 逐字要求）**：

| 层 | 输入 | 测量 |
|---|---|---|
| ① | 人工固定**主张** + **可采信证据** | 只测**主张—证据关系**（4 类） |
| ② | 整段**回复** + 可采信证据 | 主张提取覆盖 / 漏主张 / 端到端关键错误 |

- ⚠️ **人工主张只可作为第一层输入及第二层 oracle，不能补给第二层提取器**（计划 §6.3 逐字）。
  ⇒ 第二层只吃 `reply` + `evidence`；`keyClaims` **仅用于评分**。
- ⚠️ `keyClaims` 必须是 `reply` 的**逐字连续子串**，否则"提取到了没有"无从判定。
- ⚠️ **`no_assertion` 的 `claim` 归一为该句原话本身**（不是对它的描述）——
  否则被测对象会从"这句话算不算事实主张"变成"能不能认出元描述"。
- ⚠️ **组合方案必须单独登记**：官方 API **没有自由文本输出**（只有 noul/choice/score），
  所以第二层的候选链只能是 `[修复后链提取] × [Jev 判支持]`，
  两段调用分别计数、分别计时，**不得**把组合成绩归功于 Jev 单次调用。
- ⚠️ 第二层的 `derivedRelation` **表达不出 `contradicts`**（链只给"支持/不支持"）
  ⇒ 其准确率只在**金标 ≠ contradicts** 的子集上算，避免把**表达力上限**记成模型错误。

### 8.1 门的口径纪律

- G1/G2 **只**适用于对应模块；未选模块的 G7 记 **`NOT SELECTED`**，**不冒充通过**。
- G3/G6 的实际替换比较使用 **A 基线**；B 为方法控制**另列**。G6 不要求一个模块通过另一个模块的专属门。
- **G8 不与 G1–G7 混成一个采用分数**（计划 §7 逐字）。
- 传输失败与非法输出**按端到端任务失败计入全量分母**；只看有效响应的语义指标可另列，
  **不能**替代主读数。
- 安全零错误必须**同时**满足正例召回与实际有效响应要求 —— 避免"全部失败/全部弃权所以零错误"。
- 旧 M8.5 各子集定义及其余阈值在 WP1 逐项映射并锁定，**不能只抄总准确率**。

## 9. 不确定性与风险—覆盖率（分列）

- 保存 **Choice/Score 的分类概率**与 **confidence** 两列；**Noul 无 confidence**（§2.1）⇒ 该列缺失，
  **不得填 0 或填 1**。
- 对**有明确金标**的分类概率计算 **Brier score · 可靠性分箱 · ECE**；分箱**预先固定**；
  样本稀疏时标明；**不用单个 ECE** 宣布已校准。
- `confidence` **只**用于风险—覆盖率分析，**不能**当正确率标签。
- 若推荐"低置信度弃权"：同时报告接受覆盖率 · 接受集错误率 · 丢失的清晰正例 · 下游后果；
  建议接受覆盖率 **≥80%** 且继续满足 G1/G2/G3。不满足 ⇒ **不推荐**该策略。
- 本阶段**不默认**添加"低置信度再调用大模型"的生产路径；若作为实验候选，另立一列、
  限制总调用次数、保留原总期限并计入 G6。搜索失败**仍不得**绕过原失败关闭政策。

## 10. 故障矩阵（WP2/WP5 必须逐个有非零测量）

1. 正常正例 · 正常负例 · UNCERTAIN/clarify · 非目标主体 · 多家族 · 合法上下文引用。
2. `401`/`403` · `429` · `5xx` · 连接失败 · 慢响应头 · 慢响应体 · 用户取消 · 进程退出。
3. 缺字段 · 未知枚举 · `NaN`/负值/不归一概率 · 伪造引用 · 越界或拆 surrogate 的 span ·
   过长响应 · 矛盾字段 · **错模型版本**（响应 `model` ≠ 请求 `model` ⇒ 停止该批）。
4. 搜索：禁止联网 · 私人片段混杂 · 注入；所有非法判定对应 fixture 搜索执行数 **0**，正常正例 **恰 1**。
5. 情绪：影子结果**不得**提交 IMPACT、改变生产/基线水位或竞争终结闸；候选独立隔离轨**重启后不重复提交**；
   回放与在线状态一致。
6. 影子观察器异常**不得**影响基线轮成功与行为；新 API 调用**不得**阻塞原情绪轮后调度，
   也**不得**改变原搜索失败语义。

- 故障测试**优先本地 fixture 注入**，**不用**高频真实请求制造官方限流。
- 正式测试**初始网络并发 1**；调高前用 dev 小样测吞吐。**不得**套用离线 CPU 门的并发 8。
- 测量**包含**响应体读取与解析；完整链**另含**片段提取与重试。

## 11. 用量、费用与停止策略

| 项 | 次数 |
|---|---|
| 情绪：dev 100×2 + val 50×1 + test 150×3 | 700 |
| 搜索：同上 | 700 |
| **Jev 小计** | **1,400** |

| WP3 预检 | 最多 20 |
| WP5 影子（建议 40 轨迹案例） | 最多 100 |
| **Jev 总上界** | **最多 1,860**（不含重试/历史回归/辅助调用） |

- 本阶段**不擅自**改成固定美元预算，也**不宣称**已有费用熔断器；用**样本范围**限制实验扩张。
- 台账记录 `attempted`/`succeeded`/`failed` · 重试次数 · 模型返回 usage · 价格来源与日期；
  账单可核对时另记 `actual`，未核对只称 `estimated`。
- **usage 缺失不得记 0**：费用标 `UNKNOWN`，并用输入上界给范围估计。成本口径不完整时**不能**靠成本通过 G6。
- **禁止 SDK 隐藏重试**；每个逻辑请求最多 **1 次显式重试**，仅限可重试传输故障且在原总期限内。
  `401/403` · 错版本 · 非法协议**不重试**。
- 认证失败**立即停止**该 provider；连续 **3** 个逻辑请求传输失败则暂停该批，记录**部分运行**，不无限重跑。
- **不自动充值**，**不自动开通**付费方案。已有 Key 的测试调用与充值是**不同动作**。

## 14. 本契约不主张什么

- 不主张 Jev 会被采用；**得到可信、可复核的采用决定**才是本阶段成功标准。
- 不主张现行判定器有缺陷（除 WP0a 已修的那一处**量具**缺陷，且已如实登记影响面 `UNTRACEABLE`）。
- 不主张概率/confidence 等于正确率。
- 不主张 A/B/J 三列成绩可外推到**生产**端点。
- 不新增任何用户可见能力（计划 §4：新增用户能力 = **NONE**）；本阶段无 Database Migration。
