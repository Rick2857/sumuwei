> 2026-09-29 · 范围：代码静态审查、公开项目检索、一个本地离线故障复现。  
> 工作基线：`e80df70e462cb1851cf086651d7562a77f6c27f8`；M9.5 有其它会话在途写入，本文不是整仓发布审计。  
> 本轮未调用 Jev 或其它付费模型、未安装依赖、未打开真实库、未修改生产代码。  
> 与 [M9.6 执行计划](M9.6-Jev-Suitability-Execution-Plan.md) 配套；以下新增方向是建议，不自动扩大其两模块正式实验范围。

## 1. 审查结论

原计划覆盖情绪和搜索判定是合理起点，但还漏掉三个较有价值的方向：

1. **离线语义审计量具**：将固定主张与证据之间的关系做成闭集判断；先修复当前坏响应被当作干净结果的缺陷，再比较 Jev。
2. **外部搜索证据筛选**：已有预算选择按原顺序装入，可实验先按对问题的帮助程度排序，再沿原编译与引用链处理。
3. **语义召回的第二排序信号**：保留本地召回，以 Jev 补充候选排序；不能直接取代向量编码、记忆资格和遗忘过滤，而且引入私人记忆出站需要独立裁定。

关系和信念也有语义覆盖提升空间，但现有部分是确定性规则，替换它们是认知行为升级，不是节省模型费用。优先级低于已有模型调用的对照实验。

**可复用价值主要来自评测与接口设计，不是“安装一个 Jev 项目就替换我们的组件”。** 当前库已有严格的来源、事件、政策和回放边界；应在基础设施或实验层使用新组件，保留领域层纯函数。

## 3. 必须先修的评测缺陷（P1）

### 3.1 非空坏响应被视为“没有断言、回答有依据”

位置：[`parseAssertions` 第 65 行及其调用方第 122–137 行](../../scripts/m9.5-live-judge-llm.ts)。

根因链：parseAssertions 对解析失败、缺 assertions、类型错误都返回 `[]`；调用方只用 `raw.trim() === ''` 检查失败。非空坏响应因此进入正常分支，得到 `kind='abstained'`、`grounded=true` 和零 criticalErrors。注释声称的失败关闭没有覆盖该分支。

离线验证直接读取该 TypeScript 文件，用仓库已安装的 TypeScript 编译到内存模块后调用真实导出 `judgeWithModel`。全局 fetch 替换为本地 Response，环境中只有 dummy key 和 `offline.invalid`，没有真实网络与数据库访问。输入固定为问题“我在做什么项目？”、回复“毕业设计。”、证据空集。

| 模拟模型 content | 实际 kind | grounded | criticalErrors |
|---|---|---|---|
| `not-json` | abstained | true | 0 |
| `{}` | abstained | true | 0 |
| `{"assertions":"bad"}` | abstained | true | 0 |
| `{"assertions":[]}` | abstained | true | 0 |
| `{"assertions":[{"text":"毕业设计","supported":false}]}` | answered | false | 1 |

总计 5 次 mocked fetch，真实出站 0。前三条证实协议失败伪装成功；第四条是合法空列表对照，不能将它与解析失败混为一类。第五条证明非空负控能触发原判据。

建议维护修复：解析返回显式 success/error，错误映射 `unavailable/invalid_output`；合法空数组保留业务语义。补 malformed JSON、missing/wrong-type assertions、混合非法条目、HTTP 200 错 schema 的正负恢复测试。另核对实际调用期限：本函数 fetch 调用中未提供 AbortSignal，需由执行维护线验证外层是否有总期限，不能把重试次数当时限。

此问题独立于 Jev。**不能据此宣布历史结果全部无效**：尚未检查历史 run 是否实际收到坏响应。正确动作是先修量具，再检查受影响原始响应；无法追溯的读数标明证据限制。本轮未修代码或回写历史证据。

## 4. GitHub 搜索方法与范围

Exa 分官方工具、检索/证据、社区评测三个方向发现候选，加一轮定向补查，共 4 次有效请求、32 条候选结果配额（有重复）；另一次初始请求因缺 objective 参数失败，没有搜索结果。目录站只作线索，不作为能力证明。

随后直接使用 GitHub Search API 查询 `jev typesafe in:name,description,readme`、`jev rerank in:name,description`、`jev calibration in:name,description`（各取前 10 项）。第一条结果噪声很大，不能把搜索总数当 Jev 生态规模。最终核对 9 个仓库的 README、API 元数据与许可证标识；其中 5 个读取固定提交的关键源文件，另 1 个检查固定提交的基准目录树。没有执行外部安装脚本或仓库代码。

## 5. 哪些外部结果真正影响我们的选择

### 5.1 Jev 作为第二信号优于“先假定它取代 embedding”

`jev-search-rerank-eval` 作者报告，在技能目录语料的独立 LLM 标签下，Jev 单独重排相对 bge-m3 的 NDCG@10 差为 −0.028，而融合方案为 +0.064。它还展示同一排序器用 Jev 自己的标签评分时优势会放大。这是**该仓库作者读数**，未经本轮复跑；不代表本地 E5 或我们的记忆集会出现同样收益。[原始说明与结果](https://github.com/zhuyansen/jev-search-rerank-eval)

建议本项目检索实验固定同一合格候选池，比较：现有排序 / Jev 独排 / 原排序与 Jev 的融合。先测 Recall@K 判断是否根本没召回；没进候选的记录不能靠 rerank 找回来。按 query 配对统计 NDCG/MRR，同时测精确槽位、更新记录、更正/遗忘与主体混淆，不仅看平均相关性。

### 5.2 记忆重排会改变出站边界

[ADR-074](../adr/ADR-074-m9.5-semantic-memory-recall.md) 明确当前本地推理与不临时转云的约定。云端 rerank 同样要上传候选正文，即使仍保留本地 embedding，也已经增加私人记忆接收方。

因此先用合成语料验证，不能拿本次“搜索 GitHub、做审查”的授权上传真实记忆。未来正式设计至少要求：出站前来源/主体/状态/遗忘检查、最小文本集、超时回退原策略、编译前再次读取最新资格。后一次检查防止在飞请求期间发生遗忘后把旧结果装回上下文，但不能撤回已经上传的文本；必须如实说明这一时间边界。

### 5.3 外部证据筛选可能比私人记忆重排更容易试

当前 `selectExternalEvidenceContext` 顺序遍历证据并检查预算，没有问题相关性输入。可以用合成查询与公开片段实验“先排序、再预算选择”，优先保留能支持回答的片段，允许保留只提供部分证据的片段。

新增过滤器不能改变“来源附录按实际入模集合由程序生成”的规则，也不能把相关性当真实性、权威性或逐句支持证明。第一轮不做新搜索，复用固定测试片段，单独测延迟是否抵消收益。

## 6. 对 M9.6 计划的建议补充（尚未执行）

**不把九个项目都变成依赖，也不把全部历史模块塞入一次实验。** 建议按以下顺序：

1. **立即维护量具**：处理 §3 的解析失败漏洞，作为独立修复出证据；不等 Jev。
2. **原 M9.6 范围内改进方法**：优先评估官方 TS SDK；借鉴 jev-mcp 的有界候选选择、zod-jev 的失败分类；增加问法变体和组合输出矛盾负控。保留现有情绪/搜索两模块。
3. **增加一项小型审计候选研究**：使用固定人工主张与可采信证据比较 Jev 和原审计模型。主张提取覆盖率单列，不能把漏掉断言算零违规；初始只离线审计，不加聊天后置阻断。
4. **第二波选一个证据/排序实验**：优先公开外部证据筛选；私人记忆融合重排待独立出站与语义设计裁定。
5. **以后再考虑 M7/M9 语义升级**：目标是覆盖率，不是节流费用；保留原确定性计数、资格与生命周期。

对照至少保留两条基线：A = 我们现在实际使用的判定器；B = 同题 System One 形状的 LLM 对照（可借官方 Python adapter）。B 用于控制题目表达差异，A 用于判断真实替换收益。adapter 的概率规范化和纠错重试要显示，不能修好坏输出后声称原始合法输出率更高。

增加原始响应状态 `invalid_output / unavailable / valid_empty / valid_nonempty` 四分列；格式正确只是先决条件。既有量具中的“0 项”需区分合法业务空集和未成功测量。
