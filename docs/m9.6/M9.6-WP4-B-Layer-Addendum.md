# M9.6 WP4 附录 —— B 层（片段）从 `LIMITED_FIT` 变为**已解决**，以及基线自身的噪声

> 日期：2026-09-29 · 上游：[`M9.6-WP4-Pilot-Report.md`](M9.6-WP4-Pilot-Report.md)（cap=12 的读数**不回写**）

> ⚠️ 仍然**只跑 dev**（搜索模块的 val/test 未跑）⇒ 下述质量结论**不构成 G1–G3 判定**。

## 1. 起因

试点报告把 B 层（`querySpan`）判为 `LIMITED_FIT`，理由是"候选覆盖只有 0.80，未覆盖的 6 条
**结构性不可能**命中"。当时把出路写成两条：**接受 LIMITED_FIT**，或**另立多调用打分组合方案**。

两条都问错了 —— 因为**官方 API 没有自由文本输出**，多调用也换不来"表外"的区间；
而"表内覆盖"本身是**可以调的上限**，不是能力上限。

## 2. 零出站的上限扫描（把取舍变成曲线）

```text
上限   覆盖        平均候选文本(UTF-16 单元)
  12   24/30 (80%)      120.8
  16   28/30 (93%)      148.9
  24   28/30            201.0
  32   29/30            257.7
  48   30/30 (100%)     335.9   ← 本轮采用
  96   30/30            361.5
```

⇒ **上限 48 即达 100% 覆盖**，代价是每次请求多约 215 个单元的候选文本，
**调用次数不变**（仍是每案 1 次）。按官方单价估算，全量 1,400 次约多 **$0.013**。

**结论**：
1. ✅ **片段层不再是 `LIMITED_FIT`** —— 它是**参数问题**，一个上限修订就修好了，
   而且**不需要多一次调用**。
2. ✅ 覆盖满之后，**J 的片段精确率超过基线**（**22/30 vs 17/30**）——
   即：有选项时，官方 API 选片段选得**比现行判定器更准**。
   （这与试点报告的"覆盖子集内 J 17/24 优于 A 14/24"方向一致，现在在全量 30 条上成立。）
3. ⚠️ 判定质量的点估计从 −0.05 收到 **−0.03**，但区间仍跨 0。

## 4. ★ 一个改变解释方式的发现：**基线自己**在同样的输入上会翻转

`cap` 只影响 J 的**片段**问题，**完全不影响 A**（A 的输入只有用户原话）。
但 A 的判定准确率在两轮之间从 **0.79 变成 0.77**。逐条比对（输入逐字相同）：

```text
A 的判定在两轮里翻转 4/100（sn-dev-0002 / 0053 / 0060 / 0097）
  · 正确→错：0002（search→clarify）· 0053（answer→clarify）· 0060（clarify→answer）
  · 错→正确：0097（search→clarify）
J 的判定在两轮里翻转 **0/100**
```

**含义**：
- **A 的自身噪声（4% 翻转 / ±2 个百分点的准确率）大于 A 与 J 之间测到的差（2–5 个百分点）**
  ⇒ 单轮 dev 上的点值差**不可区分**。这从**测量**上（而不是从口径上）**证实了 `INCONCLUSIVE`**。
- **官方 API 在 temperature 0 下是确定的**（0/100），**而现行判定器不是**（4/100）。
  这条性质本身对"可复现的验收"有价值 —— 它也是计划要求 **test 三轮取最差**的直接理由。
- 与 G5 的关系：翻转率 A = 4%（门槛 ≤5%，**擦边通过**）· J = 0%。

## 5. 修订后的判定

| 维度 | 修订前 | **修订后** |
|---|---|---|
| 片段 / B 层 | `LIMITED_FIT`（覆盖 0.80） | ✅ **已解决**（覆盖 30/30）· J 的 span 精确率反超基线 |
| 判定质量 | `INCONCLUSIVE` | `INCONCLUSIVE`，但**现在有实测的噪声下限**作依据（基线自身 ±2pt） |
| 收益 | 仅延迟臂 | 同前（成本臂仍 `NOT RUN`：A 列未记 usage） |
| 过度搜索 | 5.71% 两侧都超 5% | cap48 轮：A 4.29% / J 5.71% ⇒ **基线过线、J 仍在线上**；仍未裁定（6 条边界用例） |

## 6. 本附录**不**主张什么

- **不**主张片段问题在 val/test 上也会是 100% —— 覆盖曲线是**在 dev 语料上**量的；
  val/test 的金标片段分布可能不同（**test 必须使用上限 48**，且覆盖率必须随 span 指标一起报）。
- **不**主张 J 的判定质量已非劣（区间仍跨 0，且只有 dev）。
- **不**主张 A 的 4% 翻转率是生产端点的性质 —— A 走的是 `.env.test` 的**测试端点**；
  生产端点未测（契约 §4 明令不得外推）。
- **不**主张这一轮修订可以再来一次 —— 搜索模块的**两轮 dev 额度已用尽**（v1→v2 策略、12→48 上限）。
