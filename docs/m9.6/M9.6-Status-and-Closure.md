## 3. 本轮真正做成的事

### 3.1 WP0a：修好了一个会**双向**误导审计结论的量具缺陷

`scripts/m9.5-live-judge-llm.ts`（`@1`）把四种解析失败一律变成空数组，而调用方只拒绝空白正文
⇒ 非空坏响应被读成"没有断言、回答有依据"（`abstained` + `grounded=true` + 0 关键错误）。
它是 `pnpm m9.5:smoke:live` 的**主判分器**（`groundedRate` 的来源）。

`@2` 的修复要点：解析显式二分 · 17 码白名单闭集（含 `@1` 从未检查的 HTTP 信封层）·
合法空数组保留业务含义 · 四态分列 · **补齐缺失的总期限与取消路径**（`@1` 完全没有）。
提示词、7 条控制、判据语义一字未改。

**负控实测推翻了初始假设**：`@1` 不只"放过"，还会"冤枉" ——
8 类输入得到**假通过**，另有 1 类（缺 `supported` 被静默当成 `false`）得到**对产品的假指控**。
两个方向都由门钉住。

**历史影响面 = `UNTRACEABLE`**：全仓无任何证据引用该判定器；受影响门的 transcript 在
gitignored 目录且已不存在。而 `m9.5:gates` 显示该门 `requiredNow: false` ⇒
**没有污染任何 M9.5 必选门判定**。未回写任何历史读数、未移动任何标签。

### 3.2 WP2：量具自己有牙，且"零"与"满分"不再混淆

- **分母纪律**：分母为 0 ⇒ `NOT RUN`（`value === null`），不是 0%。空集准确率、
  空 ECE、空 bootstrap、`wilson(0,0)` 全部返回 NOT RUN/null。
- **合法业务空集 ≠ 测量空转**：格式合法的空预测计入 `measured`；解析失败不计入。
- **主读数分母**：传输失败与非法输出按端到端失败计入全量分母；只看有效响应的**另列**，
  且用 `outputValidRate` 把"全部失败 ⇒ 零错误"这种自欺显式化。
- **伪通过负控（三段式）**：三个错公式被**重新实现一遍**并断言各自给出**不同的**数 ——
  剔除失败会把准确率抬到 0.778（真值 0.70）· 把非法输出当格式合法会把完成率抬到 0.97（真值 0.90）·
  把无定义标签按 0 计入会把宏平均压到 0.5（真值 1.0）。恢复后三个数都回到正确值。
- **校准负控不空转**：分箱计数**故意不等**（3 与 1），否则"按箱加权"与"各箱等权"会同值、
  负控就会空转通过。

### 3.3 WP3：真实预检发现的两件事

1. **我方实现错，不是服务端错**：`Score.legend` 官方返回的是**对象** `{"0": …}`，
   而我最初按有序数组实现 ⇒ 每一次 Score 调用都会被误判 `legend_mismatch`。
   预检为此做了一次原始抓取，归一化已按实测形状修正，并补了"legend 是数组即协议违规"的负控。
   **这条发现本身就是预检存在的理由。**
2. **真实超时不是偶发**：被取代的一次运行里，5 次延迟采样有 1 次撞到 20s 共享总期限
   （与 `L-M55-12` 同型）。归档 run 恰好 8/8 成功、0 超时 —— **两个读数分列，不合并**；
   样本太小，**不足以**判定 G5 的 ≤5%。
