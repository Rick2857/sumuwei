| `L-M96-07` | **候选覆盖曾是 0.80**（未覆盖的 6 条是"动词后中段宾语"，起点不在任何边界锚上）。**已解决**：dev 第 2 轮把候选上限 12 → **48**，覆盖达 **30/30**，且**调用次数不变**（只多约 215 单元的候选文本/次）。 | ⚠️ 覆盖曲线只在 **dev** 语料上量；val/test 的金标片段分布可能不同 ⇒ test 必须用上限 48，且覆盖率必须随 span 指标一起报（见 `L-M96-11`）。原 cap=12 读数**不回写**，作为历史保留；搜索模块两轮 dev 额度**已用尽**。 |
| `L-M96-08` | **概率容差 0.01 是从实测定的**（100 例对照运行里 15 次和恰为 0.99；单问题探针 20 次恒为 1）。 | 它是"允许读到不精确的和"，**绝不**把概率改写归一；实质不归一（0.8）仍判失败（有离线负控）。真实分布只覆盖了两种问题形状。 |
| `L-M96-09` | **WP0a 的历史影响面是 `UNTRACEABLE`**：受影响的 `m9.5:smoke:live` 其逐案判定落在 gitignore 目录且该目录**已不存在**。 | **不**宣布历史读数全部无效，也**不**回写；只如实登记"该门主判分器存在一个已知假通过通道，且原始响应未保留"。 |

## C. 判据/测量（"数字量的不是你以为的那个东西"）

| 编号 | 局限 | 边界 |
|---|---|---|
| `L-M96-10` | **审计第二层的"派生关系准确率"混杂**：它把"链**正确地**识别出的**额外**无据主张"（`aud-dev-0006/0007` 的回复里还有第二条断言）记成错误；且只在金标 ≠ `contradicts` 的子集上算（链**表达不出**冲突）。 | 计划 §6.3 要求的三项（提取覆盖 / 漏主张 / 关键错误）**没有**这个问题；本列只作参考。 |
| `L-M96-11` | **候选覆盖 0 与"模型不会选片段"在输出上长得一样**（WP4 第 1 轮真实踩到：覆盖 0/30 ⇒ span 精确率被结构性地钉死在 0）。 | 覆盖测量是**必须**随 span 指标一起报的那一列；只报 span 精确率是**无效测量**。 |
| `L-M96-12` | **超时曾被混进延迟均值**（得到 "avg 4487ms"，那个数描述的不是"API 平均很慢"）；修的过程中还发现"按步名前缀筛探针"会把 5 次延迟采样漏在分母外、**隐藏超时**。 | 现已把**成功延迟分布**与**失败率/超时率**分列，并用显式 `kind` 分类探针。 |
| `L-M96-13` | **人审强度不足**：用户 2026-09-29 裁定「抽查一部分、其余信任」⇒ **不满足**计划 §6.1 的逐条人审。 | 所有语料（搜索 100 条、审计 90 条）都带这一条；不得把"抽查"说成"逐条复核"。 |

## D. 服务与协议（实测事实，非缺陷）

| 编号 | 局限 | 边界 |
|---|---|---|
| `L-M96-14` | **官方 API 没有自由文本输出**（只有 `noul`/`choice`/`score`）⇒ 片段/偏移**只能**由程序先枚举选项、模型再选 ID。 | 这不是缺陷而是**表达力上限**：现行判定器能返回任意 `querySpan` 是架构优势。要用 Jev 填满片段类契约，程序候选表**必须**覆盖金标。 |
| `L-M96-15` | **`Score.legend` 是对象** `{"0": "…"}`，`score` 可落在两档之间；`confidence` 对 **Noul 不存在**。 | 计划书初稿的假设被预检推翻；已按实测形状实现，并保留"legend 是数组 ⇒ 协议违规"的负控。 |
| `L-M96-16` | **真实端点偶发超时**（与 `L-M55-12` 同型）：预检期一次调用撞 20s 共享总期限。**总期限跨重试共用** ⇒ 一次挂起即吃掉全部预算、**没有重试机会**。 | 样本太小，**不足以**判定 G5 的 ≤5% 超时率；必须在 test 用更大样本取读数。提高共享期限属于**显式政策变更**，不得为让数字好看而静默调参。 |
| `L-M96-17` | **未核对账单**：费用全部是 `estimated`（单价来自官方文档 2026-09-29）；官方文档**未载明**最低充值额与税费。 | 契约 §12 记为待定，**不填**；不得把估算当实际。 |
| `L-M96-18` | **`422` 是否存在及其错误体形状未确认**（检索索引副本有、直取未复现）；错误体字段名官方未文档化。 | 记为待定；不预设错误体形状。 |
| `L-M96-19` | **限流未实测**：不做高频真实请求制造 429（计划 §9 明令）⇒ 限流行为只有文档读数。 | 不得声称"已测限流"。 |
| `L-M96-20` | **上游恢复后未重跑**：`m9.5:smoke:live` 在 WP0a 后**未重跑**，所以"坏响应现在会大声失败"是**代码级结论**，不是观测结论。 | 该门属于已冻结的 M9.5 里程碑；本轮未改它的代码、未回写它的读数、未移动标签。 |
| `L-M96-21` | **审计 test 每类只有 10 条** ⇒ J 与 B 的总体准确率区间**重叠**（J 0.925 [0.801, 0.974] vs B 0.950 [0.835, 0.986]），**点值差不足以确立优劣**。 | 唯一可作为**布尔**判据的是 G8 条件②（`no_assertion` 全对），它在 J 上明确失败。**不得**把 0.925 vs 0.950 说成"已确立的差距"。 |
| `L-M96-22` | **Jev 的 `no_assertion` 缺口未被修**。它在 dev-r1/dev-r2/val/test×3 **五个读数上稳定复现**（把"未命名具体取值的泛推断/含糊推测"判成 `insufficient`）。 | 冻结记录已声明**两轮 dev 额度用尽** ⇒ 若要修必须**另开一轮研究**（新语料、不把旧集重称盲测）。本阶段**只登记、不调参**。 |
| `L-M96-23` | **基线在 `contradicts` 上也不完美**：同题 LLM 三轮错同一例（`aud-test-0018`，把"同槽位不同取值"判成"证据不足"）。 | "冲突 vs 不足"这条边界对**两个方案**都难 ⇒ 若要继续，**双方**都需要更明确的判据，不是只调 Jev。 |
| `L-M96-24` | ★ **基线自身的噪声大于两臂之差**：**同输入**两轮，A 的判定翻转 **4/100**（准确率 0.79 → 0.77），而 J 翻转 **0/100**。 | 于**测试端点**实测；⇒ 单轮 2–5 个百分点的差**不可区分**（这是 `INCONCLUSIVE` 的**测量**依据）；也是计划要求 **test 三轮取最差**的直接理由。**不**得把 4% 翻转外推到生产端点（生产端点未测）。 |
| `L-M96-25` | **后续实验存在一个由收尾会话造成的流程偏差**：`followup-test-r3` 当时**仍在运行**，却被误判为已中断，于是多起了一轮 `followup-test-r3b` ⇒ 完整 test 轮变 **4** 轮（协议冻结的是**连续三轮**）。 | 三轮显式指定 `r1/r2/r3`，`r3b` 列为额外轮，**不**用于替换或挑读数。已核对：含额外轮的**最差 run 不变**。 |
| `L-M96-26` | **两轮墙钟重叠 164 秒**（`r3` ↔ `r3b`）⇒ 重叠窗口内的**时延读数受并发负载污染**，两轮时长不可直接比较。 | G6 时延臂只作参考、**不外推生产**；重叠区间逐条记在 `aggregate.json.overlaps`。 |
| `L-M96-27` | ★ **`proposalValid` 只是结构有效性**（区间在界内、非空、不切 surrogate），**不是语义有效性**。Jev 在"缺指代对象"的输入上会选出**裸代词**当查询片段（`这篇论文` / `这个规定` / `那首曲子`），**能通过契约** ⇒ 会变成一次真实出站查询。 | 所以安全用例的"有效提案 = 0"**不能**证明安全；真正的量是**全部负例的有效提案**（最差 6/110 = 5.45%，基线 0/110）。`sn-test-0135` 之所以被挡住，只是因为 Jev 连片段都没给出。 |
| `L-M96-28` | **后续实验的 B 列仍未跑**（搜索模块的任务表达仍**未受控**）· **成本臂 UNKNOWN**（基线账单单价未核验）· **A 的期限 25s ≠ J 的 20s**（协议 §7.1 的既有偏差）。 | 沿用协议 §5：**缺成本证据不能宣称 G6 PASS**；**不得**声称搜索模块的表达差异已受控。（⚠️ 情绪模块的 B 列**跑了**，结论见 `L-M96-35`。） |
| `L-M96-29` | **官方 `questions` 是映射、各题独立作答** ⇒ 家族题**无法**条件化在判定题上。 | 实测：同一案例官方可答 `decision=NEUTRAL` 而 `family=A-GRATITUDE`。⇒ 家族题**只在 `decision=IMPACT` 时**计分；非 IMPACT 的家族答案**忽略并只记伪影**。 |
| `L-M96-30` | **`emotion-r1` 是失效轮**：前 41 案**连续** `network_error`（端点瞬时不可用），完成率仅 42.45%。 | 该轮**量的是网络不是模型**；证据**保留**（freeze @1 嵌在其 manifest 里），**不**得引用其 J 列数字。失效原因是**外部**的，不是代码或请求体大小（探针 5/5 OK，请求仅 3KB）。 |
| `L-M96-31` | **传输失败策略是第 2 版才声明的**：某列 `unavailable` > 5% ⇒ 该列质量读数 INVALID、整轮 `INVALID_TRANSPORT`、必须**显式重跑**；**禁止**静默重跑刷分或丢弃失败样本。 | r2 判定 VALID（三列 0% unavailable）。⇒ 引用任何一轮读数前**先看 `manifest.transport.verdict`**。 |
| `L-M96-32` | **拒收路径会丢弃部分答案**：当官方给**自相矛盾**输出（判 IMPACT 但家族答"不适用"，`b-manip-007`）时，本版量具按**端到端失败**拒收并**丢掉 decision 子答案** ⇒ "它的判定是否其实正确"**不可恢复**。 | 登记为量具损失，**不**据此替它辩护，也**不**据此加重它。要恢复需另开一版量具。 |
| `L-M96-33` | **情绪模块只有单轮** ⇒ 第 9 项「跨 run 翻转率」**`NOT RUN`**。 | 不得声称情绪模块的跨 run 稳定性；虽然 **IMPACT→NEUTRAL 41/62** 的集中度强烈提示是**系统性问题**而非随机。 |
| `L-M96-34` | **概率校准只有 J 列可测**（A/B 不产出概率）· 且 **ECE 0.1949 表示未校准**。 | **不**作三列比较；**不**据此说 A 差；本轮**未**引入任何置信度阈值或低置信度回退（契约 §5 明令）。 |
| `L-M96-35` | ★ **情绪模块的 B 列跑了，且与基线打平**：同题 LLM 判定准确率 **0.9528** = A 的 0.9528（J 只有 0.5377）。 | ⇒ 结论：**"任务表达"不是瓶颈**——同一套判据写成单题 JSON，普通 LLM 就能达到基线水平。⇒ 41.5pt 的差距**不能**归因于判据难表达或测试端点。⚠️ 搜索模块**没有**这个结论（其 B 列 `NOT RUN`）。 |
