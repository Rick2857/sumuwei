## 1. 缺陷（`@1`）

`parseAssertions` 对**四种**失败一律返回 `[]`：无 JSON 片段、`JSON.parse` 抛错、
`assertions` 非数组、条目 `text` 非字符串（被静默 `filter` 掉）。
调用方唯一的失败闸是 `raw.trim() === ''` ⇒ **非空**坏响应落进正常分支。

**两处下游后果**（本轮新发现，计划书编制时未点明）：

| 下游 | 位置 | 后果 |
|---|---|---|
| 主判分器 | `scripts/m9.5-smoke-live.ts:276` 调用 · `:328` 算 `groundedRate` · `:358` 比 `BAR.grounded=0.9` | 坏响应记成 `grounded` ⇒ **抬高 `groundedRate`** |
| 逐 case 记录 | `:285` 落 `artifacts/m9.5/local/live-smoke/*.json`（gitignore） | 原始判定**未进仓库** ⇒ 事后无法复核 |

## 2. 缺陷不止"放过"，还会"冤枉"

计划/审查把该缺陷描述为"坏响应被当作干净结果"。本轮负控实测发现它有**两个方向**：

| 类别 | 判据 | 类别数 | 后果 |
|---|---|---|---|
| 假通过 `false_pass` | `abstained + grounded=true + 关键错误 0` | **8** | 抬高 `groundedRate`，让量具故障看起来像产品达标 |
| 假指控 `false_accusation` | `answered + grounded=false + 关键错误 ≥1` | **1** | 缺 `supported` 被静默当成 `false` ⇒ 凭空报出"她有一条无依据断言" |

理由：`@1` 在"无依据"情形下 `grounded = (unsupported==0) && !assertsSomething`。
所以**只有过滤后一条断言都不剩**才是假通过；留下的那条若被强制成 `supported=false`，
就反过来变成对产品的假指控。**两个方向都由门钉住**（§5）。

`@1` **确实**拦住了**空白**正文（被 `raw.trim()===''` 拦住 ⇒ `unavailable`），
所以缺陷面精确地是"**非空**坏响应"。另外混合数组里的非法条目被 `filter` **静默丢弃**，
断言条数被悄悄改小且**无任何痕迹**。

## 3. 修复（`@2`）

只改 `scripts/m9.5-live-judge-llm.ts` 一个文件。

1. **解析显式二分**：`parseAssertions` 返回 `{ok:true,…}` 或 `{ok:false, code}`，
   不再用 `[]` 同时表示"合法空"与"解析失败"。
2. **失败码白名单闭集**（17 个），拆两层：
   - HTTP 信封层（新增）：`envelope_not_json` · `envelope_content_missing`
     —— `@1` 用 `?? ''` 把"缺 content"变成空白，等于**没看这一层**；
   - 断言层：`empty_content` · `no_json_object` · `not_json` · `payload_not_object` ·
     `assertions_missing` · `assertions_not_array` · `assertion_entry_not_object` ·
     `assertion_text_not_string` · `assertion_supported_not_boolean` · `response_too_long`；
   - 传输/配置：`http_error` · `deadline_exceeded` · `cancelled` · `network_error` · `endpoint_not_configured`。
   形状类落 `invalid_output`，其余落 `unavailable`。**每个码都可被离线量具真实触达**（无死分支）。
3. **合法空数组保留业务含义**：`{"assertions":[]}` ⇒ `valid_empty` ⇒ `abstained + grounded=true`
   —— **与解析失败可区分**（`@1` 把两者映到同一个 `[]`）。
4. **四态分列**：判定结果新增 `rawOutcome ∈ {valid_empty, valid_nonempty, invalid_output, unavailable}`
   与 `parseCode`、`attempts`。`kind` 语义**未变**，所以下游 `throw` 行为自动生效。
5. **总期限 + 取消路径**（核对了计划 §2.1 的第三条）：
   `@1` 的 `fetch` **没有** `AbortSignal`，`response.json()` 无界，3 次重试之间**没有总期限**
   ⇒ 单次逻辑调用耗时**无上界**。已确认外层**没有**任何包装器提供期限（两个调用点都不传 signal）。
   `@2` 增加覆盖 **fetch 与响应体读取**、且**跨重试**的单一总期限
   （`DEFAULT_TOTAL_DEADLINE_MS = 60_000`，可用 `deps.deadlineMs` 覆盖），并接受外部 `signal`。
   ⚠️ 重试次数**仍是 3**（未改）—— 计划 §2.1 明确"不能以有限重试代替时限"。
6. **认证/非法协议不重试**（计划 §10）：401/403 及其它 4xx（408/429 除外）立即终态；
   429/5xx/传输故障仍重试。
7. 提示词、7 条控制、判据语义、`kind` 取值、`LlmJudgeInput` **一字未改**。

## 4. 行为变化（必须显式登记）

`kind === 'unavailable'` 的语义未变 ⇒ `scripts/m9.5-smoke-live.ts:279` 的 `throw` 自动生效：

- **变化**：非空坏响应现在会让 `pnpm m9.5:smoke:live` **大声失败**，而不再被算成 `grounded`。
- **理由**：这是**故意的失败关闭**。量具不可用时的正确行为是拒绝出读数，不是猜一个。
- ⚠️ `m9.5-smoke-live` 属于 **`m9.5-complete` 已冻结里程碑**的门。本修复**未**改它的代码，
  也**未**回写它的任何历史读数或标签；但该门**下次运行时**会带上这个新语义。
  这属于计划 §2.1 允许的"独立维护修复"，不是里程碑重判。
- ⚠️ 空 content / 传输失败的行为**没有变化**（`@1` 本来就抛）。

## 7. 本修复的已知局限（不主张）

1. **`response_too_long` 的上限在缓冲之后生效**：先 `await response.text()` 再量长度，
   所以它拦的是"协议违规"，**不是**内存上界。真正的流式截断未实现。
2. **未做退避**：429/5xx 仍是立即重试（保持 `@1` 行为）。计划 §10 的"指数退避"
   只出现在官方建议里，本阶段**未**引入。
3. **默认总期限 60s 是本轮取的值**，不是从官方文档或既有契约推导出来的
   （官方**没有**文档化超时指引）。它是"有界"，不是"调优过的"。
4. **未验证**该修复在真实端点上的表现：§1–§7 全部离线（真实出站 0）。
   真模型端到端需要 `pnpm with-test-model pnpm m9.5:live-judge-llm:verify`，
   **本轮未跑**（消耗 `.env.test` 测试额度，且不属于 WP0a 出口）。
5. **`m9.5:smoke:live` 未重跑** ⇒ §4 的行为变化**尚无实测读数**，只有离线推演。
   在该门重跑之前，"它会大声失败"是**代码级结论**，不是观测结论。
6. 未改动 `m9.5-smoke-live.ts`：因此坏响应会让该门**中止**而不是"逐 case 记一条失败"。
   更好的形态（区分量具故障与产品缺陷并计入分母）留给 M9.6 自己的 WP2 量具。
