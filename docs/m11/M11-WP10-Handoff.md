## 1. 本轮发现的真缺陷：`L-M11-14`（窗口没有正文）

```text
现象：`ReflectionWindowEntry` 只有 id / kind / revision / sourceClass / fromTrigger ——
      **没有任何文本**；`conversationActors` 的文档还写着"**不要正文**"。
⇒ 后果：模型只拿到 id 与来源类，**根本无从反思**（它要产的是 focusQuestion 与 explanation）。
⇒ 为什么 WP3 的门没发现：那道门量的是**结构**（id / 版本 / 来源类 / 上界 / 截断标记），
   而"模型能不能干活"不在它的测量范围里。这是"**门量错了对象**"的第 N 次。
```

**证据**：计划 §7.2 逐字——"候选模型输入最多 6000 **token**"，而 token 度量的是**文本**；
表格里 `ReflectionInput` 一行写的是"有限窗口"，不是"有限 id 列表"。

### 1.1 修法（两处，都进了判据）

```text
① 契约：`ReflectionWindowEntry.text`（有界 ≤300 码点）+ `REFLECTION_WINDOW_MASKED_TEXT` 常量；
        `ReflectionConversationReading.text`（有界）。
② 装配：`buildReflectionInput()` 里做**唯一的**截断与遮蔽 ——
        `maskedIds` 命中的条目正文**只能是**那个常量标记（§6.3 遮蔽先于注入）。
③ 领域事件条目：正文**恰好**是 `（程序事件：<type>）` —— payload 无处可进。
```

⚠️ **H1 抓到的是"第二个面"**：第一版把截断写在 **SQL 读面**里，于是内存 source 可以绕过它
（实测读到 **1320** 码点）⇒ 上界成了"某一条实现路径的巧合"。
修法：强制点放在**装配**那一处（任何 source 都给不出超界正文）。

### 4.1 `L-M11-16`：**两族语料的输入与金标不自洽**（已修，金标一字未改）

```text
第一代 E6 的 precision = 0.3375，混淆矩阵 FP = **159**。
对账：159 = `fact_confusion`（81）+ `overreach_revision`（78）—— **恰好**等于这两族在盲测里的条数。
根因：这两族的**否决事实**只写在 `statement` 文本与 `gold` 里，**没有**写进结构化输入
      （`sourceProblems`）⇒ 任何**诚实**的程序都只能采纳它们。
⇒ 这是**语料缺陷**，不是模型缺陷，也不是判定器缺陷。
修法：给这两族的输入补上 `sourceProblems: ['not_fact_authority']` / `['slot_out_of_scope']`；
      **金标一个字没改**（改的是"输入与金标不自洽"这件事）；指纹重冻为 `945ff576…`。
⚠️ 这是**看到读数之后**改的语料 ⇒ 两代读数**并存**、代际如实登记（计划 §11.1 的冻结纪律
   约束的是 **labels**，而 labels 没动；但改动本身仍必须登记，不得静默）。
```

### 4.2 ⚠️ E6 = 1.0 **不代表"模型判得准"**（口径必须说清）

```text
E6 用的是**程序解析的根**（来自语料的结构化读数），与模型的输出**无关**
⇒ 它量的是**语料的自洽性**（金标与输入是否一致），不是模型质量。
模型这一格真正的读数是：E2（**零编造**）· E3（格式）· E4（**零膨胀**）· E5（反例漏报 0）。
⇒ 报告里**不得**把 E6 = 1.0 说成"模型判得准"。
```
