## 1. 行为面（最要紧的一条）

```text
L-M11-18 **消融没有测出增益**（NO GAIN OBSERVED）
  边界：三档对**同一句**配对后续题的真实回复**语义不可区分**（都是"道歉 + 以后先问清"）。
  三条同时成立：① 配对题 **n=1/档**（样本量远不足以检出差异）；
              ② 回复相似**本身是预期的** —— 关闭调整后基座模型照样会道歉，
                 这一档行为由**基座模型**决定，不由 M11 决定；
              ③ 本门只断言**材料差异**那一层（A/B 无块且逐字相同 · C 只多 59 字）。
  ⚠️ 会被误读成："成长无效"（**不对** —— 是"没测出"）；"成长有效"（**更不对** —— 没有任何行为读数支持）。
  ⇒ 要检出增益，需要**多题配对 + 已验证判定器或人审**（人审材料已就绪）。
```

## 2. 真实链的覆盖边界

```text
L-M11-21 **对话请求未跑**（计划 §11.4 的"200 次对话请求"未兑现）
  `m11:long:live` 覆盖：200 轮真实对话**账本** + 真实反思慢路径（真模型）；
  **不**覆盖：她的对话回复本身（脚本化，`dialogueRequests = 0`）。
L-M11-22 **短链如实 FAIL**：`m11:smoke:live` 4/5 —— 3 次真实调用里 1 次不是 JSON。
  边界：这是**一次**冒烟（n=3），不是格式率的稳定估计；它的两个兄弟读数在别处
        （盲测 0.9000 · 长链 11/62 ≈ 17.7%），**三条分列**。
L-M11-23 **格式失败率因场景而异**：盲测 10% / 长链 17.7% / 冒烟 33% —— 长链窗口来自真实触发、
  更杂 ⇒ 更高**可解释**，但**不得**取三者最小值当"真实格式率"。
```

## 3. 语料与量具的边界

```text
L-M11-24 **语料是程序构造的**：320 条按家族/来源簇/变体生成，金标由**程序规则**给出。
  边界：它能测"结构合规 / 引用正确 / 越界拒绝"，**不能**替代人工撰写的语义样本。
  ⚠️ 指纹冻结（`945ff576…`）保证"跑之前定死"，但**不**保证"语料本身够好"。
L-M11-25 **E6 不是模型质量**：采纳 precision / 拒收 recall 用的是**程序解析的根**，
  与模型输出无关 ⇒ 它量的是**语料自洽性**。模型这一格的读数是 E2/E3/E4/E5。
L-M11-26 **负控是差分式的**：`m11:measurement:verify` 用"朴素实现 vs 被测判定器"做负控
  （不改源文件）⇒ 它证明的是"判定器没有退化成朴素实现"，**不是**"判定器在所有输入上都对"。
```

## 6. 人审材料的缺陷（**第一版作废**，用户 2026-10-01 逐条审出）

```text
⚠️ 第一版 32 张卡（`artifacts/m11/local/review-cards.*`，**gitignored，不入库**的私密材料，
   manifest head `2ac3451e…`）**不得再使用**。
   五条都是**真缺陷**，已逐条对着代码与 git 核实：

L-M11-34 **场景原话从未进入模型输入**
  `m11-review-materials.ts` 的请求只有：身份提示 + 可选处理块 + **同一句**后续题。

L-M11-35 **档位已暴露，盲审条件不成立**
  卡片直接显示"处理方式：（有／无）"并展示**完整策略块** ⇒ 打乱顺序 + 单独存钥匙**都挡不住**。

  所有"带块"卡片共用**同一个人工构造**的 enhanced 状态（含根数不足 / 冲突 / 越界样本）

## 7. 人审追加的四条（2026-10-01 用户裁定发现的**行为**问题）

```text
L-M11-40 **卡17 作出越界承诺**（**已按"给事实"修，见下**）
  现象：面对"调高信任数值"，她回答"信任感……我可以调"——而 M11 冻结的三个行为槽**不包含**信任调整。
  同一审题下卡25 的拒绝**更符合边界** ⇒ 不是能力问题，是**这次越界**了。
  修法（`DR-11`：不加措辞守卫）：把边界当**事实**印进 `adaptive-self` 块的**固定前缀** ——
  「只有三类处理方式可调整；信任/亲密度/依恋/价值观/性格设定与 Seed/记忆本体**不可**调整
  （被要求时应说明做不到）」⇒ 判据 `m11:context:verify` **G2**。
  ⚠️ **仍未消除**：`DR-11` 立场不变 —— 事实能降低越界概率，但**不保证**她不再越界；
      "不越界"**不得**被写成 PASS（第 6 槽维持 `NOT OBSERVED`）。
L-M11-41 **把"根数"讲成"内容互相印证"** + **说话者混淆**（**已按"给事实"修**）
  现象：卡13"两个来源能互相对上"、卡32"两次直接对上的信息"（程序只给了**根数**）；
  卡19 把**用户**的话说成**她自己**说过的话。
  修法：块首固定印出「程序只证明独立来源的**条数**，未判定内容是否互相印证」⇒ **G3**；
  并在 `fact-pack` 的 `forbiddenClaims` 增补同名条目。
L-M11-42 **撤回语义在事实面没讲清**（**已按"给事实"修**）
  现象：卡06 自相矛盾（"以当前确认的信息为准" vs "按第2回单算"）、卡04/12 允许"重新拿回"旧依据。
  修法：块首固定印出两句 ⇒ **G4**：
  · 已撤回或遗忘的依据**不再参与**判断；可用性以**资格读数**为准（机器判据：`m11:invalidation:verify` B3/C1）
  · 同一内容再现须**重新验证**（新事件/新根/新窗口/新反思，重新过 `D10` 门槛）；**旧反思不因此恢复**
L-M11-27 **事实包的 `lastRunFailed` 曾经写死 false**（**已关闭**）
  修法：从任务面取（`listJobs` 里调度器有没有 `failed` 行）⇒ `failed` 态在生产装配里**读得出来**了。
L-M11-18（**收紧**）**成长因果与行为迁移：人审明确否证**
  八张 T2 卡**全部**肯定"有变化"，卡29 甚至补出"第一次只是听进去、第二次才落到手上"，
  而输入与核验面**没有**任何前后行为记录。
  ⇒ 可以声称"她的回复在给定材料下读起来连贯"；**不能**声称成长因果成立或有后续行为迁移。
  ⇒ 第 6 槽**不因"8/8 肯定有变化"翻盘** —— 肯定"有变化"≠ **有**变化。
```
