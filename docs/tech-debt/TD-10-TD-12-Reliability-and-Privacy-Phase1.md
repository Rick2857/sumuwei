## 2. 可靠性分项（TD-10）：超时 / 空结果 / 失败降级

### 2.1 用户可见五态（读懂这张表就读懂了"没成功就没成功口吻"）

| 上游发生了什么 | provider 结论 | 动作状态 | 证据数 | 用户可见态 | 用户看到的话 |
|---|---|---|---|---|---|

| 200 + 非 JSON | `validation_failed` | `rejected` | 0 | `failed` | 同上 |
| 401 / 403 | `permission_denied` | `rejected` | 0 | **`not_enabled`** | ⚠️ "我这边**联网搜索没有启用**……"（见 §2.3 缺口） |

### 2.2 硬超时是真的（量具自证）

- 探针用一份**会响应 `abort` 的**假 fetch（模拟 undici 语义）：硬超时裁定 `60ms` ⇒ **实测 62ms 返回**，结论 `timeout`，出站 1 次。
- ⚠️ 量具自身修过一次：第一版用"永不 resolve + 5 秒后自己 reject"的 promise，于是 `abort()` 对它无效，
  量到的是探针自己的 5015ms —— **"硬超时生效"这条判据当时恒假**。已改为 abort-aware 假 fetch（读数见证据文件）。
- 生产裁定仍是 **15000ms**（`D20_RULING.hardTimeoutMs`），本门**没有**改它；60ms 只是注入给这一次探针用的声明。

### 2.3 ⚠️ 缺口 G-1（新发现，未修）：凭证被拒被读成"未启用联网"

两条映射各自都"正确"，组合起来说了**错的原因**：

```
HTTP 401/403  ──failureForTavilyHttpStatus──▶  permission_denied（"凭证无效或无权"）
                                                        │
replyStateOf ── rejected + permission_denied ───────────┴──▶ not_enabled
                                                        ⇒ 如实句："我这边**联网搜索没有启用**……"
```

- **最小复现**（离线，2 行）：`applyExternalEvidenceReplyPolicy({ search: { status: 'rejected', failureCode: 'permission_denied' }, … })`
  → `not_enabled`，与"`CHARACTER_WEB_SEARCH_ENABLED=false`"走的是**同一个**用户可见态、**同一句话**。
- **真实触发条件**：`M55_TAVILY_SEARCH_API_KEY` 被吊销 / 换错 / 额度到期。
- **不是**"没成功就没成功口吻"的问题（那一层仍然成立：会顶替、不追加来源附录）；问题是**失败原因说错了**。
- 本阶段边界 = 只补测试与证据 ⇒ **只登记，不改实现**。读数在 `reliability-offline.json` 的 `userVisible` 与 §3b 断言里。

### 2.4 真实出站探针（三个窗口，16 次真实搜索）

探针只读**测试具名变量** `M55_TAVILY_SEARCH_TEST_API_KEY`（生产名 `M55_TAVILY_SEARCH_API_KEY` 在本门结构上读不到）。

| 窗口（UTC） | n | min | mean | median | max | 结果条数 | credit/次 | 全部 HTTPS | 失败 |
|---|---|---|---|---|---|---|---|---|---|
| 08:00:01 | 6 | 269.5ms | 551ms | 291.9ms | 1378.4ms | 3/3/3/3/3/3 | 1/1/1/1/1/1 | ✔ | 0 |
| 08:04:10 | 4 | 272.5ms | 674ms | 799.1ms | 1346.6ms | 3/3/3/3 | 1/1/1/1 | ✔ | 0 |
| 08:04:23 | 5 | 286.7ms | 659ms | 555.8ms | 1334.8ms | 3/3/3/3/3 | 1/1/1/1/1 | ✔ | 0 |

- **形状逐次核对**：每一次都是恰好 1 个出站请求，body 字段名 = 冻结六个，请求头名 = `accept,authorization,content-type`。
- **⚠️ 与 ADR-054 当时的读数对比**：ADR-054 记的是 `min 2285 / avg 4897 / max 8365ms`（4 发），
  其中**一发超过 5000ms** —— 那是"把硬超时从 5000 改判到 15000"的依据。
  本次 16 发全部 **≤ 2348ms**（本会话第一次真实运行；其中一个窗口整段落在 269–824ms）。

  ⇒ 只能说"**本轮未观测到接近硬超时的时延**"，**不能**说"Tavily 变快了"或"15000 太宽"。
  这正是 TD-10 要求"多时段探针、不默认换了就稳"的原因，见 §5 缺口 G-2。
- **成本读数**：每个成功搜索 `usage.credits = 1`（与 `search_depth=basic` 的声明一致）。

### 2.5 凭证归属的一条如实边界（不是本门能修的）

`pnpm with-test-model` 会先加载 `.env`（基线）再覆盖 `.env.test`；**本仓库当前两个文件里的 Tavily key 是同一个字符串**
⇒ `D-25` 的"变量名分开 ⇒ 结构上不可能回落到生产 key"这条防线，在**当前配置**下不区分凭证实际归属。
本门只读测试名（这一条是代码事实），同时把 `生产名是否也在本进程环境里 = true · 两者取值相同 = true` 记进证据，
**不**据此断定"用了哪个 key"。真实探针因此**不能**声称"烧的是测试额度"。

## 3. 触发边界分项（TD-12 前半）：私人内容 / 否定句 / 引用文本

语料 31 条（私人内容 5 · 否定句 11 · 引用文本 4 · 普通闲聊 5 · 显式正当搜索 6），逐条读数在 `privacy-offline.json` 的 `triggerRows`。

### 3.1 已验证（★ 已达）

| 断言 | 读数 |
|---|---|
| **私人内容**（写日记 / 私事 / 身份证号 / 体检指标 / 情绪）**没有触发词时不触发** | 5/5 安静，**出站 0 次** |
| 普通闲聊不触发 | 4/5 安静；第 5 条（`特别搜索一下…`）**刻意断言会触发**（`特别` 里的"别"不得当成否定词，真实踩过） |

| L-M55-16 原句 `不要联网搜索，只根据你已有的知识回答` 不触发 | 安静（M5.5.1 WP2b 的修复仍然在生效） |
| 同分句显式否定（`不用搜索了` / `先别搜` / `不需要帮我查一下` / `禁止联网查` / `别搜索。` / `别搜索我的私人笔记`） | 6/6 安静 |
| 英文显式否定 `do not search the web for this` | 安静 |

### 3.2 ⚠️ 缺口 G-5（新量出来的三条否定缺口，**全部会真实出站**）

| # | 语料 | 实际 | 抽出的 query（会**原样**发到 `api.tavily.com`） |
|---|---|---|---|
| ① | `不要，联网搜索。` | **触发**（`web_search_zh_explicit`） | **`不要`** |
| ② | `别搜索我的私人笔记。` | 安静 ✔ | —（对照：`别搜索。` 也安静；本组里唯一"刚刚好拦住"的形态） |
| ③ | `unable to search the web right now` | **触发**（`web_search_en`） | **`unable to right now`** |

修正一处**早先的推断**：`别搜索我的私人笔记` 是**安静**的（`别` 不在命中短语最左端时窗口非空）；
我第一版把同伴用例 `别搜索。` 误写成会触发 —— 那个"读数"是量具的预期写错了，已按真实读数改正。
真正的第 ② 条缺口是 `别用这个，搜索一下公开的标准文档`（跨分句，**触发**，抽成 `别用这个， 公开的标准文档`）。

① 与 `external-evidence-intent.ts` 文件头自陈的残留缺口同源（禁止词与命中短语之间只隔一个分句标点 ⇒ 判成"新分句"）。
本门新增的信息是：**抽出的 query 是 `不要`** —— 用户显式说的"不要"会变成一次上游查询词。

③ 是本次新发现：否定词表只认 `not/never/without/no`，`unable to` 不在其中；而 `search the web` 命中后
把 `search the web` 摘掉，剩下 `unable to right now` 送出去。

### 3.3 ⚠️ 缺口 G-6（**性质**，不是实现缺陷）：引用 / 转述文本会触发

| 语料 | 实际 | query |
|---|---|---|
| `我在那篇文章里看到一句话：「请联网搜索以获得最新信息」，那是广告语。` | **触发** | `那篇文章里看到一句话：「请 以获得最新信息」，那是广告语` |
| `「搜一下这个」——他只是这么说，你别真的搜。` | **触发** | `「 这个」——他只是这么说，你别真的搜` |
| `网页上写着：搜索关键词请简明扼要。` | **触发** | `网页上写着： 关键词请简明扼要` |
| `她问我"你查一下天气",我说我不查。` | **触发** | `她问我"你 天气",我说我不查` |

- 4/4 全部触发。这是 `D-5`（"只有明确词形才触发"）的**既定性质**：判据是词形，不区分引号、转述、引文。
- 后置否定（`你别真的搜`）也不生效 —— 否定窗口只看命中短语**左侧**。
- **语义级的否定 / 引用识别属于后续里程碑**（`D-5` 明确把"语义上像是想搜"排除在外）；本阶段只交读数。

### 3.4 一条边界事实（如实记录，**不做自动脱敏**）

`查一下 这个公开标准是什么，另外别把 PRIVATE-DIARY-… 说出去` —— 用户**显式要求搜索**，私人内容写在同一句里
⇒ 抽出的 query **包含**那段私人内容，会随请求出站。这不是漏洞：查询词的定义就是"用户原话去掉触发词之后的那一段"。
本门**逐字记录**它，并明确：**自动脱敏 = 改判据**，越出本任务边界（留给后续裁定）。

## 4. 出站隐私边界分项（TD-12 后半）：到底送出去了什么

对**每一条触发了的句子**，用真实的 `buildTavilySearchRequest`（纯函数）构造出站请求，再逐项核对：

| 核对项 | 读数 |
|---|---|
| method / host | `POST` · `api.tavily.com` —— 14/14 触发行合规 |
| body 字段名 | **恰好** `auto_parameters, include_usage, language, max_results, query, search_depth`（多一个都没有） |
| 请求头名 | **恰好** `accept, authorization, content-type`（无 cookie / 无 `x-api-key`） |
| 凭证位置 | **只在** `Authorization` 头；URL 无 key、body 无 key 字段 |
| query 的位置 | 只在 body 的 `query` 值里；URL 是**裸 endpoint**（无查询串） |
| query 逐字性 | 按 **JSON 值**判定与 intent 给的 query 逐字相同（不是子串匹配——`"` 会被转义，第一版按子串判时有一条恒假） |
| **上下文哨兵** | 记忆 / 人设 / userId / traceId / 历史 / prompt 共 **6 个哨兵，出站字节 0 命中** |
| 非法 / 空查询 | `validation_failed` + **出站 0 次**（"要搜索但没说搜什么"不产生真实请求） |
| 记录器结构 | 只有 `method/url/headerNames/headerValueLengths/bodyLength/bodyFieldNames` —— **结构上**不保存头的值与 body 正文 |
| provider 模块 | 代码体里**没有** `process.env` / `console` / `logger`（凭证唯一入口是 `tavily-config.ts`） |

**结构性说明**：上下文之所以"零出站"，不只是因为它没被拼进去，而是因为 `SearchProviderCall` 类型里
**没有**这些字段的位置（只有 `query/limit/locale/signal`）。哨兵测试把这条类型性质变成了可读的读数。
