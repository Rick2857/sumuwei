# M5.5.1 已知局限（Known Limitations）

> 里程碑：**M5.5.1**（交付 DSH）· 判定：[`M5.5.1-Gate-Decision.md`](M5.5.1-Gate-Decision.md) · 事实：[`M5.5.1-Acceptance-Report.md`](M5.5.1-Acceptance-Report.md)
> 纪律：局限**不许**因为"以后再说"就消失；每条都要说清它**影响哪个主张**。

---

## 1. `auto_public` **未激活**（生产只跑 `explicit`）　【**历史：收口当时**】

> ⚠️ **收口后已变化**：`auto_public` 于 2026-09-22 激活（[`ADR-052`](../adr/ADR-052-m6-rollup-and-m5.5.1-auto-public-activation.md)）
> ⇒ 见 [`M5.5.1-Activation-Record.md`](M5.5.1-Activation-Record.md) §6 与
> [`M5.5.1-Gate-Decision.md`](M5.5.1-Gate-Decision.md) §8。下面的原文按其**收口当时**的读数保留不改写。
> ⚠️ 但**局限本身没有被激活消掉**：`auto_public` 判定的**不够准**（最差轮 auto 召回 18/20 = 90.0%，
> 阈值 ≥90% **刚好达标**）**仍然是局限** —— 激活只改变"它会不会被触发"，不改变"它判得准不准"。

```text
生产 `.env` 只有 `CHARACTER_WEB_SEARCH_ENABLED=true`（ADR-048），**没有** `CHARACTER_WEB_SEARCH_MODE`
⇒ 走 `explicit`：只有用户原话里有显式搜索词形时才有 1 次出站。
`auto_public`（无搜索词也能自动查证）**从未在生产激活**，激活属**独立裁定**。
```

**影响哪个主张**：**不**主张"她会在你没说要搜的时候自己去查"。语义门里 `auto_public` 的读数
是**离线装配 + 语义评测**的读数，不是生产行为的读数。

## 2. 判定失败降级只在**离线门**里被证明

```text
超时 / 坏输出 / 非法形状 ⇒ 零搜索（失败关闭）—— 这条由 `m5.5.1:verify`（接线门）证明。
**生产入口没有**注入判定故障的调试口子；要硬造一个属于改生产代码 ⇒ 需另行裁定。
```

## 3. 单机 · 单端点 · 单次运行，**不外推**

```text
语义门与 Live Smoke 都跑在**本机 · 测试端点 · 实测的那几次运行**上。
不主张长期可用性、不主张换端点/换模型后仍然成立。
```

## 4. 不主张"她说得对"

`D-10` 照旧：**没有逐句蕴含验证**。`L-M55-01/02` 继续成立。证据里只留长度与形状，不留正文。
**影响哪个主张**：**不**主张"有来源所以回答正确"。

## 5. 判定超时预算是 25000ms ⇒ 最坏用户最多等 25 秒

回滚 = 显式设 `15000` / `10000` / `5000`。
**判定调用超时**与 **`L-M55-12`（SearXNG 搜索 5000ms 硬超时）不得混用**——两者是不同层的预算。

## 6. 真实搜索可用性不稳定（实测观察，不是缺陷）

```text
同一句话在不同次运行里**有时返回 5 条、有时返回 0 条**
（本机 SearXNG 的 `engines=duckduckgo,wikipedia,wikidata` 对中文查询结果不稳定，见 M6 期间的同类观测）。
系统两种情形都如实转述，但"真实搜索可用性"**不能从单次运行外推**。
```

## 7. 语料侧状态（**v2 已消除计分冲突；边界解释已冻结**）

```text
语料版本：v2 = v1（83 行一字未改）+ 登记修订表**派生**（用户 2026-09-20 裁定采纳）
  ⇒ 应搜正例 23→20 · 显式公开 12→11 · **A 类冲突 2→0** · **B 类不可达正例 1→0**
  ⇒ 修订后的标签：e09 → clarify · x04 → answer · x08 → clarify · q03 → search · e03 → clarify
```

⚠️ **更正（2026-09-22）**：本文件初版把"`e09`/`x04`/`x08` 的计分冲突"写成**未裁定** —— **那是错的**。
那三条已在 v2 里解决，本次观测也**确实**按 v2 标签运行
（`e09` = `clarify/missing_subject` · `x04` = `answer/quoted_or_metalinguistic` · `x08` = `clarify/missing_subject|ambiguous_scope`）。
v1 的冲突只作为**历史记录与量具负控**保留（`scripts/m5.5.1-corpus-audit.ts` 是"不得出站"清单的唯一来源）。

**边界解释已冻结**（判定契约的一部分，见 Gate-Decision §4.1）：区分
"**足以发起搜索**"（有可公开检索的对象，缺参数只影响答案唯一性）与"**足以给出唯一答案**"；
对象**完全缺失**才 `clarify`。据此：`e12` **保留 `search`** · `i04` **auto_public 应搜 / explicit 不自动搜**。

**仍开放的技术项**：

```text
· e05 的历史 span 故障 = **技术调查**（保留应搜标签；本次 6/6 放行、未复现 ⇒ **不能**说根因已消除）。
  需区分：①模型越界 ②坐标契约不清 ③校验器缺陷 —— 三者不得互相冒充。
· e12 的语义判断分歧：run2/explicit 返回了**合法**的 `clarify/missing_subject`（传输与格式都正常）
  ⇒ 归因是**判定器的语义判断**，**不是**超时或 token 预算；**不得**用加大预算去"修"。
```

```text
   但**整体销账仍以最终复验为准**，不在本文件里宣布关闭。
```
