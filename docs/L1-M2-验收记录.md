目标（方案原文）：

> 修改数据库里的 valence / trust 后，苏沐薇的回答会明显发生符合逻辑的变化。

## 2. 验收实验：State → Behavior

### 2.1 为什么要重做一遍实验

第一版验收（`scripts/verify-state.ts`）走的是**连续多轮**会话，得到：

```
A（trust 0.85）：快十一点了。什么事。你说。
B（trust 0.15）：什么事。你说。
```

表面通过了，但**这个实验站不住**：A 是第 1 轮、B 是第 2 轮，两组的差异
可能只来自对话轮次，而不是 trust。要证明因果，必须让状态成为唯一变量。

### 2.2 严格对照实验

`scripts/verify-state-clean.ts` 做了三件事来消除混淆：

1. 每组用**独立的 roomId**，Recent Messages 中没有任何历史
2. 每组**只问一次**，问题完全相同：`我有件比较重要的事情想告诉你。`
3. 组间**唯一变化的就是 CharacterState**

### 2.3 实测结果（终版）

| 组 | 状态（唯一变量已标注） | 苏沐薇的回复 |
|---|---|---|
| **A** | trust=0.85 closeness=0.60 valence=0.00 arousal=0.00 | 嗯。<br>你说。<br>我在听。<br>（15 字，安静承接） |
| **B** | trust=**0.15**（唯一变量） | 你说。别铺垫。重要的事你拖到现在才开口，一般没什么好事。跟我有关，还是你自己的事。<br>（41 字，盘问、猜疑、要定性） |
| **C** | closeness=**0.20**（唯一变量） | 嗯。<br>你说。<br>我听着。<br>（14 字，退成客气，去掉了 A 的「我在听」） |
| **D** | valence=**-0.70** arousal=**0.70**（唯一变量） | 说。<br>重要的事还要先报备一声。<br>你什么时候学会这套了。<br>赶紧讲。<br>（28 字，抢话、追问、抢白） |

**四组回复取值个数：4/4 —— 各不相同。**

可读出的规律（与状态语义逐条对应）：

| 组 | 状态语义 | 行为表现 | 是否合理 |
|---|---|---|---|
| A | 高信任、亲近、平静 | 最短的承接，安静地等你说 | ✅ 亲近而无戒备 |
| B | **低信任** | 话变长、盘问、往坏处猜、要求定性 | ✅ 不信 → 起疑追问 |
| C | **疏远** | 与 A 几乎同构但更冷，少了「我在听」这句亲近的确认 | ✅ 距离感落在措辞上 |
| D | **负面 + 激动** | 话变多变冲、抢话、抢白 | ✅ 激动 → 憋不住 |

其中 B 组是**修复后的关键证据**（见 5.1）：低信任不再表现为对陌生人的防备，
而是「本该亲近却被辜负」的盘问。

### 2.4 因果链可见

每组上下文中的 provider 列表均包含 `CHARACTER_STATE`（脚本会校验，缺失即判定验收无效）：

```

TIME, ROLES, SETTINGS, ACTION_STATE, CHOICE | prompt 9200 字符左右
```

## 3. 验收实验：挂钟衰减（`scripts/verify-decay.ts`）

纯函数验算，全部通过：

| 检查项 | 结果 |
|---|---|
| 情绪按半衰期回归中性（valence 半衰期 4h） | ✅ -0.8 → -0.4（4h）→ -0.1（12h） |
| arousal 半衰期 5h | ✅ 0.9 → 0.516914（4h） |
| **1000 小时后 trust 仍为 0.85** | ✅ 时间不改变信任 |
| 23 小时：未触发分开，closeness 不变 | ✅ |
| 25 小时：触发，下降 1/24 天 × 0.02 | ✅ 0.600000 → 0.599167 |
| 7 天：closeness 0.60 → 0.48 | ✅ |
| 衰减不可逆（不会自动回弹） | ✅ |
| version 每次结算 +1 | ✅ |

### 设计说明：为什么 trust 不随时间衰减

这是本项目一个刻意的**不对称设计**，也是角色设定的一部分：

> 她因为你不在而难受，是**想你**（closeness ↓），不是**开始不信你**（trust →）。

把「疏远」和「失信」混进同一个变量，系统就解释不了自己为什么这样回应。
「你答应了却没出现」这类真正影响信任的情况属于**事件**，
由 L1-M3 的 Evaluator 走 delta 通道扣 trust，与时间衰减是两条独立路径。

### 惰性结算

状态在数据库里是**上一次互动结束时的快照**，衰减在每次读取时按经过的真实时间结算。
因此无需后台定时任务，也不会因为进程没运行而漏算——
关掉程序三个月再打开，账照样算得清。

## 5. 过程中发现并修复的问题

### 5.1 单看 trust 会把她写成"对陌生人设防"

实验 B 的初版回复出现「你突然这么正经，我有点不习惯。**最好是真有事**」——
这是对陌生人的防备语气，与「对用户毫无防备、只是被辜负了」的设定冲突。

根因：`deriveBehaviorGuidance` 里 trust 与 closeness 是**各自独立**判断的，
因此 `trust=0.15 / closeness=0.60`（本该亲近却失信）被渲染成了纯冷淡。

修复：改为**联合判断**。同样是低信任，「很亲近却不信」是受伤、追问缘由；
「又疏远又不信」才是客气疏远。这也顺带解释了为什么这两个变量必须分开存。

### 5.2 两条行为指导互相抵消：激动的人反而沉默了

第三次验收时 D 组（`valence=-0.70, arousal=0.70`，即负面**且激动**）
的回答反而缩短到「什么事。说。」——**激动不该让话变少**。

根因：`deriveBehaviorGuidance` 里两条规则彼此抵消：

- `arousal >= 0.6` → 「句子会更碎、更急」
- 通用人格规则 → 「情绪不直说，藏在**更短**、更平的句子里」

后者的本意是「嘴硬掩饰」，但被模型理解成了「情绪差就少说话」。

修复：把「掩饰」与「压抑」区分开，并让 arousal 规则显式压住通用规则：

> 你会嘴硬掩饰，但掩饰不住：嘴上不承认自己的情绪，话却比平时更多、更冲，
> 追问和抢话会明显变多。**不要因为情绪差就把话变少——你此刻憋不住。**

修复后 D 组变为 28 字、含抢白与追问，符合「憋不住」的设定。

### 5.3 建表时机：插件的 init 早于插件迁移

`persistent-character` 插件的 `init` 是在 `runtime.initialize()` 内部被调用的，
而 core 的 `initialize()` 先查 `agents` 表、后跑插件迁移——
此时我们的表还没建。因此建表与首次建档**不能放在插件 init 里**，
必须由 `main.ts` 在迁移之后显式调用（`initCharacterState`）。
