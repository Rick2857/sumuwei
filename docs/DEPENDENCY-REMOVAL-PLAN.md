# ElizaOS 依赖卸载：计划边界

状态：**依赖卸载已在公开源码副本中完成**（源侧）。`package.json` 与 `pnpm-lock.yaml` **不再包含** ElizaOS 依赖；`@electric-sql/pglite` 已提升为直接依赖；薄宿主成为唯一运行时，旧的关闭值改为**拒绝启动**而不是无声忽略。

⚠️ 本文件描述的是**公开源码副本**的状态。它**不**陈述任何生产环境的事实：公开副本不含生产库、不含部署记录，也不含本机部署证据。

后续计划分为基础表维护权、运行时替代、测试设施迁移、依赖清理和整包部署，不能仅删除四个包：

- LG 接管六张兼容基础表的版本化定义，由显式迁移入口维护；普通启动应校验并在缺表/落后时拒绝。**这是目标态，不能当成当前已经完成。**
- 薄宿主成为唯一实现时，旧开关关闭值需明确拒绝，不能无声忽略。当前仍有旧宿主路径，移除前须同步改写相关回归断言。
- 回复 XML 解析器、日志、枚举、UUID 和旧上下文路径均需逐项盘点。解析器与 UUID 的对照必须真正冻结；现场调用上游不等于已获得删除依赖后的独立基线。
- PostgreSQL 测试设施必须前置，数据库门逐批迁移后再运行。新建、升级、幂等、拒绝启动、旧代码读新库等检查都需隔离 PostgreSQL；缺少测试实例时明确拒绝，不回退 PGlite。
- 全新目录安装与整包部署同时绑定代码、package、lockfile、workspace、tsconfig 和部署清单。代码回滚与数据库兼容性分别验收，不能只备份锁文件。

历史 PGlite 结果保留原样，引用时标记 `backend=pglite / historical`，不充当 PostgreSQL 验收。是否仍需 PGlite 读取历史快照，应独立盘点，不能因为停止使用它做测试就删除恢复工具。

当前公开副本只运行无数据库专项检查；本计划不构成生产迁移、依赖卸载或部署授权。
