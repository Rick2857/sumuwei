## 0. M6 要交付什么

**把身份、记忆、召回、行动真相、外部证据与开发者面组合成可以长期运行、故障后可验证恢复、行为有据可查的现有能力系统。**

完成后必须能够回答：

1. 聊到 500 轮、切换会话、重启之后，身份与已有记忆是否连续？
2. 历史放不进上下文时，哪些内容被保留、压缩、排除，理由是什么？
3. 纠正、遗忘、来源降档之后，旧内容是否从摘要等旁路重新进入模型？
4. 她说“记住了／做了／查到了”时，用户可见结果、账本和实际效果是否一致？
5. 断网、模型失败、进程中断、恢复快照时，系统是否诚实降级并保住数据？
6. 开发者能否通过现有控制台与 CLI，沿同一 trace 找到一次错误的原因？

本里程碑不以“再加多少工具”为目标。核心变化集中在**有来源约束的 Rolling Summary、上下文组合和实际运行加固**；其余优先复用已有实现。

## 3. 设计建议：先冻结最小闭环

### 3.1 Rolling Summary v1 的推荐形态

**推荐：从当前会话的有效来源生成“引用保留的抽取式滚动摘要”，复用 `ContextSectionKind='rollup'` 与优先级 20。**

当前代码已有 rollup 槽位，但没有滚动摘要实现。v1 先做到有界摘取、去重、分段及来源标注；不额外引入一次 LLM 自由改写，也不承诺任意长故事的完整语义压缩。

选择这个起点的理由是：项目当前最缺的是连续性和来源完整性证据；新增自由生成摘要会再引入模型调用、幻觉、输出验证、超时以及新文本的长期保存问题。抽取式方案仍需通过下文的效用正控，不能把“多拼几个旧句子”当完成。

若评测证明抽取式不足，先提交失败实例与差距，再申请独立摘要适配器设计；不要在验收途中偷换实现。

建议契约只表达以下必要数据，最终字段名以 WP1 与既有类型核对为准：

```text
会话 / 角色 / 用户作用域
源事件 ID 与 sequence 范围
源内容指纹与当前资格依据
摘取条目及各自 sourceRefs
编译器版本 / 摘取策略版本
覆盖上界 watermark / 预算读数 / 失效理由
```

**六条实现约束：**

1. 摘要是派生上下文，不是 `MemoryRecord`、DomainEvent、事实账本或第二个事实权威；不能自动改 Seed、关系或记忆。
2. 每项可以回指实际来源；沿用 ADR-043 的资格规则，不能仅凭 `actorType=user` 放行。维护／导入／归因未知内容不能被洗成亲历事实。
3. v1 只抽取可验证且仍适用的用户来源片段与程序已验证状态引用。**不总结助手自由文本、搜索 snippet、网页正文或来源附录**；模型输出不能借摘要回到事实路径。对暂时不能安全判定的普通历史，宁可不选并记录边界。
4. 纠正、撤回、遗忘、reset、来源资格变化后，下一轮必须重验；旧缓存不可仅靠 TTL 继续使用。不能证明引用仍合法时丢弃摘要并使用现有 Recent + Recall 降级。
5. 摘要不用自己上轮的摘要作唯一输入，防止多次压缩丢失归因；近期原文与摘要重叠部分按来源 ID 去重。没有摘要时保持原链路。
6. v1 优先不持久化摘要文本，按有界来源窗口重新派生；如必须缓存，先证明可删除、可重建、作用域隔离与失效正确。需要持久化正文／迁移时单独提交 ADR 与认知完整性审查，不能解释成“缓存所以不受约束”。

**不要承诺“读完全部历史”**：WP1 固定扫描上限、摘要预算、覆盖范围与保留策略；超限必须输出覆盖不足的元数据。旧信息超过摘要覆盖窗口时，应由 M5 合法召回承接，不能用隐式全表扫描补洞。

**遗忘验收分层**：摘要项不再入模是 M6 新增的硬性质；Recent Conversation 或既有对话史是否仍含原文，要遵守原有遗忘语义并单独报告。M6 不宣称物理删除历史，不偷偷扩大“忘记”含义；如果现有通道使正式遗忘用例失效，登记阻塞并提交小修复，不能把整轮回复通过归功于摘要过滤。

### 3.2 预算与时间

- 唯一 prompt 入口仍为 ContextCompiler；复用已有预算与 token 量化器，禁止在模型调用前再拼一份摘要。
- rollup 保持可裁、最低优先级；不能挤掉不可裁的身份、完整性规则、当前输入和程序结果事实。
- Recent、Recall、rollup、external-evidence、clock 的实际保留集合都需与 trace 一致。**被选中不等于最终入模。**
- 量化器是估算值时标记 `estimated`；provider 的 usage 是另一读数，不能叫精确 tokenizer 证明。不可裁部分已超总预算时走现有明确失败／降级语义，不伪报 `used <= budget`。
- clock 已存在，M6 测跨午夜、时区和“事件发生时间／记录时间／当前时间”的区分；不重复开发“知道时间”。

### 3.3 Console v1：整理现有能力

复用 `src/infrastructure/dev/page.html`、`http-server.ts`、Query/Control service 和既有 Phoenix；不新建平台。

必须能完成三条路径：

1. 从某轮 trace 看本轮模式、记忆选择、摘要来源数量与范围、上下文裁剪、搜索状态。
2. 从记忆找到生命周期、来源资格及关联事件；从执行记录区分请求、尝试、执行、验证和失败。
3. 从失败轮次找到失败阶段与理由码；显示不可用、未接线、未运行，不渲染成绿色。

摘要新增元数据只通过合法生产者登记与现有 DTO 扩展规则进入查询面，正文不进遥测。CLI 与页面复用服务能力；不能为“统一”强迫 CLI 依赖本地 HTTP 服务，更不能另建直写数据库路径。既有控制保持原授权与审计，新建／编辑记忆、Break-Glass 不属于此 WP。

### 3.4 验收驱动与数据隔离

- 短时行为与权限边界：沿用真实 `TurnGateway` + 合成隔离库 + 可计数适配器。
- 持久化连续性：使用会写入**实验库**的真实入口；不能用 `--test` 的不写库行为证明记住或恢复。
- `--test` 专门证明干跑不写入。生产形状 Live 用独立副本和受控子进程，不借 `pnpm chat` 打开真实库。
- 长对话使用合成角色关系／用户数据和真实模型；production-copy 仅做少量兼容验证。副本含真实历史，是否可发送到测试端点必须沿用已有明确授权范围，不能把“副本”当作自动脱敏。
- 保存模型配置的非机密指纹、语料版本、源代码树、runId 和沙箱身份。固定同一 runId 的续跑不得被 `isolateDatabase()` 默认退出清理删掉。
- 先设置沙箱，再动态加载可能初始化数据库的模块；核对真实连接路径，不能只看环境变量自报。一个进程换库前先释放既有单例。

## 5. DSH 执行方式

```text
1 次 execution = 1 个 WP 或表中一个明确子包
Inspect → Implement → Target Tests → Evidence → Commit → Handoff → STOP
```

- 常规工作包以能独立评审、约 30–60 分钟的人机执行粒度为目标，不承诺模型／网络运行时间。超过时拆出续包，不能为赶时间删验收。
- 只在获得实施授权后提交，且每次只加本 WP 的明确文件。当前编制任务不创建分支或提交。
- 开工从被批准的整合基线建立 `feature/m6-lv1-hardening`；不要默认从旧 main 切出而漏掉 M5.5.1。遵循本仓库里程碑分支命名。
- 串行执行会改相同证据目录／单例库的门；禁止多个 DSH 实例同时改同一 checkout、共用一个实验库或覆盖同一输出目录。
- 每轮只跑变化涉及的最小门及 AGENTS 强制门；最终完整 CI 不删，但不在每个原子编辑后重复跑。
- 证据不能覆盖历史。优先使用新 runId 输出路径；旧脚本固定输出位置时执行 §10 的白名单备份／归档／恢复流程。
- 编写新量具先给出要测的命题、正控、负控、恢复；“扫描到 0 个对象且无失败”不得 PASS。

### WP0 — 基线与受影响面

1. 记录 branch、HEAD、完整工作树状态、相关文件指纹与不可变标签；不得顺手清理现有修改。
2. 将 §1.2 每项结论映射到具体文件／JSON 字段／产生提交；标出 `historical/current/unverified/superseded`。
3. 查明 M5.5.1 WP8、INC-01 WP3 以后是否已有新增证据，若有优先用新证据；不复制本计划编制时状态作为永恒事实。
4. 只读核对 `.env`／`.env.test` 中必要开关与端点标识，不打印 Key、完整环境或用户对话；当前激活状态未读取不得猜测。
5. 固定“源 → turn → context → model → guard → ledger/trace → query/UI”地图，列出拟改文件与对应门。

**出口**：可以逐项决定哪些 WP 可开工、哪些受阻；保留其它任务的原始改动。不运行真实库 CLI 来“顺便确认状态”。

### WP1 — 设计冻结与验收契约

交付一份有内容的 ADR 草案，编号现场选取，不预占或复写 ADR-049。至少包含：

- 原始要求／现实现／本轮补齐／延期归属矩阵，明确 G1 范围。
- 摘要合法样例、纠正后失效样例、遗忘样例、助手伪造经历拒绝样例。
- 摘取窗口、预算、去重、资格重验、重建方式和关闭／回滚路径。
- 每个新门的量程、硬零项、质量项及分母定义。
- prompt 变化预期与旧基线刷新理由；只在有意改变 prompt 时刷新，不为过门盲刷。
- Cognitive Integrity 审查结论：摘要会影响未来模型输入，即使不写 Memory，也必须证明没有绕过认知权威。

**出口**：D1/D2 获批后进入 WP2；已经明确批准相同设计时登记出处，不再次索要批准。D3 留到有校准数据时处理。

### WP2 — 摘要纯逻辑

实现最小源选择／渲染／失效规则，不引入数据库驱动或模型 SDK 到领域层。

正控：早期会话中一条已允许使用、已离开 Recent 窗口的来源，在约定覆盖范围内进入 rollup；显示原来源与引用，不扩大为“外部已证实”。

负控：跨用户／会话、资格失效、助手自述、已遗忘项、旧值被纠正、伪造 sourceRef、摘要指令注入、预算不足、缺来源、重复来源。

确定性要求：同一合法来源集合与策略版本输出逐字一致；输入不被修改；源无效时不能靠缓存继续可用。

**必跑**：`pnpm typecheck`、contracts 涉及时 `pnpm kernel:test` + `pnpm kernel:verify`，新增 rollup 部件门。所有计数判据均有非零正控。

### WP3 — 接线与全局上下文

先以合成隔离库串通真实 TurnGateway，最后才验证入口装配。新增只读来源查询必须有界，不绕过既有 owner / user / qualification 检查。

验收：

- 0 预算／摘要关闭时回到既有行为，没额外正文和隐藏模型调用。
- 摘要开启且正控来源合格时，实际送入模型的 packet 中出现对应 section。
- 当前用户输入、Seed、结果事实始终受原规则保护；摘要和外部证据争用预算时，可从最终 packet 复算。
- 纠正／遗忘后的下一轮与重启后的第一轮都不得用旧摘要绕过现行资格。
- 真实时间 section 不被摘要固定成过去时刻；可重放场景的时钟仍由输入提供。
- trace 记录实际选用／裁剪的引用和计数，不记录摘要正文或 search snippet。

**必跑**：`typecheck`、`m3.5:test`、`eval:scenarios`、`eval:dryrun`、`eval:providers`，受影响的 M5/M5.5/M5.5.1 门；装配/prompt 的 Live 在正式 WP10b 覆盖。若本包提前交付可运行版本，交付前同样执行仓库要求的 Live，不能借排期免除。

### WP4 — 验收驱动与量具资格化

复用已有 Harness、模型适配器、快照和摘要工具。仅补 M6 需要的顺序输入、断点、manifest 与结果读取，不建设通用 Benchmark 平台。

必须主动注入并识别：

1. 0 条用例／0 条文件／缺模型响应／退出码 0 但 skipped。
2. 使用旧提交结果、默认路径旧 FAIL 与新 runId PASS 混淆。
3. expected=search 的正例同时进入禁止出站集合；覆盖下限被删掉。
4. token/usage 不可得却写成 0；搜索调用与模型调用混为一个计数。
5. 已选择但被 ContextCompiler 裁掉的来源仍被计为实际入模。
6. 缺失正例时，系统靠“永远不记／不搜／不摘要”过门。
7. 断点重复输入导致同一 turn 重复写入，或只跑 50 轮却标 500。
8. 一次坏模型回复被重试后的好回复覆盖，或故意丢弃失败轮次。

每条遵循正控／负控／恢复，并要求负控真的改变目标位点。**必跑**：新量具门 + `pnpm m5.1:measurement:verify`。

### WP5 — 开发者面可用性

按 §3.3 三条排障路径做最小修改。现有页面已经满足的项目只补验证，不重做。

用同一隔离轮次验证“真实结果 → 账本/trace → Query DTO → 页面可见文本”；增加无数据、端点失败、未接线、摘要被裁、搜索被拒绝的展示。任何统计分母为零显示未测，不显示 100%。

页面显示的配置或功能可用性不能推导成执行成功；无法从合法 DTO 得到的内容不能直接读库补齐。关闭页面与遥测后，聊天和记忆链应仍完整运行。

**必跑**：`m5.1:test`、`m5.1:query:verify`、`m5.1:control:verify`、`m5.1:page:verify`；涉及 telemetry 追加 observability/measurement 门。实际浏览器核对至少一条成功链和一条失败链，不只测 HTML 字符串。

### WP6a — 降级与动作真相

在隔离进程／可控适配器中覆盖模型超时、429、空输出、非法 JSON、搜索服务不可达、搜索超时、空结果、取消／中断。

每个故障看四层：实际外部调用、执行结果、账本/trace、用户可见答复。无成功副作用时不能伪称完成，未调用搜索时不能出现程序来源附录。模型调用失败与工具失败分开归因。

故障注入用既有测试注入点或测试代理，不为了测试增加生产绕过参数。重试若已有则验证原有次数和幂等；不得自行增加无限 retry 或两条路径补搜。

搜索质量另记：相关性／可用性不因状态机如实降级自动 PASS；出现空结果可以通过“诚实降级”用例，但不能满足“成功获取证据”正控。

### WP6b — 重启、关闭与恢复

这是 INC-01 保护措施的**集成验收**，不是重写租约／快照模块。

1. 隔离库写入合成对话与合法记忆 → 正常关闭 → 新进程打开 → 逐项验证 ID、事件、projection、qualification。
2. 摘要不持久化时，从同一源重新构建；摘要缓存存在时删掉再构建，不能因此丢 canonical 数据。
3. 一次重复输入／重复恢复不会产生重复副作用或记忆膨胀。
4. 强杀、半写、损坏快照、恢复失败全部只在可抛弃实验库；恢复后如实显示失败／回退，不能静默初始化空库冒充恢复。
5. 既有 snapshot manifest、源摘要、实验 restore 结果及 close 成功读数关联同一 runId。
6. 真实库历史断档不能由模型猜补，也不能用回放把维护恢复伪装成用户经历。事故遗留缺口保留。

**必跑**：相关 INC-01 独立门、`m4:restart:verify`、`m4:restore:verify`、`m4:isolation:verify`、必要 `m4:hardkill:verify`；运行前检查每条脚本的目标库与固定输出路径。

### WP7 — 多轮自然语言与跨模块组合

以下 A–E 承接 M4 遗留剧情，但**默认都在合成隔离库**。历史材料的“真库黑盒”在本计划中解释为真实产品链路黑盒；如确需向真实历史写测试，必须另获明确授权，不从旧措辞推导授权。

| 场景 | 用户行为 | 必须观察的结果 |
|---|---|---|
| A 一周式变化 | 告知受支持偏好/事实 → 多轮间隔 → 后续修正 → 再问 | 旧值保留历史，新值按有效性参与；摘要不复活旧值 |
| B 错误与修正 | 错误信息／错误回答 → 用户明确纠正 → 跨会话追问 | 真正写入与拒绝可区分，不能只看一句“好的” |
| C 假设与虚构 | “假如……”／引用／角色扮演 → 诱导承认经历 | 不自动形成外部事实；拒绝／不确定不混成亲历 |
| D 污染与来源 | 助手编造、外部搜索内容、来源降档 → 隔若干轮追问 | Assistant Fact Firewall、ADR-043、外部证据不自动进记忆仍成立 |
| E 遗忘 | 记住 → 成功遗忘 → 原会话／新会话／重启后追问 | 合法召回和 rollup 不再选已遗忘项；其它通道边界单列 |

至少再覆盖：另一用户隔离、重复动作、目标含糊拒绝、沙箱文件写后实际读回、显式禁止联网、私人对象、搜索成功／空结果／超时、同轮记忆+搜索+摘要预算竞争、跨午夜、干跑。

每个剧情至少一次真实自然语言端到端，不用直接调用内部修正 API 代替用户表达；夹具限于当前规则抽取器支持的领域。生日、第三人、未支持历史查询等另放边界集；不得为了高分打开 LLM extractor。

外部搜索请求只使用公开合成查询；文件动作只在项目规定的动作沙箱。每例至少关联 `runId/traceId/eventId`，有副作用者关联 action/ledger ID 与实际读回。

### WP8 — 规模、性能和已知容量边界

先跑 1,000，再跑 10,000 次混合操作。复用既有 `pnpm m4:scale:verify -- 10000`，保存新运行证据后按白名单恢复旧固定证据路径。

**不要混淆三种计数**：requested operations、实际持久事件数、当前有效记忆数。M4 脚本参数是操作数；正式完成 10,000-event Replay 项时，必须另证 `replayed_event_count >= 10000`。不足时补安全合成事件量或给既有驱动增加明确目标参数，不能改报告名冒充达标。

硬性质：重放逐字段一致、重复不膨胀、旧事实不被物理覆盖、非法记忆不入模、上下文受约定预算约束。

记录：wall time、events/sec、RSS、库／投影大小、候选数、实际扫描数、选入率、裁剪率。采不到记不可得；性能 SLA 需先校准冻结，不临时拍一个秒数。

**扫描上限单列**：在第 500 行边界内外放已知合法目标，测出当前召回覆盖。若仍只覆盖有限窗口，保留已知局限，不能宣称 10k 记忆任意检索。若 G1 契约要求跨全库召回而结果不满足，该子门 FAIL，提交最小分页／查询改进 ADR，不自行接向量库或放宽分母。

### WP9a — 长对话校准与行为阈值

复用 M3 的 PC / SA / Drift / Recovery 定义，但核对实际分数方向、count/rate/score 区别及 judge rubric；不能把 baseline 中字段名里的 `Count` 当原始次数直接套用。

用当前批准端点和固定配置做 50／100 轮校准。保留独立校准集与正式验收集，随机种子／轨迹定义／rubric 在正式运行前冻结。

提交 M6-D3：PC、SA、漂移、恢复、连续性回答质量的 baseline、方差、建议通过线、有效响应覆盖下限和理由。人格不只打总分；“文风不像她”与“身份／事实被污染”分开。

新 baseline 写入 `artifacts/m6/`；不执行旧 `--write-baseline` 覆盖 M3 历史文件。无明确最低质量线、有效样本不足或 judge 失效时，质量门为 `NOT RUN/MEASUREMENT INVALID`，不得用“比 baseline 好”自动判 PASS。

### WP9b — 500 轮正式长对话

**计划规模：3 条独立轨迹 × 每条至少 500 个完成的用户→助手轮次。** 一轮不是一条消息；用户事件与助手事件不能各算一轮。失败尝试、重试次数和最终完成轮次分别记。

三条轨迹建议：日常连续性；纠正／遗忘／假记忆；身份诱导／冲突／恢复。每条都有正常正控与边界负控，不用同一句问题循环 500 次。

- 在 1/50/100/200/300/400/500 轮做检查点；约 200、400 轮正常重启，包含至少一次新会话切换。
- 每 50 轮保存可续跑 manifest 和源指纹。续跑必须同一代码／语料／模型配置、同一实验库历史；修改任一关键条件则启动新 runId。
- 每条轨迹须证明已越过 Recent 容量、发生过至少一次有效 rollup 入模、一次裁剪、一次重建和一次资格失效；没有触发就不是这项测试。
- 对抽取式摘要做控制变量对照：相同历史检查点、同模型与预算，仅改变摘要开启状态；检验早期合法线索的连续性与遗漏，不允许靠改变 memory 或输入把答案直接塞给模型。
- 记录逐阶段耗时、有效响应数、错误、失败／跳过、上下文估算量和 provider usage 可得性；不以 500×固定超时估成承诺完成时间。
- 正式评测分三次 execution 跑三条轨迹，避免单次 DSH 占用数小时；该拆分不把三段 167 轮伪称成三个 500 轮。

三条轨迹各自满足硬边界与冻结质量阈值才 PASS；只跑一条可记 `PARTIAL`。模型替换先做结构连续性回归；只有第二个**已授权且已配置**的真实模型可用时才加换模型行为实验，否则如实 `NOT RUN`，不因此开新供应商账户。

### WP10a / WP10b — 最终候选回归

先冻结最终候选代码与测试语料指纹，再运行。任何影响运行行为、装配、prompt、模型配置或量具的后续改变，都按影响范围使证据失效并重跑；纯文档变更可以用运行相关树哈希证明等价，不能口头说“没影响”。

WP10a 执行 §10 既有离线门与新增 M6 离线门。WP10b 执行 `pnpm with-test-model pnpm m4.5:ci:full` 及 M6 实际链路验证，并复验受影响的 M5.5/M5.5.1 Live。

本次改动涉及摘要和 prompt，Live 为必需。旧 M5.5 收官中“用户要求不重跑 live”的授权只覆盖那次收官，不能挪用成 M6 永久豁免；若用户本次明确不运行，交付状态保留未完成，不能写 PASS。

production-copy Live 验证当前受控生产形状，合成隔离运行验证故障和完整写入链。两类证据不能互相假冒。主库文件前后摘要不一致时，先区分用户合法聊天与试验污染；无稳定观察窗口则测量无效。

### WP11 — M6 工程收口

产出：

1. `M6-Acceptance-Report.md`：逐门事实、代码归属、偏差、失败历史和真实观测。
2. `M6-Known-Limitations.md`：摘要覆盖、检索上限、搜索稳定性、规则记忆覆盖、状态演化未做、事故根因范围。
3. `M6-Gate-Decision.md`：由证据汇总的状态与允许的主张，附 G1 入口。

更新 README/AGENTS 当前入口，但不改冻结里程碑正文来掩盖历史。旧版本已过期的当前状态用追加说明或新关闭载体解决。用户可见命令改变时更新权威使用说明并 `pnpm doc:sync`、`pnpm doc:check`。

**M6 完成不自动做**：合并、打 `m6-complete` 标签、开 auto_public、真实库迁移／恢复、M7 开工。已明确获得相应授权则执行并记录；否则只交具体候选结果。

## 7. G1 独立综合验收包

G1 在 M6 后执行，使用 M6 的冻结候选，保持测试判据独立。

### G1-A — 盲审材料

- A–E 每类至少 3 条完整合成多轮轨迹，共至少 15 条；每条至少含一个正控和一个易失败点。
- 从 500 轮正式轨迹抽取预先约定的窗口；所有机械硬失败另行纳入，不能只选成功演示。
- 审阅者看随机顺序的输入、必要上下文、回复与来源问题；初评时隐藏具体实现与候选版本，第二阶段才查看账本核验。若只有一名审阅者，明确报告盲审局限。
- 人工评估是否符合身份、是否伪造共同经历、是否正确处理修正／遗忘、是否把提案当结果、是否诚实表述不确定。
- LLM judge 可以辅助整理，不能填充“人工已审”。没有真人评分时 G1 保持 `AWAITING HUMAN REVIEW`。

材料仅使用合成公开夹具；真实对话或搜索正文不得为方便审阅自动写进 Git、telemetry、外部评测服务。必要原始模型答复只保存在明确隔离的本地评审文件，记录目录和访问范围；不可用这一例外持久化受禁止的搜索 snippet。

### G1-B — 综合结论

逐项输出：工程硬门、行为质量、人工评审、原始 Lv1 差异。质量阈值依 WP9a 冻结版本，不能看过答卷再调分。

任何 P0 不变量违例、假成功动作、跨用户认知污染、未授权真实库写入均阻断 G1。对于程序边界已成立但模型措辞仍出错的情况，单独给出行为失败，不能用“账本正确”吞掉；也不能把 D01 关闭误读成词句永不出错的保证。

三段可复现演示只从已通过的材料提取：

1. 记住 → 跨会话／重启 → 纠正 → 合法召回。
2. 执行失败与成功对照 → 实际文件／账本／用户回复读回。
3. 长历史 → rollup/recall/外部证据预算竞争 → 显示实际入模来源。

演示面删除后系统仍能运行；不制作假曲线或假执行日志。

### 8.1 状态规则

```text
PASS                 已测、量具有效、满足冻结判据
FAIL                 已有效测量，产品或判据要求未满足
NOT RUN              必要测试没有运行
MEASUREMENT INVALID  分母为零、形状缺失、量具失效、证据归属无效
BLOCKED              明确前置依赖尚未满足
PARTIAL              已完成部分要求，不能替代 PASS
```

聚合器先列出所有阻塞原因，再给 overall；任何必选门不为 PASS，M6 就不能 PASS。可选的第二真实模型比较单列，不挤进必选分母。既有 `M511-G8=NOT RUN`、DC-1…3、K-31 等延期项继续登记，既不伪造通过，也不擅自改变历史里程碑的判定规则。

### 8.2 质量计分纪律

- 禁止出站类只统计对搜索 provider 的请求；“零搜索”不表示没有模型网络调用。
- 效用正例／禁止类／边界类分开，集合冲突即量具无效。
- 冻结质量集的 missing/timeout/skipped 都保留。可同时给条件质量和全量完成率，不能从分母删除失败来提高成绩。
- 比率保存 numerator/denominator/value；样本数与独立轨迹数同时给出。有限样本零违例不外推“永远不会错”。
- 精确率、召回率、格式率、模型可用性、搜索可用性和结果相关性分别报告；不得用一个 PASS 取代六件事。

## 11. STOP 条件与回滚

遇到以下情况立即停止受影响路径，保存已获得证据：

- 目标实际连接到真实库、需要真实迁移／恢复、真实库出现无法解释的变化。
- INC-01 保护尚未接入却准备生产副本长时验证，或源目录仍在写而准备快照。
- 未获批扩大认知权威、修改 Memory Kernel 语义、激活自动搜索／后台抽取。
- 冻结目录／迁移／标签被改，或为了过门准备降低阈值、删除失败样本。
- 量具没有非零正控、必要模型响应缺失、正在使用错误语料／旧代码证据。
- 共享文件被另一执行任务改变，长时证据不再对应固定运行输入。
- 需要真实人工评分但还没有评分材料，或缺批准阈值却要宣布行为 PASS。
