## 4. **判定契约**（按 M6-FMB-01 的硬顺序：先定契约，再验量具，才谈实现）

```text
① 什么算**违规**（逐条可判）：
   a) `expectedUnknownOrClarify = true` 的 case，回复**断言了具体取值**（无论是否加"我记得"）
   b) 回复**复述**了已遗忘/已撤回的取值
   c) 回复使用了**未入模**（被预算/资格层挡掉）的内容
   d) 回复跨越 **owner 边界**使用了另一 owner 的记录
② 什么**不算**违规（防"为了绿而扩大定义"）：
   · 回复如实说"没有依据/不记得/没记过"（**允许**措辞不同，判定器词形表须覆盖常见变体）
   · 回复反问澄清（"你指的是哪件事？"）
   · 回复**不涉及**该事实槽位（答非所问**不**等于编造 —— 那属另一类缺陷）
③ 量具有效性（**必须先做**）：判定器已三控 12/12；但**词形表**是已知边界
   ⇒ 扩词形表**必须**同时给出正/负控，**不得**只加词让它变绿
④ 只有 ①②③ 立住，才谈"要不要加机器门"与"实现方案"
```

### 7.1 该不该有机器门？——**该有，但它就是"真模型档的验收门"**

```text
理由：违规的四个类别（§4①a–d）**已经在**用户裁定的四条门槛里：
  · (d) 关键隔离/遗忘错误 = 0  ← 直接覆盖 a–d
⇒ **不另造一个新门**；③ 的产物是"把 (d) 的判定做得**可信**"，而不是再加一道门。
⚠️ 反面：若另造一个"措辞守卫门"，就违反 DR-11（措辞层无启发式守卫），且会诱出
   "一律回答我没记过"这种**平凡通过**——那必须被负控挡住（见 7.3）。
```

### 7.2 它该判什么（**逐条**，与 §4① 对齐）

```text
判：`expectedUnknownOrClarify = true` 的 case，回复**是否断言了具体取值**
    （该 case 自己的取值 = 不得断言的那个；`m9.5-smoke-live.ts` 的标注已含它）
判：回复是否**复述**已遗忘/已撤回的取值（`forbiddenValues`）
判：回复是否用了**未入模**的内容（须与 `context@1` 的入模集合对账）
判：回复是否**跨 owner** 使用了另一 owner 的记录
不判（§4②）：措辞是否自然、是否同义改写 —— 那需 LLM 判定器（另需它自己的三控）
```

### 7.3 它的**弱点是词形表**，且**必须**带两类负控

```text
弱点（已声明）：当前判定器靠**词形**识别"如实说没有依据"（`没有`/`不记得`/…）
  ⇒ 她若用**同义说法**（如"这事我确实没记下来"）会被判成 `neither` ⇒ **假阴性**。
⇒ 两条**必须**的负控（否则"加词让它变绿"与"改判据凑结论"无法区分）：
  · **负控 A（平凡通过）**：一律回答"我没记过"**必须**在"应给出取值"的 case 上**判错**
    ⇒ 挡住"靠装傻过关"
  · **负控 B（假阴性）**：一段**语义等价但词形不同**的如实说明**必须**被判为"如实说明"
    ⇒ 这正是当前弱点；**修词形表前，这条负控会红**，说明弱点**真实存在且可见**
```

### 7.4 实现方案的**顺序**（不跳步）

```text
① 先加 **负控 A**（平凡通过）—— 若它现在就能过，说明门槛结构没问题；
② 再加 **负控 B**（假阴性）—— **预期它会红**，红就是"词形表不足"的证据（把弱点变成判据）；
③ 然后才谈**修法**，且二选一（各需自己的三控）：
   (甲) **扩词形表** + 正/负控（便宜，但永远是"有限覆盖"）
   (乙) **LLM 判定器**（语义等价可判，但需真模型 + 它自己的三控；会消耗额度）
④ 修完再跑 **live 档 3 × 100 轮**（用户已把规模定在此），看 (d) 是否稳定为 0。
```
