## 1. 先定位：失败在**哪一层**（这决定修哪里）


## 2. 三层修法（由弱到强，**可叠加**）

### 第 1 层 —— **prompt 标签**（最便宜，且明确在仓库既有边界内）

```text
做法：当检索结果里**该槽位没有任何可采信证据**时，在 prompt 里加一条**显式约束**：
  「本轮该槽位**无可采信依据** ⇒ 只可说明"没有依据"或**反问澄清**；**不得给出具体取值**。」
      并在**主体不明**时把候选主体列出、要求先澄清。
依据：本仓库的机械保证边界就是"**采信 / 排序 / prompt 标签**"（`DR-11`）⇒ 标签是**在范围内**的。
⚠️ 局限：**保证是软的** —— 模型可能不遵守（本 case 正是"标签存在但被忽略"的那类）。
⇒ 它**降低**发生率，**不消除**。
```

### 第 2 层 —— **答前校验（verify-then-answer）**（较强，且量具已就位）

```text
做法：把**已经过三控验证**的 `m9.5-live-judge-llm@1`（**7/7**）用在**生成之后、展示之前**：
  ① 判"回复是否断言了本轮证据不支持的取值"；
  ② 若判为"有" ⇒ **不展示该回复**，改为**确定性澄清模板**（或**重生成一次**，仍不过则澄清）。
为什么这不是 `DR-11` 禁止的"措辞启发式守卫"：
  它判的是"**断言 ↔ 本轮证据集合**"的**集合关系**，不是"某个词出现了没有" ——
  这正是用户 2026-09-28 更正的判据形态。
成本：每轮 **+1 次调用**（判定器）；重生成再 +1。
⚠️ 必须先证明它**不空转**：现有负控（无依据却断言 ⇒ 必判关键错误）已证明；需**再补**一条
  "**该放行时必须放行**"的正控（有依据的断言 ⇒ 不得被拦），否则修复会退化成"一律澄清"。
```

### 第 3 层 —— **结构层：主体不明时**不生成答案**（最强，但是**产品取舍**）

```text
做法：当**主体无法由证据确定**时，**确定性地**走"澄清"分支（模板），不进入自由生成。
性质：把"她可能编造"变成"她不会编造"，代价是**能力下降**（有些问题她会答得更保守）。
⚠️ 难点：**"主体不明"的判定本身**需要来源 —— 语料里靠 `sceneEvidence` 给出候选主体；
  生产里要么靠**证据集合为空**这个机械信号（好办），要么靠对**问句**的判断（那又回到措辞层）。
⇒ 因此第 3 层只能对**"证据为空 + 槽位存在"**这种**机械可判**的情形生效；
  "问句是否含糊"**不能**作为机械判据（否则就是措辞启发式守卫）。
```

## 3. **反作弊约束**（必须与修法同时声明，否则修复会变成"骗过门槛"）

```text
① **不得只对本 case 生效**：修法必须是**一般性**的（任何"该槽位无证据"的轮次都适用），
   不得出现"识别到 ambiguousSubject-0002 就澄清"这类**按用例特判**。
② **必须同时守住 (a)(b)**：一个"**一律澄清**"的修法能轻松让 (c)(d) 归零，
   但会让**可答题**答不出来 ⇒ (a)(b) 崩掉。⇒ **四门槛合起来本身就抵抗这种平凡修法**
   —— 这正是必须**四门槛一起判**、不许只看 (c)(d) 的理由。
③ **量具先于修法**：第 2 层依赖 LLM 判定器 ⇒ 它的**正控（该放行时必须放行）必须先补**，
   否则"修好了"与"判定器把合法回复也拦了"在输出上分不开。
④ **修后必须重跑同一门**（32 条 · 8/类），并**保留修前读数**（不回写历史）。
```
