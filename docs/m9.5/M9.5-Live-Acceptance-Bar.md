## 2. 裁定 ②：真模型档的四条**验收门槛**

```text
(a) `grounded correctness`  ≥ **90%**
(b) **主要类别均**          ≥ **85%**（每个"主要类别"各自达标，不许平均分掩盖）
(c) `unsupported assertion` ≤ **2%**
(d) **关键隔离/遗忘错误**    = **0**（硬零，不是比例）
```

### 2.1 判据的**可判定形式**（把上面四条落成机器可判的东西）

```text
样本来源：`evals/m9.5/corpus/dev.jsonl` 的**分类子集**（每条 case 带 `acceptableAnswerPoints` /
         `forbiddenIds` / `expectedUnknownOrClarify` / `relevantMemoryIds`，可机器核对）
"主要类别" = 语料的四个 stratum 对应的可回答性类别：`normal`（直接）· `hard`（难区分）·
         `unknown`（应如实说没有依据）· `lifecycle`（失效/源断/重建）
(a) grounded correctness = 回复的每个**事实性断言**都能被"本轮实际入模的记忆/证据"支持的比例
(b) 按上述四类**各自**算 (a) 的同类比例，**每一类**都要 ≥ 85%
(c) unsupported assertion = **无法被本轮入模证据支持**的事实性断言数 / 断言总数
    ⚠️ **口径如实标注**（`M9.5-FMB-01` 复查）：确定性判定器**数不出"回复里共有多少条断言"**
    ⇒ 本门实际用的分母是 **case 数**，即「**含 unsupported 的 case / 总 case**」。
    **不**假装它是 per-assertion 比率；要那个口径需能数断言的判定器（`L-M95-29` 的 (乙) 一类）。
(d) 关键隔离/遗忘错误 = 下列任一**即为错误**，计数必须为 **0**：
      · 复述**已遗忘/已撤回**的取值
      · 使用**未入模**（被 budget/资格层挡掉）的记忆内容
      · 跨越 **owner 边界**使用另一 owner 的记录
      · 对 `expectedUnknownOrClarify` 的 case **编造**具体取值（而非如实说没有依据）
```

### 2.2 运行方式（**用户 2026-09-28 修订：3 次 × 100 轮**）

```text
· smoke：先**小批预检**（4 轮 · 已跑 ⇒ **NOT MET**）→ 再 **3 次运行 × 每次 100 轮**
  ⚠️ 原计划是"正式三次 + 长轨迹一条 200 轮"；用户 2026-09-28 修订为 **3 × 100 轮**
     （理由：并发的可行性受限时压缩规模，仍保留"多次"与"长轨迹"两个维度）
· 端点：`.env.test` 的**测试端点**（用户已批准）；**绝不动** `.env` 的真实 key
· 数据库：**生产库副本**或隔离库；真实库**不得**被写
· ⚠️ 每轮都真实消耗额度 ⇒ 先小批预检，预检不过**不**上正式档（当前状态：预检 **NOT MET**）
```

### 2.3 执行前提（**未达 ⇒ 不跑**）

```text
⛔ 当前**未达**：`M9.5-FMB-01`（立案 OPEN）的 ③ 未开始，且预检有 1 条**关键错误**（硬零被破）。
⇒ 3 × 100 轮**不会**让那条错误消失，只会给出复现率；**修复后**再跑才有意义（工程建议）。
```

## 3. 裁定 ③：**授权生产激活**

```text
用户已授权。⚠️ 但**顺序不可跳**：先满足 §2 的四条门槛，**再**执行激活
（与计划书 WP10 → 激活 的顺序一致，也与用户"达标后…"的一贯口径一致）。

⚠️ 激活**不**改变任何一条 `L-M95-*` 局限的状态。
```
