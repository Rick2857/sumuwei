### 2.3 验收契约冻结了什么

- **质量线**（9 项，含 200+ 负控全对、关键泄漏 0、Recall@20 ≥95%、Semantic-only ≥90%、
  Context Evidence ≥90%、grounded ≥90%（主要类 ≥85%）、无据断言 ≤2%（关键场景 0）、

  50k 仅容量观察；必须报告的 7 类资源字段）；
- **失败分类**（语料相关 6 类 + 组件工程 8 类，含 `canceled_no_reclaim`）；
- **S01–S60** 场景矩阵（ID 冻结，禁止运行后换含义）；
- **模型与参数的冻结指纹**（model / dtype / 维度 / pooling / 前缀 / tokenizer 指纹 /

- **语料规格**（600 条 / 240-120-240 拆分的**分组不泄漏**纪律 / 金标 17 字段冻结 /
  ≥200 机械负控与行为语料**不混分母** / 标注判命题关系不判词形）；
- **命令清单**（计划 §16.1 的 22 条逐条登记现状：4 条已存在、18 条未创建）；
- **量具有效性约束**（三段式 + `measured_count>0` + 人工核对 ≥30 例 + gold 与执行分离）。

### 3.1 C4 的设计要点（**自我审查抓到两个缺口**）

```text
第一版三段式表面全过（6 条对照 100%），但自查发现它**测不到两件事**：
  缺口 A：没有任何对照验证 `selected` ≠ `actual in model`
          —— 每一条都同时改 selectedIds 与 contextIds ⇒
             一个把两个指标合并的判定器**照样全过**（而那正是计划 §14.3 禁止的混用）。
  缺口 B：没有任何对照验证 `insufficient` 这一档
          —— 判据是"别是 correct"⇒ 一个把"覆盖不完整"判成 `wrong` 的判定器抓不到
             （后果：把"索引有缺口"记成"检索错了"）。
⇒ 补 `selected-but-not-in-context`（期望 **`correct/wrong`** 非对称）·
  `partial-coverage` · `authority-unavailable`（期望 `insufficient`），
  并把**所有**对照的判据从"别是 correct"改成"**精确等于声明的期望三态**"。
收尾读数：**9/9 对照按精确期望判定**，无 vacuous（适用 0 条的对照算失败，不算通过）。
```

```text
实测它真的在工作：`m9.5-corpus@1` 有 6 个候选（同一 head），正确选中权威档 `…-b466`。
```
