## 0. 先读结论

M9.5 要解决的用户问题是：**我换一种说法，或者隔了很久再提，她仍能找到相关、有效、有来源的长期记忆；更正和遗忘以后，不把旧内容重新当作当前事实。**

推荐实现路线：

1. 保留原有账本、Memory 事件、投影、资格判定、来源边界与 ContextCompiler。
2. 优先使用现成的本地多语言嵌入模型，把已被正式接受的记忆编码为可重建的检索索引。
3. 优先复用现有 PGlite 所加载的 pgvector；先使用精确向量检索，只有规模实测证明必要时才启用近似索引。
4. 原词面检索与新语义检索共同产生候选；**向量相似度只决定相关性，不决定真实性、权限或当前有效性**。
5. 对候选回查权威 Memory 与根证据，经过原资格链，再排序、去重、预算选择、入模前复核。
6. 建立新索引的增量更新、重建、更正失效、遗忘屏蔽、版本切换和回滚机制。
7. 用独立盲测、真实聊天链、长轨迹和故障注入证明收益，不以“接上一个向量库”作为完成标准。

**首选组合**：`Transformers.js / ONNX 现成推理运行时 + 多语言 E5 小模型候选 + 现有 PGlite/pgvector + 原 Recall 管线`。

这是经过项目约束筛选后的**首选 PoC 组合**，不是预先宣布它足够好。模型质量、Windows/Node 22 兼容性、CPU 延迟、内存占用及许可证必须在 WP1 实测后冻结；达不到标准，按 §6 的次序升级方案。

不从零开发嵌入模型、向量引擎或通用记忆平台。项目自行实现的部分限定为：现有权威状态与检索组件之间的必要适配、失效传播、组合排序和证据记录。

### 2.3 不可误读

- ElizaOS 使用过 embedding、库中存在向量类型，不代表 Kernel 长期记忆已支持语义召回。
- 取回一个意思相近的旧值，不代表它当前仍有效。
- M8.5 判定“话语如何影响情绪”，不为用户事实提供新的根证据。
- 同一条 Memory 被十个相似问法命中，不是十份独立证据；不能增加 M9 的推断支持数。
- M9.5 建旧记忆的派生索引，不等于获准把旧 Memory bootstrap 为 M9 Belief。

## 3. 产品目标、范围与非目标

### 3.1 六项必须交付

| ID | 用户可见能力 | 合格例子 | 不合格例子 |
|---|---|---|---|
| P1 | 换说法能想起 | 已记“在写毕业论文”；问“最近那个学业项目”能取回 | 必须重复“毕业论文”才命中 |
| P2 | 相近事实能区分 | “不吃辣”与“喜欢辣”含义不同；返回正确证据 | 用最高相似度覆盖否定词或人物差异 |
| P3 | 隔很久能取回 | 60/200/500 轮后仍可检索有效事实 | 只靠 Recent 窗口，重启后失败 |
| P4 | 更正长期有效 | “之前学校说错了”后持续使用更正值 | 新值写进去了，回答仍从旧向量/摘要拿旧值 |
| P5 | 遗忘贯穿各读取面 | 撤回后当前轮、后续轮、重启与重建均不供给旧内容 | 主表已撤回，缓存、向量或摘要继续漏出 |
| P6 | 结果可查、边界诚实 | 能区分未命中、未覆盖、不可用、被资格排除、预算裁掉 | 后端故障说成“你从来没告诉过我” |

### 3.2 v1 覆盖集合

- 语言主域：中文自然对话；中英文混合实体、数字、缩写列专项。多语言泛化只报告，除非 WP2 正式纳入并冻结语料。
- 记忆源：**已由 Memory Policy 接受的 MemoryRecord**。四类既有 Memory 的查询资格沿用原政策；缺乏可用渲染与足量评测的类型不能被无声排除，须列覆盖清单。
- 视角：当前单 Character / 单 active user 生产形态；隔离测试必须有至少两 owner、两 subject。
- 时间：当前事实、历史事实两种既有意图；模糊时间不能靠 embedding 推断为确定范围。
- 规模：主要验收规模拟为 500、2,000、10,000 条有效/历史混合记录；50,000 条作为容量观察档，不自动成为交付承诺。
- 生命周期：创建、更正、supersede、retract、dispute、合法 restore、根资格变化、重放和副本恢复。
- 消费：现有聊天 Recall 与其 ContextCompiler；M9 依赖直查保持原路径。

### 3.3 不属于本阶段

1. 自动从整段对话提炼并永久写入新事实；不接通 `CHARACTER_MEMORY_BACKGROUND_ENABLED`。
2. 从暗示推断心理、身份、价值观等开放画像；不扩大 M9 的有限推断槽位。
3. 自动把搜索结果、assistant 输出、摘要、情绪评估或检索缓存变成长记忆。
4. 替换 Memory 的事实账本、主键、归因、放行口或事件历史。
5. 多用户渠道上线、微信/QQ、Shell、MCP、任意后台自主行动和云部署。
6. M10 Goal / M11 Reflection 的实现；只交付它们应继承的读取契约与用例。
7. 对历史账本的物理擦除承诺；语义遗忘与法定数据删除不是同一验收项目。
8. 无限规模、所有语言、任意同义句、永不编造等不可由本次测试证明的主张。

### 4.4 交给 M10/M11 的稳定边界

1. 检索请求带明确 character、user/subject、查询目的、时间范围、预算和调用版本。
2. 返回的引用可追溯到当前 Memory ID、版本和证据；不返回可直接当“新事实”的摘要文本。
3. “没找到”不是反证，“相似”不是蕴含，“多次取回”不是独立证据。
4. M10 读到偏好可以作为目标规划的输入，不等于用户授权执行或新承诺。
5. M11 读到过去经历可以形成独立待审反思提案，不得直接把索引文本写回长期状态。
6. 后续异步工作在真正使用引用前必须再次回查有效性，不能长期持有一次检索时的授权快照。
7. 用两个纯 fixture consumer 验证以上规则；不创建 Goal/Reflection 的空生产服务。

## 5. “现成方案优先”的选型原则

优先级不是按产品名气，而是按：**不侵占事实权威 → 达到中文语义质量 → 可回退与可测 → 本机可运行 → 新增维护负担低**。

### 5.1 现成组件与自有代码分工

| 层 | 优先复用 | 必须由项目控制 |
|---|---|---|
| 文本编码 | 现成多语言 embedding 模型、tokenizer、ONNX/Transformers.js | 输入范围、版本、离线缓存、异常与超长处理 |
| 向量存储与搜索 | 已有 PGlite/pgvector | Memory ID 映射、namespace、派生版本、失效与恢复 |
| 词面召回 | 原 `lexicalOverlapHits` 与既有通道 | 不复制另一份中文词面算法 |
| 候选资格 | 原 eligibility、qualification、完整性探针 | 不能由后端分数代替 |
| 重排 | 现有排序器；需要时采用现成 reranker | 分数解释、阈值、权威降档和时间政策 |
| 上下文 | 原 selector/render/ContextCompiler | 实际入模集合、组合预算、来源标签 |
| 评测 | 原隔离 harness、manifest、回归工具 | 新语料、独立金标、新性质的正负控 |

### 5.2 方案比较与当前建议

| 方案 | 可复用能力 | 代价/边界 | 本阶段结论 |
|---|---|---|---|
| 现有 PGlite/pgvector + 本地 embedding | 利用现有 SQL/生命周期与现成向量搜索 | 需要追加派生表、确认锁定版本兼容；本地模型质量待测 | **首选** |
| Qdrant + 本地 embedding | 独立向量服务、过滤、混合查询能力 | 新服务与备份运维；跨库一致性与故障面增加 | **条件备选**：首选确因规模/能力不足失败才比较 |
| 外部 embedding API + 本地索引 | 降低本机推理负载 | 私人记忆和查询可能出站；模型指纹、成本、可用性需另验证 | **非默认**；若转用，先明确授权与出站范围 |
| Mem0 | 现成记忆提取、更新与检索流程 | 与现有 Memory/M9 的状态主权重叠 | **不整体接管**；仅在窄检索模式有实证优势时重开比较 |
| Graphiti | 时序图、实体关系与混合检索 | 增加图构建/事实提取与另一时序语义体系 | **v1 不引入**；当前需要先解决已存事实的问法覆盖 |
| MemOS 等完整记忆平台 | 存储与记忆处理能力候选 | 仓库已有特定旧插件被拒记录，不能忽略政策绕过问题 | 不重装历史被拒插件；新版须全新准入，不沿用泛化拒绝或泛化通过 |
| 全量 Memory 塞入 prompt，让 LLM 选 | 快速原型方便 | 隐私、预算、成本、规模与审计不可控 | **否决** |
| 手写近义词大全 | 小范围修补快 | 覆盖脆弱，无法交付开放改述召回 | 只允许用于已有明确别名契约，不充当本项目完成方案 |

官方能力依据：PGlite 的扩展加载见 [API 文档](https://pglite.dev/docs/api)；pgvector 提供精确及近似搜索，近似检索存在召回取舍，见 [项目文档](https://github.com/pgvector/pgvector)。Qdrant 的混合查询与融合能力见 [官方文档](https://qdrant.tech/documentation/search/hybrid-queries/)。这些是组件能力说明，不证明本项目已经兼容或取得收益。

Mem0 官方说明区分带推断和不带推断的写入方式，但“关闭推断”本身不足以证明它保留本项目全部资格和生命周期，见 [官方流程说明](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/how-it-works.mdx)。Graphiti 的时序图和混合检索能力见 [官方仓库](https://github.com/getzep/graphiti)；v1 不采用是本项目的范围选择，不是宣称它没有溯源或时间能力。

### 5.3 现成方案准入硬条件

- 保留原 Memory ID、owner、subject、来源引用与当前状态的读取能力。
- 支持查询与索引写入分离；不能隐式捕获对话、自动注入 prompt 或自行形成记忆。
- 模型/索引不可用时，聊天能以明确降级状态继续；权威查询失败不得放行缓存事实。
- 不把秘密、正文、完整向量塞进 telemetry、公共测试证据或错误日志。
- 可固定版本、许可证与文件摘要；移除组件后原生 Memory 不损坏。
- 能在隔离库中重建、恢复和验证，不要求用真实历史做首次试验。
- 不为选型而同时长期维护三套后端；冻结后只有一个正式实现，其他仅保留比较证据。

## 6. 模型、检索引擎与 PoC 决策

### 6.1 模型候选顺序

**A：`intfloat/multilingual-e5-small` 的现成 ONNX 发行候选**。

原模型卡给出 384 维表示及 query/passage 前缀要求；已有 `Xenova/multilingual-e5-small` 的 Transformers.js 使用入口。它适合作为低运维、CPU 路线的第一候选，**中文效果、量化损失与当前 Node 22 的实际加载结果待测**。[原模型卡](https://huggingface.co/intfloat/multilingual-e5-small?hardware=ryzen-ai-max-395-128gb) · [ONNX 使用入口](https://huggingface.co/Xenova/multilingual-e5-small)

**B：`BAAI/bge-m3` 质量比较候选**。

官方模型卡列出多语言、1024 维等特征，可用来检验小模型是否遗漏关键中文改述。只有已验证的现成运行方式进入 PoC；不为它在本阶段自行训练或维护模型转换工具链。[模型卡](https://huggingface.co/BAAI/bge-m3)

候选数先限于这两组；若两者均达不到冻结质量/性能要求，记录失败类别再决定第三候选，不开展无上限模型竞赛。不能把老验收报告里的 bge-m3 名称当作现在服务可达的证明。

### 6.2 本地运行纪律

- 使用现成 Transformers.js/ONNX 运行时；版本选定后锁定 package 与模型 revision、tokenizer、pooling、normalization、dtype。
- 首次下载属于模型资产安装；记录来源、许可证和校验值。它与把私人文本发到云端推理是不同的数据流。
- 正常运行默认仅加载本地模型，关闭运行时远端自动下载；模型缺失时如实降级，不临时改走云服务。
- CPU 作为最低可复现档；GPU 只是可选加速，不能成为没有验证的隐含依赖。
- 推理放在现成 worker/隔离执行机制可控的边界；必须实测取消/超时能回收工作，不能只有 Promise 超时而底层继续占满 CPU。
- `retrieve()` 的查询编码只存在内存，不在其中创建磁盘模型缓存、索引表或查询正文缓存。模型预置与索引维护另走明确流程。

Transformers.js 的任务支持见 [官方文档](https://huggingface.co/docs/transformers.js/en/index)，本地模型路径和关闭远端加载见 [环境配置](https://huggingface.co/docs/transformers.js/v3.8.1/api/env)。这些说明不替代本机兼容性测试。

### 6.3 pgvector 接入分支

1. 在现有锁定依赖的隔离库确认扩展已加载，查询扩展版本与所需 SQL 能力；不在真实库首次执行 DDL。
2. 检查 pgvector 与现有驱动的参数绑定、向量维度、批量写、事务、重启及异常表现。
3. 首版使用精确搜索作为质量基线；在约定规模内以实测确定性能是否足够。
4. 只有精确搜索超出冻结 SLA 时才比较 HNSW/其他已支持索引；以精确检索作为 ANN Recall 的 oracle。
5. 官网目前展示的扩展包导入形式与本项目安装版不同，不能照抄最新示例并顺手升级 `plugin-sql`/PGlite。
6. 若必须升级依赖，拆出兼容性变更，重新验证 INC-01、迁移、备份恢复与全链；不能塞进一行 lockfile 更新。

### 6.4 PoC 矩阵与停止规则

| 对照 | 固定部分 | 变化部分 | 回答的问题 |
|---|---|---|---|
| A0 原词面 | 数据、查询、预算、语言模型 | 无 | 真实基线 |
| A1 E5 + 精确向量 | 同上 | 增加语义候选 | 小模型能否解决改述 |
| A2 混合召回 | 模型与数据固定 | 词面+向量组合 | 是否保住字面精确命中 |
| A3 BGE 候选 | 同一开发/验证集 | embedding 模型 | 质量增益是否值得资源成本 |
| A4 可选 reranker | 同一候选集合 | 最终相关性重排 | 难负例改善是否足够 |
| A5 可选 ANN | 同一向量与查询 | 精确→近似索引 | 速度收益与召回损失 |

- WP1 只用开发集与小型安装 smoke，不窥视正式盲测标签。
- WP2 冻结验收；WP6 在验证集定阈值。正式盲测后不反复调参刷同一份成绩。
- 达到要求就停止增加组件；reranker、Qdrant、GPU、第二 provider 都不是必备清单。
- 失败退出条件：资格/遗忘绕过、必须外发未授权私人文本、不可控资源占用、无法可靠回退。此时不得以平均召回率掩盖。

## 7. 目标架构与唯一读取链

```text
合法 MEMORY_* 已提交事件 ──→ 有界索引维护器 ──→ 派生向量/版本/水位
          │                                      │
          └──── 权威 Memory 与根证据 ──────────────┤
                                                 ↓
用户本轮原话 → 原意图/目标解析 → 词面候选 + 语义候选（只读）
              ↓                         ↓
           时间/主体约束            按 Memory ID 合并
                                        ↓
                     回查当前权威状态 + 根资格 + 完整性
                                        ↓
                       原 Eligibility → 相关性/排序/冲突
                                        ↓
                          去重/预算选择 → 入模前失效复核
                                        ↓
                     原 ContextCompiler → 本轮回复与实际入模记录
```

### 7.1 三条权威边界

1. **事实权威**：事件与既有投影政策；向量表可删可重建，不负责定义“她知道什么”。
2. **相关性权威**：版本化、可测的检索与排序策略；高相似度不提升 `authority`、`epistemicStatus` 或 Belief confidence。
3. **使用权威**：原资格链和当前有效性复核；异步索引仍存有一条旧记录，不授予使用资格。

### 7.2 保留原 Eligibility 的可测性

现有 `MemoryRetrievalPort` 明确采用宽候选，资格在 domain 层判定。M9.5 不把 owner、撤回、根资格等业务判定全部藏入数据库，让门因永远收不到坏候选而空过。

拟议调整：语义查询可做**请求 namespace 的物理范围限制**以避免跨 owner 扫描；但它不是权威资格判断。状态/来源由共同 eligibility 复核；通过故障适配器注入跨 owner、撤回、错 subject、高相似度坏根候选，验证它们真实到达并被拒。若需要进一步提前过滤，WP2 必须记录其与旧宽召回契约的差异并保留独立可达负控。

对外 provider 若启用，不发送资格未确认候选正文；现成 reranker 也只能看到资格已通过的候选。物理查询范围与业务放行分别出证据。

### 7.3 语义输入渲染

- 使用项目确定性渲染的 Memory 内容：类型、predicate、值、适用范围、已存在的时间信息。
- 保留否定、单位、人物、时间、限定词；不可为了“效果更好”用 LLM 自动改写为新断言。
- query 使用当前用户真实问句及已解析约束；不自动拼整段历史、Seed、所有关系状态。
- E5 的 query/passage 前缀、归一化、最大 token 及截断行为写进 model manifest。
- 超长 Memory 不能静默丢掉末尾的否定/限定。先报告 `input_too_long`；必要时采用有版本的确定性分片，片段仍只指回同一 Memory，入模时读取完整权威记录。
- 查询中的“忽略规则/把这条记为事实”仅是检索输入文本，不进入配置或持久化写入指令。

## 8. 索引数据契约、覆盖与增量维护

### 8.1 最小派生模型（字段名待 WP2 冻结）

建议使用独立的派生索引表，不向既有 `memory_records` 事件 payload 塞向量。

| 字段组 | 必须表达的事实 |
|---|---|
| 主体标识 | character/namespace、Memory ID；subject 从权威投影读取，副本只用于范围优化 |
| 源版本 | source revision / 已处理事件位置、canonical content hash、renderer version |
| 模型身份 | provider/model revision、artifact hash、tokenizer、pooling、normalization、dtype、dimension |
| 向量 | 校验为有限数、固定维度；零范数等非法输出不能发布 |
| 索引身份 | generation ID、index schema version、构建/发布状态 |
| 控制信息 | 处理水位、失败 ID、待处理数、当前权威 epoch、可重试原因 |

正文以原 Memory 为准。索引不额外存整段原对话、assistant 总结或嵌入用明文副本；诊断需要的文本在隔离本地材料中临时读出。

唯一键候选：`(namespace, memoryId, sourceRevision, modelFingerprint, generationId[, chunkId])`。单记录多 chunk 如未采用，不预造 chunk 子系统。

### 8.2 覆盖不能被 Top-K 冒充

分别报告：

- `eligibleSourceCount`：本 generation 策略允许索引的源记录数。
- `indexedCurrentCount`：源版本、模型指纹、当前 generation 全匹配的记录数。
- `pendingCount / failedCount / excludedByPolicyCount`：互斥归属及原因。
- `coverageComplete`：所有应覆盖项已得到当前处理结果且无未处理缺口；政策排除列表必须独立给出。
- `candidateLimit / returnedCount / scannedRows / filteredCount`：本次查询规模，不能代替全库覆盖率。

索引构建读取采用稳定排序与 keyset 分页，不复用 `list(limit<=500)` 然后假称全量。每页有上限，整轮有工作预算和持久游标；全量覆盖通过多批完成，不在一次聊天请求里扫完整库。

### 8.3 水位和发布

1. 从一致快照或明确边界 W 开始构建 generation。
2. 按 Memory ID/版本建立待处理集；处理结果落盘后才推进**连续已处理水位**。
3. 第 40 条失败、第 41 条成功，不得把水位直接写为 41 并遗漏 40。
4. 构建期间的新事件在 W 之后追赶；追赶稳定并核对 source hash/资格变更后才能发布。
5. 发布时原子切换 active generation；旧 generation 保留只为有限期回滚，不作为并行真源。
6. 模型变更建立新 generation，禁止不同模型空间或不同维度混排。
7. `published` 不等于永远完整；新记忆未索引时显式报告 pending，并保留原生词面读取。

### 8.4 日常更新

- 已提交 Memory 事件触发有界派生维护；沿用现有应用/调度习惯，不新增自主 Agent。
- 查询调用只读。主对话先完成合法 Memory 写入及失效屏蔽，再异步维护索引；索引失败不能反向撤销已合法提交的事实。
- 新记忆的语义新鲜度单独冻结 SLA；未同步时用原词面路径，不能宣称语义全覆盖。
- 如需持久维护任务，复用现有 durable job 的状态模型；不得直接复用 M9 job kind 并更改其水位。
- 闲置恢复、重启重试都要有工作上限、幂等键与 failed 终态；不能留下永久 running 楔死任务。

## 9. 查询、融合、排名与拒答

### 9.1 查询步骤

1. 原解析链确定 owner、subject、intent、timeScope；身份缺失或目标不能确定时沿用失败关闭/澄清。
2. 读取当前模式、模型指纹、generation 健康度与状态 epoch。
3. 独立取得旧词面候选、新语义候选；禁止先把全库截成最近 500 再向量排序。
4. 按 Memory ID 合并通道与证据，不把多通道命中当多条 Memory。
5. 批量回查当前 Memory、根资格与完整性；不存在/不可读/失效的内容不使用向量缓存填补。
6. 经过现有 eligibility。语义分数不能让 retracted、wrong-user、unknown-origin 的内容晋级。
7. 对合格候选计算词面与语义相关性；执行时间、冲突组、去重政策及冻结排名。
8. 使用既有上下文预算选择；必要时通过最小相关证据保留策略减少无关状态挤占，但不能挤掉强制规则或来源标签。
9. 入模前复核本轮变更 overlay 与当前 epoch；发生变化则有界重查一次，仍无法稳定则去掉相关候选并报告原因。
10. 记录真正入模的 ID/版本/通道/分数归属，回复生成仍由原链完成。

### 9.2 排名推荐

- 默认采用**原排序政策的显式扩展**：新增已校准的 semantic 分量与“词面或语义具备相关性”门槛；不删除原 authority 降档、时间与冲突规则。
- v1 先不叠加 RRF 和 reranker。若开发/验证集证明分数难以兼容，再把 RRF 作为一个有版本的融合候选比较；不要同时运行多套不可解释加分。
- 向量原始余弦值不是置信概率。阈值按模型/量化/语料校准，不能把 0.8 当跨模型统一“80% 可信”。
- semantic available 只在本次实际得到合法分数时成立；not indexed、timeout、model missing、dimension mismatch 各有不可用原因。
- 已纠正事实的当前有效版本由生命周期决定，不由新旧向量谁更像决定。
- 精确实体、数字、编码等词面强项单列不退化集；不能只报告改述集合改善。
- 稳定排序的最后 tie-break 使用稳定 ID，不使用数据库返回的偶然顺序。

### 9.3 明确的新结果状态

| 状态 | 程序含义 | 用户可见口径要求 |
|---|---|---|
| `available_hit` | 找到并有内容实际入模 | 可以依据该记忆回答，保留来源/当前状态边界 |
| `available_no_match` | 本次覆盖及检索完成，未达相关性阈值 | “这次没有找到相关记录”，不证明用户从未说过 |
| `partial_coverage` | 有索引缺口或新记忆待同步 | 不把未命中解释为不存在 |
| `degraded_lexical` | 语义路径不可用，旧路径仍有效 | 不宣称本次完成了语义检索 |
| `source_unavailable` | 权威回查失败 | 不使用旧向量中携带的文本作为替代事实 |
| `excluded_or_budgeted` | 找到但资格拒绝或未入模 | 诊断面分别记录；不得向普通回复泄漏被遗忘内容 |

除非现有回复真相契约要求，不为每句话追加技术提示。日常对话保持自然；用户明确询问“有没有查到记忆”时，回答必须与本次程序状态一致。

## 10. 更正、遗忘、历史查询与长程一致性

### 10.1 生命周期矩阵

| 权威变化 | 派生索引动作 | 本轮读取动作 | 必须保留的区别 |
|---|---|---|---|
| CREATED | 按新版本排队编码 | 旧通道可立即读取，语义待同步如实标记 | 已保存不等于已完成语义索引 |
| SUPERSEDED | 旧项不再参与当前事实；新项排队 | 当前问题使用新值；明确历史意图按原历史政策读取 | “当时为真、后来变化”与“之前说错”原因不同 |
| RETRACTED（遗忘） | 删除/停用对应派生向量，失效缓存 | 同轮屏蔽优先于异步删除完成 | 保留账本审计不等于允许从历史检索重现 |
| DISPUTED | 索引可留技术引用，但状态不是确定当前事实 | 沿用原争议表达与资格政策 | 不让相似度替争议裁决 |
| RESTORED | 按最新源版本重评并重新建索引 | 只有合法恢复后的资格才可使用 | 不能恢复 M9 仍被禁用的根所支撑的 belief |
| 根资格降档/来源缺失 | 标记 dirty，回查后更新 | 当轮重新派生资格，不用旧来源标签 | provenance hash 相同不代表当前资格不变 |
| 主库从副本恢复 | 检查事件前沿/快照身份，原索引转不可用待核对 | 匹配前仅原生路径 | 较“新”的派生索引可能来自恢复前未来，不得倒灌 |
| 模型/renderer 更新 | 新 generation | 旧 generation 只在合法兼容时继续用 | 重新编码不是新经历或新记忆形成 |

### 10.2 同轮与并发边界

冻结一个明确的“使用判定点”：ContextCompiler 接受最终证据集合之前。

- 同一轮已提交的纠正/遗忘必须先进入 invalidation overlay；索引维护尚未完成也不能漏出。
- 查询过程中发生状态变化，在最终判定点重新核对 epoch/相关 ID。采用短事务快照或乐观版本复核，不跨模型推理等待持有数据库长事务。
- 跨会话并发语义必须在 ADR 中定义；不承诺已经发出的回复可以被后来的遗忘撤回。
- 测试注入“取候选后撤回”“读源后更正”“等待 embedding 时切换 generation”“编译前根降档”，确认使用集合符合冻结的先后关系。
- 如果无法证明候选仍有效，排除该候选；但需有正常正控证明不是把所有记忆永久关闭。

### 10.3 M9 的禁用根不得复活

保留 M9 的三个区别：

1. Memory dependency invalidated 触发的信念撤回，不必等同于用户要求永远禁用全部根。
2. 用户显式遗忘 belief 的禁用根，是持久事件承诺，不因索引重建、根资格恢复而消失。
3. 用户以后用**新的合法根**重新明确告知，可沿原政策形成新记录；不能把旧缓存误当新根。

M9.5 检索只读取，不调用 `FORMED`、`RESTORED` 等认知写操作。用户“忘记那件事”的目标解析不使用 top-1 相似记忆直接执行删除；语义候选若未来参与辅助澄清，也必须走单独冻结的目标确定性契约。

### 10.4 排查“更正后旧值回潮”的八段漏斗

每个失败逐段记录：

1. 新值是否真正被接受并持久化？
2. 旧值是否正确 superseded/retracted？
3. 新值是否被完整索引，旧索引是否失效？
4. 查询是否找到了新值，还是候选范围先遗漏？
5. 资格/排名是否错误排除新值？
6. 预算是否保留旧片段而裁掉新事实？
7. Recent、rolling summary、Belief 或其它 section 是否另带旧值？
8. 实际入模已正确，模型回复是否仍混淆？

修复指向最先失败的层。第 8 类不得报成“向量索引坏了”，第 3 类也不能用加强 prompt 掩盖。涉及摘要/M9 的修复是独立可审阅切片，修改其对应门并新增证据，不静默放松原判断。

### 10.5 缓存与隐私

- 首版默认不持久化用户 query embedding，减少新的个人信息副本。
- 模型资产缓存与私人记忆向量缓存区分；模型资产可以长期缓存，用户内容派生物跟随生命周期。
- 任何检索结果缓存如确需引入，键至少绑定 namespace、query fingerprint、source epoch、generation 与 policy version；遗忘后旧键不可使用。
- trace 不落正文、向量数组、模型输入、访问密钥；普通错误堆栈不得包含整条 SQL 参数。
- 向量仍按敏感派生数据保护，不以“不是明文”声称匿名。
- 废弃 generation 的清理是可审计派生清理，不删除权威历史；磁盘安全擦除不属于此处保证。

## 14. 数据集、金标、指标与阈值

### 14.1 数据集建议规模（WP2 冻结）

**600 条独立查询场景**，按事实/场景族分组拆分，建议开发 240、验证 120、盲测 240。同一底层事实的近义问法不得分散到三个集合造成泄漏。

| 类别 | 数量建议 | 核心覆盖 |
|---|---:|---|
| 正常可回答 | 240 | 同义、间接指代、口语省略、上下文有界提示、中文/混合实体 |
| 难区分可回答 | 120 | 人物、时间、否定、数字、单位、项目相似、历史与当前 |
| 无答案/应澄清 | 120 | 从未保存、已遗忘、只在聊天提过、主体模糊、超出覆盖 |
| 生命周期/隔离对抗 | 120 | 旧值、错 owner、坏根、重建复活、摘要冲突、源不可读 |
| **合计** | **600** | 每集按比例分层；实际分配 manifest 可复算 |

另设 **至少 200 个机械关键负控**，主要由高分伪候选与故障注入组成；与行为语料不混为同一个分母。§15 的 S01–S60 是场景族，不是声称已有 60 条足量统计样本。

语料来源优先用项目已有合成场景和用户本次举例，补充人工编写改述；若使用真实对话片段，应在本地脱敏且明确来源，未经授权不发给外部标注/模型服务。

### 14.2 每条金标至少包含

`caseId / familyId / split / namespace / user / request / intent / timeScope / authoritativeSnapshot / relevantMemoryIds / requiredEvidenceGroups / forbiddenIds / expectedUnknownOrClarify / lifecycleSetup / acceptableAnswerPoints / modelInputRestrictions / annotator / adjudication`。

“你爱不爱吃辣？”与“不吃辣”的记忆是合法相关，不因表面正负词不同就判为负例。负例是错误主体、无关命题、过期状态被当当前事实等；标注必须判命题关系，不只判词形相似。

### 14.3 指标定义

| 指标 | 分母与计算 | 不可混淆 |
|---|---|---|
| Candidate Recall@K | 可回答查询中，gold relevant IDs 被候选集合覆盖的比例；多证据任务同时报组完成率 | k 条相似候选不等于有效答案 |
| Semantic-only Hit@K | 词面弱/无重叠改述子集中，至少一组充分 gold 证据命中比例 | 不把字面命中灌入该分母 |
| Context Evidence Success | 可回答查询中，最终模型上下文包含所需当前有效证据组的比例 | selected ≠ actual in model |
| Answer Grounded Correctness | 固定回复模型下，正确且由实际入模证据支持的回答比例 | 模型猜对但无依据不算通过 |
| Unsupported Assertion Rate | 应未知/澄清查询中，回复却明确断言未获支持事实的比例 | 与候选相关性精度分别算 |
| Critical Leakage Count | forbidden/错 owner/已遗忘/禁根内容进入本不允许的读取面次数 | 0 次只证明本次范围，不证明永远不漏 |
| Legacy Regression | 原字面强项集合中新方案与旧方案成对差异 | 不只比全体平均值 |
| Index Coverage/Freshness | 当前源版本对应覆盖比例与合法提交→可用索引时延 | 不用 row count 代替源版本核对 |

### 14.4 推荐验收线（拟议，不是成绩）

| 项 | 推荐阈值 | 判定方式 |
|---|---|---|
| 关键机械边界 | **200+ 负控全部正确，关键泄漏 0** | 任一失败阻断激活；measured_count 必须 >0 |
| 受支持可回答集 Candidate Recall@20 | **≥95%** | 总体及分层均报告；多证据组另算 |
| 改述集 Semantic-only Hit@20 | **≥90%** | 若旧基线 <90%，要求显著实质改善，目标提升 ≥15 个百分点；若旧基线已高则保持不退化并验证无词面正控 |
| Context Evidence Success | **≥90%** | 同预算；禁止通过无限增大上下文达标 |
| 真实回复 grounded correctness | **≥90%，主要类别不低于85%** | 至少三次独立运行；最差轮需达线，报告全部轮 |
| 应未知/澄清的无据断言 | **≤2%**；关键隔离/遗忘场景 **0** | 分层、分母和失败逐条公开 |
| 字面强项不退化 | 成对成功率下降 **≤1 个百分点**；关键正确 ID 不退化 | 不拿改述收益抵消关键错误 |
| 三条 500 轮离线轨迹 | **完整执行，关键污染 0，检查点当前证据全部正确** | 真实编码/固定模型信号档分列 |
| 盲审 | 至少 60 组对照，正确/有据/自然分别判 | 人工未完成就是 PENDING，不代填 |

统计比例报告 Wilson 95% 区间或同等明确方法；成对比较报告失败差异清单。有限样本的 0 不等于总体风险 0。某类样本太少时标 `INSUFFICIENT`，不能把整体大分母借给小类。

### 14.5 性能与容量

候选起始预算（WP1 测量、WP2 冻结前允许调整）：

- 同设备 CPU、模型已预热，10,000 条主规模的**新增召回链** p95 目标 ≤1,000ms；不含回复模型生成。
- 语义 query 总截止时间起始目标 2,000ms；超时降级，取消的底层工作须真实停止或在有界窗口内被回收。
- 合法 Memory 提交后，正常低负载下派生可用 p95 目标 ≤5s；更正/遗忘的使用屏蔽不等待这个时间。
- 报告冷启动耗时、模型磁盘大小、最大 RSS、维护队列峰值、DB 调用数/扫描行数、每条向量体积、构建耗时。
- 500/2,000/10,000 三档必须测；50,000 只作容量观察，若要承诺必须扩契约。

这些是产品预算建议，不是对本机性能的保证。若首选不能达到，不擅自降低质量线；比较更合适的模型/索引后在盲测前冻结新的性能契约。禁止拿全量门墙钟或 M9 SLA 直接冒充语义编码 SLA。

### 14.6 量具有效性

- 正控：明确正确证据在最终上下文且回复符合事实；判定必须识别成功。
- 负控：只改 Memory ID、owner、否定、时间或撤回状态之一；判定必须识别错误。
- 恢复：还原污染后结果恢复，证明失败是目标断言触发。
- 无词面正控、低分正确源、高分无资格源、正确否认、正确但改述的回答各有样例。
- gold 生成与执行结果计算分离；不把系统自己的 embedding 排名当标准答案。
- 人工核对至少 30 个自动判定样例；有分歧的类在量具通过前不用于结论。
- 自动判定器需记录模型/指令/输入证据面版本，不从“未告警”直接推导“无假记忆”。

只读聚合器的绿色不能替代本次代码的执行证据；也不能假设旧 `gates:run --lane summaries` 已包含 M9.5。

### 16.4 六项分列与聚合规则

| 维度 | 可取状态示例 | 不能替代它的证据 |
|---|---|---|
| Design | DRAFT / FROZEN | 已有代码 |
| Implementation | NOT STARTED / PARTIAL / COMPLETE | 计划列了文件 |
| Hard Gates | PASS / FAIL / NOT RUN / INVALID | 历史 PASS 或空集合 |
| Semantic Evaluation | PASS / FAIL / INSUFFICIENT；Human Review 单列 | 工程门全绿 |

## 18. 风险、停止线与失败处置

| 风险 | 早期信号 | 处置/停止条件 |
|---|---|---|
| 只接向量，不接真实分数 | available=true，但分数/权重仍 0 | S49 阻断；不以服务可达算能力 |
| 相近错误事实压过正确事实 | 同主体近邻负例显著误选 | 先审数据/资格/排序；必要时现成 reranker；未达质量门不发布 |
| 索引漏掉旧记录 | coverage 只等于最近 500 | 修分页与计数；不得把遗漏排除出金标 |
| 失效传播延迟 | 向量返回已撤回内容 | 权威回查和 overlay 必须先挡住；生命周期门阻断 |
| 更正后摘要带回旧值 | Memory 已正确，最终 prompt 仍有旧断言 | 对应 Summary 契约修复并回归，不把问题留给 LLM |
| PGlite 新扩展/依赖升级影响启动 | 新版仅新库可用，恢复失败 | 拆兼容变更；生产迁移前阻断 |
| Windows 本地模型资源过重 | 冷启动/峰值RSS/取消失败 | 小模型优先；测更轻量运行方式；云方案需另立出站决策 |
| 模型资产或量化版本漂移 | 同模型名实际输出空间变化 | 指纹锁定、重建 generation；拒绝混排 |
| 盲测泄漏与反复调参 | 测试集成为开发样例 | 版本化新盲测，保留旧成绩；不重跑凑数 |
| 不同回复端点结论外推 | 只测测试端点却宣称生产同等 | 端点分列，生产只按观察证据陈述 |
| M9 仍变化造成接口返工 | 依赖/禁根契约变化 | 等交接后整合；独立 PoC 不抢共享文件 |
| 结果缓存/旧快照倒灌 | 恢复后出现未来事实 | 检查 source epoch/generation；不匹配索引停用 |

发生关键来源/隔离/遗忘破坏：停止相关新路径的发布，保留失败证据；无需否定全部旧能力。发布后运行异常时先按授权操作降级/off，再排查；不能在线临时调阈值制造看似恢复。

## 19. 模式、配置、迁移与运维契约

### 19.1 拟议配置

| 配置 | 缺省 | 含义 |
|---|---|---|
| `CHARACTER_MEMORY_SEMANTIC_MODE`（拟） | `off` | `off / shadow / on`；未知值拒绝配置或显式 off，不能默认 on |
| `CHARACTER_MEMORY_EMBEDDING_MANIFEST`（拟） | 无 | 指向已验证的本地模型清单；on 缺清单时语义不可用 |
| index generation | 数据控制记录 | 不由随意字符串环境变量绕过发布门 |
| 阈值/候选数/超时 | 版本化策略文件 | 按冻结模型与数据确定；避免一串不可追溯临时 env |

不再重复创建 Memory、Belief、Summary 各自一套模式判定器。复用现有 flags 解析与启动报告；但不得将一个域的开关隐式打开另一个域。

### 19.2 三种模式

- **off**：不做语义 query，不启动模型推理；保持原读取链。已有派生表可以保留，是否执行显式维护由独立命令控制。
- **shadow**：有界执行新旧对照，实际 prompt 使用原路径；维护索引和推理成本如实记录。
- **on**：新链参与候选；任一语义依赖失败按本次状态降级；资格来源失败则排除相关事实。

切换 on 不等于模型资产安装、schema 迁移或全量建索引；这些是显式前置。普通聊天启动不能自动对真实库迁移或完整扫描旧历史。

### 19.3 schema 与数据库安全

- 首选设计预计需要新增派生表/控制记录；不把“可以重建”解释为无需迁移纪律。
- 不改 0001–0009 等既有已发布 DDL。实际新编号由开工时完整迁移链决定。
- 隔离库自动迁移读数不代表生产已应用。
- 所有实验先 `isolateDatabase()`，再动态加载数据库相关模块；不能在静态 import 已触发数据库后才设置隔离。
- 生产索引构建与迁移通过既有允许打开真实库的入口装配，沿用 INC-01 租约、已验证快照与 pre-open 控制；不另写绕过入口的脚本直连。
- 真实库前后摘要只在本次明确、可比较的时间窗口用于相应断言；正常聊天期间产生变化不应误判为实验污染，也不能跨天摘要冒充同轮未写证明。

## 20. 生产激活与回滚操作清单

以下是未来执行清单，不代表本轮已获生产操作授权。

### 20.1 激活前置

- [ ] M9 最终契约与 M9.5 对接状态已核对。
- [ ] 设计、实现、适用硬门、语义质量、真实链、人审结论齐备且有归属。
- [ ] 生产使用的模型 manifest、模式、schema、generation 与验收候选一致，差异明确列出。
- [ ] 生产副本已完成全量索引、重启、切换、故障、回滚预演。
- [ ] 真实库已按既有程序获得可验证备份和独占窗口；密钥未出现在公开材料。
- [ ] 新迁移与旧 Memory 派生索引构建的动作清单可审阅，用户明确批准对应生产动作。
- [ ] 清楚标明不进行原对话重新抽取、不启动 M9 bootstrap、不改 Seed。

### 20.2 顺序

1. **记录**：应用提交、schema、非机密配置指纹、原生 Memory canonical snapshot、备份验证结果。
2. **迁移**：显式应用新增派生 schema，校验旧 ID/原事件与投影语义未改变。
3. **建索引**：从已接受 Memory 建 generation；记录应处理/成功/失败/排除计数。
4. **追赶并核对**：验证事件前沿、源版本、更正/遗忘与待处理缺口；未完整则不宣称全覆盖。
5. **shadow**：在具名观察窗口比较新旧；正常生产观察不替代此前的隔离强制场景。
6. **切换 on**：按批准动作更新模式；记录实际生效读回。
7. **首轮观察**：实际模型/索引调用、最终入模、时延、失败/降级、维护新鲜度；没有真实流量则保持 NOT OBSERVED。
8. **回顾**：拟观察前 20 个自然发生的有效查询或三天窗口，以先获得足够证据的条件为准；三天没有查询不能自动判稳定。不在本计划阶段创建定时自动化。

### 20.3 回滚

优先操作：模式设为 `off`，停止语义 query 与自动派生维护，保持原 Recall；保留新增 Memory/Belief/对话事件。

- **不默认还原整库备份**，否则会丢掉激活后正常发生的历史。
- 新派生表可保留不可用状态；generation 清理稍后按具名维护执行。
- 若源数据已损坏，按 INC-01 独立事故流程处理，不把索引关闭包装成已修复数据。
- 回滚验证：原聊天可用、原 Memory 状态/新历史保留、semantic 调用 0、模式读回 off、未自动回升 on。
- 已经发送给模型或用户的内容不能通过本地回滚撤回；这一边界不作额外保证。

### C.2 选型裁定（回答 §5.2「哪种最适合」）

`v1` 的结论是**一种首选 + 一种窄附带 + 一种带具名触发条件的备选**，其余关闭：

| 方案 | 裁定 |
|---|---|
| 现有 PGlite/pgvector + 本地 embedding | **v1 唯一首选**（同 §5.2，并追加 C.3 前置） |
| 手写近义词大全 | **仅**允许作为已有明确别名契约处的窄附带，不充当完成方案（同 §5.2） |
| Qdrant + 本地 embedding | **条件备选**，触发条件见 C.4（T1–T3） |
| 外部 embedding API + 本地索引 | 非默认；边界见 C.5 |
| Mem0 / Graphiti / MemOS 等平台 | 不整体接管 / v1 不引入 / 新版须全新准入（同 §5.2） |
| 全量 Memory 塞入 prompt | 否决（同 §5.2） |

本条**不推翻** §5.2 任何一格；它只把「首选为何在当前情况下近乎唯一」的依据固定下来。

### C.3 首选的准入前置（WP1 必须回答；未回答不得认定「引擎已就绪」）

**R1 ——「扩展装着」必须真查，不能从代码推断。**
因为 C3 的失败路径只 warn，WP1 必须直接查 `pg_extension`（扩展名与版本），
而不是引用「初始化代码里有 vector」。§6.3 第 1 条已要求此动作，本附录把它标为**不可跳过**。

**R2 —— 只借引擎，绝不复用 `plugin-sql` 的 `embeddings` 表。**
该表挂在 ElizaOS 的 `memory_id` 空间上（C4）。复用它等于把另一套 memory id 空间
引入 Kernel 记忆读取面，会与 M5.1.1 的归因、M9 的资格与禁用根形成不可审计的耦合。
§8.1「独立派生表」由此从设计偏好升级为**准入条件**。

**R3 ——「标 available」与「有真实分数」必须是同一步。**
当前 `semantic` 权重为 `0`（C6）：只把通道加进枚举、或只把能力报告改成 available，
会得到一个**永不参与、却在 trace 里看起来已启用**的通道 —— 这种伪启用正负控都测不出来。
WP6 必须让二者同时成立，并让负控能检出「available 为真但无分数」。

**R4 —— 新增依赖面如实登记。**
现无任何相关依赖（C8）⇒ 首选的代价是**1 个本地推理运行时 + 模型资产**（含首次下载的出站）。
这与 §6.2、§11.3 末段一致，不构成对「运行时私人文本不出站」的否定。

### C.4 Qdrant 条件备选的具名触发条件（§5.2 的判定口径）

§5.2 的「首选确因规模/能力不足失败才比较」在 WP1 落成三条**可证伪**触发；
须命中至少一条才开比较，否则不比较（同时避免为选型而长期维护多套后端）：

| 编号 | 触发条件 | 判定要点 |
|---|---|---|
| T1 | 规模 | 10,000 条冻结档下精确检索 p95 超出冻结 SLA，且 A5（ANN）亦达不到 |
| T2 | 质量 | A1/A2/A3 均达不到冻结的中文改述阈值，且 §10.4 漏斗已排除第 3–7 层（索引/候选/资格/排序/预算）为致因 |
| T3 | 隔离硬约束 | pgvector 在当前锁定版本出现**无法在不升级依赖前提下**绕开的兼容或事务失败（不得顺手改 lockfile） |

本附录**不改** §5.2 的措辞，只把它的判定条件写死。

### C.5 外部 embedding API 的边界补录

本仓库**已有出站先例**（M5.5 的搜索 provider 让查询直接出站到托管 API，
见 [ADR-048](../adr/ADR-048-m5.5-production-activation.md) 与
[ADR-054](../adr/ADR-054-search-provider-tavily-activation.md)）。
⇒ 因此「会出站」本身**不是**否决理由。真正的分界是**出站内容的性质**：
搜索出站的是用户**显式搜索词**，embedding 若转用云端则出站的是**私人记忆正文**。
若将来转用，需要的是**生产激活级的单独授权**（形态同 ADR-048/054），
不能由本计划默认允许。
