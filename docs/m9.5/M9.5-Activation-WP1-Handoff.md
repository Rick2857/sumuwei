### 2.2 ★ 本轮**顺带修了一个把整道门挡死的缺陷**（**不是** WP1 引入的）

```text
现象：`pnpm m9.5:test` **整道门跑不起来**（TDZ：`Cannot access 'SEMANTIC_INDEX_DDL' before initialization`）。
归因：**先做减法** —— 把本轮改动 `git stash` 掉之后**同样失败** ⇒ 与本轮无关，是既有的。
根因（读出来的）：`memory-semantic-index.ts → db.ts → migrations.ts → memory-semantic-index.ts` 的环，
      而 `migrations.ts` 在**模块顶层**读那个常量（`MIGRATION_0010` 的 `statements` 是模块级字面量）
      ⇒ 入口先加载前者就 TDZ。
修法：DDL 常量搬到**不 import 任何东西**的叶子 `semantic-index-ddl.ts`，`migrations.ts` 从叶子取；
      `memory-semantic-index.ts` 继续 re-export ⇒ 既有调用方零改动、**DDL 一个字节未动**。
⚠️ **为什么一直没人发现**：`pnpm m9.5:gates` 是 PASS —— 它按设计**只读已落盘的旧证据**
   （与 `L-M10-59` 同一个形状：**聚合器的绿不代表今天跑得起来**）。
```

### 2.3 三处**被量具抓出来的**我自己的错（如实登记）

```text
① "取值为空"的判据写错了：我原本比较"渲染出来的整段文本 == 前缀"，而它永远不相等
   （前缀后面总有 predicate）⇒ 门当场报红。改成判**取值本身**是否为空。
② 我写"`exclusionReasonForStatus('disputed')` 会抛错" —— **错了**，它返回 `undefined`
   （那条 throw 只在两个函数自相矛盾时才可达）。是**门里的负控**把它抓出来的。
③ ⚠️ **最要紧的一条**：我原本**复用**召回面的状态映射，被 **M5 的静态锁 AT2.1 当场判红**
   （"状态 → 理由的映射只有一个消费者"）。**那条锁是对的** ⇒ 改成由本模块拥有自己的
   `status:*` 词汇。⚠️ 锁的检测器是**字面量**匹配、**连注释都算**
   （`scripts/verify-m5-eligibility.ts:640-651` 用 `readSource` 而**不** `stripComments`）
   ⇒ 注释里写出"函数名 + 左括号"也会被判成第二个消费者。两个坑都写进了源码注释。
```
