## 4. 回滚

### 4.1 动作（计划 §20.3 逐字）

```text
优先操作：**模式设为 `off`**（删 `.env` 那两行或改 `ENABLED=false`）⇒ 停止语义 query 与自动派生维护，
  保持原 Recall；**保留**新增 Memory / Belief / 对话事件。
· **不默认还原整库备份**（那会丢掉激活后正常发生的历史）
· 新派生表可**保留不可用状态**；generation 清理稍后按具名维护执行
· 若源数据已损坏，按 INC-01 独立事故流程处理，**不把"关掉索引"包装成"已修复数据"**
· 回滚验证：原聊天可用 · 原 Memory 状态/新历史保留 · semantic 调用 **0** · 模式读回 `off` ·
  **未自动回升 `on`**
· 已经发给模型或用户的内容**不能**通过本地回滚撤回；这一边界不作额外保证
```

### 4.2 真实库操作纪律（**本计划全程适用**，INC-01 / AGENTS §5.1）

```text
① 任何打开 `data/pglite` 的入口都要先取**独占租约**（拿不到立即失败，不等待、不覆盖）
② 打开之前必须走完：租约 → pre-open verified snapshot → 本进程 token
③ ⚠️ **零删除**：pre-open 快照缺省 `keep=10`，而**本机此刻恰好 10 份**（2026-09-30 实测）
   ⇒ 再来一份会真删**最旧那份**；而"删旧快照 = 需要单独授权"（AGENTS §5.1 ③）
   ⇒ **建索引/切 on 的执行入口必须显式抬保留窗口**（先例：`pnpm inc-01:first-snapshot --keep 30`）
     并带**前置拒绝**（快照数 ≥ 窗口就不开库）+ **事后断言**（`pruned=[]`）
     —— 本仓库的只读读回脚本已经这么做，生产执行入口必须照抄
④ 收尾唯一：`stop → close → closed check`；只有 `closed === true` 才做 post-close 快照
⑤ 事故时输出 `INCIDENT HOLD`（具名 code + 源摘要 + 最近 verified 快照 + dry-run 恢复指令），
   **禁止**自动删 `postmaster.pid`/WAL、禁止自动切库、禁止反复试开
```
