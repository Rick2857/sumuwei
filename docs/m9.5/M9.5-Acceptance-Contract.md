## 2. 冻结阈值

### 2.1 质量线（**冻结于 2026-09-28，正式盲测之前**）

| 项 | **冻结阈值** | 判定方式 |
|---|---|---|
| 关键机械边界 | **200+ 负控全部正确 · 关键泄漏 = 0** | 任一失败**阻断激活**；`measured_count` 必须 > 0 |
| 受支持可回答集 `Candidate Recall@20` | **≥ 95%** | 总体**及分层**均报告；多证据组另算组完成率 |
| 改述集 `Semantic-only Hit@20` | **≥ 90%** | 若旧基线 < 90% ⇒ 要求**显著实质改善（目标提升 ≥ 15 个百分点）**；若旧基线已高 ⇒ 保持不退化并验证**无词面正控** |
| `Context Evidence Success` | **≥ 90%** | 同一预算；**禁止**通过无限增大上下文达标 |
| 真实回复 `grounded correctness` | **≥ 90%，主要类别不低于 85%** | **至少三次独立运行**；**最差轮**需达线，报告全部轮 |
| 应未知/澄清的**无据断言** | **≤ 2%**；关键隔离/遗忘场景 **0** | 分层、分母、失败**逐条公开** |
| 字面强项不退化 | 成对成功率下降 **≤ 1 个百分点**；**关键正确 ID 不退化** | **不拿**改述收益抵消关键错误 |
| 三条 500 轮离线轨迹 | **完整执行 · 关键污染 0 · 检查点当前证据全部正确** | 真实编码档与固定信号档**分列** |
| 盲审 | **至少 60 组对照**，正确/有据/自然**分别判** | 人工未完成 = `PENDING`，**不代填** |

**统计口径**：比例报告 **Wilson 95% 区间**或同等明确方法；成对比较报告失败差异清单。
**有限样本的 0 不等于总体风险 0**。某类样本太少 ⇒ 标 `INSUFFICIENT`，
**不得**把整体大分母借给小类。

### 2.2 指标定义（分母必须写出来）

| 指标 | 分母与计算 | 不可混淆 |
|---|---|---|
| `Candidate Recall@K` | 可回答查询中 gold relevant IDs 被**候选集合**覆盖的比例；多证据任务同时报组完成率 | k 条相似候选 ≠ 有效答案 |
| `Semantic-only Hit@K` | **词面弱/无重叠**改述子集中，至少一组充分 gold 证据命中比例 | **不把**字面命中灌入该分母 |
| `Context Evidence Success` | 可回答查询中，最终模型上下文包含所需**当前有效**证据组的比例 | `selected` ≠ **actual in model** |
| `Answer Grounded Correctness` | 固定回复模型下，正确**且由实际入模证据支持**的回答比例 | 模型猜对但无依据**不算通过** |
| `Unsupported Assertion Rate` | 应未知/澄清查询中，回复却明确断言未获支持事实的比例 | 与候选相关性精度**分别算** |
| `Critical Leakage Count` | forbidden / 错 owner / 已遗忘 / 禁根内容进入**本不允许的读取面**的次数 | 0 次只证明**本次范围** |
| `Legacy Regression` | 原字面强项集合中，新方案与旧方案**成对**差异 | 不只比全体平均值 |
| `Index Coverage / Freshness` | 当前源版本对应覆盖比例；合法提交→可用索引时延 | **不用 row count 代替源版本核对** |

### 2.3 性能与容量（计划 §14.5 的**起始预算**，冻结为契约值）

```text
同设备、CPU、模型已预热，**10,000 条主规模的"新增召回链"** p95 ≤ **1,000 ms**（不含回复模型生成）
语义 query 总截止时间起始目标 **2,000 ms**（超时降级；被取消的底层工作须**真实停止**或有界回收 —— D27）
合法 Memory 提交后，正常低负载下派生可用 p95 ≤ **5 s**（更正/遗忘的**使用屏蔽不等待**这个时间）
必须测的三档：**500 / 2,000 / 10,000**；**50,000 只作容量观察**，要承诺必须扩契约
必须报告：冷启动耗时 · 模型磁盘大小 · 最大 RSS · 维护队列峰值 · DB 调用数/扫描行数 ·
         每条向量体积 · 构建耗时
```

**变更触发**：若首选达不到上述，**不擅自降低质量线**；比较更合适的模型/索引后，
**在盲测前**冻结新的性能契约。**禁止**拿全量门墙钟或 M9 的 SLA 冒充语义编码 SLA。

**WP1 已出的相关读数（不是达标声明）**：编码段单条 query 热编码 p95 = 5 ms、RSS 497.6 MB、
模型磁盘 134.0 MiB（见 `M9.5-OSS-Selection.md` §3.3/§4.2）。**召回链全链未测。**

## 3. 冻结的场景矩阵（S01–S60；**ID 冻结，禁止运行后换含义**）

来源：计划 §15.1–§15.4 的 60 个场景，逐字冻结为契约条款。
每个场景**必须**绑定：fixture · 断言层 · 期望 ID/状态 · 负控 · 证据路径。

| 组 | ID 范围 | 覆盖 |
|---|---|---|
| 语义相关与相似事实 | **S01–S10** | 改述 / 数值与否定 / 精确编号 / 模糊指代 / 只提过没保存 / 超长末尾限定 |
| 更正 · 遗忘 · 来源 · 历史 | **S11–S30** | 新值取胜 · 历史意图 · 修订原因 · 同轮更正/遗忘 · 重启 · 重建 · 重新告知 · 归因降档 · 跨 owner · 断链 · 缓存顶替 · 高信任坏来源 · 摘要藏旧值 · 冲突未裁定 · 多目标澄清 · M9 禁根 |
| 索引 · 模型 · 恢复 | **S31–S45** | 1/50/51/500/501/最老 · 三档规模 · 页边界 · 水位缺口 · 三个断电点 · generation 切换 · 混维 · 非法向量 · 模型缺失/摘要不符 · 超时取消 · top-k 全失效 · 旧库新索引 · 重建不变 · 迁移中途失败 |

**最低实现纪律**：每个场景的断言**不得**退化成"一条字符串包含"；每条必须有
**期望 ID/状态** + **至少一条负控**。

### 4.1 语料与数据拆分（冻结规格；manifest 为同批交付物）

```text
总量：**600 条独立查询场景**，按**事实/场景族**分组拆分 —— 建议开发 240 / 验证 120 / 盲测 240。
⚠️ 同一底层事实的近义问法**不得**分散到三个集合造成泄漏。

  正常可回答        240   同义 / 间接指代 / 口语省略 / 上下文有界提示 / 中文与混合实体
  难区分可回答      120   人物 / 时间 / 否定 / 数字 / 单位 / 项目相似 / 历史与当前
  无答案或应澄清    120   从未保存 / 已遗忘 / 只在聊天提过 / 主体模糊 / 超出覆盖
  生命周期与隔离对抗 120   旧值 / 错 owner / 坏根 / 重建复活 / 摘要冲突 / 源不可读
  另设 ≥ **200 个机械关键负控**（高分伪候选 + 故障注入）；**与行为语料不混为同一分母**

每条金标至少含（字段名冻结）：
  caseId / familyId / split / namespace / user / request / intent / timeScope /
  authoritativeSnapshot / relevantMemoryIds / requiredEvidenceGroups / forbiddenIds /
  expectedUnknownOrClarify / lifecycleSetup / acceptableAnswerPoints / modelInputRestrictions /
  annotator / adjudication
```

**标注纪律**：负例是**错误主体 / 无关命题 / 过期状态被当当前事实**等，
**必须判命题关系，不只判词形相似**。「你爱不爱吃辣？」与「不吃辣」是**合法相关**，
不因表面正负词不同就判负例（计划 §14.2）。

## 7. 量具有效性约束（计划 §14.6 + AGENTS §6.7/§6.8）

对应 `pnpm m9.5:measurement:verify`（**✅ 已交付**；读数见 `M9.5-Measurement-Report.md`）。

**本阶段覆盖范围（边界冻结）**：本节约束**检索侧判定器**（候选面 / 上下文面 / 泄漏面 /
覆盖与权威面）—— 它是确定性判定、可离线完整自证。
**回复侧**（`grounded correctness` / `unsupported assertion`）**不属本节**，需真模型 ⇒ WP10；
在证据里如实标 `not-run`，**不得**用 0 冒充。

```text
三段式（**缺一不可**）：
  正控：合法输入 ⇒ 检测器**安静**
  负控：注入假象 ⇒ 检测器**必须响**，且**判定必须精确等于声明的期望三态**
       （只断言"别是 correct"会让一个把 `insufficient` 混成 `wrong` 的判定器照样通过）
  恢复：放回真实实现 ⇒ **重新安静**（且必须先断言注入**确实响过**）
只做正控的量具与"什么都不检查"在输出上无法区分。

逐条要求：
· 正控：明确正确证据在最终上下文且回复符合事实；判定必须识别成功。
· 负控：只改 **Memory ID / owner / 否定 / 时间 / 撤回状态 之一**；判定必须识别错误。
· ★ **必须有一条对照只改"选中 vs 实际入模"**（`selected` ≠ actual in model，计划 §14.3）
  —— 否则一个把 `Candidate Recall` 与 `Context Evidence Success` 合并的判定器会全过。
· ★ **必须有对照验证 `insufficient` 这一档**（`partial_coverage` / `source_unavailable`）
  —— 它们**不得**被判成 `wrong`（把"索引有缺口"记成"检索错了"）或 `correct`（把"没查到"说成"你没说过"）。
· 无词面正控 · 低分正确源 · 高分无资格源 · 正确否认 · 正确但改述的回答 —— **各有样例**。
· gold 生成与执行结果计算**分离**；**不得**把系统自己的 embedding 排名当标准答案。
· 人工核对至少 **30 个**自动判定样例；有分歧的类在量具通过前**不用于结论**。
· 自动判定器需记录**模型/指令/输入证据面版本**；**不得**从"未告警"直接推导"无假记忆"。
· **计数型检测器必须自检 `measured_count > 0`**（0 检查 0 失败 = `MEASUREMENT INVALID`，不是 PASS）。
· **对照的"适用条数"必须 > 0**：适用 0 条的对照是**空的**，算失败不算通过。
```

### 7.1 本轮（WP0/WP1）已自证的量具纪律（沿用）

```text
· 量具的**预期**必须是判据字段：`succeed` / `fail` / `record`（"应当失败却成功" ⇒ unexpected-success）。
· **负控必须真的可能触发**：WP1 vector 半边第 1 档就是因为负控空过（判据恒真）而作废。
· runId 目录**拒绝覆盖**；取代用 `--supersedes` + `--supersession-reason`，**旧档留在库里**。
· `gapCount`（被测对象有缺口）与 `instrumentFailureCount`（量具没跑成）**必须分开**。
```
