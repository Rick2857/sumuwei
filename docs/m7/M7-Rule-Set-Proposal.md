## 0. 设计立场（先读这个再裁）

```text
① 精度优先，失败关闭：判不准就不提案（空提案是正常结论）。
   规则触发器是「采信层」的机械判据（DR-11 允许的层），不是措辞守卫。
② 语义规则的已知代价：模式匹配看不见反讽/引用/第三人称转述。
   缓解四件套：模式清单冻结 + WP3 量具验证（精度探针，不达标不冻结）
   + delta 有界（单条 ≤0.05/0.03，错了也错得有限）+ 纠正链可回滚（supersede）。
③ 每条规则只吃 ESTABLISHED 资格的用户消息（relationshipEvidenceVerdictOf），
   她的生成/工具/未确立归因一律不进规则输入。
④ 幂等：提案键 = (processor, version, ruleId, 窗口, 命中事件 id)——
   与 memory extractor 同一模式，重叠窗口不重复计票。
⑤ 里程碑/累积类规则（R-1/R-5）完全不需要语义，是最稳的一层；
   语义类规则（R-2/R-3/R-4）是覆盖场景 2/3/4 的必要面，但必须过精度探针才冻结。
```

## 1. 规则草案（逐条裁定）

### R-1 日常陪伴累积（closeness +）

| 项 | 提案 |
|---|---|
| 触发 | 处理窗口内 ≥ **10** 条 ESTABLISHED 用户消息，跨 ≥ **2** 个自然日，且窗口内无 R-3 命中 |
| delta | closeness **+0.02**（每个累积单元一次；同一天最多计一次单元） |
| 依据 | 场景 4 长期陪伴；"在场"是最鲁棒的信号——零语义依赖 |
| 负控 | 她的消息不计；未确立资格不计；R-3 命中的窗口不计（吵架当天不算陪伴） |

### R-2 显式正反馈（trust + closeness +）

| 项 | 提案 |
|---|---|
| 触发 | 用户消息命中**冻结模式清单**：明确感谢/信任表述（初版候选：「谢谢你」「多亏有你」「我相信你」「有你真好」「辛苦了」……完整清单在 WP3 量具阶段给出并冻结） |
| delta | trust **+0.02** · closeness **+0.02** |
| 依据 | 场景 2 可靠互动 |
| 负控 | 反讽/引用/转述由精度探针把关（见 §2）；同窗口多次命中只计一次 |
| ⚠️ | **冻结前置条件**：精度探针 ≥ 90% 才冻结模式清单；不达标就缩清单，不放宽 |

### R-3 显式负面事件（trust −，closeness 微降不清零）

| 项 | 提案 |
|---|---|
| 触发 | 用户消息命中冻结模式清单：明确指控欺骗/背叛（初版候选：「你骗我」「你骗了我」「我不信你了」「你出卖我」……） |
| delta | trust **−0.05**（单事件上限）· closeness **−0.02** |
| 依据 | 场景 3：**很熟但刚吵过架 ≠ 不可信但亲近**——closeness 刻意不清零 |
| 负控 | 玩笑/引用由精度探针把关；命中后该窗口的 R-1 累积停计 |
| ⚠️ | 同 R-2：精度探针前置；这条错报的代价最高（trust 大降），模式清单应最保守 |

### R-4 更正与修复（trust 部分恢复；误解可取代）

| 项 | 提案 |
|---|---|
| 触发 | 两种形态：**(a)** R-3 命中在案后，用户明确修复（候选模式：「没关系」「我原谅你」「不怪你」）；**(b)** 用户明确撤回指控（候选模式：「刚才是我误会你了」「对不起怪错你了」） |
| delta | (a) trust **+0.03**（部分修复，**不满血**——场景 4"不能一轮跳满"）；(b) 同 (a)，且 payload 带 `supersedes` 指向被撤回的那条 R-3 事件 |
| 依据 | 场景 4 修复 + 场景 11 纠正/撤回（保留旧事件与取代关系，不物理删除） |
| 负控 | 无 R-3 在案时，修复模式**不触发**（没有可修复的对象）；supersedes 指向非 IMPACT 事件 → 校验拒绝 |

### R-5 长程陪伴里程碑（closeness +）

| 项 | 提案 |
|---|---|
| 触发 | 累计 ESTABLISHED 用户消息数跨过里程碑（每 **100** 条 / 每 **30** 个活跃自然日，先到先计）；计数从账本派生（确定性，不依赖投影） |
| delta | closeness **+0.03** |
| 依据 | 场景 4 的长程面；与 R-1 同源但按累计而非窗口 |
| 负控 | 计数只含合格消息；里程碑幂等（同一里程碑只计一次，提案键含里程碑号） |

## 2. 量具验证计划（WP3 第一步，先于任何规则实现）

```text
判定契约（本提案）→ 量具有效性验证 → 才实现机器门与规则（M6-FMB-01 §3 的硬顺序）
① 语料：正控样本（真实语气的感谢/指控/修复各 ≥ 20 条）+
   负控样本（反讽、引用他人、第三人称转述、无关含关键词 ≥ 20 条）
② 探针：冻结模式清单跑语料，输出 precision / recall
③ 判据：R-2/R-3/R-4 的 precision ≥ 90% 才冻结；不达标 → 缩清单重跑，不放宽判据
④ 读数落盘 artifacts/m7/<runId>/，进 m7-manifest@1
```

## 3. 明确不做（如实登记，不是遗漏）

```text
✗ 失约检测（承诺-兑现）：规则层看不见"承诺过什么"，需要语义理解——
  留给未来的 LLM evaluator（U-M7-04 的 B 选项位）。场景 3 的"失约"半边
  在 M7 的行为是"无证据不变化"（失败关闭），作为已知限制登记。
✗ 情绪联动（valence/arousal）：M8 的变量，M7 不碰（计划 §3.2）。
✗ 自动长记忆抽取：关系事件不写记忆（关系不是记忆，ADR-064 §4.1）。
```
