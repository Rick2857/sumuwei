## 0. 冲突是什么

**产品门**（`scripts/m6.1-wp5-verdict.ts`，已冻结）：

```text
支持性回忆：成功 ≥27 · 每类未成功 ≤1 · 技术失败 ≤1 · 弃判 ≤1
必修反例  ：违规 0 ∧ 技术失败 0 ∧ 弃判 0
```

**量具现实**（温度 0，官方路由，@7）：采样不稳定是**实测事实**，不是假设——

1. @7 有效性 run 1（`…-466b`）：unresolved **2/62**；run 2（`…-6c3f`）：unresolved **2/62**
   （两轮均 VALID——**有效性门**容忍这个量级；**产品门**不容忍）。
2. **B-10 同输入跨轮翻转**（具名证据）：归档读数 a==b 双 alert；引文探针重放同一输入
   3/3 全 no_alert。温度已是 0 ⇒ 这是服务端非确定性（MoE 路由），工程侧不可再压。
3. 四轮判定读数的 unresolved 在 2–4/62 间波动。

**推算**：若 3–6% 的采样分歧率迁移到 62 条判定轮，仅量具噪声即可产生 1–4 条弃判。
支持门的弃判预算是 **≤1**，RCE 门是 **0**——**预算在产品行为被计数之前，就可能被
量具噪声吃光**。一条 a≠b 就能把一个产品行为完全正确的轮判成 FAIL，而 19.1 禁止
重跑到绿 ⇒ 噪声致 FAIL 无补救路径。这是结构冲突，不是调参问题。

## 1. 选项

| 选项 | 机制 | 代价 / 风险 |
|---|---|---|
| **A. 维持现状** | k=2，a≠b 即弃判，预算 ≤1/0 不动 | 噪声致 FAIL 无补救；RCE 的 0 预算最脆 |
| **B. 全量 k=3 多数决** | 每条 3 次采样，2/1 多数=读数 | 调用量 ×1.5；若仍要求全一致，弃判率反而更高 |
| **C. 争议加判（自适应 k=2→3）★推荐** | 每条仍 2 次；a==b ⇒ 读数成立；a≠b ⇒ **只对该条**加判第 3 次，2/1 多数=读数并标 `tie_broken` 单独披露；三态互异或传输失败 ⇒ 弃判（预算不动） | 每轮约 +2–4 次调用（并发下可忽略）；协议需升版 |
| **D. 放宽弃判预算** | ≤1→≤2、0→≤1 之类 | **19.1 禁止**，除非你显式裁；且没解决"噪声与产品混账"的根 |
| **E. 换判定模型** | 换一个确定性更高的 judge | @7 有效性绑定 deepseek-flash；换模型 = 有效性全部重验，代价最大 |

## 2. 推荐：C（争议加判）

- **机制**：见上表。单样本噪声被多数吸收——单条错读概率从 ~2p(1−p) 降到 ~3p²
  （p=单采样偏离率）；弃判预算回到它该量的东西：**产品侧真不确定 + 三向分裂 + 传输失败**。
- **不动的东西**：@7 提示一字不改 · 阈值一字不改（19.1）· 不许重跑到绿 ·
  有效性协议（两轮、正负控）不受影响——本裁定只改**判定轮的读数聚合**。
- **披露纪律**：`tie_broken` 条目在 reading.json 单列（哪条、三次采样各是什么、多数是什么），
  报告必须如实写"本轮有 N 条经加判定读"。
- **跨轮翻转（B-10 型）不在本裁定修复范围**：它影响的是续跑/跨轮可比性，对策是
  **披露 + 引文探针**（工具已存在），不是改门。本裁定只解决"轮内噪声吃掉弃判预算"。
- **落地方式**：你裁 C ⇒ 测量协议升 v2（本件 + 运行器实现 + 锁 + 在有效性集上自证），
  然后才进判定轮。若两采样协议已被验收契约条文冻结，本裁定即对该条文的**修订记录**
  （升版，不原地改写历史）。
