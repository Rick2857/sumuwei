WP3 要回答的是「**为什么她会在没有依据时补造事实**，以及**该改哪一层、用什么门来判**」——


冻结数字（支持性回忆 30 条 / ≤3 未成功 / 每类 ≤1 / 必修反例 0 / 写入正控 10→0 /
误触发负控 12→0）目前**是门上的期望值，不是读数**。把它们读成"已通过"是本收口最大风险。

## 2. 四项核对点的结论（WP3 的实质产出）

```text
① 角色/来源/资格是否保留、编造是否经 Recent 被当作共同历史
   已证：账本只记 **role 不记 authorship** ⇒ agent 用一次性入口替用户发的话，
   落进 conversation_events 就是一条**不可区分的 [user] 发言**（§2.x / AGENTS §10）。
   ⇒ 这是"她为什么会说起一件没发生过的事"的一条**真机制**，不是措辞问题。

② 纠正/遗忘是否真的成功、旧值从哪条路径重新出现
   已证（实测）：取代的唯一入口是 `correct` **意图**，而 `intent-detector` 当时
   只认一小撮子串 ⇒「记住，我吃辣。」**根本不触发取代**（生产路径上冲突分析
   从未接线，见 ③）。这条是 WP4 的 `A` 项（冲突分析进显式写入路径）。

③ 依据是否存在却未入模 / 是否被预算裁剪 / 是否只是旧 M3 host 漏接
   已证：`recordsInCanonicalSlot` 只存在于 `pipeline.ts` 内，而
   `runMemoryExtractionPipeline` **只被** `scripts/eval-m4.ts` 与
   `scripts/verify-m4-persistence.ts` 调用 ⇒ **生产从未用过冲突分析**（后台 = NOT-WIRED）。
   ⇒ 既有 `m4:*` 门**不可能**证明 `A` 有效（它们测的是另一条路径）。这是 WP4 的
   等价判据（设计文档 §4.6）存在的原因。

④ 既有 reply-truth 处理前后差异；程序"执行真相"与语义"记忆真相"分开
   已证：守卫链四道在账本写入之前，其中 `response-truth` 有一条**静默分支**
   （`result === undefined` ⇒ 早退、不打日志、`executed: undefined`）⇒ 观测缺口。
   这是 WP4 的"守卫三态进 trace"（设计文档 §4.5 / §6.3）。
```

## 4. 交给 WP4 的清单（按依赖排序，不含"跑一次看看"这类空话）

```text
1. D1′ 渲染（设计文档 §4.5 第二稿，**已冻结**）
   一条**程序生成**的记录状态行 + 具名枚举；**五种情形不得合并**
   （无记录 / 检索没命中 / 预算裁剪 / 资格不合格 / 根本没检索）；
   状态行必须跟随编译期实况（`applyContextReality()` `turn-gateway.ts:1138`）、
   自己有预算、**不依赖** `memory-recall` 非空。
   基准句只在**程序确实覆盖全部相关来源**时才可用：
     「本轮提供的上下文中，没有可支持这段共同经历的合格记录。」
2. R-8③（与 D1′ 同一机制）：声明该槽位**当前状态**；措辞
   「该槽位的旧记录已作废，目前没有有效替代值。」——需**该槽位当前状态的完整查询**支持，且槽位具名。
   R-8② 仅在能建立可靠"事件—历史行"关联时再议；R-8④ 已否决。
3. 守卫三态进 trace（设计文档 §6.3）：具名守卫 + 结构化原因 + **隐私白名单**，
   三态（未运行/静默通过/触发）都要落；**不存原始正文**。
   最省的接法：`main.ts` 把守卫返回值经 `completeTurn` 的可选参数带出去，
   不去动 `response-truth.ts` 的既有语义。
4. L3-11 从 **5 条**假触发文本扩到 **12 条**（= `correction_intent_negative_v1`），
   判据仍是 **mutation 级**：12 条都不得造成未经请求的记忆变更。
5. 等价判据的**运行期**三读数（设计文档 §4.6 ②③）：实际入模 · Gateway 之外的路径
   （意图 → 写入 → 编译 → 守卫 → 完成记录）· "结果没进后续链路"的负控。
   静态那一半已在 L1 里（**不许**拿它冒充运行期已验）。
6. **两轮正式运行的运行器**（WP5/WP6）：两轮分别判定、不合并不择优；
   成功/技术失败/弃判**三数同时报**；技术失败与弃判都在 30 条内且计入未成功额度。
   ⇒ 这是把冻结数字从"期望值"变成"读数"的**唯一**途径。
```
