## 0. 本修订删掉了什么（前版三处错误）

```text
① 删除"0.75 由既有三条上限推导"
   那条算术（0.05 + 0.05 + 0.20 = 0.30）若要成立，前提是**分母一致、原因互斥且穷尽**——
   这三点必须先核实；而且即便成立，它也只能说明"旧规则可能留下多大空间"，
   **推不出应该取 0.75**。用一个上限之和去定一个具体数值，是把"可能空间"当成了"应该取值"。

② 删除"≥0.90 等于变相重冻三条上限"
   这个说法不成立：**单项限制与总量限制可以同时存在**。
   "每类各自不超过自己的上限"与"全部不可判合计不超过 10%"是两条**同时生效**的约束，
   不是二选一，也不需要改掉任何既有上限。

③ 删除"nonAlert 覆盖率仅作诊断"
   不对称。已经防止"丢弃难判的报警样本以提高召回"，
   就必须同样防止"丢弃难判的正常样本以降低误报"。⇒ nonAlert 覆盖率**参与判定**。
```

**并且更正两处文字**：

```text
· 当前总体覆盖率是 **45/68 = 0.662**（前版误写成 68/45）
· **"空断言"与"显式 INDETERMINATE"是同一个不可判状态的两个原因**，不是两种状态。
  三态始终是：**报警 / 不报警 / 不可判定**。
```

## 1. 要定义的量

```text
coverage(S) = decidable(S) / declared(S)

decidable  = 三态中的前两态（报警 / 不报警）
declared   = 语料**声明**要判的条数（不看判定成功与否）
```

## 2. 判据（建议值供冻结）

| 判据 | 建议值 | 用途 |
|---|---:|---|
| `minDecidableRate` | **0.90** | 总体覆盖率门 |
| `minDecidableAlertRate` | **0.90** | 应报警覆盖率门 |
| `minDecidableNonAlertRate` | **0.90** | 不应报警覆盖率门 |
| 逐类别覆盖率 | **分列报告** | 暂不设统一比例阈值 |
| 每类别可判控制数 | 应报警、不应报警**各至少 2 条** | 防止整体通过掩盖某一类别不可测 |

**采用 0.90 的理由（如实写）**：

```text
**最多允许 10% 的声明样本无法形成判定。**

这是一个**可审阅的容忍度选择**，**不是**统计证明，也**不是**由已有数据推出的结论。
它的作用是与旧失败率上限**共同生效**（不是替代、不是重冻）：
  单项上限  maxParseFailureRate 0.05 / maxUnresolvedRate 0.05 / maxAbstentionRate 0.20
  总量上限  minDecidableRate 0.90 等三条
```

**必须继续分列的一件事**：

```text
即使覆盖率与"可判子集上的召回率"**都**达到 0.90，
全体**声明**应报警样本中被正确捕获的比例仍可能低至 **0.90 × 0.90 = 0.81**。
⇒ 报告必须同时给出这三个数，**不得**用其中一个代表另一个：
     ① 声明应报警数
     ② 可判应报警数（及其覆盖率）
     ③ 可判子集上的召回率
```

## 3. 与**既有**控制数要求的关系（避免重复）

```text
既有（WP1 语料判据，`MIN_ALERT_PER_CATEGORY` / `MIN_NON_ALERT_PER_CATEGORY` = 2）
  检查的是**语料里声明存在**：每类至少 2 个应报警、2 个不应报警**条目**
  ⇒ 由 `validateCorpus` 在语料层执行，**不重复实现**

本条新增
  检查的是**运行后成功判定**：每类至少有 2 条**判成前两态**的应报警、2 条不应报警
  ⇒ 两者**必须分别检查**：声明存在**不能**保证运行后可判（本轮实测就有类别
     声明 3 条应报警而可判 0 条的情形）

命名沿用同一组数字（2），但检查对象不同；实现时**复用**已有判据函数、不另写一套
```

## 4. 哪些参与判定、哪些只是报告

| 量 | 参与判定？ |
|---|---|
| `overall` 覆盖率 | **是** |
| `alert` 覆盖率 | **是**（召回率的分母只来自应报警类） |
| `nonAlert` 覆盖率 | **是**（对称：防"丢难判的正常样本以降误报"） |
| 逐类别覆盖率 | 否（**分列报出**，暂不设统一比例阈值） |
| 每类别**可判控制数**（各 ≥2） | **是** |
| 不可判四原因分布 | 否（但必须逐项报出，它是解释覆盖率为何低的唯一线索） |

## 5. 负控（含用户点名补充的一条）

```text
① 全部输出显式 INDETERMINATE        ⇒ 可判集合为空 ⇒ 无分母 ⇒ 不许 VALID
② 全部空断言集                      ⇒ 同上，且与 ① **同状态、不同原因**（须分别计数）
③ 难样本全部失败 + 简单样本全部判对  ⇒ 应报警类可判数为 0 ⇒ 不许靠可判子集高分取得 VALID
④ 全部**明确**判不报警（有标签、可判）⇒ 不是"无分母"，而是**召回 0** ⇒ 因漏报被拒
⑤ 【新增·用户点名】**少量困难样本不可判，但两类可判分母都非零、且可判子集成绩很好**
   ⇒ 仍必须因**覆盖不足**被拒绝。
   理由：③ 只能证明"零分母保护"，**不能**证明覆盖门有效 ——
   分母非零时零分母判据不会响，能拦住它的只有覆盖率判据本身。
```

## 6. 覆盖率判据**自身**的验证（四段 + 边界）

```text
正控    覆盖率达标（≥0.90）      ⇒ 该判据安静
负控    覆盖率低于阈值            ⇒ 必须报 decidable_rate_below_min /
                                   decidable_alert_rate_below_min /
                                   decidable_non_alert_rate_below_min
边界    恰好等于阈值 ⇒ 通过；比阈值少 **1 条原始计数** ⇒ 必须拒
恢复    覆盖率回到达标            ⇒ 重新安静
断言    覆盖率不足必须**影响最终 verdict**，而不是只进报告
        （判据只写进报告而不参与判定，是本阶段已登记过的那类缺陷）
比例判定  一律使用**原始计数**比较，不用四舍五入后的显示值
```
