## 1. 建议顺序

```text
M6 / G1 审核结束（G1=PARTIAL）
 → M6.1：假记忆 + 纠正/遗忘后陈述 + 必要量具与证据修复
```

“M7 前置质量包”是建议的工作包位置，不自动新增一个 M6.2 里程碑。后续正式计划必须接收本表条目或明确延期与影响，不能只写“以后再说”。

## 5. 接收与销账格式

每个正式计划接收本表项时写：`TD-id → 正式问题编号 → 所属 WP → 前置条件 → 验收命令/人工材料 → 状态 → 证据 runId → 剩余限制`。不要求先建设一个工单系统，Markdown 表即可。

状态用 `QUEUED / IN PROGRESS / BLOCKED / VERIFIED / DEFERRED`；`VERIFIED` 必须说明只关闭哪个主张。延期要写下一触发点与影响，不能只留“以后”。

本轮只核对仓库文件与代码位置，没有重跑旧门、在线搜索探针或数据库试验。这里的历史 PASS 来自明确引用的已落盘记录，不代表本轮刷新。
