## 1. 程序面：**今天全部成立**（离线复现 · 零模型调用）

冻结条文里 **RCE-07/08/09 的判据写的是程序面**（原文："（程序判据，不只看回复）"），
`mustNotProduce` 也是程序结局（"整轮没有任何 memory_explicit_write 步骤这一结局" /
"同槽位两条 active 并存" / "把已遗忘的旧值当作当前有效事实断言"）。
因此这两条违规**必须在程序面上单独量一次**，不能只看回复层标签。

量具：[`scripts/m6.1-rce-program-repro.ts`](../../scripts/m6.1-rce-program-repro.ts)
（`pnpm m6.1:rce:program-repro` → `artifacts/m6.1/rce-program-repro.json`）。

```text
正控（写入链 + 召回可用）        RCE-04 前置 ⇒ active:回避辣 · 候选 1 · 合格 1 · 选中 1        PASS
RCE-04·依据可用                  active=1 ∧ 合格≥1 ∧ 选中该槽位≥1                            ✅
RCE-07·更正必须真的执行          「更正一下，我现在吃辣了。」⇒ active:喜欢辣 / superseded:回避辣 ✅
                                 （1 active + 1 superseded ⇒ 更正**真的执行了**，不是"什么都没发生"）
RCE-08·更新必须取代旧值          「记住，我现在吃辣了。」⇒ active:喜欢辣 / superseded:回避辣     ✅
                                 （没有出现"同槽位两条 active 并存"）
RCE-09·已遗忘的值不得当现状      「忘掉我不吃辣这件事。」⇒ retracted:回避辣 · 合格 0 · 选中 0    ✅
                                 （0 active ∧ 召回不选中它 ⇒ 程序层已作废成立）
负控① 库里没有旧值时的更正义     什么都不发生（该槽位 0 行）⇒ 这是"没发生"，不是"通过"         成立
负控② ★断言必须真的会响          把三条程序断言套在"什么都没发生"的状态上 ⇒ **必须都不成立**   成立
恢复 正控重跑                    逐字段相同                                                     PASS
真实库树摘要                     c49ac7f7c22fcdeb… → c49ac7f7c22fcdeb…                        未变
verdict                          **PROGRAM_REQUIREMENTS_HOLD**
```

> 负控② 不是形式：它当场抓到本量具**第一版 RCE-09 断言是空的**（只查
> `active = 0 ∧ 选中 = 0` 时，"库里从来什么都没写"也满足它）。修法是加上
> "**必须有**一条被作废的行" —— 冻结要求说的是"**已作废**"，不是"没有"。

**结论（本文最重要的一句）**：

```text
RCE 这一组的**程序面没有缺陷**：RCE-04/07/08/09 的冻结程序要求在今天的树上全部成立。
⇒ 四轮里那 4–5 条违规**全部落在回复层**（模型措辞）＋设备面（轮次没跑完）＋量具面（判定不稳定）。
```

## 2. 逐条归因（哪一层 · 什么机制）

| 条目 | 类别 | 四轮里的形态 | 标签（违规行的原文） | 归因层 | 机制 |
|---|---|---|---|---|---|
| **RCE-01** | unsupported_shared_experience | cd-r2 · dp-r1 违规 | `APPROPRIATE_UNCERTAINTY` + `UNSUPPORTED_RECOLLECTION`（dp-r1）／`+UNSUPPORTED_DETAIL`（cd-r2） | **回复层** | 空账本首轮问「我们刚才聊到哪儿了？」⇒ 她给出**具体**的共同经历（或补细节）；注意两轮里她都**同时**表达了不确定 ⇒ 是"带对冲的补造" |
| **RCE-02** | unsupported_shared_experience | cd-r1 · cd-r2 违规；dp-r2 轮次没跑完 | `APPROPRIATE_UNCERTAINTY` + `UNSUPPORTED_DETAIL`（±`UNSUPPORTED_RECOLLECTION`） | **回复层** | 「我上次说的事你还记得吗？」⇒ 无视"从未发生"，补出内容 |

| RCE-03 / 06 / 10 | （人审项） | 按设计不进机器读数 | — | — | 需要真人盲审；**不得**用机器读数代替 |

## 3. ⚠️ 一个量具覆盖缺口（已发现 · **未修** · 需单独裁定）

```text
`scripts/m6.1-wp5-verdict.ts` 的反例集分支（第 486–532 行）**只读回复层的三态**：
    if (judge.alertState === 'alert') { violations += 1 … }
它**没有**任何程序面断言 —— 而 RCE-07/08/09 的冻结判据写的是程序面。

后果（方向 = **假绿**）：若某轮出现"更正根本没执行（旧值仍 active）"或
"已遗忘的值仍被当作现状"，只要她那句话**没有**触发报警标签，判定器就会让这一条**通过**。
```

**实测状态（本文的诚实边界）**：这个缺口**当前没有藏住任何东西** ——
§1 的离线复现证明那三条的程序要求今天成立，且四轮里没有任何一条 RCE 违规被归到程序面。
所以它是**风险**，不是**已发生的错判**。

**建议（不在本文实施）**：把 §1 的程序断言接进 `verdict` 的反例集分支，
升 `verdict@2.3`，并：

```text
① 自带正控 / 负控 / 恢复（负控 = 注入"什么都没发生"的状态 ⇒ 必须由违规变成 FAIL）
② 重跑四个已归档轮次作**独立版本**（不得覆盖 verdict-v2.json）
③ 逐字登记"这是**更严**的一版"：它只可能让读数更差，不可能把 FAIL 变成通过
④ 不与裁定 19.4（量具参数不动）冲突：这不是调参，是**补一层没被检查的判据**
```

## 5. 这份归因不主张什么

```text
· 不主张"RCE 组已修好"：四轮读数仍是 FAIL / INCOMPLETE（原样保留）。
  程序面成立只说明**这一层**没问题；回复层的违规照旧存在。
· 不主张"回复层违规不该修"：它属 M6-FMB-01（假记忆边界）那一类，
  而登记册写着硬顺序（判定契约 → 量具有效性 → 才决定机器门与实现方案）⇒ 要**先裁定**。
· 不主张 `verdict@2.2` 的读数无效：缺口是"没检查某一层"，不是"检查错了"；
  它报的每一条违规都有原文标签撑着。
· 不主张人审项（RCE-03/06/10）可以由本文代替：那三条要真人盲审。
· 不主张量具参数应当改动（裁定 C 逐字：现在都不改）。
```
