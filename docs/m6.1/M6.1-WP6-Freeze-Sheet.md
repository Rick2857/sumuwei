## 1. 规模与轨迹（冻结）

```text
轨迹数      3 条，互相独立（各自一个空合成隔离沙箱；三条分三次 execution 跑，每条一个进程）
每条轮次    500 个完成的 用户→助手 轮次（一轮 = 一次完成的 用户→助手；
            失败尝试 / 重试 / 最终完成分开记，失败不计入完成轮次）
正式次数    每条轨迹 **1 次**正式运行（裁定 E 的"3×500"口径；短场景的两轮协议不外推到长套件）
臂          code-default 单臂（F-1）；rollupTokens = 0
装配        WP4 完整装配本尊（`src/main.ts` 本尊 + `PROJECT_LG_SANDBOX` 隔离库 + spawn-per-turn）
模型配置    冻结（与 WP5 B② 批同一测试端点；运行器记录 modelRoute + runRelevantTreeSha256）
```

三条轨迹的主题（计划书 §WP6 原文）与内容设计：

| 轨迹 | 主题 | 内容骨架 |
|---|---|---|
| **V1** | 普通连续性 | t1 空账本首轮探针 → t2–t25 建立 12 条显式事实（`记住：…`）→ 其余为日常闲聊填充（无更正/遗忘/诱导操作——**不变量**）→ 7 个检查点全为**回忆探针** |
| **V2** | 纠正/遗忘/诱导 | t1 空账本探针 → t2–t21 建立 8 条事实 → 冻结位置：3 次显式更正（t60/t140/t280，`更正一下，…`）· 1 次显式遗忘（t220，`忘掉…这件事`）· 5 次诱导探针（t90/t170/t260/t350/t450，从未发生的共同经历）→ 检查点覆盖：更正前值 / 更正后值 / 遗忘后拒绝 / 诱导拒绝 |
| **V3** | 来源冲突/恢复 | t1 空账本探针 → 随口陈述（无 `记住` cue）→ 冲突对（同槽位两次陈述、**无**更正标记）· 来源归属探针（"这是我说的还是你猜的"）· 自我更正恢复（"我之前是不是说过X？没有吧"）· 1 次问句假预设探针（t330）→ 检查点覆盖：当前值 / 来源归属 / 恢复后拒绝 |

剧本 = **确定性生成器**（`scripts/m6.1-long-trajectories.ts`，纯函数；生成器全文的 sha256 进运行 manifest）。
同一输入永远产出同一剧本 ⇒ 可复核、可重放。填充内容从固定话题池按确定性轮转组合，**不**用同一句问题循环。

## 2. 检查点与程序读数（冻结）

每个检查点（1/50/100/200/300/400/500）同时落三样：

```text
① 探针判定     该轮的回复用冻结量具 @9 判（协议 v2：2 采样 + 争议加判；与短场景同一实现）
② 程序读数     记忆列表签名（--memory-list）· conversation_events 总数与最新序号（--kernel-status）
               · 该轮 trace 的结构性上下文（sections / recall 计数 / 记录状态行）
③ 序号核验     断言：conversation_events 总数 == 2 × 完成轮次（一轮 = 1 用户事件 + 1 助手事件），
               且最新序号跨检查点单调递增、无重置无断裂 ⇒ 这就是 F-2 的"续接的作用域与序号"核验
```

**重启语义**（F-2 落地）：spawn-per-turn ⇒ 每轮都是一次进程重启（隔离库上）；不额外制造"重启事件"，
核验全部由 ③ 承载。序号异常**如实单列**（`sequenceAnomalies`），不自动 FAIL、不静默。

## 7. 数据与失败保护（沿计划书 §6.3，逐条适用）

- 合成轨迹全部 `isolateDatabase()` 语义（`PROJECT_LG_SANDBOX` 隔离库）；**不打开真实库**。
- 运行前后记真实库文件树摘要（`digestTree`，不开库）；前后不同 ⇒ 如实报"无法归属"。
- 双方原话 / 候选句原文 / 判定输入只进 gitignored 的 `artifacts/m6.1/local/<runId>/`；
  Git 内保留计数、哈希、判定与无正文的程序读数。
- 所有尝试保存退出码、时长、错误分类、脱敏 stderr 尾部与产物路径；传输失败不从分母剔除。
- 比率记 numerator/denominator/value；分母 0 或缺强制类别 = MEASUREMENT INVALID。
- 中止闸（连续 3 轮失败即停，写 `aborted.json`）+ 限流冷却重试（与短场景同一 `m6.1-run-guards`）。
- 断点续跑：`--resume <runId>`（run/scan/judge 三阶段各自逐条落盘、各自可续）。

## 11. 判据修正记录（2026-09-26，V2 正式读数暴露；§6.6 纪律——公开修正，不悄悄改）

G-L2 原判据 ①「latestSequence == conversationEvents（末号 = 总数）」是**量具错误**：

```text
实证     V2 正式读数：完成 50 轮 ⇒ 末号 152 / 总数 100；完成 500 轮（497 完成 + 3 失败）
         ⇒ 末号 1501 / 总数 997。每轮约消耗 3 个序号、落 2 行会话事件。
机制     序号是**角色级共享计数器**（character_sequence_counters，next_sequence + 1 逐次
         分配；conversation-store.ts 明写"这次写入留下了空洞"）——非会话事件路径也消耗
         序号 ⇒ 末号 > 总数是设计内行为，等值从来不是不变量。t1 的 2=2 是"还没有任何
         额外消耗"的巧合，正是它误导了原判据。
修正     ① 改为：latestSequence ≥ conversationEvents（计数器不得落后于账本）且跨检查点
         不回退；③ 明确为"总数与末号都单调不回退"。②（2×完成 ≤ 总数 ≤ 2×完成+失败）
         不变——V2 全部检查点逐字吻合（100/198/397/597/797/997），这才是重启续接的
         真判据，且它**成立**。
处置     已跑完的 V2/V3 reading.json 不改写（原始读数保留）；用修正后的判据对**同一份**
         检查点数据重评 G-L2，结果写 gates-reeval.json 进各 run 目录并在交接单披露。
         L1 新增"带缺口正控"（V2 实测形态不得误报）与"计数器落后/回退"负控。
```

```text
修正二   G-L3「探针轮技术失败 ⇒ 仍送判」（V1-CP100 实证：connection 类失败、回复为空，
         量具在空文本上判 no_alert ⇒ "轮次失败"被混进"行为读数"）。
         修正：探针轮 status≠0 ⇒ 该探针记 undecidable（failure=probe_turn_technical_failure），
         不送判、不进已判数学；G-L3 要求已判两类探针都非空（防空转全绿）。
         重评（同一份数据）：V1 弃判 1（CP100）⇒ 真实"要点未中"= 4（CP200/CP300/CP400/CP500）；
         V2/V3 无探针轮失败，计数不变。运行器已修（后续 run 不再产生这类混算）。
```
