# M6.1 — WP4 对 M5 判据的兼容性变更记录（M5 Compatible Assertion Record）

> **为什么要这份文件**：M6.1 WP4 的 `D1′`（ADR-055 `D-55e`）**有意**改变了
> 「空召回 ⇒ 零 section」这条 M5 机制 —— 她必须能看见**程序生成的记录状态行**，
> 否则"什么都没有"会被读成"可以自由发挥"（R-2 的实测根因）。
> 于是 `pnpm m5:runtime:verify` 的两条断言不再为真。
>
> 改 M5 已冻结的判据**必须逐条留痕**，否则下一个人无法区分"判据被合理更新"
> 与"判据被悄悄放宽"。格式沿用 M5.1.1 的兼容性记录：
> **[文件] · [旧断言] · [新断言] · [为什么这不是放宽]**。
> 本文件只覆盖 M6.1 WP4 改动的 M5 判据。

日期：2026-09-24 · 归属：**M6.1 / WP4** · 载体：[`ADR-055`](../adr/ADR-055-m6.1-wp4-explicit-memory-correction-and-context-facts.md) `D-55e`
冻结设计：[`M6.1-Root-Cause-and-Design.md`](./M6.1-Root-Cause-and-Design.md) §4.5（已冻结）

## 1. 总原则

```text
① M5 的**语义**一个字不改：召回仍然只读、资格/排序/预算/去重全部不动；
   被裁的仍然是"记忆内容"这一条链（`memory-recall`，`droppable: true`）。
② 变的是**一条新增的程序事实 section**（`memory-record-status`，`kind: 'record-status'`）：
   它有**自己的额度**（`ContextCompileInput.statusTokenBudget`，缺省 120 token），
   **不占**共享预算 ⇒ 它不会挤掉记忆（这条由 L1 的不变量直接断言）。
③ 没有任何断言被"改成更容易通过"：被替换的每一条都换成**更强**的版本 ——
   从"prompt 逐字节相同"改成"差异**只**能来自那一行状态、且**不得**出现记忆内容 section、
   且"检索过"的那一轮**不许**说"没有发起检索"。
④ M3.5 的 `prompt 逐字节基线`（`evals/fixtures/m3.5/prompt-baseline.txt`）**没有被动过**：
   基线构造器（`scripts/m3.5-prompt-baseline.ts`）走 `buildContextCompilerV2` 且**不传**
   `extraProviders` ⇒ 状态行**不进**那条路径（`pnpm m3.5:test` EXIT 0 即此事的机器读数）。
```

## 2. 逐条变更

| # | 文件 | 旧断言 | 新断言 | 为什么不是放宽 |
|---|---|---|---|---|
| M5-1 | `scripts/verify-m5-runtime.ts` §② | `**逐字节**一致：无关问句下"接端口"与"不接端口"的 prompt 完全相同` | `差异**只**来自程序生成的记录状态行：去掉它之后，两者的 prompt 逐字节相同`（比较 `withoutStatusSection()`） | 判据换了对象而不是放宽：原来比的是"整段 prompt 相同"，现在比的是"**除状态行外**逐字节相同"，并**新增**一条"两轮都不得出现 `memory-recall` section"。差异被限定到一行程序文本 ⇒ 任何**记忆内容**泄漏仍然必红 |
| M5-2 | 同上 §② | `这是 FC-T08（prompt 逐字节基线）不被破坏的机制 —— 空召回 = 0 个 section` | `**不得**出现记忆内容 section：两轮的 section 名单逐字相同（都只有状态行）` **＋**（新增）`D-55e：两轮的具名原因**不同**，且"检索过"的那一轮**不得**说"没有发起检索"` | 旧断言的**意图**（保护 prompt 基线不被记忆内容污染）被保留成"名单逐字相同 + 无 `memory-recall`"；FC-T08 基线的保护机制改由"基线构造器不传 extraProviders"承担，并由 `m3.5:test` 直接守。新增的一条**更严**：禁止把"检索过但没命中"写成"没有发起检索" |
| M5-3 | 同上 §③ | `关掉开关后的 prompt 与"没有召回"逐字节一致（同一句话）` | `D-55e：关掉开关后的差异**只**是状态行，且那个具名原因是"开关关闭"（与"端口未接"分得开）` | 从"整段相同"改成"除状态行外相同 **且** 三种缺省各自具名"。旧断言无法区分"没查"与"查失败/查了没命中"，新断言**要求**它们不同（这正是 ADR-055 §2.1 ④ 的落地） |

覆盖范围（**本轮实测**）：`pnpm m5:runtime:verify` **28 通过 / 0 失败**（变更前是 25 / 2）。

## 3. 另有一处**不是**断言变更的处置（必须写清）

`pnpm m5:verify` 的静态锁 AT2.1（"排除理由字符串不许出现在判定层"）在本轮**先红后绿**：

```text
红：`src/kernel/app/recall/record-status.ts` 里出现了 'FORGOTTEN' / 'SUPERSEDED' 字面量
    （映射"排除理由 → 记录状态原因"要引用它们）。
处置：**不改判据**，改实现 —— 把那个映射搬进 `src/kernel/contracts/recall.ts`
     （`recordStatusReasonOfExclusion()`，静态锁明确允许的位置），消费方改成
     **逐条读直方图**再翻译 ⇒ 判定层一个理由字面量都不写。
⇒ 这是"代码去符合既有的锁"，不是"把锁放宽"。读数：`pnpm m5:verify` 26 通过 / 0 失败。
```
