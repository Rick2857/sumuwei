### B.2 ⚠️ Layer D 抓到的**第二个**缺口（离线三层全绿时它穿过去了）

第一版的相关性闸只用 `predicate + value` 当候选文本，于是：

```text
用户说「忘掉我不吃香菜这件事」
记录是 food.preference.cilantro = dislike
→ haystack 里**没有"香菜"两个字**（它在英文键与登记表的中文说明里）
→ 判成零命中 → not_found
→ **用户明确要求忘掉的那条，系统说找不到**
```

**为什么离线三层全绿**：它们的夹具恰好都是"值里含中文"的形状
（`示例工程科技大学` / `VS Code`）。实测冒烟 S3 红、S7（它的下游）跟着红 ——
**这是 M4.1 里第二次由"装起来跑"发现的缺陷**，与 M4 的 D1 同源。

**修法用的是本项目自己的教条**（`memory-predicates.ts` 原文）：

> 同义词归并的正确位置是**登记表**

因此把登记项的 `description` / `examples` 算进候选文本。
连带影响两处，均给了**显式开关** `includeRegistrySurfaceForms`：

| 调用方 | 取值 | 要什么 | 为什么 |
|---|---|---|---|
| 相关性闸（第 3 步） | `true` | **召回** | "香菜"只在登记表里 |
| 词面判别器（第 5 步） | `false` | **精度** | 否则多条候选的登记描述共享同一个词 → 总是弃权 → 这一步失效 |

**离线的回归锁**（关键 —— 以后不必再等真实冒烟）：
`m4:test` `T-D1-008`、`m4:nl-mutation` `L3-08`。

> 这一节本身就是 INV-M41-05 的活证据：**993 项全绿挡不住它，真实多轮一跑就现形。**

### B.3 两处**测试夹具/量具**的问题（都是我自己写的）

这两处是**同一类错误的两面**，而且是同一段代码：`activeValues()`。
它们值得单独记，因为**两次都是"被测对象是好的，量它的东西是坏的"**，
而且两次都会把绿的说成红的 —— 与 M4 的事故恰好反方向，但同样危险：
**一个会假红的量具，最终会被拿去"解释"而不再被信任。**

**(1) 噪声混进来。** 冒烟第一版用"取所有含 `=` 的行"来读 active 记忆，于是把
启动日志里的 `hash=…`、`载入状态 v13：valence=…` 一起收了进来 —— 两次调用之间
**日志本身会变**，于是「active 集合逐条不变」在库没动的情况下红了
（实测 `24 → 24`：条数一样、内容不一样）。
判据已改为只按"记录内容行"的形状筛（形如 `predicate = value`，
且不含日志特征词）。

**(2) 范围放太宽（第三次冒烟才暴露，见 §D.2）。** 函数名叫 `activeValues`，
但 `--memory-list` **默认列出所有状态**的记录，retracted 的旧行也被当成了
"当前有效事实"：

```text
S3「忘掉我不吃香菜这件事」
  stats  : active 2→1, retracted 1→2   ← 库里的行为是对的
  S7     : activeValues() 仍读出 food.preference.cilantro = dislike → 假红
```

修法：显式传 `--status active`（生产 CLI 本来就支持这个筛选）。
**没有放松任何断言** —— S7 想验的"她真的不再把这条当有效事实"一个字没改，
改的只是"去哪里读"。

> 教训与本项目已有的一条同源：**先问"我量的是不是我关心的那个东西"，
> 再问"它是红是绿"。** 这里如果偷懒把 S7 删掉或改弱，就会掩盖 §B.2 那个真实缺口
> —— 事实上 S7 在 §B.2 里正是靠"红"把缺口顶出来的。

### E.5 结论

**M4.1 修复有效，13 个 Gate 全绿，两个 Hard Gate（G12 / G13）都在"装起来跑"
的那一层拿到机器证据。** 结论是 **PASS**，依据不是"测试数变多了"，
而是下面三件在修复前**不成立**的事，现在成立：

| # | 修复前（有证据） | 修复后（有证据） |
|---|---|---|
| 1 | 库里有且仅有一条 active 时，**任何** forget 说法都会改它 —— 「忘掉我养过一只鹦鹉」把示科那条撤了 | 只有**词面相关**才允许命中；S4 场景下示科那条一字不动（G13 S4 / Layer B 20/20） |
| 2 | 用户明确要求忘掉、且那条**真的存在**时，系统说"找不到"（零线索 → not_found） | 「忘掉我不吃香菜这件事」正确命中并撤销（G13 S3；离线回归锁 `T-D1-008` / `L3-08`） |
| 3 | 抽取不支持的说法时，她仍可能用"记住了"这种成功口吻回答，而库里什么都没发生 | 回复由 `applyResponseTruthPolicy` 与实际执行结果绑定；S1b/S2/S4/S5 逐轮机器判定"未宣称成功"（C23） |

**必须同时说清的三点限制**（否则上面的 PASS 会被误读）：

1. **993 项离线断言在修复前也是全绿的**，其中还有一份专门盯这个问题的
   离线套件。真正把 D1 与它的同源缺口抓出来的是 **Layer D（真实多轮）**。
   → 这是 INV-M41-05，也是本轮最有价值的产出：**"装起来跑"不是可选项。**
2. **自动记忆路径（D3）仍然没有接生产**，这是**如实记录**而不是修复：
   `CHARACTER_MEMORY_BACKGROUND_ENABLED` 已被标注 `NOT-WIRED` + 启动告警 +
   回归锁。用户说"记住某事"时走的是**显式路径**，这条路径的写入是可靠的。
3. **报告里没有"PASS WITH KNOWN S1"这种写法**（任务书硬规则）：
   要么 S1 不存在，要么结论就是 FAIL。本轮 S1 的形态（唯一 active → 自动命中）
   已被 §B.1 的相关性闸消除，且由正控 S1a/S3 与负控 S4/S5 双向锁定。

Scenario A–E 真库多轮黑盒），它们**不影响**本轮 PASS —— 本轮修的是
"安全地不写/不删"，而推迟的两项测的是"规模与语义召回"。
