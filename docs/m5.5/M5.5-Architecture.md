## 0. 一句话

M5.5 **只做一件事**：让"她这一轮从外面看到了什么"成为一条**可审计的执行事实**，
并且让**她说不说实话由程序决定，而不是由模型的措辞决定**。

```text
M5.5 交付的不是"联网能力"，是"一句外部事实的完整证据链"：
  一次出站 → 一次普通动作 → 一份 typed 证据 → 一段可裁的上下文 → 一句被程序绑定的回复
它刻意**不**新建任何平行系统：Bundle / 上下文拼接 / trace / 账本 / 执行路径全部复用既有那套。
```

## 1. 分层与唯一插入点

依赖方向与仓库既有纪律完全一致（`infrastructure → domain`，绝不反向）。

```text
┌─ 纯契约（不 import 基础设施 / node:*）─────────────────────────────────────────┐
│  src/kernel/contracts/external-evidence.ts                                    │
│    ExternalEvidence（当轮内存，**含摘要**） / ExternalEvidenceRef（**无摘要**）  │
│    EVIDENCE_LIMITS · 构造 buildExternalEvidenceList · 投影 toExternalEvidenceRef│
│    渲染 renderExternalEvidenceBlock · 附录 buildCitationAppendix               │
│    WP5 追加：selectExternalEvidenceContext · evidenceContextReality             │
│  src/kernel/contracts/{context,recall,trace,observability}.ts                  │
│    section 种类 'external-evidence' · SECTION_PRIORITY=45 · TraceStepKind       │
│    'external_evidence' · TRACE_STEP_STAGE → 既有 'context'                      │
└───────────────────────────────────────────────────────────────────────────────┘
                                   ↑ 只依赖类型
┌─ 行动协议（与 contracts 同纪律；不 import 基础设施）───────────────────────────┐
│  src/kernel/action/external-evidence-capability.ts  能力声明（独立工厂）        │
│  src/kernel/action/external-evidence-intent.ts      显式词形 → 一次请求          │
│  src/kernel/action/external-evidence-reply.ts       回复五态 · 剥离 · 确定性附录 │
│  src/kernel/action/search-port.ts                   provider 端口（只有三样入参）│
└───────────────────────────────────────────────────────────────────────────────┘
                                   ↑ 端口由装配层注入实现
┌─ 基础设施 ────────────────────────────────────────────────────────────────────┐
│  src/infrastructure/search/{search-config,searxng-search-provider,            │
│    fingerprint,recording-fetch,fixture-search-provider}.ts                    │
│  src/infrastructure/action/adapters/web-search.ts   provider 结果 → typed 证据  │
└───────────────────────────────────────────────────────────────────────────────┘
                                   ↑ 只有装配层能构造真实 provider
┌─ 装配层（唯一允许依赖基础设施的 kernel 目录 + 唯一入口）───────────────────────┐
│  src/kernel/app/turn-gateway.ts  唯一插入点：beginTurn / compileTurn / completeTurn│
│  src/main.ts                     授予权限 + 构造适配器 + 守卫链 + 开发者面注入   │
└───────────────────────────────────────────────────────────────────────────────┘
```

**唯一插入点**（计划书附录 A.1，实测）：

| 阶段 | 位置 | M5.5 动作 |
|---|---|---|
| ① `beginTurn` | `src/kernel/app/turn-gateway.ts` 的既有 action 段 | 搜索走**既有** action 链；结果挂到 `IncomingTurn.actionResults` |
| ② `compileTurn` | 同文件 | 有界选择 → `external-evidence` section → bundle 挂载（**只有接了召回端口时**）→ 编译**之后**写 `external_evidence` step |
| ③ 回复层 | `src/main.ts` | guard 链尾追加外部证据回复策略，**在 `completeTurn` 之前** |
| ④ `completeTurn` | `turn-gateway.ts` | 落账本（只 refs）、收 trace |

## 2. 一次搜索的完整链路

与 ADR-045 `D-3` 一致：**一次联网 = 一次普通动作**，它有副作用等级、有权限、有终态账本、有执行真相。

| # | 环节 | 落点 | 关键性质 |
|---:|---|---|---|
| 1 | 能力**恒登记** | `createExternalEvidenceCapabilityDefinitions()`（`D-11` 独立工厂） | 不并入 `createDefaultCapabilityDefinitions()` ⇒ M4.5 的"默认 3 个能力"判据不变 |
| 2 | 意图判定 | `createExternalEvidenceIntentDetector()`（`D-5`/`D-6`） | **只有明确词形**才触发（搜索 / 搜一下 / 查一下 / 上网查 / 联网查 / web search）；**模型不决定执行** |
| 3 | 检测器链 | `chainIntentDetectors([M4.5, M5.5])` | 混合指令**本地优先**（文件读写可回滚，联网不可撤回） |
| 4 | 目标解析 | `main.ts` 的 `resolveTarget` → `{type:'external_service', canonicalId:'searxng-local', confidence:'exact'}` | endpoint 是**代码常量**，与用户输入无关 ⇒ `exact` 是如实，不是"只有一个候选就说是它" |
| 5 | 策略 | 既有 Policy（唯一入口） | 权限 `web:search`、`sideEffect=read`、`riskLevel=R1`、`idempotency='none'`（`D-13`）；**拒绝时适配器一次都不被调用** |
| 6 | 适配器 | `web-search.ts` | 发请求**之前**校验 query/limit/locale（失败关闭） |
| 7 | provider | `searxng-search-provider.ts` | 1 请求 / 0 重试 / 硬超时 5000ms / ≤5 |
| 8 | 构造证据 | `buildExternalEvidenceList()`（唯一入口） | 逐条校验 + 去重 + 稳定标签 `E1…En`；拒绝**如实计数**，不静默修；`id` 由 provider+指纹派生（不含时间） |
| 9 | 内存载体 | `ActionResult.externalEvidence` | **含摘要**（模型要读它）；**永不进库** |
| 10 | 上下文 | `selectExternalEvidenceContext()`（独立额度）→ `external-evidence` section | kind `external-evidence` · 优先级 **45 > 记忆 40** · `droppable: true`（用户显式要求的数据优先于机会性回忆） |
| 11 | 现实判定 | `evidenceContextReality()` | **"选择器选了谁" ≠ "模型看到了谁"**：section 是一个原子，被整段丢掉时 `selected` 就是空 |
| 12 | trace | `external_evidence` step，映射到既有 `context` 阶段（`D-15`） | 属性恰好七键（下表）；**只在真的尝试过搜索时**才追加 ⇒ 普通对话的 trace 不变长 |

`external_evidence` step 的七个属性（`D-18③`：全部落在既有白名单或 `_count`/`_ids` 后缀族内，
**不需要**扩 telemetry 白名单）：

```text
provider · candidate_count · selected_count · evidence_budget_dropped_count
context_budget_dropped_count · selected_evidence_ids · bundle_attached_count
```

`bundle_attached_count` 的两种取值是**两个装配**，不是两种运气：

| 装配 | 结果 | 出处 |
|---|---|---|
| 没接召回端口 | `0` —— 没有 bundle 可挂，**证据仍然进 prompt** | `artifacts/m5.5/verify-runtime.json` 的 `positive.traceAttributes` |
| 接了召回端口 | `1` —— `withExternalEvidence()` 真的被走到 | WP9 真实一轮：`artifacts/m5.5/smoke/smoke-result.json` 的 `level2.tracesWithExternalEvidence` / `selectedCounts` |

## 3. 两条隐私边界

### 3.1 `D-8` —— 引用是**唯一**的落库通道

```text
ExternalEvidence（内存，含 snippet + title）
        │
        └── toExternalEvidenceRef()  ← **唯一**的通道；它只挑七个字段
                │
                ├─→ 账本 ActionEvidence[].externalEvidence（引用）
                └─→ ContextBundle.externalEvidence（引用）
ExternalEvidenceRef 的字段：kind · id · provider · source · retrievedAt
                            · contentFingerprint · citationLabel
        ⇒ **没有 snippet，也没有 title**
```

trace / 账本只存 URL、来源、时间、指纹、计数、标签（`D-8` 逐字）。
落地证据：L2 门的哨兵级负控（`snippetSentinelInTrace: false` · `titleSentinelInTrace: false`
· `snippetSentinelInLedger: false`，见 `artifacts/m5.5/verify-runtime.json` 的 `privacy`），
以及 WP9 真实一轮（账本行详情 `evidence 6 条` 且整份详情里没有正文）。

### 3.2 `D-18` —— 三件配套边界

| # | 边界 | 可检形式 |
|---|---|---|
| ① | 证据**不经召回管线** | `selectMemoryContext` 仍恒填 `externalEvidence: []`；证据在 gateway 层附加 ⇒ `verify-m5-runtime.ts` 的既有断言继续为真（COMPAT-2） |
| ② | 开发者面**只**经既有注入点 `runtimeCapabilities` 上报可用性；**不改** `query-service.ts` 与 DTO 表 | 八个开发者面文件（含 `developer-query.ts` 等 DTO 表）与 M5.5 动手前（`cfd9219`）**逐字节相同**；`query-service.ts` 里没有 `web.search` 字样（量具 §12，正控 + 三负控） |
| ③ | **不**扩 telemetry attribute 白名单 | 七个属性键过得了 `assertTelemetryAttributesAllowed`；把 `snippet` 加进去**必须被拒** |

## 4. 回复真相：三层

`D-9`（来源列表由程序追加）与 `D-17`（五态 + 剥离）落在**三层**上，缺一层都不够。

```text
第 1 层（前置，prompt 层）  droppable:false 的 action-result section
        ⇒ 让模型**倾向于**如实转述"这一轮动作做成了什么"
        ⇒ WP9 实测：真超时那一轮，她自己就说了"一次动作执行超时了…我不说它成了"

第 2 层（后置，确定性守卫） src/main.ts 的守卫链
        记忆（applyResponseTruthPolicy） → 动作（applyActionClaimGuard）
          → 外部证据（applyExternalEvidenceReplyPolicy）
        ⇒ 最终 replyText 取自**最后一道**；仍在 completeTurn（写账本）**之前**
        ⇒ 账本 = 用户所见（M4.1 的现场纪律）

第 3 层（同一处完成的两件事）
        ① **剥离**：正文里所有 [E<n>] 形态标签一律去掉（连合法编号也去）
           —— 因为"标签挂在哪句话后面"机器验证不了（D-17）
        ② **追加**：查到并形成证据时，按**实际入模集合**追加确定性来源附录（D-9）
```

五态（由**程序**确定性映射，不看模型措辞）：

| 用户可见态 | 来源事实 | 程序行为 |
|---|---|---|
| 查到并形成证据 | `success` 且实际入模 > 0 | 守卫安静 + 追加来源附录 |
| 搜索执行但无结果 | `success` 且实际入模 = 0（含"被预算裁掉"） | 无附录；出现成功口吻时顶替成如实句 |
| 超时 | `timeout` | 同上（如实句） |
| 失败 | `failed` / `rejected`（非授权） | 同上（如实句） |
| 未启用联网 | `rejected` + `permission_denied` | 同上说"联网搜索没有启用" |

⚠️ 两个**刻意的边界**（详见 [`M5.5-Known-Limitations.md`](./M5.5-Known-Limitations.md) L-M55-03/04）：
`no_search` 时守卫**完全不经手**（与 `applyActionClaimGuard` 在 `results === undefined` 时同一纪律）；
非成功态**只在回复出现成功口吻时**才顶替。

## 5. 预算与开关

| 名字 | 缺省 | 有界 | 语义 |
|---|---|---|---|
| `ContextBudget.externalEvidenceTokens` | **0** | `assertContextBudget` 要求 `记忆 + 预留 + 外部证据 ≤ 总预算` | 证据的**独立**额度（与上下文总预算是两件事）；缺省 0 = "今天不注入外部证据"是**真实配置**，不是忘了填（COMPAT-3） |
| `CHARACTER_WEB_SEARCH_ENABLED` | **false** | 真值词 `1/true/yes/on`；坏值退回 false | 决定**两件事**，少一件都不算打开：① 是否授予 `web:search` ② 是否构造 provider + 适配器（`D-12`） |
| `CHARACTER_WEB_SEARCH_EVIDENCE_TOKENS` | **800** | 0..2000（越界**夹住**；非整数退回缺省） | 只在 flag on 时才被装配层用；flag off 时传 0 |

⚠️ flag off ⇒ 策略在授权那一步拒绝 ⇒ 用户说"搜一下"得到的是一条**可审计的** `permission_denied`
（模型据此如实说"联网没启用"），而**不是**"装作没听懂"（`D-12`）。

## 6. provider：`P-2 / 本地 SearXNG`（ADR-047 `D-31`）

| 项 | 冻结值 |
|---|---|
| endpoint | `http://127.0.0.1:8080/search`（loopback 逐段校验：127.0.0.1 / 8080 / `/search` / 无 userinfo·hash·query） |
| 健康 | `http://127.0.0.1:8080/healthz` |
| method / body / 请求头 | `GET` · **body = 0** · 只有 `accept` |
| 参数（**恰好六个**） | `q` · `format=json` · `language` · `pageno=1` · `safesearch=1` · `engines=duckduckgo,wikipedia,wikidata` |
| 认证 / SDK | **无**（无 key、无 cookie）· 无 SDK |
| 有界 | 1 次请求 · 0 重试 · 硬超时 5000ms · 结果 ≤ 5 |
| 价格 | `api_fee = 0`（自托管）；成本**只报告、不阻断**（`D-30` 的结论沿用） |
| 生产激活 | `NOT_APPROVED` |

> ⚠️ **"本地"≠"不出站"**：`q` 会被本机实例**转发给**上面那三个上游引擎。
> 这句话在 WP9 的门输出里被逐字打印出来，也在证据里（`frozenFacts.outboundScope`）。

## 7. 三条跨里程碑硬性质如何在 M5.5 落地

| 硬性质 | M5.5 的落地 | 证据 |
|---|---|---|
| ① 她生成的内容**永不**自动变成外部事实 | 外部证据只活在**当轮内存 + 上下文 + 引用**里；`D-7` 明文禁止自动进长期记忆 | L2/L3 的"记忆侧计数 + 内容快照哈希逐项不变"、业务表摘要不变（配"动作表确实变了"的对照） |

| ③ 有副作用就必须有目标确定性、有账本、有 traceId；**没成功就没成功口吻** | 走完 M4.5 全链（策略 → 账本 → trace）；回复真相对齐执行终态 | `artifacts/m5.5/verify-runtime.json`（账本一行 success + 一行 rejected）· `e2e.json` 场景 12 · WP9 真实一轮账本 `timeout, success` |
