### 5.2 工程上真实踩到的坑（写进代码注释了）

| # | 现象 | 根因 | 正确做法 |
|---:|---|---|---|
| E-1 | `conversationId 含有不适合放进 ID 的字符："…m5.5-runtime"` | 标签里的**点**不在 ID 允许字符集（只允许字母数字与 `_ - :`） | harness 统一把非法字符换成 `-` |
| E-2 | `会话内序号出现空洞：当前最大 5，收到 7` | `nextTurnSequence` 是 **harness 局部**计数器（一轮前进 2）；两个 harness 共用一个库 ⇒ 第二份从 1 重新数 | **一个隔离库配一个 harness**，且上一个必须先停掉 |
| E-3 | `会话内序号出现空洞` 的第二种成因 | `beginTurn` 开了序号却不 `completeTurn` ⇒ 留空洞 | 对照轮也要**走完整一轮** |
| E-4 | `解析 transport 身份：Failed query: select user_id from user_identity_mappings` | `resetPluginSqlConnection()` 在**上一个 runtime 还活着**时被调 | 先 `dispose()` 上一个 harness，再 reset，再建下一个 |
| E-5 | `PGlite is closed` | 在下一个 `freshBed` 已经停掉上一个 harness 之后，才去读它的账本 | 所有读数在**那个 harness 还活着的时候**取 |
| E-6 | `ERR_UNSUPPORTED_ESM_URL_SCHEME: Received protocol 'c:'` → 修完又变成 `Cannot find module '…/project'` | Windows 上 `--import` 必须给**百分号编码过的 `file://` URL**（工作区路径含空格 `project LG`） | 用 `pathToFileURL(...).href` |
| E-7 | `SyntaxError: Missing initializer in const declaration`（预载模块） | 预载路径**不经过 tsx 转译**，而我写了 TS 注解（`const x: string[] = []`） | 预载必须是**纯 JS**（`.mjs`） |
| E-8 | `拒绝写入真实对话库（…data\pglite）` —— 父进程读副本时 | 父进程没有把 `PGLITE_DATA_DIR` / `PROJECT_LG_SANDBOX` 指向副本 | 在**碰 `initDatabase` 之前**指过去。⚠️ 那个闸**是对的**，它又一次证明自己没有失效 |

```text
WP0–WP9 = 完成（含第一次真实出站）
```

来源列表是**程序生成**的，五态是**程序映射**的，出站形状是**可捕获且合规**的，
真实库**没有被碰过**，而"她最后说了什么"在真实模型 + 真实 provider 下**跑通过一次**。

**不能主张的**：逐句事实蕴含、抓全文、"有来源"等于"说法成立"、
以及任何形式的生产激活。逐条见
[`M5.5-Gate-Decision.md`](./M5.5-Gate-Decision.md) §3 与
[`M5.5-Known-Limitations.md`](./M5.5-Known-Limitations.md)。
