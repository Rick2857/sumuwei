```text
               生产激活 = NOT APPROVED
```

**口径必须说清楚**（否则这一行会被读大）：


把两半压成一个 PASS，正是这个仓库历史上最容易被读大的那类表述。

## 3. 这个判定**不**主张什么

为避免把"五道门全绿"读大，明确列出**不被主张**的东西：

```text
✗ 不主张"她从此说的都对" —— 本里程碑只让**来源集合与执行证据一致**，
   不做 claim-level 蕴含验证（ADR-045 D-10）。"有来源" ≠ "说法成立"
✗ 不主张"抓了网页全文" —— v1 只有**搜索结果级**证据（V-5 否决了抓全文）
✗ 不主张"她自称上过网时一定会被纠正" —— `no_search` 时守卫**完全不经手**
   （与 applyActionClaimGuard 在 results === undefined 时同一纪律，L-M55-03）
✗ 不主张"所有非成功态都会被改写" —— 只在回复**出现成功口吻**时才顶替（L-M55-04）
✗ 不主张"模型自写的来源会被清理" —— 只剥离 `[E<n>]` **形态**（L-M55-05）
✗ 不主张"词表是完备的" —— 它是启发式的，漏报退回 prompt 层（L-M55-06）
✗ 不主张"开发者面能看到每一轮的搜索细节" —— 只有一行可用性；计数在 trace 里（L-M55-08/09）
✗ 不主张"查询词一定是良构的" —— URL 形态的查询词今天会被放行（L-M55-10）
✗ 不主张"真实 provider 一定答得上来" —— WP9 实测冷启动会超时（L-M55-12）；
   注入用例也只是**可能**被真实返回满足（L-M55-13，主证在离线 fixture）
✗ 不主张"注入防护已被真实世界验证过" —— WP9 那一次是 SATISFIED，
   但确定性主证是 L2 门的 fixture 注入场景
✗ 不主张"生产激活已批准 / 真实聊天能联网" —— `production activation = NOT APPROVED`，
   `CHARACTER_WEB_SEARCH_ENABLED` 的真实聊天默认仍是 **false**（L-M55-14）
✗ 不主张"§5.1 的 14 处判据修正没有发生过" —— 它们**发生过**，全部留在
   M5.5-Acceptance-Report §5.1 与各轮提交信息里（AGENTS §6.6）
```

## 4. 什么会改变这个判定

```text
· 任一 Hard Gate 从 PASS 变 FAIL（含继承的 M4.5 / M5 / M5.1 / M5.1.1 门）→ 判定降级为 FAIL
· 任一硬门证据缺失 → 该门 not-run → 汇总器 `hardGateVerdict` 变 FAIL
  （汇总器已断言这条行为：文件不存在 = not-run，**不是** PASS）
· 出现"摘要正文进了 trace / 账本 / 开发者面"的实测案例 → 直接违反 INV-M55-02 / D-8
· 出现"来源列表与实际入模集合不一致"的实测案例 → 直接违反 INV-M55-04 / D-9
· 出现"没有显式搜索词形也发生了出站"的实测案例 → 直接违反 INV-M55-03 / D-5·D-6
· 外部证据出现在 `memory_records` 里 → 直接违反 INV-M55-06 / D-7
· 冻结面出现 diff（`docs/m5/**`、`docs/m5.1/**`、`docs/m5.1.1/**`、`ADR-045/046/047`、
  `artifacts/**` 的历史证据）→ 违反冻结纪律
· 真实库被任何一道门打开 / 写入 → 违反 AGENTS §3 与 §7
· 把本判定读成"联网已经在真实聊天里启用" → 违反 §0 的口径与 L-M55-14
```
