## 1. 它补的是什么（一句话）

```text
`D02` 的慢路径约定识别（有界窗口 + 一次模型调用 + 严格校验）此前**只有门在用** ——
`src/kernel/app/agreement/**` 在 `src/**` 里**没有任何运行时消费者**（`L-M10.1-11`）。
本步把**生产装配**接上：每轮之后按账本尾部跑一次识别，走出与目标理解**同一条**放行口与写路径。
```

## 2. 一次调用的完整路径

```text
账本尾部（`conversation_events`，角色级序号）
  → ① 有界读：`readAgreementWindowEntries`（区间 + 上限 50 + **撤销先遮蔽**）
  → ② 装配：`assembleAgreementWindow`（再遮蔽一次；`windowTruncated` ⇒ **本次不下结论**）
  → ③ **一次**模型调用：`createOpenAiAgreementDraftProvider`（窗口按 `[序号] 说话者：正文` 渲染）
  → ④ 形状闸：`recognizeAgreement`（对象 / schema / 字段闭集 / kind 闭集 / **序号→事件 id 由程序解析**）
  → ⑤ 语义闸：WP1 的 `validateAgreementDraft`（同一方 / 顺序 / 遮蔽 / 上界 / 12 条具名理由）
  → ⑥ `buildAgreementProposal`（判据由**程序**给：v1 只代表 `user_report`）
  → ⑦ `draftToProgramProposal` → ⑧ `validateGoalProposal`（M10 的**唯一**放行口）
  → ⑨ 写事件 + 落投影（形状照抄 `m10-harness`：事件一事务、投影行另一事务）
```

**为什么模型只说序号**：WP1 的草案用**事件 id** 指出处，而窗口渲染里**没有 id**（长 UUID）。
让模型报 **`[序号]`**、由**程序**解析回 id ⇒ "指得到出处"在**形状上**成立（与目标域
"`targetGoalId` 必须来自程序给的候选"同一条纪律）。⇒ `proposal_not_found` /
`acceptance_not_found` **经模型面不可达**（如实登记在门里，不假装覆盖）。

## 3. 调度机器的五条硬性质（门里逐条有读数）

```text
① **一次性 cutover**（`D33`）：水位行不存在 ⇒ 预置成**此刻**的账本序号，本次**不消费** ⇒ 不回判历史。
② **失败不抛、水位不前进**：provider 抛 ⇒ `failed` + 任务行如实落 `failed` + 同窗下一轮 `retry_deferred`
   （尾窗下一轮重新覆盖 = 补洞）。**留 running 会让补洞永远走不通**（M8 WP7 的教训）。
③ **结论 ≠ 失败**：模型说"没有约定"（`no_agreement`）是**结论** ⇒ 水位**照样前进**（否则永远卡同一窗）。
④ **同窗不并发**：幂等键含 `[from,to]`；活干完再调 ⇒ `recovered`（只补水位，**不**重跑 ⇒ 不产生第二份业务事件）。
⑤ **晚写闸门**：`fence.closed` ⇒ `cancelled`，零写入（与 M11 共用同一把收尾闸门）。
```

## 5. 本步**没有**主张什么（新登记的边界）

```text
· **不**主张真模型会识别出约定 —— 本门用**桩** provider（离线）；真模型读数在 live 车道（`A11` 一节）。
· **不**主张生产已打开 —— 开关**代码缺省 off**；是否在生产 `.env` 里打开 = **独立裁定**（本步未做）。
· **不**主张多会话正确 —— 窗口按**角色**读尾部（`L-M10.1-13`：多房间在途时会混窗；单会话假设）。
· **不**主张全部三类判据 —— v1 的慢路径只代表 `user_report`（`L-M10.1-14`）；
  `conversation_output` / `action_result` 的约定会在 `buildAgreementProposal` 处被拒（**具名**，不是猜）。
· **不**主张到期会发生 —— 模型面**没有** `dueAt` 字段（`D06`：不猜日期）⇒ `U-04` 的边界照旧。
```
