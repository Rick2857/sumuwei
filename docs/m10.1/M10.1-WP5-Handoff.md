## 3. ⚠️ 本轮**发现并登记**的 M10 缺口 `L-M10.1-04`

```text
现象（实测）：走"**她提出**"那条路（`origin=character_proposed`）时，提案在放行口被拒：
  `GOAL_CREATED: goal_proposal_ambiguous_target`（连带承诺侧 `goal_not_found`）。
根因：`goal-validator.ts` 的 **D28 判据**要求 `character_proposed` 的 create 必须给出
  **两组**带 `span` 的引用（**提议侧 + 采纳侧**，跨轮无法唯一定位时必须澄清、不得猜）；
  而装配层（`understanding.ts` 的 create 分支）**只造一个** `sourceRef`（采纳侧），
  **从不使用** `draft.proposalSpan`。
覆盖情况：M10 的门只在 **`m10:source:verify` B5** 覆盖到 **`understood`**（草案被理解），
  **没有**覆盖"**放行口接受**" ⇒ 这个缺口此前**没有机器判据**。

⇒ 影响：**"她提出"的约定目前无法成为承诺**（"用户提出"那条路是通的，WP5 走的就是它）。
⇒ 为什么**不**在本轮顺手修：修它需要一个"**提议侧指纹**"约定 —— 提议原话（那条 assistant 消息）
   不在 `DraftToProgramInput` 的形状里 ⇒ 属**设计决定**（要不要扩输入形状？还是由调用方传指纹？），
   不是机械补丁。⇒ 登记，等裁定。
```
