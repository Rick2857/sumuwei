# Lv4.5 持续对话：可行性、开源复用与范围取舍

日期：2026-10-04。状态：**研究结论 / 建议方案，尚未实施或验收**。

本轮任务：核查尚未实现的持续对话能力，优先找现成方案，并说明工程代价和不采用的路线。核查基线为 `dd02f8b960a76ca83b10bbd6cb88de8497f7380d` 及本机已部署的皮套前端源码。只读核查与文档落盘；未安装新依赖、下载模型、启动模型测试或打开正式数据库。

## 1. 结论与推荐范围

目前可以建设一个**受限但真实的持续对话版本**：持续收音、临时理解/本地召回、语境内提前查证、少量快反、可靠停播、任务结果版本仲裁、依据播放事实续聊，以及合法新证据触发的中途纠正。

开源项目提供了不少可复用机制，但本轮没有找到能直接接上 LG、同时保留它全部人格/记忆/行动/回复检查约束的成套组件。推荐保留现有 Open-LLM-VTuber 外壳与 CosyVoice3 执行器，直接试用小型独立检测组件，借鉴 Pipecat / LiveKit 的协调实现，在 LG 内增加受限的临时准备和交付入口。

**首版不采用**：全域自由插话/争辩、持续重新推理整段回答、用端到端语音模型替换 LG 表达主链、迁移整套语音平台、强杀正在运行的 GPU 线程。它们分别涉及开放域语义品质、持续算力/调用成本、回复检查和声线替换、平台迁移、原生推理状态安全。

推荐包估算 **70–120 个有效工程小时**，包括专项联调与验收；按单人每个工作日约 8 小时，约 9–15 个工作日，通常需 2–3 周。数字是依据当前源码的粗估，不是已测工时或截止承诺；正式开工前应先用小范围探针校准。第一阶段的可取消播放与交付上下文预计 24–40 小时，可独立交付。

## 2. 八项能力的可行性

| 能力 | 判定 | 首版可以实现的范围 | 代价与局限 |
|---|---|---|---|
| 边听边理解、回忆、准备任务 | **可实现，需接入** | 真正音频块输入 → 带 revision 的 partial → LG 内临时只读召回/意图候选；final 才提交正式轮次 | 中等。当前 SenseVoice 入口是整段离线识别；不能直接打开一个 streaming 开关。复杂任务只提前做无副作用准备 |
| 边听边查证 | **有条件可实现** | 用户明确允许边听边查、对象已稳定、请求范围明确时，走既有搜索策略；结果保留请求/证据版本，final 再确认采信 | 中高。联网查询增加出站和费用；不能把任意半句话当出站授权，不能提前执行外部写操作 |
| 角色在用户结束前插话 | **限定场景可实现** | 呼唤、明确停止、明确更正冲突、已经允许的边查边提醒；短句后让出话权 | 中高。要新增合法的角色输出入口和话权调度；不能伪造用户轮次。开放话题的自由抢话/反驳本期不承诺 |
| 名字、固定短句、强信号快反 | **可实现，小集合优先** | 本地停止信号、角色呼唤、简短倾听回应；规则和流式识别优先，专用 KWS 可作后备 | 低至中。KWS 只能发现词语，不能天然区分引用、否定或对别人说话。名字不授权剧情或外部动作 |
| 用户插话、及时停播 | **可补齐与验收** | 已有 VAD/手动打断与版本过滤；补真实麦克风抢话、误打断恢复、扬声器回声负控 | 中。耳机与扬声器分别验证；检测到人声不自动等于有效抢话，设备环境影响结果 |
| 取消旧任务、话题改变后弃用旧答案 | **可实现分层协调** | 控制消息及时受理；本地停播；取消可取消的检索/准备；旧 generation 不能播放，旧 request 结果不能注入新话题 | 中高。LG 主模型还需取消信号和失败收口；已提交事件不撤销。不可取消的外部任务保留原 actionId，结果不重执行、不串入新话题 |
| 说到一半依据新信息纠正 | **限定证据可实现** | 合法检索新证据或用户最终更正到达 → 作废未播部分 → LG 重新判断/检查 → 新纠正段 | 高。现成框架解决调度与停播，不替 LG 判断证据是否推翻旧结论；无新证据的另一种模型措辞不能当事实更新 |
| 播放事实进入后续上下文；延迟验收 | **可实现，属于必须补齐的基础** | 客户端确认播完的句子进入语音上下文；中断/断线标未知；浏览器同钟记录首反馈与实质答复 | 中高。CosyVoice 当前没有本轮验证过的字词时间对齐，首版保守到完整句子，不按时间比例猜已说出的字；延迟达标须实测 |

“可实现”表示存在可接线的技术路径。中文识别、插话恰当度、CPU/GPU 占用、时延阈值和真人体验目前仍没有新验收读数。

## 3. GitHub 优先核查的候选

### 3.1 Pipecat：协调机制的主要源码参考

[仓库](https://github.com/pipecat-ai/pipecat)，代码 BSD-2-Clause。本轮 API 与原文件核查固定到 `c027943125c0ef7ea1b946b6c438032eb8ff0483`。

确认的可借鉴实现：

- [EagerUserTurnStopStrategy](https://github.com/pipecat-ai/pipecat/blob/c027943125c0ef7ea1b946b6c438032eb8ff0483/src/pipecat/turns/user_stop/eager_user_turn_stop_strategy.py)：预测结束后提前推理；继续讲话、转录不匹配或超时则撤回。
- [SpeculationGate](https://github.com/pipecat-ai/pipecat/blob/c027943125c0ef7ea1b946b6c438032eb8ff0483/src/pipecat/turns/speculation_gate.py)：未确认的回复暂存，确认后释放，否则丢弃；控制帧能越过普通队列。
- [LLMService](https://github.com/pipecat-ai/pipecat/blob/c027943125c0ef7ea1b946b6c438032eb8ff0483/src/pipecat/services/llm_service.py)：函数并行、打断取消、长任务生命周期。
- [TTSService](https://reference-server.pipecat.ai/en/stable/api/pipecat.services.tts_service.html)：音频上下文和可用时的字词时间戳；这不证明自定义 CosyVoice 已支持同等对齐。

采用判断：**借鉴消息优先级、推测结果撤回与任务生命周期；不直接接管 LG 对话**。当前环境已是 Python 语音服务，语言相容；但整包有自己的框架依赖和聊天上下文，不能为了几个机制直接替换已接好的外壳。复制源码时须保留许可声明，并对固定版本做独立适配测试。

注意：eager endpointing 是预测用户可能结束后的准备；它仍依赖服务给出对应信号，并不自动把当前 SenseVoice 变成流式识别，也不等于任意半句话都已足够理解。

### 3.2 Smart Turn v3.2：优先做独立组件探针

[仓库与说明](https://github.com/pipecat-ai/smart-turn)，固定源码 `4786657e242dfe77dd138699ac564ee074a2a543`，BSD-2-Clause。

官方提供本地音频话轮结束检测，包含中文，CPU INT8 模型约 8 MB；输入是 16 kHz 单声道音频，分析最近至多约 8 秒，在 VAD 检出静音后判断说话是否完成。可以单独使用其 ONNX 推理路径，无须迁移整个 Pipecat。[独立推理源码](https://github.com/pipecat-ai/smart-turn/blob/4786657e242dfe77dd138699ac564ee074a2a543/inference.py)

采用判断：**适合直接复用的小组件候选**，用于减少思考停顿时被抢答、减少过长等待。上游 CPU 时延不能当本机读数；Windows、当前 ONNX/特征提取依赖和中文句子要先实测。它判断话轮完整性，**没有替我们实现事实核实、主动插话或中途纠正**。

### 3.3 LiveKit Agents：重要参考，整体迁移作为后备

[Python 仓库](https://github.com/livekit/agents) / [Node 仓库](https://github.com/livekit/agents-js)，均 Apache-2.0。本轮固定源码分别为 `530ec952c030a68fcb4ac94c0a22c8b58806a256` / `c3a02bde8225f141b52266ed0c0545a4e99db526`。

官方机制涵盖话轮检测、误打断恢复、预生成和长任务并行。预生成通常从 STT 的一段 final transcript 到来时启动，早于整个用户话轮确认；转录/上下文变了要撤回。默认先做 LLM，提前 TTS 会额外浪费算力。[话轮参数](https://docs.livekit.io/agents/logic/turns/tuning/) · [音频与预生成](https://docs.livekit.io/agents/multimodality/audio/)

[异步工具](https://docs.livekit.io/agents/logic/tools/async/)支持工作继续进行时的交流与显式取消；取消仍要求向实际执行器传递信号。[固定版本的播放与上下文处理](https://github.com/livekit/agents/blob/530ec952c030a68fcb4ac94c0a22c8b58806a256/livekit-agents/livekit/agents/voice/agent_activity.py)在打断时使用可用的同步转录/播放位置，这正是 LG 应补齐的交付边界。

采用判断：**借鉴调度、取消传递、播放后上下文；不同时启动第二套 runtime**。整体使用需要适配媒体传输、客户端、LG 生成入口与现有皮套，并重新验证三本账。其本地与托管检测模型也要区分，不能把云端能力或 Python 功能直接视作 Node 本地可用。[检测器部署说明](https://docs.livekit.io/agents/logic/turns/turn-detector/)

### 3.4 sherpa-onnx：流式输入和有限 KWS 的现成选择

[仓库](https://github.com/k2-fsa/sherpa-onnx)，引擎代码 Apache-2.0；**各模型权重仍须单独核对许可**。

现有工程已用过 OnlineRecognizer / Zipformer，有音频块与 partial 处理的基础。[官方流式服务示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/streaming_server.py)

官方 KWS 支持自定义关键词，并提供中英与中文模型及 Windows 用法，可识别呼唤/停止词而不调用大模型。[KWS 机制](https://k2-fsa.github.io/sherpa/onnx/kws/index.html) · [模型与 Windows 示例](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html)

采用判断：**优先复用现有流式接口，KWS 作为可选后备**。KWS 是词检测，引用/否定/回声处理需要协调层补充。现有 SenseVoice 最终识别保持；流式输入方案见 §4，不能默认加两套 ASR。

### 3.5 RealtimeSTT：参考稳定 partial，暂不换识别栈

[仓库](https://github.com/KoljaB/RealtimeSTT)，核查到 MIT 代码许可。[配置说明](https://github.com/KoljaB/RealtimeSTT/blob/master/docs/configuration.md)提供实时转录更新、稳定转录回调及短静音时的提前识别。

采用判断：**接口与稳定文本策略参考**。它的录音/转录栈仍需要适配当前模型、网页麦克风和 LG；现有 sherpa 已能产 partial，没有证据支持为了回调更换识别引擎会更省工。未进行本机准确率、延迟或依赖验证。

### 3.6 TEN 主框架：本机运行路线不采用

[仓库](https://github.com/TEN-framework/ten-framework)已有实时语音示例，但[根许可证](https://github.com/TEN-framework/ten-framework/blob/main/LICENSE)是在 Apache-2.0 上添加条件，明确限制把框架或衍生品放在 End User devices 上，还包含竞争用途约束。

本项目在用户电脑本地运行。基于这一条款和部署适配成本，**不把 TEN 主框架作为本机 runtime 候选，也不从其受限核心直接复制实现**。这不是对整个 TEN 生态作同一许可判定；单独组件需要读取自己的 LICENSE。主框架未取得可靠固定 commit：GitHub API 本轮中途返回 403 rate limit，改用直接原文件核查。

### 3.7 PersonaPlex / Moshi：本期不采用端到端替换

[PersonaPlex 仓库](https://github.com/NVIDIA/personaplex)属于真正的全双工 speech-to-speech；[官方模型卡](https://huggingface.co/nvidia/personaplex-7b-v1)描述 7B 模型、英语输入输出和 Linux 支持。代码 MIT，权重另有 NVIDIA Open Model 许可。

不采用的理由：它直接生成语音，换掉当前可先检查的文本表达链；还需验证 LG 独立权威、中文、用户所选 CosyVoice 声线和本机算力。官方测试硬件不能当本机需求下限，也不能用 CPU offload 的存在证明低延迟。Moshi 自身的[PyTorch 路线说明](https://github.com/kyutai-labs/moshi)提到约 24 GB 显存，但不能据此断言任何量化 PersonaPlex 版本都需要同样显存。

这是架构与产品选择的大改，无法作为当前几个协调功能的低成本插件。**拒绝本期替换，不等于断言它在任何环境都无法运行**。

另查到 [HiThink Turn 论文](https://arxiv.org/abs/2609.34096)，研究意图足够的前缀、播放状态和选择性打断；本轮未找到可核对的官方实现/权重/许可链，因此只记为研究参考，不计作成熟现成方案。

## 4. 流式识别是实际依赖，不能掩盖

当前网页 `LGSenseVoiceASR.transcribe_np()` 接收完整录音；浏览器 `handleSpeechEnd()` 才把音频交给后端，`handleFrameProcessed()` 只记录语音概率。因此两个地方都要改：实时发送带序号的音频块，后端产带假设版本的 partial/final。

可以优先探测现有 Zipformer 做临时输入，同时保留 SenseVoice 为唯一正式最终转录。这会增加一条 ASR 计算支路，虽然不是把两次完整识别都当最终答案，仍有额外 CPU/准确率/维护成本。**鉴于用户先前希望两遍识别作备用，这个组合仅作为可行性探针，不默认启用**。

如果需要始终单引擎，须另选真正支持中文流式识别的模型，重新做准确率与实时成本对比；不能只凭框架 README 替换现在的最终识别。将离线 SenseVoice 对不断变长的录音反复重跑，也不作为本版“原生流式识别”交付。

partial 的初始用途收敛到本地召回和候选意图。只有明确允许边听边查的请求才尝试提前出站；完整回答的推测生成列为后续优化。每个输入版本最多一份在飞准备，改口则撤销，final 到来后重新检查上下文/证据/授权版本。LG 本轮 Affect、Belief 等更新会让准备时的上下文变旧，缓存不能无条件复用。

## 5. LG 接入的实际改动面

| 当前源码/边界 | 核查事实 | 建议改动与架构影响 |
|---|---|---|
| `scripts/postlv2_vtuber_runtime.py` 的 `LGBridgeAgent.chat` | 只接正式文本/final，等待完整回复，拒绝 `proactive_speak` | 加受限临时输入、控制/交付路由；主动输出通过 LG 新入口登记，不能解除外壳 prompt/历史隔离 |
| `src/infrastructure/bridge/turn-bridge-transport.ts:280` | 普通输入处理 await 当前轮，取消也排在后面 | 读取和控制消息解耦；正式 `SUBMIT_TURN` 的串行闸保留。需要新传输并发负控，不允许并行正式写库 |
| `src/main.ts` 的 `ChatSession.send` | `beginTurn` 先写用户事实和同轮状态；模型/回复检查/助手落账都在方法内 | LG 增加不调用 `beginTurn` 的临时只读准备入口；主调用的取消要逐个阶段收口，不能拿部分转录直接调用 `send` |
| `src/infrastructure/runtime/adapters.ts:283` | 主模型仅经 `runtime.useModel(..., { prompt })`，没有当前轮取消参数 | 若 provider 支持，则传递取消；否则如实记录后台仍执行，只废弃输出。既有 `failTurn` 能收 trace，但不代表整个取消/序号生命周期已解决 |
| `src/infrastructure/search/tavily-search-provider.ts:247` | 已支持外部 AbortSignal 与取消/超时分列 | 复用底层能力，补从会话/任务到 adapter/provider 的信号。查询已发出时不能承诺撤回服务端消耗 |
| `src/kernel/contracts/media-delivery.ts` | 已有三本账和合法迁移的纯函数，尚非完整线上交付通路 | 直接复用合同结构，接客户端回报/断线/乱序，LG 接收后构造语音 recent context；按既有持久化约束保存必要元数据 |
| 网页 `utils/postlv2-speech.js` | 能停源、丢旧包、本地记播放状态；等待至少 3 秒音频内容或 final，调度 lead 为 0.4 s | 增加带身份/单调序号的播放回报；测量后再调整预缓冲。3 秒是音频内容量，不是固定 3 秒墙钟等待 |
| `scripts/postlv2_cosyvoice.py` | 原生推理在线程中进行；取消后排空当前句、丢迟到块，下一句可能等锁 | 先停止可见输出、取消未启动合成、限制在飞句子；安全原生停止点须单独验证。不给出 GPU 计算已瞬停的虚假读数 |

改动集中在输入/取消/任务/交付的协调边界和 LG 的轮次应用层，**可以保留现有人格、记忆域、行动放行、回复守卫与正式历史**。然而这仍是中等规模接入，尤其准备入口和播放上下文会碰到 `main.ts` / TurnGateway，不应描述为完全不碰内核。

首版保留完整已检查回复的生成记录，另加交付记录，不能删改已提交助手历史。语音上下文只包含确认播完的句子；被打断句的毫秒位置不代表已知文本前缀。更精确的字词对齐属于后续增强。

## 6. 工作包、验证与工程量

| 顺序 | 交付 | 出口验证 | 粗估 |
|---|---|---|---|
| A | 优先控制消息、取消/过期仲裁、播放回报、LG 交付上下文、有限停止/呼唤快反 | 慢 LG 请求时仍能受理取消；旧音频与旧任务结果不能跨版本；未播句不成为“已告诉用户”；重连 unknown；正式写入继续串行 | 24–40h |
| B | 音频块与真实 partial/final；临时只读召回；明确语境内提前检索；话轮检测探针 | 用户仍在讲话时发生真实准备；更正/否定/引用撤销候选；无临时用户事件或记忆；单/双 ASR 方案分别报告准确率和成本 | 18–30h |
| C | 受控角色插话、合法证据触发中途纠正、话权冲突仲裁 | 已经开始说话后有效证据才到达；旧余句停播、新判断过检查；用户抢话优先；不能用假用户输入触发 | 18–30h |
| D | 六组重叠交互、同钟端到端延迟、量具负控、真人与专项/全仓回归 | 按现行媒体契约 M7–M12 逐项出证据，保留 FAIL/NOT RUN，不能用固定占位音代替实质回答 | 10–18h |

合计 70–118h，规划时取 70–120h。各包含自身专项验证，D 是联合验收而非再次重跑所有单元检查。未计入开放域训练、多用户、平台迁移、全局代码重构、已有独立门失败的修复，以及用户排期/下载等待。

旧总计划 WP5 的 13–15h 是在接口尚未全部探明时的粗估；当前已查明控制消息被阻塞、主回复与状态落账耦合、播放事实不进入 LG 三个实际接入点，**不再把旧估算当本轮剩余工作的可靠上限**。旧计划和读数不回写。

继承现行[媒体契约](../post-lv2/Post-Lv2-Media-Delivery-Contract.md)：60 次首反馈样本、实质语音 p50/p95/max、六类交互各至少 5 次、引用/否定/回声/断线/重复包负控和真实麦克风演示。250ms 本地停播、500ms 快信号/服务失效、普通短轮 p95≤5s 是目标，模型或网络使其失败时按 FAIL 报告；新架构本身不产生 PASS。

CPU/GPU 探针与真实回放开始前，继续遵守用户关于游戏占用的安排，届时先联系用户。本轮没有运行这些测试。

## 7. 不采用与停止扩张条件

1. **开放域自由插话/争辩不进入首版。** 时机恰当需要中文语义、话权、语气与误触发评价；现成调度器不能证明这项品质。范围限于 §2 的明确场景。
2. **不迁移整套平台来修一个取消点。** 当前外壳已有实际回放和皮套成果；LiveKit / Pipecat 整体迁移会重新引入媒体、模型、UI、启动与验收成本。只有现有路径出现无法局部解决的硬阻塞，才重新比较替换路线。
3. **不强杀 GPU 线程或 LG 数据库进程。** 强杀不能作为取消实现；模型缓存安全、正常关闭和已提交事实保持有效。原生推理不能中止时分别报告“输出已停”和“计算仍排空”。
4. **不反复推测整段回答。** 先证明本地召回/短请求提前准备带来实际收益，再考虑最多一份在飞的模型推测；收益不明显或显著影响游戏则不开默认。
5. **不能保留 LG 权威/回复守卫的组件不采用。** 允许换执行组件，禁止用外壳历史、MCP 默认工具或裸模型绕开既有记忆、动作与证据链。
6. **探针不能满足中文/许可/依赖约束时停止该候选。** Smart Turn 与 KWS 都保留当前 VAD/识别回退；不以安装成功、健康端点或上游数字代替真人与端到端结果。

本轮结果仅完成了现成方案核查与可行性取舍。运行集成、模型探针、真实并发和完整 Lv4.5 验收全部待后续执行。
