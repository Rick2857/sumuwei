## 0. 一页概览

### 0.1 问题陈述（一句话）

真实库 **`active` 记忆 = 1 条**；而她**只记得住被明确告知的事**
（[`memory-invariants.md`](../architecture/memory-invariants.md) §16.11 逐字：
"`CHARACTER_MEMORY_BACKGROUND_ENABLED` 没有任何消费者 …… 因此**她目前只记得住被明确告知的事**"）。
而"明确告知"还要连过**两道窄门**（§0.2 的 ②③）。⇒ 语义召回、关系状态、情绪、
信念这些下游能力**再准也排不出差别**，因为**池子里只有 1 条**。

### 0.2 三个"体积闸门"（**逐个已核实**，每条给证据）

```text
                    用户说了一句话
                          │
   ①  后台自动路径 ──✗──  NOT-WIRED（没有任何消费者；打开它什么也不会发生）
                          │
   ②  显式意图检测 ──✗──  纯规则关键词表（LLM 分类器存在、已测试、**未接线**）
                          │
   ③  内容抽取     ──✗──  纯规则 12 条规则 / 10 个已登记槽位（LLM 抽取器存在、**已接线但开关缺省 off**）
                          │
                       落库（还照常过 Schema / Authority / 冲突 / 去重 / 放行口）
```

## 1. 为什么这件事**必须先立量具**（本计划最容易被跳过的一步）

`AGENTS.md` §6.2 逐字："**量具自己也要被验证**（INV-M45-06）。任何 Hard Gate 都要同时证明
'测量范围正确'与'测量结果正确'"。而这条线今天有一个**结构性陷阱**：

```text
"覆盖面变大了" 这个主张，最容易被一个**坏量具**伪造出来：
  · 拿"已登记槽位"的句子去测 ⇒ 命中率天然很高（M6.1 的 28 条就是这样：unresolved = 0）
  · 拿"规则能抽的句子"去测 ⇒ 同上
⇒ 一个只在"规则本来就会"的集合上跑的量具，与"什么都不检查"在输出上无法区分（AGENTS §6.7）
```

⇒ 因此 `WP0` **先建覆盖率量具**，且必须走**正控 / 负控 / 恢复**三段式（§6.7）+ 自检
`measured_count > 0`（§6.8）。**在量具被验证之前，本计划的任何"覆盖率"数字都不得当成结论。**
