## 3. 已知未完成（**逐条给理由**）

### 3.1 `relationship` —— 被登记表**自己的标准**排除

登记表头部逐字："因此这里**没有**情绪、**没有人际关系**、没有目标 —— 那些在 M4 不是 Claim"。
而且 `G1` 点名的那批里 `relationship` **已经落地**（M7 的独立模块 + 自己的 ADR），**不是**扩线索表
⇒ 再往记忆登记表里加关系槽位会造出**第二套表示**。

### 3.2 `schedule` —— 过不了收纳标准第 ② 条，且会与 M10 撞车

收纳标准要求"取值形状**稳定**"，而「我周三要答辩」这类**一次性事件**不是稳定取值；
且 M10 已有完整的 **goal / commitment 域**（受理证据 / 生命周期 / 失效处理）。
⇒ 正确做法是**先裁定**"用户的日程属于记忆还是属于 M10 的目标/承诺域"（一道**域边界裁定**）。

### 3.3 ⚠️ 一条**已知的假阳路径**：问句会被记成事实

```text
本抽取器**没有问句守卫**（全仓 grep 无 `isQuestion` 一类实现）
⇒「记住，我的生日是什么时候」会被记成 `person.birthday = 什么时候`
⇒ 语料里有一条**专门的探针**（`mc-probe-0001`）把它**量出来**，而不是假装没有。

⚠️ 今天它够不到生产：唯一接线的显式路径要求用户先说「记住」；
   后台路径（`CHARACTER_MEMORY_BACKGROUND_ENABLED`）是 **NOT-WIRED**（`main.ts:3769` 只打告警）
⇒ 它是**未来风险**（TD-19 一旦接上后台路径，它就变成现实风险）。
⚠️ 修它需要**问句守卫** —— 那是**行为变更**（会影响所有规则），不在"只扩线索表"的授权内。
⚠️ 而且这是**既有的一般性质**，不是本次引入的：既有槽位同样如此
   （「我的专业是什么？」→ `education.major = 什么`）。
```

### 3.5 ⚠️ 两条**工程教训**（写给下一个增量）

```text
① **往一条已有规则上挂线索词，只有在该规则的取值不是"短语专属"时才安全。**
   增量 1 第一版把「海鲜过敏」挂进 `food.avoid.general`（那条的 `positive` 是 '喜欢辣'）
   ⇒ 实测取值变成 `food.avoid.general = 喜欢辣` —— 只看闸门会以为改动成功，**读取值**才发现。
   ⇒ 每加一条都要**同时看闸门与取值**。

② **不要用 `Select-Object -First N` 去截 `pnpm <门>` 的输出**：它会在收满 N 行后
   **终止上游进程**，而本门是**清单最后写**（`writeManifestAtomic`）⇒ 进程在写完
   `coverage.json`、还没写清单时被杀，留下一个**没有 `manifest.json` 的目录**。
   （这恰好说明「清单最后写」这条纪律有用：没有清单的目录 = 不完整的 run，
   按仓库惯例读作 **NOT RUN**，不是 PASS。）要看尾部就 `Select-Object -Last N` 或写进文件。

③ ⚠️ **加线索词不是"只影响新说法"**：加一个**更长、且会出现在取值内部**的 cue，
   会**改变既有条目的取值**。实测（增量 3 的预备测量）：给 `device.primary` 临时加 cue
   `'Windows'` ⇒ 目标句「我平时用 Windows」可抽但取值是 **「平时用Windows」**，
   **同时**「我平时用的是 Windows 笔记本。」的取值从 **「Windows 笔记本」→「笔记本」**
   （机制：`best` 取**最长线索词** ⇒ 取值那一支从"往后"翻到"往前"）。
   ⇒ **增量 3 每加一条都要先跑一次前后对照**，看的**不只是**新条目，还有**既有条目的取值**。
   （登记为 `L-M97-14`；那次注入的档在库、逐字可核。）
```
