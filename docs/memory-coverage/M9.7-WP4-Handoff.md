### 2.3 ★ **本门最重要的一句**：这 29 条与可达性读数**逐条重合**

> ⚠️ **本节是 WP4 当时的读数**（语料 rev 4）。**取值边界线第 1 轮（`ADR-080`）之后**：
> 可达 `extracted` 与 `written` **都变成 27**（`mc-registry-0006` / `mc-probe-0001` 如实改成不可达）。
> ⇒ ⚠️ **那条恒等式 `written == extracted` 仍然成立** —— 本节要主张的那件事（下游写路径没丢东西）
> **不因取值边界轮改变**。本节数字**不回写**（它记录的是那一轮的读数）。

```text
可达性（WP0/WP1）：extracted = 29
写读（WP4）      ：written   = 29   ← 同样那 29 条
⇒ 在**本语料**上，"抽得出" ⇒ "真的落库"：**下游写路径一条都没丢**。
⇒ 结论：体量的瓶颈**完全在闸门②（意图）与闸门③（抽取）**，
  不在目标解析 / 冲突 / 去重 / 放行口 / 折叠。
```

⚠️ **这条结论的边界**（不许外推）：
- 它说的是**本语料**（46 条抽样），不是真实对话分布；
- 它**不**说明写路径"没有风险" —— 它说明**在这批输入上**没有丢；
- 同一句话喂两次的第二条走的是 `already_applied`（幂等命中）⇒ 同槽位重复**不会**变成两条 active。

### 2.4 三段式自证 + 计数自检

| 段 | 做法 | 读数 |
|---|---|---|
| **正控** | 逐条比对声明的期望与实测写读 | 一致 **46 / 46** |
| **负控①** | 数"**尝试**"（40）vs 数"**写入**"（29）⇒ 两个数**必须不同** | ✅ 40 ≠ 29 —— 若相等，本门就分不清"她试过"与"她真的记住了"（那正是它存在的理由） |

| **恢复** | 换**全新沙箱**重喂同一条 ⇒ 与正控那一条**逐字段相同** | ✅ `kind=written activeDelta=1 domainEventsDelta=1` |
| **计数自检** | `measuredCount > 0` | **PASS**（46 项） |
