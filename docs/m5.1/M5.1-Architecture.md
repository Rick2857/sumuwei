## 0. 一句话

M5.1 **不新增能力，只新增"看得见"**：给已经存在的 Kernel 加一个**只读 + 受控**
的开发者平面（Query / Control / Page）与一条**能自证**的可观测路径，
并且**每一个结论都必须能从已落盘的证据里读出来**。

```text
M5.1 交付的是"观察装置"，不是"新的认知能力"。
所以它的验收标准不是"功能多"，而是"观察结果与权威状态一致，且不一致时一定会响"。
```

## 1. 平面与权威（谁是事实源）

```text
                 ┌─────────────────────────── 权威（唯一事实源）───────────────────────────┐
                 │  Character Kernel 事件账本（conversation_events / character_action_events）│
                 │  投影：memory / trace（**派生的**，删掉能重放出来）                        │
                 └───────────────────────────────┬─────────────────────────────────────────┘
                                                 │ 只读
                          ┌──────────────────────┴──────────────────────┐
                          │                                             │
              ┌───────────▼───────────┐                     ┌───────────▼───────────┐
              │  Query Plane（只读）   │◄──── 唯一消费方 ────│  Control Plane（受控） │
              │  8 个端点 · GET-only   │                     │  白名单 2 条命令        │
              │  Mutation Count = 0    │                     │  写 → **只经由 Gateway**│
              └───────────┬───────────┘                     └───────────┬───────────┘
                          │                                             │
                          └──────────────┬──────────────────────────────┘
                                         │ 都只走 loopback + 开发者平面 flag
                              ┌──────────▼──────────┐
                              │  Page（静态 HTML）   │  零 import / 零外部资源 / 无框架
                              │  只消费 /dev/query/* │
                              └─────────────────────┘

        旁路（不参与判定，只做观察与导出）：
        ┌──────────────────────────────────────────────────────────────────────┐
        │  Canonical Span 分类法 → 遥测适配器（Phoenix / 通用 OTLP）           │
        │  白名单**拒绝式**；泄漏扫描扫**导出的负载**（含 protobuf 线上字节）   │
        └──────────────────────────────────────────────────────────────────────┘
```

**关键点**：上面每个箭头都是**单向**的，而且方向被静态测试守着
（`pnpm m5.1:test` 的"零基础设施依赖静态锁"+ `pnpm m5.1:query:verify` 的
"handler 层无 SQL、service 无写语句"）。反向依赖 = G-02/G-03 被破坏。

## 2. 四个平面各自的"不许做的事"

| 平面 | 允许 | **禁止**（可检查形式） |
|---|---|---|
| **Query** | 读既有投影、8 个 GET 端点 | 任何 mutation。判据不是"代码里没有 insert"，而是**调用全部端点前后整库逐字段快照相同**（AT2.7，`Query Mutation Count = 0`） |
| **Control** | 经 Execution Gateway 执行白名单命令（`RUN_DIAGNOSTIC` / `RUN_AUDIT`） | 绕过 Gateway；7 条禁止命令（含 `RESET_KERNEL`）**逐条被拒**；`dryRun` 不许进执行路径 |
| **Page** | 消费 `/dev/query/*` | 任何外部资源、任何框架、任何 import、任何 persistence 直连；**硬编码命令名**（命令按钮必须来自 `GET /dev/query/control/commands`） |
| **Telemetry** | 导出规范 span | 敏感键出去。白名单是**拒绝式**的；扫描对象是**导出的负载**而不是内存对象 |

> **为什么要四条闸**：开发者平面的威胁模型不是"外人攻击"，而是
> **"不小心把它当成写入口/事实源"**。所以四道闸分别是
> ①显式 flag ②loopback 绑定 ③每请求 peer 检查 ④每路由 GET-only。

## 3. 执行真相（AT3.6 五档阶梯）

这是 M5.1 最容易被做错的一块。**"执行过了"和"成功"是两件事**，
所以契约里**没有 `success: boolean`**，取而代之是一个五档阶梯：

```text
rejected    被拒（白名单/禁止命令）              → HTTP 400
accepted    被接受但只做了 dryRun                → HTTP 200
attempted   真的开始执行了（ACTION_STARTED）      → HTTP 200
executed    执行完毕（但核验还没做）              → HTTP 200
verified    执行完毕**且**权威证据核验通过        → HTTP 200
```

**三条由此推出的性质**（每条都有负控）：

1. **HTTP 200 ≠ executed**。`accepted`、`attempted`（失败）、`verified` 都是 200，
   只有 `rejected` 是 400。所以"状态码对上了"什么都证明不了。
2. **`verification` 是四态枚举**（`verified` / `failed` / `not_attempted` / `not_applicable`），
   **不是布尔**。`not_attempted` 是一个**诚实的答案**，不是缺陷（见 Known-Limitations L-13）。
3. **`verified` 不许由 `executed` 推导**。必须去权威证据（账本）里核验；
   WP3 的硬判据是"9 张领域表前后逐字段相同 + 5 项交叉核对零不一致"。

> **WP3 的量具自检**：伪造一个"重放却声称本次真的执行过"的结果 → **必须被报出**。
> 这就是 INV-M45-06（量具自己也要被验证）在 M5.1 的落地。

## 4. 可观测性真相（Trace Truth）

与执行真相同构：**"我们发了 span"和"span 说的和现实一致"是两件事**。

```text
真实一轮
  → ContextCompiler（可能因为 tokenBudget 整段丢掉记忆）
  → 得出现实：本次真的用了哪些 memory id
  → span 的 selected_memory_ids **只能**取编译之后的现实
```

WP4 的判据（AT4.4）：**被预算丢掉的那条记忆不得出现在 span 里**，
且必须带理由码 `BUDGET_EXHAUSTED`。
量具自检：把被丢掉的 id 注入 span → 必须被 `spanTraceInconsistencies` 报出。

**泄漏判据**（AT4.5）：四个哨兵 × 6 份**导出的负载**（含 **protobuf 线上字节**），
`Leakage = 0`。量具自检：塞进哨兵必须被找到。
—— 扫"导出的字节"而不是"内存里的对象"，是因为**只有前者是用户真的会看到的**。

## 5. 分类法（Canonical Span）

单一映射函数，避免"一个概念两处实现"：

```text
trace step kind ──stageOfTraceStepKind──► OBSERVABILITY_STAGE（12 个，全是受控词汇）
control 执行    ──mapControlExecutionToCanonicalSpan──► 自成一棵单 span trace
canonical span  ──canonicalSpanToTelemetrySpan──► 遥测 span（**白名单在此强制**）
```

`OBSERVABILITY_STAGE_FACTS` 里每个阶段都登记了**生产者**与**理由码**
（无死枚举值），理由码一律复用既有受控词汇（如 `developer_control` 阶段
直接复用 `CONTROL_REASON_CODES`）—— 不许为遥测再造一套词汇。

## 6. 页面（AT5.6 的"删掉它"判据）

`src/infrastructure/dev/page.html` 是**自足的 377 行**：零 import、零外部资源、
无框架、只有一个 POST。它证明独立性用的不是"代码里没写"，而是**真的删一次**：

```text
删除 page.html → GET / 返回 404，其余 9 个端点**逐字节不变**
还原 page.html → 逐字节相同
```

—— 这是"派生性"思想在 UI 上的复用：**一个部件可被删除而不影响系统，才叫独立**。

## 7. 三条跨里程碑硬性质如何在 M5.1 落地

| 硬性质 | M5.1 的落地方式 |
|---|---|
| ① **Assistant Fact Firewall**（她生成的内容不得自动变成外部事实） | 开发者平面只读**既有**投影；控制命令**不许**写 trace（L-02）；动作参数只出 key 不出 value（L-15） |
| ② **投影是派生的**（删掉能重放，逐字段一致） | Query 面 Mutation Count = 0；页面的"删掉它"判据；`memoryDigest` / `stableMaterial` 复用既有稳定序列化 |
| ③ **副作用 ⇒ 目标确定性 + 账本 + traceId；没成功就没成功口吻** | AT3.6 五档 + `verification` 四态 + "HTTP 200 ≠ executed" + `verified` 不许由 `executed` 推导 |

**M5.1 没有改动这三条性质中的任何一条** —— 它只是让它们**可被观察**。
冻结区在每个 WP 的 diff 里都是空的（见 `M5.1-Implementation-Report.md` §3）。

## 8. 证据等级链（为什么 Unit Test 不能作为验收）

```text
Level 1  真实外部结果（真实模型回复、导出的负载）      ← E1 / E6-Live / 泄漏扫描
Level 2  账本 / 事件（character_traces / action_events）← E2 / E4 / E5 / AT3.6 核验
Level 3  ActionResult
Level 4  集成测试
Level 5  单元测试                                      ← 只配当"部件门"
```

**最终验收至少要有 Level 1 + Level 2** —— M5.1 的 E1/E2/E5/E6 提供了两者。
单元测试（`pnpm m5.1:test` 的 52 项）是**部件门**，它全绿**不等于**链路正确
（M4 的 D1 缺陷穿过了 939 项断言，是 Live Smoke 才发现的）。
