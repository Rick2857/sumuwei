## 5. 过程中**门抓到的真实缺陷**（这是本报告的实质部分）

M5.1 的价值有一半在这些行里 —— 它们证明门真的会响，而不是"我自己写自己过"。

| # | 缺陷 | 谁抓到 | 怎么修的 |
|---|---|---|---|
| D-1 | 查询服务**手搓** `finishedAt - requestedAt` → `durationMs: -10351909773` | `m5.1:query:verify` | 统一走 `developerDurationMs` + 加非负断言 |
| D-2 | `?orderBy=x` **返回 200**（handler 只读已知参数，未知参数静默通过） | `m5.1:query:verify` | 加 `allowedQueryParams` 白名单，fail-closed |
| D-3 | 既有 `phoenix.ts` **发点号键**（`error.message`），且**从来没过白名单** | `m5.1:observability:verify` | 有限别名表 + 钉住 `TELEMETRY_LEGACY_KEYS_OUTSIDE_POLICY` + **白名单只强制在规范路径上** |
| D-4 | `getTrace` 返回 `DeveloperLookup` 信封，HTTP 层按裸对象处理 → `Cannot read properties of undefined` | `m5.1:query:verify` | 加 `unwrapLookup`（`character_mismatch` → 404）+ `kind: 'lookup'` 路由 |
| D-5 | 汇总器**首跑报告九道门全部 not-run** | 自检 | 路径拼接少了 `artifacts/` 前缀。**它没有假 PASS** —— 这正是想要的失败关闭行为 |
| D-6 | 量具脚本里两个**死检测器**（`!x === false` 恒真、`conversationMutation.length > 0` 恒真） | 自查 | 换成真实的前后对比 |
| D-7 | 页面验证脚本三次假阳性（HTML 注释里的 `<script src>`、`/*` 被当成注释开头吞掉 85 行、`<select id=…>` 撞上 SQL 正则） | `m5.1:page:verify` | 拆分扫描面（整页查资产 / `<script>` 体查行为）+ 端点前缀匹配 + `node --check` |

> **D-5 值得单独说**：一个"永远报 PASS"的汇总器是最危险的量具。
> M5.1 的汇总器从设计上就只读**已落盘**的证据，文件不存在 = `not-run`，
> 缺一道硬门 = 总判定降级为 `FAIL`。它首跑的"全 not-run"就是这条性质的**活证据**。
