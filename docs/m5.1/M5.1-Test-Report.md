```text

缺一道硬门     →  总判定降级为 FAIL              ✓ 已断言
spike          →  不参与总判定，且每条必须有 claimLimit  ✓ 已断言
```

## 5. E2 的三处投影对齐（本里程碑的核心判据）

```text
同一轮真实对话的三个投影：
  ① 真实 prompt packet 的 sourceRefs
  ② trace 的 selectedMemoryIds
  ③ Query API 返回的 DTO
  →  三者必须指向同一个 memory id：mem:…:person_fact-071d9d0ea33d4075
```

**负控（E3）**：主语换成陌生人 → `selected = []`。
区别很重要：这不是"召回被关掉了"（关掉也能得到空），
而是**真的没有证据**与**有证据时三处必须一致**同时成立。

## 6.1 一处**已更正**的措辞：E6 的 `migrationVersion` 量的不是真实库

初版报告引述过"副本只读跑真实历史（`migration=v6`）"，那句话**会误导**。
源码核实后的机制：

```text
· 迁移闸只拦"有待应用迁移**且**未被放行"的库
· 沙箱路径（isolateDatabase 置 PROJECT_LG_SANDBOX）与显式放行都不被拦
· 所以 E6 的副本在启动时被 harness 施加了待应用迁移 → 报 6
  —— 这个 6 反映的是**副本**，不是真实库
```

**直接证据**：WP8/WP9 期间真实库一直是 **v5**；2026-09-17 首次 apply 时日志明写
`schema 迁移 5 → 6`。所以 E6 的那个版本号当时**不可能**来自真实库。

**不影响** E6 的实质结论：副本里确实是真实历史（`memory.total=2`、`traces=5`），
真实库确实一字节未动，Live Smoke 确实是真模型跑在副本上。
受影响的只是**对那个版本号的解释**。

这类"判据对了、我把它读错了"的失误正是 INV-M45-06 针对的对象 ——
记在这里，而不是悄悄改掉。
