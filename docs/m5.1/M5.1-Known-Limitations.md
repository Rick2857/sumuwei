# M5.1 Known Limitations

> 这份文件是**如实清单**，不是待办列表。绝大多数局限来自某个 WP 的
> 交接单（`WP2`–`WP8`），并且**大部分被 G-05 明确禁止在本轮修**。
> 谁要修它们，先看每条的"要改就得…"。
>
> **例外**：`L-16` 是**用户提问追查出来的架构级缺陷**，
> 已按用户裁定**正式立案** → [`M5.1-D01`](./M5.1-D01-Ledger-Actor-Attribution-Gap.md)。
> 它不是"某个功能还没做"，而是**账本语义不完整**，见 §2 的说明。
>
> 读法：**§1 是本轮自己造成的**（M5.1 的边界选择，11 条）；
> **§2 是继承来的**（M5 / M4.5 的既有事实 + `M5.1-D01`，5 条）；
> **§3 是证据强度**的局限（结论没错，但证据只到某个等级，6 条）。
> 合计 22 条。

## 1. M5.1 自己造成的局限（本轮的设计边界）

| # | 局限 | 为什么这样 | 要改就得… |
|---|---|---|---|
| L-01 | **控制面没有持久账本** —— 幂等只在进程内（`ControlIdempotencyStore`） | 计划书只要求"重放不再执行"，没要求跨进程；持久化要先有"控制命令算不算领域事件"的裁定，那是 Domain Model 变更（STOP 条件 2） | 先出 ADR 裁定控制命令的领域地位 → 才谈持久账本 |
| L-02 | **AT3.4 不适用** | 计划书 AT3.4 假定控制命令会写 trace，但 `CharacterRunTrace.inputEventId` 在 DDL 里是 **NOT NULL** 且语义指向**真实会话事件**（`migrations.ts:205`）→ 控制命令**不许**写 trace，`ControlResult.traceId` 恒缺省 | 改 DDL 或改 trace 语义 = 动 Event Ledger（STOP 条件 4） |
| L-03 | **审计结果的分页表达不出** | 既有 `character_action_events` 读取器没有 keyset cursor；为了不新增索引（F-11 不许加迁移），审计沿用既有扫描 | 加索引/迁移 → 新里程碑 |
| L-04 | **wire 键未统一**：既有 `phoenix.ts` 发**点号键**（`error.message` 等），而 M5.1 的白名单是**下划线键** | WP4 的边界是"只在新路径上强制白名单"，把既有导出路径的重命名当成独立变更，避免一次 WP 里同时改语义和改线上格式 | 出 ADR + 一次独立的 wire 格式迁移 |
| L-05 | **子阶段嵌套表达不出**：span 的父子关系只到两层 | 分类法映射（`mapTraceToCanonicalSpans`）保守处理，宁可不表达也不臆造层级 | 扩展 `OBSERVABILITY_STAGE_FACTS` + 回归锁 |
| L-06 | **`error.message` 无界**：这个键的**值**长度没有上限 | 白名单管的是**键**，值级截断是另一件事（WP1 明确"key 级白名单不重复实现值级哨兵"） | 在导出侧加值级长度策略（不是白名单的事） |
| L-07 | **开发者页面（`page.html`）的 DOM 渲染没有自动化覆盖** | AT5.7 只要求"零外部资源 + 无框架 + 只消费 Query API"；DOM 行为要靠浏览器，而本仓库没有浏览器测试设施，硬造一套就是引入新依赖 | AT5.7 那类要求 + `pnpm m5.1:page:verify` 的静态面 + 一次人工核对 |
| L-08 | **静态资产与 DTO 之间没有编译期约束** | 页面刻意零 import（AT5.7），所以它拿不到 TypeScript 的类型 | 要么放弃零 import，要么让页面走一个真实的最小校验（本轮选了前者） |
| L-09 | **页面每请求读一次文件** | 极简静态 HTML，没有缓存层；开发者平面是本机单用户的 | 加缓存时要先证明"删掉页面一切照常"仍然成立 |
| L-10 | **开发者平面是 loopback-only、GET-only**（每个路由） | G-02/G-03 的可检查形式；这是**故意的**，不是缺陷 | 想放开 = 改权威地图（`M5.1-Authority-Map.md`） |
| L-11 | **E1 / E6-Live 依赖真实 `OPENAI_API_KEY`，且每次重跑都花真实调用**（2 次/轮） | Live Smoke 是唯一能回答"用户看到的是不是真的"的门（AGENTS §6.1），不能为了省钱换成干跑 | 无 Key 环境下脚本会**如实降级为 not-run**，不会假绿 |

## 2. 继承来的局限（**G-05 禁止在 M5.1 修**）

| # | 局限 | 出处 | 为什么不能顺手修 |
|---|---|---|---|
| L-12 | **M5 的 8 条已知局限仍然全部有效**（无意图分类器 / 词面桥是二值 bigram / 无第三人 subject / D-9 / 旧探针口径 / 语义通道不可用 / 扫描 500 行上限 / 合成轮次不召回） | `docs/m5/M5-Acceptance-Report.md` §8；`docs/m5/WP8-Handoff.md`；本仓库登记为 **D-12** | G-05 + STOP 条件 5/6/7（D-9 / Vector DB / Intent Classifier）。其中第 1 条**直接约束 M5.1 的 Execution DTO** |
| L-13 | **Execution DTO 的 `intent` 只能如实填 `not_available`**，`verification` 只能是 `not_attempted` | 上面那条的直接后果（F-10） | **不许伪造**。契约（`DeveloperExecutionSummaryDto`）从设计上就允许 `{ status: 'not_available', reason }` —— 这是**正确**的表达，不是缺陷 |
| L-14 | **执行账本没有 cursor** | WP2 实测 | 与 L-03 同因（不许新增索引/迁移） |
| L-15 | **动作参数只暴露 key、不暴露 value** | WP2/WP3 的隐私负控 | 这是**故意的**；放开就等于把她的动作参数写进开发者响应 |
| **L-16** | ⚠️ **账本只记 role、不记 authorship** —— 见**正式立案文书** [`M5.1-D01-Ledger-Actor-Attribution-Gap.md`](./M5.1-D01-Ledger-Actor-Attribution-Gap.md)（`M5.1-D01` · Severity Architectural Correctness · **P1 · OPEN**） | 2026-09-17 用户提问"她为什么记得我没说过的校名"追查出来的：`conversation_events.actor_type` 是**归属声明**不是**作者证明**（agent 用受支持的一次性入口替用户发的话，落进账本与用户亲手打的字**无法区分**）；`character_action_events` 只有 `character_id`，**没有** initiator/authority/executor | **不在本轮修**（触碰 Event Ledger / Identity / Execution Truth = STOP 条件 1–4）。也不许"顺手加个 `authorId`"了事 —— 必须先拆开 subject / initiator / actor / executor / authority / recordedBy / author 七个概念，**G5.1 Decision Freeze 前裁定**方案，并在进入多主体 / 外部行动**之前**关闭 |

> **L-16 与其它条的区别**：它不是"某个功能还没做"，而是**账本语义不完整**。
> 与 **D-9** 同类（都属账本语义缺口），但方向不同：
> D-9 偏**事件完整性**（重放会不一致），L-16 偏**归因完整性**（审计语义含混）。
> 只要系统开始"真的做事"，后者的技术债会迅速放大。

## 3. 证据强度的局限（结论没错，但只到某个等级）

| # | 结论 | 证据只到哪一级 |
|---|---|---|
| L-17 | **OTLP 协议兼容性 verified** | 只到"标准 OTLP 发出去了、通用接收端逐字段收下了"。**具体后端（Langfuse / OpenLIT）一次都没在本机部署过** → `claimLimit: specific backend deployment not exercised`。**禁止**被引述为任何后端 integration PASS |
| L-18 | **所有第三方"能不能接"的结论**都是**文档级 + 协议级**，没有一个是"跑起来试过" | 唯一的实跑证据是 OTLP spike。ADR-037~041 的 "Future Milestone" 小节就是每个候选的**准入判据** |
| L-19 | **Graphiti 的 REJECT 依据是类别推断** | 本轮未取得一手页面（检索只命中同话题聚合页）→ 要改判先补一手文档 + 一次 spike |
| L-20 | **沙箱（ADR-041）的判决对象是"这一类执行后端"**，不是某个具体产品 | 计划书只写了 "Sandbox"，没点名项目 → 属于类别级审计 |
| L-21 | **Langfuse 的 LLM 语义映射表不存在** | trace 进得去，但 generation/span 详情视图不会自动完整 → ADR-037 把"面板里真的看到了那条 trace"写成准入判据 |
| L-22 | **E2 的三处投影对齐是"一次真实轮次"的证据** | Level 1 + Level 2，但样本是 1 轮（E1 + E6-Live 各一次），不是统计意义上的分布 |

## 4. 明确**不是**局限的东西（免得被误读成缺陷）

- **开发者平面删掉页面后其余端点不变** —— 这是 AT5.6 要求的**性质**，WP5 用"真的删一次"证明了它。
- **只读查询面 `Mutation Count = 0`** —— 这是 AT2.7 的**硬判据**，不是"功能少"。
- **`rejected` 返回 HTTP 400 而 `executed` 返回 200** —— 这是刻意让"HTTP 200 ≠ executed"成立的表达。
- **遥测里没有敏感键** —— 白名单是**拒绝式**的，`error.message` 在既有路径上能出去是 L-04/L-06，不是说白名单错了。
