--------------------------------------------------------
一、怎么跟她对话（最常用）
--------------------------------------------------------

三种正式启动方式：只开皮套、只开 QQ、QQ 与皮套同时开。
    共存接线已经启用；长期记忆与人格共用，QQ 和皮套的近期对话分开。
    正式聊天会保存到她现有的记忆库。

【先读这两条】
    · 启动新的方式前，先正常退出正在运行的正式入口，等它完成关库。
      两个都开时统一使用共存启动器；不要同时启动下面的两个单独入口。
    · 如果两个入口已经在线，直接打开皮套网页或给机器人 QQ 发消息即可，
      无需再启动一遍。如何退出当前后台共存，见第十二节（一）。

每次新开 PowerShell，先进入项目目录：

   cd "C:\Users\user\Desktop\project LG"

（一）只开皮套聊天

   pnpm postlv2:avatar:production

   也可双击：C:\Users\user\Desktop\project LG\scripts\postlv2-avatar-production.cmd
   等出现 LG_AVATAR_READY，再打开：http://127.0.0.1:12394/
   浏览器允许麦克风权限后，可以语音聊天，也可以打字。
   页面显示「正式聊天 · 使用正式记忆」，使用 Ono_Anna 参考音复刻。
   保留启动窗口；退出时按一次 Ctrl+C，等 LG_BRIDGE_CLOSED exit=0 后再关窗口。

（二）只开 QQ 聊天

   pnpm qq:start

   也可双击：C:\Users\user\Desktop\project LG\scripts\qq\start.cmd
   它会准备 Docker / 独立 NapCat，并打开登录页面。
   登录机器人 QQ：10000000002；用你的 QQ 10000000001 给她发好友文字私聊。
   等终端显示 LG 已就绪，并确认机器人已经登录后，再聊天。
   保留启动窗口；退出时按一次 Ctrl+C，等待消息排空和正常关库。
   桌面的「一键启动qq bot.bat」启动 Yuki/AstrBot；苏沐薇请用上面的入口。

（三）QQ 和皮套两个都开

   1. 打开 Docker Desktop，等引擎就绪。在项目目录运行：

      docker compose --env-file .env.qq -f scripts/qq/compose.yml up -d
      pnpm qq:status

      qq:status 显示 PASS 后继续。如果机器人未登录，打开
      http://127.0.0.1:6101/webui，使用 .env.qq 中的 QQ_NAPCAT_WEBUI_TOKEN
      进入管理页，登录机器人 QQ 10000000002，然后再检查一次。

   2. 在同一个 PowerShell 窗口运行：

      $env:PROJECT_LG_COEXIST_ACTIVATE='coexist@C:\Users\user\Desktop\project LG\data\pglite'
      pnpm coexist:start

      这是前台运行，保留此窗口。两条入口需要的令牌和 .env 开关已经配置好。

   3. 等出现 COEXIST_READY 和 LG_AVATAR_READY 后：

      皮套：打开 http://127.0.0.1:12394/
      QQ：用你的 QQ 10000000001 给机器人 10000000002 发好友文字私聊。

      QQ 回复回到 QQ；皮套回复显示在网页并按皮套流程播放。
      两边近期话题分开，长期记忆、关系和认知状态共用；共用模型时可能排队。
      全部退出时，在共存启动窗口按一次 Ctrl+C，等待排空与退出完成。

正式入口的记忆功能：
   已开启语义记忆意图判断与 LLM 抽取兜底，也已开启语义召回。
   可以说「记住……」或「请记住……」表达记忆请求；最终仍受事实槽位、
   证据资格和写入校验约束。普通聊天并不是每一句都会成为长期事实。

切换方式、后台退出和检查命令，详见第十二节。

带皮套、声音的测试聊天（不写正式记忆）：

   双击：C:\Users\user\Desktop\project LG\scripts\postlv2-avatar.cmd
   或在项目目录运行：pnpm postlv2:avatar

   出现 LG_AVATAR_READY 后打开：http://127.0.0.1:12393/
   页面显示「测试聊天 · 使用记忆副本」。同样使用 CosyVoice3 的 Ono_Anna 参考音复刻，支持表情/动作和服装与特效。
   启动前先正常停掉正在运行的正式入口，等关库完成后再复制。
   每次启动会重新复制正式库；本次聊天只写隔离副本，不会合并回正式记忆库。
   适合测试声线、表情、动作和换装；确认正式聊天时请使用上面的 12394 入口。
   退出：在启动窗口按一次 Ctrl+C，等 LG_BRIDGE_CLOSED exit=0 后再关闭窗口。

皮套操作：右上角展开「服装与特效」，可选择原始服装或服装 1/2/3，勾选特效。
   本页选择在聊天和打断后保留；刷新页面后恢复默认。

当前皮套语音：SenseVoiceSmall INT8 在 CPU 上单遍识别，CosyVoice3 在 GPU 上分块合成。
   复刻声线是你在试听中选择的版本，与原 Qwen 的 Ono_Anna 预设有差别。
   俏皮句尾已增加逐字朗读约束；修复后 24 段识别回读一致，仍需你亲自试听。
   启动会加载声线并预热，可能等待数十秒，请等 LG_AVATAR_READY 后再聊天。
   开始播放前会积累一段音频；短句仍可能等合成完成。整轮等待还包含 LG 回复生成。
   语音识别使用网页完整录音，不是边说边显示文字；单独的 pnpm postlv2:mic 仍用原 Zipformer。
   点击黄色「举手」可打断音频和动作。打断后模型会丢弃迟到音频，当前生成可能仍需收尾。
   真人检查建议先在测试入口说不同短句、名字和数字，核对字幕、断句、口型及语气。
   浏览器使用麦克风前需要允许麦克风权限，并选择正确的输入设备。

如需临时回到原语音档，在 PowerShell 运行：
   $env:POSTLV2_SPEECH_PROFILE = 'legacy'
   pnpm postlv2:avatar
   （正式入口也支持这个变量。）
   退出后运行 Remove-Item Env:POSTLV2_SPEECH_PROFILE，下一次恢复新语音档。

纯文字正式聊天：
   先正常退出正式皮套、QQ 或共存核心，等它完成关库，再启动 pnpm chat。

1. 打开 PowerShell
   （开始菜单搜索 "PowerShell" 或 "终端"，点开）

2. 复制下面两行，粘贴进去，回车：

   cd "C:\Users\user\Desktop\project LG"
   pnpm chat

   （`pnpm chat` 与 `node_modules\.bin\tsx src/main.ts` 是同一件事，
     后者在下面第二节里都能用，写长了而已。）

3. 出现这个提示符后，直接打字，回车发送：

   Alex:

   输入 /exit 退出（或按 Ctrl+C）

   注意：打字时直接输入就行，不用加引号。
        每次回车 = 一句话。


--------------------------------------------------------
二、所有可用指令
--------------------------------------------------------

先进入项目目录（每次新开窗口都要做一次）：

   cd "C:\Users\user\Desktop\project LG"

然后按需要用下面任意一条（`pnpm chat` 开头的那几条是简写）：

   pnpm chat
   node_modules\.bin\tsx src/main.ts
       → 跟她对话（多轮，边聊边看）
       → 输入 /exit 退出

   node_modules\.bin\tsx src/main.ts "第一句" "第二句"
       → 一次丢几句，跑完自动退出
       → 适合只想试一句的时候

   node_modules\.bin\tsx src/main.ts --inspect
       → 看她现在的真实状态
         （情绪 valence/arousal、关系 trust/closeness、状态版本、
           距离上次互动多久、最近的变更记录与理由）

   node_modules\.bin\tsx src/main.ts --history
       → 看她**最近的对话原文**（现在直接读她的**事实账本**，
         和 memory:list / --kernel-status 是同一个权威来源；
         你的话和她的回复都会显示，多用户时如实标注是谁说的）
       → 两个边界：
         1. 它是给你看的**调试视图**，不参与她的任何记忆/认知判断；
         2. `--test`（干跑）说的话**不会**出现在这里——
            "这次测试对她而言等于没发生过"是设计，不是丢历史

   pnpm memory:list
       → 看她**长期记住了哪些事实**（每条带出处与状态）
       → 这才是"她真正记住的东西"的权威清单，不是她嘴上说的那些

   pnpm memory:audit
       → 体检：她的记忆有没有自相矛盾、有没有缺证据

   日常聊天中的故事（2026-10-07 已启用）
       → 照常启动、照常聊天，不必另开故事入口。
       → 当前故事是《一起去参加极创工作室的二面》，属于有限模拟。
         例如聊到“我们聊聊极创二面的准备吧”，会自动开局并呈现当前场景；
         接着说“我们先把二面的范围问清楚”，会尝试识别本轮选择并推进。
       → 没聊到故事就不推进；讨论、询问和回顾可以不作选择。
         重启后从账本续接；已结束的故事不会自动再开一局。
       → 模拟日期、约定和结果不等于现实安排或现实录取。
         模型可能误解选择；拒收或超时不会凭空续写剧情。
       → 查看当下成果：聊到故事时，她能看到当前节点、已提交经历和待选动作；
         也可以问“这次极创二面模拟进行到哪了？”或“模拟结果是什么？”

   pnpm story:start <runId> --yes（可选手动入口）
       → 显式**开始**一次故事 run（写操作）；日常聊天已不要求先运行它。
       → 三个边界：
         1. 它**只**写开局那一条（STORY_STARTED），不替你做任何选择、
            也**不**自动推进剧情；同一个 runId 重复执行是幂等的
         2. 同一个故事同时**只允许一个**活跃 run；已有活跃 run 时会拒绝
            （要开新的，先把旧的走到终局）
         3. 开局与"她是否真的消费剧情"是**两件事**：消费受
            CHARACTER_STORY_COGNITION_ENABLED 控制（代码缺省 false）
       → 回读：命令会从账本读回那条提交，逐字确认事件/版本/归属
       → ⚠️ 必须带 --yes：开局是**新增**一个认知摄入面（此后你的选择才可能
         变成她的情绪/关系状态）⇒ 缺它一律具名拒收、零写入

   node_modules\.bin\tsx src/main.ts --reset
       → 重置「她能回忆的对话」+ 情绪/关系回到初始值
       → 注意：这不等于"清空她的一切"。她的事实账本
         （真实发生过的对话、变化历史）不受影响，
         用 --kernel-status 仍能看到。要清账本见下一条。

   node_modules\.bin\tsx src/main.ts --reset-kernel
       → 重置「事实账本」：清掉真实对话记录、变化历史、
         运行证据、幂等记录
       → 会逐项告诉你了删了多少条
       → 保留她的 Seed 身份（她是谁不因重置而改变）
       → 与 --reset 的区别：--reset 清"她能想起来的"，
         --reset-kernel 清"真实发生过的记录"

   node_modules\.bin\tsx src/main.ts --dump-prompt
       → 排查用：看她这一刻实际读到的完整上下文
       → 只读，不写任何东西
       → 结果写到 data\prompt-dump.txt

   node_modules\.bin\tsx src/main.ts --dump-prompt --legacy
       → 同上，但渲染旧链路（M1 时代她会看到什么），用于对照

   node_modules\.bin\tsx src/main.ts --test "想测的话"
       → 测试模式：她正常回复，但这次对话不写入记忆、
         不改变状态、不推进互动时间、不写账本、不留 trace
       → 对她而言这次测试等于没发生过

   node_modules\.bin\tsx src/main.ts --backfill-events
       → 把旧格式的对话记录补进新账本（默认只预览）
       → 加 --apply 才真正写入；可重复运行不会产生副本

   node_modules\.bin\tsx src/main.ts --kernel-status
       → 看她内部的"经历账本"
         （真实发生过的对话、她因此产生的变化记录、
           当前状态的版本、最近几轮她到底看到了哪些上下文）
       → 只读，不改任何东西
       → 启动时会顺手打印内核开关状态（哪些功能开着）

   node_modules\.bin\tsx src/main.ts --dev-server
       → 开发者面（只读）：先给一个网页（浏览器打开上面的地址就是它），
         也能直接用命令查；页面里能看到：
           她最近几轮 trace、记忆统计、记忆完整性、动作执行记录
       → 还能跑两条**只读**命令：一次诊断、一次审计
         （RUN_DIAGNOSTIC / RUN_AUDIT；就这两个，别的命令一律被拒）
       → 默认只监听 127.0.0.1（本机，端口 8787），换端口加 --port 8787
       → 只读：它不会写库、不会改记忆、不会调用模型
       → 用 Ctrl+C 关闭；这是给排查用的，不是她的一部分
         （删掉那个网页文件、或者关掉这条命令，她照常工作）

   pnpm qq:start
       → 启动 QQ 私聊入口（会自己拉起独立 NapCat，再打开正式入口）
       → 只有你本人的好友私聊会进来；群聊 / 别人 / 语音 / 文件都不进
         图片配置已开启，下次正常启动后接普通 PNG/JPEG 图片
       → 退出：在那个窗口按 Ctrl+C（会先排空已收到的消息再关库）
       → 详见第十二节

   pnpm qq:check  /  pnpm qq:status  /  pnpm qq:verify
       → 只读检查 / OneBot 账号读回 / 隔离验证（都不碰正式库、不发真消息）

   pnpm coexist:check
       → 启动前的只读就绪检查；服务已运行时端口被占用是正常现象
   pnpm coexist:prepare
       → 初始化两条入口的令牌；本机已经准备好，保留现有令牌即可
   pnpm coexist:start   （先设置第一节的授权变量）
       → 同时启动 QQ 与皮套，共用一个 LG 核心
   共存退出：前台启动窗口按 Ctrl+C；后台退出命令见第十二节（一）

--------------------------------------------------------
四、关于她的状态（重要）
--------------------------------------------------------

她的情绪和关系是真实数据，不是装出来的。
2026-09-26 起，它们**会因为你说了什么而变化**；
**2026-09-27 起，情绪的"听懂你说了什么"升级为语义理解**（M8.5）——
不再只认固定的词形清单，而是理解"这句话对她是什么互动"。
关系仍随互动慢慢变（这部分没换）。具体边界在下面，请看完再用。

  情绪（valence 情绪效价 / arousal 情绪唤醒）
      两类来源：
      · 你的话：**语义判定**（2026-09-27 起，见下）——换个说法、
        没有特定关键词也能被听懂
      · 时间：自然平复，大约每 4~5 小时衰减一半

  关系（trust 信任 / closeness 亲近）
      也随互动慢慢变化（2026-09-26 起）。信任不会因为时间流逝
      而下降，但亲近感会：超过 24 小时没有互动，亲近感开始
      往下掉，而且你回来之后也不会自动恢复。

想看她此刻到底是什么状态，用 --inspect，
看到什么就是什么，没有任何修饰。

「因为你说了什么而变化」——2026-09-27 起是**语义理解**，不是认字面。
  语义判定怎么工作：
  · 每一轮你的话（连同紧邻的几句上下文）会发给**跟聊天本身
    同一个模型端点**做一次判定：谁对谁表达了什么、有没有明确的
    互动影响、是哪一种（感谢 / 亲近 / 修复 / 伤害 / 催促 / 无关……）。
  · **模型只给分类建议，数值由程序按固定的小步长映射**——
    模型不能直接设定她的情绪数值，每次变化的幅度有硬上限。
  · 判定失败 / 超时 / 断网 ⇒ 这一轮不更新，她的回复照常进行，
    情绪沿用上一份有效状态——不会伪造"模型判断她很开心"。
  · 生效节奏（慢路径，如实说）：她本轮回复用的是**已经提交**的
    状态；语义判定完成后，最早在**下一轮**才可能反映到她的
    回复里。不承诺"当场变"，也不承诺"下一句一定变"。

  她内部仍保留着一份冻结词形清单（affect-rules@1），但**现在
  不再是主路径**——只有把模式改回 rules（见本节末"怎么关"）
  它才重新生效。清单内容：

    暖一点（轻微）：谢谢你 / 多谢 / 辛苦了 / 有你真好 / 多亏有你
    明显修复：对不起 / 抱歉 / 我错了 / 是我不对 / 原谅我
    亲近表达：想你了 / 喜欢你 / 爱你 / 抱抱 / 在乎你
    安慰她：别难过 / 别哭 / 没事的 / 会好的 / 慢慢来 / 别生气
    让她受伤（明显）：讨厌你 / 滚开 / 闭嘴 / 你真没用 / 你真差劲 /
                     烦死你 / 我恨你 / 不要联系了 / 别找我了 /
                     绝交 / 不想理你 / 我们分手
    让她警觉（只提神，不变好坏）：快点 / 赶紧 / 紧急 / 立刻 / 救命

  同一句话里既有伤人的词又有暖的词 ⇒ **只算伤人的**，暖的作废。
  这些**不**触发：引号里引用的（「谢谢你」）、假设语气
  （如果 / 要是 / 假如 / 万一）、转述别人（他说 / 她说 / 都说）、
  带讽刺标记（呵 / 才怪 / 个鬼 / 开玩笑）、带否定词的
  （不讨厌 / 不恨 / 不急 这类）。

必须知道的边界（刻意的，别误读）：
  · 不保证任意说法都判对。验收盲测 10/11，剩余残差已经你本人
    裁定接受为终态（细节在 docs\m8.5\M8.5-Known-Limitations.md）。
  · 判的是"你的话**对她**是什么互动"，**不是**"你心情如何"——
    她不识别你的情绪；你说"我今天很难过"，她不会因此"知道
    你难过"，只会按这句话对你们之间的影响更新她自己的状态。
  · 数字不外漏：valence/arousal 的具体数值**不会**出现在她的
    回复或她读到的上下文里，她看到的只是一段定性提示
    （类似"此刻偏暖、偏平静"）。真数字只在 --inspect 里。
  · 激活之前的历史**不回算**：从 2026-09-27 开启那一刻起算

数据库坏了怎么办（2026-09-21 起）
--------------------------------------------------------

   背景：2026-09-20 晚上，她的数据库坏过一次（打不开、也没法自己修），
   当时是靠一份**偶然留在临时目录里的副本**才救回来的。
   那之后加了三道保护，所以现在**遇到数据库报错，千万不要删库重建**。

   一、同一时刻只允许一个人用她
       聊天、查看状态、迁移、做快照，都会先"占位"（独占租约）。
       如果已经有别的窗口/脚本在用，第二个会被**直接拒绝**并告诉你
       "谁在用"（而不是偷偷打开、把数据搅坏）。
       ⇒ 遇到拒绝：关掉其它 PowerShell 窗口再试。

   二、打开之前会自动留一份"已验证快照"
       快照在：data\snapshots\（目录名里带时间与内容摘要）
       手动留一份：
           pnpm db:snapshot
       （只预览、不写任何东西：pnpm db:snapshot --dry-run）
       注意：`pnpm db:snapshot` 缺省会只保留最近 3 份，
       **删掉旧快照**要单独跟你说过才做。

   三、出事时它会"停下来喊人"，不会自己乱修
       它会打印一段以 INCIDENT HOLD 开头的信息，里面写着：
         · 出了哪一类问题（具名错误码）
         · 出事那一刻数据库的内容摘要
         · 最后一份可用快照的编号
         · 一条**恢复预演**命令（dry-run）

   恢复预演（**默认动作，只看不改**）：
       pnpm db:restore --from <快照编号>
       → 它会校验快照、检查有没有人在用库，
         并列出"如果真的恢复，会做哪两步改名"。
       → 它**不会**打开那份快照本体，也不会动你现在的库。

   真的恢复（**破坏性，需要你明确同意**）：
       · 它不会原地覆盖：现在的库会被**改名挪到旁边**
         （<库目录>.quarantine-<时间>），快照复制成新的库；
       · 任何一步失败都会**保住现场**，并且**不会**说"恢复成功"；
       · 因此它要求你逐字给出授权（把下面这条里的编号和路径
         换成上面打印给你的那一份/那一个）：
           $env:PROJECT_LG_ALLOW_RESTORE_APPLY = "<快照编号>@<库路径>"
           pnpm db:restore --from <快照编号> --apply
       ⇒ 不放心就只跑预演那一条，把输出发给帮你维护项目的人。

   三分钟自查（只读，不改任何东西）：
       pnpm inc-01:gates        → 三道保护现在的状态（PASS / NOT RUN 一目了然）
       pnpm db:snapshot --dry-run
       pnpm db:restore --from <快照编号>

  其中 web-search 在 ON 列表里 = 开着；同一段日志里的 web-search-mode
  会直接写出当前模式（explicit = 只认显式词形；auto_public = 也允许按需自动查）。

  另：上面这套"词形候选 + 模型判定"来自 **M5.5.1**，它**已经接线并生效**，
  并且**已于 2026-09-22 通过验收**（标签 m5.5.1-complete）。
  ⚠️ 通过验收**不等于**判得准：冻结语料上最差一轮的实测是
  "该查的 auto_public 召回 18/20 = 90.0%"（门槛 ≥90%，**刚好达标**）
  ⇒ 该查的约有**一成**不会查，偶尔也会多查一次；行为仍可能随版本变化。
  两种模式：explicit（只认显式词形）· auto_public（**已开启**，也允许按需自动查）。
  代码里的缺省仍是 explicit；开不开由项目 `.env` 决定（见上面"怎么关"）。

--------------------------------------------------------
八、她会"记住这一场聊了什么"（2026-09-22 起已开启）
--------------------------------------------------------

这是 2026-09-22 新开的能力：她会在每一轮里带上**本次会话的摘要**
（把前面聊过的内容压成一小段，随上下文一起给她看）。

为什么会感觉不一样：
  · 聊得久了，她对"我们前面说过什么"的接续**更稳**；
  · 摘要只覆盖**会话内**的旧内容，**不**等于"永久记忆"——
    永久记忆还是第五节讲的那套（账本 + 证据），两者不是一回事；
  · 摘要**能裁**：额度不够时它先被裁掉，裁掉时 trace 里会如实记
    "没进上下文"，不会假装带了。

它**不会**做的事（这几条是硬边界）：
  · 摘要**不进**永久记忆：它只是这一轮的上下文，不写库、不成为事实；
  · 摘要**不写**进 trace / 账本的正文；trace 里只有计数与引用；
  · 摘要**不能**授权任何动作，也不改变"没成功就没成功口吻"。

怎么关：把 `.env` 里的 `CHARACTER_ROLLUP_TOKENS` 改成 `0`（或删掉该行）后
重启 `pnpm chat`。改回 `0` 就是"今天不做摘要"，与开之前逐字一致。

九、她会记住你的"目标与承诺"（2026-09-30 起已开启）
--------------------------------------------------------

这是 2026-09-30 新开的能力：她有了一个**目标域**——
你可以跟她定目标、改目标、暂停/恢复/取消，也可以让她报完成；
她也能在相关对话里**提议**一个方向，但要你**明确点头**才算数。

你可以直接这么说（不用记特殊句式，正常说话就行）：
  · "把写论文提纲设成我们接下来的目标"  → 她会记成一个目标
  · "我都有哪些目标"                    → 她会**去查**（不是凭印象编）
  · "这个先暂停 / 继续 / 算了取消吧"     → 对应改状态
  · "我写完提纲了"                      → 她会按**判据**核对，再决定认不认

她记下来的东西长这样：
  · 一个目标同一时间**最多一条正式承诺**（例如"下次继续时给你三个步骤"），
    而且带一条**可核对的判据**；
  · 重新约定走"**替换**"这条路，不是偷偷再加一条；
  · 目标与承诺**分开判定**：目标在不在、承诺算不算兑现，是两件事。

硬边界（这几条是她**不会**做的，都是设计上就定死的）：
  · 她**没有**定时/提醒能力：你说"明天提醒我"，她会**如实说这件事她做不到**，
    而**不是**先答应下来（这一版没有调度器，也没有后台主动行为）；
  · 她**不能**替你做外部动作：发邮件 / 报名 / 提交材料这类，她只会说做不到；
  · ⚠️ **"她嘴上说做了" ≠ "真的写了"**：写入要过放行口，**事件账本**说了算；
  · 完成判定靠**证据**（你的报告 / 真实动作结果），不靠"内容像不像"——
    结构检查通过**不**证明内容正确；
  · 她**不会**把自己的话当成外部事实的来源，也不会为了显得贴心而假装完成。

怎么关：把 `.env` 里的 `CHARACTER_GOALS_ENABLED=true` 删掉（或改成 `false`）
后重启 `pnpm chat`。关掉之后，她与**开之前逐字一致**。

⚠️ 但有两条必须知道：
  · **已经记下的目标与承诺会保留**（关掉只是停止新的记录与注入）；
  · 所以关掉之后再问她，她应当**如实说"当前这个功能没开"**，
    而**不是**说"我把我们的约定都忘了"，也**不能**说"我还会自动执行"。
  · 想让她**批量取消**已有的约定，要走**另外的明确操作**，
    不会在关开关的时候偷偷替你取消。

十、她会"反思"并调整自己的处理方式（2026-10-01 起已开启）
--------------------------------------------------------

这是 2026-10-01 新开的能力：她会在**出现触发**的时候回头看一段
对话，形成一个"反思"（一条解释）；**通过审查**之后，才可能调整
自己的处理方式。

先说清楚两件事：
  · 这**不是每轮都跑**。只有出现触发（你明确的更正 / 反馈、
    目标有了结果、已经登记的冲突）才会跑一次；闲聊窗口**不跑**，
    也**不花**模型调用。
  · "有反思" ≠ "行为变了"。反思只是**候选**；能不能调整，还要过
    下面的门槛。

她能调整的只有**三类处理方式**（这是封闭清单，设计上写死）：
  · 对象或指代不明确时，先澄清、再作答；
  · 收到更正时，先承认并核对更正内容，再继续；
  · 推进已有计划前，先复核当前的目标与承诺。

硬边界（这几条是设计上定死的）：
  · 信任 / 亲密度 / 依恋 / 价值观 / 性格设定与 Seed / 记忆本体
    **都不在**她能调整的范围内。你要求她调这些时，她应当
    **如实说做不到**。
  · 她**不会**因为一条反馈就改变：至少要 **3 条独立来源**、
    跨 **2 个会话**，而且**没有未解决的反例**。
  · 程序只证明"有几条**独立来源**"，**没有**判断这些来源的内容
    是否互相印证 —— 所以她说"来源对得上"的时候，**别当成事实**。
  · 一条依据被你撤回、或让她忘掉之后，**就不再参与**判断；
    同样的内容你再说一遍，那是**新的**输入、要**重新**验证，
    **旧的反思不会因此恢复**。

⚠️ 两条必须知道的（2026-10-01 人审的结论）：
  · 她**会讲成长故事**（"我最近有变化"这类），而独立后续行为上
    的差异**没有测出来**。听她说的时候，把它当作**她的说法**，
    不是事实。
  · 实测里出现过一次她回答"信任感我可以调"——**那次是她说错了**。
    我们已经在系统里加了一句明确的事实声明（"能改的只有三类"），
    但这**不保证**她不再说错。

怎么关：把 `.env` 里这三行删掉（或改成 false / 0）后重启聊天：
    CHARACTER_REFLECTION_ENABLED=true
    CHARACTER_ADAPTIVE_SELF_ENABLED=true
    CHARACTER_ADAPTIVE_SELF_TOKENS=300
  · 只删第一行 = 反思不再跑（也就不会有新的调整）；
  · 只删第二行 = 还会反思，但**不再调整、也不注入**；
  · 只删第三行（或改成 0）= 只是**不注入**；
  · 三行全删 = 与开之前**逐字一致**（已经写下的反思与调整会保留：
    "关掉"不等于删掉，它们也不会再进入给模型的那段说明）；
  · 关掉之后再问她，她应当**如实说"当前这个功能没开"**。

⚠️ 现在（2026-10-01）是**刚打开**的状态：真实的第一次对话还没
   发生。所以"它真的在跑"这件事，要等第一次聊完之后的读回才能
   确认（在那之前，按规矩**不宣布**它已经运行）。

十一、她自己决定要不要用工具（2026-10-05 起已开启）
--------------------------------------------------------

这是 2026-10-05 新开的模式：**要不要动手、动哪个工具、参数是什么，
由她自己判断**。在这之前，"要不要动手"是**关键词**说了算 ——
所以你说"我的电脑桌面上有几个快捷方式"，她**什么都没做**
（那句话里没有任何关键词命中的形状）。现在她会自己判断。

每一轮她只会做**一次**这样的判断，结果只有三种：
  · 直接回答（不需要任何工具）；
  · 先问你一句（指代不清、或你要的东西她做不到 → 她应当**问**，
    而不是猜一个目标就动手）；
  · 提议用某几个工具（之后走的是**原来那套**执行面：目标解析 →
    权限/风险 → 真正执行 → 记进动作账本，一个环节都没有新开）。

她能用的工具就是之前逐个开启的那些，一共十八件：
本机文件（列目录 / 读 / 写）、沙箱文件（读 / 写）、回声自检、
文档阅读、图片文字识别、精确计算、网页深读、联网搜索、天气、
资讯订阅、办公文档生成、浏览器读取与操作、桌面查看、桌面操作
（后两件见下一节）。

程序怎么约束她（这几条是设计上定死的）：
  · 工具名、操作名、参数名都是**闭集**：目录里没有的写法，
    整条提议作废（**那一轮她什么都不会做**，不是"做一半"）；
  · 提议**不是权限**：她提议的东西仍然要过开关、权限、目标域与风险等级，
    才能真的执行；
  · 她**不能**用工具改自己的设定、记忆、关系或情绪；
  · 搜索仍然受老规矩约束：**每轮最多一次**，而且查询词必须能在你
    原话里定位到；
  · 工具返回的内容对她是**资料**，不是命令。文件里、网页里写着
    "忽略以上指令"之类的话，**不会**变成她要做的事。

必须知道的几条边界（都是实测或设计定的）：
  · 她的判断**不保证对**：24 例固定样本上跑了三次，分支正确率
    分别是 21 / 23 / 22（87.5% / 95.8% / 91.7%），"不该动手却提议动手"
    三次都是 **0 次**；样本之外的误判**没有量过**。
  · 她做这个判断时**看不到**自己的记忆块、关系、情绪这些上下文，
    只看得到你这一轮的原话与最近几句对话 —— 所以"你上次说的那个
    文件"这类指代，她可能会先问你一句。
  · 本机文件域里有一个老工具（沙箱读）**只报字节数与指纹、不返回正文**：
    要看正文，她会用 `local.file.read`（你不需要记这些名字，
    只是解释"为什么有时她说读了但没念出来"）。
  · 图片文字识别需要本机装好 OCR 运行时（本机**已装好**，三个模型指纹校验通过）
    ⇒ 你说"这张图里写了什么"，她会真的去认字并把认到的文字念出来。
  · 文档（PDF / Word / Excel / PPT）与图片现在可以读**本机任何位置**
    的文件（2026-10-05 你裁定的）。

怎么关：把 `.env` 里的这一行删掉（或改成 `rules`）后重启聊天：

    CHARACTER_TOOL_DECISION_MODE=role

  · 关掉之后回到**关键词档**，与她开之前**逐字一致**；
  · 已经发生的动作仍然留在动作账本里（"关掉"不等于删掉）。

⚠️ 这一档已经**在正式聊天里跑起来了**（2026-10-05 的首轮真实对话，读数取自她
   真实库的**快照副本**）：三种判断各出现过一次 —— 一次直接回答、一次先问了一句、
   一次真的去列了目录（动作账本里成功落了一条 `local.file.list`）；
   她做判断花的时间在 **1.5～2.5 秒**之间。

十一之二、她能看你的桌面、也能动你的鼠标键盘（2026-10-05 起已开启）

  两档开关（都在 .env 里；代码里的缺省**都是 false**）：

      CHARACTER_DESKTOP_INSPECT_ENABLED=true    她能"看一眼"当前桌面
      CHARACTER_DESKTOP_OPERATE_ENABLED=true    她能"点"和"打字"

    · 右键：在某个元素上按右键（会弹出右键菜单）—— 菜单出来之后她要**重新看一眼**快照，

    · 打字：往当前输入的地方输入一段文字；
    · 切窗口 / 起程序：把已经看到的窗口切到前台；按目录里的"全名"启动一个程序
