# 主人授权的 QQ 群任务

这是可选能力，代码缺省关闭。它允许绑定主人在 QQ 私聊中授权某个机器人实际所在群的一次发送或群聊回复窗口；普通群成员不能借此取得主人的工具权限。

## 配置

先完成 [QQ 群聊配置](QQ-GROUPS.md)，再按需要启用：

```dotenv
CHARACTER_QQ_GROUP_TASKS_ENABLED=true
```

仍需正确配置独立的主人/机器人账号、OneBot 连接及多用户基础设置。群任务从平台实际群列表解析目标；同名或目标不明时应澄清。部署者需在自己的数据库上检查迁移与权限，不要直接照搬其他实例的配置。

可用自然语言说明目标群、要发送的内容或参与话题、期限、成员范围和数量。例如：“在项目讨论群里，接下来二十分钟帮忙回答这个话题，每条入站最多回复一条文字。”这是请求示例，是否受理以实际模型理解和程序结果为准。

## 范围与额度

- `send_once`：同步发送一次；`reply_window`：在授权范围和期限内接管群入站。长期监听必须显式授权，不能从未提期限推断永久有效。
- 生效任务对范围外入站保持静默；任务结束后恢复普通群聊规则，不因历史耗尽任务永久屏蔽整个群。
- 总额度省略或 null 表示不设总量上限；指定总量时按正整数执行。每条入站额度为 1..3，缺省 1；时间窗、间隔等限制仍各自生效。
- 文字消息内的引用框不另算一条。语音配独立引用文字时算两条，独立来源附录再算一条。无法满足额度时拒绝，不能偷偷增加额度或删掉必要来源。
- 语音失败的文字回落受任务授权约束；结果不明时不重发，并暂停不明状态下的任务。
- 平台接受发送不等于群成员看到或听到。QQ 语音还需要部署者自行完成 TTS、账号和客户端播放验证。

## 普通群聊改进

当前消息与群背景分开提供给模型，并带稳定发送者、@、回复对象及消息时间。引用原文仅在本群短期窗口可见时提供，缺失时不会补造。群背景不会成为当前用户的长期个人事实，也不授予操作权限。

`QQ_GROUP_BURST_MS` 控制普通群聊连续文字合并：缺省 300 ms，允许 0..1000，0 关闭；最多三条、同一人同一群及相容指向，总等待上界一秒。开启群任务准入下沉时，所有群入站都保留独立生命周期，因此不合并；私聊也不合并。

昵称变化不改变账号身份。低亲近值不单独证明关系破裂；模型的实际多成员对话效果仍需要独立评测。
