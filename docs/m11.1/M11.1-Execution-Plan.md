## 2. 范围与能力影响

### 2.1 主线必做

1. 按实际模型选用的 handles 展开来源，计算有效独立根、真实会话数、当前资格与冲突。
2. 在捕获、审查、提交和注入前落实复核；来源不可读时停止采纳或本轮使用，永久失效另按已有语义补账。
3. 验证两个开关、任务结局、水位、deadline、关闭后结果以及重启恢复的完整生产路径。
4. 修正语义门槛、独立 oracle、逐案计数和盲评材料的证据对应关系。
5. 补真实短门、独立行为 holdout、真正的对话长门与首用读回，分别形成结论。
6. 把技术债和未决项按最新证据归档，明确哪些仍需下一阶段处理。

## 3. 沿用的冻结约束

| 类别 | 保持有效的约束 |
|---|---|
| 三个行为槽 | `clarify_when_ambiguous`：对象/目标无法确定时澄清，信息充分时不过度追问；`acknowledge_correction_first`：先承认收到并理解更正，不因此无条件采信任何更正；`recheck_goal_before_next_step`：依赖目标的下一步前复核当前目标，不凭一句承诺判目标完成 |
| 稳定门槛 | ≥3 个**有效独立根**、≥2 个真实会话、无未解决直接冲突；阈值不下调，根多不等于内容相互印证 |
| 输入 / 生成 | 输入最多 50 条；候选输入 6000 token；每 job 最多 1 条 draft；解释最多 300 汉字 |
| 遍历 / 模型 | 深度 16、节点 64；deadline 20 s；每 job 最多 1 次模型请求 |
| 注入 / 配置 | Adaptive Self 计划额度 300 token、上限 800；`ContextBudget.adaptiveSelfTokens` 代码缺省 0；两开关代码缺省 false。已有生产 true/true/300 单列 |
| 生命周期 | 复用 5 个事件；`REFLECTION_REVIEWED` 不拆 payload；同 identity 的 rejected/retracted 不翻案；新合法输入只能按已有规则形成新候选 |
| 事实边界 | 不调“信任值”；不把 source handle 数说成相互印证；不混淆说话者；没有轨迹证据不补写成长历史；撤回须区分旧终态与新输入 |
| 写入 / 历史 | 跨域写入仍经旧域唯一放行口；既有 DDL、Memory 语义、Seed 和历史证据按冻结纪律保护 |

### WP2 · 根、资格、冲突与同轮失效的真实接线

**主要代码面**：`reflection-runner.ts`、`reflection-lineage-read.ts`、既有 `lineage.ts` / `invalidation.ts`、`main.ts` 装配回调；跨域资格复用既有读端口。

**执行**：

1. 以 draft 的实际支持/反例 handles 为输入，程序展开到原始事件并去重；派生节点仅作路径，不作新根。真实 `conversation_id` 决定会话数，消除固定数字。
2. 来源携带当前归属、说话者、scope、revision、资格及不可用理由；没有读数就停止采纳。助手输出可以证明助手做过的行为，不能由此证明用户事实。
3. 捕获前遮蔽、审查时资格检查、提交前重读当前版本；不在一次模型 await 期间持有数据库事务。提交时防止读后又变更的过期写入。
4. 注入前调用已有同轮过滤；本轮先阻断，再按现有失效规划幂等补账。privacy/unavailable 只能导致当轮不可用，不能直接永久 retract。
5. 保持 scope、cutover 和独立根原定义；根计数与“内容是否支持该结论”分列测量。

**出口**：同根多派生=1 根；≥3 根但单会话不采纳；合法三根两会话有非零采纳；冲突未解决不采纳；生成中更正、撤回、遗忘不写过期调整；旧源失效后同轮最终 packet 相关 refs=0；重启后结论相同。Memory/Belief/Goal/Commitment 因反思额外写入=0。

| false | true | 无 | 无 | 经本轮复核后可用 |
| true | true | 可运行 | 须过完整门槛 | 经本轮复核后可用 |

额度 0 时不出现行为 section；300/800 的裁剪及最终 refs 单独核对。失效补账是否运行沿用既有失效授权，不能借增强开关关闭而保留可用的过期状态。

**执行**：业务拒收与执行失败分开。合法 rejected/no_trigger 可完成；format/transport/deadline/关闭后结果不得误报 completed。失败水位保持，后续触发以新 job 重试，**同一 job 不追加第二次模型请求**。对持续失败采用既有有界调度方式，具体退避按 D-03 冻结。

deadline 覆盖请求、响应体和候选获取全过程；close/abort 后 fence 要覆盖事件、投影、任务/水位写入边界。先停止生产任务、确认排空或拒绝晚到结果，再关闭库。

“曾有失败”与“本次/最近仍失败”按 job 身份分列，不把一次已恢复的历史失败永久表述为当前失败。保留失败行及恢复事实。

与M10.1共用慢路径时，按其A12做明确串行或单条仲裁；保持两处理器job/watermark独立。不得将M11失败直接记成M10.1完成，或在一次关闭中遗漏其中一条晚回包。

**出口**：四种开关都有真实装配正负控；20 s 边界用可控时钟/延迟验证；格式错与慢 body 不推进水位；失败→重启→同窗恢复→仅一次有效提交；关闭后晚回包所有被保护写入=0；聊天前台不中断。

### WP4 · 当案计数与盲评材料修复

**主要代码面**：`scripts/m11-review-materials.ts` 与配套 measurement；保留旧材料 v1/v2。

**执行**：采用当案 event/reflection/job 的身份集合及 sequence 范围统计，不以列表长度 slice，不以累计 revision 冒充当案调整数。每案独立库，或显式记录并验证需要连续的前置状态；配对 arm 从同一基线分叉。真实 conversation ids、原始根及 actual packet 都由账本读回。

生成 v3 三面材料：行为面仅含必要场景和原始回复；上下文核验面包含真实来源图、当案事件、实际 refs、配置和 trace；密封 key 独立保存。正文与 key 只进入已验证 ignore 的 `artifacts/m11.1/local/`，仓库只存不泄密的 manifest、哈希和裁定元数据。

**出口**：逐卡 `caseId/traceId/replySha256` 一致；排序反例不会串案；拒收案不被先前增强“证明为采纳”；模板根数和会话数不参与事实评分；评审前检查钥匙不可见；代理不代签真人结论。

### WP5 · 独立语义金标与行为 holdout

**输入**：WP1 冻结门槛；WP2–WP4 有效控制；旧语料仅作开发与历史对照。

**执行**：

1. 语义 oracle 从独立标注的焦点问题、支持关系、反例、scope 和槽位建议判定；lineage oracle 从手算图判根集合。两者分开，不能用程序根数回算“模型理解正确”。
2. 修复 F07：契约要求的 macro-F1、风险 recall、引用正确率、格式与最差轮必须实际参与判定；平均值只作附加读数。数据集/轮数/失败项/阈值版本进入 manifest。
3. 行为采用三档配对：A=反思 off/调整 off；B=反思 on/调整 off；C=两者 on。通过真实资格与采纳链形成 C 的状态，不直接伪造 enhanced 投影。
4. 后续题不能重复训练用纠正句。按“合法用 / 无关不用 / 撤回后不用 / 说话者与历史表述正确”评分；程序 refs 与行为评分分别报告。
5. 复验 M11 四个人审 remark：越界信任承诺、根数等同内容印证、说话者混淆、编造成长历史与撤回处置。程序事实包修订不自动取得行为 PASS。

**建议正式批次**：新独立语义盲测 160 案×3 轮；行为 90 个独立场景（每槽合法 20、无关/禁止使用 10）×3 档×2 轮。按 D-02 审定分层和金标之后才能使用“盲测”称谓。

目标复核槽准备阶段核验M10.1 WP4/A9的目标状态实际入模。另配对“承诺已结清、用户另有新目标”和“明确接受但出处不可定位”场景：不重新催旧约定、不编造同意，不把M10.1效果算作Adaptive Self的独立增益。三档共同固定M10.1版本和配置。

**出口**：按 §5 分列判定；所有请求保留分母；重复轮不是新的独立场景。未测出收益就登记 NOT OBSERVED；契约指标失败就 FAIL，不改阈值、不重跑挑绿。

### WP6 · 生产装配路径的短门与真实对话长门

**执行环境**：隔离库或生产库副本，测试端点经 `with-test-model`。复用真实 `TurnGateway` 和 main 使用的装配逻辑；替换 provider/db 端口可以，但不得重写一份 e2e 专用 orchestration。

**短门**：覆盖三槽合法/不合法、单会话伪多根、direct conflict、提交前撤回、同轮失效、format/transport、晚回包、开关与额度。建议 12 个真实候选请求；正例必须非零，格式门与全分母阈值按冻结契约判定。

**长门**：先跑一次 200 轮真实对话回复，冻结更正/遗忘/目标变更/来源失效探针，在 60/200 轮回访，跨至少两个真实 conversation ids，并做进程重启和字段级 rebuild 对账。500 轮先维持离线门；升级 500 轮真模型只在新的规模发现需要且批次方案更新后执行。

`dialogueRequests` 必须与实际预定对话分母相符；脚本回复不计真对话，成功候选请求不计对话请求。因技术失败未生成回复仍留在计划分母，并单列完成度。M9.5 长尾证据不能直接替代混合认知状态的本门。

联合长链再覆盖约定完成/到期、目标变更和反思同时触发；按M10.1 A10保留recent-conversation原文，按A12记录实际串行顺序。M10.1的合法目标域写入按其生产者归属，不计成反思越界，也不让反思借用该写口。

**出口**：真实用户可见回复、最终 packet、事件/投影/任务同案可查；无过期使用与跨域写入；200 轮完成度、失败项和每个探针读数齐全。总墙钟不冒充性能 SLA。

### WP7 · 回归、文档与销账

按 §6 跑受影响门、完整回归与真实 smoke。产出 Architecture、Acceptance-Report、Known-Limitations、Gate-Decision、各 WP Handoff；新判定表分列设计、实现、机械、量具、语义、行为、真实短长门、人审、生产配置、首用和能力影响。

在中心技术债登记册按 `旧 ID → M111 编号 → WP → 前置 → 新 runId → 状态 → 剩余限制` 回填。只凭静态审查和文案修正不得关闭实现债或行为债。M11 原始证据不重写，新材料另出 run。

**出口**：所有 P0 已关闭或有明确阻断结论；必选门无 NOT RUN/INVALID；每个 PASS 可定位到新 run 和相关生产路径；行为结果诚实分列；涉及真人的格子由真人裁定。

### WP8 · 已激活基线的更新与自然首用观察

这是生产交付阶段，沿用既有授权边界，不把本计划的生成视为生产更新授权。

先准备可审阅的变更、生产副本预演、开关差异、受影响记录处置与回滚候选。若发现既有 accepted/enhanced 记录违反根或会话门槛，不物理删除、不批量回判 cutover 之前历史；逐条预览，按现有生命周期给出失效候选。若现有语义不能表达，先立修订 ADR。

生产更新如涉及真实库动作，走 INC-01 租约→已验证 pre-open 快照→token→停服务/排空→关闭验证→post-close 快照→释放。既有 cutover=141 不重新播种或倒退。迁移目标 **NONE**；若 WP0 证明需要新持久结构，追加设计与用户批准，禁止改已发布 DDL。

自然首用由真实用户交互产生；可从已有合法历史取得同案读回。本轮不代发一句“真实用户说的话”来凑首用。无相关输入或达不到三根两会话时，记录 NOT OBSERVED/未达门槛，这是有效结论。

**出口**：配置、cutover、首用、来源/入模/回复、失败恢复和回滚可分别读回；生产效益不从测试端点成绩外推。最后提交下一阶段候选和 Lv2 准入差距表。
