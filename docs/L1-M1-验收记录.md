## 2. 关键验收：对话连续性与 Recent Messages

脚本化运行两轮：

```bash
node_modules/.bin/tsx src/main.ts "你好，我叫Alex" "我刚才说我叫什么名字？"
```

**实际输出（DeepSeek 官方端点 `deepseek-flash`）：**

```
未命名角色: 你好 Alex，很高兴认识你！有什么我可以帮你的吗？

未命名角色: 你刚才说你叫 Alex 呀，怎么啦？
```

第 2 轮明确引用第 1 轮用户自报的姓名——**说明历史消息确实经由
`RECENT_MESSAGES` provider 进入了本轮上下文**，不是模型凭空猜测。

同时这也验证了 **模型输出的解析链路**：模型按 `messageHandlerTemplate`
返回的是 `<response><thought/><actions/><text/></response>` 结构，
provider 用 `parseKeyValueXml` 取出 `<text>`，因此打印给用户的是
自然语言而不是原始 XML。

**早前在硅基流动端点上的同一实验，另附模型自述的思考过程：**

```
第 1 轮 thought：对方简单打了个招呼，我也应该礼貌回应，简单介绍下自己。
第 2 轮 thought：对方在测试我是否记住他的名字。他刚才说叫Alex，我应该直接回答。
```

## 3. 上下文组成实测

每轮的 provider 贡献被记录在日志中（`DEBUG_CONTEXT=1`）：

```
# DeepSeek 官方端点
[turn 1] providers: ACTIONS(2542), PROVIDERS(488), ANXIETY(316), RECENT_MESSAGES(313),
                   TIME(153), CHARACTER(102), ROLES(93), SETTINGS(67),
                   ACTION_STATE(37), CHOICE(34) | 估算历史行数: 34 | prompt 8067 字符

[turn 2] providers: ACTIONS(2538), PROVIDERS(488), RECENT_MESSAGES(479), ANXIETY(316),
                   TIME(153), CHARACTER(102), ROLES(93), SETTINGS(67),
                   ACTION_STATE(37), CHOICE(34) | 估算历史行数: 37 | prompt 8229 字符
```

可读出两件事：

1. **`RECENT_MESSAGES` 从 313 → 479 字符**，正好是第 1 轮问答被累加进来，
   历史注入链路可量化验证。
2. **`CHARACTER(102)`** 说明角色人设走的是 ElizaOS 原生 `CHARACTER` provider，
   而不是我们手写进 prompt。

> 注：`ANXIETY` / `CHOICE` / `ACTION_STATE` 等 provider 来自官方 bootstrap 插件，
> L1-M1 并未使用它们的输出；后续会用 provider 白名单收敛上下文。

## 5. 本次运行环境

| 项 | 值 |
|---|---|
| Node | v22.23.2 |
| 包管理器 | pnpm 12.4.1 |
| `@elizaos/core` | 1.7.2（发布稳定版） |
| `@elizaos/plugin-sql` | 1.7.2 |
| `@elizaos/plugin-bootstrap` | 1.7.2 |
| `@elizaos/plugin-openai` | 1.6.0（仅用于 embedding） |
| 数据库 | pglite（本地文件，免运维） |
| 对话模型 | **DeepSeek 官方** `deepseek-flash`（`https://api.deepseek.com`，OpenAI 兼容 `/chat/completions`） |

> **端点与模型名的实测结论**：DeepSeek 官方 `/models` 实际提供的是
> **`deepseek-flash`** 与 `deepseek-v4-pro` 两个模型。
> 传入 `deepseek-v4.1-flash` 会被拒：
> `The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-v4.1-flash.`
> 另外 `deepseek-chat` 是自动映射到 `deepseek-flash` 的别名（响应里 `model` 字段会回写为 `deepseek-flash`）。
> 因此 `.env` 中固定使用 `deepseek-flash`。
