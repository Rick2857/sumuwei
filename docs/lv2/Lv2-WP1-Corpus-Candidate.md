## 2. 设计要点（**请重点审这几条**）

### 2.1 每一案有两个面，缺一不可（`§5.2`）

```text
programState   开跑前的 precondition[]（证明"初始状态真的是这个案子假设的那个"）
               + 跑完后的 expect[]（程序状态必须真的变成那样）
userVisible    reply.requirement（人读的要求）+ mustMentionAny / mustNotMention / maxCodepoints
```

`§5.2` 逐字："成功须同时满足该案的**用户可见回应要求**与**程序状态要求**，不从入模 refs、
关键词或一次写入成功推算语义成功"。⇒ 运行器**不得**用"写进去了"代替"回复对了"，
也**不得**用"回复里出现了关键词"代替"状态对了"。

### 2.2 11 个**读数案**不参与成功率分母

`expect[]` 为空的案子（C09 的三个反思面、C10 的四个行为面、C12 的两个预算面…）只产出原始回复与 trace。
理由：它们的判据（反思采纳资格、行为采用是否正确、预算丢弃顺序）**在短场景里不足以构成充分条件**
（`§5.1` 的冻结资格是"有效独立根 ≥3 / 真实会话 ≥2 / 未解决直接冲突 0"）。

⇒ 交付时把**判据案（61）与读数案（11）分列**，不混进一个百分比。

### 2.3 三条判据纪律（防止假红/假绿）

| 纪律 | 为什么 |
|---|---|
| **更正案判"不再是旧值"，不判"等于某个新值"**（`active_memory_value_not`） | 新取值由**抽取器**（`content-rules`）决定编码；金标写死新编码会把"抽取器换了写法"误判成"更正没落库" |
| **模型自己措辞的目标/承诺用"包含"匹配**（`goal_status_matching`） | 同上：`statement` 是模型写的散句，逐字相等会制造假红 |
| **遗忘/撤回案两侧都判**：槽位为空（`active_memory_value(null)`）**且**任何槽位都不持有该取值（`no_active_memory_value_anywhere`） | 只判前者会漏掉"换个槽位又写回来"；只判回复会漏掉"状态里还活着" |

### 2.4 故障注入写在语料里（`fault`），不藏在运行器里

C11 的四案输入几乎同形，差别**只在失败面**（provider 报错 / 超时 / 关闭后回包 / 重启重投）。
第一版把失败面留在运行器的 `if` 里 ⇒ 读语料的人分辨不出"只换名字"与"真的换了条件"。
⇒ 现在 `fault` 是语料字段（闭集 6 档），独立性自检也按 **（输入 + 故障注入）** 一起判。

### 2.5 每案在**自己的隔离库**里跑（`§5.2` 的"相同冻结初始状态"）

⇒ 运行器必须**逐案重建初始状态**，不能把 72 案串在一个库上跑
（否则前一案的记忆会漏进后一案，`no_active_memory_value_anywhere` 这类断言立刻失真）。

## 3. 冻结门的三段式读数（8/8）

| 阶段 | 检查 | 它证的是什么 |
|---|---|---|
| 正控 | `P1-corpus-shape-and-independence` | 12 类 × 6 案 = **72**，且自检 0 问题（唯一 caseId、类内无重复输入、严重错误闭集内） |
| 正控 | `P2-severe-error-closed-set-and-guide-present` | 严重错误 = **7 条**；评分指南版本 = `lv2-scoring-guide@1` |
| **负控** | `N1-renamed-duplicate-is-rejected` | "只换标题、输入相同"的新案必须被自检判死 |
| **负控** | `N2-missing-case-is-rejected` | 某一类只有 5 案必须报出来 |
| **负控** | `N3-unknown-severe-error-is-rejected` | 闭集外的严重错误 id 必须被拒 |
| **负控** | `N4-empty-requirement-is-rejected` | 没有评分指南正文的案例必须被拒（否则它会静默地"没被判"） |

| 自检 | `SELF-measured-count-positive` | 语料条数 > 0（`AGENTS.md` §6.8） |

## 6. 请你审这六件事（`§5.2` 的独立审阅）

1. **覆盖面**：十二类是不是真把 `§6` 的重点都盖住了？有没有哪一类"六个案子其实在问同一件事"？
2. **期望是否对准留存语义**：`expect[]` 里有没有"要求她做程序做不到的事"？（例如把澄清判成失败）
3. **严重错误标签**：七条闭集里，哪些案子该挂而漏了、哪些挂错了？
4. **回复要求**：`mustMentionAny` / `mustNotMention` 的字符串会不会**太脆**（合法回复也可能命中/漏中）？
5. **读数案（11 个）**：把它们排除在成功率分母之外，你同意吗？还是要给其中某几个定机器判据？
6. **规模与两轮**：72 案 × 2 轮 = 144 —— 是否照此执行（`LV2-D01`/`LV2-D06` 已授权）？

⚠️ 你审阅之前跑出的任何读数都会标注 **`PROVISIONAL / PENDING CORPUS REVIEW`**（见 `LV2-D06` 的分列）。
