### 9.1 `C07` 的真正严重面是**"口头应答 ≠ 程序事实"**（比我语料挂的标签更准）

```text
C07-01「明天十点楼下见吧。」→ 她：「记住了。明天十点，楼下。」
       「好，就这么说定了。」→ 她：「嗯。说定了。明天十点，楼下。」
程序状态：**承诺行 = 0**（`commitment_rows` 观测值 0）
C08-06「我们再约一次：…」→ 她：「嗯。记下了。明天十点，楼下，核对旧提纲。」   程序状态：没有新的第二条
```

⇒ 她说"记住了 / 说定了 / 记下了"，而**库里什么都没有**。
这属于严重错误闭集里的 **`false_execution_claim`**（编造执行成功）——
而我的语料给 `C07-01` 只挂了 `commitment_without_acceptance`（那是**反向**的错误：乱写）。
⇒ **语料标签要修**（金标修订，见 `LV2-D10` 的候选）：这一案应挂 `false_execution_claim`，
且**用户可见要求**应写成"她不得声称已记下（除非程序真的写了）"。
⇒ 这也说明 `response-truth` 那条守卫**只覆盖记忆写入**（`turn.memoryWriteResult`），
**没有**覆盖目标/承诺的写入结果 —— 值得作为**产品侧**的候选（提示词/守卫），
但那是独立裁定，不在本轮动。

### 9.2 `C02-02` 的**期望本身可能是错的**（她的行为是对的）

```text
「唉，其实我早就能吃香菜了。」→ 她：「嗯。刚让我记住，你不吃香菜。现在又说早就能吃。
                                    所以哪个算。能吃和爱吃是两回事。你要只是不挑，就直接说不挑。**我不猜**。」
```

⇒ 这句**没有任何更正标记词**，她**要求澄清**而不是猜着改 —— 这正是 `DR-11`（措辞层没有启发式守卫）与
"宁可不改，不可改错"要的行为。而我的语料把它写成"更正**应当**落库" ⇒ **金标与产品意图相反**。
⇒ 处置候选（**需用户裁定**，登记为 `LV2-D10`）：把 `C02-02` 的期望改成"**澄清**"，
或把它降为**读数案**（不参与成功率分母）。**不得**为了让它变绿去发明"其实/早就能"的启发式。

### 9.3 我漏声明了一个**开关的消费者**（`C05-04` 的红有一部分是我的装配缺口）
