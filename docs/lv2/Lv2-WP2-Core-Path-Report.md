## 0. 这一轮要解决的那个具体问题

`R-29` 的**契约修复已经落地**（`4f8474d8`，2026-10-02 14:51）：

```text

· 映射层：模型面草案**没有** `acceptanceEventIds` ⇒ 回落到**程序事实**（本轮用户事件 `sourceRef`）
```

但**没有任何一处证明**："这样一份草案经**原生轮次链**（理解 → 草案校验 → 映射 → 放行口 → 写库）
跑完，会**真的**落成一条 `COMMITMENT_ACCEPTED`"。
而唯一那份端到端的真读数（`m10.1:long:live --turns 200`，`R-33`）是 **0 条承诺** ——
那是**"没发生"**，**不是"不可能发生"**。两者对 Lv2 的含义完全不同：

- 若是"不可能" ⇒ 机制缺口 ⇒ `C07` 的正例永远写不进去，Lv2 必须继续修；
- 若是"没发生" ⇒ **模型行为**读数 ⇒ 机制可达，问题在"真实模型会不会产承诺"，属真模型档。

本门用**确定性的（脚本化 provider）端到端控制**把这两件事分开。**零模型请求**。

## 2. 三处必须分列的裁定/发现

### 2.1 `LV2-D04` 的出口**: 已达**（非零正控成立）

`LV2-D04` 逐字要求："修复完成后必须在 **Lv2 候选**上出**非零正控**（'约定真的被记成承诺'）与**负控**
（含糊接受 / 闲聊 / 单方提出**不得**写成承诺）"。分开回答：

| `LV2-D04` 的子句 | 本轮的答案 | 依据 |
|---|---|---|
| "约定真的被记成承诺"（机制） | ✅ **成立** | `A1` / `A6` 经**原生轮次链**落成 `COMMITMENT_ACCEPTED`（`A1` 的采纳出处就是本轮用户事件），`C1b` 走生产路由也成立 |
| 负控（**形状**层：写了 id / 判据档不合 / 操作不匹配） | ✅ **成立**（三条具名理由） | `A3` / `A4` / `A5` |
| 负控（**行为**层：含糊接受 / 闲聊 / 单方提出**不得**写成承诺） | ⚠️ **机械上做不到** | `B1`：放行口照收 ⇒ 闸在**提示词**，不在放行口（`L-M10.1-09`） |

⇒ 结论写得比"通过"更细：**机制可达（正控非零）**，**行为层无机械守卫（边界如实登记）**。
"含糊接受 / 闲聊不得写成承诺"这一条**不能**由本门判定，**只能**由真模型档（`LV2-G3` 的 144 短场景、
`LV2-G5` 的 50 轮）按**用户可见回复 + 程序状态**双满足来判。**不许**用本门的 PASS 去顶替它。

### 2.2 `R-33` 的重新定性：**"机制可达、模型没做"**

`R-33`（200 轮真模型长链、`COMMITMENT_ACCEPTED=0`）此前只能读成"快路径没记下约定"。
本门给出了它的**另一半**：同一套契约与映射，只要草案带承诺，链就会写。
⇒ `R-33` 的 0 是 **模型行为**读数（该材料上模型没有把那次约定表达成承诺草案），
**不是**契约/映射/放行口的缺口。

⚠️ **这不等价于"R-33 已解决"**：

- `R-33` 的读数**不回写**（历史事实）；
- 真模型在新候选上会不会产承诺，**仍然未知**（`4f8474d8` 的提示词改动**没有**在真模型上量过）；
- 这正是 `LV2-D05` 授权的那 **50 轮**要回答的问题之一（且它是**唯一**能回答的档）。
