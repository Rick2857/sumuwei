# QQ 多用户与白名单群聊

本次发布提供 U1/G1 源码及合成离线测试。公开副本没有生产群、运行数据或真人收发验收记录。QQ 多用户默认关闭；旧 owner 好友私聊保留。

## 配置自己的入口

先配置自己的 `.env`、模型端点、数据库和 [LLBot / PMHQ](QQ-DEPLOYMENT.md)；将 `.env.qq.example` 复制为 `.env.qq` 并填写独立的主人 QQ、机器人 QQ、OneBot token。机器人须已加入自己的白名单群。使用自己的备份和停机窗口运行 `pnpm migrate:apply`，当前 schema 为 v22；生产迁移需要操作者明确决定，源码发布不会替你执行。

`.env.qq` 的可选片段（群号是合成示例，须替换）：

```dotenv
QQ_MULTI_USER_ENABLED=true
QQ_ALLOWED_GROUP_IDS=10000000011,10000000012
```

单 QQ 入口运行 `pnpm qq:chat`；与呈现入口共存时先在自己的 `.env` 设置 `CHARACTER_ENTRY_SCOPED_CONVERSATIONS=true`，按已有共存准备流程生成本机入口令牌，再使用共存编排。3D/原生语音的 `pnpm postlv2:avatar:production` 在多用户开启时读取该令牌文件并启动同一核心及 QQ 外壳；没有配置 `.env.qq` 时保留独立语音入口。仅运行一种核心编排。关闭 3D/语音共存用 `pnpm avatar:3d:stop`；不要杀核心进程。

## 当前范围

- 白名单群的当前成员可私聊。入站和发送前均使用 `get_group_member_info(no_cache=true)` 核验机器人与发言者；平台不可用或资格失败时拒绝。QQ 平台仍可能限制临时或陌生人私聊。
- 群首版接普通文字。@机器人、当前连接已核验的机器人回复引用、明确名字呼唤会触发。引用名字、第三人称和含糊提及可能保持沉默。
- 未受理消息仅留同群短期缓冲：20 条 / 6000 字 / 5 分钟，每行 1000 字，最多 32 群；不进入长期记忆或逐条后台认知。
- 逐人关系、一个共享情绪投影；新用户关系为 0.2/0.2。源房间授权约束召回、Recent、派生来源根和后台写入；私聊资料不能因本人在群里而披露给全群。
- 普通成员和群入口关闭主人的 action/task/skills/主动投递权限；主人私聊保留原通路。人物印象要求提问者两维关系严格大于 0.4，只给定性依据。主人具名查询其他已映射用户私聊资料需独立审计，群中不开放。
- 有界队列、限频、去重和成员变更失效；API 回执只表示接受，不证明真人看到，回执不明不自动重发。

## 存储与运行维护

迁移 0019 保存归属标签；0021 登记来源房间与读取审计，并按房间 ID 后缀分域 ACTIVE 内容指纹唯一索引；0022 对 memory_records / conversation_events 开启 FORCE RLS。0020 保留既有 admin_jobs schema 序号，仅作为迁移链兼容，不发布管理后台。已发布事件与记忆 reducer 不改，旧记录缺标签按原主人私聊处理，不回填虚构来源。

RLS 覆盖两张表；可信程序以事务局部设置传入外部读取作用域。内部消费者及本机管理仍为可信通路，不能把这一实现当成给任意 SQL 客户端的隔离账号体系。新迁移后完整管理备份使用 `pg_dump --enable-row-security` 并保留原备份参数；管理连接不携带聊天读取作用域，核对备份清单和同快照逐表计数。恢复另行演练。

调整白名单后有序重启核心和 QQ 外壳，使入口、在途队列、缓存及核心成员核验一起更新。关闭多用户为 `QQ_MULTI_USER_ENABLED=false` 后同样有序重启；保留数据及标签，不执行 down 迁移。

## 验证

```powershell
pnpm ci:offline
pnpm u1:completion:verify
pnpm qq:group:verify
pnpm qq:group:coexist:verify
```

测试仅使用本副本新建、关闭的合成数据源和临时数据库，人工 OneBot/模型夹具模拟网络协议。它们验证身份、授权过滤、遗漏 WHERE 的 RLS、后台来源归因、真实桥/核心整链、房间隔离与成员撤销；不调用真实 QQ 或模型。新副本的实测结果见 [PUBLIC-VERIFICATION](PUBLIC-VERIFICATION.md)。真人首次使用、真实模型拒绝语义和长期收益仍需用户自己的证据。
